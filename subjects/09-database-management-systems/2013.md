**Paraphrased problem context:** An index is clustered if A its fields form a candidate key; B its fields include the primary key; C data records follow the same order as index data entries; D data records do not follow that order.

## Solution

A clustered index has its data records physically organized in the same order as the index’s data entries. This is about file ordering, not merely whether the indexed fields form a candidate or primary key. Hence C.

Teaching detail:
Clustering describes physical locality/order of the records relative to the index ordering. Scanning adjacent index entries can therefore correspond to nearby ordered records. Key uniqueness is a different property: an index can be clustered on a nonunique field, and a primary-key index need not determine the physical record order in every storage design. Thus C states the defining relationship, while A/B confuse clustering with key constraints and D describes the opposite relationship.

Desired result is distinct student names scoring>90 in course 107. I SQL SELECT DISTINCT S.sname FROM Students S, Registration R WHERE R.rollno=S.rollno AND R.courseno=107 AND R.percent>90. II relational projection sname after selecting courseno107 and percent>90 from Registration natural-join Students. III tuple calculus {T:∃S∈Students,∃R∈Registration(S.rollno=R.rollno∧R.courseno=107∧R.percent>90∧T.sname=S.sname)}. IV domain calculus {<SN>:∃SR∃RP(<SR, SN>∈Students∧<SR, 107, RP>∈Registration∧RP>90)}. Which equivalent queries? A all four; B I, II, III; C I, II, IV; D II, III, IV.

## Solution

Each expression joins a student to a registration on roll number, requires course 107 and percent>90, and returns the student name. SQL DISTINCT and set-valued relational algebra/calculi remove duplicate names. Hence all four are equivalent, A, with the tuple-calculus output T understood to have the displayed single sname attribute. Quantifiers in III/IV were visually checked with MuPDF.

Teaching detail:
All four forms bind the same join witness: a student row and a registration row with equal rollno, course 107 and percent greater than 90. SQL DISTINCT removes duplicate names; relational projection and calculus use set semantics. The Courses table is not needed because filtering uses its numeric course identifier, not its name. In IV, SR is the shared roll number, SN is the returned name, and RP is the qualifying percentage. In III, the result tuple is understood to have just the sname attribute, matching the projected result schema.

**Paraphrased problem context:** R(A, B, C, D, E, F, G, H) has atomic fields and exactly FD closure generated by CH→G, A→BC, B→CFH, E→A, F→EG. Number of candidate keys: A3, B4, C5, D6.

## Solution

D never occurs on any right-hand side, so every key must contain D. The dependencies A→B, B→F, F→E and E→A form a reachability cycle among A, B, E, F. Starting from any one of those four attributes derives the other three, C and H through B→CFH, and G through F→EG. Consequently A+, B+, E+, F+ each equal {A, B, C, E, F, G, H}, missing only D. Thus AD, BD, DE and DF are candidate keys, and each is minimal. For completeness, any set containing none of A, B, E, F can include only C, D, G, H; its closure can at most add G via CH→G and can never reach that four-attribute cycle. Therefore every key includes at least one of A, B, E, F, and a minimal key includes exactly one together with D. There are precisely four candidate keys, option B.

Teaching detail:
Compute closures to establish keys and then prove the list exhaustive. D cannot be derived because it never appears on an FD right side, so it must be supplied. Any one of A, B, E, F reaches all the other members of that cycle and then C, H, G. Supplying D alongside one therefore determines all eight attributes. With none of A, B, E, F, the remaining C, D, G, Hcannot generate an entry point into the cycle. Consequently a minimal key consists of Dplus exactly one cycle member: four possibilities.

**Paraphrased problem context:** For the same relation and FDs CH→G, A→BC, B→CFH, E→A, F→EG, classify normal form: A1NFnot2NF; B2NFnot3NF; C3NFnotBCNF; DBCNF.

## Solution

Atomic fields give 1NF. The candidate keys are AD, BD, DE, DF, so the prime attributes are A, B, D, E, F and the non-prime attributes are C, G, H. From the given dependency A→BC we obtain A→C. Here A is a proper subset of the candidate key AD and C is non-prime, so C has a partial dependency on a candidate key. This violates 2NF. Therefore the relation is in 1NF but not 2NF, option A; no higher-normal-form analysis is needed.

Teaching detail:
Second normal form forbids a nonprime attribute from depending on a proper subset of any candidate key. AD is a candidate key and C is nonprime, but Aalone determines C through A→BC. This single partial dependency suffices to disprove 2NF. Atomic fields already establish 1NF, so the exact classification is 1NFbut not 2NF. There is no need to test every FD against 3NF/BCNF after a lower prerequisite has failed.
