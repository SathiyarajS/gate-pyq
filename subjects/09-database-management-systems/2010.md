**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 4. Consult original wording and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** In a B+ tree, the maximum number of keys in a node is five. What is the minimum number of keys in any nonroot node?
Options: (A) 1; (B) 2; (C) 3; (D) 4.

## Solution

With at most five keys, an internal node has at most six child pointers. A nonroot internal node must have at least ceil(6/2)=3 children and therefore at least two separator keys. Such an internal node attains the minimum, giving 2, B. Under the usual leaf convention a leaf with capacity five has at least three data keys; the requested minimum over nonroot nodes is still two, not a claim that every leaf may have two.

Teaching detail: An internal search node with c child pointers has c−1 separator keys. The maximum of five keys therefore corresponds to order six, whose half-full lower bound is three children, not three keys. The root is exempt from the ordinary minimum occupancy rule. Keeping child counts distinct from key counts avoids the common off-by-one error.

# GATE 2010: Q29 (printed CS Q19)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 4. Consult original wording and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Schemas: Passenger(pid,pname,age) and Reservation(pid,class,tid).
Passenger rows: (0,Sachin,65), (1,Rahul,66), (2,Sourav,67), (3,Anil,69).
Reservation rows: (0,AC,8200), (1,AC,8201), (2,SC,8201), (5,AC,8203), (1,SC,8204), (3,AC,8202).
Which pids does this query return?
SELECT pid FROM Reservation
WHERE class='AC' AND EXISTS
 (SELECT * FROM Passenger WHERE age>65 AND Passenger.pid=Reservation.pid);
Options: (A) 1,0; (B) 1,2; (C) 1,3; (D) 1,5.

## Solution

The outer query first keeps AC reservation rows, whose passenger IDs are 0,1,5,3. The correlated EXISTS requires a Passenger row with the same pid and age greater than 65. ID 0 has age exactly 65 and fails; ID 5 has no Passenger row and fails. IDs 1 and 3 have ages 66 and 69 and pass, giving 1,3, option C.

Teaching detail: EXISTS tests whether at least one matching subquery row exists; it does not require every Passenger row to meet the age condition. Passenger 2 is old enough but its only reservation is SC, so the outer AC filter removes it. Passenger 1’s additional SC reservation also does not add another output row. No ORDER BY is present, so 1,3 describes the result members rather than a guaranteed row order.

# GATE 2010: Q30 (printed CS Q20)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 5. Consult original wording and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Which concurrency-control protocols ensure both conflict serializability and freedom from deadlock? I: two-phase locking. II: timestamp ordering.
Options: (A) I only; (B) II only; (C) Both I and II; (D) Neither I nor II.

## Solution

Two-phase locking guarantees conflict serializability but can create a cycle of transactions waiting for locks, so I does not guarantee deadlock freedom. Basic timestamp ordering enforces conflicts in timestamp order and rejects/aborts violating operations rather than making transactions wait on locks. It is conflict serializable and deadlock-free, although retries can still starve a transaction. Thus II only, B.

Teaching detail: A simple 2PL deadlock is T1 holding lock X while requesting Y and T2 holding Y while requesting X; neither needs to violate the two-phase rule. Timestamp ordering instead disallows an operation inconsistent with the fixed transaction order. Deadlock freedom does not imply starvation freedom: repeated abort/restart of one transaction is still possible.

# GATE 2010: Q52 (printed CS Q42)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 10. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Transactions T1,T2,T3 execute this schedule, in time order: r1(X), r2(Y), r3(Y), w2(Y), w1(X), w3(X), r2(X), w2(X). Which serial order is equivalent to the schedule?
Options: (A) T1→T3→T2; (B) T2→T1→T3; (C) T2→T3→T1; (D) T3→T1→T2.

## Solution

In time order the schedule is r1(X), r2(Y), r3(Y), w2(Y), w1(X), w3(X), r2(X), w2(X). Conflicts on X impose T1→T3, T1→T2 and T3→T2; r3(Y) before w2(Y) also imposes T3→T2. There is no reverse edge. Its unique topological ordering is T1→T3→T2, option A.

Teaching detail: Two operations conflict only if they belong to different transactions, access the same item, and at least one is a write. Reads r2(Y) and r3(Y) do not themselves create an edge. However r3(Y) before w2(Y) creates T3→T2. A topological ordering of the resulting acyclic graph gives a conflict-equivalent serial execution; source-code transaction numbering alone does not determine that order.

# GATE 2010: Q53 (printed CS Q43)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 10. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Relations R(A,B,C) and S(B,D,E) obey B→A and A→C in R. R contains 200 tuples and S contains 100 tuples. What is the maximum possible cardinality of their natural join R⋈S?
Options: (A) 100; (B) 200; (C) 300; (D) 2000.

## Solution

Within R(A,B,C), B→A and A→C imply B→ABC, so B is a key under relational set semantics. In the natural join on common attribute B, each of the 100 tuples of S(B,D,E) matches at most one R tuple. Therefore the join has at most 100 tuples. This bound is attainable by choosing all S.B values among the 200 R.B values, so A. The cardinality of R does not multiply each S row because B is unique in R.

Teaching detail: The bound is attained, for example, by choosing 100 S rows whose B values all occur in R, with distinct D,E as needed. Every S row then contributes exactly one join row. Different S rows may share a B value without violating any stated dependency, but none can match two R rows because B determines every attribute of R. This is a many-to-one join from S to R.
