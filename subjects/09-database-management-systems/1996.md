

# GATE 1996: Q94 (printed B Q27(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Returns (6, title) pairs for books recorded as issued to user 6.

**Essential problem context (paraphrased):** Relations are USERS(User#,UserName,HomeTown), BOOKS(Book#,BookTitle,AuthorName), and ISSUED(Book#,User#,Date). Natural joins match the identically named key attributes. Explain in one English sentence the query σ_User#=6(π_User#,BookTitle((USERS ⋈ ISSUED) ⋈ BOOKS)). This paraphrase uses GFG's legible relational operators; GateForum's reproduction drops join symbols and degrades projection typography.

## Solution

One-sentence answer: It returns user number 6 together with the titles of books recorded as issued to that user.

To see why, USERS ⋈ ISSUED first connects each issue record with the user whose User# matches. Joining this result with BOOKS on Book# adds the associated BookTitle and AuthorName. The projection π_User#,BookTitle retains just the user identifier and title, discarding names, dates, book identifiers and author names. Finally σ_User#=6 keeps only rows whose user identifier is 6.

Selection occurs after projection here without losing its input attribute, because User# is explicitly retained. It could equivalently be pushed earlier to restrict the user or issue records before the joins. Under ordinary set-based relational algebra, projection removes duplicate pairs: borrowing the same titled book more than once does not produce multiple identical (6,title) rows, and distinct books with the same title also collapse at this projection. No return-date or current-loan condition exists in the schema, so “recorded as issued” is more precise than claiming these are necessarily the user's currently unreturned books. The query yields titles with the fixed identifier 6, not a count of loans, author names, or all users who borrowed the same books.

# GATE 1996: Q95 (printed B Q27(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Names of authors with at least one book issued to a Delhi-hometown user.

**Essential problem context (paraphrased):** Relations are USERS(User#,UserName,HomeTown), BOOKS(Book#,BookTitle,AuthorName), and ISSUED(Book#,User#,Date). Natural joins match the identically named key attributes. Explain in one English sentence the query π_AuthorName(BOOKS ⋈ σ_HomeTown='Delhi'(USERS ⋈ ISSUED)). Use the projection and natural-join symbols visible in GFG; GateForum misprints/degrades these operators.

## Solution

One-sentence answer: It returns the names of authors having at least one book recorded as issued to a user whose hometown is Delhi.

The inner natural join USERS ⋈ ISSUED matches each issue to its borrower through User#. Selecting HomeTown='Delhi' retains issue records belonging to Delhi users; the condition describes the borrower's hometown, not the author's residence or the book's publication place. The join with BOOKS matches Book# and adds the author of each surviving issued book. Projection onto AuthorName then discards every other attribute.

Under set semantics each distinct author name appears once, even if several Delhi users borrowed that author's books or one user borrowed several such books. The condition is existential: one qualifying issue suffices. It does not require that all books by the author have been issued, that every Delhi user has read the author, or that the author is popular by any numerical threshold. Likewise nothing in the given schema tests whether a book has since been returned. If no Delhi user has any issue record, the result is empty. Two different people who happen to share AuthorName are not distinguished by this schema and projection; the result is a set of names rather than necessarily unique real-world author identities. GateForum's apparent σ before AuthorName would not be a well-formed selection predicate; the GFG π supplies the coherent reading.
