**Official answer:** Not available; no official key located.

**Independently derived answer:** False

**Essential problem context (paraphrased):** True or false: every schema has a BCNF decomposition that is both lossless and dependency preserving.

## Solution

Take R(A,B,C) with F={AB→C,C→B}. Its candidate keys are AB and AC. The dependency C→B violates BCNF because C is not a superkey. Decomposing into CB and AC is lossless, since the common C determines CB, and both components are BCNF. But their projected dependencies do not imply AB→C: from AB one cannot derive C. More generally every proper subrelation here supplies no dependency producing C from AB, so no decomposition into proper BCNF components can preserve that FD. BCNF can guarantee losslessness, not simultaneous dependency preservation in every case.

**Independently derived answer:** No

**Essential problem context (paraphrased):** One instance of R(A,B,C) has distinct values for A. Can A be concluded to be a candidate key for the schema?

## Solution

A candidate key is a schema-level guarantee: it must uniquely identify rows in every legal instance and be minimal among such attribute sets. Distinct A values in one observed instance show only that A happens to be unique there. For example rows (1,x,u),(2,y,v) are consistent with no uniqueness constraint on A; a later legal row (1,z,w) could repeat it. Therefore one instance does not establish the functional dependency A→BC or candidate-key status. The alternate retains the explicit “Can you conclude” question omitted in GFG.

**Independently derived answer:** R−(R−S), using two differences

**Essential problem context (paraphrased):** Give an expression equivalent to R∩S using the minimum number of operators from {∪,−}.

## Solution

The inner R−S contains exactly the R tuples absent from S. Removing those from R leaves the tuples present in both, namely R∩S. This uses two operators. One operator cannot work for arbitrary R,S: R∪S includes exclusive tuples, R−S and S−R keep exclusives rather than common tuples, and applying an operator to a relation twice yields either that relation or the empty relation. Thus two is minimal under set semantics with only R,S and the listed binary operators, assuming union-compatible schemas.

**Type / marks:** true-false-with-reason, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** False

**Essential problem context (paraphrased):** True or false: logical data independence is easier to achieve than physical data independence.

## Solution

Physical data independence hides changes such as indexes, file organization and storage placement behind an unchanged logical schema. Applications can often remain unaffected. Logical data independence must hide changes to the conceptual schema itself, such as restructuring relations or attributes, while preserving external views and application meaning. That generally requires more semantic translation and is harder. Therefore the source reverses the usual difficulty comparison. This is a database-design principle, not an assertion that every individual physical change is trivial.

**Independently derived answer:** Registered: π_rollno(σ_cno=322(REGISTERED_FOR)). Not registered: π_rollno(STUDENTS) − π_rollno(σ_cno=322(REGISTERED_FOR)).

**Essential problem context (paraphrased):** COURSES(cno,cname), primary key cno; STUDENTS(rollno,sname,age,year), primary key rollno; REGISTERED_FOR(cno,rollno), composite primary key (cno,rollno). year denotes the student’s current year of study. GateForum asks for a relational algebra query printing roll numbers of students who HAVE registered for cno 322. GFG instead asks for those who HAVE NOT registered.

## Solution

1. Select registrations for course 322 before projecting rollno, so registrations in other courses do not count.

2. For the registered variant, projection directly returns the wanted roll numbers under the usual valid student-reference assumption. Without that assumption, intersect with π_rollno(STUDENTS).

3. For the not-registered variant, subtract the selected roll-number set from all student roll numbers. Selecting registrations where cno≠322 would be wrong because a student may register for both 322 and another course, or for no course.

# GATE 1994: Q61 (printed B Q13(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** SELECT MIN(age) AS age, year FROM STUDENTS GROUP BY year;

**Essential problem context (paraphrased):** COURSES(cno,cname), primary key cno; STUDENTS(rollno,sname,age,year), primary key rollno; REGISTERED_FOR(cno,rollno), composite primary key (cno,rollno). year denotes the student’s current year of study. Write SQL to print the age and year of the youngest student in each year.

## Solution

1. Group rows by year so each year is processed independently.

2. MIN(age) computes the youngest age within that group. Output just age and year, as requested, rather than an arbitrary student name or roll number.

3. Ties need no extra rows because the requested attributes are identical for tied youngest students. Standard SQL ignores NULL ages; if all ages in a year are NULL, the result is NULL.
