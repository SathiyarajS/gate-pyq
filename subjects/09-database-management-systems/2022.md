**Question:** [Official archived paper page 12](https://gate2026.iitg.ac.in/doc/download/2022/cs_2022.pdf#page=12); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A under the nonempty-determinant convention

**Paraphrased problem context:** Which relational-model statement is true under the intended textbook interpretation? A every two-attribute relation is BCNF; B all attributes prime implies BCNF; C every relation has a nonprime attribute; D BCNF decompositions preserve functional dependencies. Discuss any needed qualification.

## Solution

With two attributes A, B and nonempty determinants, the only potentially nontrivial dependencies are A→B and B→A; either determinant is a key. Thus the relation is BCNF, intended A. All-prime attributes do not suffice: R(A, B, C) with AB→C and C→B has keys AB and AC but violates BCNF. BCNF decomposition need not preserve all dependencies. Literal qualification: empty determinants are legal in general FD theory. If ∅→A holds in R(A, B) while B varies, ∅ is not a superkey, so this binary relation is not BCNF. Official A therefore needs the usual exclusion of constant-column dependencies, which the prompt does not state.

Teaching detail:
BCNF requires every determinant of a nontrivial functional dependency to be a superkey. For the three-attribute counterexample, AB and AC each determine all attributes, so all attributes are prime, but C alone determines B without determining A. This also illustrates why “prime” is weaker than the BCNF determinant condition. Keep the empty-determinant exception separate from the intended exam convention.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** A,B

**Derived answer:** A,B under the standard division candidate universe

**Paraphrased problem context:** Given Employee(eId,Name), Brand(bId,bName), Own(eId,bId), select expressions returning owners of every brand. Define O=π_eId,bId(Own), E=π_eId(Own), B=π_bId(Brand), H=π_bId(Own). Options: A π_eId(O÷B); B E−π_eId((E×B)−O); C π_eId(O÷H); D π_eId((E×H)÷B).

## Solution

A divides the employee-brand pairs by all brand IDs. B starts with employee IDs occurring in Own and removes those with at least one missing pair from the Cartesian product with Brand. These are the standard equivalent formulations of relational division. C divides only by brands that someone owns, potentially omitting unowned brands; D manufactures ownership pairs by a Cartesian product. Thus A, B. Boundary qualification: both A and B use π_eId(Own), not all rows of Employee, as their candidate universe. If Brand is empty and “all brands” is interpreted vacuously for every Employee, employees absent from Own are omitted. The intended nonempty-brand/owner-universe reading should be kept explicit.

Teaching detail:
For B, E×B enumerates every required owner-brand pair, and subtracting O finds missing ownerships. Projecting to eId identifies failures, which are subtracted from E. For C, one brand absent from all Own tuples is a counterexample: division by H ignores it. D can claim someone owns a brand merely because another employee owns it.

**Type / marks:** NAT, 1 mark(s).

**Official answer:** 8 to 8

**Derived answer:** 8

**Paraphrased problem context:** For R(A,B,C,D,E), dependencies are AB→C, BC→D, C→E. How many superkeys exist?

## Solution

A and B never appear on a dependency’s right side, so every key and superkey must include both. AB determines C, then BC determines D, and C determines E; hence AB is a key. All superkeys are AB with any subset of {C, D, E}, giving 2³=8.

Teaching detail:
Compute (AB)+: begin {A,B}; AB→C adds C; BC→D adds D; C→E adds E. No set lacking A or B can obtain it from these FDs, proving AB is the unique minimal key. The eight superkeys are AB,ABC,ABD,ABE,ABCD,ABCE,ABDE,ABCDE.

**Paraphrased problem context:** With Ri(z),Wi(z) denoting transaction i's reads/writes, schedule S is R4(x),R2(x),R3(x),R1(y),W1(y),W2(x),W3(y),R4(y). Choose a conflict-equivalent serial order: A 1,3,4,2; B 1,4,3,2; C 4,1,3,2; D 3,1,4,2.

## Solution

Conflicts on x give T4→T2 and T3→T2. Conflicts on y give T1→T3, T1→T4 and T3→T4. Their topological order is T1, T3, T4, T2, option A. Read-read pairs add no edges.

Teaching detail:
The precedence graph can be drawn as T1→T3→T4→T2, with additional T1→T4 and T3→T2 edges. Each edge enforces the same relative ordering of conflicting operations in a serial schedule. Since this chain orders all four transactions, the topological order is unique.

**Official answer:** 2 to 2

**Derived answer:** 2

**Paraphrased problem context:** Student(sNo,sName,dNo): (S01,James,D01),(S02,Rocky,D01),(S03,Jackson,D02),(S04,Jane,D01),(S05,Milli,D02). Dept: (D01,CSE),(D02,EEE). Course(cNo,cName,dNo): (C11,DS,D01),(C12,OS,D01),(C21,DE,D02),(C22,PT,D02),(C23,CV,D03). Register pairs: S01:C11,C12; S02:C11; S03:C21,C22,C23; S04:C11,C12; S05:C11,C21. Count rows returned by SELECT * FROM Student AS S WHERE NOT EXIST (SELECT cNo FROM Course WHERE dNo = “D01” EXCEPT SELECT cNo FROM Register WHERE sNo = S.sNo). The printed spelling/quotes are retained to expose the source syntax issue.

## Solution

The intended NOT EXISTS test succeeds when the set of D01 courses minus the student's registered courses is empty. The D01 course set is {C11, C12}. The visually inspected Register table shows both courses for S01 (James) and S04 (Jane), and not for S02, S03 or S05. Therefore the intended query returns 2 student rows. Source syntax discrepancy: the printed SQL says NOT EXIST, missing the final S, and uses typographic double quotes around D01. Executable standard SQL needs NOT EXISTS and a single-quoted character literal. The official numeric answer assumes these obvious syntax repairs; the literal printed statement is not valid standard SQL.

Teaching detail:
The missing-D01-course sets are S01:∅, S02:{C12}, S03:{C11,C12}, S04:∅, S05:{C12}. NOT EXISTS accepts only empty sets. A student’s own department is not a filter in the outer query; only coverage of the D01 courses matters.
