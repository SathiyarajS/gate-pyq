**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Essential problem context (paraphrased):** Relation R(A,B,C,D) has dependencies A→B and C→D and is decomposed into AB and CD. Classify the decomposition as dependency-preserving or not and lossless or not.

## Solution

Step 1: A→B can be checked entirely in R1(AB), and C→D entirely in R2(CD). Thus the decomposition preserves both supplied dependencies.

Step 2: The two schemas have empty intersection. Their natural join is a Cartesian product, which can create spurious combinations. For instance tuples(a1,b1,c1,d1) and(a2,b2,c2,d2) satisfy the dependencies, but joining their projections also creates(a1,b1,c2,d2) and(a2,b2,c1,d1).

Hence the decomposition is dependency-preserving but not guaranteed lossless, C.

**Essential problem context (paraphrased):** Given an adjacency relation Adj(X,Y), which query cannot be expressed by a fixed-length ordinary relational-algebra expression: neighbors of a vertex, vertices with self-loops, vertices in cycles with fewer than three vertices, or all vertices reachable from a vertex?

## Solution

Step 1: Adjacency and self-loops require selection/projection on Adj. A cycle of a fixed bounded length can be described by a fixed number of renamed joins and equality tests.

Step 2: Reachability permits paths of arbitrarily large length as the graph grows. Ordinary nonrecursive relational algebra has no transitive-closure operation; one fixed expression cannot supply an unbounded chain of joins.

Thus D cannot be expressed by a constant-length ordinary relational-algebra expression over all finite input graphs. Recursive query extensions or a fixed maximum graph size change that setting.

**Essential problem context (paraphrased):** For relations r and s with A an attribute of r, simplify σ_(A=a)(r⋈s). Choices are σ_(A=a)(r), r, σ_(A=a)(r)⋈s, or none.

## Solution

Step 1: The predicate A=a refers only to an attribute of r. A joined tuple survives the selection exactly when its r component has that value.

Step 2: Rejecting the failing r tuples before joining therefore removes exactly the same joined tuples: σ_(A=a)(r⋈s)=σ_(A=a)(r)⋈s. This is C.

Dropping s altogether can lose its attributes and its filtering effect, so neither r nor its selected subset alone is generally equal to the joined result.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Essential problem context (paraphrased):** Which FD set on R(A,B,C,D) does not admit a lossless, dependency-preserving BCNF decomposition? A: A→B,B→CD. B: A→B,B→C,C→D. C: AB→C,C→AD. D: A→BCD.

## Solution

Step 1: For option C, AB→C and C→AD imply AB and BC are keys. Yet C alone does not determine B, so C→A and C→D violate BCNF. Decomposition into CAD and BC is lossless because their intersection C determines CAD, but it loses local enforcement of AB→C.

Step 2: Any relation containing A,B,C is not BCNF: it retains C→A while C is not a key. Without such a relation, projected dependencies cannot derive C from AB; no proper smaller attribute subset provides that dependency. Thus no dependency-preserving BCNF decomposition exists.

The other options admit lossless preserving choices: AB and BCD for A; AB,BC,CD for B; and the original already-BCNF relation for D. Hence C.

**Independently derived answer:** C is unsafe; B is also unsafe as literally printed

**Essential problem context (paraphrased):** Which tuple-calculus expression is unsafe? A binds t[A] to an R1 value absent from R2. B says for every u∈R1, u[A]=constant x implies some s∈R2 has t[A]=s[A] and s[A]=u[A]. C is {t:¬(t∈R1)}. D binds t[A] to values present in both relations. Examine empty/unguarded cases as well as the obvious complement; exact formulas remain linked.

## Solution

Step 1: C returns all tuples outside R1. Over an unrestricted infinite domain and finite R1, this produces an unbounded complement, so it is unsafe. A and D bind the returned A-value to existing relation values, under the intended one-attribute result interpretation.

Step 2: B universally quantifies u in R1 and guards the existential restriction on t with u[A]=the constant x. If R1 is empty, or contains no tuple with that A-value, every implication is vacuously true. Then t is unconstrained and arbitrary outside-domain values satisfy the expression. Thus B is also not domain-independent.

This is a literal second-unsafe-option issue confirmed in both reproductions, not an official-key correction. Adding an existence requirement for the guarded R1 value would change the question.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Essential problem context (paraphrased):** Table geq has nonnull integer lb,ub, primary key lb, and self-referencing foreign key ub with ON DELETE CASCADE. Every row(x,y) obeys y≥x. On deleting(x,y), can a cascaded row(z,w) have z>y, z>x, or w<x, or must deletion be prohibited?

## Solution

Step 1: Deleting parent key x directly cascades to rows(z,w) with w=x. Since every row obeys w≥z, these direct children have z≤x. Cascades continue to their children, so keys along a deletion chain cannot increase. Options requiring z>x or z>y≥x are therefore impossible.

Step 2: A deeper descendant can have w<x. For example the legal rows(3,3),(2,3),(1,2) satisfy the ordering and foreign key. Deleting(3,3) cascades to(2,3) and then(1,2), whose upper value 2 is less than the original x=3.

Thus C is possible. ON DELETE CASCADE means the mere presence of dependent rows does not prohibit the deletion; self-reference is handled by the database’s cascade semantics.

**Independently derived answer:** π_X.name σ_(X.name=Y.name ∧ X.regno≠Y.regno)(ρ_X(examinee) × ρ_Y(examinee)).

**Essential problem context (paraphrased):** examinee(regno,name,score), with primary key regno. Use projection, selection, renaming and Cartesian product to find names appearing in multiple tuples.

## Solution

Rename the relation twice so the two tuple occurrences are distinguishable: X=ρ_X(examinee), Y=ρ_Y(examinee). Form X×Y, retain equal names but different registration numbers, then project the name.

π_X.name(σ_(X.name=Y.name AND X.regno≠Y.regno)(X×Y)).

The equal-name condition identifies candidates; the unequal-key condition ensures two different examinees rather than pairing a row with itself. Because regno is a key, different regno values mean different rows. Standard relational algebra has set semantics, so projection returns each repeated name once even if it has many matching pairs. Example: (1,Asha,70),(2,Asha,80),(3,Bela,90) returns only Asha. Without the unequal-key predicate every name would incorrectly qualify.

**Independently derived answer:** SELECT regno FROM examinee WHERE score > (SELECT AVG(score) FROM examinee);

**Essential problem context (paraphrased):** examinee(regno,name,score), where regno is a primary key and score is real. List registration numbers with score above the relation-wide average.

## Solution

Use an uncorrelated scalar subquery to compute one average over all examinees:

SELECT e.regno
FROM examinee AS e
WHERE e.score > (SELECT AVG(x.score) FROM examinee AS x);

The outer query compares each score with the same global average. Strict > excludes scores exactly equal to that average. No GROUP BY is needed because the intended comparison is to the whole relation, not a separate average per person or centre. The primary key ensures no duplicate registration number in the result. In SQL, AVG ignores NULL scores and comparison with NULL is unknown, so NULL-score rows do not qualify; the stated mathematical real-number model normally excludes this extra case.

# GATE 2001: Q97 (printed B Q21(c))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** SELECT DISTINCT a.centr_code FROM appears a JOIN examinee e ON e.regno=a.regno WHERE e.score>80;

**Essential problem context (paraphrased):** examinee(regno,name,score) and appears(regno,centr_code). List centre codes having an examinee whose score exceeds 80.

## Solution

Join each appearance to its examinee using the shared registration number, keep scores strictly greater than 80, then project distinct centre codes:

SELECT DISTINCT a.centr_code
FROM appears AS a
JOIN examinee AS e ON e.regno = a.regno
WHERE e.score > 80;

DISTINCT is important because several high-scoring examinees can share a centre. This is an existential requirement: one qualifying examinee is sufficient. It is not a condition on centre average, and it does not require every examinee at that centre to exceed 80. An equivalent SQL formulation selects DISTINCT centre codes from appears a WHERE EXISTS (SELECT 1 FROM examinee e WHERE e.regno=a.regno AND e.score>80).
