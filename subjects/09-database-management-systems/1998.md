**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D after projecting duplicate columns; raw theta join has four attributes

**Essential problem context (paraphrased):** For union-compatible R1(A, B), R2(C, D), interpret R1 join on A=C and B=D R2. Choices include union, product, difference, intersection.

## Solution

A qualifying pair contains the same two values in both input relations. Thus each output is (a, b, a, b), one for each common tuple (a, b). Projecting onto A, B gives the intersection R1∩R2 after renaming, explaining D. But an ordinary theta join retains all four attributes A, B, C, D, whereas intersection has only two. They are not literally equal schemas without projection or a duplicate-column-eliminating join convention. This arity distinction is recorded rather than silently identifying the raw four-column relation with the two-column intersection.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Essential problem context (paraphrased):** Which normal form is conventionally adequate for ordinary relational design:2NF, 5NF, 4NF, 3NF?

## Solution

Third normal form addresses dependencies of nonkey attributes that produce common update anomalies while permitting dependency-preserving, lossless decompositions. It is therefore the conventional general design target among these choices, D. Second normal form only removes partial dependence on composite keys and can leave transitive problems. Fourth and fifth normal forms address additional multivalued or join dependencies and may be necessary for particular schemas, but are not implied as the routine minimum by the question.

**Essential problem context (paraphrased):** Which rewrite is not generally valid? A commuting selections; B moving a well-defined selection before projection; C distributing selection over union; D moving selection after projection without retaining predicate attributes.

## Solution

Selections commute because both predicates must hold, and selection distributes over union tuple by tuple. If selection after projection is already well typed, all predicate attributes survived, so pushing it down is safe. In the reverse direction, projecting first may delete an attribute needed by the predicate. For R(A, B), πA(σB=1(R)) is defined, but σB=1(πA(R)) is not. Thus D is not an unrestricted rule. The alternate prints A with repeated C1 on the left and repeated C2 on the right, which is also false for different predicates. Enlarged GFG B shows its right outer operator as σ with attribute subscript A 1 rather than a projection π, another literal typing defect; the coherent projection rule analyzed above is an explicitly stated reconstruction, not a silent transcription. **Official answer:** Not available; no official key located.

**Independently derived answer:** C: 60% under 5-byte text and 16-bit integer conventions

**Essential problem context (paraphrased):** Signed four-digit values are stored as character strings or integers. Choose reduction 80%, 20%, 60%, 40%.

## Solution

A sign plus four decimal characters uses 5 bytes with one byte per character. Values from−9999 to 9999 fit in a 16-bit signed integer, using 2 bytes. The saving is 5−2=3 bytes, or 3/5·100%=60%, C. This assumes a fixed sign character and no text terminator or length metadata. A 32-bit integer would save only 20% under the same text layout, while other encodings change the comparison. Therefore the supplied result depends on the conventional storage widths rather than the numeric domain alone.

# GATE 1998: Q63 (printed A Q7(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Join FREQUENTS to SERVES by parlor and LIKES by both student and ice cream; select distinct students.

**Essential problem context (paraphrased):** Given FREQUENTS(student,parlor), SERVES(parlor,ice_cream), and LIKES(student,ice_cream), print students who frequent at least one parlor serving at least one ice cream they like. Each student likes an ice cream and frequents a parlor.

## Solution

A qualifying student needs one witness consisting of a frequented parlor and a flavor both served there and liked by that same student. Match those three facts with a join:

SELECT DISTINCT f.student
FROM FREQUENTS AS f
JOIN SERVES AS s
  ON s.parlor = f.parlor
JOIN LIKES AS l
  ON l.student = f.student
 AND l.ice_cream = s.ice_cream;

The schema spells the attribute as “ice-cream”; ice_cream above is a SQL-friendly identifier for that same field. If the actual schema uses a hyphen, use the database's identifier quoting, for example l."ice-cream" in standard SQL. The query assumes the ordinary relational model with non-NULL identifying values.

The first join enumerates flavors served at every parlor a student frequents. The second retains only flavors liked by that student. Both equalities in the second join matter: omitting the student equality would incorrectly let somebody else's preference qualify the student. DISTINCT prints each qualifying student once even if several parlors or flavors witness qualification.

For example, if Ada frequents P, P serves vanilla, and Ada likes vanilla, the triple survives. If Bob also frequents P but only likes chocolate, Bob does not survive unless P serves chocolate as well. The request is existential, so it needs neither relational division nor a test that every frequented parlor serves every liked flavor. The assumptions that students have some likes and visits do not by themselves imply qualification.

# GATE 1998: Q98 (printed B Q26(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 2NF under intended Author-Name→Nationality; key alone does not establish that dependency.

**Essential problem context (paraphrased):** Relation(Book-id,Subject-Category,Author-Name,Author-Nationality) has Book-id primary key. What is its highest normal form?

## Solution

Under the usual semantic assumption that an author name uniquely identifies one author with one nationality, the dependencies include Book-id→all attributes and Author-Name→Author-Nationality. The key is a single attribute, so there is no nonempty proper subset of it on which a nonprime attribute can partially depend. With atomic values, this gives 2NF in the conventional setting.

However Author-Name is not a superkey when an author can write several books, and Author-Nationality is nonprime. The dependency Author-Name→Author-Nationality therefore violates 3NF, and also BCNF. Thus the intended highest form is 2NF.

The premise formally states only the primary key, not all functional dependencies or candidate keys. If the only nontrivial dependencies were those forced by Book-id, the relation would be BCNF instead. Names need not uniquely identify authors in a real database, and multiple nationalities may require a separate modeling choice. Hence 2NF is a conditional semantic answer, not a theorem from the primary-key declaration alone. Constant-valued attributes with empty determinants would introduce additional exceptional dependencies not assumed by the textbook model.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 1NF under intended author→nationality,address dependencies; otherwise underdetermined.

**Essential problem context (paraphrased):** Add Book-title and Author-address to the preceding book relation, with primary key(Author-Name,Book-title). What is its highest normal form?

## Solution

Assume all values are atomic and that each author identifier determines one nationality and one address. The declared key is now K={Author-Name,Book-title}, but the nonprime attributes Author-Nationality and Author-address depend on Author-Name alone, a proper subset of K. These are partial dependencies, violating 2NF. The intended highest normal form is therefore 1NF.

The contrast with part (a) is important: the same author dependency was transitive from a one-attribute book key there, but becomes partial when author is itself one component of the composite key. A decomposition into Author(Author-Name,Nationality,Address) and Book(Author-Name,Book-title,...) removes that particular partial dependency, subject to the remaining domain dependencies.

As before, the key declaration alone does not logically imply the semantic FDs. Author homonyms, multiple addresses or other candidate keys change the analysis. If no such non-key dependencies are imposed, one cannot infer a 2NF violation solely from the displayed attribute names. The conditional answer and its assumptions are retained because no official original/key has been verified.

# GATE 1998: Q100 (printed B Q27)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Return courses minus those with a missing prerequisite, including courses having no prerequisites.

**Essential problem context (paraphrased):** COURSES(Cno,name), PRE-REQ(Cno,pre-Cno), COMPLETED(student-no,Cno). Use relational algebra to list courses for which student 2310 has completed every prerequisite.

## Solution

First collect completed course numbers for the selected student and rename the attribute to match the prerequisite column:
D=ρ_(pre-Cno←Cno)(π_Cno(σ_(student-no=2310)(COMPLETED))).
Let P=PRE-REQ. A natural join P⋈D contains exactly those prerequisite pairs whose prerequisite was completed. Hence Missing=P−(P⋈D) contains pairs identifying at least one uncompleted prerequisite. Project these to obtain Bad=π_Cno(Missing).

Let All=π_Cno(COURSES). Then Eligible=All−Bad, and the requested full course listing is COURSES⋈Eligible. The join uses Cno and returns each eligible course's number and name.

This construction implements 'all' by excluding counterexamples. If a course has three prerequisites and one is missing, that missing pair places it in Bad and removes it. A course with no prerequisites has no missing pair, so it remains eligible by vacuous truth. A naive division over only existing prerequisite pairs can accidentally omit such courses. Nothing in the question excludes courses already completed by the student; add that exclusion only if explicitly requested. The expression uses set relational algebra, so duplicate completion records have no effect.
