

# GATE 2007: Q59 (printed CS Q59)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 15. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

## Solution

Let F be the set of female student IDs and C the set of course IDs occurring in enroll. The Cartesian product F×C contains every possible female-student/course pair. Subtracting enroll leaves exactly pairs (f,c) for which female f is not enrolled in c. Projecting on courseId therefore returns courses missing at least one female student. Since the premise says every course has at least one female enrollee, these are courses whose female enrollee set is a nonempty proper subset of all female students. This is B, not courses taken by every female student.

**Independently derived answer:** C

## Solution

The universal disjunction ¬employee(x) ∨ x.supervisorName≠e.name ∨ x.sex=male is the implication: if x is an employee supervised by e, then x is male. Consequently the result includes employees all of whose immediate subordinates are male, including employees with no subordinates by vacuous truth. Under the male/female domain convention used by the options, this is exactly employees with no immediate female subordinates (C). It says nothing about the sex of e's own supervisor.

## Solution

Q2 uses > ANY, which means greater than at least one returned salary, not every salary. For department salaries 10 and 20, a salary 15 passes Q2 but not Q1. Hence A under the usual non-NULL salary interpretation. Strict SQL NULL semantics require qualification: NULL comparisons are UNKNOWN, so Q1 can admit NULL salaries or ignore unknown department salaries; no NOT NULL constraint is printed.

# GATE 2007: Q62 (printed CS Q62)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 15. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

## Solution

Under standard textbook normalization conventions, a two-attribute relation is BCNF: a nontrivial dependency from one attribute to the other makes its determinant a key. Single-attribute candidate keys have no proper nonempty subset, so no partial dependency prevents 2NF. In 3NF a non-key determinant may determine a prime attribute, permitting the transitive dependency in C. BCNF instead requires every nontrivial determinant to be a superkey, so it excludes a transitive dependency through a non-key determinant. D is the intended false statement. Here transitive dependency means the normalization violation through a non-superkey, not merely any composable implication. The claims about two-attribute relations and singleton keys also assume the textbook convention excluding nontrivial empty-determinant dependencies. If such dependencies are allowed, R(A,B) with ∅ -> B and candidate key A violates both BCNF and 2NF: ∅ is not a superkey, and the nonprime B depends on a proper subset of key A. Consequently A and B are also false under that fully general interpretation, so D is the intended answer only with this convention.

## Solution

In S1, r1(Y) precedes w2(Y), producing T1 -> T2, while r2(X) precedes w1(X), producing T2 -> T1. The cycle prevents conflict serializability. In S2, w2(Y) precedes r1(Y) and r2(X) precedes w1(X), both giving T2 -> T1; there is no reverse edge. S2 is equivalent to serial order T2,T1. Thus C.
