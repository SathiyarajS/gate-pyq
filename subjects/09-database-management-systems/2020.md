

# GATE 2020 CS: Q23 (printed CS Q13)

**Question:** [Official archived paper page 7](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=7); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** Catalogue(sno,pno,cost) has rows (S1,P1,150),(S1,P2,50),(S1,P3,100),(S2,P4,200),(S2,P5,250),(S3,P1,250),(S3,P2,150),(S3,P5,300),(S3,P4,250), primary key (sno,pno). Suppliers has primary key sno and one row each: S1/Royal furniture/Delhi, S2/Balaji furniture/Bangalore, S3/Premium furniture/Chennai. Parts has primary key pno: P1/Table/Wood, P2/Chair/Wood, P3/Table/Steel, P4/Almirah/Steel, P5/Almirah/Wood. Count rows returned by:
SELECT s.sno, s.sname FROM Suppliers s, Catalogue c
WHERE s.sno=c.sno AND cost >
(SELECT AVG(cost) FROM Catalogue WHERE pno='P4' GROUP BY pno);
Options: A 4; B 5; C 0; D 2.

## Solution

Worked explanation

Evaluate the uncorrelated scalar subquery once. Filtering pno=P4 leaves prices 200 and 250, so its one group has average 225. Apply the outer strict comparison to every Catalogue row; prices 250,250,300,250 survive. The supplier primary key makes each surviving row join with exactly one supplier row, so the join neither loses nor multiplies them. Projection returns S2 once and S3 three times. SQL SELECT uses bag semantics unless DISTINCT is requested; it does not automatically collapse those repeated S3 names. The Parts table is not referenced by this query and cannot affect the count.

Derivation and answer

The P4 rows have costs200 and 250, so the subquery returns 225. Catalogue costs greater than225 occur at(S2, P5),(S3, P1),(S3, P5),(S3, P4): four rows. The supplier join preserves all four and SELECT has no DISTINCT, so repeated S3 output rows remain. Answer 4, A. The table entries were visually checked.

# GATE 2020 CS: Q24 (printed CS Q14)

**Question:** [Official archived paper page 7](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=7); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** In an ER diagram, which symbol denotes the supporting many-to-one relationship for a weak entity? A double/bold diamond; B double/bold rectangle; C double/bold oval; D oval with underlined identifier.

## Solution

Worked explanation

In Chen notation, shape and border encode different information. A rectangle denotes an entity, an oval an attribute, and a diamond a relationship. A double rectangle marks a weak entity whose identity depends on an owner. The supporting identifying relationship is correspondingly the double diamond. A double oval normally represents a multivalued attribute, and underlining an attribute name indicates key information, not a relationship. Because the question asks about the relationship rather than the weak entity itself, A rather than B is required.

Derivation and answer

The identifying relationship connecting a weak entity to its owner is shown by a double-bordered diamond in the standard Chen ER notation. A double rectangle denotes the weak entity itself. Thus A.

# GATE 2020 CS: Q46 (printed CS Q36)

**Question:** [Official archived paper page 12](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=12); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** R is in 3NF but not BCNF. Which must hold? A a nontrivial FD X→A has nonsuperkey X and prime A; B such an FD has nonprime A and X not a proper subset of any key; C such an FD has nonprime A and X a proper subset of some key; D some cell is a set rather than atomic.

## Solution

Worked explanation

For each nontrivial dependency X→A, BCNF requires X to be a superkey. 3NF allows an exception when A is prime, meaning A belongs to at least one candidate key. Because R is not BCNF, at least one dependency violates its determinant requirement. Because R still is 3NF, that violating dependency must meet the prime-attribute exception. This proves A directly. Whether X is or is not a proper subset of a key cannot make a nonprime right-hand side acceptable to 3NF when X is not a superkey. Option D contradicts the ordinary atomic-relation setting.

Derivation and answer

Failure of BCNF guarantees a nontrivial FD X→A with X not a superkey. Since3NF still holds, its permitted exception forces A to be prime, belonging to some candidate key. Thus A. The nonprime alternatives violate3NF, and set-valued cells violate the assumed first normal form.

# GATE 2020 CS: Q47 (printed CS Q37)

**Question:** [Official archived paper page 12](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=12); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** Read the following schedule equivalents left to right; Ri(X),Wi(X) belong to transaction i. Both commits follow the listed operations in order C1,C2. Original: R1(A),R2(B),W2(B),R1(C),R2(D),W1(D),W2(C),W1(B),C1,C2. Which is conflict equivalent?
A R2(B),W2(B),R2(D),R1(A),R1(C),W1(D),W1(B),W2(C),C1,C2.
B R1(A),R1(C),W1(D),W1(B),R2(B),W2(B),R2(D),W2(C),C1,C2.
C R1(A),R1(C),W1(D),R2(B),W2(B),R2(D),W1(B),W2(C),C1,C2.
D R2(B),W2(B),R2(D),W2(C),R1(A),R1(C),W1(D),W1(B),C1,C2.

## Solution

Worked explanation

Two operations conflict exactly when they belong to different transactions, access the same item, and at least one writes. There is no cross-transaction access to A. On B, both R2(B) and W2(B) precede W1(B). On D, R2(D) precedes W1(D). On C, R1(C) precedes W2(C). Those four pairwise orders are the complete test, independent of where unrelated reads move. A preserves all four and each transaction’s internal order. B reverses the B and D orders; C reverses only the D order among these; D reverses C. The precedence graph contains both T2→T1 and T1→T2, so the original is not conflict-serializable, but it can still have a conflict-equivalent nonserial schedule. Do not confuse these two questions.

Derivation and answer

The original intertransaction conflict orders are R2(B)<W1(B), W2(B)<W1(B), R2(D)<W1(D), and R1(C)<W2(C). OptionA preserves all four. B reverses the B andD conflicts; C reverses theD conflict; D reverses theC conflict. Thus A. The visually checked column positions, not OCR ordering, determine these relations.

# GATE 2020 CS: Q64 (printed CS Q54)

**Question:** [Official archived paper page 16](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=16); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 4 to 4

**Derived answer:** 4

**Paraphrased problem context:** A B+ tree indexes one million records on a disk with 4 KB blocks. Search keys are 12 bytes and tree/disk pointers 8 bytes. Initially no index node or record is cached; each record fits in one disk block. Find the minimum disk accesses to retrieve any record in the conventional separate-record layout.

## Solution

Worked explanation

An internal node with m child pointers has m−1 separating keys. Its bytes are 8m+12(m−1)=20m−12, at most 4096. Thus m≤205.4 and maximum fanout is 205 (206 would require 4108 bytes). A leaf key/record-pointer pair takes 20 bytes, so it holds at most 204 pairs; adding an 8-byte next-leaf pointer still permits 204. Two index levels, root and leaves, hold at most 205×204=41820 entries and cannot cover one million. Three levels have capacity 205²×204=8573100, enough. A lookup must read one node per level, then follow the leaf’s record pointer to a separate data block. Three index reads plus one data read give four. The calculation concerns minimum height, not arbitrarily sparse trees.

Derivation and answer

With4KB=4096 bytes, an internal node with m child pointers and m−1 keys needs 8m+12(m−1)≤4096, giving maximum fanout205. A leaf holds up to 204 key/record-pointer pairs even with one8-byte next-leaf pointer. A root plus leaves can address at most205*204=41820 records, below one million. Three index levels can address205*205*204=8573100 records, so the minimum tree has three levels. With nothing cached, fetch root, internal node and leaf, then the separate record block: 4 disk accesses. This is the conventional separate-record B+ index layout; the record itself is not stored inline in the leaf.
