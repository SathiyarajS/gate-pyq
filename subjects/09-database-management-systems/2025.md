

# GATE 2025 CS1: Q15

**Question:** [Official archived paper page 15](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=15); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** A database schedule is R1(X), W1(Y), R2(X), R2(Y), R3(Y), followed by ABORT(T1). No intervening commit or write is shown. Which other transactions must roll back? A only T2; B only T3; C both T2 and T3; D neither.

## Solution

Approach: Track reads of a value produced by an uncommitted transaction; read-read overlap alone is not a rollback dependency.
W1(Y) installs T1’s new value of Y. R2(Y) occurs after that write and before T1 commits, so T2 reads an uncommitted value from T1. R3(Y) sees the same value because no intervening write to Y is shown; T3 also depends on T1.
When T1 aborts, its write to Y must be undone. Both dependent transactions have computed using a value that cannot be retained, so both must roll back. This is a cascading rollback and gives C.
The reads R1(X) and R2(X) do not establish a dirty-read dependency because neither transaction writes X in this schedule. The important issue is which transaction produced the value read, not simply whether two transactions access the same data item.

# GATE 2025 CS1: Q21

**Question:** [Official archived paper page 21](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=21); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** B;D

**Derived answer:** B;D

**Paraphrased problem context:** A pictured B+ tree has a root with keys [6,12,19] and four leaf children, shown left to right as [1,4,3], [7,9,10], [13,15,17], [20,21,22]. Each node holds at most three keys, and there are five nodes initially. Insert 23 using ordinary B+ tree insertion. Which statements hold? A no node splits; B at least one node splits and redistributes; C node count stays unchanged; D height increases. The unsorted first leaf [1,4,3] is reproduced literally, not silently repaired.

## Solution

Approach: Follow the insertion path and propagate any overflow upward.
Because 23 exceeds the largest root separator, it routes to the rightmost leaf [20,21,22]. Adding it produces four keys in a node whose capacity is three. This leaf must split into two leaves under the ordinary insertion algorithm; for example its data can be distributed as [20,21] and [22,23]. A separator for the new leaf is inserted into the parent.
The parent is the root and is already full with three keys. Its overflow requires an internal-node split and a new root above the split pieces. Thus the height increases by one. B and D are true, while A and C are false. The usual allocation adds one leaf, one internal node and one new root, raising five nodes to eight.
Source qualification: the printed first leaf is unsorted, so the figure is not literally a valid B+ tree. Separator conventions also are not fully specified. The intended overflow argument uses the unaffected rightmost branch and assumes a valid initial tree apart from the diagram defect. The official B;D answer is preserved, with that limitation explicit.

**Question:** [Official archived paper page 39](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=39); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** Relations are teams(tid,tname) and players(pid,pname,tid). Return names of players on a team named MI. A {p.pname | p∈players ∧ ∃t(t∈teams ∧ p.tid=t.tid ∧ t.tname='MI')}; B the same expression but p∈teams and t∈players; C the expression in A without p.tid=t.tid; D the expression in B without p.tid=t.tid. Which is correct?

## Solution

Approach: Translate the desired result into tuple bindings, a join predicate, a selection predicate and a projected attribute.
A returned name must come from a player tuple, so bind p to players. There must exist a team tuple t whose id equals the player’s team id, giving t∈teams and p.tid=t.tid. The selected team must have t.tname='MI'. Project p.pname from precisely those player tuples. These requirements combine exactly as A.
B and D bind p to teams even though teams has no pname attribute, and bind t to players even though players has no tname attribute. They are not correctly typed for the supplied schemas.
C has the right bindings but omits the join. If any team is called MI, its existential condition becomes true for every player, including players on other teams. That illustrates why a selection on team name does not replace the relationship connecting a player to that team.

# GATE 2025 CS1: Q47

**Question:** [Official archived paper page 47](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=47); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** B;C

**Derived answer:** B;C

**Paraphrased problem context:** Schema team(name,city,owner) has dependencies name→city and name→owner, and is decomposed into t1(name,city),t2(name,owner). Select true statements: A team is not BCNF; B both components are BCNF; C the join is lossless; D team is not 3NF.

## Solution

Approach: Find the key, check the determinants of nontrivial dependencies, then use the binary lossless-join criterion.
The closure of {name} contains name, city and owner, so name is a key of team. All nontrivial given dependencies, and their relevant nontrivial consequences, have a determinant containing that key. Therefore team is BCNF. Since BCNF implies 3NF, A and D are false.
In t1, name determines city; in t2, name determines owner. Thus name is also a key of each component and both are BCNF, making B true.
The common attribute set is t1∩t2={name}. It determines all attributes of t1 and also all attributes of t2. In particular it satisfies the binary lossless-join condition that the intersection determine one component. Therefore joining the projections cannot create spurious combinations for any original instance satisfying the dependencies, making C true.
Select B,C. Decomposition is not needed to fix a normal-form violation here; it is nevertheless lossless, and the listed dependencies are also retained in the separate components.

**Paraphrased problem context:** Tables: player(pid,pname,age) has (1,Jasprit,31),(2,Atharva,24),(3,Ishan,26),(4,Axar,30). coach(cid,cname) has (101,Ricky),(102,Mark),(103,Trevor). team(tid,tname,city,cid) has (10,MI,Mumbai,102),(20,DC,Delhi,101),(30,PK,Mohali,103). members(pid,tid) has (1,10),(2,30),(3,10),(4,20). Evaluate SELECT MIN(P.age) FROM player P WHERE P.pid IN (SELECT M.pid FROM team T,coach C,members M WHERE C.cname='Mark' AND T.cid=C.cid AND M.tid=T.tid).

## Solution

Approach: Evaluate the inner join and filter to get a set of player IDs, then apply the outer aggregate only to those players.
The condition C.cname='Mark' selects coach row cid=102. Joining on T.cid=C.cid selects team tid=10, because that is the team coached by 102. Joining membership on M.tid=T.tid then selects the rows (1,10) and (3,10), so the subquery returns player IDs {1,3}.
The outer WHERE P.pid IN (...) retains Jasprit, age 31, and Ishan, age 26. MIN over those two ages is 26, which is the returned value.
Atharva’s age 24 is smaller overall but belongs to team 30 coached by Trevor; the predicate removes that row before MIN is computed. Axar likewise belongs to team 20 coached by Ricky. This demonstrates why aggregating over the entire player table before applying the team/coach restriction would be incorrect. All displayed rows were visually verified against the source table.

# GATE 2025 CS2: Q27

**Question:** [Official archived paper page 22](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=22); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** B;C

**Derived answer:** B;C

**Paraphrased problem context:** Two joint holders simultaneously transfer ₹10000 each from account A to B. Both transactions read A's initial balance as ₹11000 and are allowed to finish. B receives two ₹10000 credits, but A is debited only once and ends at ₹1000. Which ACID properties are certainly violated?
Options: A. atomicity; B. consistency; C. isolation; D. durability.

## Solution

A typical interleaving is: T1 reads A=11000; T2 reads A=11000; each computes 11000−10000=1000; T1 writes A=1000 and T2 overwrites it with the same value. Both credits to B survive. This is a lost update.

Isolation fails because the result is not equivalent to executing the two valid transfers serially. After the first transfer, a serial second transaction would observe A=1000, not the original 11000; it could be rejected for insufficient funds or, if overdraft were permitted, debit to −9000. Neither serial behavior produces the reported one-debit/two-credit result.

Consistency also fails: A decreases by only 10000 while B increases by 20000, so the transfer has created 10000 of aggregate balance rather than conserving it. Atomicity need not fail: both transactions may have executed all their own read/write steps and committed, with the race occurring between otherwise complete transactions. Durability is about retaining committed results despite later failures, and no such loss after a failure is described. Thus only B and C are certain.

# GATE 2025 CS2: Q46

**Question:** [Official archived paper page 35](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=35); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** C;D

**Derived answer:** C;D

**Paraphrased problem context:** Relations have the following complete sets of functional dependencies:
R1(A,B,C,D,E): D→E, EA→B, EB→C.
R2(A,B,C,D): A→D, A→B, C→A.
Select true assertions: A. R1 is in 3NF; B. R2 is in 3NF; C. R1 is not in 3NF; D. R2 is not in 3NF.

## Solution

For 3NF, every nontrivial dependency X→Y must have X a superkey or each right-hand attribute prime, meaning it belongs to some candidate key. Identify the keys before applying this test.

In R1, A and D never appear on any right-hand side, so neither can be obtained from other attributes and every key must contain both. Compute (AD)+: start with A,D; D→E adds E; EA→B adds B; EB→C adds C. Thus AD determines all five attributes and is the unique candidate key. Only A,D are prime. The dependency D→E violates 3NF: D+=DE is not a superkey and E is nonprime. Hence R1 is not in 3NF.

In R2, C never appears on a right-hand side and must belong to every key. C→A, followed by A→D and A→B, gives C+=ABCD, so C alone is the unique candidate key. A is not a superkey, since A+=ABD lacks C, and D,B are nonprime. Either A→D or A→B therefore violates 3NF. R2 is not in 3NF either. Select C,D.

# GATE 2025 CS2: Q53

**Question:** [Official archived paper page 41](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=41); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** R_i(V) and W_i(V) denote transaction i reading/writing item V; C_i is its commit. Select all conflict-serializable schedules.
A. R1(X),W2(X),W1(Y),W2(Y),R1(X),W1(X),C2,C1.
B. W2(X),R1(X),W2(Y),W1(Y),R1(X),C2,W1(X),C1.
C. R1(X),W1(Y),W2(X),W2(Y),R1(X),W1(X),C1,C2.
D. W2(X),R1(X),W1(Y),W2(Y),R1(X),C2,W1(X),C1.

## Solution

Construct a precedence graph with vertices T1,T2. Two operations conflict when they are in different transactions, access the same item, and at least one is a write. An earlier conflicting operation from Ti followed by one from Tj creates edge Ti→Tj. The schedule is conflict-serializable exactly when this graph is acyclic.

In A, the first R1(X) precedes W2(X), giving T1→T2. The later R1(X), and also W1(X), follow W2(X), giving T2→T1. There is a cycle. C has the same two conflicting directions on X, so it also fails.

In B, W2(X) precedes both reads and the write of X by T1. On Y, W2(Y) precedes W1(Y). Thus all intertransaction conflicts point T2→T1; there is no reverse edge. This is conflict-equivalent to serial order T2 followed by T1.

In D, the X conflicts point T2→T1, but W1(Y) precedes W2(Y), adding T1→T2 and creating a cycle. Commit positions do not remove conflicts or make a cyclic precedence graph acyclic. Select B only. Conflict serializability is a property distinct from whether an interleaving satisfies a particular recovery or locking protocol.

# GATE 2025 CS2: Q54

**Question:** [Official archived paper page 42](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=42); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A;C;D

**Derived answer:** A;C;D

**Paraphrased problem context:** Schema: Students(rollno,name,age,cgpa), Courses(courseno,cname,credits), Enrolled(rollno,courseno,grade). Primary keys are Students.rollno, Courses.courseno, and the composite Enrolled(rollno,courseno). Which SQL queries retrieve names of students enrolled in course 1470?
A. SELECT S.name FROM Students S WHERE EXISTS (SELECT * FROM Enrolled E WHERE E.courseno=1470 AND E.rollno=S.rollno);
B. SELECT S.name FROM Students S WHERE SIZEOF (SELECT * FROM Enrolled E WHERE E.courseno=1470 AND E.rollno=S.rollno)>0;
C. SELECT S.name FROM Students S WHERE 0 < (SELECT COUNT(*) FROM Enrolled E WHERE E.courseno=1470 AND E.rollno=S.rollno);
D. SELECT S.name FROM Students S NATURAL JOIN Enrolled E WHERE E.courseno=1470;

## Solution

A's correlated subquery considers enrollment rows for the current student's rollno and the requested course. EXISTS is true exactly when at least one such row exists, so A returns the desired name.

C tests the same correlated set. COUNT(*) returns a scalar count, including zero when no enrollment matches. The condition 0<count is therefore equivalent to existence, so C is also valid. B tries to use SIZEOF(subquery), which is not the standard SQL operator for counting a query result; COUNT(*) is the relevant aggregate.

For D, the only shared attribute name between Students and Enrolled is rollno, so NATURAL JOIN equates those roll numbers. Filtering the joined row by courseno=1470 selects enrolled students and projecting S.name gives their names. Thus D is the intended third valid query; Courses is unnecessary because the required course number is already stored in Enrolled.

The source marks (rollno,courseno) as Enrolled's composite primary key, so at most one enrollment can match a given student and course. D therefore has the same per-student-row multiplicity as A/C. Different students may share a name, and none of these queries removes such duplicate names. Without the composite-key constraint, a join could repeat a name per matching enrollment, but that is not the stated schema. The correct selection is A,C,D.

# GATE 2025 CS2: Q57

**Question:** [Official archived paper page 43](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=43); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 33 to 33

**Derived answer:** 33

**Paraphrased problem context:** A B+ tree node holds at most four keys. One root-to-leaf path is A=(49,77,83,−), B=(7,19,33,44), C=(20*,22*,25*,26*), where stars mark leaf data entries. A pointer between separators k1,k2 covers [k1,k2), and a newly created leaf copies its smallest key into its parent. Insert key 23. What is the smallest separator key in the parent of the resulting leaf that contains 25*?

## Solution

The insertion belongs in C because 19≤23<33. Its sorted data entries become [20*,22*,23*,25*,26*], exceeding the four-key limit, so C splits. With a 2/3 split, the leaves are [20*,22*] and [23*,25*,26*], and separator 23 is copied up. With a 3/2 split, they are [20*,22*,23*] and [25*,26*], and separator 25 is copied up. Let k be that copied separator, either 23 or 25.

B was already full. After receiving k, its ordered separators are [7,19,k,33,44], so B must split as well. For an internal-node split, the middle separator k is promoted to A rather than kept as a key in either split internal node. The left internal node retains [7,19], and the right retains [33,44]. The leaf holding 25* is on the right side of k and is a child of this right internal node.

Consequently its parent's smallest stored key is 33, even though that parent has a leftmost child whose values can be smaller than 33. A had spare capacity, so receiving k causes no further split. The unspecified 2/3 versus 3/2 leaf convention does not change the requested answer: 33.
