**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** Assess two claims: I strict two-phase locking generates conflict-serializable and recoverable schedules; II timestamp ordering with Thomas's Write Rule can generate view-serializable schedules that are not conflict-serializable. Choices: A I only; B II only; C both; D neither.

## Solution

Method: separate the ordering guarantee of locking from the weaker observational guarantee allowed by ignoring obsolete writes.

1. In two-phase locking, a transaction first acquires locks and then releases them; it cannot acquire a new lock after releasing one. Ordering transactions by their lock points yields an order consistent with their conflicting operations. Hence 2PL gives conflict serializability.
2. Strict 2PL additionally retains exclusive locks until commit or abort. A second transaction cannot read a value written by the first before that writer commits, so it cannot commit while depending on an uncommitted writer. This prevents cascading dirty reads and implies recoverability. Thus I is true.
3. Thomas's Write Rule modifies timestamp ordering: if a proposed write is older than an already recorded write timestamp, and the relevant read-timestamp check does not require abort, that obsolete write can be ignored. It need not replace the newer value.
4. Ignoring such a write can preserve every transaction's observed reads and the appropriate final writes even where the logical ordering of conflicting write requests cannot be rearranged by conflict-equivalent swaps. View serializability preserves those observations and final writers, whereas conflict serializability imposes the stronger pairwise-operation ordering condition. Thus Thomas's rule can admit view-serializable schedules beyond conflict serializability, making II true.

Result: C, both statements. Recoverability and serializability are distinct properties; the first follows here from strict locking, not merely from conflict serializability alone.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** Which statement about a B+ tree index is incorrect? A it is height-balanced; B non-leaf nodes have pointers to data records; C each node's keys are sorted; D each leaf has a pointer to the next leaf.

## Solution

Method: distinguish routing information in internal nodes from data entries at leaves.

1. A B+ tree keeps all leaves at the same depth, giving a balanced search height. Thus A describes the standard structure correctly.
2. An internal node contains separator keys and child-node pointers. Comparing a search key against the separators chooses the child subtree that may contain the record. Those pointers lead to more index nodes, not directly to the table's data records.
3. Data entries or record references occur at the leaves. Therefore B assigns a leaf responsibility to non-leaf nodes and is the incorrect statement.
4. Sorted keys let a node determine the correct child or locate the leaf entry, so C is correct. Linking leaves supports ordered scans and range queries without repeatedly returning to the root, so D is the usual leaf-link property; the last leaf's next pointer is null.

Result: B. This leaf-focused record organization is a key distinction between a B+ tree and a B-tree variant that may keep records in internal nodes.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** On X(P,Q,R,S), F={QR→S, R→P, S→Q}. Decompose X into Y(P,R) and Z(Q,R,S). Test I: both components are BCNF; II: the decomposition is lossless and dependency preserving. Options A both, B I only, C II only, D neither.

## Solution

1. BCNF requires the determinant of every nontrivial functional dependency to be a superkey. In Y, R→P gives R+={R,P}, so R is a key and Y is in BCNF.
2. In Z, S→Q still holds. But S+ within Z is only {S,Q}; no dependency derives R. Thus S is not a superkey and this nontrivial dependency violates BCNF. Statement I is false.
3. Dependency preservation asks whether enforcing dependencies locally suffices for the original F. R→P can be checked in Y; QR→S and S→Q can both be checked in Z. All original dependencies survive, so preservation holds.
4. For a binary decomposition, losslessness follows if the intersection functionally determines either component. Y∩Z={R}, and R→PR means the intersection determines Y. Joining valid projections therefore introduces no spurious tuples.
5. Both parts of II hold, so II alone is true: C. Losslessness and dependency preservation are distinct tests; neither implies that every resulting relation must satisfy BCNF.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 5 to 5

**Derived answer:** 5

**Paraphrased problem context:** Student rows (Roll_no,Student_name) are (1,Amit),(2,Priya),(3,Vinit),(4,Rohan),(5,Smita). Performance rows (Roll_no,Subject_code,Marks) are (1,A,86),(1,B,95),(1,C,90),(2,A,89),(2,C,92),(3,C,80). Student key is Roll_no and Performance key is (Roll_no,Subject_code). Query: SELECT S.Student_name, sum(P.Marks) FROM Student S, Performance P WHERE P.Marks>84 GROUP BY S.Student_name. How many rows result?

## Solution

1. Read the actual WHERE clause before inferring the intended relationship. It contains P.Marks>84 but no condition S.Roll_no=P.Roll_no. Listing both tables in FROM therefore forms their Cartesian product, not a join on the similarly named columns.
2. Five Performance rows pass the filter: marks 86,95,90,89,92. The 80-mark row is excluded. Each of the five Student rows pairs with every one of these five surviving rows, yielding 25 intermediate rows.
3. GROUP BY S.Student_name partitions those rows by the five distinct student names. Each group has five rows and the same marks sum: 86+95+90+89+92=452.
4. The result is (Amit,452), (Priya,452), (Vinit,452), (Rohan,452), (Smita,452), in unspecified order. Hence the requested row count is 5.
5. Rohan and Smita are included even though they have no Performance records: the query never correlates a performance with its owner. Primary keys do not automatically add a join predicate. Adding that missing predicate would answer a different query and must not be silently done.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 1 to 1

**Derived answer:** 1

**Paraphrased problem context:** Relations: P(X,Y,Z)={(X1,Y1,Z1),(X1,Y1,Z2),(X2,Y2,Z2),(X2,Y4,Z4)}; Q(X,Y,T)={(X2,Y1,2),(X1,Y2,5),(X1,Y1,6),(X3,Y3,1)}; R(Y,V)={(Y1,V1),(Y3,V2),(Y2,V3),(Y2,V2)}. Count tuples in π_X(σ_{P.Y=R.Y and R.V=V2}(P×R)) − π_X(σ_{Q.Y=R.Y and Q.T>2}(Q×R)).

## Solution

1. Evaluate the two projected sets separately before subtracting them. The left selection is an equality join on Y with the additional restriction R.V=V2.
2. Restricting R to V2 leaves (Y3,V2) and (Y2,V2). P has no Y3 tuple and has exactly one Y2 tuple, (X2,Y2,Z2). Thus the left join contributes X2 and its projection is {X2}. P's Y1 and Y4 rows fail the selection.
3. On the right, first keep Q rows with T>2: (X1,Y2,5) and (X1,Y1,6). The rows with T=2 and T=1 are excluded by the strict inequality.
4. The surviving Y2 row matches two R rows, with V3 and V2; the Y1 row matches (Y1,V1). These three join tuples all carry X1. Relational-algebra projection removes duplicates, so the right projected set is {X1}, not three copies of X1.
5. Set difference keeps left-side tuples absent from the right side: {X2}−{X1}={X2}. The result contains exactly 1 tuple.
6. Difference is directional and is not subtraction of the two row counts. Also, relational algebra uses set projection here; SQL without DISTINCT would require separate attention to bag semantics.
