**Official answer:** Not available; no official key located.

**Independently derived answer:** D

## Solution

If T2 reads data written by uncommitted T1, then T2 commits before T1 aborts, the schedule is nonrecoverable: a committed transaction depended on an aborted value. Thus D may lead to the stated error. A dirty read alone does not always force irrecoverability; delaying dependent commits can permit cascading rollback.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

## Solution

Restrict the listed dependencies to R(Roll_number,Name,Date_of_birth,Age). They give Roll_number→Name, Name→Roll_number, and Date_of_birth→Age. Neither Name nor Roll_number determines Date_of_birth under this stated set. The candidate keys are therefore {Roll_number,Date_of_birth} and {Name,Date_of_birth}; Age is nonprime and depends on the proper key subset Date_of_birth. This violates 2NF, so the literal listed-dependency answer is D, none of the first three choices. If one additionally assumes Roll_number→Date_of_birth because roll numbers identify complete student records, Name and Roll_number become single-attribute keys and the relation is 2NF but not 3NF owing to Date_of_birth→Age, yielding A. That extra dependency is not supplied and must be labelled as an assumption.

# GATE 2003: Q87 (printed CS Q87)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=13), physical page 13. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

## Solution

On D1, T1 writes before T2 reads/writes, imposing T1→T2. On D2, T2 writes before T3 reads/writes, and T3 writes before T1 reads/writes, imposing T2→T3→T1. This cycle rules out conflict serializability, so D. It also rules out view serializability here: T2 reads the initial D2 value, T3 reads T2's D2 value, T1 reads T3's D2 value, and T2 reads T1's D1 value. Any view-equivalent serial order would need T2 before T3 before T1 before T2, which is impossible.
