

# GATE 2003: Q29 (printed CS Q29)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=4), physical page 4. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Which operation may lead to an irrecoverable database error? A. Writing an item after an uncommitted transaction reads it; B. Reading an item after an uncommitted transaction reads it; C. Reading an item written by a committed transaction; D. Reading an item written by an uncommitted transaction.

## Solution

1. Use the concrete schedule W₁(X), R₂(X), C₂, A₁. Transaction 2 has already committed a result based on transaction 1’s value when transaction 1 aborts. Recovery would need to undo a committed dependency, which is why the schedule is nonrecoverable. The word “may” matters: a dirty read need not always lead to such a commit order.

2. If T 2 reads data written by uncommitted T 1, then T 2 commits before T 1 aborts, the schedule is nonrecoverable: a committed transaction depended on an aborted value. Thus D may lead to the stated error. A dirty read alone does not always force irrecoverability; delaying dependent commits can permit cascading rollback.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Translate SELECT DISTINCT a₁,a₂,...,aₙ FROM r₁,r₂,...,rₘ WHERE P into classical relational algebra. Every option first applies selection σ_P and then projection π_(a₁,...,aₙ). Their innermost operation is: A. r₁×r₂×...×rₘ; B. r₁⋈r₂⋈...⋈rₘ; C. r₁∪r₂∪...∪rₘ; D. r₁∩r₂∩...∩rₘ.

## Solution

1. FROM first chooses every combination of one tuple from each relation. WHERE then keeps only combinations satisfying P. Finally SELECT chooses attributes, and DISTINCT removes repeated projected tuples. A natural join would additionally impose equality on common-named columns, which this arbitrary SQL query does not necessarily request.

2. The comma-separated FROM clause forms the Cartesian product of all relations, WHERE applies selection σ_P, and SELECT DISTINCT applies set projection onto the listed attributes. Thus π_attributes(σ_P(r 1×...×rm)), A, with attribute renaming/qualification as required and the classical relational-algebra interpretation.

# GATE 2003: Q85 (printed CS Q85)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** The database functional dependencies are Date_of_birth→Age; Age→Eligibility; Name→Roll_number; Roll_number→Name; Course_number→Course_name; Course_number→Instructor; (Roll_number,Course_number)→Grade. Classify relation R(Roll_number,Name,Date_of_birth,Age):
A. In 2NF but not 3NF
B. In 3NF but not BCNF
C. In BCNF
D. None of the above
Use only the listed dependencies unless an additional identifying dependency is explicitly assumed.

## Solution

1. Project the dependencies onto R. The relevant nontrivial ones are Roll_number→Name, Name→Roll_number and Date_of_birth→Age. No listed rule determines Date_of_birth from Roll_number or Name.
2. The closure of {Roll_number,Date_of_birth} contains all four attributes, and removing either attribute loses information. Likewise {Name,Date_of_birth} is a candidate key. Roll_number and Name alone are not keys under the stated dependency set.
3. Age is nonprime and depends on Date_of_birth, a proper subset of each composite candidate key. This is a partial dependency violating 2NF. Therefore none of A–C holds; D is the literal answer.
4. If one additionally assumes Roll_number→Date_of_birth, a single-attribute identifying key results and the usual 2NF-but-not-3NF answer A follows. The source does not supply that extra dependency, so it is a separate conditional interpretation.

Baseline derivation and caveats (retained): Restrict the listed dependencies to R(Roll_number,Name,Date_of_birth,Age). They give Roll_number→Name, Name→Roll_number, and Date_of_birth→Age. Neither Name nor Roll_number determines Date_of_birth under this stated set. The candidate keys are therefore {Roll_number,Date_of_birth} and {Name,Date_of_birth}; Age is nonprime and depends on the proper key subset Date_of_birth. This violates 2NF, so the literal listed-dependency answer is D, none of the first three choices. If one additionally assumes Roll_number→Date_of_birth because roll numbers identify complete student records, Name and Roll_number become single-attribute keys and the relation is 2NF but not 3NF owing to Date_of_birth→Age, yielding A. That extra dependency is not supplied and must be labelled as an assumption.

# GATE 2003: Q86 (printed CS Q86)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Relations are Students(Roll_number,Name,Date_of_birth), Courses(Course_number,Course_name,Instructor), and Grades(Roll_number,Course_number,Grade). Interpret this query with the printed string constants rendered in SQL quotes:
SELECT DISTINCT Name
FROM Students,Courses,Grades
WHERE Students.Roll_number=Grades.Roll_number
  AND Courses.Instructor='Korth'
  AND Courses.Course_number=Grades.Course_number
  AND Grades.Grade='A';
What set is computed?
A. Students' names with A in all courses taught by Korth
B. Students' names with A in all courses
C. Students' names with A in at least one course taught by Korth
D. None of the above

## Solution

1. The Roll_number equality pairs each student with that student's grade records. The Course_number equality pairs each grade with its course.
2. The two filters discard any joined row whose instructor is not Korth or whose grade is not A. Every surviving row therefore witnesses one qualifying course for that student.
3. Projection selects the name and DISTINCT removes repeated names when several qualifying rows exist. It does not test unselected rows or require every course to qualify.
4. Thus a student appears if at least one qualifying Korth-course A exists, C. Requiring all such courses would need a different universal/anti-existence/division construction.

Baseline derivation and caveats (retained): The joins connect each student to their grade records and the corresponding courses. The filters retain records having grade A in a course taught by Korth. A student's name is produced whenever at least one such joined record exists, and DISTINCT removes duplicate names. There is no universal quantifier, division, or count comparison requiring all courses to qualify. The intended relational query therefore computes option C, names of students with an A in at least one course taught by Korth.

# GATE 2003: Q87 (printed CS Q87)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=13), physical page 13. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Three transactions act on D1,D2,D3. In chronological order the printed schedule is:
R2(D3), R2(D2), W2(D2), R3(D2), R3(D3), R1(D1), W1(D1), W3(D2), W3(D3), R2(D1), R1(D2), W1(D2), W2(D1).
Ri(D) and Wi(D) denote transaction Ti reading/writing D. Which is correct?
A. Serializable as T2,T3,T1
B. Serializable as T2,T1,T3
C. Serializable as T3,T2,T1
D. Not serializable

## Solution

1. On D1, T1 writes before T2 reads and writes, forcing edge T1→T2 in the conflict graph.
2. On D2, T2 writes before T3 reads/writes, forcing T2→T3; T3 writes before T1 reads/writes, forcing T3→T1. These edges already form T1→T2→T3→T1.
3. A directed cycle means no serial ordering can preserve all conflicts, so the schedule is not conflict-serializable.
4. Even view equivalence cannot rescue it: T2's D2 read is initial, T3 reads T2's D2 write, T1 reads T3's D2 write, and T2 reads T1's D1 write. Preserving these reads requires T2<T3<T1<T2, impossible. Therefore D holds even under the broader view-serializability interpretation.

Baseline derivation and caveats (retained): On D1, T1 writes before T2 reads/writes, imposing T1→T2. On D2, T2 writes before T3 reads/writes, and T3 writes before T1 reads/writes, imposing T2→T3→T1. This cycle rules out conflict serializability, so D. It also rules out view serializability here: T2 reads the initial D2 value, T3 reads T2's D2 value, T1 reads T3's D2 value, and T2 reads T1's D1 value. Any view-equivalent serial order would need T2 before T3 before T1 before T2, which is impossible.
