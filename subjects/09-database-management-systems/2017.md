

# GATE 2017 CS2: Q27 (printed CS Q17)

**Question:** [Official archived paper page 7](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C under nonnullable merge convention

**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

For a many-to-one relationship, each A entity has at most one B partner, so a B key can be stored in the A row. Total participation guarantees that key exists for every row, giving intended C without nulls. If nullable foreign keys are allowed, partial participation can also be represented in A, making D feasible too. Therefore the unique official answer assumes the conventional null-free relationship-table merge criterion.

# GATE 2017 CS2: Q54 (printed CS Q44)

**Question:** [Official archived paper page 18](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 54.0 to 54.0

**Derived answer:** 54

**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

Only Y is shared. A precedence edge T1→T2 exists when a conflicting Y operation of T1 precedes one of T2, and vice versa. Acyclic schedules must put both Y operations of one transaction before both of the other. There are C(8, 4)=70 order-preserving interleavings. T1 before T2 requires all four T1 operations before T2 starts, giving1 schedule. T2 before T1 requires its second operation before T1’s third. The opposite event has T1’s third operation in position3 or4: 5 completions for prefix111, and 3*4=12 completions with its third1 at position4. Thus53 schedules satisfy T2 before T1. Total 1+53=54. An independent enumeration of all70 interleavings gives the same count.

**Official answer:** 2.6 to 2.6

**Derived answer:** 2.6 under intended grouped-table query

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

## Solution

The department counts are 4, 3, 3, 2, 1; their average is 13/5=2.6. This is the official intended result. The printed SQL is malformed: EC is referenced in the outer FROM without being defined as a CTE/derived table, while AS EC(DeptName, Num) is attached inside the SELECT list after COUNT. A corrected query defines EC as SELECT DeptName, COUNT(EmpId) AS Num FROM EMP GROUP BY DeptName and then averages EC.Num. The literal displayed query is not standard executable SQL.

# GATE 2017 CS1: Q51 (printed CS Q41)

**Question:** [Official archived paper page 18](https://web.archive.org/web/20170712112248id_/http://www.gate.iitg.ac.in:80/2017questions/CS1.pdf#page=18); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** D

**Derived answer:** Only III under unrestricted-domain TRC; official D under active-domain restriction

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

## Solution

The result tuple t is not itself bound to EMP. Query III bounds its name by an EMP tuple and its department by a DEPT tuple, so it has finite domain-independent results. In I and II, a department value outside the database can satisfy the inequality. For example, take EMP={(Alice, 1)} and DEPT={1}; every outside department value paired with Alice satisfies both I and II. These queries therefore admit infinitely many results over an unrestricted infinite domain and are unsafe. Only III is safe under classical unrestricted-domain tuple calculus, but that selection is absent. Official D (all three) requires an implicit finite active-domain restriction on t. The allowance of NULL in EMP does not bind t or repair this safety problem.
