

# GATE 2017 CS2: Q27 (printed CS Q17)

**Question:** [Official archived paper page 7](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C under nonnullable merge convention

**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** In an ER model, entity types A and B are related by R, which has no attributes of its own. When can the relational table for R be merged into A? A:R is one-to-many and A participates totally. B:one-to-many and A participates partially. C:many-to-one and A participates totally. D:many-to-one and A participates partially. Cardinalities are read from A to B.

## Solution

1. Merging R into A means representing an A entity's partner by storing a B key in its row, instead of using a separate relationship row. A single such field can represent at most one B partner for each A. Thus the appropriate direction is many A entities to one B entity, not one A to many B entities.

2. Under the conventional null-free merge rule, every A must have a partner so that each A row has a valid B key. Total participation provides this guarantee. These two conditions yield the intended option C.

3. The wording leaves a modeling caveat: with nullable foreign keys, an A that does not participate can use NULL, so many-to-one with partial participation, D, can also be represented in A. Official C is retained under the nonnullable conventional criterion rather than treating D as impossible in SQL generally.

**Derived answer:** 0

**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** T1(P,Q) contains (2,2),(3,8),(7,3),(5,8),(6,9),(8,5),(9,8). T2(R,S) contains (2,2),(8,3),(3,2),(9,7),(5,7),(7,2). P and R are their primary keys. T1.Q references T2.R with ON DELETE CASCADE and ON UPDATE CASCADE. T2.S references T1.P with ON DELETE SET NULL and ON UPDATE CASCADE. Delete (3,8) from T1. How many additional T1 records must be deleted?

## Solution

1. Follow the incoming foreign-key references to the deleted key P=3. In T2, only row (R=8,S=3) references this value through S. Its specified action is ON DELETE SET NULL, so it becomes (8,NULL).

2. Crucially, this action neither deletes the T2 row nor changes its primary key R=8. The references from T1.Q to T2.R remain valid, including Q=8 values in other T1 rows.

3. T1's ON DELETE CASCADE would apply if a referenced T2 row were deleted; that has not happened. Nor has a referenced primary key been updated. Thus no cascade returns to T1 and the number of additional deletions is 0. A change to a foreign-key field is not automatically a change to the key referenced by the opposite table.

# GATE 2017 CS2: Q54 (printed CS Q44)

**Question:** [Official archived paper page 18](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 54.0 to 54.0

**Derived answer:** 54

**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Transactions are T1:r1(X),w1(X),r1(Y),w1(Y) and T2:r2(Y),w2(Y),r2(Z),w2(Z). Here r and w denote read and write operations. How many order-preserving interleavings of the eight operations are conflict serializable?

## Solution

1. Each schedule is an interleaving of four operations from each transaction, so there are C(8,4)=70 candidates. Only Y is shared; read/write or write/write pairs on Y create precedence-graph edges. A schedule is serializable precisely when it does not create edges in both directions.

2. For order T1→T2, w1(Y) must precede r2(Y). Since these are respectively the last T1 and first T2 operations, this requires the single serial schedule 11112222, where digits identify transactions.

3. For order T2→T1, w2(Y) must precede r1(Y): the second 2 must occur before the third 1. Count its complement, third 1 before second 2. If the third 1 occurs at position 3, the prefix is 111 and the last 1 has 5 possible positions. If it occurs at position 4, the first three positions contain two 1s and one 2 in 3 arrangements, and the final 1 has 4 positions. The complement has 5+12=17 schedules, so this serial order has 70-17=53.

4. The two acyclic cases are disjoint, yielding 1+53=54. This counts conflict serializability, not only the two fully serial schedules. Independent enumeration of all 70 order-preserving interleavings confirms the count.

**Paraphrased problem context:** top_scorer(player,country,goals) rows: Klose,Germany,16; Ronaldo,Brazil,15; G Müller,Germany,14; Fontaine,France,13; Pelé,Brazil,12; Klinsmann,Germany,11; Kocsis,Hungary,11; Batistuta,Argentina,10; Cubillas,Peru,10; Lato,Poland,10; Lineker,England,10; T Müller,Germany,10; Rahn,Germany,10. Query: SELECT ta.player FROM top_scorer AS ta WHERE ta.goals > ALL (SELECT tb.goals FROM top_scorer AS tb WHERE tb.country='Spain') AND ta.goals > ANY (SELECT tc.goals FROM top_scorer AS tc WHERE tc.country='Germany'). How many tuples result?

## Solution

1. The Spain subquery returns no rows. A comparison quantified by ALL over an empty set is true, because there is no counterexample. Hence the first predicate eliminates none of the outer rows.

2. The Germany subquery returns goals 16,14,11,10,10. The >ANY condition requires exceeding at least one of them, so with these non-NULL values it is equivalent to goals>10, not goals>16.

3. Seven rows have goal counts above 10: 16,15,14,13,12,11,11. They yield Klose,Ronaldo,G Müller,Fontaine,Pelé,Klinsmann,Kocsis, so the result has 7 tuples. The query does not say DISTINCT, but these seven selected player values are distinct anyway. Empty ALL and empty ANY behave differently.

**Question:** [Official archived paper page 9](https://web.archive.org/web/20170712112248id_/http://www.gate.iitg.ac.in:80/2017questions/CS1.pdf#page=9); consult original wording, diagrams and choices.

**Official answer:** A

**Derived answer:** A

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

**Paraphrased problem context:** R(V,W,X,Y,Z) has dependencies V→W, VW→X, Y→VX, Y→Z. Choose an irreducible equivalent set. A {V→W,V→X,Y→V,Y→Z}; B {V→W,W→X,Y→V,Y→Z}; C {V→W,V→X,Y→V,Y→X,Y→Z}; D {V→W,W→X,Y→V,Y→X,Y→Z}.

## Solution

1. First split Y→VX into Y→V and Y→X, so every right-hand side is a singleton.

2. From V→W, knowing V gives both V and W; VW→X then gives X. Therefore W is extraneous in the left side of VW→X, and we replace it by V→X.

3. Now Y→X is implied by Y→V and V→X and can be removed. None of V→W,V→X,Y→V,Y→Z follows from the other three. This is A; C is equivalent but not irreducible.

**Official answer:** 2.6 to 2.6

**Derived answer:** 2.6 under intended grouped-table query

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

**Paraphrased problem context:** EMP(EmpId,EmpName,DeptName) has rows with IDs 1 through 13, names XYA through XYM, and departments AA,AA,AA,AA,AB,AB,AB,AC,AC,AC,AD,AD,AE respectively. The source SQL is:
SELECT AVG(EC.Num) FROM EC WHERE (DeptName, Num) IN
(SELECT DeptName, COUNT(EmpId) AS EC(DeptName, Num) FROM EMP GROUP BY DeptName)
Find its output. This unusual source syntax is retained; the solution distinguishes the intended aggregate from the literal SQL.

## Solution

1. For the intended group operation, collect all rows with equal DeptName. The counts are AA:4, AB:3, AC:3, AD:2, AE:1.

2. AVG must average these five group counts, not average EmpId values or take an ungrouped COUNT. Their sum is 13, so the average is 13/5=2.6.

3. That derives the official intended numeric answer, but not an execution of the literal SQL. EC is not introduced as a proper relation/CTE, and AS EC(DeptName,Num) is not a valid ordinary COUNT alias. A corrected query must define EC before SELECT AVG(Num) FROM EC.

# GATE 2017 CS1: Q51 (printed CS Q41)

**Question:** [Official archived paper page 18](https://web.archive.org/web/20170712112248id_/http://www.gate.iitg.ac.in:80/2017questions/CS1.pdf#page=18); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** D

**Derived answer:** Only III under unrestricted-domain TRC; official D under active-domain restriction

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

**Paraphrased problem context:** EMP(EmpId,EmpName,DeptId), DEPT(DeptName,DeptId); EMP.DeptId may be NULL. Which tuple-calculus queries are safe?
I {t | ∃u∈EMP (t[EmpName]=u[EmpName] ∧ ∀v∈DEPT (t[DeptId]≠v[DeptId]))}
II {t | ∃u∈EMP (t[EmpName]=u[EmpName] ∧ ∃v∈DEPT (t[DeptId]≠v[DeptId]))}
III {t | ∃u∈EMP (t[EmpName]=u[EmpName] ∧ ∃v∈DEPT (t[DeptId]=v[DeptId]))}
A I and II; B I and III; C II and III; D all three. No range restriction t∈EMP is printed.

## Solution

1. Safety requires finite results independent of arbitrary values outside the database. The free result tuple t is not explicitly restricted to EMP; only t.EmpName is equated to an employee name in I and II.

2. Use one employee Alice with DeptId 1 and one department with DeptId 1. For every value z outside the database, t=(Alice,z) satisfies I: z differs from every department ID. It also satisfies II because the existing department ID 1 differs from z. Infinitely many z are possible in an unrestricted domain.

3. III instead equates t.EmpName to an EMP name and t.DeptId to a DEPT ID, bounding both fields by finite stored values. Therefore only III is classically safe, but that option is missing. Official D requires an unstated finite active-domain interpretation. Allowing NULL in EMP neither binds t nor removes the counterexample.

**Paraphrased problem context:** CR(StudentName,CourseName) contains course sets SA:{CA,CB,CC}, SB:{CB,CC}, SC:{CA,CB,CC}, SD:{CA,CB,CC,CD}, SE:{CD,CA,CB}, SF:{CA,CB,CC}. T1=πCourseName(σStudentName=SA(CR)); T2=CR÷T1. Find rows in T2.

## Solution

1. Selection finds the rows for SA, then projection removes the student column. Thus T1 is the three-course set {CA,CB,CC}.

2. Relational division returns each student who is paired with every course in T1. Extra courses do not disqualify a student.

3. SA,SC,SD,SF contain all three. SB lacks CA; SE lacks CC. Thus T2 consists of four student names, so the answer is 4. The number of qualifying enrolment rows is not what division returns.
