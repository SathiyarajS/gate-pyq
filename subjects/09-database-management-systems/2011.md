## Solution

Joint accounts allow two students to have the same primary BankAccount_Num, so it need not uniquely identify a student and is not guaranteed to be a candidate key. Registration numbers are unique; a national UID is unique under the stated same-country assumption; adding an attribute to a superkey preserves uniqueness. Therefore A is incorrect. NULL in the set expression is understood as empty intersection, not SQL NULL.

**Source access:** Archived official IIT Kharagpur paper and IIT Madras key, booklet A. Physical PDF page numbers are used; code A is the matching key column. Final-revision designation is unverified.

## Solution

The rows obey X=k and Y=2^k−1 by induction from(1, 1): the next maximum Y is doubled and increased by 1. Hence the row X=7 has Y=127, A. Completing all128 additional inserts would require representing2^129−1 in the final row, beyond common fixed-width SQL INTEGER types. The problem’s statement that all inserts occur therefore assumes sufficiently large integers or an abstract unbounded-integer model; the requested early row itself is representable.

**Source access:** Archived official IIT Kharagpur paper and IIT Madras key, booklet A. Physical PDF page numbers are used; code A is the matching key column. Final-revision designation is unverified.

## Solution

Q1 is equality on the indexed attribute, where a well-distributed hash index normally locates its bucket in expected constant time and outperforms ordered search. Q2 is a range predicate, for which an ordered index finds the first qualifying entry and scans the interval; hashing lacks that order. Thus C is the conventional comparison. Actual performance also depends on collisions, selectivity, caching and index layout, so this is not a universal measured-time guarantee for every database.

**Derived answer:** C

**Source access:** Archived official IIT Kharagpur paper and IIT Madras key, booklet A. Physical PDF page numbers are used; code A is the matching key column. Final-revision designation is unverified.

## Solution

The common column of the two projections is Bank_Manager. Sunderajan appears in two rows of each projection, so the natural join yields 2×2=4 combinations for that manager. Ramgopal appears once in each projection, yielding 1×1=1 combination. COUNT(*) returns 4+1=5, option C. The join does not pair rows by their original borrower, since Borrower is absent from the second projection.
