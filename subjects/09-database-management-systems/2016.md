**Question:** [Official archived paper page 10](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B is not guaranteed; literal insufficiency of dependencies

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** A relational schema has attributes V,W,X,Y,Z and primary key VY. Which choice is NOT a superkey? A: VXYZ. B: VWXZ. C: VWXY. D: VWXYZ. No other functional dependencies are specified; distinguish the intended answer from what the premise alone guarantees.

## Solution

A, C, D contain the given primary key VY and are therefore superkeys. B=VWXZ omits Y, so it is the only set not guaranteed to be a superkey by that key alone, intended B. However a primary key does not exclude other candidate keys: adding X→Y would make B a superkey too while VY can remain minimal. No complete FD set is supplied, so the literal assertion that B is not a superkey needs the implicit assumption that no other dependency determines Y.

A superkey determines every attribute; any superset of a known key is therefore automatically a superkey. This immediately verifies A,C,D. Under only the supplied key dependency VY→VWX YZ, closure of VWXZ lacks Y, giving intended B. But “primary” means the chosen candidate key, not the only candidate key. If X→Y is additionally valid, VWXZ closes to all attributes. Keeping this caveat prevents a multiple-choice convention from being taught as a false database theorem.

**Question:** [Official archived paper page 10](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** D

**Derived answer:** D

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Which is NOT an ACID transaction property? A: Atomicity. B: Consistency. C: Isolation. D: Deadlock-freedom.

## Solution

ACID expands to Atomicity, Consistency, Isolation and Durability. Deadlock freedom is a concurrency/liveness property, not an ACID component. Thus D.

Atomicity means all-or-nothing effects; consistency preserves the database's declared constraints; isolation controls interactions among concurrent transactions; durability preserves committed results. A locking implementation can satisfy these properties while occasionally encountering a deadlock, provided it detects and resolves that deadlock by aborting a transaction. Thus deadlock-freedom is a separate liveness guarantee rather than the missing fourth letter of ACID, which is durability.

**Paraphrased problem context:** An article relation has attributes Volume,Number,StartPage,EndPage,Title,Year,Price. Its primary key K is (Volume,Number,StartPage,EndPage), with FDs K→Title, (Volume,Number)→Year, K→Price. It is decomposed into (Volume,Number,StartPage,EndPage,Title,Price) and (Volume,Number,Year). What is the weakest normal form the new database satisfies but the old one does not? A:1NF. B:2NF. C:3NF. D:BCNF.

## Solution

The old relation has a partial dependency (Volume, Number)→Year from a proper subset of the composite key to a nonprime attribute, violating 2NF. Splitting off(Volume, Number, Year) removes it; under the supplied FDs both resulting determinants are keys. The weakest newly satisfied form is 2NF, B, although the new schemas also satisfy higher forms under these dependencies.

Second normal form forbids a nonprime attribute from depending on only part of a candidate key. Year violates precisely this condition because Volume and Number are a proper subset of K. In the new Year relation, that pair is the whole key, so its dependency is no longer partial. In the other relation, Title and Price depend on its full key. The word weakest is decisive: even if BCNF also holds under the stated FDs,2NF is the first level crossed.

# GATE 2016 CS1: Q61 (printed CS Q51)

**Question:** [Official archived paper page 19](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** A transaction accessing objects O1,...,Ok first obtains exclusive locks on all of them in increasing memory-address order, then performs its operations, then releases all locks. The same protocol is followed by every transaction. What is guaranteed? A:serializability and deadlock-freedom. B:neither. C:serializability only. D:deadlock-freedom only.

## Solution

Acquiring all exclusive locks before releasing any is two-phase locking, ensuring conflict serializability. Every transaction acquires locks in the same increasing object-address order. A circular wait would force a strict sequence of increasing addresses to return to its starting address, impossible. The protocol is therefore also deadlock-free, A.

The growing phase contains every lock acquisition, and the shrinking phase contains only releases, so this is stronger than ordinary two-phase locking and ensures conflict serializability. The common global address order prevents cycles in the wait-for graph: following a chain of waits requires strictly increasing lock addresses. Serializability alone would not prevent deadlock in arbitrary two-phase locking, so both parts of the argument are needed. Locking exclusively for reads is conservative but does not invalidate either guarantee.

**Paraphrased problem context:** B+ trees are balanced because: A all root-to-leaf path lengths equal; B those lengths differ by at most 1; C child counts of nonleaf siblings differ by at most 1; D record counts of leaves differ by at most 1.

## Solution

Every B+ tree leaf is at the same level. Consequently every root-to-leaf path has the same length, A. Occupancy counts may differ much more than one while still meeting the minimum/maximum occupancy constraints.

Balanced here describes tree height, not identical node fill. A root-to-leaf search examines the same number of tree levels whichever key range it follows. Option B is a weaker consequence of equality, but A states the defining stronger invariant. The intended single-choice answer should not be read as making the weaker inequality mathematically false.

# GATE 2016 CS2: Q32 (printed CS Q22)

**Question:** [Official archived paper page 31](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A under conflict-serializability interpretation

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Build a schedule’s precedence graph with transactions as vertices and conflicts as directed edges. If the schedule is “serializable,” which vertex order guarantees a serial schedule? A topological; B depth-first; C breadth-first; D increasing transaction index. Explain the intended meaning of serializable.

## Solution

An acyclic precedence graph admits a topological order, and placing transactions in that order respects every conflicting pair, yielding a conflict-equivalent serial schedule. Thus A. The word serializable must mean conflict-serializable here: view-serializable schedules can have cyclic conflict graphs (for example blind writes w1(X), w2(X), w1(X)), so a topological order need not exist under that broader meaning.

An edge Ti→Tj says a conflicting operation of Ti precedes one of Tj and that order must be preserved. A topological sort respects every such edge; ordinary traversal orders need not. For example an edge T2→T1 rules out increasing index order. Graph acyclicity is both necessary and sufficient for conflict serializability, not for every broader serializability notion.

# GATE 2016 CS2: Q61 (printed CS Q51)

**Question:** [Official archived paper page 41](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** C

**Derived answer:** C

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Schedule S=r2(X);r1(X);r2(Y);w1(X);r1(Y);w2(X);a1;a2, where r,w,a mean read,write,abort. A nonrecoverable; B recoverable but cascading abort; C no cascading abort; D strict.

## Solution

Every read occurs before the other transaction has written the read item, so neither transaction reads uncommitted data from the other. There is therefore no read-dependency requiring a cascading abort, C. The two explicit aborts do not themselves establish a cascade. The schedule is recoverable (neither commits prematurely), but not strict because w2(X) overwrites uncommitted w1(X).

Dirty reads, dirty writes and recoverability are different conditions. Here r2(X),r1(X) occur before w1(X), and neither transaction writes Y, so all reads see previously committed values. But w2(X) occurs before T1 aborts, a dirty write, ruling out strictness. Two transactions aborting in the same schedule need not have a causal read-dependency cascade.

The single average row is crossed with those four totals; filtering retains 40 and 30. A repaired standard SQL form uses WITH total AS (...), total_avg AS (...) SELECT ..., making the intended semantics executable without claiming the printed syntax is valid.
