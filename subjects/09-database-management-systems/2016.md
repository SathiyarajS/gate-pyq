**Question:** [Official archived paper page 10](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B is not guaranteed; literal insufficiency of dependencies

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

A, C, D contain the given primary key VY and are therefore superkeys. B=VWXZ omits Y, so it is the only set not guaranteed to be a superkey by that key alone, intended B. However a primary key does not exclude other candidate keys: adding X→Y would make B a superkey too while VY can remain minimal. No complete FD set is supplied, so the literal assertion that B is not a superkey needs the implicit assumption that no other dependency determines Y.

# GATE 2016 CS1: Q61 (printed CS Q51)

**Question:** [Official archived paper page 19](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

Acquiring all exclusive locks before releasing any is two-phase locking, ensuring conflict serializability. Every transaction acquires locks in the same increasing object-address order. A circular wait would force a strict sequence of increasing addresses to return to its starting address, impossible. The protocol is therefore also deadlock-free, A.

# GATE 2016 CS2: Q32 (printed CS Q22)

**Official answer:** A

**Derived answer:** A under conflict-serializability interpretation

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

An acyclic precedence graph admits a topological order, and placing transactions in that order respects every conflicting pair, yielding a conflict-equivalent serial schedule. Thus A. The word serializable must mean conflict-serializable here: view-serializable schedules can have cyclic conflict graphs (for example blind writes w1(X), w2(X), w1(X)), so a topological order need not exist under that broader meaning.

# GATE 2016 CS2: Q61 (printed CS Q51)

**Question:** [Official archived paper page 41](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** C

**Derived answer:** C

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

Every read occurs before the other transaction has written the read item, so neither transaction reads uncommitted data from the other. There is therefore no read-dependency requiring a cascading abort, C. The two explicit aborts do not themselves establish a cascade. The schedule is recoverable (neither commits prematurely), but not strict because w2(X) overwrites uncommitted w1(X).
