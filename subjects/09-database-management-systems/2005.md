# GATE 2005: Q29 (printed CS Q29)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C under the usual nonempty-determinant convention

## Solution

A lossless dependency-preserving3NF decomposition always exists, whereas achieving BCNF can sacrifice dependency preservation. For example R(A,B,C) with AB→C and C→B has a BCNF violation C→B; decomposition into CB and AC loses the ability to enforce AB→C locally. Thus C is false. The separate assertion that every two-attribute schema is BCNF assumes no nontrivial empty-determinant dependencies: with ∅→A but A not determining B, R(A,B) is a counterexample to that assertion. Under literal unrestricted FDs both C and D can fail; the conventional answer excludes constant-column FDs.

# GATE 2005: Q77 (printed CS Q77)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D, assuming non-NULL prices

## Solution

For each B the subquery counts books with a strictly higher price. The predicate count<5 selects ranks 1 through5 in descending price order, because they have respectively 0 through4 more expensive books. Distinct prices rule out ties. The result is the titles of the five most expensive books (or all books if fewer than five), option D. This intended interpretation additionally assumes prices are non-NULL. Distinct prices alone does not establish a NOT NULL constraint: for a row B with NULL price, every T.price>B.price comparison is UNKNOWN, so the subquery counts zero and that NULL-priced row is included regardless of the five highest non-NULL prices.

**Independently derived answer:** D

## Solution

Neither E nor H appears on any dependency right-hand side, so every key contains both. E supplies C. Adding A yields B then D through BC→D; adding B yields D then A; adding D yields A then B. Thus AEH, BEH, DEH each determine all six attributes. EH alone cannot determine A,B,D, and adding only C gives nothing new, so these are precisely the minimal keys, option D.
