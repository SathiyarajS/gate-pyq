

# GATE 2008: Q41 (printed CS Q41)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 7. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

## Solution

An order-four B-tree has at most three keys per node. The maximum is five splits. For ordinary overflow-triggered insertion, inserting 1 through 10 in ascending order and promoting the lower middle key splits a leaf on insertions 4, 6, 8 and 10; the fourth leaf split also overflows and splits the root. For a timing-independent bound, after L leaf splits there are L+1 nonempty leaves. A B-tree with L+1 leaves has exactly L separator keys in all internal nodes combined: each internal node has one fewer key than children, and summing over the tree gives leaves minus one. Consequently n≥(L+1)+L=2L+1. With n=10, L≤4. Under overflow-triggered insertion, the first internal split needs the root to receive four separators from four leaf splits. With no further leaf split possible, no second internal split can occur. Thus there is at most one internal/root split and the total is at most 4+1=5. Under preemptive splitting, the full root may instead split after three leaf splits, distributing its three separators into a new root with one key and two internal children with one key each. At most one further leaf split is possible, which can increase only one such child to two keys; no internal node can become full again. The same upper bound therefore holds, and increasing-key insertion attains five splits under this convention too.

# GATE 2008: Q46 (printed CS Q46)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 8. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

## Solution

Θ(n) time is sufficient and necessary. Read the postorder sequence backward: the next element is the root, followed by the right subtree in reverse postorder and then the left. A recursive builder with allowed key interval (low,high) consumes a value only if it belongs in that interval; after creating a node with key r, build the right interval (r,high), then the left (low,r). Each key is consumed once and there are O(n) calls, so the time is O(n). Distinct BST keys and their ordering make the construction unique. Reading and outputting n nodes requires Ω(n), yielding Θ(n).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

## Solution

Append all n new elements to the existing n-element heap array, then run bottom-up BUILD-HEAP on the resulting 2n elements. Its total sift-down work is O(n), since the number of nodes of height h decreases geometrically and Σh/2^h is constant. Reading/storing n new elements requires Ω(n), so the optimum total is Θ(n), option B. The permission to insert them in a batch is crucial: n separate ordinary heap insertions can require Θ(n log n).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

## Solution

Initially p and q denote nodes 1 and 2. Each iteration swaps their values, then advances p to the node after q and q to the following node. Thus the pairs (1,2), (3,4), (5,6) are swapped and the last unpaired 7 remains. The resulting list is 2,1,4,3,6,5,7, option B. Links are not changed.
