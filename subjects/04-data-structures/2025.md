

# GATE 2025 CS1: Q26

**Question:** [Official archived paper page 26](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=26); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** A;B

**Derived answer:** A;B under upper-bound interpretation; B under literal per-tree equality

**Paraphrased problem context:** For a BST storing n distinct integers, assess: A “The maximum length of a path from the root node to any other node is (n−1).” B inorder traversal is always sorted. C worst-case search takes O(log₂ n). D every BST is a Min-Heap. Select all true statements. A’s wording is retained because it has a material quantifier ambiguity.

## Solution

Approach: Separate guarantees for every individual tree from the largest possible height among all n-node BSTs.
Inorder traversal visits the left subtree, root, then right subtree. By the BST ordering invariant all left keys are smaller and all right keys are larger. Applying that reasoning recursively produces sorted order, so B is unconditionally true.
Any root-to-node path contains at most n nodes, hence at most n−1 edges. A completely skewed BST attains this bound. Under the intended “maximum possible over all BSTs” interpretation, A is true and the official answer is A,B. Literally, however, A says that each tree’s maximum root path IS n−1. A balanced three-node BST has height 1 rather than 2, so under that reading A is false and only B survives.
C is false because search follows a root-to-node path and may take Θ(n) in a skewed BST; balancing is not promised. D is false because a BST need not be complete, and its left child can be smaller than its root, violating min-heap order.
Keep the official A;B for scoring while explicitly warning about A’s wording. The mathematical distinction must not be hidden by replacing “is” with “at most”.

# GATE 2025 CS1: Q35

**Question:** [Official archived paper page 35](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=35); consult original wording, diagrams and choices.

**Type / marks:** NAT, 1 mark(s).

**Official answer:** 5 to 5

**Derived answer:** 5

**Paraphrased problem context:** Height is the largest number of edges on a root-to-leaf path. A Min-Heap stores 32 keys. Under the standard binary-heap convention, what is its height?

## Solution

Approach: Use the complete-binary-tree shape of a binary heap; key order does not determine its height.
At depth d, a binary tree can contain at most 2^d nodes. The completely filled levels from depth 0 through depth 4 contain 1+2+4+8+16=31 nodes. A 32nd node therefore cannot fit in those levels and must occupy depth 5.
A heap is complete: all levels except possibly the last are full, with the last filled from left to right. Hence 32 keys create one node at depth 5 and none deeper. The height, measured in edges, is 5.
Equivalently, an n-node complete binary tree has height floor(log₂ n), and floor(log₂32)=5. Counting occupied levels would give 6, but the question explicitly uses edges. The answer relies on the conventional binary meaning of Min-Heap; arbitrary heap-ordered trees need not have this shape.

# GATE 2025 CS1: Q62

**Question:** [Official archived paper page 62](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=62); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 5 to 5

**Derived answer:** 5

**Paraphrased problem context:** L1 is 1→7→12→3→9→5→11→15→8→NULL and L2 is 1→11→6→9→15→12→4→NULL. find(q,L2) returns whether q occurs in L2. Starting ptr1=L1, repeat while ptr1->next!=NULL: set query=ptr1->next->data; if find(query,L2), execute ptr1->next=ptr1->next->next; otherwise advance ptr1=ptr1->next. How many nodes remain reachable in L1?

## Solution

Approach: Notice that the tested node is ptr1’s successor, not ptr1 itself. On deletion the pointer stays still, so the replacement successor is tested next.
Initially ptr1 points to the head value 1. Its successor 7 is not in L2, so advance to 7. The next value 12 is in L2, so bypass it, leaving 7 pointing to 3. Keep ptr1 at 7, test 3, and then advance to 3 because it is absent from L2.
Delete successor 9, retain and advance to 5, then delete 11 and 15 in consecutive iterations while ptr1 remains at 5. Finally retain 8 and stop because its next pointer is NULL.
The resulting list is 1→7→3→5→8, so five nodes remain. Although head value 1 also occurs in L2, it is never tested as a successor and is not removed. Advancing ptr1 after a deletion would incorrectly skip a candidate such as 15. The code unlinks nodes without calling free; the question asks reachability in L1, not the count of still-allocated memory objects.

# GATE 2025 CS1: Q65

**Question:** [Official archived paper page 64](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=64); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 10 to 11

**Derived answer:** 10

**Paraphrased problem context:** An initially empty hash table has m=11 slots. h1(k)=k mod 11, h2(k)=1+(k mod 7), and probe i uses [h1(k)+i·h2(k)] mod 11, starting at i=0. Insert 63,50,25,79,67,24 in that order. In which slot does 24 end up? The formula yields a zero-based index; the official range also accepts the corresponding one-based slot number.

## Solution

Approach: Insert the earlier keys first, because their occupied positions determine how many probes key 24 needs.
For the first five keys the primary hash locations are 63 mod 11=8, 50 mod 11=6, 25 mod 11=3, 79 mod 11=2 and 67 mod 11=1. All differ, so each key is placed on its first probe. Occupied indices are therefore {1,2,3,6,8}.
For 24, h1=24 mod 11=2 and h2=1+(24 mod 7)=1+3=4. Probe i=0 checks index 2, occupied by 79. Probe i=1 checks (2+4) mod 11=6, occupied by 50. Probe i=2 checks (2+8) mod 11=10, which is empty, so 24 is stored there.
The derived index is 10. This is the eleventh slot if slots are described with one-based ordinal numbers. Preserve the official accepted interval 10–11, but use 10 when interpreting the given modulo formula literally. The second hash is the step size, not a replacement initial index.

# GATE 2025 CS2: Q13

**Question:** [Official archived paper page 12](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=12); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** A nonempty binary tree has n nodes, and every node has either zero or exactly two children. How many nodes have two children?
Options: A. (n−2)/2; B. (n−1)/2; C. n/2; D. (n+1)/2.

## Solution

Let i be the number of internal nodes and l the number of leaves, so n=i+l. Count the tree edges in two ways. Every non-root node has exactly one parent, giving n−1 edges in total. On the other hand, each internal node contributes two parent-to-child edges and each leaf contributes none, giving 2i edges. Therefore 2i=n−1 and i=(n−1)/2.

This also implies l=i+1=(n+1)/2, which explains why D is a plausible but incorrect distractor: it counts leaves. Such a tree has odd n, as n=2i+1. At the boundary n=1, the root is a leaf and the formula gives zero two-child nodes, as required. This is a full/proper binary tree property; it does not require the tree to be balanced or all leaves to be at the same depth. Answer: B.

# GATE 2025 CS2: Q35

**Question:** [Official archived paper page 26](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=26); consult original wording, diagrams and choices.

**Type / marks:** NAT, 1 mark(s).

**Official answer:** 4 to 4

**Derived answer:** 4

**Paraphrased problem context:** Insert 10,−4,15,30,20,5,60,19 in that order into an initially empty ordinary binary search tree, with no balancing rotations. How many edges are on the path from node 19 to the root?

## Solution

Insert by comparing each new key with the nodes on its search path. The first key 10 becomes the root. −4 is its left child and 15 its right child. Next 30 becomes the right child of 15; 20 becomes the left child of 30. The key 5 goes right of −4, and 60 goes right of 30.

For 19, compare with 10: go right. Compare with 15: go right. Compare with 30: go left. Compare with 20: go left and insert there. Thus its root path is 10→15→30→20→19.

There are five nodes on that path but four edges, so the requested distance is 4. This is its depth when the root has depth zero. The left branch containing −4 and 5, and the right branch containing 60, do not contribute to this path. Answer: 4.

# GATE 2025 CS2: Q38

**Question:** [Official archived paper page 29](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=29); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** Meld combines two size-n instances into one of the same data structure. Let P be an unsorted doubly linked list with head and tail pointers, Q an array-based min-heap, and R a binary search tree. Choose the best worst-case time complexities.
A. P Θ(1), Q Θ(n), R Θ(n).
B. P Θ(1), Q Θ(n log n), R Θ(n).
C. P Θ(n), Q Θ(n log n), R Θ(n²).
D. P Θ(1), Q Θ(n), R Θ(n log n).

## Solution

P: join the first list's tail to the second list's head, set the corresponding previous pointer, and choose the resulting head and tail. Only a constant number of pointer changes are needed, with separate constant-time handling of empty lists. The list is unsorted, so no ordering merge is required: Θ(1).

Q: place both arrays into one 2n-element array and apply bottom-up build-heap. Build-heap is linear, not Θ(n log n): there are many nodes near leaves that require only short sift-down operations, and summing their heights gives O(n). The concatenation/output work is also linear, so Θ(n) suffices. Inserting each item separately is valid but needlessly slower in the worst case.

R: perform inorder traversals to get two sorted sequences in Θ(n), merge them in Θ(n), and build a balanced BST from the merged sequence by choosing midpoints recursively in Θ(n). Arbitrarily interleaved key sets require linear worst-case work/comparisons to establish their joint ordering, so the meld bound is Θ(n), rather than the cost of repeated naive insertions into a possibly skewed tree.

The three bounds are Θ(1),Θ(n),Θ(n): A.

# GATE 2025 CS2: Q45

**Question:** [Official archived paper page 34](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=34); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** A stack stores records with distinct positive integer keys. Add MIN, which returns a pointer to the minimum-key record without removing it, in O(1) time while keeping PUSH and POP O(1). Which proposed augmentations suffice?
A. Every record stores a pointer to the smallest-key record below it.
B. Store only one pointer to the current minimum record.
C. Maintain an auxiliary sorted array of all present keys.
D. Maintain a min-heap of all present keys.

## Solution

A preserves the minimum of every stack prefix, which is the information needed after future pops. For an empty stack use a null pointer. When pushing a new record r onto old top t, compare t.key with the key at t's saved below-minimum pointer, if present. The smaller of those records is the minimum of the entire old stack, so store its pointer in r. This takes O(1). MIN compares the current top with its saved below-minimum and returns the smaller. POP simply exposes the previous top, whose saved pointer is still valid because stack deletion has removed nothing below it. Thus all three operations remain O(1).

B alone supports a new minimum on PUSH but loses the information needed when POP removes the current minimum. Finding the next minimum can require scanning the remaining stack. C permits constant-time access to the smallest sorted entry, but inserting an arbitrary new key can require Θ(n) shifts. D exposes its minimum in O(1), but maintaining the heap on insertions and deletions costs O(log n), not O(1) worst case. Those structures do not meet all requirements merely because their MIN operation is fast. Select A only.
