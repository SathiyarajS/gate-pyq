**Paraphrased problem context:** What is the worst-case search time in a balanced binary search tree containing n·2^n elements?
(A) Θ(n log n) (B) Θ(n·2^n) (C) Θ(n) (D) Θ(log n).

## Solution

A balanced binary search tree on N elements has worst-case search length Θ(log N). Here N=n·2^n, so log₂N=log₂n+n=Θ(n). The answer is C, not Θ(log n), since n itself is not the number of elements.

Worked check / additional reasoning: Search follows just one root-to-leaf branch and performs constant work per visited node. With base-two logarithms, n≤log₂(n2^n)≤2n for n≥2, explicitly establishing matching linear upper and lower asymptotic bounds.

**Paraphrased problem context:** Suppose a circular queue of capacity (n −1) elements is implemented with an array of n elements.
        Assume that the insertion and deletion operations are carried out using REAR and FRONT as array
        index variables, respectively. Initially, REAR = FRONT = 0. The conditions to detect queue full
        and queue empty are
        (A) full: (REAR+1) mod n == FRONT               (B) full: (REAR+1) mod n == FRONT
            empty: REAR == FRONT                            empty: (FRONT+1) mod n == REAR

        (C) full: REAR == FRONT                         (D) full: (FRONT+1) mod n == REAR
            empty: (REAR+1) mod n == FRONT                 empty: REAR == FRONT

## Solution

With one of n slots deliberately unused, equal FRONT and REAR denotes the initial empty queue and all subsequent empty states. The queue is full when advancing REAR by one modulo n would collide with FRONT: (REAR+1) mod n=FRONT. These conditions permit n−1 stored elements and distinguish empty from full. Hence A.

Worked check / additional reasoning: For example, with n=4 the usable capacity is three. Starting at FRONT=REAR=0, three insertions advance REAR to 3; its next value would be 0, equal to FRONT, so the full test succeeds without confusing it with the empty state.

**Paraphrased problem context:** The source defines tree height as “the number of edges on the longest path in the tree” and gives this rooted-tree routine. Fill B1,B2:
int height(treeptr n) {
 if(n==NULL) return -1;
 if(n->left==NULL)
   if(n->right==NULL) return 0; else return B1;
 else { h1=height(n->left);
   if(n->right==NULL) return 1+h1;
   else { h2=height(n->right); return B2; }
 }
}
(A) B1=1+height(n->right), B2=1+max(h1,h2).
(B) B1=height(n->right), B2=1+max(h1,h2).
(C) B1=height(n->right), B2=max(h1,h2).
(D) B1=1+height(n->right), B2=max(h1,h2).

## Solution

For the conventional rooted height, a leaf has height 0 and every parent-to-child step adds one edge. If only the right child exists, B1 must be 1+height(n→right). If both exist, B2 must be 1+max(h1, h2). Thus A is the intended rooted-height answer and matches the official key. However, the opening sentence literally defines the longest path anywhere in the tree, which is its diameter, not necessarily its root-to-leaf height. A root with two leaf children has rooted height 1 but diameter 2; none of the listed B2 expressions returns 2 for that example. Preserve this wording defect rather than claiming the code computes the literal definition.

Worked check / additional reasoning: Check a node with only a right leaf: the child returns 0 and the parent must return 1, forcing B1’s +1. With two children, choose the larger subtree height and add the edge from the current node, forcing B2’s +1.
