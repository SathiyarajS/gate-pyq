**Independently derived answer:** C

**Paraphrased problem context:** Insert 12, 18, 13, 2, 3, 23, 5, 15 in an empty 10-slot table using h(k)=k mod 10 and linear probing. Candidate A stores 2:2, 3:23, 5:15, 8:18; B stores 2:12, 3:13, 5:5, 8:18; C stores slots 2–9 as 12, 13, 2, 3, 23, 5, 18, 15; D chains 2:[12, 2], 3:[13, 3, 23], 5:[5, 15], 8:[18]. Other slots empty. Which is correct?

## Solution

Insertions place 12 at 2, 18 at 8, 13 at 3, 2 at 4, 3 at 5, 23 at 6, 5 at 7 and 15 at 9 after probing past occupied slots 5 through 8. The final slots 2–9 are 12, 13, 2, 3, 23, 5, 18, 15, exactly option C.

Teaching detail:
Probe consecutive slots until empty. First 12→2 and 18→8; 13→3. Key 2 collides at 2 and 3, so goes 4. Key 3 goes 5; 23 goes 6; 5 goes 7. Finally 15 probes 5, 6, 7, 8 before reaching 9. This yields candidate C. D instead uses chaining, which is explicitly not the requested collision strategy; A/B discard keys rather than preserving them in later empty slots.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Maximum edge-height of an AVL tree with 7 nodes, with singleton height 0? A 2; B 3; C 4; D 5.

## Solution

The minimum-node recurrence for edge height h is N(h)=1+N(h−1)+N(h−2), with N(−1)=0, N(0)=1. Hence N(1)=2, N(2)=4, N(3)=7, N(4)=12. Seven nodes attain height 3 but cannot reach 4, so B.

Teaching detail:
To make an AVL tree as tall as possible with few nodes, give its two subtrees heights h−1 and h−2. Thus the minimum nodes at height h obey N(h)=1+N(h−1)+N(h−2). Starting with empty height−1 and singleton 0 gives 0, 1, 2, 4, 7, 12. Seven nodes suffice exactly for height 3, but any height 4 tree needs at least 12. This proves both attainability and impossibility, so B.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 10. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Insert 10, 3, 6, 8, 4, 2, 1 into an empty B+ tree. Internal nodes allow at most 3 child pointers; leaves at most 2 data items. What is the maximum number of leaf splits, allowing valid choices of how 3 overflow items split? A 2; B 3; C 4; D 5.

## Solution

There can be at most one leaf split per insertion; the first two keys fit in the initial two-item leaf, so at most five splits occur. This bound is attained by leaving two smaller keys in the left leaf and one larger key in the right leaf at each overflow. Starting[3, 10], insertion 6 gives[3, 6]|[10]; 8 gives[3, 6]|[8]|[10]; 4 gives[3, 4]|[6]|[8]|[10]; 2 gives[2, 3]|[4]|[6]|[8]|[10]; 1 gives[1, 2]|[3]|[4]|[6]|[8]|[10]. Thus all five later insertions split a leaf, D. Internal-node splits are not counted. Exhaustive permitted split-choice enumeration confirms the maximum 5.

Teaching detail:
The first two insertions cannot split a capacity-two leaf. There are only five insertions left and each can overflow at most one leaf, so five is an upper bound. The explicit sequence of valid 1/2 splits in the baseline attains one split on each remaining insertion. That witness proves the maximum, not merely an observed count under one fixed implementation. Promoted separator changes and internal-node splits do not add to the requested leaf-split count.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Which zero-based array is a binary max-heap? A[25, 12, 16, 13, 10, 8, 14]; B[25, 14, 13, 16, 10, 8, 12]; C[25, 14, 16, 13, 10, 8, 12]; D[25, 14, 12, 13, 10, 8, 16].

## Solution

In a zero-based heap each parent at i must be at least as large as children at 2i+1 and 2i+2. In C, [25, 14, 16, 13, 10, 8, 12], the checks are 25≥14, 16; 14≥13, 10; and 16≥8, 12, so every edge satisfies max-heap order. A fails because parent 12 has child 13; B fails because parent 14 has child 16; D fails because parent 12 has child 16. Thus C alone is a max-heap.

Teaching detail:
A max-heap needs parent≥child along every edge, not a globally descending array. In C, root 25 exceeds 14/16; 14 exceeds 13/10; 16 exceeds 8/12. A fails at 12<13; B at 14<16; D at 12<16. Checking only the root would wrongly admit the distractors; every internal node must satisfy the local condition.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Perform two delete-max operations on the valid heap from Q59. Result? A[14, 13, 12, 10, 8]; B[14, 12, 13, 8, 10]; C[14, 13, 8, 12, 10]; D[14, 13, 12, 8, 10].

## Solution

Start from Q59’s heap [25, 14, 16, 13, 10, 8, 12]. Delete 25, move final element 12 to the root, and sift down by swapping with the larger child 16. The six-element heap is [16, 14, 12, 13, 10, 8]. Delete 16 and move final element 8 to the root: [8, 14, 12, 13, 10]. Swap 8 with larger child 14, then with larger child 13, giving [14, 13, 12, 8, 10]. This is option D. Each deletion removes the maximum and reduces the active heap length by one.

Teaching detail:
Delete-max replaces the root by the last active element, shrinks the heap and repeatedly swaps downward with the larger child. First deletion moves 12 to the root and swaps it with 16, yielding[16, 14, 12, 13, 10, 8]. Second deletion moves 8 to the root, then swaps with 14 and 13, yielding[14, 13, 12, 8, 10]. Choosing the smaller child would not restore heap order, which explains several plausible-looking alternatives.
