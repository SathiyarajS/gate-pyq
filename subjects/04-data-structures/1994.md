**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: i(i−1)/2+j

**Essential problem context (paraphrased):** Rows of a lower triangular n×n matrix, including their diagonal, are stored consecutively. With one-based indices, where is entry (i,j), j≤i?

## Solution

Before row i, the stored rows have lengths 1,2,…,i−1, totaling i(i−1)/2 entries. Entry j in the next row is j positions beyond that prefix under one-based indexing. Therefore its packed index is i(i−1)/2+j. A zero-based packed offset would subtract one from this result. The formula stores every position in the lower triangle, even if a particular value happens to be zero; omitting actual zeros would require additional sparse-matrix metadata.

**Independently derived answer:** B: 34521

**Essential problem context (paraphrased):** Input 1,2,3,4,5 arrives in order. Which output is possible with one stack: 34512,34521,15234,54312?

## Solution

Push 1,2,3 and pop 3; push 4 and pop 4; push 5 and pop 5; then pop 2 and 1. This constructs 34521. For 34512, after producing 345 the stack has 2 above 1, so 1 cannot come next. For 15234, after popping 1 then pushing through 5, the next available value is 4, not 2. For 54312, after popping 5,4,3, value 2 still blocks 1. Thus only B is feasible.

**Type / marks:** MCQ, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B: binary search

**Essential problem context (paraphrased):** Among insertion sort, binary search, radix sort and polynomial manipulation, which is poorly supported by a plain linked list?

## Solution

Binary search repeatedly accesses a midpoint by index. An array provides that access in constant time, but a plain linked list must traverse links to locate it, losing the logarithmic-access advantage. Linked lists can support insertion-sort splicing, bucket chains in radix sorting and sparse polynomial terms naturally. The issue is not that binary-search comparisons are impossible on a list, but that the necessary positional access is inefficient without additional indexing structures.

3. The overflowing internal root splits around its middle separator 69. Promote 69 into a new root, leaving internal nodes [25,38] and [93,100], each with three children.

4. All six leaves remain at equal depth and hold between two and four keys. Keys in internal nodes are routing separators, not additional data records.

# GATE 1994: Q63 (printed B Q14(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** O(1+log_(d+1) n); commonly written O(log_d n) for d≥2 and nontrivial trees.

**Essential problem context (paraphrased):** A B+ tree of order d holds d to 2d keys per node. For n leaf nodes, fill the order of the number of nodes accessed during a search.

## Solution

1. An internal non-root node has at least d+1 children because keys separate child ranges. A root that is internal has at least two children.

2. If the root-to-leaf distance is h≥1, there are at least 2(d+1)^(h−1) leaves. Rearranging bounds h by 1+log_(d+1)(n/2).

3. Search follows a single child at each internal level and accesses the leaf, for h+1 node accesses. The extra constant handles n=1.

4. For d≥2, changing the logarithm base from d+1 to d changes only a bounded factor; log_d n is the conventional blank. When d=1, log_d n is undefined, so the d+1 expression is safer.

# GATE 1994: Q81 (printed B Q26)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Transfer Q→S, then S→Q, then Q→S; use three n-iteration loops.

**Essential problem context (paraphrased):** A queue Q contains n items and stack S is empty. Move all items into S so the original queue front is the stack top, with all remaining relative order preserved. Use only queue Delete/Insert and stack Push/Pop, O(n) time and O(1) extra storage.

## Solution

Use a single item variable x and a loop counter. First repeat n times: x:=Delete(Q); Push(S,x). Next repeat n times: x:=Pop(S); Insert(Q,x). Finally repeat n times: x:=Delete(Q); Push(S,x). Here Delete removes the queue front, Insert appends at its rear, Push adds at the stack top, and Pop removes the top. No direct indexing or knowledge of either implementation is needed.

Let the original queue, from front to rear, be q1,q2,…,qn. After the first pass Q is empty and S is qn,…,q2,q1 from top to bottom, because each successive pushed item covers the previous one. The second pass pops in that reversed order and enqueues it, producing Q front-to-rear qn,…,q2,q1 and leaving S empty. The third pass reverses that queue order once more on the stack, leaving S top-to-bottom q1,q2,…,qn, exactly as required, and Q empty.

There are six primitive operations per item across the three passes, hence 6n operations and O(n) time under the usual constant-time ADT operations. Only x and counters are additional storage. The originally supplied queue and stack are reused rather than allocating another container. Recursively popping and pushing could also reverse an order but would consume O(n) call-stack storage and would violate the additional-space condition. The empty case performs no operations and already meets the postcondition.
