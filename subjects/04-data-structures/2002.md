## Solution

Step 2: Put the target in the final node. Before examining that node, none of the earlier comparisons succeeds, so there are n−1 failed comparisons and one successful comparison. Conclusion and qualifications: An absent key or a key only at the final node requires examining all n nodes. Each node entails one comparison with the search key, so the worst case is n, D.

Step 2: If child sizes are a≥b, the weight constraint gives a≤2b. Since a+b=n−1, this implies a≤2(n−1)/3. Repeating the inequality along a path yields geometric shrinkage and a logarithmic height. Integer rounding prevents the option from being an exact height formula; its role is to express the extremal shrinkage factor rather than a literal answer for every small n.

Conclusion and qualifications: A child subtree contains at most2(n−1)/3 nodes. Following a deepest branch therefore shrinks the remaining size by at least a constant factor3/2, yielding height at most log_(3/2)n+O(1). The displayed logarithm is a growth bound, not an exact integer height for every n; rounding and admissible tree sizes matter.

## Solution

Step 1: Walk through a one-stack evaluation.

Step 2: For postfix tokens a b + c *, push a then b, pop them and push a+b, then push c, and finally replace the top two values with(a+b)c. The same procedure handles arbitrary finite postfix expressions by induction on the expression tree. Extra stacks can help conversion or implementation, but are not inherently required for evaluation.

Conclusion and qualifications: For a postfix representation, push operands and replace the required top operands by the result whenever an operator is encountered. One evaluation stack suffices for any finite expression tree without embedded calls, A. Infix parsing can use a combined stack representation or first produce postfix; two separate stacks are a convenient implementation, not a necessity.

# GATE 2002: Q60 (printed B Q6)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203519/GATE2002.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Exactly 5 ordered binary trees

## Solution

1. Use the first preorder symbol to fix the root. Preorder visits root, then left subtree, then right subtree. Therefore every requested tree must have C at its root.

2. Partition the two remaining nodes between C’s subtrees. The possible left/right subtree sizes are (2,0), (0,2), and (1,1). These cases exhaust the possibilities because there are exactly two nodes besides C.

3. Handle the two single-subtree cases. For sizes (2,0), B is C’s left child, and A is either B’s left child or B’s right child: two trees. For sizes (0,2), B is C’s right child, and A again has two child positions: two more trees. B must precede A because their subtree’s preorder must be B,A.

4. Handle sizes (1,1). Preorder visits the entire left subtree before the right, so the left child is B and the right child is A: one tree. Reversing those children would give C,A,B and is not allowed.

5. Draw the resulting 2 + 2 + 1 = 5 ordered binary trees:

```text
(1)      C         (2)      C
        /                 /
       B                 B
      /                   \
     A                     A

(3)      C         (4)      C
          \                 \
           B                 B
          /                   \
         A                     A

(5)      C
        / \
       B   A
```

6. Verify each tree by reading root-left-right. Each gives C,B,A. The exhaustive subtree-size split proves that no additional ordered binary-tree shape can qualify. In explicit node(left,right) notation, with - for no child, the five trees are C(B(A(-,-),-),-), C(B(-,A(-,-)),-), C(-,B(A(-,-),-)), C(-,B(-,A(-,-))), and C(B(-,-),A(-,-)).
