**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C with head-only representations; stored tails also suffice

**Essential problem context (paraphrased):** Which standard representation permits O(1) concatenation: singly linked, doubly linked, circular doubly linked, or array list?

## Solution

A circular doubly linked list exposes its tail as head.prev. For nonempty lists with heads h1, h2 and tails t1, t2, set t1.next=h2, h2.prev=t1, t2.next=h1, h1.prev=t2. Only four links change, so concatenation is O(1), C. Empty-list cases need only pointer assignments. A head-only linear list requires traversal to find its tail, but an explicitly stored tail pointer also makes singly or doubly linked concatenation constant-time. Thus uniqueness of C depends on the usual representation metadata, not merely the link direction.

**Independently derived answer:** A

**Essential problem context (paraphrased):** Which structure is essential for efficient infix-to-postfix conversion: operator stack, operand stack, both stacks, or parse tree?

## Solution

Operands can be emitted directly to the postfix output. Operators must wait until higher-precedence operators and parenthesized subexpressions are resolved, so a stack stores pending operators and delimiters. When an operator is popped, it is appended to the output. Thus the standard shunting-yard conversion needs an operator stack, A, not an operand-value stack. An operand stack is used later to evaluate postfix, and an explicit parse tree is an alternative representation rather than a requirement of this direct conversion.

**Independently derived answer:** D as the sufficient unambiguous scheme

**Essential problem context (paraphrased):** A priority queue is used to implement a LIFO stack. PUSH inserts an item with a chosen integer key; POP deletes the minimum. Should keys be nonincreasing, nondecreasing, strictly increasing, or strictly decreasing?

## Solution

The newest live item must have the smallest key so it is returned first. Assign successively decreasing keys, for example 0, −1, −2, …; then delete-min exactly follows last-in-first-out order. Strict decrease prevents ties whose unspecified resolution could return an older item. Thus D is the standard sufficient choice. A merely nonincreasing sequence permits equal keys and does not guarantee LIFO without an extra tie rule. Keys need only outrank still-live items, so global decrease is a simple implementation policy rather than the only possible schedule-aware assignment.

# GATE 1997: Q53 (printed A Q8)

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B5=p; B8=change; B10=q^.next; B11=p^.next.

**Essential problem context (paraphrased):** A singly linked list L=(a1,…,an), n≥0, has nodes with fields next:^list and val:integer. Swap adjacent pairs a_(2i−1),a_(2i), 1≤i≤floor(n/2), by filling the four boxes:
1 function change(p:^list):^list;
2 var q,t:^list;
3 begin
4   if p=nil then change:=p
5   else if p^.next=nil then change:=[B5]
6   else begin
7     q:=p^.next;
8     [B8]:=q;
9     t:=q^.next;
10    [B10]:=p;
11    [B11]:=change(t)
12  end
13 end

## Solution

The required fillings are line 5: p; line 8: change; line 10: q^.next; line 11: p^.next. With them, the nontrivial branch is

q := p^.next;
change := q;
t := q^.next;
q^.next := p;
p^.next := change(t).

Before the change, the first two nodes and the remaining list have the shape p → q → t. The function must return q as the new head, so line 8 assigns the function result rather than overwriting a next pointer. Save t before reversing q's link; otherwise the remaining list could be lost. Then q^.next:=p reverses the first pair, and p^.next:=change(t) joins its second node to the recursively transformed remainder. The final shape is q → p → change(t).

For an empty list, returning nil preserves it. For a one-node list, returning p preserves the last unpaired node. These are also the induction bases. Assuming the recursive call correctly swaps all pairs in the suffix of length n−2, linking the reversed first pair to that result swaps every required pair in the whole list and preserves every node exactly once.

For example, 1→2→3→4→5 becomes 2→1→4→3→5. The code exchanges nodes through pointers, not merely their stored integer values. It takes Θ(n) time and Θ(n) recursive-stack space, with about floor(n/2) pair-processing calls. Pascal's function-name assignment in line 8 is the mechanism for returning a pointer; it is not another recursive call.

# GATE 1997: Q72 (printed B Q16(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 3 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Every such tree has N≥2^h; the bound is attainable.

**Essential problem context (paraphrased):** A size-balanced binary tree has, at every node, left and right subtree sizes differing by at most one. Node distance is the number of edges from the root, and tree height h is the greatest root-to-leaf distance. Prove by induction on h that a tree of height h has at least 2^h nodes.

## Solution

Use induction on the nonnegative height h. For h=0 the tree consists of the root, so N=1=2^0.

For h≥1, at least one child subtree has height h−1; otherwise no root-to-leaf path could have length h. Call that subtree T and let its size be s. By the induction hypothesis, s≥2^(h−1). The other child subtree has size t≥s−1, because the defining balance condition bounds the size difference by one. Empty subtrees are allowed and have size zero, so this also handles h=1.

Counting the root gives

N=1+s+t ≥1+s+(s−1)=2s ≥2^h.

This proves the assertion. We did not assume the two subtrees have equal height or that every level is full. Size balance is a statement about node counts, and the proof uses exactly that statement.

The bound is sharp. For h≥1, combine a minimum-size tree of height h−1, with 2^(h−1) nodes, and a perfect tree of height h−2, with 2^(h−1)−1 nodes, below a new root. Their sizes differ by one and their subtrees satisfy the same condition. The total is 2^h and the height is h. At h=1 the smaller subtree is empty. This construction also explains why the stronger bound 2^(h+1)−1 would be false: a size-balanced tree need not be perfect at its last level.

# GATE 1997: Q73 (printed B Q16(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Exactly 2^(h−1).

**Essential problem context (paraphrased):** A size-balanced binary tree has, at every node, left and right subtree sizes differing by at most one. Node distance is the number of edges from the root, and tree height h is the greatest root-to-leaf distance. For h≥1, how many nodes are at distance h−1 from the root?

## Solution

The level at distance h−1 is full, so it contains 2^(h−1) nodes. To justify fullness rather than assume it, first use the proved size bound: a size-balanced tree of height h has N≥2^h nodes.

For any node whose subtree has s nodes, its child sizes sum to s−1 and differ by at most one. Hence each child has at least floor((s−1)/2) nodes. Starting from N≥2^h, induction on depth shows that every node at depth d≤h−1 has subtree size at least 2^(h−d)−1. Indeed, a parent lower bound 2^(h−d)−1 gives each child at least 2^(h−d−1)−1.

In particular, at every depth d<h−1 this lower bound is at least 3. Such a subtree has both children nonempty. Beginning with one root, the node count therefore doubles at each step until depth h−1, giving exactly 2^(h−1) nodes there. The last level h may be only partly occupied, so this does not assert that the entire tree is perfect.

For h=1 the requested level is the root itself and the formula gives 1. For h=2 a smallest example has four nodes: its depth-1 level still has both children, while only one node need occur at depth 2. GFG explicitly states h≥1. GateForum visibly prints h≤1; under that literal restriction h=0 would ask for a negative distance, so the nonnegative-depth question uses the coherent GFG range and flags the typo.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Independently derived answer:** n−1.

**Essential problem context (paraphrased):** The following C-like code removes duplicate values from a sorted singly linked list. Node has int val and Node *next. Assume the input is acyclic and contains n≥2 nodes; j points to a separate valid integer. Pointer-member syntax is normalized from the reproduced typesetting.
Node *remove_duplicates(Node *head,int *j) {
  Node *t1,*t2;
  *j=0;
  t1=head;
  if(t1!=NULL) t2=t1->next;
  else return head;
  *j=1;
  if(t2==NULL) return head;
  while(t2!=NULL) {
    if(t1->val!=t2->val) {             /* S1 */
      (*j)++; t1->next=t2; t1=t2;      /* S2 */
    }
    t2=t2->next;
  }
  t1->next=NULL;
  return head;
}
How many times is the comparison S1 evaluated?

## Solution

The first input node is taken as the initial retained node t1. Before the loop, t2 is set to the second input node. The loop then advances t2 exactly once through every remaining original node, stopping at NULL. Since there are n−1 nodes after the first, S1 is evaluated exactly n−1 times.

Rewiring t1->next inside S2 does not skip any as-yet unvisited node. When S2 executes, t1 is moved to the current t2, but that current node's own next pointer has not been changed. The subsequent t2=t2->next therefore advances to its original successor. When S2 does not execute, t1 remains the retained node and the same successor step still happens. Thus all-equal and all-distinct lists perform the same number of value comparisons.

For example, on [1,1,2,2], S1 compares the second 1, first 2, and second 2 against the current retained value, for three comparisons. The while-condition test is a different comparison and is not included in this count.

# GATE 1997: Q76 (printed B Q18(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Minimum 0; maximum n−1. For d distinct values, the block runs d−1 times.

**Essential problem context (paraphrased):** The following C-like code removes duplicate values from a sorted singly linked list. Node has int val and Node *next. Assume the input is acyclic and contains n≥2 nodes; j points to a separate valid integer. Pointer-member syntax is normalized from the reproduced typesetting.
Node *remove_duplicates(Node *head,int *j) {
  Node *t1,*t2;
  *j=0;
  t1=head;
  if(t1!=NULL) t2=t1->next;
  else return head;
  *j=1;
  if(t2==NULL) return head;
  while(t2!=NULL) {
    if(t1->val!=t2->val) {             /* S1 */
      (*j)++; t1->next=t2; t1=t2;      /* S2 */
    }
    t2=t2->next;
  }
  t1->next=NULL;
  return head;
}
What are the minimum and maximum numbers of executions of the block S2?

## Solution

The list is sorted, so equal values occur in contiguous runs. The first run's first node is retained before the loop begins. Thereafter S2 executes precisely when t2 reaches the first node of a new value run, because its value differs from that in the last retained node t1.

If the input has d distinct values, there are d runs and exactly d−1 transitions to new runs. Thus the S2 block, and each of its three statements, executes d−1 times. Since 1≤d≤n for a nonempty list, the minimum is 0 and the maximum is n−1.

The minimum occurs when all n values are equal: every comparison S1 is false, t1 stays at the first node, and the final t1->next=NULL detaches all duplicate nodes from the returned chain. The maximum occurs when all n values are distinct: every one of the n−1 loop iterations takes S2, retains the current node and advances t1.

For [1,1,2,2,3], d=3 and S2 runs twice, once on the first 2 and once on the first 3. It does not run once per duplicate removed. This distinction prevents reversing the extremes: an all-equal list removes the most duplicate links but executes S2 the fewest times. The final NULL assignment is outside S2 and is not counted as one of these block executions.

What does the integer *j contain when the function completes?

## Solution

For a nonempty list, the code explicitly sets *j=1 before entering the loop. This counts the first retained value. Every later S2 execution marks the first encounter with a new value and increments *j once. Since sorted order puts equal values together, no later run repeats an earlier value.

If there are d distinct input values, S2 executes d−1 times and the final value is 1+(d−1)=d. The returned chain contains exactly one representative of each run, so d is also its number of nodes. For [2,2,5,5,5,9], the initialization counts 2, and the two increments count 5 and 9, giving *j=3. The number of removed duplicate nodes is n−*j, not *j itself.

The early cases are consistent even though this question assumes n≥2. An empty list returns with *j=0; a one-node list returns with *j=1. The *j=1 assignment after the empty-list check is therefore essential to interpreting the result. Omitting it would incorrectly leave the counter at d−1.

The function changes links but does not free detached nodes. Its logical output is deduplicated, but claiming that it releases their memory would go beyond the code. Sortedness is also essential for “distinct values”: on an unsorted list such as [1,2,1], the code would count three runs rather than two globally distinct values. This explanation applies to the ordered-list precondition actually given.
