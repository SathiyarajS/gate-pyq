**Paraphrased problem context:** An efficiently implemented array-based queue contains n items. Which complexity statement is correct? A: Both ENQUEUE and DEQUEUE can be O(1). B: At most one is O(1), with the other worst-case Ω(n). C: Both are worst-case Ω(n). D: Both are worst-case Ω(log n).

## Solution

A fixed-capacity circular array stores front/rear indices and wraps them modulo capacity. Enqueue writes at rear and advances it; dequeue reads at front and advances it. Both take O(1) without shifting elements, A, with overflow handled separately from dynamic resizing.

Maintain an item count or an extra full/empty flag to distinguish a full circular queue from an empty one when indices coincide. Each operation performs a bounded number of array accesses and index updates independent of n. Removing the head does not require compacting the stored elements because the front index identifies the new head. An implementation that shifts every item is possible, but the question asks what an efficient representation can achieve, not what every array implementation does.

**Paraphrased problem context:** An array-stored binary heap has depth d, measured in root-to-farthest-leaf edges. After deleting the item at arbitrary index i, what is the efficient worst-case time for restoring heap order? A: O(1). B: O(d) but not O(1). C: O(2^d) but not O(d). D: O(d·2^d) but not O(2^d).

## Solution

Replace the deleted element with the last heap element, reduce the heap size, then sift up if the parent order is violated or otherwise sift down. At most one root-to-leaf path is traversed, length≤d. Some deletions require movement throughΘ(d) levels, so the worst-case bound is O(d) and not O(1), B.

Replacing the deleted slot with the last array element preserves the complete-tree shape and avoids shifting an entire subtree. For a min-heap, compare the replacement with its parent: if it is too small, move it upward; otherwise any violation can only be below it, so move it downward by choosing the smaller child. The max-heap case reverses inequalities. There are at most d edges on the chosen path, with constant work at each, and worst-case inputs require traversal to the root or deepest leaf.

**Paraphrased problem context:** Initially queue Q holds 16 numbers and stack S is empty. Head and Top inspect without removing. Repeat while Q is nonempty: if S is empty or Top(S)≤Head(Q), dequeue Q's head and push it on S; otherwise pop S's top and enqueue it at Q's tail. What is the maximum number of loop iterations?

## Solution

Let F(n) be the maximum number of loop iterations with n queued values and no relevant stack entries. Until a minimum queued value is pushed, each value originally preceding that minimum is pushed at most once and popped at most once: popped items return behind the minimum. Thus this phase costs at most 2n−1 iterations. Once the minimum is pushed it never pops, leaving at most n−1 values to process above it. Hence F(n)≤2n−1+F(n−1), giving F(n)≤n². A strictly descending initial queue attains equality at each phase, because all preceding values are pushed and popped and return in descending order behind the minimum. Therefore F(16)=256.

Each loop iteration moves one item either from Q to S or from S to Q. For a descending input 16,15,...,1, the first phase moves 15 earlier values onto the stack and back off before finally pushing 1:31 moves. That 1 never leaves, and the remaining values are again descending, giving phases 29,27,...,1. Their sum is 16^2=256. The upper-bound argument counts at most one push and one pop before the next minimum is fixed, so the example achieves the maximum rather than merely a large runtime.

**Paraphrased problem context:** BFS starts at the root of a binary tree. Vertex t is at distance 4 from the root and is the nth visited vertex, counting the root first. Find the maximum n.

## Solution

BFS visits all shallower levels first. A full binary tree has 1+2+4+8=15 nodes above level4 and at most 16 nodes on level4. Taking t last on that level gives position 31, attained by a perfect tree through level4.

The last possible position at depth d in a binary tree is Σ(k=0 to d)2^k=2^(d+1)−1. Nodes at greater depth cannot precede t in BFS. Sparse levels or placing t earlier can only reduce its ordinal, so a full tree and a last-on-level choice attain the bound.

**Paraphrased problem context:** A sorted doubly linked list initially holds N items. Delete and decrease-key receive pointers to their records. An algorithm performs, in order, Θ(N) deletes, O(log N) inserts, O(log N) finds and Θ(N) decrease-key operations. Select total time: A O(log²N); B O(N); C O(N²); D Θ(N² log N).

## Solution

With the node pointer, doubly linked deletion is O(1). Maintaining sorted order can require O(N) search per insertion, find, or decrease-key repositioning. Thus Θ(N) deletions cost O(N), O(log N) insert/find calls cost O(N log N), and Θ(N) decreases cost O(N²) in the worst case. Total O(N²), C; the deletion count may leave Θ(N) elements, allowing this worst case.

A pointer removes the need to locate a node for deletion, but decreasing its key may move it far left to preserve order. Relinking is constant time; locating the new position can be linear. A linked list does not permit constant-time access to a middle index, so sortedness alone does not give array-style logarithmic binary search.

**Paraphrased problem context:** A complete binary min-heap contains each integer 1,…,1023 exactly once. Root depth is 0. What is the greatest possible depth of key 9?

## Solution

A node at depth d has d strictly smaller ancestors in a heap of distinct keys. Key9 has only eight smaller values, so d≤8, also below the full tree’s maximum depth 9. Place1..9 along a root-to-depth 8 chain and assign remaining keys in a parent-before-child order; all heap inequalities can be satisfied. Thus depth 8 is attainable.

There are 1023=2^10−1 nodes, so levels 0 through 9 exist. Depth 9 would require nine ancestors smaller than 9, but only eight values qualify. A heap is not a BST: siblings need not be numerically ordered, so the remaining values can be assigned without imposing a search-tree constraint on the chosen chain.

**Paraphrased problem context:** New-order visits root, then right subtree, then left subtree recursively. For the expression tree of postfix “3 4 * 5 - 2 ^ 6 7 * 1 + -”, choose its New-order. A + - 1 6 7 * 2 ^ 5 - 3 4 *; B - + 1 * 6 7 ^ 2 - 5 * 3 4; C - + 1 * 7 6 ^ 2 - 5 * 4 3; D 1 7 6 * + 2 5 4 3 * - ^ -.

## Solution

The postfix expression gives root subtraction with left subtree((3*4)−5)^2 and right subtree(6*7)+1. Root-right-left order visits −, then + 1 * 7 6, then ^ 2 − 5 * 4 3. Thus − + 1 * 7 6 ^ 2 − 5 * 4 3, C.

Build the tree with a stack: push operands; for an operator pop the right child first, then the left child. The final minus combines the two large subexpressions. Reversing child visits does not exchange the operands in the original expression; it changes only traversal order. In particular the right multiplication is visited * 7 6, excluding B.

**Paraphrased problem context:** How many permutations of 1,…,7, inserted into an empty BST, produce height 6? Height counts edges, so a one-node tree has height 0.

## Solution

Height6 with seven nodes means every node lies on one chain. The first inserted value must be the smallest or largest remaining key; otherwise both subtrees would be nonempty and the tree could not be a chain. Recursively choose either endpoint for each of the first six insertions, with the last forced. This gives 2^6=64 distinct insertion orders.

For a chain, all remaining keys must fall on one side of each successive root. Thus the smallest or largest key is chosen repeatedly. This counts insertion permutations, not merely final shapes. For three keys the valid orders are 123,132,312,321, illustrating the recurrence C(k)=2C(k−1), C(1)=1.
