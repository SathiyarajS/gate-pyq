**Paraphrased problem context:** Height means the length in edges of the longest root-to-leaf path. Find maximum and minimum node counts of a binary tree of height 5. A 63 and 6; B 64 and 5; C 32 and 6; D 31 and 5.

## Solution

Levels run from depth 0 through 5. At most 2^d nodes fit at depth d, so the maximum is the geometric sum 2^6−1=63. The minimum still requires one path containing five edges, hence six vertices. The number 32 counts only the possible last-level nodes, not the entire tree.

Baseline derivation and retained qualifications: Height5 counts edges. The complete tree has 1+2+4+8+16+32=63 nodes; a single path needs 6. Thus maximum63 and minimum6, A.

**Paraphrased problem context:** An algorithm performs N inserts and sqrt(log N) each of find, delete, decrease-key on ordered keys. Delete and decrease-key receive pointers to their records. Which structure minimizes total asymptotic cost? A unsorted array; B min-heap; C sorted array; D sorted doubly linked list.

## Solution

Let k=sqrt(log N). Unsorted insertion is constant amortized time, while each arbitrary-key find scans O(N), giving O(N+Nk)=O(Nsqrt(log N)). Even charging O(N) per deletion for compaction leaves the same order; decrease-key requires no ordering repair. A binary heap's online inserts can cost Θ(Nlog N) altogether and it does not speed arbitrary-key search. Sorted structures pay to locate or maintain insertion positions, potentially Θ(N²). Pointer access removes the search for a deletion target, not the need to preserve a chosen ordering.

Baseline derivation and retained qualifications: Let k=sqrt(log N). With an unsorted array, N insertions take O(N) amortized and k arbitrary-key finds take O(Nk); pointer-directed deletion and decrease-key need at most O(Nk) total even if compaction work is charged. Total O(Nsqrt(log N)). A standard online binary min-heap costs O(Nlog N) for N worst-case insertions, and arbitrary-key finds are still linear. Maintaining sorted arrays or lists can cost Θ(N²) over the N insertions. Thus the unsorted array is best among the listed textbook online structures, A. This comparison is for the specified operation model, not an alternative offline bulk-sorting/heap-building algorithm.

**Paraphrased problem context:** A complete binary tree has both root subtrees already max-heaps. What lower bound describes operations to turn it into a heap? AΩ(logn), BΩ(n), CΩ(nlogn), DΩ(n²). The intended interpretation is worst-case repair work, not a lower bound for every instance.

## Solution

Sift the root down, swapping with the larger child until order is restored. The path can have Θ(log n) levels, and a smallest root with heap-ordered descendants realizes that worst case. Thus the intended worst-case lower bound is Ω(log n), A. It is not a per-instance lower bound: a root already exceeding its children needs only constant checking.

Teaching detail:
Only the root can violate heap order because its subtrees already satisfy it. Compare the root with its larger child and swap downward as needed; each swap moves the offending value one level. A complete n-node tree has height Θ(logn), and placing a sufficiently small value at the root can force a descent to a leaf. That is the intended worst-case lower bound matched by sift-down. If the root already dominates its children, constant work is enough, so the statement cannot mean every instance requires logarithmic work.

## Solution

Let n0, n1, n2 count nodes with 0, 1, 2 children. Counting edges gives n1+2n2=n0+n1+n2−1, so n2=n0−1=19, regardless of one-child nodes.

Teaching detail:

Equating U+2B=L+U+B−1 cancels U and gives B=L−1. Hence 20 leaves imply 19 two-child nodes, regardless of how many unary nodes occur.

## Solution

Standard Young-tableau deletion moves the smaller right/down neighbor into the hole. Removing 1 successively shifts 2, 4, 6, 18, 25, then places infinity at(3, 4), giving five moved entries. At each step selecting a larger adjacent neighbor would violate the row/column inequality with the smaller one, so this is the forced minimum adjacent-shift deletion path.

This proves minimality for the conventional adjacent-hole sliding model, not by itself for arbitrary whole-table rearrangement; the source does not explicitly restrict movements to adjacent cells.

**Paraphrased problem context:** Which hash best distributes integers i=0…2020 over buckets 0…9? A i²mod 10; B i³mod 10; C11i²mod 10; D12 imod 10.

## Solution

Cubing permutes decimal residues: 0, 1, 8, 7, 4, 5, 6, 3, 2, 9. Therefore each block of 10 consecutive keys places one in each bucket. Among 2021 keys bucket 0 gets 203 and every other bucket 202, optimally balanced. Squares use only six residues, 11i² is identical modulo 10, and 12i only reaches even buckets. Thus B.

Teaching detail:
Only the last decimal digit matters modulo 10. Cubes of residues 0 through 9 give 0, 1, 8, 7, 4, 5, 6, 3, 2, 9, which is a permutation. Each full ten-key block therefore hits every bucket once. The 2021 keys consist of 202 full blocks plus one extra key 0 mod 10, giving counts 203, 202, …, 202, as balanced as possible. Squaring collapses residues, 11i²has the same residues as i², and 12i≡2i can only reach even buckets.

## Solution

1. Let n0,n1,n2 count nodes with zero, one and two children. Every non-root node contributes one incoming edge, so E=n0+n1+n2−1. Counting edges from parents instead gives E=n1+2n2; subtracting cancels n1 and yields the result without assuming a full binary tree.

2. Counting tree edges gives n1+2n2=n0+n1+n2−1. Hence the number with two children is n2=n0−1=200−1=199.
