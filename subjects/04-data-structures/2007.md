## Solution

For ordered binary trees, let T(0)=1 and T(n)=sum T(i)T(n−1−i). Then T(1)=1,T(2)=2 and T(3)=2+1+2=5, B. Left and right child positions are distinguished, as in the standard binary-tree convention; unlabeled does not mean unordered.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B under linear probing

## Solution

The hash values for1,3,8,10 are0,6,0,6. With linear probing, place1 at0 and3 at6;8 probes from0 to1;10 probes6,0,1 and lands at2. The table is[1,8,10,empty,empty,empty,3], B. Closed hashing/open addressing does not alone specify the probing sequence; quadratic or double hashing could differ, so linear probing is an explicit assumption rather than a stated guarantee.

## Solution

Count the edges in two ways. Each of the I internal nodes contributes exactly n child edges, while a tree with I+L vertices has I+L−1 edges. Thus nI=I+L−1 and n=(10+41−1)/10=5 (C). The question calls this complete, but explicitly defines the full n-ary property, which is all the calculation needs.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

## Solution

GetValue returns zero for a null pointer, one when both children are null, and otherwise the sum of the values for the left and right subtrees. By induction on the tree, this counts precisely the leaves: an internal node adds no contribution of its own. Therefore C, the number of leaf nodes, is correct, including zero for an empty tree.

# GATE 2007: Q47 (printed CS Q47)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 11. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

## Solution

A complete binary heap has a root-to-new-leaf path containing Θ(log n) positions. Existing keys along this path are monotone because it is a max heap. Binary search among h=Θ(log n) positions uses Θ(log h)=Θ(log log n) key comparisons in the usual worst-case interpretation, so B. This is a bound on comparisons, not all insertion work: shifting keys along the path can still require Θ(log n) moves. Array indices allow an ancestor at a specified depth to be selected without doing key comparisons.
