**Paraphrased problem context:** The height of a binary tree is the maximum number of edges on a root-to-leaf path. What is the maximum number of nodes at height h?
Options:
(A) 2^h−1
(B) 2^(h−1)−1
(C) 2^(h+1)−1
(D) 2^(h+1)

## Solution

1. Approach. With edge height, the root is at depth zero. Count all levels including both level zero and level h, rather than counting only h levels.

2. Derivation and interpretation. At depth i a binary tree has at most2^i nodes. For edge height h, depths 0 through h sum to 1+2+...+2^h=2^(h+1)−1, C, attained by a perfect binary tree.

**Paraphrased problem context:** How many different binary trees can be formed using three unlabeled nodes?
Options:
(A) 1
(B) 5
(C) 4
(D) 3

## Solution

1. Approach. Distinguish left and right child positions. There are four three-node chains (LL, LR, RL, RR) and one root with two children.

2. Derivation and interpretation. For ordered binary trees, let T(0)=1 and T(n)=sum T(i)T(n−1−i). Then T(1)=1,T(2)=2 and T(3)=2+1+2=5, B. Left and right child positions are distinguished, as in the standard binary-tree convention; unlabeled does not mean unordered.

**Paraphrased problem context:** Evaluate the postfix expression 8 2 3 ^ / 2 3 * + 5 1 * − using a stack; ^ denotes exponentiation. What are the top two stack elements, top first, immediately after the first * is evaluated?
Options:
(A) 6,1
(B) 5,7
(C) 3,2
(D) 1,5

## Solution

1. Approach. For each operand, push; for each binary operator, pop right operand then left operand, compute left op right, and push the result. Stop at the first multiplication rather than evaluating the whole expression.

2. Derivation and interpretation. Read 8,2,3, then exponentiation replaces 2,3 with 8; division replaces 8,8 with 1. Push 2 and 3; the first multiplication replaces them with 6. The stack is now [1,6] from bottom to top, so its top two elements are 6,1, A.

**Paraphrased problem context:** A binary tree has inorder traversal d,b,e,a,f,c,g and preorder traversal a,b,d,e,c,f,g. What is its postorder traversal?
Options:
(A) d,e,b,f,g,c,a
(B) e,d,b,g,f,c,a
(C) e,d,b,f,g,c,a
(D) d,e,f,g,b,c,a

## Solution

1. Approach. The first preorder item is the root. Its position in inorder separates left and right subtrees; recursively repeat, then output left subtree, right subtree, root.

2. Derivation and interpretation. Preorder starts with root a. Inorder splits the left subtree as d,b,e and the right as f,c,g. The remaining preorder makes b the left root with children d,e, and c the right root with children f,g. Postorder is d,e,b,f,g,c,a, option A.

# GATE 2007: Q40 (printed CS Q40)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 9. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B under linear probing

**Paraphrased problem context:** An initially empty hash table has seven slots indexed 0–6 and h(x)=(3x+4) mod 7. Insert 1,3,8,10 in that order using “closed hashing” as stated in the source. Which final table is intended? A dash means an empty slot. The probing rule is not explicitly specified.
Options:
(A) [8,−,−,−,−,−,10]
(B) [1,8,10,−,−,−,3]
(C) [1,−,−,−,−,−,3]
(D) [1,10,8,−,−,−,3]

## Solution

1. Approach. Under linear probing, collisions advance one slot at a time with wraparound modulo 7. Compute each home position before inserting and never overwrite an occupied slot.

2. Derivation and interpretation. The hash values for 1,3,8,10 are 0,6,0,6. With linear probing, place 1 at 0 and 3 at 6;8 probes from 0 to 1;10 probes 6,0,1 and lands at 2. The table is [1,8,10,empty,empty,empty,3], B. Closed hashing/open addressing does not alone specify the probing sequence; quadratic or double hashing could differ, so linear probing is an explicit assumption rather than a stated guarantee.

**Paraphrased problem context:** Here a complete n-ary tree means each node has exactly n children or none. It has I=10 internal nodes and L=41 leaves. Find n.
Options:
(A) 3
(B) 4
(C) 5
(D) 6

## Solution

1. Approach. Count child edges once from the parent side and once using the identity edges=vertices−1 for a tree. Equating the counts eliminates the shape of the tree.

2. Derivation and interpretation. Count the edges in two ways. Each of the I internal nodes contributes exactly n child edges, while a tree with I+L vertices has I+L−1 edges. Thus nI=I+L−1 and n=(10+41−1)/10=5 (C). The question calls this complete, but explicitly defines the full n-ary property, which is all the calculation needs.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 11. Consult original wording and choices.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** CellNode represents a binary-tree node. What does GetValue return when called on the root?
struct CellNode {
    struct CellNode *leftChild;
    int element;
    struct CellNode *rightChild;
};
int GetValue(struct CellNode *ptr) {
    int value=0;
    if(ptr!=NULL) {
        if(ptr->leftChild==NULL && ptr->rightChild==NULL)
            value=1;
        else value=value+GetValue(ptr->leftChild)+GetValue(ptr->rightChild);
    }
    return value;
}
Options:
(A) Number of nodes
(B) Number of internal nodes
(C) Number of leaves
(D) Tree height

## Solution

1. Approach. Check the two base cases: null contributes zero, and a node with no children contributes one. All other nodes merely add child results, so their own elements and depths are irrelevant.

2. Derivation and interpretation. GetValue returns zero for a null pointer, one when both children are null, and otherwise the sum of the values for the left and right subtrees. By induction on the tree, this counts precisely the leaves: an internal node adds no contribution of its own. Therefore C, the number of leaf nodes, is correct, including zero for an empty tree.

**Paraphrased problem context:** Insert an element into an array-represented max heap of n elements. Use binary search along the path from the new leaf to the root to locate its insertion position. What is the asymptotic worst-case number of key comparisons?
Options:
(A) Θ(log₂ n)
(B) Θ(log₂ log₂ n)
(C) Θ(n)
(D) Θ(n log₂ n)

## Solution

1. Approach. The binary search is not across the entire array. It searches the sorted ancestor chain, whose length is logarithmic in n; take the logarithm of that length.

2. Derivation and interpretation. A complete binary heap has a root-to-new-leaf path containing Θ(log n) positions. Existing keys along this path are monotone because it is a max heap. Binary search among h=Θ(log n) positions uses Θ(log h)=Θ(log log n) key comparisons in the usual worst-case interpretation, so B. This is a bound on comparisons, not all insertion work: shifting keys along the path can still require Θ(log n) moves. Array indices allow an ancestor at a specified depth to be selected without doing key comparisons.
