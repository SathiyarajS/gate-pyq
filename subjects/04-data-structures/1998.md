

# GATE 1998: Q24 (printed A Q1.24)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B under the full-tree interpretation of complete

**Essential problem context (paraphrased):** Which is false: n-node trees have n−1 edges; preorder plus postorder uniquely determine a labelled binary tree; full binary trees have leaves=internal+1; maximum nodes at edge-height h is 2^(h+1)−1?

## Solution

Take a root r with only one child c. Making c the left child or the right child gives the same preorder r, c and postorder c, r, so uniqueness fails: B. A connected acyclic n-node graph has n−1 edges. A full binary tree satisfies 2I=I+L−1, hence L=I+1. Summing complete levels 0 through h gives 2^(h+1)−1. The source says “complete” for the leaf formula; modern heap-complete trees may have a one-child node, invalidating that formula. Under that terminology C can fail too, so the intended full/proper definition is a qualification.

**Essential problem context (paraphrased):** A[1…10][1…15] is stored in row-major order, uses one memory location per integer, and A[1][1] is at 100. Find address A[i][j].

## Solution

Before row i there are i−1 complete rows, each containing 15 entries, contributing 15(i−1) locations. Within row i, column j is j−1 locations beyond its start. Add the base:100+15(i−1)+(j−1)=15i+j+84. This is A. Check i=j=1 gives 100, and increasing j by 1 advances one location, whereas increasing i by 1 advances fifteen. Those checks distinguish row-major from column-major formulas.

**Official answer:** Not available; no official key located.

**Independently derived answer:** GFG swaps nodes i+1 and i+2; GateForum creates a cycle through i+1,i+2,i+3.

**Essential problem context (paraphrased):** Initially p points to node i in i→i+1→i+2→i+3→suffix. Execute q=p.next; p.next=q.next; q.next=(q.next).next; (p.next).next=q. GateForum instead prints p.next, not q.next, on the third line. Explain both.

## Solution

Write P=i, A=i+1, B=i+2 and C=i+3. Initially P→A→B→C→suffix. With the GFG third line, step 1 sets q=A. Step 2 bypasses A by setting P.next=B. Step 3 sets A.next=C, preserving the link to the suffix. Step 4 sets B.next=A. The resulting chain is P→B→A→C→suffix: the two adjacent nodes after p have been exchanged without copying their payloads. This requires those nodes and the next fields used in the expressions to exist.

GateForum's third line is materially different. After the first two steps, q=A, P.next=B, A.next=B and B.next=C. Its third line sets P.next=C instead of changing A.next. Its last line then sets C.next=A. Thus from P the chain becomes P→C→A→B→C→..., a three-node cycle; the original suffix after C is detached from this chain. It is not an adjacent swap.

Both secondary versions are disclosed because silently replacing p by q changes the program's effect. The correct algorithmic explanation cannot establish which version appeared in the official original.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 3 x 1 + log * a 2 / −

**Essential problem context (paraphrased):** Find postfix for 3*log(x+1)−a/2.

## Solution

First parenthesize by the usual precedence and the unary function call: (3*log(x+1))−(a/2). A postfix traversal writes operands before their operator. The subtree x+1 becomes x 1 +; applying the unary log appends log, giving x 1 + log. Multiplication by 3 becomes 3 x 1 + log *. Independently, a/2 becomes a 2 /. Finally append subtraction after both subexpressions:

3 x 1 + log * a 2 / −

The spaces separate tokens, and log is one unary operator rather than three operands. Evaluating this stack form pushes 3, forms log(x+1), multiplies, forms a/2, then subtracts the right value from the left. Reversing the final operands would change the expression.

**Essential problem context (paraphrased):** Construct the tree with inorder a f b c d g e and postorder a f c g e d b.

## Solution

The final postorder symbol b is the root. Split inorder around b: left subtree has a,f and right subtree has c,d,g,e. The corresponding postorder chunks are a,f and c,g,e,d.

For the left subtree, final f is its root and a lies to its left, so f has left child a and no right child. For the right subtree, final d is its root. Inorder splits into c on its left and g,e on its right. The left child is c. The right chunk has postorder g,e, hence root e with left child g.

        b
       / \
      f   d
     /   / \
    a   c   e
           /
          g

Checking inorder yields a,f,b,c,d,g,e. Checking postorder yields a,f,c,g,e,d,b. The labels are distinct, so the recursive splits uniquely determine the tree. A different shape that merely shares the root would not suffice.

# GATE 1998: Q89 (printed B Q21(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** N(h)=1+N(h−1)+N(h−2); edge-height bases N(−1)=0,N(0)=1.

**Essential problem context (paraphrased):** Derive the minimum number N(h) of nodes in an AVL tree of height h. State the height convention.

## Solution

Take height to count edges on a longest root-to-leaf path; an empty tree has height −1 and a leaf height 0. A tree of height h must have at least one child subtree of height h−1. AVL balance permits the other to be no shorter than h−2. To minimize nodes, choose exactly those two heights and make both subtrees themselves minimum-size AVL trees. Counting the root gives N(h)=1+N(h−1)+N(h−2), with N(−1)=0,N(0)=1.

This is both a lower bound and attainable: recursively attach extremal subtrees of heights h−1 and h−2 to a root. The height difference is one, so the construction is AVL. Writing M(h)=N(h)+1 gives M(h)=M(h−1)+M(h−2), and the bases imply N(h)=F_(h+3)−1 when F0=0,F1=1.

If height instead counts levels, the empty tree is height 0 and a leaf height 1, so the same recurrence has bases N(0)=0,N(1)=1 and formula F_(h+2)−1. The recurrence is structural; the indexing convention must not be mixed between parts.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 88 nodes for edge height; 54 for level height.

**Essential problem context (paraphrased):** Find the smallest AVL tree size for height 8.

## Solution

Using the edge-height convention from part (a), start N(−1)=0,N(0)=1 and apply N(h)=1+N(h−1)+N(h−2). The values at heights 1 through 8 are 2,4,7,12,20,33,54,88. Thus the smallest tree at edge height 8 has 88 nodes. Equivalently, F11−1=89−1=88.

If the source's unstated height convention counts levels, the same physical tree's level height is one larger. A level-height-8 minimum tree therefore has edge height 7 and 54 nodes. This is not a disagreement in AVL structure, only an indexing ambiguity. Specify the convention rather than asserting both numbers describe the same notion of height.
