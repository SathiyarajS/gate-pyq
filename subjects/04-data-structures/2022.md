**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** Reverse the links of an n-node singly linked list using O(1) auxiliary space, e.g. head→a→b→c→NULL becomes head→c→b→a→NULL. What is the best worst-case time? A Θ(n); B Θ(n log n); C Θ(n²); D impossible in O(1) space.

## Solution

Keep previous, current and next pointers. Save current.next, reverse that link, and advance; at termination previous becomes the head. This uses constant auxiliary space and one pass, O(n). Reversing the links of an arbitrary n-node list requires Ω(n) link changes, so the optimum is Θ(n), A.

Teaching detail:
Executable pointer pseudocode:
prev=NULL; cur=head;
while(cur!=NULL){ next=cur.next; cur.next=prev; prev=cur; cur=next; }
head=prev;
Loop invariant: prev heads the already reversed prefix and cur heads the untouched suffix; saving next prevents losing the suffix. Only three pointer variables are needed, independent of n.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** Hash n keys into m slots, using simple-uniform hash function h1 for odd keys and h2 for even keys. Find the expected occupancy of a fixed slot. A m/n; B n/m; C 2n/m; D n/(2m).

## Solution

For a fixed slot, each key maps there with probability 1/m under whichever uniform hash function applies to its parity. Summing n indicator expectations gives n/m. Independence between all indicators is unnecessary for this expectation. Thus B.

Teaching detail:
Let Ii=1 if key i lands in the chosen slot, and 0 otherwise. Occupancy X=ΣIi. Whether i is odd or even, E[Ii]=1/m, so E[X]=ΣE[Ii]=n/m. Using two functions does not double the number of keys or halve the table.

**Official answer:** 509 to 509

**Derived answer:** 509

**Paraphrased problem context:** A BST with 1000 distinct keys is a complete binary tree, stored in zero-based heap-array positions 0…999. At what index is its third-largest key?

## Solution

The maximum key lies on the right spine, with zero-based array indices 0, 2, 6, 14, 30, 62, 126, 254, 510. Index 510 has no children because their indices exceed 999. The predecessor is its parent 254. The next predecessor is the maximum in 254’s left subtree, rooted at 509; 509 has no children either. Hence the third largest key is at index 509.

Teaching detail:
The heap-array formulas are left(i)=2i+1, right(i)=2i+2; they locate nodes, not key ordering. BST ordering implies reverse inorder visits largest first. At 254, the right child is 510 and left child 509. Both are leaves, so the first three reverse-inorder positions are 510,254,509.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 0 to 0

**Derived answer:** 0

**Paraphrased problem context:** Q1 initially contains four elements in front-to-back order 1,2,3,4 and Q2 is empty. Only Enqueue and Dequeue on either queue are permitted, with no extra storage. End with Q1 empty and Q2 front-to-back 4,3,2,1. What minimum number of Enqueue operations on Q1 is necessary?

## Solution

No enqueue into Q1 is necessary. Move its front item to Q2, then rotate Q2 by moving each of its previously present items from front to back. Starting with Q2 empty, the successive states after these steps are [1], [2, 1], [3, 2, 1], [4, 3, 2, 1]. Each insertion is Enqueue(Q2, Dequeue(Q1)), and rotations are Enqueue(Q2, Dequeue(Q2)); Q1 is never enqueued. Since the count cannot be negative, the minimum is 0. As in the allowed operation model, a dequeued value can be passed directly to enqueue without an auxiliary storage data structure.

Teaching detail:
Construction using only queue operations: after transferring item k from Q1 to Q2, rotate Q2 exactly k−1 times by Enqueue(Q2,Dequeue(Q2)). Before rotation Q2=[k−1,…,1,k], and afterward [k,k−1,…,1]. Induction establishes reversal after four transfers. The rotations cost enqueues on Q2, which the objective does not count.
