

# GATE 2001: Q15 (printed A Q1.15)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B for nonroot nodes

**Essential problem context (paraphrased):** A binary heap occupies array indices 1 through n. For an element at index i, choose the parent index from i−1, floor(i/2), ceil(i/2), and (i+1)/2. Account for the root boundary.

## Solution

Step 1: A node at index j has left child 2j and right child 2j+1. For an even child index i=2j, division gives i/2=j. For an odd child i=2j+1, floor(i/2)=j.

Step 2: Both cases are captured by floor(i/2), B. For example indices 6 and 7 both have parent 3; ceiling would incorrectly map 7 to 4.

Boundary: The root at i=1 has no parent. The formula returns sentinel index 0, outside the heap, rather than describing a genuine parent.

# GATE 2001: Q41 (printed A Q2.16)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B under the standard auxiliary-storage model

**Essential problem context (paraphrased):** Under the usual stack-only auxiliary-storage model, what is the minimum number of size-n stacks needed to implement a size-n queue: one, two, three, or four?

## Solution

Step 1: Push new elements onto an input stack. To dequeue, pop from an output stack; when that stack is empty, move all input elements to it. The reversal places the oldest element on top, so two stacks suffice.

Step 2: With only one LIFO stack and O(1) other element storage, reaching the oldest of n elements requires removing and retaining n−1 newer elements somewhere, so the usual general implementation needs the second stack.

Hence B in this model. A recursive “one explicit stack” implementation uses the call stack as another unbounded stack; allowing an auxiliary array or such hidden storage changes what is being counted.

# GATE 2001: Q80 (printed B Q14(c))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** S1: y=depth(t->right); S2: x+1; S3: y+1.

**Essential problem context (paraphrased):** depth(t) returns 0 for NULL, sets x=depth(t->left), then needs S1, S2 and S3 to return the tree depth.

## Solution

The null-tree base case fixes depth as the number of nodes on a longest root-to-leaf path. Each nonempty tree contributes its root plus the larger child depth. Full compilable function:

#include <stddef.h>
typedef struct node {
    int key;
    struct node *left, *right;
} *Tree;
int depth(Tree t) {
    int x, y;
    if (t == NULL) return 0;
    x = depth(t->left);
    y = depth(t->right); /* S1 */
    if (x > y) return x + 1; /* S2 */
    else return y + 1; /* S3 */
}

A leaf returns 1. The preceding tree returns 4. Each node is visited once, giving O(n) time and O(h) recursive stack space; an edge-count definition would require a different base case and is not the convention of the supplied program.
