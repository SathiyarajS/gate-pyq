**Essential problem context (paraphrased):** Match X depth-first search,Y breadth-first search,Z sorting to 1 heap,2 queue,3 stack.

## Solution

Step 1: DFS must return to the latest unfinished branch, a last-in-first-out behavior implemented by an explicit stack or recursive call stack. Thus X→3.

Step 2: BFS processes older discovered vertices first, using a FIFO queue, so Y→2. A heap supports repeated minimum/maximum extraction for sorting, so Z→1.

Together these matches give C. The sorting match refers to heap sort, not to every possible sorting algorithm.

**Independently derived answer:** D for heap-complete trees; B for perfect/full-rightmost-path convention

**Essential problem context (paraphrased):** For a “complete binary tree,” compare the last vertices in postorder,inorder,preorder. Options equate inorder/postorder,inorder/preorder,preorder/postorder,or none.

## Solution

Step 1: Postorder ends at the root. Inorder ends at the rightmost node, while preorder ends at the last leaf visited after exploring subtrees.

Step 2: Under the modern complete-tree definition (last level filled left to right), take six heap-indexed nodes. Node 3 has left child 6 but no right child. Inorder ends at 3, preorder at 6, and postorder at 1. All three differ, so none of the proposed equalities is always true: D.

If “complete” is intended to mean perfect, the rightmost node is a leaf and is last in both inorder and preorder, giving B. The terminology ambiguity is retained rather than silently imposing the stronger shape.

# GATE 2000: Q71 (printed B Q13(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** ENQUEUE(x): PUSH(x). DEQUEUE: REVERSE; x = POP(); REVERSE; return x.

**Essential problem context (paraphrased):** A stack supports PUSH, POP and REVERSE, which reverses all its elements. Implement ENQUEUE with one operation and DEQUEUE with three.

## Solution

Maintain the queue front at the bottom of the stack and its rear at the top. If queue order is a,b,c (a oldest), the stack bottom-to-top is [a,b,c]. ENQUEUE(d) executes PUSH(d), producing [a,b,c,d], exactly the required FIFO order. To remove the oldest element, REVERSE changes the stack to [d,c,b,a], POP returns a, and the second REVERSE restores [b,c,d]. Thus the invariant is restored after each completed operation. The return statement is not an additional stack operation. On an empty queue, detect underflow rather than POP an absent item. The question counts interface operations, not their implementation costs: REVERSE may require linear time in an ordinary stack representation.

## Solution

Repeated set(i) calls may put repeated copies of i into q, while p[i] records the latest position. The claim is about values that have been set, not necessarily distinct values.

# GATE 2000: Q79 (printed B Q15(c))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Either p[i] is out of the initialized range, or q[p[i]] differs from i.

**Essential problem context (paraphrased):** Arrays p[1..N] and q[1..N] initially contain arbitrary values; count=0. Pseudocode:
set(i) { count=count+1; q[count]=i; p[i]=count; }
is_set(i) { if (p[i]<=0 or p[i]>count) return false; if (q[p[i]]!=i) return false; return true; }
Assume valid indices and no capacity overflow. Prove is_set(i) returns false if set(i) has never been called, regardless of the initial p[i].

## Solution

There are two exhaustive cases. First, p[i]<=0 or p[i]>count: the first guard returns false before q is indexed, so an arbitrary invalid p[i] cannot cause an out-of-range read. Second, 1<=p[i]<=count: every cell in q[1..count] was explicitly written by some set(j) call and stores that call’s j. Since set(i) never occurred, none of these cells equals i. In particular q[p[i]]!=i, so the second guard returns false. This argument also covers count=0, when every possible integer p[i] fails the range guard. The reverse-pointer check is what prevents a coincidentally plausible initial p[i] from producing a false positive. This is an abstract-array algorithm, not permission to read indeterminate C objects: a literal C implementation must use a representation for which such reads are defined. Calls must stay within the arrays’ capacity; otherwise the premise that q[1..count] is valid fails.
