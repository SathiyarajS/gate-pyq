**Independently derived answer:** A

## Solution

A minimum occurs among the leaves. There are Θ(n) leaves and their values have no guaranteed mutual ordering. Scanning them gives O(n) time; arbitrary leaf values require Ω(n) comparisons in the worst case. Therefore Θ(n), A.

## Solution

Following right children produces indices1,3,7,...,2^n−1 for an n-node chain. No n-node tree has depth beyond n−1, whose largest possible index is2^n−1. Therefore an array indexed from1 must provide that many positions, D. This counts logical one-based entries, not an extra unused C array index0.

# GATE 2006: Q49 (printed CS Q49)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** No universally correct printed option

## Solution

Let t be the number of items moved from S1 to S2 and d the number of successful deletes. Then x=n+t pushes and y=t+d pops, with d≤t≤n. If all m deletes succeed, d=m, so n+m≤x≤2n and 2m≤y≤n+m. These are the tight intended bounds. The supplied reproduction prints x<2n in all four options, which fails when all n inserts precede a delete: t=n and x=2n. Furthermore arbitrary ordering permits deletes on an empty queue; then d need not equal m and the printed lower bounds can fail. If < were repaired to ≤ and successful deletions assumed, A states the tight bounds, but other looser options would also be true. Do not treat this reproduction as a sound unique-answer MCQ without checking a better source. The cleaner GateForum reproduction also prints x<2n in every option. Thus the strict-upper-bound defect persists across both third-party versions. A minimal counterexample is one insert followed by one delete: n=m=1 and x=y=2. This does not establish what the official original printed.

## Solution

In a zero-based ternary heap, children of i are 3i+1,3i+2,3i+3. For D=[9,5,6,8,3,1], root 9 dominates 5,6,8 and node 5 dominates children 3,1. A fails at the root; B has parent 6 with child 8; C has parent 3 with child 5. Only D is a valid max-heap.

**Independently derived answer:** A

## Solution

Start with [9,5,6,8,3,1]. Insert 7 at index 6 and exchange with parent index 1, obtaining [9,7,6,8,3,1,5]. Insert 2 at index 7, whose parent 6 is already larger: [9,7,6,8,3,1,5,2]. Insert 10 at index 8, exchange with parent index 2 (6), then root 9, obtaining [10,7,9,8,3,1,5,2,6]. Insert 4 at index 9 under parent 9, with no exchange. Final array [10,7,9,8,3,1,5,2,6,4], A.
