**Paraphrased problem context:** Two stacks share A[1..MAXSIZE], growing from opposite ends. top1<top2 identify their topmost occupied cells. What full condition uses the available space efficiently?
Options:
(A) top1=MAXSIZE/2 AND top2=MAXSIZE/2+1
(B) top1+top2=MAXSIZE
(C) top1=MAXSIZE/2 OR top2=MAXSIZE
(D) top1=top2−1

## Solution

1. The unused positions lie strictly between top1 and top2. There is no free position exactly when the tops are adjacent, top1=top2−1, D.

2. This lets either stack use all available space instead of reserving half the array.

3. Teaching check: The number of unused cells is top2−top1−1. Setting this to zero immediately gives the full condition. A fixed half-array boundary can falsely declare overflow while the other stack leaves unused cells, defeating the purpose of sharing capacity.

## Solution

**Paraphrased problem context:** Which listed data structure is best for checking whether parentheses in an arithmetic expression are balanced?
Options:
(A) Queue
(B) Stack
(C) Tree
(D) List

## Solution

1. A stack matches each closing delimiter with the most recently unmatched opening delimiter. Reject an unmatched/mismatched close and accept only if the stack is empty at the end.

2. Thus B. With only one kind of parenthesis a counter is sufficient, but stack is the appropriate listed general delimiter-matching structure.

3. Teaching check: On an opening parenthesis, push it; on a closing one, require and pop its matching opener. The last-in-first-out rule handles nesting such as (()()). A FIFO queue does not retain the most recently opened delimiter at its removal end.

(D) Breadth-first search

## Solution

1. Breadth-first search uses a queue to visit the root, then all children, then their children, and so on. This is precisely level order, D; depth-first traversals do not generally preserve depth order.

2. Teaching check: Begin with just the root in a queue. Repeatedly dequeue a vertex and enqueue its children. Children of a depth-d vertex are enqueued behind all remaining depth-d vertices, so no depth-(d+1) vertex is processed prematurely.

**Paraphrased problem context:** For an unrestricted binary tree with distinct node labels, which pairs of label sequences determine the tree uniquely? (i) preorder and postorder; (ii) inorder and postorder; (iii) preorder and inorder; (iv) level order and postorder.
Options:
(A) i only
(B) ii and iii
(C) iii only
(D) iv only

## Solution

1. With distinct node labels, inorder plus preorder identifies the root then splits both subtrees recursively; inorder plus postorder does the same using the final element as root. Thus ii and iii, B.

2. A root with one left child versus one right child has identical preorder, postorder and level order, so the other pairs do not suffice for unrestricted binary trees. Distinct labels are the conventional assumption.

3. Teaching check: For a concrete ambiguity, a root A with sole left child B and a root A with sole right child B both have preorder A,B, postorder B,A and level order A,B. Inorder distinguishes B,A from A,B, explaining why it is indispensable among the offered pairs.

**Paraphrased problem context:** A queue is represented by a singly linked circular list: front→successive queue nodes→rear→front. One pointer p is available. Where should p point so both enqueue and dequeue take constant time?
Options:
(A) Rear node
(B) Front node
(C) Impossible with one pointer
(D) Node next to front

## Solution

1. Keep p at the rear, whose next pointer is the front. Enqueue inserts after p and advances p to the new rear; dequeue removes p.next, with a special empty result for a singleton.

2. Both take constant time, A. Keeping only the front would require finding its predecessor to update the rear link.

3. Teaching check: For enqueue, set new.next=p.next, then p.next=new and p=new. For dequeue, remove p.next and advance that link; if it was the sole node, mark the queue empty. A circular rear pointer therefore exposes both ends without a predecessor scan.

**Paraphrased problem context:** Each set is an unsorted linked list. Under direct list algorithms, which operations among union, intersection, membership and cardinality are slowest?
Options:
(A) Union only
(B) Intersection and membership
(C) Membership and cardinality
(D) Union and intersection

## Solution

1. Membership scans a list in O(n), and cardinality is O(n) by traversal (or O(1) if stored). For union/intersection of two unsorted lists of comparable size, direct algorithms test each element against the other list, taking Θ(n²) worst case while avoiding duplicates in the union.

2. Thus union and intersection, D. Auxiliary hashing or sorting can improve these operations; the comparison assumes direct operations on the stated unsorted-list representation without such an index.

3. Teaching check: For two length-n lists, compare each candidate against up to n elements of the other list. That nested search costs Θ(n²), unlike a single membership or counting scan. Union must eliminate duplicates rather than merely concatenate the lists.

**Paraphrased problem context:** Consider a binary-tree node with fields leftChild, element and rightChild, and this function (max returns the larger argument):
int DoSomething(struct CellNode *ptr) {
  int value=0;
  if(ptr!=NULL) {
    if(ptr->leftChild!=NULL)
      value=1+DoSomething(ptr->leftChild);
    if(ptr->rightChild!=NULL)
      value=max(value,1+DoSomething(ptr->rightChild));
  }
  return value;
}
What is returned when ptr is the root of a nonempty tree?
Options:
(A) Number of leaf nodes
(B) Number of nodes
(C) Number of internal nodes
(D) Height of tree

## Solution

1. A leaf returns zero. A node with a child takes one plus that child’s recursively computed value; with two children it takes the maximum.

2. Induction gives the maximum number of edges from the node to a descendant leaf, i.e. height measured in edges. The null check returns zero but no missing child adds an edge.

3. The code does not count nodes or leaves.

4. Teaching check: A singleton tree returns zero, immediately excluding both total-node and leaf counts. A two-edge chain returns two. The recursive maximum chooses the deepest child path, while adding one accounts for the edge from the current node to that child.
