

# GATE 1992: Q17 (printed A Q2(vii))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204205/GATE1992.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MSQ, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A, D: 4 and 7

**Essential problem context (paraphrased):** A 2–3 tree has nine leaves, all at equal depth, and every internal node has two or three children. Which internal counts 4, 5, 6, 7 are possible?

## Solution

At height two, the root must have three children and each must have three leaves, giving 1+3=4 internal nodes and nine leaves. At height three, nine leaves require four parents at the deepest internal level, since five would already require ten leaves. The preceding level must therefore have two nodes with two children each, and the root has those two children. Internal count is 1+2+4=7; give one deepest node three leaves and the others two to get nine. Greater height needs at least sixteen leaves. Thus counts 5 and 6 cannot fit the equal-depth constraint.

# GATE 1992: Q49 (printed B Q9(i))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204205/GATE1992.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Use inverse-position array: MEMBER(x) returns pos[x]≠0.

**Essential problem context (paraphrased):** Represent S⊆{1,…,n} so MEMBER, FIND-ONE, ADD and DELETE each take worst-case constant time independent of |S|. Give pictorial examples and routines, and state initialization assumptions. Give MEMBER(x) using the common representation.

## Solution

Use two length-n arrays: dense[1..m] stores precisely the current set in arbitrary order; pos[x] is x’s dense position if present, otherwise 0. The invariant is pos[dense[j]]=j for 1≤j≤m, and pos[x]=0 exactly for absent elements. Initialize m:=0 and pos[1..n]:=0, which takes Θ(n) time once. dense need not be initialized because only its active prefix is read. Space is Θ(n). Array indexing, integer comparison and assignment are constant-time in the word-RAM model, with words large enough for 0..n. Operations assume 1≤x≤n or reject out-of-range x before indexing.

Pictorial example, n=7 and S={2,5,7}:
dense positions: 1  2  3 | 4 5 6 7
dense values:    2  5  7 | unused
pos index:      1  2  3  4  5  6  7
pos value:      0  1  0  0  2  0  3
m=3; arrows are 2→1, 5→2, 7→3. A plain Boolean array gives easy membership but could require Θ(n) scanning to FIND-ONE; the dense prefix supplies an immediate element. Set order is deliberately not preserved, which enables constant-time deletion.

Routine:
MEMBER(x):
  if x<1 or x>n then return false;
  return pos[x]<>0.
The initialization and update invariant make a nonzero position an exact certificate of membership. In the pictured set MEMBER(5)=true because pos[5]=2, whereas MEMBER(4)=false because pos[4]=0. The routine performs only a fixed number of comparisons and one array access, so its worst-case cost is O(1), regardless of the number of stored elements. All later ADD and DELETE operations must preserve the inverse links; membership must not read uninitialized pos entries. The stipulated one-time Θ(n) initialization is not being hidden as an O(1) operation.

Hence the result is valid when nonempty and the routine never reads an inactive or uninitialized cell. It requires one test and at most one array lookup, yielding worst-case O(1). Returning a remembered arbitrary element without maintaining its validity on DELETE would not suffice; the companion deletion routine keeps the prefix compact and therefore maintains this guarantee.

**Independently derived answer:** If pos[x]=0, append x to dense and set pos[x] to the new m; otherwise do nothing.

The invariant is pos[dense[j]]=j for 1≤j≤m, and pos[x]=0 exactly for absent elements. dense positions: 1  2  3 | 4 5 6 7
dense values:    2  5  7 | unused
pos index:      1  2  3  4  5  6  7
pos value:      0  1  0  0  2  0  3

Routine:
ADD(x):
  require 1<=x<=n;
  if pos[x]=0 then begin
    m:=m+1;
    dense[m]:=x;
    pos[x]:=m
  end.
Sets do not contain duplicate elements, so the initial presence test is essential. If x is already present, returning without changes preserves the representation. If it is absent, adding a new dense entry and its inverse position establishes the invariant for x without changing any existing entry. Since an absent x exists in a universe of size n, m<n before the increment; the append cannot exceed capacity.

For example ADD(4) changes dense [2,5,7] to [2,5,7,4], changes pos[4] from 0 to 4, and changes m from 3 to 4; all other positions stay fixed. ADD(5) thereafter changes nothing. There is no search, shifting or allocation during an operation because storage was reserved at initialization. The fixed number of reads/writes gives worst-case O(1), not merely amortized O(1).

**Independently derived answer:** Replace x in dense by its last element, repair that element’s inverse position, shorten m and clear pos[x].

## Solution

Use two length-n arrays: dense[1..m] stores precisely the current set in arbitrary order; pos[x] is x’s dense position if present, otherwise 0. The invariant is pos[dense[j]]=j for 1≤j≤m, and pos[x]=0 exactly for absent elements. dense positions: 1  2  3 | 4 5 6 7
dense values:    2  5  7 | unused
pos index:      1  2  3  4  5  6  7
pos value:      0  1  0  0  2  0  3
m=3; arrows are 2→1, 5→2, 7→3. A plain Boolean array gives easy membership but could require Θ(n) scanning to FIND-ONE; the dense prefix supplies an immediate element. Set order is deliberately not preserved, which enables constant-time deletion.

Routine:
DELETE(x):
  require 1<=x<=n;
  k:=pos[x];
  if k=0 then return;
  y:=dense[m];
  dense[k]:=y;
  pos[y]:=k;
  m:=m-1;
  pos[x]:=0.
The position array directly locates x, avoiding a search. Moving the final member into x’s slot avoids shifting the remaining members. Updating pos[y] repairs the one inverse link affected by the move. The shortened prefix contains all old members except x, and clearing pos[x] makes future membership queries false.

Example DELETE(5) on dense [2,5,7] moves 7 from position 3 to position 2. The new active prefix is [2,7], m=2, pos[7]=2 and pos[5]=0. The old dense[3] value is irrelevant because it lies outside the prefix. If x already is the final element, then y=x; the self-assignment is harmless and the last assignment pos[x]:=0 is essential. The same code safely empties a singleton set. Deleting an absent element leaves everything unchanged. Only a fixed number of assignments and lookups are performed, proving worst-case O(1).
