**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** In a B+ tree, which nodes are exempt from the general requirement of at least 50% occupancy? A Only the root; B all leaves; C all internal nodes; D only the leftmost leaf.

## Solution

Approach: Separate the root's special role from the minimum-occupancy rules for ordinary nodes.
1. A B+ tree keeps nonroot nodes sufficiently full so that the number of nodes, and hence the height and search cost, stay controlled. Splitting, redistribution and merging maintain these lower bounds after updates.
2. The root needs an exception. If the entire tree fits in one leaf, that root leaf can contain only a few records. If the root is internal, it may have just two children even when the ordinary minimum for an internal node is larger.
3. Giving all leaves or all internal nodes the same exemption would abandon the normal occupancy guarantee. Being the leftmost leaf does not create an exception either.
Answer: A. Precise key-versus-child counts depend on the chosen order convention, but the special status of the root does not.

**Official answer:** D

**Derived answer:** D

**Paraphrased problem context:** The array [82,101,90,11,111,75,33,131,44,93] is “heapified”. Which first three entries result? A 82,90,101; B 82,11,93; C 131,11,93; D 131,111,90. The original does not specify min-heap versus max-heap; the official answer uses the usual bottom-up max-heap interpretation.

## Solution

Approach: Under the intended max-heap convention, every parent must be at least as large as its children. Build the heap bottom-up by sifting down internal nodes, using zero-based indices.
1. Start at index 4 (value 111), whose child is 93, so no change. At index 3, swap 11 with its larger child 131. Index 2 contains 90 above children 75 and 33 and needs no change.
2. At index 1, 101 has children 131 and 111. Swap with 131; 101 then sits at index 3 above 11 and 44.
3. At index 0, 82 must move below 131. At its new index 1, move it below 111; then at index 4 move it below 93.
4. The resulting array is [131,111,90,101,93,75,33,11,44,82]. Its first three entries are 131,111,90, matching D.
Source qualification: “Heap” alone also allows a min-heap, whose root would be 11, absent from all options. The question also does not name a particular construction algorithm. D is retained as the official intended answer, not as a uniquely forced result of the literal wording. Existing discrepancy CS-2024-S1-Q41-HEAP-TYPE remains open.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** A binary min-heap contains 105 distinct elements. If k is the array index holding the maximum element, how many values can k take over valid heaps? A 53; B 52; C 27; D 1.

## Solution

Approach: Use the heap-order property to restrict the maximum to leaves, then count leaves in the complete binary-tree shape.
1. In a min-heap every parent is smaller than its children because all keys are distinct. If the maximum were an internal node, its child would need to be still larger, a contradiction. Thus the maximum must be a leaf.
2. With one-based indexing, internal nodes are indices 1 through floor(105/2)=52. Leaves occupy indices 53 through 105, giving 105−52=53 leaves.
3. Every leaf is a feasible maximum location: place the largest key at the chosen leaf and assign the remaining keys in increasing order along a parent-before-child ordering of the remaining nodes. All parent-child inequalities can be satisfied.
Answer: A, 53. Zero-based indexing changes the leaf indices to 52 through 104 but not their number. The maximum is not fixed at the last array position; any leaf can hold it.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** A BST is built by inserting distinct integers from a known set V into an empty tree, with smaller keys in each left subtree. The insertion order and tree are unknown. What can always be determined from V? A inorder traversal; B root; C preorder; D postorder.

## Solution

Approach: Use the BST order invariant and test the other traversals on two possible insertion sequences.

1. Derivation. An inorder traversal of a BST with distinct keys and smaller keys to the left always visits exactly the sorted set V, regardless of insertion order. The first inserted key becomes the root, and different insertion orders can change the root, preorder, and postorder. Hence only inorder is determined in general, option A. Trivial sets can coincidentally determine more, but do not establish those claims for arbitrary V.

2. Explanation and checks. For V={1,2,3}, inserting 2,1,3 gives root 2, preorder 2,1,3 and postorder 1,3,2. Inserting 1,2,3 gives root 1, preorder 1,2,3 and postorder 3,2,1. Both have inorder 1,2,3. Recursively, inorder visits smaller values, then the node, then larger values; thus it is the sorted list for every valid shape. The examples demonstrate why knowledge of the set alone cannot recover the shape-sensitive alternatives.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** B;C;D

**Derived answer:** B;C;D

**Paraphrased problem context:** S1 has capacity 4 and initially contains bottom-to-top 100,200,300,400. S2 has capacity 2 and is empty. T pops S1 into S2; R pops S2 into S1; O pops S1 to output. Empty pops and full pushes are forbidden. Which output orders are possible? A 100,200,400,300; B 200,300,400,100; C 400,200,100,300; D 300,200,400,100.

## Solution

Approach: Give legal operation witnesses for possible orders and a storage lower bound for the impossible order.

1. Derivation. Write T for PushToS2, R for PushToS1, and O for GenerateOutput. Starting with S1 bottom-to-top100, 200, 300, 400 and empty S2: B is realized by T, T, O, R, O, R, O, O; C by O, T, O, O, R, O; D by T, O, O, R, O, O. These produce the stated sequences without exceeding S2 capacity 2. A cannot start with 100: reaching it before any output requires all three higher elements outside S1, but S2 holds only two. Thus B, C, D.

2. Explanation and checks. For B, the first two T operations park 400 then 300 in S2, exposing 200. Output 200, restore and output 300, restore and output 400, then output 100. For C, output 400 first and park only 300; this exposes both 200 and 100 before restoring 300. For D, park only 400 and output 300,200 before restoring it. No hidden extra buffer is available, which is why starting with 100 is impossible.
