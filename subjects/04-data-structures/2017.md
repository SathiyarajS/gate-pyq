**Paraphrased problem context:** A circular queue uses singly linked nodes, each with one next pointer, and exactly two external pointers FRONT and REAR. For O(1) insertion and deletion, which general structural conditions hold? I:front.next points to rear. II:rear.next points to front. A:I only. B:II only. C:both. D:neither.

## Solution

1. For queue order to follow next links, the circular chain must run FRONT → second → ... → REAR → FRONT. Its closing link is therefore REAR.next=FRONT, statement II.

2. To enqueue node u, set u.next=FRONT, REAR.next=u and REAR=u. To dequeue, save the old front, advance FRONT=FRONT.next and set REAR.next=FRONT. Both require only a fixed number of pointer changes, with empty and singleton cases handled separately.

3. If links instead run backward through queue order, removing the front would require finding its predecessor by traversal. Statement I is not the general rule, even though both statements happen to hold in a two-node circle. Choose B.

**Paraphrased problem context:** A binary search tree has preorder 12,8,6,2,7,9,10,16,15,19,17,20. Which is its postorder? A:2,6,7,8,9,10,12,15,16,17,19,20. B:2,7,6,10,9,8,15,17,20,19,16,12. C:7,2,6,8,9,10,20,17,19,15,16,12. D:7,6,2,10,9,8,15,16,17,20,19,12.

## Solution

1. Preorder visits root,left,right, so the first value 12 is the root. The contiguous values below 12 form its left preorder 8,6,2,7,9,10; the remaining values form right preorder 16,15,19,17,20.

2. Reconstruct the left side: root 8 has left root 6 with children 2 and 7, and right root 9 with right child 10. Its left-right-root postorder is 2,7,6,10,9,8.

3. On the right, root 16 has left child 15 and right root 19 with children 17 and 20. Its postorder is 15,17,20,19,16. Concatenate left postorder, right postorder and final root 12, obtaining B. Sorting the values would instead produce inorder, not postorder.

**Paraphrased problem context:** In a B+ tree, search keys occupy 8 bytes, blocks are 512 bytes, and block pointers occupy 2 bytes. What is the maximum order of the tree?

## Solution

1. Use the conventional definition of order m as the maximum number of child pointers in an internal node. Such a node needs m pointers and m-1 separator keys, since keys separate adjacent child ranges.

2. The capacity inequality is 2m+8(m-1)≤512. Expanding gives 10m-8≤512, hence 10m≤520 and m≤52.

3. At m=52, the node uses 104 pointer bytes plus 408 key bytes, exactly 512. Increasing to 53 would require 522 bytes, so the maximum is 52. This is an internal-node calculation that ignores unspecified metadata; a different convention defining order as the number of keys must not be substituted silently.

**Paraphrased problem context:** A binary search tree has 15 nodes. A one-node tree has height 0. Find minimum and maximum heights. A (4,15); B (3,14); C (4,14); D (3,15).

## Solution

1. Height counts edges, so levels 0 through h hold at most 1+2+...+2^h=2^(h+1)−1 nodes.

2. For 15 nodes, 2^(h+1)−1≥15 requires h≥3. A perfect four-level tree realizes height 3 and can be assigned sorted BST keys.

3. At the other extreme, a one-child chain uses one edge per additional node, giving 14 edges. No simple root-to-leaf path can exceed 14 edges with 15 nodes. Answer B.
