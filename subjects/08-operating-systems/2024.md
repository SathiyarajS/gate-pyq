**Type / marks:** MSQ, 1 mark(s).

**Official answer:** D

**Derived answer:** D

**Paraphrased problem context:** Which thread statements are true? A Threads can exist only in kernel space. B Every thread has its own open-file descriptor table. C All threads of a process share one execution stack. D Threads in one process are not protected from each other by default.

## Solution

Approach: A process supplies a shared resource environment; a thread supplies a separate flow of execution inside it.
1. Thread management can be implemented by a user-space library, by the kernel, or by a combination. Kernel space is not the only possibility, so A is false.
2. Threads of a process normally share the process's open-file descriptor table. One thread's file operations can therefore affect descriptors available to the others. B is false.
3. Each thread needs its own program counter, register state and execution stack so that its calls and local execution can progress independently. A common address space does not mean a common stack, so C is false.
4. The stacks and other memory still lie in the shared address space. Ordinary thread boundaries do not provide the protection boundaries that separate processes have; a thread can access or corrupt another thread's memory. Thus D is true.
Answer: D only.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** B;C

**Derived answer:** B;C

**Paraphrased problem context:** In the standard process-state model, which direct transitions are not possible? A Running→Ready; B Waiting→Running; C Ready→Waiting; D Running→Terminated.

## Solution

Approach: Recall the distinction between being eligible to run, actually executing, and being blocked for an event.
1. Running→Ready is possible when the scheduler preempts a process, for example when its time slice expires. The process can still execute, but no longer holds the CPU. Thus A is not selected.
2. Waiting→Running is not a direct transition in this model. Completion of the awaited event makes the process Ready; only a later scheduling/dispatch action makes it Running. Select B.
3. Ready→Waiting is also not direct. A ready process is not executing and therefore cannot issue the blocking operation that makes it wait. It must first be dispatched to Running. Select C.
4. Running→Terminated is possible when a process exits, so D is not selected.
Answer: B and C. The question is about edges of the abstract state diagram, not whether a waiting process can eventually run after passing through Ready.

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** Initially a=b=1. Thread T1 performs a=a+1 followed by b=b+1. Thread T2 performs b=2*b followed by a=2*a. Each assignment is atomic, but threads may interleave. Which set lists every possible final (a,b)? A {(4,4),(3,3),(4,3)}; B {(3,4),(4,3),(3,3)}; C {(4,4),(4,3),(3,4)}; D {(2,2),(2,3),(3,4)}.

## Solution

Approach: Preserve each thread's internal order while allowing every merge of the two two-statement sequences.
1. Label T1's statements A: increment a, B: increment b; label T2's statements C: double b, D: double a. Legal interleavings satisfy A before B and C before D.
2. There are six such orders: ABCD gives (4,4); ACBD gives (4,3); ACDB gives (4,3); CABD gives (4,3); CADB gives (4,3); CDAB gives (3,3). For example, ABCD increments each initial 1 to 2 before doubling it to 4.
3. Removing duplicates leaves {(4,4),(4,3),(3,3)}.
4. To see why (3,4) is impossible, a=3 would require D before A, while b=4 would require B before C. Together with the thread orders this demands C<D<A<B<C, an impossible cycle.
Answer: A. Atomic assignments prevent lost updates inside an assignment, but do not force a whole thread to run as one unit.

**Official answer:** 14 to 14

**Derived answer:** 14

**Paraphrased problem context:** The code is int x=3; while(x>0){fork(); printf("hello"); wait(NULL); x--;}. The printed question assumes successful system calls and asks how many times printf executes. The ordinary POSIX behavior of wait creates a qualification to that premise.

## Solution

Approach: Count statement executions in the process tree, not the number of visible copies of buffered output or the number of processes at one instant.
1. At x=3, the original process forks into a parent and child. Both continue after fork and execute printf, giving 2 executions associated with that loop value.
2. Each process has its own copied x. Both eventually reach x=2, and each forks again, giving 4 printf executions at that level. At x=1, the four process lineages each fork, giving 8 more executions.
3. Total executions are 2+4+8=14. wait may delay a parent while descendants finish, so these levels need not occur simultaneously, but waiting does not erase the later iterations of the parent's loop.
Source qualification: A newly created child initially has no child of its own. Its first wait(NULL) therefore returns −1 with ECHILD on POSIX, contradicting the blanket premise that all calls succeed. The code ignores the return value, so the intended count is still 14 when normal no-child wait failures are allowed. Buffered “hello” text can also be copied by fork; that concerns output rendering, not the number of printf executions asked here.
Answer: 14 under the intended counting model. Existing discrepancy CS-2024-S1-Q57-WAIT-PREMISE remains preserved.

**Paraphrased problem context:** Pages are 2 KB, with addresses starting at zero. Virtual pages 0,1,2,3 occupy physical frames 1,3,2,0 respectively. What decimal physical address corresponds to decimal virtual address 2500? Use 1 KB=1024 bytes.

## Solution

Approach: Split the virtual address into a page number and page offset. The page table replaces only the page number; the offset stays unchanged.
1. Page size is 2×1024=2048 bytes. Compute 2500=1×2048+452, so the virtual page is 1 and the offset within it is 452 bytes.
2. The mapping for virtual page 1 is physical frame 3. It is the second listed mapping because page numbering starts at 0.
3. Physical frame 3 begins at address 3×2048=6144. Add the same offset: 6144+452=6596.
Answer: 6596. The result lies within frame 3's address range [6144,8191], and subtracting its start recovers offset 452. Using page 2 or frame 1 would confuse zero-based numbering with the order in which the mappings are listed.

**Official answer:** B;C;D

**Derived answer:** B;C;D

**Paraphrased problem context:** Which are MMU responsibilities in a paging system? A allocate a new process’s page table; B translate virtual to physical addresses with the page table; C trap on a missing/invalid page-table mapping; D trap on a write to a read-only page.

## Solution

Approach: Separate fast hardware checks from policy and resource management performed by the operating system.

1. Derivation. The OS allocates a new process’s page-table structures, so A is not an MMU duty. The MMU uses the mappings to translate addresses, detects absent/invalid mappings and raises page-fault exceptions, and checks permissions such as write protection. Thus B, C, D. A TLB miss alone is not the same as a page being absent from the page table.

2. Explanation and checks. The MMU interprets the mapping and protection information supplied by the OS. For a valid writable mapping it can complete a write translation; for a nonpresent page or forbidden write it transfers control through an exception so the OS can decide what to do. Creating the table and allocating its memory belong to OS management. A TLB cache miss may be resolved by a page-table walk without any missing mapping or page-in operation.

**Official answer:** A;B

**Derived answer:** A;B

**Paraphrased problem context:** Running process P encounters one of these events. Which always move P to a non-running state in the intended model? A an actually blocking disk-read system call; B a page fault for a page in swap; C a disk interrupt delivering another process’s data; D a timer interrupt.

## Solution

Approach: Ask whether P must wait for something unavailable, rather than merely whether control enters the kernel.

1. Derivation. A genuinely blocking disk read puts P into a waiting state while I/O completes. A fault on a page currently in swap also requires storage I/O, so P is blocked pending page-in. An interrupt for another process need not deschedule P, and a timer interrupt may return to P if no switch is needed. Thus A, B. A mere user-to-kernel mode switch is not necessarily a switch to a different process; blocking in A is taken as actual blocking, as stipulated.

2. Explanation and checks. For A, the CPU cannot complete P’s read until the requested I/O finishes; for B, execution cannot retry the memory access until the swapped page is brought into memory. Both create a reason to block P and run another process or idle. In C, handling an interrupt can make a different process ready without forcing immediate preemption. In D, the scheduler may choose P again. Kernel entry and saving a trap frame alone are not the requested process context switch.

At time 6 C needs only 1 more, so D does not preempt it. In nonpreemptive SJF, A cannot be displaced after starting at time 0; when it finishes at 10 all others are ready and C is shortest. These decisions explain the difference in the two timelines.

**Official answer:** B;C

**Derived answer:** B;C

**Paraphrased problem context:** Threads share s1=1,s2=0,x=0. T1: wait(s1); x++; print(x); wait(s2); signal(s1). T2: wait(s1); x++; print(x); signal(s2); signal(s1). Possible outcomes? A T1 prints 1 then T2 prints 2; B T2 prints 1 then T1 prints 2; C T1 prints 1 then deadlock without T2 printing; D T2 prints 1 then deadlock without T1 printing.

## Solution

Approach: Branch on which thread acquires s1 first, since this excludes the other thread from its increment.

1. Derivation. The first successful wait(s1) excludes the other thread. If T1 acquires it first, T1 increments and prints 1, then blocks on initially zero s2 while still holding s1; T2 cannot reach its signal(s2), so this deadlocks, giving C. If T2 acquires first, it prints 1 and signals s2 and s1. T1 can then acquire s1, print2, consume s2, and finish, giving B. Thus B, C.

2. Explanation and checks. In the T1-first branch the wait-for chain is T1 waiting for s2, which only T2 signals; T2 waits for s1, which T1 will not signal until its s2 wait finishes. In the T2-first branch signal(s2) either stores a permit or satisfies a waiting thread, so T1’s later wait(s2) cannot deadlock. The mutual exclusion around x prevents a lost increment, but it does not prevent the circular wait caused by the semaphore ordering.

**Official answer:** 1028 to 1028

**Derived answer:** 1028

**Paraphrased problem context:** A 32-bit byte-addressed system uses 4 KiB pages and 4-byte PTEs. Each process receives one outer directory page. Inner table pages are allocated only when they hold a valid mapping. A process accesses 2000 distinct pages and none is swapped out. Let X and Y be minimum and maximum total page-table pages over both levels. Find X+Y; do not count data pages.

## Solution

Approach: Compute how many data-page mappings each inner table can hold and how many inner tables the directory can address.

1. Derivation. A4KB table page holds4096/4=1024 entries. The32-bit address divides into 10 outer-index bits, 10 inner-index bits and 12 offset bits, allowing1024 inner table pages. Minimum table storage for2000 mapped pages packs them into ceil(2000/1024)=2 inner pages plus the allocated outer page: X=3. Maximum spreads mappings across all1024 distinct outer entries, possible with 2000 pages, giving Y=1024+1=1025. Thus X+Y=1028. Data pages themselves are not counted.

2. Explanation and checks. To achieve the minimum, map 1024 data pages through one outer entry and the remaining 976 through a second. To achieve the maximum, use at least one data page in each of the 1024 outer regions; the remaining 976 accesses can fall in regions already used. This construction shows the upper bound is attainable, not just theoretical. An outer entry does not itself map one data page: it selects an entire inner table, so counting 2000 table pages would be incorrect.
