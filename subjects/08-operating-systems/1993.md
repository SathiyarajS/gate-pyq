

# GATE 1993: Q33 (printed II-A Q7.7)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D in the conventional resident-loader model; E for the literal universal claim

**Essential problem context (paraphrased):** Which listed system software must reside in main memory under all circumstances: editor,assembler,linker,loader,or none?

## Solution

A simple textbook system keeps a resident loader or loading service available to bring executable code into memory, motivating D. Editors,assemblers and linkers can be loaded only when needed. But “under all circumstances” is too strong: a bootstrap loader can finish and release its memory; loading can be implemented by firmware or by parts of an OS rather than a permanently resident standalone loader. Therefore no listed application is universally required to remain in RAM for every architecture. The conventional answer is retained conditionally, not elevated into an architecture-independent fact.

# GATE 1993: Q34 (printed II-A Q7.8)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B for a fixed-root layout; a discoverable pointer permits arbitrary placement

**Essential problem context (paraphrased):** Where should the root directory be placed: (A) fixed address in main memory, (B) fixed location on its disk, (C) anywhere on its disk, (D) fixed location on the system disk, or (E) anywhere on the system disk?

## Solution

The filesystem must be able to locate its root from known metadata. In a simple fixed-root layout this is achieved by placing the root at a predefined disk location, giving B; each disk or filesystem can have its own root, so it need not reside on a separate system disk. Modern designs can instead store a root block or inode pointer in a discoverable superblock, allowing the root itself to be elsewhere. Thus fixed placement is one implementation convention, not a universal requirement. A fixed RAM address does not establish persistent disk organization.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D,E: 13 and 15; exact threshold 11

**Essential problem context (paraphrased):** Three processes have maximum same-resource demands 3,4,6. Among m=7,9,10,13,15,which supplies guarantee no resource deadlock?

## Solution

If all three unfinished processes hold one less than their maxima, they can hold 2+3+5=10 units and still each request another. Thus ten units can deadlock, and smaller listed supplies can also be exhausted among unsatisfied processes. With eleven units, at least one additional unit is available whenever all processes are below their maxima, enabling some process to reach its demand, finish and release resources. Repeating resolves the rest. Therefore every supply at least eleven is safe under the standard completion model; the listed qualifying values are 13 and 15, not only the smaller of them.

**Essential problem context (paraphrased):** At time 0 jobs p,q,r,s,t arrive in that order with bursts 4,1,8,1,2. Quantum is 1. Find p’s completion time.

## Solution

The first round executes p,q,r,s,t from time 0 to 5; q and s then finish. The second round runs p from 5–6,r from 6–7,t from 7–8, completing t. The remaining queue is p,r. They run p8–9,r9–10,p10–11. This is p’s fourth unit, so it completes at 11. Context-switch overhead is assumed zero, and the arrival order determines the initial queue. A simple burst-only count would miss the intervening slices consumed by the other ready jobs.

# GATE 1993: Q60 (printed II-C Q22)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=13), physical page 13. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** DESCRIPTIVE, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** One zero-initialized semaphore per edge; each task waits on incoming edges and signals outgoing edges.

**Essential problem context (paraphrased):** Implement DAG edges S1→S2,S1→S3,S2→S4,S2→S5,S3→S5,S6→S4,S6→S5 using parbegin/parend and semaphores. Note S6 is a source, not a sink.

## Solution

Use semaphores e12,e13,e24,e25,e35,e64,e65, each initialized to zero. P(e) waits and decrements atomically; V(e) signals. Run these six branches in one parbegin/parend block:

begin S1; V(e12); V(e13) end
begin P(e12); S2; V(e24); V(e25) end
begin P(e13); S3; V(e35) end
begin P(e24); P(e64); S4 end
begin P(e25); P(e35); P(e65); S5 end
begin S6; V(e64); V(e65) end

For each edge u→v, its semaphore can be signalled only after Su finishes, and Sv cannot start until its wait succeeds. Hence every required precedence is enforced. Distinct edge semaphores prevent one successor from consuming another's notification. They also allow a signal to arrive before its matching wait without being lost.

Only S1 and S6 have no predecessors, so they can begin concurrently. S4 awaits S2 and S6, while S5 awaits S2,S3,S6. In particular, the arrows drawn upward from S6 end at S4 and S5; reversing them would implement a different graph. No extra ordering is imposed between incomparable task executions, although a blocked wait can hold a branch until all its own predecessors finish. With terminating tasks and fair scheduling this acyclic dependency system has no synchronization deadlock.
