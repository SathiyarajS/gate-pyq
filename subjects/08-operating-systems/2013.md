**Paraphrased problem context:** All processes arrive at time0, have no I/O, and start with zero priority. Priority is proportional to accumulated waiting time. Every T time units priorities are reevaluated and the next process is selected. Which policy is equivalent? A FCFS; B round-robin; C shortest-job-first; D shortest-remaining-time-first.

## Solution

With all jobs arriving together and no blocking, running a process stops its waiting time from growing while the others continue to accumulate waiting time. At each T-unit reassessment, the previously waiting processes take priority over the one just served. With a fixed fair cyclic resolution of ties this is round-robin with quantum T, B. The statement does not independently specify how equal priorities are ordered, so an exact fixed cyclic order requires that usual tie convention.

Teaching detail:
For processes that remain ready, elapsed time equals CPU service received plus accumulated waiting time. At a fixed reassessment time, maximizing waiting time is therefore the same as favoring the process that has received the least service. Starting together, the unserved processes outrank the one just given a T-unit slice. With consistent cyclic tie-breaking, each gets a slice before that process gets another, reproducing round-robin. Neither job lengths nor remaining times are consulted, excluding SJF/SRTF. FCFS would let the first job keep running rather than preempt it at each reassessment.

**Paraphrased problem context:** Binary semaphores a, b, c, d start at 1. X acquires a, b, c; Y acquires b, c, d; Z acquires c, d, a, then each releases its three locks after work. Which acquisition ordering is deadlock-free? A X:abc, Y:bcd, Z:cda; B X:bac, Y:bcd, Z:acd; C X:bac, Y:cbd, Z:acd; D X:abc, Y:cbd, Z:cda.

## Solution

Option B respects a single global order b<a<c<d in every process: X takes b, a, c; Y takes b, c, d; Z takes a, c, d. A circular wait would require strictly increasing lock ranks around a cycle, which is impossible. The other choices admit contradictory acquisition orders and circular-wait executions. Thus B.

Teaching detail:
Assign ranks b=1, a=2, c=3, d=4. In B every process acquires strictly increasing ranks, so a process holding one lock can wait only for a higher-ranked lock. A circular chain would require rank to increase all the way back to its starting value, which is impossible. For contrast, A permits X holding a while Z holds c, d and waits for a, with X eventually waiting for c. C permits X holding b and Y holding c, each waiting for the other. D permits X holding a, b and Z holding c, d, with X waiting for c and Z for a. These are concrete circular waits, not merely inconvenient orderings.

**Paraphrased problem context:** Shared x starts0. W and X each read x, add1 locally, then store; Y and Z each read x, subtract2 locally, then store. Each process waits on a counting semaphore initially2 before reading and signals after storing. Each executes once. Maximum final x: A−2, B−1, C1, D2.

## Solution

Each increment operation adds1 to a previously read value, while each decrement subtracts2. A causal chain of reads and writes contains at most the two increment operations, so no value can exceed2 starting from 0. This is attainable with semaphore capacity2: W reads0 and pauses; Y reads0 and writes−2; Z reads−2 and writes−4; W then writes1; X reads1 and writes2. The capacity restriction is respected throughout. Thus the largest final value is 2, D.

Teaching detail:
A write stores a locally computed value based on an earlier read, so updates need not add algebraically to−2. With capacity2, W can occupy one slot while reading0; the other slot is reused by Y then Z, producing−2 then−4. W’s delayed write overwrites these with 1. After W leaves, X can read1 and write2. For the upper bound, trace a written value backward through the reads it depends on. Each increment process can appear at most once in such a causal chain, so no chain adds more than 2; decrements only decrease it. This proves both attainability and optimality.

**Paraphrased problem context:** Producer X computes a[i]=f(i), then ExitX; consumer Y calls EntryY, then computes b[i]=g(a[i]), for i=0,…, n−1. Binary semaphores R, S initially0. Which implementation synchronizes them? A Exit=P(R), V(S);Entry=P(S), V(R). B Exit=V(R), V(S);Entry=P(R), P(S). C Exit=P(S), V(R);Entry=V(S), P(R). D Exit=V(R), P(S);Entry=V(S), P(R).

## Solution

In C, the consumer first signals S to indicate readiness, then waits on R; the producer waits on S before signaling R after its item has been computed. The consumer reads the item only after that R handshake. Since the next S is not issued until the preceding consumer iteration finishes, signals cannot outrun the corresponding item and collapse in a binary semaphore. A deadlocks immediately because both sides initially wait on zero semaphores. B lacks a readiness handshake, so multiple signals can collapse. In D, the producer can signal R for the next item before the consumer consumes the preceding R, again collapsing signals. Thus C provides the required synchronization.

Teaching detail:
A binary semaphore stores only whether a signal is pending, not an unbounded count. The consumer’s V(S) in C grants permission for one producer notification, then its P(R) waits for the corresponding completed a[i]. The producer cannot notify the next item without another S grant, which the consumer issues only in its next iteration. This prevents two notifications collapsing into one. In D, after the first readiness signal the producer can release R twice before the consumer takes R even once, losing a notification and potentially blocking a later consumer iteration.

**Paraphrased problem context:** A46-bit virtual/32-bit physical address machine uses3-level paging. T1 fits exactly one page; T1 entries point to page-sized T2 blocks; T2 entries point to page-sized T3 blocks of 32-bit PTEs. Under32-bit table entries throughout, page size: A2, B4, C8, D16 KB. Shared data:1MB16-way virtually indexed physically tagged cache, 64-byte block.

## Solution

Let each page contain 2^p bytes. Under the standard fixed-width organization, a 32-bit PTE or physical-address entry occupies four bytes, so each page-sized table contains 2^(p−2) entries and each of the three levels uses p−2 index bits. The page offset uses p bits. Covering the 46-bit virtual address therefore gives 3(p−2)+p=46, hence 4p=52 and p=13. The page size is 2^13 bytes=8 KiB, labeled 8 KB in the options, so C. This uses 32-bit entries at the upper levels as well as the stated 32-bit leaf PTE, page-sized table blocks, full address-space coverage, and the usual binary KB convention.

Teaching detail:
A page of 2^pbytes contains 2^p/4=2^(p−2)table entries when each occupies4 bytes. Hence each level contributes p−2 index bits and the final byte offset contributes pbits. With three levels, the address budget is(p−2)+(p−2)+(p−2)+p=46. Solving gives p=13and8192 bytes. The result is conditional on the usual fixed-width pointer entries at upper levels; the problem explicitly gives the leaf PTE size and implies that conventional organization.
