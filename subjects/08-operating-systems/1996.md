**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B: preemptive scheduling

**Essential problem context (paraphrased):** A process-state diagram includes ready→running, running→ready, running→blocked and blocked→ready. What scheduler feature does the usual diagram indicate?

## Solution

Dispatch moves a ready process into running. An I/O or resource wait moves it into blocked, and completion moves it back to ready. In the standard scheduling diagram, the extra running→ready edge represents the scheduler taking the CPU away, for example at time-slice expiry. That is preemption, giving B. A real system may also let a process voluntarily yield into ready; the unlabeled graph alone would then not prove involuntary preemption. The answer uses the conventional interpretation of this textbook state-transition diagram.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: access to shared resources

**Essential problem context (paraphrased):** What distinguishes a critical section of a program?

## Solution

A critical section is code that accesses shared state or a shared resource in a way requiring coordination with other concurrent executions. Uncontrolled overlap can violate an invariant, so a mutual-exclusion mechanism is typically needed. The definition does not require a semaphore specifically: locks, monitors, atomic operations or other protocols may enforce the required property. Nor is every short or computationally important block a critical section. The shared-resource access is the relevant characteristic, C.

**Independently derived answer:** A: line printer

**Essential problem context (paraphrased):** Which listed device is naturally served by spooling?

## Solution

A printer consumes output serially and relatively slowly. Spooling first stores each job in a disk-backed queue, allowing producing processes to continue while a spooler feeds complete jobs to the device in order. This avoids intermixing different jobs and decouples application execution from printing speed. A line printer is therefore the standard example. Spooling is not merely a CPU cache or an arbitrary buffer: its key role here is queued management of an exclusive sequential output device.

**Independently derived answer:** B: 181 Kbytes

**Essential problem context (paraphrased):** A 1000-Kbyte variable-partition memory has two allocated partitions of 200 and 260 Kbytes, with no compaction. What smallest integer-Kbyte request could be denied?

## Solution

Free space totals 1000−200−260=540 Kbytes. Two occupied contiguous partitions divide linear memory into at most three free holes. Therefore at least one hole has size at least 540/3=180 Kbytes, so every request of at most 180 Kbytes can fit somewhere. This bound is attainable by arranging hole180,allocation200,hole180,allocation260,hole180. In that layout a request of 181 Kbytes fails despite sufficient total free memory. Thus 181 is the smallest integer request that could fail; the question asks a possible worst layout, not a guarantee for every layout.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: one reverses the order

**Essential problem context (paraphrased):** Which fork-taking rule prevents dining-philosopher deadlock: all left first, all right first, or one philosopher reversing the order used by everyone else?

## Solution

If every philosopher takes the same side first, all can hold one fork and wait for the next, forming a circular wait. Reversing one philosopher’s order breaks that directed cycle: the neighboring philosophers compete for a common first fork, so they cannot all simultaneously hold distinct first forks while each awaits the next. Consequently the full circular-wait deadlock is impossible in the standard ring model. This prevents deadlock, not necessarily starvation without a fairness assumption. The uniform-left and uniform-right rules both retain the circular wait.

**Essential problem context (paraphrased):** At time 0, jobs A,B,C,D arrive in that order with CPU bursts 4,1,8,1. With quantum 1 and no overhead, when does A complete?

## Solution

The first four one-unit slices execute A,B,C,D, ending at time 4. B and D have now finished; A has three units left and C has seven. The next slices are A from 4–5, C from 5–6, A from 6–7, C from 7–8, and A from 8–9. A’s fourth unit therefore finishes at time 9. Counting four slices for A alone would ignore the CPU time given to other ready jobs. The result assumes the stated arrival order determines the initial queue and there is no context-switch cost.

**Independently derived answer:** [17,1,63,0]; [17,63,0,1]; [63,0,1,16]; [0,1,16,17].

**Essential problem context (paraphrased):** A demand-paged system has 16-bit virtual addresses, 256-byte pages, 1 KiB physical memory, and LRU order [17,1,63] from least to most recent. Process hexadecimal addresses 00FF,010D,10FF,11B0 in order. Only three initial residents are listed, so assume the fourth frame is free. Give the new list after each access.

## Solution

The offset occupies eight bits because a page has 2^8 bytes. Discard the low two hexadecimal digits to obtain decimal page references 0,1,16,17. Physical memory holds 1024/256=4 pages.

At 00FF, page 0 is absent: fault, load into the free frame, order [17,1,63,0]. At 010D, page 1 is present: hit, remove it from its old LRU position and append it, order [17,63,0,1]. At 10FF, page 16 is absent and memory is full: evict 17, append 16, order [63,0,1,16]. At 11B0, page 17 is absent because the previous reference evicted it: evict 63, append 17, order [0,1,16,17].

A page fault need not cause a replacement when a free frame exists; this distinction matters for the first reference. The initial figure shows three residents despite four-frame capacity. If an unprinted fourth resident was intended instead, its identity and recency are necessary for a unique trace. We do not invent that page or silently change memory capacity to three frames.

# GATE 1996: Q84 (printed B Q21)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Edges S1→S3, S2→S3, S3→S5, S4→S5, using GFG’s goto next.

**Essential problem context (paraphrased):** fork L creates a new process starting at label L while the original continues. join V atomically decrements V and terminates the arriving process unless the new value is zero. For N=2; M=2; fork L3; fork L4; S1; L1: join N; S3; L2: join M; S5; goto next; L3: S2; goto L1; L4: S4; goto L2; next:, draw the precedence graph for S1..S5. The goto next after S5 is present in GFG but omitted in GateForum.

## Solution

After the two forks there are three branches. The original executes S1, the L3 branch executes S2, and the L4 branch executes S4. There is no synchronization among those three statements, so they can occur in any order or overlap.

The S1 and S2 branches both reach join N. Because N starts at 2, the first arrival changes N to 1 and terminates; the second changes N to 0 and survives. Exactly one process therefore continues to S3, and S3 cannot start until both S1 and S2 have finished. This gives edges S1→S3 and S2→S3. The identity of the surviving process is irrelevant to the statement ordering.

The branch completing S3 and the branch completing S4 both reach join M. The same counting argument, with M initially 2, permits S5 exactly once, after both predecessors finish. Add edges S3→S5 and S4→S5. These four edges form the transitive reduction: draw S1 and S2 feeding S3, then S3 and S4 feeding S5. The additional transitive relations S1→S5 and S2→S5 need not be drawn.

This finite five-statement interpretation uses GFG's explicit goto next after S5. In the literal GateForum listing, the survivor instead falls through into L3 and executes S2 a second time, then decrements N from 0 to −1 and terminates. Its execution is not captured by the intended one-node-per-statement DAG. Omitting the jump is a material control-flow variant, not harmless punctuation.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Independently derived answer:** Safe sequence P1→P2→P0; Work evolves (2,2,0)→(2,5,1)→(3,5,3)→(4,5,5).

**Essential problem context (paraphrased):** Three processes P0,P1,P2 share resource types R0,R1,R2. Maximum total claims are P0=(4,1,2), P1=(1,5,1), P2=(1,2,3). Current allocations are P0=(1,0,2), P1=(0,3,1), P2=(1,0,2), and Available=(2,2,0). Show that this can be a state admitted by the Banker’s algorithm.

## Solution

The table heading “Maximum Need” gives total claims, not outstanding requests. Subtract each allocation to obtain remaining Need: P0=(3,1,0), P1=(1,2,0), P2=(0,2,1). The total resource vector is Available plus all allocations, namely (4,5,5); every maximum is individually within this total.

Run the safety test with Work=(2,2,0). P0 cannot finish yet because it needs 3 units of R0 but only 2 are free. P2 cannot finish because it needs one R2 while none is free. P1 can finish since (1,2,0) is componentwise at most (2,2,0). After it finishes, Work increases by its current allocation (0,3,1), yielding (2,5,1). Adding allocation, rather than maximum, is correct: its extra temporary requests are returned too, leaving the net increase equal to the allocation it already held.

Now P2's need (0,2,1) fits, so its completion releases (1,0,2) and Work becomes (3,5,3). Finally P0's need (3,1,0) fits; releasing (1,0,2) yields (4,5,5). Thus P1,P2,P0 is a safe sequence, proving that all claims can be satisfied in a suitable order. Safety does not assert that every possible future request is immediately grantable; it establishes at least one completion schedule from the current allocations.

**Essential problem context (paraphrased):** Three processes P0,P1,P2 share resource types R0,R1,R2. Maximum total claims are P0=(4,1,2), P1=(1,5,1), P2=(1,2,3). Current allocations are P0=(1,0,2), P1=(0,3,1), P2=(1,0,2), and Available=(2,2,0). Determine what happens when P0 requests one unit of R1.

## Solution

The request vector is R=(0,1,0). First check R<=Need0=(3,1,0), so the request does not exceed P0's remaining claim. Also R<=Available=(2,2,0), so the requested unit is physically available. These necessary checks alone do not justify granting it.

Tentatively allocate the unit. Available becomes (2,1,0), P0's allocation becomes (1,1,2), and P0's remaining need becomes (3,0,0). The other needs remain P1=(1,2,0), P2=(0,2,1). Begin the safety test with Work=(2,1,0). P0 cannot finish because 3>2 in R0; P1 cannot finish because 2>1 in R1; P2 cannot finish because it needs 2 R1 and 1 R2, while only 1 R1 and 0 R2 are free. No process can be the first in a guaranteed completion sequence.

The tentative state is therefore unsafe. The Banker rolls back the tentative change and makes P0 wait, preserving Available=(2,2,0) and the original safe allocations. This is not a claim that the request is invalid or that an actual deadlock has already occurred. It is a refusal to enter a state from which completion under all declared maximum claims cannot be guaranteed. The one free unit's availability is precisely why a full safety test, rather than a simple availability check, is needed.

# GATE 1996: Q87 (printed B Q23(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 1024 directory entries/files when empty files are permitted; nonempty-file capacity is additionally data-block limited.

**Essential problem context (paraphrased):** A one-level file system uses 4K-byte disk blocks. Disk block 0 contains a FAT with one 8-bit next-data-block address entry per data block. Disk block 1 is a directory with one 32-bit entry per file. Disk blocks 2,3,... are data blocks 1,2,... . Take K=1024. Find the maximum possible number of files.

## Solution

The directory occupies one block, so its storage is 4×1024=4096 bytes. A directory entry uses 32 bits=4 bytes. Hence it contains 4096/4=1024 entries and can name at most 1024 files. This is a directory-capacity bound; the FAT entry count must not be substituted into this division.

Attaining that many named files does not require one data block for every file if zero-length files are allowed. Empty files can occupy directory entries without owning data blocks, so the customary directory-capacity interpretation gives 1024 files. If instead the question requires every file to be nonempty, the result also depends on the number of addressable data blocks and the unspecified pointer conventions. Under a uniform 8-bit data-block address convention with all 256 patterns usable, at most 256 one-block nonempty files fit, and reserved FAT markers reduce that number.

There is a related source-design omission: a 4096-byte FAT can physically hold 4096 one-byte entries, but one-byte next pointers cannot name all 4096 positions under a uniform address scheme. Thus table capacity, pointer addressability, and directory capacity are three distinct quantities. The problem does not specify empty-file policy, reserved values, or actual disk capacity; 1024 is the unambiguous maximum directory entry count, not a proof that 1024 nonempty files can simultaneously occupy the disk.

# GATE 1996: Q88 (printed B Q23(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Conventional answer: 256 data blocks (1 MiB), conditional on uniform 8-bit identifiers without reserved codes; literal exact bound depends on unspecified encoding.

**Essential problem context (paraphrased):** A one-level file system uses 4K-byte disk blocks. Disk block 0 contains a FAT with one 8-bit next-data-block address entry per data block. Disk block 1 is a directory with one 32-bit entry per file. Disk blocks 2,3,... are data blocks 1,2,... . Take K=1024. Find the maximum possible file size in data blocks.

## Solution

A FAT-linked file is a chain: its directory entry identifies the first data block, and each block's FAT entry identifies the next. With a uniform 8-bit data-block addressing convention there are 2^8=256 possible address values. If all values are usable data-block identifiers and termination is represented separately (for example by known file length), a file can traverse at most 256 distinct data blocks. It would occupy 256×4096=1,048,576 bytes. This is the conventional intended pointer-width answer.

The 4KB FAT itself has room for 4096 one-byte entries, but room to store an entry is not the same as enough pointer bits to address its block. Therefore 4096 blocks is not justified merely by dividing FAT size by entry size. A pointer width of at least 12 bits would be required to name 4096 data blocks uniformly.

The literal question does not define end-of-file encoding or whether addresses refer to physical disk blocks or data-block ordinals. Reserving one of the 256 values for EOF leaves at most 255 usable uniform data-block addresses. If physical block numbers 0 and 1 are also excluded as metadata locations, the usable range changes again. These are specification choices, not values established by the reproduction. Accordingly 256 blocks is conditional on the standard all-patterns-usable data-block model; an exact implementation-level maximum cannot be certified without the address and termination conventions. The directory entry's 32 bits do not by themselves repair the short next pointers.
