**Independently derived answer:** C

**Essential problem context (paraphrased):** Match thread, virtual address space, file system and signal to CPU, memory, disk and interrupt respectively; option C gives 3,2,4,1.

## Solution

A thread is an execution context scheduled on a CPU. A virtual address space is the process-facing abstraction of memory. A file system organizes persistent disk storage into named files and directories. A signal is a software notification analogous to an interrupt in its asynchronous transfer of control. Thus the mapping is thread→3, virtual address space→2, file system→4, signal→1, giving C. This matches abstractions rather than asserting that signals and hardware interrupts are identical.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B under the usual seek-dominated comparison

**Essential problem context (paraphrased):** Which is likely to provide best throughput: farthest cylinder next, nearest cylinder next, FCFS, or elevator?

## Solution

Nearest-cylinder-next, or SSTF, chooses the pending request needing the least immediate head movement. Shorter seeks usually reduce service time and allow more requests per unit time, motivating B. FCFS ignores position; farthest-next deliberately increases movement. Elevator scheduling trades some local seek economy for orderly service and better fairness. The question says likely, not universally optimal: arrivals, rotational latency and starvation can change observed performance, so this is a conventional workload judgment rather than a theorem for every request sequence.

**Essential problem context (paraphrased):** Which hardware feature is essential in the standard native protected-OS model: address translation,DMA,two privilege modes,demand paging?

## Solution

User code must be prevented from directly changing privileged OS state, while kernel code must be allowed to do so. Distinct privileged and unprivileged execution modes provide this boundary, motivating C. The literal word cannot is broader than the textbook model: trusted programs or an interpreter can implement multiuser services without native privilege modes. Thus the result concerns untrusted applications executing natively with hardware-enforced protection.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Essential problem context (paraphrased):** Which is typically NOT performed when switching A to B: save/restore registers,change translation tables,swap A’s entire memory image to disk,invalidate TLB?

## Solution

A context switch preserves A’s architectural state and restores B’s registers. It also selects B’s address-translation context. In a conventional untagged TLB, old translations must be invalidated to avoid interpreting B’s addresses through A’s mappings. None of this requires writing all of A’s memory to disk: both processes can remain resident. Therefore C is the operation not normally required. Tagged TLBs may avoid full invalidation, but that architectural optimization is distinct from whole-process swapping and does not turn every switch into a disk transfer.

# GATE 1999: Q81 (printed B Q19(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 128 bytes

**Essential problem context (paraphrased):** A byte-addressed segmented-paging system has 2^16 bytes in each of its virtual and physical address spaces, divided into 8 equal virtual segments. The hardware segment table points to each segment’s page table in main memory. Each page-table entry is 2 bytes. GateForum visibly prints 2^16; GFG loses exponent formatting and appears as 216. Find the smallest power-of-two page size for which one segment’s page table occupies at most one page.

## Solution

The eight segments need 3 segment-number bits, leaving 13 bits of segment offset. Each segment therefore contains 2^16/8=2^13=8192 bytes. If page size is P=2^p bytes, the segment contains 8192/P pages and needs that many page-table entries. At 2 bytes each, its table occupies 16384/P bytes. The one-page requirement is 16384/P≤P, or P²≥16384=2^14. Thus p≥7 and the smallest allowed power of two is P=128. Verification: 8192/128=64 entries occupy 128 bytes exactly. The preceding power of two, 64 bytes, would need 128 entries or 256 bytes, exceeding one page. The hardware segment table does not add to the per-segment page-table storage being bounded.

# GATE 1999: Q82 (printed B Q19(b))

**Type / marks:** descriptive, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 3 tag bits

**Essential problem context (paraphrased):** A byte-addressed segmented-paging system has 2^16 bytes in each of its virtual and physical address spaces, divided into 8 equal virtual segments. The hardware segment table points to each segment’s page table in main memory. Each page-table entry is 2 bytes. GateForum visibly prints 2^16; GFG loses exponent formatting and appears as 216. With 512-byte pages, a direct-mapped TLB holds 16 virtual-page translations. How many tag bits per entry are needed?

## Solution

A 512-byte page has 9 offset bits. Therefore the full 16-bit virtual address has 7 virtual-page-number bits. A 16-entry direct-mapped TLB uses 4 of those bits as its index, leaving 7−4=3 tag bits. In this segmented layout the address can be drawn as [segment:3 | page within segment:4 | byte offset:9]. Indexing by the low 4 virtual-page bits chooses the page number within a segment; the stored 3-bit segment tag distinguishes the eight segments that map to that same TLB slot. Page offset bits neither select a translation nor belong in its tag. This is the tag for the single address space described; unmentioned address-space identifiers or additional implementation status are not included.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 4 aging bits

**Essential problem context (paraphrased):** A byte-addressed segmented-paging system has 2^16 bytes in each of its virtual and physical address spaces, divided into 8 equal virtual segments. The hardware segment table points to each segment’s page table in main memory. Each page-table entry is 2 bytes. GateForum visibly prints 2^16; GFG loses exponent formatting and appears as 216. With 512-byte pages, each entry has 1 valid bit, 3 protection bits and 1 dirty bit. How many bits remain for aging information?

## Solution

There are 2^16/2^9=2^7 physical page frames, so a page-table entry needs 7 bits for the physical frame number. The offset is supplied by the original virtual address and is not stored in the entry. Each entry is 2 bytes=16 bits. The stated non-address metadata occupies 1+3+1=5 bits. Thus the aging budget is 16−7−5=4 bits. A valid field allocation is [frame number:7 | valid:1 | protection:3 | dirty:1 | aging:4], totaling 16. Subtracting a full 16-bit physical byte address would be wrong because a page frame is aligned and its low 9 offset bits need not be recorded. This answer assumes no additional unspecified fields consume the remaining capacity.

# GATE 1999: Q84 (printed B Q20(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Spin until TSET returns 0; release by setting flag to 0.

**Essential problem context (paraphrased):** TSET register,flag atomically copies flag into register and sets flag=1. Give entry and exit pseudocode for a critical region.

## Solution

Initialize a shared flag to 0 before any competing process starts. Each process uses its own register r.

shared flag := 0

entry:
  repeat
    TSET r, flag
  until r = 0

  critical_region()

exit:
  flag := 0

TSET must run on every retry; reading a stale r in a spin loop would never acquire the lock. When flag=0, exactly one atomic TSET can observe that 0 and simultaneously change flag to 1. That process enters; all later tests obtain 1 and continue waiting. Only the owner clears the flag on exit. This establishes mutual exclusion, assuming atomic release stores and the abstract sequentially consistent memory model of the question. Real machines additionally require appropriate acquire/release memory ordering. The scheme busy-waits and does not by itself guarantee bounded waiting or freedom from starvation.

# GATE 1999: Q85 (printed B Q20(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 3 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A wakeup between the consumer’s test and sleep is lost; producer later sleeps on the full buffer.

**Essential problem context (paraphrased):** A one-slot producer-consumer buffer uses count=0 initially. Tests and assignments of count are individually atomic. Producer repeats: produce item; if count=1 then sleep; put item in buffer; count:=1; wakeup(Consumer). Consumer repeats: if count=0 then sleep; remove item; count:=0; wakeup(Producer); consume item. Show an execution where both processes sleep.

## Solution

Assume ordinary sleep/wakeup semantics: waking a process not currently asleep does not save a future wakeup token. The following interleaving is legal even though each test and assignment is atomic.
1. Consumer tests count=0 and gets true, but is preempted just before executing sleep.
2. Producer produces an item, tests count=1 (false), places the item, then atomically sets count=1.
3. Producer calls wakeup(Consumer). Consumer is not sleeping yet, so the notification is lost.
4. Consumer resumes at the pending sleep instruction and goes to sleep, without rechecking count. The buffer is full and count remains 1.
5. Producer begins its next iteration and produces another item. Its count=1 test is true, so it sleeps waiting for space.
Now both processes are asleep. Only the sleeping consumer could remove the buffered item and wake the producer; only the sleeping producer could issue another consumer wakeup. Individual atomicity of test and assignment does not make the combined test-and-sleep sequence atomic. A semaphore that retains notifications, or correctly synchronized condition-variable wait with a predicate loop, prevents this lost-wakeup window.
