

# GATE 2021 CS1: Q21 (printed CS Q11)

**Question:** [Official archived paper page 17](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=17); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** A; C

**Derived answer:** A; C

**Paraphrased problem context:** Select all correct paging statements. A paging addresses external fragmentation; B page size has no impact on internal fragmentation; C paging incurs memory overhead; D multilevel paging is necessary to support different page sizes.

## Solution

Fixed-size page frames avoid external fragmentation, while partially filled pages still incur internal fragmentation whose amount depends on page size. Page tables and related translation metadata require memory overhead. Multiple page sizes can be supported without requiring multilevel page tables, so that mechanism is not logically necessary. Thus A, C.

External fragmentation means sufficient free space exists but is scattered into unusable variable-size gaps. Equal-sized frames avoid that requirement for contiguous allocation. Internal fragmentation occurs inside the final allocated page, potentially wasting almost one page per allocation. Translation requires page-table entries and sometimes additional levels or supporting structures. The number of page-table levels and the set of supported page sizes are separate design choices.

# GATE 2021 CS1: Q24 (printed CS Q14)

**Question:** [Official archived paper page 18](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=18); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** A; C

**Derived answer:** A; C

**Paraphrased problem context:** Which standard C library functions always invoke a system call when executed by a single-threaded UNIX/Linux process? Select all: A exit; B malloc; C sleep; D strlen.

## Solution

Normal process termination through exit eventually asks the kernel to terminate the process. A blocking sleep asks the kernel to suspend execution and arrange resumption. malloc can satisfy a request from existing user-space heap storage, and strlen scans user-space memory, so neither always needs a system call. Thus A, C in the ordinary UNIX/Linux library execution model. This is a systems-interface question, not a claim about abnormal nonreturning exit handlers or arbitrary replacement libraries.

Library routines are not synonymous with system calls. strlen needs only reads of its argument up to the terminating zero byte. malloc commonly obtains a larger region once, then fulfills many allocations from its own free lists without entering the kernel. In contrast, normal process exit changes kernel process state, and a blocking sleep requires kernel scheduling/timer support. The exam's 'always' language is interpreted under these normal library semantics.

# GATE 2021 CS1: Q25 (printed CS Q15)

**Question:** [Official archived paper page 19](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=19); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** A; C

**Derived answer:** A; C under fresh-name uniqueness checking

**Paraphrased problem context:** A directory foo is implemented as an unsorted linear list of nodes containing file names and metadata including data-block pointers. Which successful operations necessarily require a full scan? A create a new file; B delete an existing file; C rename an existing file; D open an existing file.

## Solution

Creating a new file requires checking that its proposed name is absent from the entire unsorted directory list. Renaming to a new unused name similarly needs an absence check. Deletion or opening can stop when the existing entry is found, so they do not necessarily scan the entire list. Thus A, C under the intended simple-directory model. A real rename operation that is permitted to replace an existing target, or an indexed name cache, changes the necessity claim; those are outside this linear-list/fresh-name interpretation.

A successful lookup can stop at the matched name, perhaps the first node, so opening/deleting do not necessarily scan all nodes. To establish that a proposed new name is absent, finding no match in only a prefix is insufficient: it could occur in the unvisited suffix. Creation and a rename to a fresh name must therefore inspect the whole directory. The distinction is existential lookup versus proof of absence, not simply whether the operation changes disk contents.

# GATE 2021 CS1: Q35 (printed CS Q25)

**Question:** [Official archived paper page 22](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=22); consult original wording, diagrams and choices.

**Type / marks:** NAT, 1 mark(s).

**Official answer:** 12 to 12

**Derived answer:** 12

**Paraphrased problem context:** Three processes arrive at time zero with CPU bursts 16,20,10 milliseconds. With prior burst knowledge and non-preemptive scheduling, what is the minimum average waiting time, rounded to the nearest integer in milliseconds?

## Solution

Shortest-job-first minimizes total waiting time when all jobs arrive together and burst lengths are known. Execute bursts10, 16, 20. Their waiting times are0, 10, 26, whose average is 36/3=12 milliseconds.

For three jobs of lengths a,b,c in that order, total waiting is 0+a+(a+b)=2a+b. Placing shorter jobs earlier minimizes this weighted sum. More generally, swapping adjacent lengths x>y reduces the waiting total by x−y while leaving later completion times unchanged. This exchange argument proves shortest-job-first is optimal here. Completion/turnaround times would be 10,26,46 and are not the requested waiting times.

# GATE 2021 CS1: Q56 (printed CS Q46)

**Question:** [Official archived paper page 37](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=37); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A; B; D

**Derived answer:** A; B; D

**Paraphrased problem context:** Shared counter=0 and counting semaphore S=5. Five threads concurrently execute parop(){wait(S); wait(S); counter++; signal(S); signal(S);} The increment is explicitly non-atomic. Select possible outcomes: A counter=5 after all complete; B counter=1 after all complete; C counter=0 after all complete; D all five threads deadlock.

## Solution

Serially completing all five operations gives counter=5, proving A. For B, let one thread acquire two permits and read counter=0, then pause before writing. The other four can each acquire two of the remaining three permits, increment and finish sequentially. Finally the paused thread writes its stale result 1 and finishes. C cannot occur after successful completion: every write is a nonnegative value read plus one, so the final write is at least 1. For D, let each of the five threads acquire its first permit before any acquires a second. All then block on the second wait with no permit left and none able to signal. These are pseudocode read-modify-write interleavings, as explicitly assumed.

The semaphore limits simultaneous holders of permits but does not provide mutual exclusion for counter++: two threads can each hold two permits out of five. For final value 1, the crucial schedule is a delayed stale write from the first thread after the other four have successively completed. For deadlock, no thread reaches its first signal because every thread is stuck on its second wait. Replacing the two waits by one atomic acquisition of two permits would remove that particular hold-and-wait pattern, but that is not the given code.

# GATE 2021 CS2: Q24 (printed CS Q14)

**Question:** [Official archived paper page 62](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=62); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 1 mark(s).

**Official answer:** A; C; D

**Derived answer:** A; C; D

**Paraphrased problem context:** Select correct CPU scheduling statements: A turnaround includes waiting; B goal is only maximize CPU use and minimize throughput; C round robin works without advance CPU burst lengths; D preemption requires hardware support.

## Solution

Turnaround measures arrival-to-completion and includes waiting, so A. Throughput should ordinarily be increased, not minimized, refuting B. Round-robin only needs a time quantum, not advance knowledge of each burst, giving C. Preemption of an otherwise running process requires hardware interruption support, typically a timer interrupt, giving D in the standard OS model.

For an ordinary CPU-only job, turnaround=completion−arrival=waiting+CPU service; I/O time is also included if relevant. Round robin dispatches a ready job for at most a quantum, regardless of its remaining burst. A timer interrupt lets the OS regain control even if the process does not voluntarily yield.

# GATE 2021 CS2: Q52 (printed CS Q42)

**Question:** [Official archived paper page 79](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=79); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A; D

**Derived answer:** A; D

**Paraphrased problem context:** Two separate processes each execute: global x=0 and global lock L1; main creates two threads running foo, joins both, prints x. foo has local y=0; acquire L1; x=x+1;y=y+1;release L1;print y. A both processes print x=2; B at least one prints x=4; C some thread prints y=2; D all four threads print y=1.

## Solution

Each process has its own address space, hence its own global x and lock. Within one process the lock serializes the two increments, giving x=2 after both threads finish. Each invocation has its own stack-local y, initialized to zero and incremented once, so every thread prints 1. The two processes do not share x merely because it is global. Thus A, D.

Threads share a process's global variables and synchronization objects, but ordinary separate processes do not share those objects without explicit shared-memory setup. Joining both threads ensures main prints after both increments. Each thread's y is an automatic local variable, so the lock is not needed to protect y, though it is needed for the shared x increment within each process.

# GATE 2021 CS2: Q53 (printed CS Q43)

**Question:** [Official archived paper page 80](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=80); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A; B; C

**Derived answer:** A; B; C

**Paraphrased problem context:** One instance per resource type, exclusive ownership. OWNRESOURCE(R) acquires global lock L; if free, acquire R and release L; else if owned by another P, terminate P after freeing its resources, acquire R, restart P, release L. Select: A prevents deadlocks; B may livelock; C may starve; D violates mutual exclusion.

## Solution

Under the intended atomic termination/resource-release model, a requester never waits for another process to release its resource: it terminates that owner and takes the resource while holding L. Thus no circular resource wait develops, giving A. Two restarted processes can repeatedly take resources from and restart each other without completing, giving livelock B. An unfair execution can repeatedly kill the same process before it finishes, giving starvation C. The global lock and removal of the previous owner preserve exclusive ownership, so D is false. This assumes requests concern resources not already owned by the requester and that termination/restart do not themselves block on L; those implementation details are abstracted by the pseudocode.

For a livelock witness, let P hold A and Q hold B. P requests B, kills and restarts Q; later restarted Q requests a resource now held by P and kills/restarts P. Repeating such interference can prevent either from completing despite activity. A lock provides mutual exclusion, not fairness or progress. The answer depends on treating termination and resource release as atomic successful operations in the model.

# GATE 2021 CS2: Q58 (printed CS Q48)

**Question:** [Official archived paper page 85](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=85); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 4108 to 4108

**Derived answer:** 4108

**Paraphrased problem context:** 39-bit virtual address splits as 9-bit level1,9-bit level2,9-bit level3,12-bit offset. Pages are 4KB and all PTEs 8 bytes. Process maps 2GB virtual to 2GB physical. Find minimum total page-table memory in KB, with binary KB/GB.

## Solution

Each page-table page holds4096/8=512 entries. The2GB mapping needs 2^31/2^12=2^19 leaf entries, hence1024 level3 pages. Packing these contiguously minimizes higher levels: 1024/512=2 level2 pages and one level1 root page. Total=(1024+2+1)*4KB=4108KB. This is the minimum with allocated whole page-table pages and a densely placed virtual mapping.

Each level-2 page indexes up to 512 level-3 pages, which collectively map 512×512×4KB=1GB. Thus the 2GB region can occupy two such subtrees under one root. Sparse placement could require more page-table pages; the word minimum permits contiguous, suitably aligned placement. Physical page contents consume 2GB but are not part of page-table overhead.
