**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

## Solution

FIFO can incur more faults with more frames: the standard reference string1,2,3,4,1,2,5,1,2,3,4,5 has9 faults with3 frames and10 with4. LRU and optimal replacement have the stack-inclusion property; ordinary MRU also preserves inclusion for nested initially empty caches. Thus FIFO is the supplied policy exhibiting the anomaly, A.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A under blocked-process local time

## Solution

Initially P1 holds both R2 units, P2 two R3 units, and P3 one R4. P1 obtains its R3 at1; P2 obtains its R4 and P3 two R1 at2. P1 then waits for two R1 at3 because only one is free. P2 can take that last R1 at4. At5 P3 releases its two R1, allowing P1 to resume. Its local-time5 releases now occur at wall time7, providing the R2 requested by P3. P2 releases R3 at6 and finishes at8, so P3 can obtain R3 at8 and finish at9. P1’s later two-R4 request can be satisfied after those completions, and it finishes. No circular wait persists; A. The timeline treats each listed time as progress time in an independently running process, with blocked execution delayed.

## Solution

Atomic test-and-set allows exactly one contender to observe0 and enter, preserving mutual exclusion. When the current holder eventually leaves and resets X, some contender can acquire it, so the lock is deadlock-free under ordinary progress assumptions. There is no FIFO order or bounded-wait guarantee: the same process can repeatedly win and starve another. Only I holds, A. X denotes shared lock storage in this pseudocode, not an ordinary pass-by-value C local.
