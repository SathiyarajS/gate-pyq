**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** For which listed page replacement policy may Belady’s anomaly occur? A FIFO; B optimal; C LRU; D MRU.

## Solution

FIFO can incur more faults with more frames: the standard reference string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 has 9 faults with 3 frames and 10 with 4. LRU and optimal replacement have the stack-inclusion property; ordinary MRU also preserves inclusion for nested initially empty caches. Thus FIFO is the supplied policy exhibiting the anomaly, A.

Teaching detail:
FIFO can evict a page because it arrived long ago even if it will be reused immediately; adding frames changes that queue order and can increase faults. The classic reference string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 produces 9 FIFO faults with three frames and 10 with four. LRU and optimal have the inclusion/stack property that prevents this anomaly. The intended listed answer is FIFO; the baseline qualification concerning the exact MRU model remains important.

**Independently derived answer:** B

**Paraphrased problem context:** What is essential in each conventional page-table entry? A virtual page number; B physical page-frame number; C both numbers; D access-right information.

## Solution

A conventional page table is indexed by the virtual page number, so that number need not be stored again in each entry. Its essential mapping result is the physical page-frame number, B. Permission and status bits may also be included; inverted/hashed organizations have different entry layouts and are not the conventional indexed table assumed here.

Teaching detail:
A conventional page table is indexed by virtual page number, so that number is implicit in the entry’s position rather than necessarily stored again. The essential translation payload identifies the physical frame. Protection, valid and dirty information may also be stored, but access rights alone cannot perform address translation. Thus B is the expected minimum translation information; hashed or inverted page-table organizations can require additional explicit tags.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 7. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A under blocked-process local time

**Paraphrased problem context:** Resources R1, R2, R3, R4 have totals 3, 2, 3, 2. Requests are nonpreemptive and all-or-nothing. Independent progress timelines: P1 t0 requests 2R2, t1 requests 1R3, t3 requests 2R1, t5 releases 1R2+1R1, t7 releases 1R3, t8 requests 2R4, t10 finishes. P2 t0 requests 2R3, t2 requests 1R4, t4 requests 1R1, t6 releases 1R3, t8 finishes. P3 t0 requests 1R4, t2 requests 2R1, t5 releases 2R1, t7 requests 1R2, t8 requests 1R3, t9 finishes. Starting together, choose A all finish; B only P1/P2 deadlock; C only P1/P3 deadlock; D all deadlock.

## Solution

Initially P1 holds both R2 units, P2 two R3 units, and P3 one R4. P1 obtains its R3 at 1; P2 obtains its R4 and P3 two R1 at 2. P1 then waits for two R1 at 3 because only one is free. P2 can take that last R1 at 4. At 5 P3 releases its two R1, allowing P1 to resume. Its local-time 5 releases now occur at wall time 7, providing the R2 requested by P3. P2 releases R3 at 6 and finishes at 8, so P3 can obtain R3 at 8 and finish at 9. P1’s later two-R4 request can be satisfied after those completions, and it finishes. No circular wait persists; A. The timeline treats each listed time as progress time in an independently running process, with blocked execution delayed.

Teaching detail:
A temporary wait is not sufficient evidence of deadlock: check whether another process can still progress and release the needed resource. At time 3, P1 lacks its two R1 units, but P3 will release two at time 5 without needing anything from P1 first. That release allows P1 to resume. P1’s later release of R2 lets P3 progress; P2 independently releases R3 and finishes. The dependency chain therefore has an escape. Using progress times delayed during blocking gives the timeline above and all processes eventually finish, A. Treating delayed operations as occurring retroactively at their original wall times would be inconsistent.

**Paraphrased problem context:** A disk has 100 cylinders, head initially 50, all requests pending in listed order 4, 34, 10, 7, 19, 73, 2, 15, 6, 20. SSTF costs 1 ms per cylinder moved. Total seek time? A 95; B 119; C 233; D 276 ms.

## Solution

With all listed requests pending, SSTF visits 50→34→20→19→15→10→7→6→4→2→73. The decreasing leg costs 48 cylinders and the final increasing leg 71, totaling 119. At 1 ms per adjacent cylinder the seek time is 119 ms, B, excluding unspecified transfer/rotation costs.

Teaching detail:
At 50, the nearest pending request is 34 (distance 16), not 73 (distance 23). From 34 choose 20, then 19, 15, 10, 7, 6, 4, 2, always the nearest remaining cylinder. This monotone descent costs 50−2=48 in total. Only 73 then remains, costing 73−2=71. Total movement 119 times 1 ms gives 119 ms. Initial request order is irrelevant after all are pending under SSTF; FCFS would follow that order and produce a different answer.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C under conventional preemption labeling

**Paraphrased problem context:** Process transitions: A Start→Ready; B Ready→Running; C Running→Ready; D Running→Terminated; E Blocked→Ready; F Running→Blocked. A uniprocessor always has some ready processes. Assess I D immediately causes another A; II E may occur while another process runs; III preemptive scheduling; IV nonpreemptive scheduling. A I/II; B I/III; C II/III; D II/IV.

## Solution

D terminates a running process; another ready process is dispatched through B, not newly admitted through A, so I is false. A blocked process can become ready by E while another runs, so II is true. The running-to-ready edge C represents preemption in the conventional diagram, making III true and IV false. Thus II and III, C. If C were instead explicitly defined as voluntary yield, the drawing alone would not establish preemption; the usual state-diagram convention is used.

Teaching detail:
Termination frees the CPU, so the scheduler dispatches an already ready process along B. It need not create or admit a process along A, making I false. An I/O completion can move a different process from blocked to ready while the CPU is busy, making II true. Under the conventional interpretation, C is preemption and distinguishes the diagram from a purely nonpreemptive scheduler. Thus III is selected with II; if C instead explicitly meant voluntary yield, that additional meaning would need a separate analysis.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Shared lock X starts 0. enter_CS spins while atomic test-and-set(X) returns true; leave_CS writes X=0. Assess I deadlock-free; II starvation-free; III FIFO entry; IV multiple simultaneous entrants. A I only; B I/II; C II/III; D IV only.

## Solution

Atomic test-and-set allows exactly one contender to observe 0 and enter, preserving mutual exclusion. When the current holder eventually leaves and resets X, some contender can acquire it, so the lock is deadlock-free under ordinary progress assumptions. There is no FIFO order or bounded-wait guarantee: the same process can repeatedly win and starve another. Only I holds, A. X denotes shared lock storage in this pseudocode, not an ordinary pass-by-value C local.

Teaching detail:
The atomic operation returns the old flag and sets it to 1 as one indivisible action. Only one contender can see old 0, so IV is false. Once the holder releases, some waiting process can succeed, assuming the holder and scheduler make ordinary progress; this supplies deadlock freedom. But no queue orders contenders. A newly arriving or repeatedly scheduled process can keep winning before another waiter, defeating both FIFO and starvation freedom. Therefore only I is justified.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Why prefer multilevel over single-level page tables? A shorter memory access time; B reduced page-table storage for a process virtual address space; C required by a TLB; D fewer replacement page faults.

## Solution

A sparse virtual address space need not allocate lower-level page tables for unused regions. This can reduce the resident page-table storage compared with a full flat table, B. Extra levels do not inherently shorten a page walk, eliminate page faults or become mandatory merely because a TLB exists.

Teaching detail:
A flat table allocates an entry for every possible virtual page even when most virtual regions are unused. A multilevel table can omit entire lower-level tables for absent regions, saving storage. This is the purpose captured by B. The price may be additional memory references on a TLB miss, not a guaranteed speedup. Neither a TLB nor the page-replacement policy logically requires a multilevel representation.

## Solution

Each cylinder contains 20×63=1260 sectors. Divide 1039 by 1260: cylinder c=0 with remainder 1039. Then 1039=16×63+31, giving surface h=16 and sector s=31. Thus the address is (0, 16, 31), option C. This uses the zero-based indexing explicitly defined in the common data on physical page 11.

Teaching detail:
Invert the mixed-radix calculation. One cylinder spans 1260 sectors, so 1039 lies in cylinder 0. Divide the remainder by 63: quotient 16 is the surface and remainder 31 is the sector. Check by recomposition:((0·20)+16)·63+31=1039. This is C; options differing by one reveal the common mistake of silently switching to one-based counting.
