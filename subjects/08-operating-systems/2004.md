

# GATE 2004: Q11 (printed CS Q11)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Regarding user-level and kernel-supported threads, select the true statements: (1) Context switching is faster with kernel-supported threads. (2) A system call by a user-level thread can block the whole process. (3) Kernel-supported threads can be scheduled independently. (4) User-level threads are transparent to the kernel.
Options:
(A) 2,3,4 only
(B) 2,3 only
(C) 1,3 only
(D) 1,2 only

## Solution

1. In the conventional many-to-one user-thread model, a blocking system call can block the process, the kernel does not see individual user threads, and kernel-supported threads can be scheduled independently. Thus2,3,4 are true, A.

2. User-thread context switches normally avoid kernel transitions and are not slower by definition; statement 1 is false. Modern hybrid threading arrangements need not share the many-to-one blocking limitation.

3. Teaching check: Separate visibility from speed: the kernel schedules only what it knows about. A library can switch its user threads without a kernel transition, but a blocking call can stop their common kernel scheduling entity. Kernel-supported threads trade that limitation for kernel-managed scheduling.

# GATE 2004: Q12 (printed CS Q12)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D under synchronous single-request I/O

**Paraphrased problem context:** An OS can load and execute one sequential user process at a time. FCFS disk scheduling is replaced by SSTF, advertised as giving 50% better benchmark performance. What improvement in user-program I/O performance is expected? The usual one-outstanding-request assumption is not explicitly stated.
Options:
(A) 50%
(B) 40%
(C) 25%
(D) 0%

## Solution

1. If the single sequential process blocks for each disk request, there is never a choice among queued requests. FCFS and SSTF therefore execute the same sequence, giving 0% improvement, D; a benchmark with concurrency does not transfer to this case.

2. The premise of one sequential process alone does not prohibit asynchronous I/O, readahead or background requests. Without the one-outstanding-request assumption, the improvement is not determined by the stated facts.

3. Teaching check: A seek scheduler can improve ordering only when it can choose between multiple pending requests. With exactly one pending request, both rules choose it. “50% better” on another workload is not evidence for this workload; asynchronous requests would require further information.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A under a fixed paging configuration

**Paraphrased problem context:** What determines the minimum number of page frames that must be allocated to a running process in a virtual-memory environment?
Options:
(A) Instruction set architecture
(B) Page size
(C) Physical memory size
(D) Number of processes in memory

## Solution

1. The instruction set determines which instruction bytes and operands may have to be resident together to complete/restart one instruction without endless page faults. Thus A is the standard determinant of the minimum required frame count, rather than a count based simply on concurrent processes or total RAM.

2. Exact numerical requirements also depend on the fixed page size, operand placement, and restart implementation; the answer identifies the architectural constraint, not independence from all those details.

3. Teaching check: The minimum is about making forward progress on an instruction, not fitting the whole working set. For example, an instruction may simultaneously need its code page and multiple operand pages. The ISA constrains these requirements; page geometry and restart details matter when calculating an actual number.

**Independently derived answer:** A

**Paraphrased problem context:** Processes (arrival time,CPU burst), in ms, are P1=(0,5), P2=(1,3), P3=(2,3), P4=(4,1). What is the average turnaround time under preemptive shortest remaining processing time first (SRPT)?
Options:
(A) 5.50 ms
(B) 5.75 ms
(C) 6.00 ms
(D) 6.25 ms

## Solution

1. A valid SRPT schedule is P1:[0,1), P2:[1,4), P4:[4,5), P3:[5,8), P1:[8,12). P2 still has the smallest remaining time when P3 arrives.

2. Completion times for P1,P2,P3,P4 are 12,4,8,5; subtracting arrivals 0,1,2,4 gives turnaround times 12,3,6,1. Their mean is 22/4=5.50ms.

3. Teaching check: Turnaround is completion minus arrival, not total waiting time. The four turnaround values are 12,3,6,1; their sum is 22. Context-switch overhead is not supplied and is therefore excluded. Arrival of P3 at time 2 does not preempt P2, whose remaining burst is only 2.

# GATE 2004: Q47 (printed CS Q47)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 1260 ns under literal two-level page-table model; no listed option

**Paraphrased problem context:** A two-level paging system has regular memory access time 150 ns and page-fault service time 8 ms. An average instruction uses 100 ns CPU time and two memory accesses. TLB hit ratio is 90%; page faults occur once per 10,000 instructions. What is effective average instruction time? TLB lookup time and caching of page-table levels are unspecified.
Options:
(A) 645 ns
(B) 1050 ns
(C) 1215 ns
(D) 1230 ns

## Solution

1. Assuming negligible TLB lookup time and a true two-level page table, a TLB hit costs 150ns and a miss costs three memory accesses: two page-table reads plus the requested data access,450ns. Two accesses per instruction therefore cost 2(0.9×150+0.1×450)=360ns.

2. Add100ns CPU time and 8,000,000/10,000=800ns amortized fault service:1260ns. None of 645,1050,1215,1230 matches.

3. Option D=1230ns results from counting only TWO total memory accesses per TLB miss:100+2(0.9×150+0.1×300)+800. That requires a single-level translation model or an unstated cached first-level entry.

4. Treat the result as model-dependent rather than silently forcing D. Minor whether-fault-service-includes-retry conventions do not account for the 30ns discrepancy.

5. Teaching check: A true two-level TLB miss reads level 1, level 2 and data: three memory accesses. The page-fault rate is per instruction, so add the 800-ns average penalty once, not twice. The closest-looking listed value must not erase the extra translation read.

# GATE 2004: Q48 (printed CS Q48)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Shared X,Y are protected by binary semaphores Sx,Sy, initially 1. P waits/decrements and V signals/increments. Fill L1,L2,L3,L4 to avoid deadlock:
P1: while true {
  L1; L2; X=X+1; Y=Y-1; V(Sx); V(Sy);
}
P2: while true {
  L3; L4; Y=Y+1; X=X-1; V(Sy); V(Sx);
}
GateForum prints X=Y−1 in P2; that arithmetic variant does not change the locking question.
Options:
(A) P(Sy),P(Sx),P(Sx),P(Sy)
(B) P(Sx),P(Sy),P(Sy),P(Sx)
(C) P(Sx),P(Sx),P(Sy),P(Sy)
(D) P(Sx),P(Sy),P(Sx),P(Sy)

## Solution

1. Both processes must acquire both Sx and Sy, exactly once, in the same global order. Option D supplies P(Sx),P(Sy) to both processes.

2. A process that has acquired Sx prevents its competitor from holding Sy while it waits for Sx, so the circular-wait condition is impossible. Options A/B use opposite acquisition orders and admit deadlock; C acquires the same binary semaphore twice and can block itself.

3. Different release orders do not invalidate the common acquisition order.

4. Teaching check: Construct an opposite-order deadlock: P1 holds Sx and waits for Sy while P2 holds Sy and waits for Sx. Requiring the same acquisition order eliminates this cycle. A release-order difference is harmless here because neither process waits while executing V.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 17,247,250,432 bytes; C only as a power-of-two approximation

**Paraphrased problem context:** A Unix-style inode has 10 direct pointers and one each single-, double- and triple-indirect pointer. Blocks are 1 Kbyte, block addresses are 32 bits, and integers are 48 bits. What is the maximum file size? Use 1 Kbyte=1024 bytes; alternatives are powers of two, not exact inode totals.
Options:
(A) 2^24 bytes
(B) 2^32 bytes
(C) 2^34 bytes
(D) 2^48 bytes

## Solution

1. A1KiB indirect block holds 1024/4=256 addresses. The inode can reference 10+256+256²+256³=16,843,018 data blocks, totaling 17,247,250,432 bytes.

2. The32-bit block-address space and 48-bit integer bound are both larger and do not constrain this total. The dominant triple-indirect contribution alone is 256³×1024=2^34 bytes, option C, but the exact maximum includes direct, single-indirect and double-indirect blocks and exceeds 2^34 by 67,381,248 bytes.

3. Thus no offered power-of-two option is exactly the stated maximum; C is the usual scale approximation, not an exact equality.

4. Teaching check: Indirect blocks contain addresses, so divide 1024 bytes by four bytes per address before exponentiating. The triple-indirect branch contributes 256³ data blocks; it does not replace the smaller branches. Distinguish exact capacity from the dominant-power approximation offered by the choices.
