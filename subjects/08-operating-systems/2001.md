**Independently derived answer:** D

**Essential problem context (paraphrased):** Which virtual-memory claim is false? It translates program addresses to physical addresses; allows a program larger than primary memory; increases possible multiprogramming; or reduces context-switch overhead.

## Solution

Step 1: Virtual memory translates virtual addresses, permits only part of a program to be resident, and can accommodate more simultaneously active processes than whole-program residency allows. These explain the usual claims A–C.

Step 2: A context switch still saves/restores CPU state and may change page-table context or invalidate/repopulate translation caches. Virtual memory does not inherently remove that work and can add translation-related overhead.

Thus D is the false general claim. The benefit in multiprogramming is a capability, not a guarantee against thrashing under every workload.

**Essential problem context (paraphrased):** What is the principal system purpose of a software interrupt: testing interrupts, implementing coroutines, requesting system services needing privileged instructions, or returning from a subroutine?

## Solution

Step 1: User-mode code cannot directly execute protected operations such as arbitrary device control. It must transfer control through an authorized entry point into the operating system.

Step 2: A software interrupt/trap provides that controlled transfer and lets the kernel execute the privileged instructions, so C. Testing interrupts is possible but is not their essential system-service purpose.

**Independently derived answer:** B under the finite-horizon completion interpretation

**Essential problem context (paraphrased):** Given n tasks with known runtimes r1,…,rn on one processor, which policy maximizes throughput: round robin, shortest-job-first, highest-response-ratio-next, or FCFS? Explain the throughput interpretation needed.

## Solution

Step 1: If all jobs are ready and their runtimes are known, the k shortest jobs have the minimum possible total runtime among all k-job subsets. Executing them first therefore completes as many jobs as possible by each time horizon, under zero overhead and no blocking. This favors SJF, B.

Step 2: However, if throughput means the entire fixed batch’s n completions divided by its total processing time, every work-conserving order gives n/(r1+…+rn). Under that definition no unique scheduler maximizes it.

The answer therefore needs the finite-horizon or average-completion interpretation; it must not claim SJF reduces the sum of all CPU bursts.

Therefore additional frames can sometimes increase faults, C; neither a universal decrease nor universal increase is valid.

**Essential problem context (paraphrased):** A machine has 64 MiB physical memory, 32-bit virtual addresses, and 4 KiB pages. Estimate a flat page-table size from choices 16,8,2,24 MiB, and state the necessary page-entry-size assumption.

## Solution

Step 1: A 4 KiB page has 12 offset bits. A 32-bit virtual address therefore has 20 virtual-page bits, requiring 2^20 entries in a full single-level page table.

Step 2: Physical memory 64 MiB=2^26 bytes contains 2^14 frames, so a physical frame number needs 14 bits. Rounding that field to two bytes gives 2^20·2=2 MiB, option C, with only limited room for additional status bits.

Qualification: The entry size and organization are not specified. Four-byte entries would require 4 MiB, not listed; multilevel allocation can use a different amount. Therefore 2 MiB is a conventional estimate, not uniquely determined by the stated capacities alone.

Choose P: flag[j] AND turn=i; flag[j] AND turn=j; flag[i] AND turn=j; flag[i] AND turn=i. Distinguish progress from safety alone.

## Solution

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** Under the printed one-shot, atomic-read/write model: yes, no overlapping use for opposite-order GFG; literal GateForum also prevents overlap but self-blocks. Repeated execution is not specified.

**Essential problem context (paraphrased):** GFG variant: P1 executes S1 wait until R1 free; S2 set R1 busy; S3 wait until R2 free; S4 set R2 busy; S5 use both; S6 free R1; S7 free R2. P2 executes Q1 wait until R2 free; Q2 set R2 busy; Q3 wait until R1 free; Q4 set R1 busy; Q5 use both; Q6 free R2; Q7 free R1. Initially both free. Each test and subsequent set is a separate operation.

## Solution

For the GFG program, assume each individual flag read or write is atomic, but test-and-set is not, and each process executes its printed sequence once. Mutual exclusion of the actual use intervals S5 and Q5 is nevertheless guaranteed. Suppose the intervals overlapped. Neither process could yet have released a resource. P2 must therefore have passed its R1 test Q3 before P1 sets R1 at S2, giving Q3<S2. Similarly P1 must pass its R2 test S3 before P2 sets R2 at Q2, giving S3<Q2. Program order imposes S2<S3 and Q2<Q3. Combining yields the impossible strict cycle S2<S3<Q2<Q3<S2. Hence an overlapping execution is impossible. Separate tests and sets alone are not enough to prove a race in this particular opposite-order program.

For the literal GateForum variant, P2 sets R1 at Q2 and then waits for that same flag to become free at Q3. The only possible intervening freeing operation is P1’s S6, which follows completion of S5. Therefore P2 cannot reach Q5 before P1 finishes its use. This is poor progress behavior, not an overlapping-use counterexample. These conclusions concern the printed one-shot programs; an unspecified outer repetition loop or non-atomic/memory-reordered implementation is a different model.

**Essential problem context (paraphrased):** GFG variant: P1 executes S1 wait until R1 free; S2 set R1 busy; S3 wait until R2 free; S4 set R2 busy; S5 use both; S6 free R1; S7 free R2. P2 executes Q1 wait until R2 free; Q2 set R2 busy; Q3 wait until R1 free; Q4 set R1 busy; Q5 use both; Q6 free R2; Q7 free R1. Initially both free. Each test and subsequent set is a separate operation. Exchange Q1 with Q3 and Q2 with Q4.

## Solution

After swapping the GFG operations, both processes check/set R1 and then check/set R2. Name the new P2 order Q1′=test R1, Q2′=set R1, Q3′=test R2, Q4′=set R2, followed by use and the original releases. A violating interleaving is S1,Q1′,S2,Q2′,S3,Q3′,S4,Q4′, followed by overlapping S5 and Q5. Both tests of each free flag precede either write to that flag, so both reach their use intervals. This shows why a real atomic lock operation is required.

There is no resource deadlock in the reordered GFG protocol: a process waiting on R2 has already passed the R1 test. Any competing process that made R2 busy has also passed both tests and can finish and release; it cannot be waiting to acquire R1 afterward. This excludes a circular resource wait, assuming a runnable process eventually runs. It does not promise fairness or fix mutual exclusion.

Literal GateForum has identical operations in Q1/Q3 and Q2/Q4, so swapping changes nothing. Its one-shot nonoverlap and self-wait deadlock from parts (a),(b) remain. Source variants must not be silently conflated.

The source does not explicitly distinguish these conventions, so both are reported with their policies. Rotation rate and sector count do not enter a seek-time-only answer.

# GATE 2001: Q94 (printed B Q20(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203551/GATE2001.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Seek-only maximum 19.8 ms. Under a conventional one-sector/request bound, total ≤2039.8 ms (see assumptions).

**Essential problem context (paraphrased):** Disk has tracks 0–99, rotates at 3000 rpm, has 100 sectors per track and takes 0.2 ms to move one track. Initially 100 arbitrary requests, no new arrivals, head starts at track 0; determine worst-case completion time under elevator scheduling.

## Solution

Starting at the lowest track, all requests can be served in one upward sweep. The maximum head travel is 99 tracks, so seek time is at most 99×0.2=19.8 ms, attained if a request is at track 99. A revolution takes 60/3000 seconds=20 ms, and a single sector transfer takes 20/100=0.2 ms.

If each request reads one sector and one charges a separate worst-case rotational wait of up to one full revolution to every request, an additive bound is 19.8+100×(20+0.2)=2039.8 ms. A uniform-random-phase average latency would be 10 ms, yielding a different, average-model value 1039.8 ms; it is not a worst-case answer. If a convention counts a complete revolution as covering both wait and the requested sector transfer, the bound is instead 19.8+100×20=2019.8 ms.

The printed request description does not specify bytes/sectors per request, sector ordering at one track, or a rotational-latency convention. Therefore it does not determine a unique exact total completion time. The 19.8 ms seek bound is unambiguous; any fuller time must state its service assumptions. Independent per-request latency maxima are a conservative additive bound, not a proof that a single finite queue attains every maximum simultaneously.
