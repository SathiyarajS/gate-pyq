

# GATE 2008: Q20 (printed CS Q20)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 4. Consult original wording and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

## Solution

Traditional Unix inodes combine direct block pointers with singly, doubly and triply indirect pointer blocks. Very large files therefore use an extension of indexed allocation, D, rather than contiguous or linked allocation. Indexed allocation is the broad family, while D identifies the multilevel extension specifically.

# GATE 2008: Q63 (printed CS Q63)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

## Solution

The semaphore x_b protects the shared count and must start unlocked at 1. The semaphore y_b represents the waiting gate and must start at 0, so a P operation with negative count blocks. Thus the required initial values are (1,0), option C. This answers the initialization question, not a proof of the whole implementation. Under ordinary saturating binary-semaphore semantics the shown implementation can lose a wakeup: two P callers decrement to -2 and pause before P_b(y_b); two V callers then both signal y_b before either waiter consumes it, leaving only one stored signal. A robust implementation needs additional synchronization or a specified wakeup protocol.

# GATE 2008: Q64 (printed CS Q64)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

## Solution

In the intended interrupt-driven I/O model, both synchronous and asynchronous operations can invoke an ISR on completion. Synchronous versus asynchronous describes whether the requesting process waits, not whether completion interrupts exist. Hence A is the false statement; B, C and D describe the model. More generally I/O can be polled, so interrupt use is an assumed implementation detail rather than a universal consequence of synchronous/asynchronous semantics.

# GATE 2008: Q65 (printed CS Q65)

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

## Solution

Avoidance evaluates the resulting state and permits an otherwise valid request if that state is safe. Prevention instead enforces a structural restriction, such as global resource ordering or requesting everything together, which can reject a request even when its resulting state would be safe. Thus A is not true. Avoidance is less restrictive in this standard comparison and needs advance information about maximum resource requirements.

# GATE 2008: Q66 (printed CS Q66)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

## Solution

Assuming every fork succeeds, the number of processes doubles on each of n iterations because parent and child both continue the loop. There are 2^n total processes, of which one is the original. The number of newly created child processes across the entire process tree is 2^n−1, option B, not merely the n direct children of the original.

# GATE 2008: Q67 (printed CS Q67)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 14. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

## Solution

Each second- and third-level table has 2^9 entries of 4 bytes, so it occupies 2^11 bytes. With compact 2-KiB-aligned tables in a 36-bit physical address space, a pointer to either table needs 36−11=25 bits. A data page frame occupies 2^12 bytes and its frame number needs 36−12=24 bits. The result is (25,25,24), option D. This uses the intended natural table-size alignment; forcing every table to a separate 4-KiB frame would instead produce 24-bit table-frame pointers.
