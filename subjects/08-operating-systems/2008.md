**Paraphrased problem context:** How are blocks of a very large file allocated in the Unix file system?

(A) Contiguous allocation
(B) Linked allocation
(C) Indexed allocation
(D) An extension of indexed allocation

## Solution

1. Unix inodes store direct data-block addresses for small files.
2. For larger files, indirect blocks contain further addresses; double and triple indirection extend this hierarchy.
3. This is multilevel indexed allocation, the extension described in D. It neither requires contiguous blocks nor follows a next-block pointer stored in each data block.

# GATE 2008: Q63 (printed CS Q63)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Counting-semaphore operations are P(s): decrement s and wait if s<0; V(s): increment s and wake one waiter if s≤0. Given binary-semaphore wait/signal Pb,Vb, consider:
P(s): Pb(xb); s=s−1; if(s<0){Vb(xb); Pb(yb);} else Vb(xb);
V(s): Pb(xb); s=s+1; if(s≤0) Vb(yb); Vb(xb);
What initial values should xb,yb have respectively?

(A) 0,0
(B) 0,1
(C) 1,0
(D) 1,1

## Solution

1. The semaphore x_b protects the shared count and must start unlocked at 1. The semaphore y_b represents the waiting gate and must start at 0, so a P operation with negative count blocks.
2. Thus the required initial values are (1,0), option C. This answers the initialization question, not a proof of the whole implementation.
3. Under ordinary saturating binary-semaphore semantics the shown implementation can lose a wakeup: two P callers decrement to -2 and pause before P_b(y_b); two V callers then both signal y_b before either waiter consumes it, leaving only one stored signal. A robust implementation needs additional synchronization or a specified wakeup protocol.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Independently derived answer:** A

**Paraphrased problem context:** Which statement about synchronous/asynchronous I/O is NOT true in the interrupt-driven model?

(A) An ISR is invoked on synchronous completion but not asynchronous completion
(B) Both synchronous and asynchronous I/O invoke an ISR after completion
(C) Synchronous callers wait for completion; asynchronous callers do not
(D) For synchronous I/O, the completion ISR wakes the waiting process

## Solution

1. In the intended interrupt-driven I/O model, both synchronous and asynchronous operations can invoke an ISR on completion. Synchronous versus asynchronous describes whether the requesting process waits, not whether completion interrupts exist.
2. Hence A is the false statement; B, C and D describe the model. More generally I/O can be polled, so interrupt use is an assumed implementation detail rather than a universal consequence of synchronous/asynchronous semantics.

# GATE 2008: Q65 (printed CS Q65)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Which is NOT true of deadlock prevention and avoidance?

(A) Prevention always grants a request if the resulting state is safe
(B) Avoidance always grants a request if the resulting state is safe
(C) Avoidance is less restrictive than prevention
(D) Avoidance needs resource requirements known in advance

## Solution

1. Prevention breaks a necessary condition for deadlock, for example by requiring a fixed acquisition order or all-at-once requests. It may deny a request even though granting it would leave a safe state.
2. Avoidance explicitly tests safety using declared maximum needs and grants an otherwise valid request if safety is preserved.
3. Thus A incorrectly attributes avoidance’s rule to prevention. The conventional comparison makes B,C,D true: avoidance is less structurally restrictive but needs advance resource information.

# GATE 2008: Q66 (printed CS Q66)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 13. Consult original wording and choices.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** A process executes for(i=0;i<n;i++) fork();. How many child processes are created in total, assuming all forks succeed?

(A) n
(B) 2^n−1
(C) 2^n
(D) 2^(n+1)−1

## Solution

1. Both parent and new child continue the loop after each successful fork. Hence each iteration doubles the number of processes still executing.
2. From one process, n iterations yield 2^n total processes. Equivalently the iterations create 1+2+⋯+2^(n−1) children.
3. Subtract the one original process: 2^n−1, B. Counting only n forks by the original parent misses descendants’ forks.

# GATE 2008: Q67 (printed CS Q67)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 14. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** A processor has 36-bit physical and 32-bit virtual addresses, 4-KiB page frames, and 4-byte page-table entries. Its three-level translation indexes level 1 with VA bits 30–31, level 2 with bits 21–29, level 3 with bits 12–20; bits 0–11 are page offset. How many address bits in entries at levels 1,2,3 identify the next table or final frame, respectively?

(A) 20,20,20
(B) 24,24,24
(C) 24,24,20
(D) 25,25,24

## Solution

1. Each second- and third-level table has 2^9 entries of 4 bytes, so it occupies 2^11 bytes. With compact 2-KiB-aligned tables in a 36-bit physical address space, a pointer to either table needs 36−11=25 bits.
2. A data page frame occupies 2^12 bytes and its frame number needs 36−12=24 bits. The result is (25,25,24), option D.
3. This uses the intended natural table-size alignment; forcing every table to a separate 4-KiB frame would instead produce 24-bit table-frame pointers.
