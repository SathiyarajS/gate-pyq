**Paraphrased problem context:** Let t1 be the time to switch between user and kernel execution modes, and t2 the time to switch between two processes. Which comparison is intended to hold?

(A) t1 > t2
(B) t1 = t2
(C) t1 < t2
(D) Nothing can be said about their relation

## Solution

A user/kernel mode switch changes privilege and performs the associated entry/exit bookkeeping without necessarily changing the current process. A process context switch additionally saves/restores execution context and changes scheduling/address-space state. In the conventional comparison this costs more, giving t1<t2, C. It is an architectural cost-model comparison, not a hardware-independent numerical law for arbitrary implementations.

A system call can enter the kernel, do work for the same process, and return without scheduling another process. In a full context switch, the OS must preserve enough state to resume one process later and load another process's state; address-space switching may also entail translation/cache overhead. Thus a mode switch is conceptually a smaller operation. The question supplies no timings from which a numerical ratio could be calculated, only this conventional ordering.

**Paraphrased problem context:** Threads are called lightweight processes because the OS maintains smaller structures for a thread than a process. Which statement is TRUE?

(A) Per thread, the OS maintains only CPU register state
(B) The OS does not maintain a separate stack for each thread
(C) Per thread, the OS does not maintain virtual-memory state
(D) Per thread, the OS maintains only scheduling and accounting information

## Solution

Threads of one process share its virtual address space, so virtual-memory mappings are maintained at process level rather than separately for each thread. Each thread still needs its own register context, stack and scheduling information. Therefore C.

Independent execution requires each thread to remember its own instruction pointer and registers, and its own stack holds function calls and local execution state. The scheduler also tracks the thread's run/block status. Those facts refute A, B and D: none of the single listed items is the whole thread context, and stacks are not omitted. Virtual-memory mappings, however, describe the shared process address space, which is why C identifies the saving.

**Paraphrased problem context:** Memory access takes 20 ns on average, a page fault takes 10 ms to service, and one page fault occurs per 10^6 memory accesses. Find the effective access time.

(A) 21 ns
(B) 30 ns
(C) 23 ns
(D) 35 ns

## Solution

The fault probability is 10^−6 and 10ms=10^7 ns. Average fault overhead contributes10 ns per access, in addition to the 20 ns memory time, giving approximately30 ns, B. If fault service is taken as a replacement rather than added time, the weighted result29.99998 ns has the same rounded answer.

Convert all units before averaging: 1 ms=10^6 ns, so the fault penalty is ten million nanoseconds. Although the event is rare, multiplying that large penalty by 1/1000000 adds 10 ns to the average. This is half the normal access time, so ignoring faults because they are rare would be a large relative error. Conversely, adding the full 10 ms to every access would wrongly assume every reference faults.

**Paraphrased problem context:** Processes P0,P1,P2 have (arrival,burst) times in ms of (0,9),(1,4),(2,9). Use preemptive shortest-job-first scheduling, reconsidering at arrivals or completions. What is their average waiting time?

(A) 5.0 ms
(B) 4.33 ms
(C) 6.33 ms
(D) 7.33 ms

## Solution

P0 runs0–1, then P1 with its shorter remaining time runs1–5 despite P2 arriving at 2. P0 finishes its remaining 8 units during5–13; P2 then runs13–22. Waiting times are13−0−9=4, 5−1−4=0 and 22−2−9=11. Average(4+0+11)/3=5ms, A.

At time 1, P0 has 8 units remaining and P1 needs 4, so preemption is required. At time 2, P1 has only 3 remaining, less than P0's 8 and newly arrived P2's 9, so no further preemption occurs. Waiting time is turnaround minus burst, not completion time alone. P0 waits from 1 to 5, P1 never waits, and P2 waits from 2 to 13. These intervals independently reproduce the total 15 ms waiting time.

**Paraphrased problem context:** An application loads 100 libraries at startup. Each takes one disk access to a random location. Average seek time is 10 ms and rotational speed is 6000 rpm. Neglect data-transfer time once positioned at the block. What is the expected total load time?

(A) 0.50 s
(B) 1.50 s
(C) 1.25 s
(D) 1.00 s

## Solution

At 6000 rpm the disk makes 100 revolutions per second, so one revolution lasts 10 ms. Random angular position gives an average rotational latency of 5 ms. Each library requires one access with 10 ms seek time plus 5 ms average rotational latency; transfer time is neglected. The total expected loading time is 100×15 ms=1500 ms=1.50 s, option B. The random-location wording calls for average rotational latency, not a full revolution per access.

Convert rpm to revolutions per second before computing time: 6000/60=100. Uniform random angular placement means the desired sector can be anywhere from just under the head to nearly a full revolution away, averaging half a turn. Seek and rotational wait occur for each of the 100 distinct accesses, so both contributions must be counted 100 times. The expected seek total is 1 second and expected rotation total is 0.5 second; ignoring either would select an incorrect smaller answer.
