**Independently derived answer:** C in the traditional resident-loader model

**Essential problem context (paraphrased):** In a resident-OS model, which software must remain available in main memory: assembler, linker, loader, compiler?

## Solution

A loader brings executable code into memory and prepares it for execution. In the traditional resident monitor model, this loading support must remain available to bring in subsequent programs, motivating C. Assemblers, linkers and compilers can be ordinary separately loaded programs and need not be continuously resident. The universal wording is model-dependent: modern systems can page portions of loading software or use firmware and other mechanisms. The answer identifies the conventional resident component, not a theorem about all possible OS designs.

**Essential problem context (paraphrased):** What is a computation whose result depends on relative process speeds called: cycle stealing, race condition, time lock, deadlock?

## Solution

A race condition occurs when competing execution orders affect the result of shared operations. For example, two processes that each read, increment and write a counter may overwrite one another’s update depending on timing. Synchronization is needed when the intended result must not depend on such an interleaving. This is B. Deadlock instead means processes cannot make progress, while cycle stealing describes bus access by a device.

**Essential problem context (paraphrased):** A counting semaphore starts at 10. Six completed P(wait) and four completed V(signal) operations occur. Find the final value among 0, 8, 10, 12.

## Solution

Each completed wait consumes one available unit, decreasing the count by 1. Each signal adds one unit. Thus the net change is−6+4=−2, and the final count is 10−2=8. Because all six waits are stated to complete and the initial count is sufficient even before signals, no blocking ambiguity affects this arithmetic. Hence B; counting only the signals would incorrectly increase the initial value.

**Independently derived answer:** B: 5 under unrestricted incremental allocation

**Essential problem context (paraphrased):** Six identical tape drives are shared by n processes, each needing at most two. Find the largest n guaranteeing no resource deadlock among 6, 5, 4, 3.

## Solution

The dangerous state gives each process one drive while it waits for a second. With n≤5, at least one of six drives remains free, so some waiting process can receive its second, finish and release both; repeat to complete others. With n=6, all six can hold one and wait forever for a second, producing deadlock. Therefore the largest guaranteed-safe n is 5, B. This is a worst-case allocation guarantee, assuming eventual release and no other resources; an avoidance policy could safely serialize more processes.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A for maximum off-CPU waiting; start-to-start wording differs

**Essential problem context (paraphrased):** n processes share CPU; switches cost s seconds and quantum is q. Minimize overhead while each process gets a turn at least every t seconds. Options use q≤or≥(t−ns)/(n−1) or denominators n+1.

## Solution

After a process’s quantum ends, n−1 other quanta occur before it runs again. Including the n intervening switches gives waiting time (n−1)q+ns. Requiring this≤t yields q≤(t−ns)/(n−1), A, for n>1 and feasible t>ns. Switching overhead fraction decreases as q grows, so choose equality to minimize it within that constraint. If “every t seconds” instead measures successive start times, the interval includes the process’s own quantum: n (q+s)≤t, giving q≤t/n−s. The listed answer assumes off-CPU waiting, not literal start-to-start spacing.

**Essential problem context (paraphrased):** An instruction takes i microseconds; one page fault per k instructions adds j microseconds. Find effective instruction time.

## Solution

Over k instructions, ordinary execution costs ki microseconds. The average one fault adds j, so the total for that block is ki+j. Divide by k to obtain i+j/k per instruction, option A. The word additional matters: the base instruction cost is already counted and must not be divided away or counted twice. # GATE 1998: Q64 (printed A Q7(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** At time 19 under listed-order, nonpreemptive fixed-partition scheduling.

**Essential problem context (paraphrased):** Fixed partition sizes are 4,8,20,2 KB. Jobs in order have (size KB, execution time): (2,4),(14,10),(3,2),(6,1),(6,4),(10,1),(20,8),(2,6). With best-fit allocation, when does the 20 KB job finish?

## Solution

Assume all jobs are available at time 0, listed order resolves admission priority, partitions are fixed and not split, runtimes are elapsed times while resident, and loading/switching costs are zero. Best fit places an admitted job in the smallest currently free partition that accommodates it. Call the listed jobs J1 through J8.

At time 0, J1 occupies 2 KB until t=4, J2 occupies 20 KB until t=10, J3 occupies 4 KB until t=2, and J4 occupies 8 KB until t=1. J5, J6 and J7 cannot yet fit. At t=1, J4 finishes and J5 enters the 8 KB partition for four units, finishing at t=5.

The critical resource is the 20 KB partition. J6 needs 10 KB, so it cannot use the 4,8 or 2 KB partitions. J7 needs the entire 20 KB partition. At t=10, J2 releases it. Listed-order priority admits J6 first for one unit, t=10 to 11. Then J7 runs for eight units, t=11 to 19. Thus the requested completion time is 10+1+8=19.

A compact critical-resource diagram is:
20 KB: | J2, 0–10 | J6, 10–11 | J7, 11–19 |
8 KB:  | J4, 0–1 | J5, 1–5 |

J8 may enter a smaller partition earlier if the allocator bypasses blocked jobs, or later under strict head-of-line waiting; this does not change the listed-order use of the 20 KB partition. Best fit alone specifies a partition choice, not a scheduling discipline or arrival times. If arbitrary priority allowed J7 ahead of J6 at t=10, it would finish at 18. Therefore 19 is the conventional answer with the stated order assumptions, not a consequence of the phrase “best fit” alone.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 875 ms transfer time; a unique total needs rotational phase, layout/skew and servicing assumptions.

**Essential problem context (paraphrased):** Read 35 sectors on a soft-sectored, two-sided floppy, 8 sectors/track, 8 ms track step, 300 rpm, starting sector 3 of track 10 with head initially on track 10. Controller has one-sector buffer. Find total time.

## Solution

One revolution takes 60/300=0.2 s=200 ms, so a sector takes 200/8=25 ms. Reading the 35 payload sectors therefore needs 35×25=875 ms of on-media transfer. Starting at sector 3, the track portions contain 6,8,8,8,5 sectors, so five surface-tracks are visited and four surface-track boundaries crossed.

A two-sided disk does not necessarily seek at all four boundaries. With cylinder-major allocation starting on side 0, the order is cylinder 10 side 0, cylinder 10 side 1, cylinder 11 side 0, cylinder 11 side 1, cylinder 12 side 0. Ignoring head-switch time, this requires two radial steps, totaling 16 ms. A simplified additive estimate with no initial or boundary rotational waiting is then 891 ms. If 'track' instead means successive tracks of one surface requiring four steps, the corresponding estimate is 907 ms.

Neither estimate is an unconditional exact answer. The initial angular position is not specified. Without track skew, an 8 ms seek after sector 8 can miss the start of sector 1, requiring a wait for its next revolution. Under the cylinder-major example, zero initial wait, aligned sector numbering and instantaneous head switches, each of the two step boundaries costs an entire 200 ms including seek plus rotational wait, giving 875+400=1275 ms. A suitably skewed layout changes that boundary cost.

Finally, a one-sector buffer does not specify how quickly the host drains it. Missing the next sector while transferring a buffer can add whole rotations. A defensible expression is 875 ms + initial rotational wait + radial-step time + head-switch time + boundary/buffer waiting. The supplied facts fix only some terms, so report assumptions rather than invent an exact total.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Shortest expected processing time first, subject to standard all-arrived nonpreemptive assumptions.

**Essential problem context (paraphrased):** Four jobs with expected run times 6,3,5,x are waiting. In what order should they run to minimize average response time?

## Solution

Assume one processor, all four jobs ready at time zero, no scheduling overhead, and response interpreted as time to completion (or waiting time to first execution under nonpreemptive execution). Consider adjacent jobs of lengths a>b starting at time t. Their completion-time sum in order a,b is (t+a)+(t+a+b)=2t+2a+b. Reversing them gives 2t+2b+a, smaller by a−b. Other jobs' completion times do not change, because the pair's total length is unchanged. Repeatedly removing inversions proves ascending processing time is optimal.

Thus for x≥0: if x≤3, use x,3,5,6; if 3≤x≤5, use 3,x,5,6; if 5≤x≤6, use 3,5,x,6; if x≥6, use 3,5,6,x. Ties can be broken either way. For random run times the same exchange proof minimizes expected mean completion using their expected durations, when the decision is a fixed order and those expectations are known.

The answer is not a universal interactive-response policy: different release times, preemption or defining response as first service with arbitrarily small time slices changes the optimization problem. These are not specified, so the conventional nonpreemptive model is stated.

**Independently derived answer:** S1; parbegin {S2;S4} || {S3} parend; S5.

**Essential problem context (paraphrased):** Represent the graph with edges S1→S2,S1→S3,S1→S4,S1→S5,S2→S4,S4→S5,S3→S5 using parbegin/parend.

## Solution

S1 must finish first. Afterward S3 can run independently of the chain S2 then S4. S5 must wait for both branches. A structured program is:

begin
  S1;
  parbegin
    begin
      S2;
      S4;
    end
    S3;
  parend;
  S5;
end

Here parbegin starts its two child statements concurrently, and parend joins them. The first child is a sequential block, so S2 precedes S4. The second child is S3. The final join guarantees both S3 and S4 finish before S5. Edges S1→S4 and S1→S5 are already implied by the paths through S2/S4, but are still satisfied. There is no imposed order between S3 and S2 or between S3 and S4, so the program preserves the graph's available parallelism rather than unnecessarily serializing it.

# GATE 1998: Q96 (printed B Q25(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Fd<B in the conventional address-list accounting.

**Essential problem context (paraphrased):** Disk addresses take d bits; a disk has B blocks, F free. When does a free list occupy less storage than a bitmap?

## Solution

A bitmap uses one bit for every disk block, allocated or free, so its size is B bits. An explicit list storing one d-bit address per free block uses Fd bits. Thus the list is smaller precisely when Fd<B, or F/B<1/d. Equality is a tie, not a reduction. For example d=32 means the list wins below a free-block fraction of 1/32 under this model.

This compares payload metadata. An additional list-head pointer, count or alignment changes the inequality by the corresponding overhead, for example (F+1)d<B if one extra d-bit head is counted only for the list. A linked free list may store next pointers inside otherwise free blocks; in that implementation physical placement and reserved-memory costs differ from an external address array. The simple condition requested assumes the conventional one-address-per-free-block versus one-bit-per-total-block accounting.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** For zero-based disk coordinates and one-based n, j=((cL*t+tL)*s+sL)+(n−1); decode j by division.

**Essential problem context (paraphrased):** A disk has C cylinders,t tracks/cylinder,s sectors/track, sector length sl. A contiguous file begins at (cL,tL,sL), with record length rl=sl. Derive cylinder,track,sector of logical record n.

## Solution

Assume disk coordinates cL,tL,sL are zero-based, records are numbered from 1, and the file starts at a sector boundary. Since each record equals one sector, record n is n−1 sectors beyond the initial address. Linearize the starting location as j0=(cL*t+tL)*s+sL and set j=j0+n−1.

Then cylinder=floor(j/(t*s)); within-cylinder remainder r=j mod(t*s); track=floor(r/s); sector=r mod s. These divisions automatically carry across track and cylinder boundaries. For n=1, quotient/remainder reconstruction returns exactly the starting triple. Crossing a sector boundary from s−1 adds one track; crossing track t−1 adds one cylinder.

Require 0≤j<C*t*s so the record fits on the disk. If sector labels are one-based, replace the starting sL by sL−1 before linearization and add 1 to the final sector result. If all three disk labels are one-based, first subtract 1 from each and then add 1 to each output. If records themselves are numbered from zero, use n rather than n−1. Without these conventions an off-by-one ambiguity remains; the physical addressing rule is otherwise the same.
