**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Three CPU-bound processes arrive at times 0,2,6 and need 10,20,30 time units respectively. With shortest-remaining-time-first scheduling, how many context switches occur, excluding initial dispatch at time 0 and final termination?
Options:
(A) 1
(B) 2
(C) 3
(D) 4

## Solution

1. At time 2 the first process has 8 units remaining, less than the new 20. At time 6 it has 4 remaining, less than 30.

2. It therefore runs 0–10, followed by the 20-unit process 10–30 and the 30-unit process 30–60. Excluding initial dispatch and final exit leaves two process switches, B.

3. Teaching check: Draw the CPU timeline 0–10:P1, 10–30:P2, 30–60:P3. An arrival is not automatically a preemption: compare its burst with the current remaining time. Only the changes P1→P2 and P2→P3 count under the exclusions in the question.

# GATE 2006: Q61 (printed CS Q61)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Atomic fetch-and-set(x,y) sets shared location x to 1 and returns its old value in y, without an intervening access. Binary semaphore code is:
P(S): do { fetch-and-set(S.value,y); } while(y);
V(S): S.value=0;
Which statement is true?
Options:
(A) P may fail to work if context switching is disabled inside it
(B) A normal load/store pair can replace atomic fetch-and-set
(C) V is incorrectly implemented
(D) The code does not implement a binary semaphore

## Solution

1. P repeatedly atomically exchanges S.value with 1 and succeeds only when the previous value was 0. V releases it by storing 0.

2. On a uniprocessor, a process spinning in P with context switching disabled can prevent the lock owner from running V, so progress can fail. Separate load/store instructions are not atomic and allow two contenders to enter.

3. Thus A is true. This is a busy-wait semaphore using 0 for available and 1 for held; assume the intended atomic shared-memory model.

4. Teaching check: Atomicity prevents two contenders from both observing an available semaphore and entering. It does not guarantee progress if the spinning contender prevents the holder from being scheduled. Thus mutual-exclusion correctness and scheduling/liveness assumptions must be considered separately.

# GATE 2006: Q63 (printed CS Q63)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** A system has both 32-bit virtual and 32-bit physical addresses. Its designers remove virtual memory because the address-space sizes are equal. Which claimed consequence is true?
Options:
(A) Efficient multiuser support becomes impossible
(B) The cache organization can be made more efficient
(C) Hardware memory-management support is no longer needed
(D) CPU scheduling can be made more efficient

## Solution

1. Equal virtual and physical address widths do not make virtual memory redundant: address-space isolation, relocation, and protection still matter. Nevertheless removing address translation can simplify cache lookup, avoid translation-related latency and virtual alias issues, and thus permit a more efficient cache organization (B says can, not must).

2. Multi-user operation remains possible with other protection mechanisms; memory-management hardware can still be needed, and CPU scheduling does not automatically improve.

3. Teaching check: Equal address widths do not imply an identity mapping or a single shared address space. Different processes can map the same virtual address to different physical pages. The question’s true claim is only that cache organization can become simpler without translation, not that deleting virtual memory is generally desirable.

**Independently derived answer:** A

**Paraphrased problem context:** Processes with IDs 0,1,2 all arrive at time zero and need 2,4,8 compute units respectively. Use longest-remaining-time-first, reevaluated each time unit, with ties favoring the lower ID. What is average turnaround time?
Options:
(A) 13
(B) 14
(C) 15
(D) 16

## Solution

1. Using one-unit scheduling steps and breaking ties by the lower process ID, the running process IDs for times 0 through 13 are 2,2,2,2,1,2,1,2,0,1,2,0,1,2. Completion times are 12,13,14 for IDs 0,1,2.

2. Since arrivals are all zero, mean turnaround=(12+13+14)/3=13 units, A. This uses the intended discrete time-unit model; ideal continuous reevaluation at every instant would require a separate tie-sharing convention.

3. Teaching check: Turnaround equals completion time because every arrival is zero. LRTF initially favors the eight-unit process, but its remaining time eventually ties the four-unit process and the tie rule changes the schedule. Computing each completion time is safer than averaging burst lengths or waiting times alone.

**Independently derived answer:** B

**Paraphrased problem context:** Three processes arrive at time zero with total activity durations 10,20,30. Each spends its first 20% in I/O, next 70% computing, and last 10% in I/O. I/O overlaps as much as possible. The CPU chooses the shortest remaining compute burst when its current process blocks or completes its burst. What percentage of the entire elapsed interval is CPU-idle?
Options:
(A) 0%
(B) 10.6%
(C) 30.0%
(D) 89.4%

## Solution

1. The three initial I/O bursts last 2,4,6; compute bursts last 7,14,21; final I/O bursts last 1,2,3. CPU is idle 0–2, executes process 1 during 2–9, process 2 during 9–23, and process 3 during 23–44.

2. Their final I/O finishes at 10,25,47. Over the complete 47-unit elapsed interval, CPU idle time is 2+3=5, hence 100×5/47≈10.6%, B.

3. The question continues on physical page 10.

4. Teaching check: The initial I/O phases overlap, so their elapsed cost is not 2+4+6 in series. While the first process computes, the other initial I/Os finish. The final three-unit I/O of the last process extends the completion horizon beyond the final CPU burst, producing additional CPU-idle time.

# GATE 2006: Q66 (printed CS Q66)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B in alternate reproduction; no universally necessary listed condition as GFG prints B

**Paraphrased problem context:** There are n processes; process i holds xᵢ instances of a resource and requests yᵢ additional instances. All resource instances are allocated. Exactly two processes p,q have yₚ=y_q=0. Which can be a necessary condition for avoiding impending deadlock? Max/min below range over k≠p,q. GFG prints max in B; GateForum prints min, a materially different condition.
Options:
(A) min(xₚ,x_q)<max yₖ
(B) xₚ+x_q≥max yₖ [GFG]; xₚ+x_q≥min yₖ [GateForum]
(C) max(xₚ,x_q)>1
(D) min(xₚ,x_q)>1

## Solution

1. Only p and q can initially finish without another allocation. After both finish, available resources equal W=x_p+x_q.

2. To make any further progress, at least one remaining process must have y_k≤W; therefore W≥min_{k≠p,q}y_k is necessary (not sufficient for eventual completion of all processes). This is option B in the GATE Forum reproduction, physical page 20.

3. GFG instead prints max in B: W≥max y_k is sufficient, assuming these are remaining completion needs, but is not necessary. Counterexample: allocations (1,1,2,1), additional requests (0,0,1,3) have a safe sequence p,q,r,s: W grows 2→4→5, yet initial W=2<3.

4. No other GFG option is universally necessary: with all four allocations 1 and remaining requests (0,0,1,1), a safe sequence exists while A (1<1), C (1>1), and D (1>1) are false. Do not silently replace max by min in the primary source.

5. Teaching check: A necessary condition need not guarantee full completion. Once p and q release their holdings, at least one remaining process must be able to obtain its requested resources. Requiring enough for the largest request is stronger than necessary; a smaller request may finish first and release more resources.

# GATE 2006: Q78 (printed CS Q78)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Three processes repeatedly synchronize at a barrier. Shared process_arrived and process_left start at 0. S is a binary semaphore, initially available; P acquires and V releases it. Each process calls:
void barrier(void) {
 1: P(S);
 2: process_arrived++;
 3: V(S);
 4: while (process_arrived != 3);
 5: P(S);
 6: process_left++;
 7: if (process_left == 3) {
 8:   process_arrived=0;
 9:   process_left=0;
10: }
11: V(S);
}
Use the intended shared-memory pseudocode model, not a claim of data-race-safe modern C. Why is the implementation incorrect?
Options:
(A) The use of binary semaphore S makes it wrong
(B) Two consecutive barrier invocations can deadlock
(C) Lines 6–10 do not need a critical section
(D) It is correct with two processes instead of three

## Solution

1. Once all three arrive, process_arrived=3. Let P leave the first barrier, increment process_left to 1, and immediately enter its next barrier before Q and R have finished the first.

2. It increments process_arrived to 4. If Q and R have not passed the first barrier’s while test, they now wait for process_arrived==3, and P also waits in its second invocation.

3. No one can perform the final reset: deadlock. Binary semaphores correctly protect the updates and are not the cause; the missing separation between barrier generations is.

4. The same issue can occur with two processes. Hence B.

5. Teaching check: The first invocation opens when arrival count reaches three, but the code does not close entry to the next generation. An early returning process can raise the count to four while another still tests for equality with three. A protected increment alone does not prevent mixing generations.

# GATE 2006: Q79 (printed CS Q79)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B, with generation-entry qualification

**Paraphrased problem context:** Three processes repeatedly synchronize at a barrier. Shared process_arrived and process_left start at 0. S is a binary semaphore, initially available; P acquires and V releases it. Each process calls:
void barrier(void) {
 1: P(S);
 2: process_arrived++;
 3: V(S);
 4: while (process_arrived != 3);
 5: P(S);
 6: process_left++;
 7: if (process_left == 3) {
 8:   process_arrived=0;
 9:   process_left=0;
10: }
11: V(S);
}
Use the intended shared-memory pseudocode model, not a claim of data-race-safe modern C. Which proposed repair addresses its reuse problem? The phrase “first process” in B is only a conceptual generation gate and needs a concrete synchronization implementation.
Options:
(A) Replace lines 6–10 by process_arrived--
(B) At barrier entry, the first process waits for process_arrived to become zero before executing P(S)
(C) Disable context switching throughout the barrier
(D) Make process_left private instead of shared

## Solution

1. The intended repair is to prevent a process from incrementing the next generation’s arrival count until the previous generation has reset process_arrived to zero, corresponding to B. It must wait before acquiring S, leaving S available to the final departing process that performs the reset.

2. A lets an early departure lower process_arrived while others still need to observe 3; C prevents necessary scheduling on a uniprocessor; D prevents the shared departure count reaching 3. However the phrase first process to enter is a conceptual generation gate, not complete executable synchronization.

3. Merely adding an unconditional while(process_arrived!=0) to every invocation blocks the second arrival of the same generation; waiting only one vaguely designated process while allowing another new-generation entrant through is also insufficient. A concrete reusable barrier needs a correctly synchronized generation flag or two-turnstile design.

4. Teaching check: Waiting while holding S would prevent the final departing process from acquiring S to reset the counters. Waiting must therefore occur outside that critical section, and it must distinguish generations correctly. A two-turnstile or generation-counter barrier is a concrete way to enforce this separation.
