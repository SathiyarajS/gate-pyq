**Independently derived answer:** A

**Paraphrased problem context:** In the conventional comparison for a fixed-block-size file system, increasing block size leads to: A. Better disk throughput but poorer space utilization; B. Better throughput and better utilization; C. Poorer throughput but better utilization; D. Poorer throughput and poorer utilization.

## Solution

1. Reading a larger contiguous block transfers more useful bytes per seek or setup cost for a sequential workload. But the last block of a file is allocated in full even when only partly used; increasing the allocation unit can increase this internal slack. These effects explain the conventional throughput/utilization tradeoff.

2. Larger blocks amortize per-I/O overhead across more bytes, often improving sequential disk throughput, but waste more unused space in partially occupied final blocks. Thus better throughput with poorer space utilization, A, under the conventional workload comparison. It is not a universal guarantee for every random-access workload.

**Paraphrased problem context:** With 32-bit virtual addresses and 1 KB pages, why is a one-level page table impractical? A. Large internal fragmentation; B. Large external fragmentation; C. Large memory overhead for page tables; D. Large computation overhead in translation.

## Solution

1. A 1 KB page means 2¹⁰ byte offsets, so a virtual address splits into 22 page-number bits and 10 offset bits. Even a sparsely used process address space requires all 2²² slots in a flat table. Four-byte entries are an illustration, not an additional given: they would occupy 16 MiB per table.

2. A 1 KiB page uses 10 offset bits, leaving 22 virtual-page bits in a 32-bit address. A flat table therefore needs 2^22 entries per address space; at 4 bytes each this is 16 MiB. The large memory overhead, C, motivates multilevel or other sparse organizations.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Which is NOT an advantage of shared, dynamically linked libraries over statically linked libraries?
A. Smaller executable files
B. Lower overall page-fault rate in the system
C. Faster program startup
D. Existing programs need not be relinked to benefit from newer library versions

## Solution

1. Static linking copies required library code into each executable. Dynamic linking can leave that code in a separately loaded library, reducing executable size, so A is a conventional benefit.
2. Multiple processes can map the same read-only physical library pages. This reduces duplicated resident code and can reduce total memory pressure/page faults, the intended benefit in B.
3. A compatible replacement library may be used on the next load without rebuilding each application, explaining D; compatibility remains necessary.
4. Dynamic loading and symbol relocation/resolution add work at startup or first use. Faster startup is not a general advantage, so C is the requested exception. Actual cache and page-fault behavior still depends on workload.

Baseline derivation and caveats (retained): Dynamic linking can keep library code out of the executable, share physical library pages among processes, and permit compatible library updates without relinking each application. It also introduces runtime loading, relocation, or symbol-resolution work. Faster program startup is therefore not the characteristic advantage over static linking, option C. The other listed benefits are the conventional shared-library benefits; actual page-fault and startup measurements can depend on caching and workload.

# GATE 2003: Q77 (printed CS Q77)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=11), physical page 11. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** A uniprocessor runs only two processes, created nearly simultaneously. Each alternates a 10 ms CPU burst with a 90 ms I/O burst; their I/O can proceed in parallel. Which policy gives the least long-run CPU utilization?
A. First come, first served
B. Shortest remaining time first
C. Static priority with different priorities
D. Round robin with a 5 ms quantum

## Solution

1. Ignore switching overhead as the statement supplies none. Under FCFS one process runs 0–10 and the other 10–20. Their I/O ends at 100 and 110, and each finishes its next CPU burst just as the other becomes ready. Thus the CPU supplies 20 ms work per 100 ms: 20% utilization. SRTF and distinct priorities have the same sustained burst staggering here.
2. Under 5 ms round robin, the initial slices are P:0–5, Q:5–10, P:10–15, Q:15–20. Their I/O begins at 15 and 20, only 5 ms apart, and ends at 105 and 110.
3. With the usual ordering when I/O completion coincides with quantum expiry, Q gets the CPU at 110, so the next completed CPU bursts are at 120 and 125. This repeats the paired pattern after 105 ms.
4. Utilization is 20/105≈19.05%, less than 20%, making D the conventional answer. The smaller separation causes more simultaneous I/O and hence more CPU idle time.

Baseline derivation and caveats (retained): Ignoring context-switch cost, FCFS, shortest-remaining-time, and distinct static priorities run the two initial CPU bursts consecutively for 10 ms each. Their I/O completions stay offset by 10 ms, giving 20 ms of CPU work in a 100 ms steady-state period. With round robin at a 5 ms quantum, the initial bursts finish at 15 and 20 ms, so the processes enter I/O only 5 ms apart. Under the usual ready-queue ordering at simultaneous quantum expiry and I/O completion, this pattern repeats every 105 ms, giving utilization 20/105≈19.05%, below 20%. Thus D is the conventional answer: fine time slicing makes their long I/O intervals overlap more.

**Independently derived answer:** C

**Paraphrased problem context:** A byte-addressable processor has 32-bit virtual and physical addresses and two-level page tables stored in main memory. Address bits are split 10 bits for first-level index, 10 for second-level index, and 12 for page offset. All page-table entries are 4 bytes. TLB hit rate is 96%, physical-cache hit rate 90%; TLB and cache access each take 1 ns, and main memory takes 10 ns. A process maps only two contiguous code pages starting at 0x00000000, two contiguous data pages starting at 0x00400000, and one stack page starting at 0xFFFFF000. How much storage is needed for its page tables?
A. 8 KB  B. 12 KB  C. 16 KB  D. 20 KB

## Solution

1. A 10-bit index selects 1024 entries. At four bytes per entry each full table occupies 4096 bytes, one 4 KiB page.
2. One second-level table covers 1024 virtual pages, or 1024×4096=4 MiB. The code pages fall in the first 4 MiB region, top-level index 0. The data begins exactly at 4 MiB, index 1. The stack address has index 1023.
3. The two contiguous code pages share one second-level table, as do the two data pages. The stack needs a third second-level table. Add one top-level table: four tables total.
4. Storage=4×4096=16384 bytes=16 KiB, option C. Mapped content pages are not additional page-table storage.

Baseline derivation and caveats (retained): Each page-table level has 2^10 entries of four bytes, so each allocated table uses 4096 bytes. The two code pages occupy top-level index 0; the two data pages starting at 0x00400000 occupy index 1; the stack page at 0xFFFFF000 occupies index 1023. Three second-level tables are therefore required, plus the first-level table. Total page-table storage is 4×4096=16384 bytes=16 KiB, option C. The five mapped code/data/stack pages are not themselves included in page-table storage.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Independently derived answer:** B

**Paraphrased problem context:** Two concurrent processes use binary semaphores S,T. Process P loops forever: W: [synchronization]; print '0'; print '0'; X: [synchronization]. Process Q loops forever: Y: [synchronization]; print '1'; print '1'; Z: [synchronization]. Synchronization can be placed only at W,X,Y,Z. P(S) means wait/decrement and V(S) means signal. Which always gives an output starting 001100110011...?
A. W=P(S), X=V(S), Y=P(T), Z=V(T); S=T=1 initially
B. W=P(S), X=V(T), Y=P(T), Z=V(S); S=1,T=0 initially
C. W=P(S), X=V(T), Y=P(T), Z=V(S); S=T=1 initially
D. W=P(S), X=V(S), Y=P(T), Z=V(T); S=1,T=0 initially

## Solution

1. The required output demands both pairwise exclusion and alternation starting with P's zeros. Initially only P should have permission: S=1 and T=0.
2. P passes wait(S), prints both zeros, then signals T. Q cannot print any one until this signal; once released it consumes T, prints both ones and signals S.
3. P's next wait(S) cannot pass before Q completes its pair. Inductively the execution consists of 00,11,00,11,..., so B works.
4. In A independent locks allow arbitrary interleaving. C initially lets both processes enter, so even the first pair need not be 00. In D Q waits forever on T because no other process signals T.

Baseline derivation and caveats (retained): Initially give P permission to run by setting S=1 and block Q with T=0. P waits on S at W, prints both zeroes, and signals T at X. Q waits on T at Y, prints both ones, and signals S at Z. Each process therefore hands permission to the other only after completing its pair, forcing 00,11,00,11,… starting with 00. This is B. Separate locks do not coordinate the processes, and initializing both cross-signalling semaphores to one would permit initial interleaving.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Two concurrent processes use binary semaphores S,T. Process P loops forever: W: [synchronization]; print '0'; print '0'; X: [synchronization]. Process Q loops forever: Y: [synchronization]; print '1'; print '1'; Z: [synchronization]. Synchronization can be placed only at W,X,Y,Z. P(S) means wait/decrement and V(S) means signal. Which ensures the output never contains 0 1^n 0 or 1 0^n 1 with n odd?
A. W=P(S), X=V(S), Y=P(T), Z=V(T); S=T=1
B. W=P(S), X=V(T), Y=P(T), Z=V(S); S=T=1
C. W=P(S), X=V(S), Y=P(S), Z=V(S); S=1
D. W=V(S), X=V(T), Y=P(S), Z=P(T); S=T=1

## Solution

1. The forbidden patterns mean a run of ones between zeros, or zeros between ones, must have even length. It is sufficient for each process to print its identical pair atomically.
2. C uses the same initially available semaphore at both W and Y. Only one process can enter its two-print critical section, and it releases the mutex only after the pair.
3. Output is thus a concatenation of whole 00 and 11 blocks. Adjacent blocks of the same digit may merge, but their lengths remain multiples of two, proving the desired property.
4. A and B initially allow both processes inside, permitting P's first 0, Q's first 1, P's second 0: a forbidden 010. D does not make P acquire a common mutex and likewise does not ensure whole-pair exclusion. Therefore C.

Baseline derivation and caveats (retained): Use one common binary semaphore S, initially one, as a mutex around both print statements of either process: wait(S) at W and Y, signal(S) at X and Z. Each critical section then emits either 00 or 11 without interleaving, so any run between opposite digits is a concatenation of equal pairs and has even length. That is C. For example, when independent locks or two initially available cross-signalling permissions let P emit its first zero, Q one one, and P its second zero, the forbidden substring 010 occurs. Mutual exclusion of entire pairs is the needed property, not merely exclusion within each individual process.
