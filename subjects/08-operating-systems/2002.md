**Essential problem context (paraphrased):** Which scheduling method is nonpreemptive?
(A) Round robin; (B) First-in first-out; (C) Multilevel queue scheduling; (D) Multilevel queue scheduling with feedback.

## Solution

Step 1: Identify the event that removes the running process.

Step 2: Under FIFO, arrival of another ready process does not by itself interrupt the current one. The current process relinquishes the CPU by blocking or finishing. Round robin deliberately introduces timer preemption. A multilevel policy needs additional rules before one can decide whether it preempts, so its name is not an unconditional alternative to FIFO.

Conclusion and qualifications: FIFO/FCFS lets the running job continue until it blocks or completes, so B. Round robin preempts at a time quantum. Multilevel scheduling families depend on their specified interqueue and intraqueue policies and are not, by name alone, the fixed nonpreemptive policy sought.

(B) The one whose next use is farthest in the future.
(C) The one used the fewest times.
(D) The one used the most times.

## Solution

Step 1: Compare future reuse times.

Step 2: If resident pages will next be requested after 2,5 and 10 accesses, evict the page needed after 10. Evicting the page needed after 2 causes a miss sooner while retaining a page that is not yet useful. This exchange argument can be repeated to match an optimal schedule. The method is a theoretical benchmark because the future reference string is generally unavailable online.

Conclusion and qualifications: Choose the resident page whose next use lies farthest in the future, treating no further use as infinity. Exchanging any earlier-needed victim for this one cannot increase future faults, yielding Belady’s optimal policy, B. Past recency describes LRU instead.

Conclusion and qualifications: Keeping multiple programs resident, (a), and switching to another ready program when one waits, (b), permit useful CPU work while I/O proceeds: the characteristic multiprogramming behavior. Thus the minimal defining combination is B. Scheduling another job after termination, (c), occurs in ordinary serial batch processing too. Literally D contains this sufficient combination as well; the usual question asks which features distinguish the model, not all logical supersets. An available ready job is implicit in the scheduling statements.

(C) Block size, number of index blocks, and block-address size.

## Solution

Step 1: Track the dimensions of the capacity calculation.

Step 2: Each index block contains floor(B/p) addresses. I such blocks contain I·floor(B/p) addresses in a flat organization, and each address identifies a B-byte data block. Multiplying gives I·floor(B/p)·B bytes. Omitting address size ignores how many pointers fit, while omitting index-block count ignores how many such pointer containers are available.

Conclusion and qualifications: If I index blocks of B bytes store addresses of p bytes each, a simple flat index addresses I·floor(B/p) data blocks, giving roughly IB²/p file bytes. Thus block size, index-block count and address size all affect capacity, C. Multilevel structures alter the detailed formula, not the need to account for these quantities.

**Independently derived answer:** Deadlock-free under the usual progress assumptions; not starvation-free.

**Essential problem context (paraphrased):** Atomic TEST_AND_SET(int*x) performs A1:y=*x; A2:*x=1; A3:return y. Shared mutex initially 0. Entry/exit templates: void enter_cs(){while(blank);} void leave_cs(){blank;} Original18(b)(ii): For the resulting spinlock entry/exit solution, determine whether it is deadlock-free and starvation-free.

## Solution

With atomic TEST_AND_SET, one contender acquires any free lock, and a holder that finishes its finite critical section releases the lock. Under the usual assumptions that a holder continues to receive execution time and eventually exits, the lock is deadlock-free: processes do not remain mutually blocked with no one able to proceed. It is not starvation-free, since a waiting process is not assigned a turn. Each time the lock is released another contender can acquire it first, so one process can lose indefinitely even while other processes keep making progress. As with any spinlock, a scheduler that prevents the holder from running can itself defeat progress; deadlock-freedom is not an unconditional scheduling guarantee.

## Solution

A 4 KiB page has 2^12 bytes, so the low 12 address bits are the unchanged page offset. The remaining 32−12=20 virtual-page bits split equally into two 10-bit indices. The translation is:
VA[31:22] --index--> first-level table --second-level table base
VA[21:12] --index into that table--> second-level entry --20-bit physical frame number
PA = (physical frame number << 12) | VA[11:0].
More explicitly, the first entry is at first_table_base + 4·VA[31:22]; it identifies the second-level table. The second entry is at second_table_base + 4·VA[21:12]; it identifies the data page frame. Validity and protection flags are checked along the way; absent or disallowed mappings fault. The diagram describes a successful translation and does not require a TLB assumption.
