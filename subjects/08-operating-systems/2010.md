**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Processes P1 and P2 use shared Boolean variables S1,S2 whose initial values are assigned randomly. Whenever they need their critical sections they execute:
P1: while (S1==S2); critical section; S1=S2;
P2: while (S1!=S2); critical section; S2=not(S1);
Which properties are achieved?
Options: (A) Mutual exclusion but not progress; (B) Progress but not mutual exclusion; (C) Neither mutual exclusion nor progress; (D) Both mutual exclusion and progress.

## Solution

P1 passes its guard only when S1≠S2; P2 passes only when S1=S2. Neither changes the shared state until leaving its critical section, so while one is inside the other’s guard stays blocking: mutual exclusion holds. Progress fails: if S1=S2 and only P1 wants to enter, P1 spins forever unless P2 participates and changes S2. The symmetric case also occurs. This is strict alternation, so A, assuming atomic sequentially consistent accesses as the pseudocode model does.

Teaching detail: After P1 exits it sets S1=S2, making P2 eligible and itself ineligible; after P2 exits it makes S2 the opposite of S1, restoring P1’s turn. Consequently the processes alternate even if one no longer wants the critical section. Mutual exclusion is a safety property; progress additionally requires that an uninterested process not prevent an interested one from entering.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** A FIFO page-replacement system has four frames, initially empty. It accesses 100 distinct pages in some order, then accesses those same 100 pages in the reverse order. How many page faults occur?
Options: (A) 196; (B) 192; (C) 197; (D) 195.

## Solution

The first 100 distinct references all fault. The four resident pages are then the last four in forward order, and the reverse scan hits these four first. Every one of the other 96 reverse references is to a page not yet resident; those faults evict only pages already visited in the reverse scan. Therefore faults total 100+96=196, option A. Hits do not refresh FIFO order.

Teaching detail: Name the forward sequence p₁,…,p₁₀₀. The reverse sequence starts p₁₀₀,p₉₉,p₉₈,p₉₇, all already resident. Then p₉₆,…,p₁ must each fault because none remains from the forward scan. There are 200 total references and exactly four hits, giving 200−4=196 independently of the original ordering.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 6. Consult original wording and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Which statements about CPU scheduling are true? I: shortest-remaining-time-first may cause starvation. II: preemptive scheduling may cause starvation. III: round robin is better than FCFS in response time.
Options: (A) I only; (B) I and III only; (C) II and III only; (D) I,II and III.

## Solution

SRTF may indefinitely postpone a long job when shorter jobs keep arriving, so I is true. SRTF is itself preemptive, establishing that preemptive scheduling may cause starvation, so II is true. Round robin’s time slices let waiting jobs receive CPU service without waiting for a long earlier job to finish, which is the conventional interactive response-time advantage asserted by III. The intended answer is all three, D. III is a qualitative textbook comparison, not a strict improvement for every workload and quantum; for a quantum exceeding all bursts, RR reduces to FCFS.

Teaching detail: Starvation means unbounded waiting, not merely a long finite delay. Under SRTF, a long job can be repeatedly preempted by a stream of shorter jobs. Round robin uses a bounded quantum to distribute service opportunities among ready jobs, which improves typical interactive first-response behavior, while potentially increasing context-switch cost. The word “may” in I and II is essential.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 11. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Three concurrent processes use binary semaphores initially S0=1,S1=0,S2=0:
P0: while(true) { wait(S0); print '0'; release(S1); release(S2); }
P1: wait(S1); release(S0);
P2: wait(S2); release(S0);
How many times will P0 print '0'?
Options: (A) At least twice; (B) Exactly twice; (C) Exactly thrice; (D) Exactly once.

## Solution

P0 consumes the initial S0 permit and prints once, then enables P1 and P2. Each of those processes releases S0 exactly once. If both releases occur before P0 next waits on S0, binary saturation coalesces them into one permit, allowing only one further print: total 2. If P0 consumes the first released permit before the other process releases S0, it receives two separate permits and prints three times total. Thus 2 or 3 prints are possible, so the only correct choice is A, at least twice. This assumes ordinary progress/eventual scheduling; an adversarial scheduler that permanently starves runnable processes defeats any eventual-print guarantee. A counting semaphore would instead give exactly three.

Teaching detail: The distinction between binary and counting semaphores changes the answer. A binary semaphore stores at most one available permit; release on an already available semaphore does not accumulate a second permit. P1 and P2 have no loops, so they cannot supply unbounded future permits even though P0 keeps releasing S1 and S2. That bounds the total prints above by three.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 11. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** There are n single-instance resources R₀,…,Rₙ₋₁ and k processes P₀,…,Pₖ₋₁. Each process Pᵢ requests resources using:
if(i%2==0) {
 if(i<n) request Rᵢ;
 if(i+2<n) request Rᵢ₊₂;
} else {
 if(i<n) request Rₙ₋ᵢ;
 if(i−2<n) request Rₙ₋ᵢ₋₂;
}
For which offered n,k is deadlock possible? The odd-branch subscripts are faint in the scan; the explicit reading above preserves the inherited interpretation. The second odd-branch guard is printed i−2<n, not silently repaired.
Options: (A) n=40,k=26; (B) n=21,k=12; (C) n=20,k=10; (D) n=41,k=19.

## Solution

Read the code as even i requesting Ri followed by R(i+2), and odd i requesting R(n−i) followed by R(n−i−2), subject to the printed guards. For n=21,k=12, P10 requests R10 then R12, while P9 requests R12 then R10. If each obtains its first resource, they wait on each other: deadlock is possible, B. For even n (A and C), even processes use only even-indexed resources in increasing order, while odd processes use only odd-indexed resources in decreasing order. Each parity class has a consistent order, so neither can cycle. For D, n=41,k=19: even processes use resources 0 through 20, whereas odd processes use even resources 22 through 40, so these opposite-order sets do not overlap and cannot form a cycle. This uses single-instance, non-preemptive resources held until completion, the standard deadlock model. The low-quality scan has faint minus signs/subscripts in the odd branch; the relevant R(n−i),R(n−i−2) reading is recorded explicitly.

Teaching detail: The deadlocking B execution can be written explicitly: P10 acquires R10; P9 acquires R12; P10 blocks requesting R12; P9 blocks requesting R10. The resource-allocation graph now has a cycle with single-instance resources. Consistent increasing or decreasing order prevents cycles within one resource set, but opposing orders on overlapping resources can create the exhibited cycle.
