**Paraphrased problem context:** A process executes the code
                fork();
                fork();
                fork();
        The total number of child processes created is
        (A) 3                   (B) 4                      (C) 7                  (D) 8

## Solution

Assuming each fork succeeds, the first invocation creates one child, the second is executed by two processes and creates two more, and the third by four processes creates four more. There are 1+2+4=7 children, or eight total processes including the original. Hence C.

Worked check / additional reasoning: Track the live population after each call as 1→2→4→8. Every new process is a child of an existing process, but the original process is not its own child, so subtracting it from the final population avoids distractor D.

**Derived answer:** C

**Source access:** Open archive member CS/CS2012.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Consider the 3 processes, P1, P2 and P3 shown in the table.

                                       Process       Arrival       Time Units
                                                     time          Required
                                       P1            0             5
                                       P2            1             7
                                       P3            3             4

        The completion order of the 3 processes under the policies FCFS and RR2 (round robin scheduling
        with CPU quantum of 2 time units) are
        (A) FCFS: P1, P2, P3 RR2: P1, P2, P3                 (B) FCFS: P1, P3, P2 RR2: P1, P3, P2
        (C) FCFS: P1, P2, P3 RR2: P1, P3, P2                 (D) FCFS: P1, P3, P2 RR2: P1, P2, P3

## Solution

FCFS executes P1 from 0–5, P2 from 5–12 and P3 from 12–16, so completion order is P1, P2, P3. For quantum 2, round robin runs P1 0–2, P2 2–4, P1 4–6, P3 6–8, P2 8–10, P1 10–11, P3 11–13, P2 13–15 and 15–16. Completion times are respectively 11, 16, 13, giving P1, P3, P2. Hence C.

Worked check / additional reasoning: The arrivals occur between quantum boundaries: P2 joins during P1’s first slice, and P3 joins during P2’s first slice. A preempted unfinished process returns to the tail, whereas a completed process is removed. This explains why the shorter P3 finishes before P2 under RR.

**Official answer:** B

**Derived answer:** B

**Source access:** Open archive member CS/CS2012.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Fetch_And_Add(X,i) is an atomic Read-Modify-Write instruction that reads the value of
        memory location X, increments it by the value i, and returns the old value of X. It is used in the
        pseudocode shown below to implement a busy-wait lock. L is an unsigned integer shared variable
        initialized to 0. The value of 0 corresponds to lock being available, while any non-zero value
        corresponds to the lock being not available.

            AcquireLock(L){
                  while (Fetch_And_Add(L,1))
                        L = 1;
            }

            ReleaseLock(L){
                  L = 0;
            }

        This implementation
        (A) fails as L can overflow
        (B) fails as L can take on a non-zero value when the lock is actually available
        (C) works correctly but may starve some processes
        (D) works correctly without starvation

## Solution

Suppose one process holds the lock with L=1. A waiter executes Fetch_And_Add, obtains old value 1 and changes L to 2, so it must execute the loop body. Before that body executes, the owner releases the lock by storing L=0. The waiter then executes its pending L=1 assignment, restoring a nonzero value even though nobody holds the lock. Subsequent tests keep failing and there need be no owner left to release it. Thus B identifies a failure even without arithmetic overflow.

Worked check / additional reasoning: Atomicity protects the fetch-and-add operation itself, not the following plain assignment. The interleaving is: waiter atomically changes 1→2; owner changes 2→0; waiter changes 0→1. The last store overwrites the release and leaves no holder responsible for another release.

**Paraphrased problem context:** A file system with 300 GByte disk uses a file descriptor with 8 direct block addresses, 1 indirect
        block address and 1 doubly indirect block address. The size of each disk block is 128 Bytes and the
        size of each disk block address is 8 Bytes. The maximum possible file size in this file system is
        (A) 3 KBytes
        (B) 35 KBytes
        (C) 280 KBytes
        (D) dependent on the size of the disk

## Solution

Each indirect block holds 128/8=16 addresses. The descriptor therefore reaches 8+16+16²=280 data blocks. Their payload is 280×128=35, 840 bytes=35 KiB (the option calls these KBytes). Indirection blocks are metadata and do not count as file payload. The 300 GByte disk is more than large enough. Hence B.

Worked check / additional reasoning: The eight direct pointers cover 1024 bytes, the single-indirect pointer covers 16×128=2048 bytes, and double indirection covers 256×128=32768 bytes. Their sum is 35840 bytes. Multiplying 280 by KiB instead of by 128 bytes produces the 280-KByte distractor.

# GATE 2012 CS: Q52 (printed CS Q42)

**Question:** [Official archived paper page 10](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Derived answer:** B

**Source access:** Open archive member CS/CS2012.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Consider the virtual page reference string
             1, 2, 3, 2, 4, 1, 3, 2, 4, 1
        on a demand paged virtual memory system running on a computer system that has main memory
        size of 3 page frames which are initially empty. Let LRU, FIFO and OPTIMAL denote the number
        of page faults under the corresponding page replacement policy. Then
        (A) OPTIMAL < LRU < FIFO                                     (B) OPTIMAL < FIFO < LRU
        (C) OPTIMAL = LRU                                            (D) OPTIMAL = FIFO

## Solution

Number the ten references from 1. FIFO faults at positions 1, 2, 3, 5, 6, 8: six faults. LRU faults at 1, 2, 3, 5, 6, 7, 8, 9, 10: nine faults. Optimal replacement faults at 1, 2, 3, 5, 8: five faults; at reference 5 evict page 2, whose next use is later than those of 1 and 3, and at reference 8 evict page 3, which is never used again. Thus OPTIMAL=5 < FIFO=6 < LRU=9, B.

Worked check / additional reasoning: A hit updates recency in LRU but does not move a page in FIFO’s arrival order. This distinction first matters after reference 4, a hit on page 2: LRU remembers page 2 as recent, while FIFO still regards page 1 as the oldest arrival.
