

# GATE 2005: Q20 (printed CS Q20)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** With memory-mapped I/O and no separate privileged I/O opcodes, what enforces device-access protection? A OS routines alone; B hardware trap; C system configuration alone; D protection impossible.

## Solution

Map device registers into protected address ranges/pages and have the processor’s memory-protection hardware trap unauthorized user-mode loads or stores. Thus the immediate enforcement is a hardware trap, B, although the operating system configures the permissions and handles the exception. Ordinary unprivileged load/store opcodes do not bypass address protection.

Teaching detail:
Memory-mapped device registers occupy addresses just like memory. The OS configures access permissions, but hardware checks each user access and raises a protection exception if forbidden. This immediate trap prevents bypassing the OS merely by issuing a load/store instruction. A software routine alone cannot intercept an unchecked direct memory access, so B names enforcement, while configuration establishes policy.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** What is disk swap space for? A temporary HTML; B process data; C filesystem superblock; D device drivers.

## Solution

Swap space stores process memory contents that have been evicted from RAM and may later be paged back in. Thus saving process data, B, rather than caching HTML pages or storing filesystem superblocks.

Teaching detail:
A process may have memory pages that cannot all remain in physical RAM. Swap space provides backing storage for evicted process contents, allowing them to be brought back when needed. Thus B. It is distinct from a browser cache, filesystem metadata and the ordinary files holding drivers, even though all may reside on the same physical disk.

# GATE 2005: Q22 (printed CS Q22)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Why does increasing RAM typically help? A more virtual memory; B larger chips are intrinsically faster; C fewer page faults; D fewer segmentation faults.

## Solution

More physical memory can retain a larger working set, reducing expensive page faults and disk paging, C. Capacity does not inherently make memory chips faster, nor does it repair illegal accesses that cause segmentation faults. Improvement depends on the workload being memory-constrained.

Teaching detail:
When working sets exceed physical memory, pages are repeatedly fetched from much slower secondary storage. Additional RAM can hold more of those pages and reduce paging, hence C. It does not automatically enlarge the architecture’s virtual address width, accelerate each DRAM access, or make an illegal address valid. The performance benefit is workload-dependent rather than guaranteed for every program.

# GATE 2005: Q71 (printed CS Q71)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** n processes share m identical reusable units, acquired/released one at a time. Process i has positive maximum need s_i. Which is sufficient to avoid resource deadlock? A every s_i<m; B every s_i<n; C Σs_i<m+n; D Σs_i<m·n.

## Solution

If no process can finish, every process can hold at most s_i−1 units while still needing another unit. Thus at most sum(s_i−1)=sum(s_i)−n units can be held in an all-unfinished configuration. If sum(s_i)<m+n, this total is less than m, so at least one resource is free; allocating available units eventually lets a process reach its maximum and finish. Release its resources and repeat. Equivalently m>sum(s_i−1) guarantees progress for the single resource type. This is option C.

Teaching detail:
Suppose every unfinished process is blocked below its maximum claim. It can hold at most s_i−1 units, so together they can hold at mostΣ(s_i−1). If m exceeds that bound, some units remain available and can be allocated until at least one process finishes; its release only improves the position. Rearranging m>Σs_i−n gives option C. Individual small claims alone do not prevent circular waiting among multiple processes.

# GATE 2005: Q72 (printed CS Q72)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C, under intended address-printing semantics

**Paraphrased problem context:** Code: if(fork()==0){a=a+5;printf("%d,%d\n", a,&a);}else{a=a−5;printf("%d,%d\n", a,&a);}. Parent prints u, v and child x, y. A u=x+10, v=y; B u=x+10, v≠y; C u+10=x, v=y; D u+10=x, v≠y. Address formatting is reproduced literally and requires a portability qualification.

## Solution

Let a initially equal a 0. The child executes the zero-return branch and obtains x=a 0+5; the parent obtains u=a 0−5. Therefore u+10=x. fork preserves the virtual address of a, so its address has the same numeric value in each process even though the memory is logically separate: v=y. Hence C under the intended OS model. Strictly, the reproduced printf uses %d for &a; that variadic type mismatch is undefined behavior in ISO C, so literal portable-C output is not guaranteed. Using %p with (void *)&a expresses the intended comparison.

Teaching detail:
fork duplicates the address-space state. The child and parent modify separate copies starting from the same initial a 0: child a 0+5, parent a 0−5, hence a difference 10. Their virtual addresses retain equal numerical locations despite distinct physical memory. This supports C as the intended OS result. The actual %d address argument is type-incorrect; use %p and a void* cast to state the intended comparison in portable C.
