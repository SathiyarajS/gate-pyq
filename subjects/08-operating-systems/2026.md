**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=22).

**Paraphrased problem context:** Select the false statements: A Banker’s algorithm is deadlock prevention; B disallowing hold-and-wait prevents deadlock; C an assignment edge in a resource-allocation graph goes from process to resource; D a safe state permits every process to finish without deadlock.

**Type / marks:** MSQ, 1.

**Official answer:** A;C

**Derived answer:** A;C

## Solution

Givens and goal
Select the false statements: A Banker’s algorithm is deadlock prevention; B disallowing hold-and-wait prevents deadlock; C an assignment edge in a resource-allocation graph goes from process to resource; D a safe state permits every process to finish without deadlock.

Approach
Distinguish the standard algorithm categories, recall graph edge direction, and interpret safety as existence of a safe completion sequence.

Step-by-step solution
1. Deadlock prevention structurally rules out at least one necessary condition, such as hold-and-wait. Avoidance instead examines potential grants and declines those that would leave the system unsafe.
2. Banker’s algorithm is an avoidance algorithm: it checks whether a safe completion sequence remains after a proposed allocation. Calling it prevention in the standard technical taxonomy is false, so select A.
3. If no process may hold resources while waiting for more, the hold-and-wait condition cannot hold. Since that condition is necessary for resource deadlock, B is true and must not be selected.
4. A request edge goes process→resource; an assignment edge goes resource-instance→process to indicate ownership. C reverses assignment direction, so select C.
5. A safe state means there is an order in which each process can obtain its remaining declared maximum need, finish, and release resources for later processes. That establishes D in the conventional safe-allocation sense.
6. Therefore the false statements are A and C. “Safe” asserts a feasible completion sequence under controlled allocation, not that arbitrary future grants can never make the system unsafe.

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=24).

**Paraphrased problem context:** Five processes share k identical resource instances. Each process needs at most two, requests or releases only one at a time, and can request its second only after receiving its first. Find the smallest k guaranteeing freedom from resource deadlock.

**Type / marks:** NAT, 1.

**Official answer:** 6 to 6

**Derived answer:** 6

## Solution

Givens and goal
Five processes share k identical resource instances. Each process needs at most two, requests or releases only one at a time, and can request its second only after receiving its first. Find the smallest k guaranteeing freedom from resource deadlock.

Approach
Show an unsafe allocation for too few resources and prove that one additional resource always lets some process finish.

Step-by-step solution
1. With k=5, allocate one instance to each process. If all five then request a second, all five available instances are held and every process is waiting. No process can reach its maximum claim and finish: this is a possible deadlock.
2. Smaller positive capacities also fail to give a universal guarantee: the available instances can each be held by a different process waiting for its second, while the others wait for their first. Thus merely showing failure at five is consistent with the lower-capacity cases.
3. Now let k=6. If some process holds two instances, it has its complete maximum resource requirement and can finish without waiting for another instance, then release what it holds.
4. Otherwise each of the at most five processes holds at most one instance, so at most five are allocated. At least one of the six remains free. It can be granted as a second instance to a waiting holder, enabling that process to finish and release two.
5. Repeating the reasoning gives a safe sequence of completions, so a resource deadlock cannot arise. The smallest required capacity is 6.

This is the standard resource-deadlock model, assuming a process eventually completes when its maximum resource need is satisfied. It does not guarantee fair scheduling or rule out starvation caused by a scheduler.

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=42).

**Paraphrased problem context:** A cache is physically addressed. An MMU has a TLB, and eviction of a page invalidates that page’s cache blocks. Which sequences cannot occur for a reference: A TLB miss/page-table hit/cache hit; B TLB hit/page-table miss/cache hit; C TLB miss/page-table miss/cache hit; D TLB miss/page-table miss/cache miss?

**Type / marks:** MSQ, 2.

**Official answer:** B;C

**Derived answer:** B;C

## Solution

Givens and goal
A cache is physically addressed. An MMU has a TLB, and eviction of a page invalidates that page’s cache blocks. Which sequences cannot occur for a reference: A TLB miss/page-table hit/cache hit; B TLB hit/page-table miss/cache hit; C TLB miss/page-table miss/cache hit; D TLB miss/page-table miss/cache miss?

Approach
Distinguish a missing cached translation from a nonresident page, and apply the cache invalidation condition.

Step-by-step solution
1. Interpret a page-table miss here as a nonresident page (a page fault), not as a cache miss while fetching the page-table entry. The cache is physically addressed, so the ordinary sequence first resolves virtual-to-physical translation and then accesses the referenced cache block.
2. A TLB miss can occur even when the page is resident: the translation may simply not be cached in the TLB. After a successful page-table lookup the data block may still be present in the cache. Therefore A is possible.
3. In a correctly maintained translation system, a TLB hit supplies a valid resident-page translation, and a page-table walk is not needed for that reference. It cannot simultaneously be the page-table-fault sequence described in B. Thus B is impossible.
4. If the referenced page is absent from memory, the stated invalidation rule prevents its data blocks from remaining valid in the cache. Therefore the page-fault-plus-cache-hit sequence C is impossible. A TLB miss, page fault and absence of the data block from cache, as in D, is possible.

**Interpretation note:** These are hit/miss conditions for the original reference before fault recovery. Fault servicing can populate memory or cache and then retry the instruction; hits on that later retry are not the same event sequence. Correct TLB invalidation is implicit in a functioning virtual-memory system.

Possible-state examples help separate the two misses. A resident page whose translation has been displaced from the small TLB, but whose recently used data still sits in cache, gives A. A never-loaded virtual page gives a TLB miss and page fault; since it has no valid physical cached block, its initial data access is also a cache miss, matching D. “Page-table miss” is not being used to mean that the page-table entry itself missed in a processor cache.

**Paraphrased problem context:** In main, for i=0; i<3; i++, the program calls fork(). The child (fork()==0) executes continue; the parent executes break. After the loop each process executes printf("Hello!"). All forks succeed. Count executions of printf.

**Type / marks:** NAT, 2.

**Official answer:** 4 to 4

**Derived answer:** 4 to 4

## Solution

Givens and goal
In main, for i=0; i<3; i++, the program calls fork(). The child (fork()==0) executes continue; the parent executes break. After the loop each process executes printf("Hello!"). All forks succeed. Count executions of printf.

Approach
Trace which process continues the loop after each fork rather than assuming every process performs all three iterations.

Step-by-step solution
1. Begin with process P0 at i=0. It forks child P1. P0 receives a nonzero return value, skips the child branch, executes break, and prints once.
2. P1 receives zero and executes continue. In a for loop, continue proceeds to the increment i++, then tests the condition. Thus P1 reaches i=1 and forks P2. P1 then breaks and prints once; P2 continues.
3. P2 reaches i=2 and forks P3. P2 breaks and prints once. P3 continues to the increment, giving i=3, where i<3 is false. P3 exits the loop normally and prints once.
4. The process structure is a chain P0→P1→P2→P3, with exactly three successful forks and four processes. Every one reaches the single printf once, so the answer is 4.
5. The execution order of the four prints is scheduling-dependent, but the count is not. The usual 2^3=8 doubling applies only when both parent and child continue forking on later iterations; here each parent immediately leaves the loop. There is also no pre-fork buffered print in the snippet whose output could be duplicated.

**Paraphrased problem context:** Actuator processes A require 6 CPU seconds and arrive at times 10,20,30,40,50. Controller processes C require 8 seconds and arrive at 11,22,33,44,55. FCFS scheduling is nonpreemptive and the first A starts at 10. Find the average waiting time of all ten processes to one decimal place.

**Type / marks:** NAT, 2.

**Official answer:** 9.5 to 9.5

**Derived answer:** 9.5 to 9.5

## Solution

Givens and goal
Actuator processes A require 6 CPU seconds and arrive at times 10,20,30,40,50. Controller processes C require 8 seconds and arrive at 11,22,33,44,55. FCFS scheduling is nonpreemptive and the first A starts at 10. Find the average waiting time of all ten processes to one decimal place.

Approach
Merge arrivals chronologically and use start=max(arrival, previous finish), wait=start−arrival for each row.

Step-by-step solution
1. The chronological order is A1,C1,A2,C2,A3,C3,A4,C4,A5,C5. FCFS serves them in exactly this order, without preempting a current process when a new one arrives.
2. Compute starts and finishes sequentially. For A1, start=10, finish=16 and wait=0. C1 arrived at 11 but must wait until 16, so its wait is 5 and finish is 24. Continue the same recurrence:

    Process   Arrival   Burst   Start   Finish   Wait
    A1           10       6       10      16       0
    C1           11       8       16      24       5
    A2           20       6       24      30       4
    C2           22       8       30      38       8
    A3           30       6       38      44       8
    C3           33       8       44      52      11
    A4           40       6       52      58      12
    C4           44       8       58      66      14
    A5           50       6       66      72      16
    C5           55       8       72      80      17

3. Total waiting time is 0+5+4+8+8+11+12+14+16+17=95 seconds. Divide by ten processes to get 95/10=9.5 seconds.
4. Waiting time excludes the process’s own CPU burst. Using finish−arrival would give turnaround time instead. There is no idle gap after the first process starts: at each completion, the next process in the table has already arrived.

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** Which CPU scheduling algorithm cannot be preemptive under its standard definition? A SRTF; B FCFS; C Round Robin; D Priority.

## Solution

Givens and goal
Which CPU scheduling algorithm cannot be preemptive under its standard definition? A SRTF; B FCFS; C Round Robin; D Priority.

Approach
Distinguish the order of selecting ready jobs from taking the CPU away mid-burst.

Step-by-step solution
1. FCFS serves ready processes in order of arrival. Once selected, a process continues until it finishes its CPU burst or voluntarily blocks. Standard FCFS does not preempt that burst.
2. SRTF chooses the smallest remaining execution time. If a shorter job arrives, it may preempt the current job; this is the preemptive form of shortest-job scheduling.
3. Round Robin explicitly preempts when a time quantum expires and places an unfinished process back in the ready queue. Priority scheduling can be defined either with immediate higher-priority preemption or with selection only at release points.
4. Thus B is the intended answer. A hardware interrupt or a process blocking for I/O is not, by itself, evidence that the scheduler uses a preemptive FCFS policy.

**Paraphrased problem context:** Three processes each execute: wait(A); print(*); X=X+1; if X==2 then {print($); signal(B);}; signal(A); wait(B); print(#); signal(B). Binary semaphores start A=1,B=0 and shared X=0. Each line is atomic. Which outputs are possible? A **$*###; B **$#*##; C **$##*#; D ***$###.

## Solution

Givens and goal
Three processes each execute: wait(A); print(*); X=X+1; if X==2 then {print($); signal(B);}; signal(A); wait(B); print(#); signal(B). Binary semaphores start A=1,B=0 and shared X=0. Each line is atomic. Which outputs are possible? A **$*###; B **$#*##; C **$##*#; D ***$###.

Approach
Find invariant ordering constraints, then exhibit schedules achieving each candidate.

Step-by-step solution
1. A protects the star and increment section. The first entrant prints a star and changes X from 0 to 1. The second prints another star and changes X to 2, then prints $ before releasing A.
2. The third entrant cannot print its star until that release. Therefore the dollar must occur immediately after the second star among these star/dollar events, and ***$### is impossible. Preempting the second process before $ does not help: it still holds A.
3. B initially blocks all hash printing. It is first signaled only after the dollar; each process that prints a hash then signals B for another. Thus no hash can precede $, while each process’s own star must precede its hash.
4. For A, let the first two processes complete their A sections, then let the third complete its A section before allowing any hash sections. For B, after the first two A sections allow one of those processes to print a hash, then allow the third star, then the remaining hashes.
5. For C, let both first and second processes print their hashes after $, delaying the third A section until afterward. The third then prints its star followed by its hash. These realize all A,B,C exactly.
6. Therefore select A,B,C. The invariant and the explicit schedules together establish both impossibility and feasibility; a single simulated scheduling order would not suffice.

## Solution

Givens and goal
A 16 GB disk uses 2 KB blocks. A linked-list bookkeeping scheme stores 32-bit free-block numbers in list blocks, each also reserving one 4-byte next pointer. With K=2¹⁰,G=2³⁰, compute the number of list blocks under the intended capacity-to-record-all-disk-blocks convention; the current free count is not specified.

Approach
Compute entries per list block and round the required quotient upward.

Step-by-step solution
1. The disk has (16×2³⁰)/(2×2¹⁰)=2²³=8,388,608 blocks. A block number occupies 32/8=4 bytes.
2. Each list block holds 2048 bytes, but 4 are reserved for its successor pointer. The remaining 2044 bytes hold 2044/4=511 block numbers. Counting 512 would forget the link pointer.
3. The capacity calculation is ceil(8,388,608/511). Since 511×16,416=8,388,576, those blocks fall short by 32 entries; one additional block is required. Thus the answer is 16,417.
4. This preserves the official result under the full-disk bookkeeping-capacity convention. If the actual free count is F, the needed entry capacity is ceil(F/511), so an arbitrary partially occupied disk is not determined by the stated disk size alone.
5. If list-storage blocks themselves are excluded from the free-block population on the same disk, a different self-consistent accounting model applies. The official value should therefore not be presented as a universal current free-space measurement. The unspecified free count and accounting convention remain explicit qualifications.

Givens and goal
A TLB reaches 1 MB with 4 KB pages. Virtual space is 64 GB and physical space 1 GB. Each entry stores a 4-bit process ID, virtual page number, physical frame number, and 2 control bits. Find the TLB size in bytes, with binary K,M,G.

Approach
Find entry count and entry width independently, then multiply.

Step-by-step solution

4. One entry contains 4+24+18+2=48 bits, or 6 bytes. Total storage is 256×6=1536 bytes.
5. The page offset is not stored as part of a translation entry because it passes through unchanged. This answer includes exactly the specified fields and assumes no unmentioned padding, replacement information, or other implementation metadata.
