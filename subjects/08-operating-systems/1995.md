

# GATE 1995: Q7 (printed A Q1.7)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A: the segment table can be too large for one page

**Essential problem context (paraphrased):** Why might a paged-segmented memory scheme give the segment table itself a page table?

## Solution

A large segment table can span multiple pages. Paging that table lets its pieces be placed in separate physical frames and, where supported, brought in on demand. A page table is then needed to translate addresses of the segment-table pages themselves. This is distinct from the page tables belonging to individual program segments. The wording “must” is architecture dependent: a small segment table or an architecture requiring contiguous resident tables need not use this extra paging level. A describes the motivation within the assumed paged-table design.

# GATE 1995: Q8 (printed A Q1.8)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: FIFO

**Essential problem context (paraphrased):** Which replacement policy can have more page faults after increasing the frame count: OPT, LRU, FIFO, or OPT and FIFO?

## Solution

FIFO removes the page that has been resident longest, independent of recent use or future demand. Its resident sets with different frame counts need not be nested, so adding a frame can alter the eviction order disadvantageously. The classic string 1,2,3,4,1,2,5,1,2,3,4,5 gives nine FIFO faults with three frames and ten with four. LRU and OPT have the stack-inclusion property and do not suffer this anomaly. Therefore C is the correct policy.

# GATE 1995: Q15 (printed A Q1.15)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B: round robin

**Essential problem context (paraphrased):** Which policy is most suitable for a time-shared OS: shortest job first, round robin, FCFS or elevator?

## Solution

Round robin gives each ready process a bounded time slice and cycles through the queue. This prevents one long CPU-bound job from monopolizing the processor and supports responsive interactive use. FCFS can make short interactive requests wait behind a long job. SJF requires burst predictions and can disadvantage long jobs; elevator is chiefly a disk-head scheduling rule. Round robin is therefore the standard choice here, with quantum size balancing response time against context-switch overhead.

## Solution

Treating addresses as the stated decimal record numbers, integer division by 100 gives pages 1,2,4,4,5,5,5,1,2,2,2,3,3. With just one frame, a fault occurs on the first reference and each change of page. The seven consecutive runs are 1 | 2 | 4,4 | 5,5,5 | 1 | 2,2,2 | 3,3. Thus there are seven faults. Leading zeros are address formatting here, not C octal literals; interpreting them as octal would be incompatible with the printed digit 9.

# GATE 1995: Q41 (printed A Q2.16)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=4), physical page 4. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C under the textbook larger-than-RAM/smaller-than-backing-store model; no universal “must”

**Essential problem context (paraphrased):** Must the CPU-addressable virtual space be smaller or larger than physical memory and secondary storage?

## Solution

Virtual memory commonly lets a process use an address space larger than the currently installed RAM, with inactive pages backed by secondary storage. Under a simple fully backed textbook model, this motivates larger than physical memory and smaller than backing storage, choice C. But address-bit width defines a possible address space, not a promise that every possible address is allocated or backed simultaneously. Sparse mappings, demand-zero pages and reservation policies break the claimed universal inequality. Thus the word “must” is too strong without the fully allocated/backed model, and actual capacity ratios are architecture and configuration dependent.

**Independently derived answer:** First fit admits all jobs; best fit cannot admit J6.

**Essential problem context (paraphrased):** 1000K of contiguous free memory receives J1=200K, J2=350K, J3=300K; J1 finishes; then J4=120K, J5=150K and J6=80K arrive, in that order. Assume allocations start at the low-address end of a selected hole, free holes coalesce, no compaction and first fit searches from the lowest address. Draw both memory allocation sequences.

## Solution

Use half-open address intervals in K so that [0,200) has size 200. Both algorithms initially allocate J1=[0,200), J2=[200,550), J3=[550,850), leaving [850,1000) free. When J1 finishes, the holes are [0,200) and [850,1000).

First fit: J4 takes [0,120), leaving holes [120,200) of size 80 and [850,1000) of size 150. J5 cannot fit in 80, so it occupies [850,1000). J6 then exactly fills [120,200). Final low-to-high layout is J4:120 | J6:80 | J2:350 | J3:300 | J5:150.

Best fit: J4 takes the smaller adequate hole [850,1000), occupying [850,970) and leaving 30K. J5 takes [0,150), leaving [150,200) of size 50. J6 needs 80K but neither the 50K nor 30K hole suffices. Final layout is J5:150 | free:50 | J2:350 | J3:300 | J4:120 | free:30, with J6 waiting.

The total free space is 80K, equal to J6’s request, but it is split into nonadjacent holes. This is external fragmentation, not a shortage of aggregate space.

# GATE 1995: Q55 (printed A Q5(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** First fit.

**Essential problem context (paraphrased):** 1000K of contiguous free memory receives J1=200K, J2=350K, J3=300K; J1 finishes; then J4=120K, J5=150K and J6=80K arrive, in that order. Assume allocations start at the low-address end of a selected hole, free holes coalesce, no compaction and first fit searches from the lowest address. Which policy performs better for this sequence?

## Solution

First fit places the 120K job in the initial 200K hole, preserving an 80K remainder. It then puts the 150K job in the separate 150K hole and admits the final 80K job into the exact remainder. Consequently every arriving job is resident at the end, filling all 1000K.

Best fit uses the 150K hole for the 120K request, leaving 30K. The later 150K request takes 150K out of the 200K hole, leaving 50K. Although 50+30=80, the final 80K request requires one contiguous region and cannot be admitted without relocation or compaction. First fit therefore performs better on the stated admission/utilization criterion. This trace is a counterexample to the intuition that the locally smallest leftover always leads to the best future allocation. It is not a proof that first fit dominates best fit for every workload.

**Essential problem context (paraphrased):** Draw the precedence graph of nine concurrent branches (separated here by |): S1;V(a);V(b) | P(a);S2;V(c);V(d) | P(c);S4;V(e) | P(d);S5;V(f) | P(e);P(f);S7;V(k) | P(b);S3;V(g);V(h) | P(g);S6;V(i) | P(h);P(i);S8;V(j) | P(j);P(k);S9. All variables a through k are semaphores. This is the GFG version. GateForum instead has V(c) after S4 and P(j);P(j);P(k) before S9. Initial semaphore values are not explicitly supplied; state the synchronization assumption.

## Solution

Assume the usual precedence convention: every semaphore initially equals zero, P waits for and consumes one signal, and V supplies one signal. Initialization is essential: positive initial tokens would allow some statements to run before their supposed predecessors. With initially-zero semaphores, map each signal after a statement to the wait before another statement.

The labeled dependency edges are S1−a→S2, S1−b→S3; S2−c→S4, S2−d→S5; S4−e→S7, S5−f→S7; S3−g→S6, S3−h→S8; S6−i→S8; S8−j→S9 and S7−k→S9. This edge list is a complete exact specification of the requested graph. To draw it, put S1 at the top, S2 and S3 below it, S4/S5 below S2, S6 below S3, S7 below S4/S5, S8 below S6, and S9 below S7/S8; include the additional direct S3→S8 edge. That direct edge is transitively redundant because S3→S6→S8 already holds, but faithfully represents semaphore h.

S7 is a join: it cannot execute until both S4 and S5 have completed. Similarly S8 waits for both signals from S3 and S6, and S9 joins the two sides. Statements on different sides need not execute in a fixed order.

Do not apply this successful graph silently to the GateForum text. Its V(c) after S4 supplies no e token, so S7 is permanently blocked at P(e). Its final branch also waits twice on j, although S8 signals j only once, so S9 blocks at its second P(j), even independently of the missing k signal. Under fair execution, S1,S2,S3,S4,S5,S6,S8 may finish; S7 and S9 do not. GFG provides a coherent alternate reproduction, not proof of original official wording.

# GATE 1995: Q79 (printed B Q20)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** FCFS:204 tracks. SSTF:85 tracks. SSTF saves119 tracks.

**Essential problem context (paraphrased):** A disk has tracks 0–99. Its head is at track55, and the pending FIFO queue is 10,70,75,23,65. Calculate total head movement for FCFS and SSTF and say which is smaller.

## Solution

Head movement is the sum of absolute differences between consecutive serviced track numbers, including the initial position. FCFS must preserve arrival order: 55→10→70→75→23→65. Its successive movements are 45,60,5,52,42, totaling 204 tracks.

SSTF repeatedly chooses the nearest pending request from the current position, not the request nearest the original position. From55 the distances to10,70,75,23,65 are45,15,20,32,10, so choose65. From65 choose70 (distance5), then75 (distance5). Of the remaining tracks23 and10, track23 is52 away and10 is65 away, so service23 then10. Thus the route is55→65→70→75→23→10, and the total is10+5+5+52+13=85. There are no distance ties in this instance.

SSTF therefore requires119 fewer track movements, assuming seek effort is being compared by track distance. Neither algorithm requires a sweep to track0 or99; that would be a different scheduling policy. No return to the starting track is requested. The conclusion concerns this finite queue, not a claim that SSTF prevents starvation or always optimizes every possible workload.
