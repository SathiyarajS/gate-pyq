**Paraphrased problem context:** Which are shared by all threads of one process? I:program counter. II:stack. III:address space. IV:registers. A:I and II. B:III only. C:IV only. D:III and IV.

## Solution

1. Threads belong to one process and operate in its common virtual address space, including code, global data and heap. Thus III is shared.

2. Each thread may be executing a different instruction, so it needs its own program counter and saved register values. Sharing one program counter or register context would prevent independent execution.

3. Each thread also needs its own call stack for local variables, return addresses and nested calls. Although another thread may access that stack through an address in the shared memory, the execution stack is still distinct. Hence only III is correct, B.

**Paraphrased problem context:** Which file-allocation schemes avoid external fragmentation? I:contiguous. II:linked. III:indexed. A:I and III. B:II only. C:III only. D:II and III.

## Solution

1. External fragmentation means sufficient total free space may exist but be split into separate regions, so a request needing one contiguous run cannot fit. Contiguous file allocation has this problem.

2. Linked allocation connects a file's blocks by pointers, so successive blocks can occupy arbitrary free block positions. Indexed allocation instead keeps their addresses in an index structure and likewise allows scattered blocks.

3. Both II and III avoid requiring one contiguous extent, giving D. This does not assert that every allocated block is completely used: an incompletely filled last block can still cause internal fragmentation, which is a different phenomenon.

**Paraphrased problem context:** A system has 9 tape drives. Processes (current allocation,maximum requirement) are P1:(3,7), P2:(1,6), P3:(3,5). Classify the state. A:safe,deadlocked. B:safe,not deadlocked. C:not safe,deadlocked. D:not safe,not deadlocked.

## Solution

1. Current allocations total 3+1+3=7, leaving 9-7=2 drives available. Remaining maximum needs are P1:7-3=4, P2:6-1=5, P3:5-3=2.

2. P3 can receive its remaining two drives and finish. It then returns all five drives, leaving five available to the other processes. Equivalently, in the safety simulation add its existing allocation 3 to the current available count 2.

3. Now P1 can finish and release its three previously allocated drives, raising available to 8; P2 can then finish. Thus P3,P1,P2 is a safe sequence (P3,P2,P1 also works). Existence of a safe sequence establishes safe and not deadlocked, B. The visually checked maximum for P3 is 5, not 6.

**Paraphrased problem context:** Threads of one process share: A globals but not heap; B heap but not globals; C neither globals nor heap; D both globals and heap.

## Solution

1. Threads are separate execution streams inside the same process address space. Globals live in that shared address space.

2. Heap allocations also belong to the process address space; one thread can pass an allocated object’s address to another. Sharing does not itself make unsynchronized updates safe.

3. Each thread instead has its own execution state, such as registers and program counter, and normally its own stack. Hence both heap and globals are shared, D.

**Paraphrased problem context:** A program has x threads and y non-reentrant locks. A thread cannot reacquire a lock it holds, and blocks if acquisition fails. Find minimum x,y allowing deadlock. A (1,2); B (2,1); C (2,2); D (1,1).

## Solution

1. Consider a single thread and one initially free non-reentrant lock L. The thread acquires L successfully.

2. Before releasing L, let the same thread request L again. The non-reentrancy rule blocks it because L is already held, even though the holder is itself.

3. Only this blocked thread could release L, so it cannot progress: self-deadlock. At least one thread and one lock are needed to discuss this failure, and this example achieves both minima. Answer D.

**Paraphrased problem context:** Belady’s anomaly means page faults may increase when allocated frames increase. S1 random replacement suffers from it; S2 LRU suffers from it. A both true; B S1 true,S2 false; C S1 false,S2 true; D both false.

## Solution

1. For LRU, order all pages by recency after each reference. The k-frame cache contains the k most recent distinct pages; those pages are included in the first k+1 pages of that same order.

2. This stack inclusion means a reference hitting with k frames cannot miss with k+1. Increasing LRU capacity therefore never increases faults for a fixed reference string, so S2 is false.

3. Random replacement has no such nested-set guarantee: its eviction choices can retain different useful pages, and an adverse larger-cache realization may fault more. S1 is interpreted as possibility, not inevitability or a claim about every run. Hence B.

**Paraphrased problem context:** Transactions receive unique Lamport timestamps. T1 holds resource R; T2 requests a conflicting lock. If TS(T2)<TS(T1), kill T1; otherwise T2 waits. Killed transactions restart with the same timestamp; any transaction not killed eventually terminates. A both deadlock-free and starvation-free; B deadlock-free only; C starvation-free only; D neither.

## Solution

1. Smaller timestamps denote older transactions. An older requester wounds a younger holder; a younger requester waits rather than aborting the older holder. This is wound-wait.

2. Every actual waiting edge points from a younger transaction to an older one, so timestamps strictly decrease along waits. A directed cycle would require returning to the original timestamp after strict decreases, impossible. Hence no deadlock.

3. A restarted transaction keeps its old timestamp, so it does not repeatedly become youngest. With the stated eventual-termination assumption and finitely many older predecessors, those predecessors finish and it ultimately becomes able to proceed. This is the intended starvation-free guarantee, A.
