**Question:** [Official archived paper page 4](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Official answer:** B

**Derived answer:** B

**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

Threads of one process share its address space. Each thread has its own execution context, including program counter, registers and stack. Thus III only, B. Another thread can access a stack through shared memory, but that does not make it the same execution stack.

**Official answer:** D

**Derived answer:** D

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

## Solution

One thread can acquire a non-reentrant lock and attempt to acquire that same lock again before release. It blocks waiting on a lock only it can release, producing self-deadlock. One thread and one lock suffice, and neither count can be zero. Thus D.

# GATE 2017 CS1: Q50 (printed CS Q40)

**Question:** [Official archived paper page 18](https://web.archive.org/web/20170712112248id_/http://www.gate.iitg.ac.in:80/2017questions/CS1.pdf#page=18); consult original wording, diagrams and choices.

**Official answer:** B

**Derived answer:** B

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

## Solution

LRU has the stack property: the pages held with k frames are contained in those held with k+1 frames, so extra frames cannot increase faults on the same reference string. Random replacement lacks that containment and can realize adverse replacement sequences with more faults for a larger allocation. Thus S1 true, S2 false, B; this refers to possible realizations, not a promise about every random run.

# GATE 2017 CS1: Q52 (printed CS Q42)

**Question:** [Official archived paper page 19](https://web.archive.org/web/20170712112248id_/http://www.gate.iitg.ac.in:80/2017questions/CS1.pdf#page=19); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Source access:** Archived July2017 original official paper and key. Page numbers refer to the paper PDF; key is a separate two-page PDF.

## Solution

This is wound-wait: an older requester aborts the younger holder; a younger requester waits for the older holder. Every wait edge goes from younger to older, precluding a directed cycle and hence deadlock. Retaining the original timestamp after restart prevents a transaction from continually becoming youngest. With eventual scheduling/completion and finitely many older transactions, those older transactions finish and the transaction eventually proceeds, yielding the intended starvation-free result A.
