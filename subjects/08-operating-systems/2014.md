**Type / marks:** MCQ, 2 mark(s).

**Official answer:** C

**Derived answer:** C

**Source access:** Open archive member CS/CS2014.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

If the consumer acquires s while n=0, it blocks on n while retaining s. The producer needs s before adding an item and signaling n, so neither can proceed. That is the deadlock in C. Correct ordering is to wait for n before acquiring the buffer mutex; inventing an initial item by setting n=1 is not a valid repair.

# GATE 2014 CS2: Q43 (printed CS Q33)

**Question:** [Official archived paper page 38](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** D

**Derived answer:** Official D needs initially reclaimable frames; literal initial occupancy makes no listed policy optimal

**Source access:** Open archive member CS/CS2014.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

MRU is often optimal for cyclic scans larger than memory when frames initially fill with the scan’s pages. Here all20 frames already contain irrelevant101–120. Literal MRU evicts one old page for1, then evicts the newly referenced1 for2, and so on, retaining19 irrelevant pages forever. Every requested page therefore faults. LIFO likewise keeps19 irrelevant pages; LRU/FIFO also fault on every pass because the cycle exceeds20 frames. OPT discards the never-used initial pages and retains useful pages for later passes: for three total passes an explicit farthest-future simulation gives 260 faults instead of 300. Even simply preserving19 useful pages across passes beats all-fault behavior. Official D requires treating the initial frames as free/reclaimable before MRU, a missing convention.
