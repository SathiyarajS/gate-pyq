

# GATE 2000: Q20 (printed A Q1.20)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Essential problem context (paraphrased):** Which need not necessarily be saved: general-purpose registers, the TLB, the program counter, or all of these?

## Solution

Step 1: The process’s program counter and live architectural registers determine where and how it resumes; their values must be preserved by the switching mechanism.

Step 2: A TLB is a cache of translations also represented in page tables. It may be invalidated and refilled, or entries may remain with address-space identifiers, without saving its entire contents in the process context.

Therefore B. Losing cached translations can hurt performance but does not inherently lose the process’s architectural execution state.

# GATE 2000: Q21 (printed A Q1.21)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=3), physical page 3. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Essential problem context (paraphrased):** Processes P[0]…P[4] use mutexes m[0]…m[4]. Each waits on m[i], then m[(i+1) mod4], before releasing them. Can this cause thrashing, deadlock, starvation without deadlock, or none?

## Solution

Step 1: Schedule P0,P1,P2,P3 so each acquires its first mutex before any attempts the second. They now hold m0,m1,m2,m3 respectively.

Step 2: P0 waits for m1, P1 for m2, P2 for m3, and P3 for m0. Each resource is held by the next blocked process, creating a circular wait.

Thus deadlock is possible, B. The printed modulus is 4 even though five processes/mutexes are named; the four-process cycle already proves the result without silently changing it to 5. P4 does not remove this cycle.

**Essential problem context (paraphrased):** Memory access takes 1 μs, average page-fault service 10 ms, and hit ratio is 99.99%. Choose effective time from 1.9999 ms,1 ms,9.999 μs,1.9999 μs.

## Solution

Step 1: Convert 10 ms to 10,000 μs and use fault probability 1−0.9999=0.0001.

Step 2: If the fault-case time is the stated total service, expected time is 0.9999·1+0.0001·10,000=0.9999+1=1.9999 μs, D.

If “service” excludes the final retried access, add another 0.0001 μs to obtain 2 μs. This tiny convention difference is explicit; neither interpretation gives a millisecond-scale average.

# GATE 2000: Q46 (printed A Q2.23)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Essential problem context (paraphrased):** Which is not a valid general prevention policy: release all before requesting a new resource; request only in increasing resource-number order; never request after releasing any resource; acquire all required resources before execution?

## Solution

Step 1: Releasing all held resources before a new request removes hold-and-wait. A global increasing order removes circular wait. Atomic acquisition of the full required set before running also avoids partial hold-and-wait.

Step 2: Merely forbidding requests after the first release does not prevent deadlock during the initial acquisition phase. Process P can hold A and request B while Q holds B and requests A; neither has released anything, so both obey that rule.

Thus C is insufficient. The prevention interpretation presumes the usual nonreentrant-resource model and an all-or-nothing initial acquisition policy in the last option.

# GATE 2000: Q88 (printed B Q20(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** (1) signal(mutex); (2) signal(mutex); (3) R>0 || W!=0.

**Essential problem context (paraphrased):** R=W=0, binary semaphore mutex=1. Reader acquires mutex, and if W==0 increments R then executes box 1; otherwise executes box 2 and retries. After reading it acquires mutex, decrements R and releases mutex. Writer acquires mutex; if box 3 is true it releases mutex and retries; otherwise it sets W=1, releases mutex, writes, then acquires mutex, sets W=0 and releases mutex. Fill boxes 1,2,3.

## Solution

The complete intended protocol is:
Reader() {
L1: wait(mutex);
  if (W == 0) {
    R = R + 1;
    signal(mutex);                 // box 1
  } else {
    signal(mutex);                 // box 2
    goto L1;
  }
  /* read shared data */
  wait(mutex);
  R = R - 1;
  signal(mutex);
}
Writer() {
L2: wait(mutex);
  if (R > 0 || W != 0) {           // box 3
    signal(mutex);
    goto L2;
  }
  W = 1;
  signal(mutex);
  /* write shared data */
  wait(mutex);
  W = 0;
  signal(mutex);
}
wait/signal must implement a genuine atomic binary semaphore with appropriate memory visibility. Merely reading and writing an ordinary flag is not a substitute. All tests and updates of R,W occur under mutex, so checking admission and registering the admitted reader/writer are atomic relative to competitors. A writer enters only when no reader and no writer is active, and W=1 prevents later admissions until it finishes. Multiple readers are allowed while W=0. Both reader branches must release mutex; retaining it would block exits or retries and can deadlock. The mutex protects admission bookkeeping, not the whole read/write operation; R and W reserve access while mutex is released. Safety holds, but fairness is not guaranteed.

# GATE 2000: Q89 (printed B Q20(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Yes. Waiting writers do not prevent new readers from entering.

**Essential problem context (paraphrased):** R=W=0, binary semaphore mutex=1. Reader acquires mutex, and if W==0 increments R then executes box 1; otherwise executes box 2 and retries. After reading it acquires mutex, decrements R and releases mutex. Writer acquires mutex; if box 3 is true it releases mutex and retries; otherwise it sets W=1, releases mutex, writes, then acquires mutex, sets W=0 and releases mutex. With correct boxes, can writers starve?

## Solution

Consider two streams of readers whose reading intervals overlap. Before the last current reader exits, a new reader acquires mutex, observes W=0, increments R and begins reading. Arrange this repeatedly so R never becomes 0. A waiting writer may acquire mutex infinitely often, but each time it finds R>0, releases mutex and retries. It therefore never reaches W=1, even though every individual read finishes. A pending writer is not recorded anywhere: W means an active writer, not a waiting writer. Consequently new readers remain admissible throughout this schedule. This is starvation, not deadlock, since readers keep making progress. Even fairness in acquiring the bookkeeping semaphore would not repair this example because the writer gets turns and still cannot enter. Avoiding it requires a different admission policy, for example recording waiting writers and refusing new readers while a writer waits, together with suitable queue fairness; that change is outside the requested three boxes.
