

# GATE 2003: Q1 (printed CS Q1)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** For large positive integer y, what does this C function approximate?
float f(float x, int y) { float p, s; int i; for(s=1,p=1,i=1; i<y; i++){p*=x/i; s+=p;} return s; }
A. x^y; B. e^x; C. ln(1+x); D. x^x.

## Solution

1. The recurrence for p is p₀=1 and pᵢ=pᵢ₋₁x/i. Induction gives pᵢ=xⁱ/i!. The accumulator includes the initial term 1, so it contains exactly y terms, not y+1. Comparing with the Taylor expansion eˣ=1+x+x²/2!+⋯ identifies the limit.

2. Initially p=1 and s=1. On iteration i, p is multiplied by x/i, so it becomes x^i/i!, which is added to s. The returned value is the truncated series sum from i=0 to y−1 of x^i/i!, approaching e^x for fixed x as y increases. Thus B in the mathematical arithmetic model; finite floating-point range/roundoff can limit the actual approximation.

# GATE 2003: Q2 (printed CS Q2)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Given int *A[10], B[10][10]; consider I. A[2], II. A[2][3], III. B[1], IV. B[2][3]. Which expressions can be left-hand sides of assignments without compile-time errors, assuming type-compatible right-hand sides? A. I, II and IV only; B. II, III and IV only; C. II and IV only; D. IV only.

## Solution

1. Resolve the declarations before considering assignment: A[i] has type int*, while B[i] has array type int[10]. Applying another subscript dereferences an element and yields int in either case. Arrays are not modifiable lvalues, but pointer objects and int objects are. No actual dereference safety can be inferred from these declarations alone.

2. A is an array of 10 pointers to int. A[2] is an assignable pointer object, and A[2][3] is an assignable int lvalue if the pointer identifies suitable storage. B[2][3] is likewise an int lvalue. B[1] is an array row and cannot be assigned as a whole in C. Thus I,II,IV, option A, with type-compatible right-hand sides; compile-time validity does not establish safe runtime initialization.

# GATE 2003: Q88 (printed CS Q88)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=13), physical page 13. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** In this C fragment j,k,n,TwoLog_n are integers, A is an integer array and n≥3. GFG defines TwoLog_n=2 floor(log2 n); GateForum instead uses 2 ceil(log2 n).
for(k=3;k<=n;k++) A[k]=0;
for(k=2;k<=TwoLog_n;k++)
  for(j=k+1;j<=n;j++)
    A[j]=A[j] || (j%k);
for(j=3;j<=n;j++)
  if(!A[j]) printf("%d ",j);
What set is printed?
A. {m:m≤n and m=i! for some integer i}
B. {m:m≤n and m=i² for some integer i}
C. {m:m≤n and m is prime}
D. ∅

## Solution

1. Logical OR leaves A[j]=0 only if every tested remainder j%k is zero. A nonzero remainder permanently sets the entry to 1. This is divisibility by every tested k, not primality testing.
2. Let L=TwoLog_n. For 3≤j≤L+1, the iteration k=j−1 is performed and leaves remainder 1, so none of those j prints.
3. For j>L+1, all k=2,...,L are tested. A printed j would therefore have to be a multiple of M=lcm(1,...,L). The useful bound M≥2^(L−1) follows because each binomial coefficient C(L−1,k) divides M/L, so summing the L coefficients gives 2^(L−1)≤M.
4. With r=floor(log2 n) and L=2r, for n≥4 we have r≥2, hence M≥2^(2r−1)≥2^(r+1)>n. No positive multiple can lie in the printing range. For n=3, k=2 marks 3 directly.
5. Nothing prints, D. The ceiling variant has at least the same tests, so also cannot print anything.

Baseline derivation and caveats (retained): A[j] becomes true as soon as one tested k does not divide j; this is not a sieve that marks multiples. Let L be the outer-loop limit. If 3≤j≤L+1, the tested k=j−1 leaves remainder one, so j is not printed. For j>L+1, printing requires j to be divisible by every integer from 2 through L, hence by lcm(1,…,L). In the GFG floor version let r=floor(log2 n), L=2r. For n≥4, the standard bound lcm(1,…,L)≥2^(L−1)=2^(2r−1)≥2^(r+1)>n rules this out. The n=3 case is directly marked by k=2. Thus nothing is printed, D. The GateForum ceiling version tests at least as many divisors and reaches the same empty output. The LCM bound can also be established from the fact that every binomial coefficient in row L−1 divides lcm(1,…,L)/L, whose row sum is 2^(L−1).

# GATE 2003: Q89 (printed CS Q89)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=13), physical page 13. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Consider this C-style program (print emits its integer argument followed by a space):
int x;
void Q(int z) { z+=x; print(z); }
void P(int *y) {
  int x=*y+2;
  Q(x);
  *y=x-1;
  print(x);
}
main(void) { x=5; P(&x); print(x); }
What output is produced?
A. 12 7 6  B. 22 12 11  C. 14 6 6  D. 7 6 6

## Solution

1. main sets the global x to 5 and passes its address, so y inside P points to that global object.
2. P declares a different, local x and initializes it to *y+2=5+2=7. Calling Q(x) copies 7 into Q's parameter z.
3. Q has no local x, so its x denotes the global, still 5. z becomes 7+5=12 and Q prints 12; this does not alter either x.
4. Back in P, *y=x−1 uses local x=7 on the right and writes 6 to the global through y. P prints its unchanged local 7.
5. main finally prints global x=6, producing 12 7 6, A. Passing the pointer allows the global update despite P's name shadowing.

Baseline derivation and caveats (retained): main sets global x=5 and passes its address to P. P's local x becomes *y+2=7 and shadows the global only inside P. Q receives z=7; its unqualified x is the global 5, so z becomes 12 and Q prints 12. Returning to P, *y=x−1 writes 6 to the global, but P's local remains 7 and is printed. Finally main prints the global 6. The output is 12 7 6, A.
