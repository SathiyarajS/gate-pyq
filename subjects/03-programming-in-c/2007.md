**Independently derived answer:** floor(log2 n)+2 including the final failed test; no exact listed option

**Paraphrased problem context:** Consider the C fragment:
int j, n;
j = 1;
while (j <= n)
    j = j * 2;
For n>0, how many comparisons are made during execution? The printed choices are below; note the distinction between successful comparisons and the final failing test.
Options:
(A) ceil(log₂ n)+1
(B) n
(C) ceil(log₂ n)
(D) floor(log₂ n)+1

## Solution

1. Approach. Let k=floor(log₂ n). The successful tests use j=2^0 through 2^k. Then the loop tests 2^(k+1) once and fails. Check n=1 as a quick boundary example: two tests, one iteration.

2. Derivation and interpretation. Assume n is supplied positive and arithmetic does not overflow. The loop condition is tested with j=1,2,4,...,2^floor(log2 n), all successful, then once more at 2^(floor(log2 n)+1), which fails. Thus body executions and successful comparisons number floor(log2 n)+1, but all comparisons number floor(log2 n)+2. Option D counts successful tests/body executions only. The fragment declares n without assigning it; the question’s n>0 premise must supply its value, and literal fixed-width C may also overflow for large n. No official key is inferred.

**Independently derived answer:** D

**Paraphrased problem context:** What is f(5) for the following C function?
int f(int n) {
    static int r=0;
    if(n<=0) return 1;
    if(n>3) { r=n; return f(n-2)+2; }
    return f(n-1)+r;
}
Options:
(A) 5
(B) 7
(C) 9
(D) 18

## Solution

1. Approach. The static r is one persistent shared object, not a fresh zero-initialized local for each recursive call. Record the single assignment r=5 before unwinding the recursion.

2. Derivation and interpretation. The static variable r is shared by all activations. In f(5), r becomes 5, and the return expression is f(3)+2. Calls f(3), f(2), and f(1) each recurse with n−1 and add the unchanged r=5. The base f(0)=1. Hence f(1)=6, f(2)=11, f(3)=16, and f(5)=18 (D). No smaller activation changes r, so operand evaluation order does not affect this particular call.
