**Source access:** Open archive member CS/CS2-2017.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

## Solution

Array subscripting is commutative: 2[p]=p[2] is T and 6[p]=p[6] is I. In ASCII, T−I−1=84−73−1=10, so the intended pointer is c+10, pointing to the suffix17 of GATECSIT2017; its length is 2. However the printed expression c+2[p]-6[p]-1 is left-associative. Its first pointer operation forms c+84, outside the 13-byte string object containing12 characters and its null terminator, before subtracting back. Strict C makes that out-of-bounds pointer arithmetic undefined even though the intended final offset is valid. The answer 2 also assumes a character encoding with the stated T/I difference. Writing c+(2[p]-6[p]-1) would avoid this intermediate-pointer problem under that encoding.

The memory-leak analysis assumes these routine declaration issues are repaired.
