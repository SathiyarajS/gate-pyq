**Type / marks:** MCQ, 2 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** What happens in this ANSI C program? #include <stdio.h>
int main(void){ int i,j,count; count=0; i=0; for(j=-3;j<=3;j++){ if((j>=0)&&(i++)) count=count+j; } count=count+i; printf("%d",count); return 0; }
A fails compilation; B compiles and prints 10; C compiles and prints 8; D compiles and prints 13.

## Solution

For j=−3,−2,−1 the left operand of && is false, so i++ is not evaluated. At j=0 the old i=0 makes the condition false, but increments i to 1. At j=1, 2, 3 the old i is nonzero, adding 1+2+3=6 while i reaches 4. The final addition gives count=6+4=10. Thus B. Short-circuiting and postincrement order are defined by C.

A compact trace (j, i after condition, count after body) is (−3,0,0),(−2,0,0),(−1,0,0),(0,1,0),(1,2,1),(2,3,3),(3,4,6). Postincrement yields the old value as the expression result, then changes i. The logical AND operator sequences and short-circuits its operands, so the first three iterations do not increment i at all. The final statement adds the final i=4 once, obtaining 10 without undefined unsequenced modifications.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 1023 to 1023

**Derived answer:** 1023

**Paraphrased problem context:** ANSI C function: int SimpleFunction(int Y[],int n,int x){int total=Y[0],loopIndex; for(loopIndex=1;loopIndex<=n-1;loopIndex++) total=x*total+Y[loopIndex]; return total;} Array Z has ten elements, all equal to 1. Find SimpleFunction(Z,10,2).

## Solution

The loop performs Horner evaluation. Starting at total=1, each of the nine iterations replaces total by 2*total+1. After k iterations total=2^(k+1)-1, so after nine iterations the result is 2^10-1=1023. All intermediate results are within even the minimum standard signed-int range.

The values after initialization and each iteration are 1,3,7,15,31,63,127,255,511,1023. An induction proves total after k loop iterations is 2^(k+1)−1: base k=0 is 1, and 2(2^(k+1)−1)+1=2^(k+2)−1. More generally the function evaluates Y[0]x^(n−1)+Y[1]x^(n−2)+...+Y[n−1] in n−1 multiplications, which is Horner's method.

**Official answer:** C

**Derived answer:** C under intended flattening; undefined in strict C

**Paraphrased problem context:** ANSI C declares int arr[4][5] and initializes arr[i][j]=10*i+j for 0≤i<4,0≤j<5. It prints *(arr[1]+9) with %d. Offered outputs: A 14; B 20; C 24; D 30. Explain the intended result and the language-standard issue.

## Solution

The intended contiguous-address calculation begins at row1, column 0, linear index 5; advancing 9 integers reaches index 14=row2, column 4, whose initialized value is 24, C. However arr[1] decays to a pointer into the five-element row subarray. Adding9 goes beyond that array and its one-past position, so the expression has undefined behavior under C pointer-arithmetic rules. Contiguous storage of the outer array does not legalize this cross-row pointer arithmetic. The official C is retained as the intended exam answer, not a portable guarantee.

The intended memory layout has rows 0–4,10–14,20–24,30–34. The desired element is arr[2][4], which is a portable way to express it. Do not run this original expression and treat one observed compiler output as a proof of defined behavior. The official option describes the conventional exam address calculation only.

**Paraphrased problem context:** SomeFunction(x,y): if x==1 or y==1 return 1; if x==y return x; if x>y recurse on (x−y,y); if y>x recurse on (x,y−x). Find SomeFunction(15,255).

## Solution

Each recursive step subtracts the smaller positive argument from the larger, preserving their gcd. Starting at(15, 255), repeated subtraction reaches(15, 15), which returns 15. Neither argument reaches 1 on this input.

The invariant gcd(x,y)=gcd(x,y−x) explains correctness, while decreasing x+y proves termination for positive integers. Here y successively becomes 240,225,…,30,15, after sixteen subtractions of 15, and the equality branch returns 15. A modulo-based Euclidean algorithm would skip these repeated subtraction calls.

**Official answer:** D

**Derived answer:** D

**Paraphrased problem context:** C Node has int value; Node *next. Allocate head=boxE, set value=0. For index=1..3 allocate boxN, set boxE->next=boxN, boxN->value=index, boxE=boxN. Then for index=0..3 print head->value, assign head=head->next, and print head->value again. No final next initialization occurs. A five nodes created; B infinite loop; C missing return causes compile error; D uninitialized pointer dereferenced, possibly runtime error.

## Solution

The initial allocation plus three loop allocations create four nodes with values 0, 1, 2, 3. The final node’s next field is never initialized. The second loop advances head and dereferences it again each iteration; on the fourth iteration it reads that uninitialized next pointer and uses it for head->value. This is undefined behavior and may cause a runtime error, D. The loops themselves have bounded iteration counts.

Before the second loop, the chain is 0→1→2→3→uninitialized. The first three iterations safely advance to nodes 1,2,3 if allocation succeeds. The last iteration prints 3, then follows the indeterminate pointer and dereferences it. Initializing next to NULL alone would still leave the unconditional extra dereference invalid; correct traversal tests the pointer before using it. Allocation failure is another issue, not needed for the intended diagnosis.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 60 to 60

**Derived answer:** 60

**Paraphrased problem context:** foo(x,y,q): if x≤0 and y≤0 return q; if x≤0 return foo(x,y−q,q); if y≤0 return foo(x−q,y,q); otherwise return foo(x,y−q,q)+foo(x−q,y,q). What does printing foo(15,15,10) yield?

## Solution

With q=10, each initial coordinate 15 requires two decrements to become nonpositive. When both remain positive the recursion branches on which coordinate decreases; once one is nonpositive only the other can decrease. Thus leaves correspond to the six interleavings of two x decrements and two y decrements, binomial(4, 2)=6. Each leaf returns 10, so the output is 60. There are no side effects across recursive calls, so unspecified operand evaluation order does not affect this sum.

Let F(i,j) denote the return with i,j remaining decrements needed. Interior recurrence F(i,j)=F(i−1,j)+F(i,j−1), with F(i,0)=F(0,j)=10. Hence F(1,1)=20, F(1,2)=F(2,1)=30, F(2,2)=60. The base is reached at −5, not necessarily exactly zero, because tests are nonpositive.
