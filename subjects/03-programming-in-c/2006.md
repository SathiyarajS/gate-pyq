

# GATE 2006: Q15 (printed CS Q15)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** For positive integer n, the C fragment is: for (i=n,j=0; i>0; i/=2,j+=i); . Here i,j,n are integer variables and the loop body is empty. Which is the asymptotic value of j after termination, rather than the running time?
Options:
(A) Θ(log n)
(B) Θ(√n)
(C) Θ(n)
(D) Θ(n log n)

## Solution

1. The update uses the comma operator: first integer-divide i by 2, then add the new i to j. For positive n, j=floor(n/2)+floor(n/4)+...=n−popcount(n).

2. It is at least floor(n/2) and less than n, hence Θ(n), C. This is the value accumulated, not the Θ(log n) iteration count.

3. Its value remains below n, so no positive signed overflow is needed when n is representable.

4. Teaching check: For n=13 the updates add 6,3,1,0, yielding j=10 even though there are only four iterations. Generally the sum lies between floor(n/2) and n, which supplies matching linear bounds without needing the exact popcount identity.

# GATE 2006: Q53 (printed CS Q53)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Sorted integer arrays a[0…n−1],b[0…m−1] have positive lengths. Array c has capacity n+m. Execute:
i=j=k=0;
while (i<n && j<m) {
  if (a[i]<b[j]) c[k++]=a[i++];
  else c[k++]=b[j++];
}
Which printed postcondition is valid?
I: if i=n, then j<m, k=n+j−1, and a[n−1]<b[j].
II: if j=m, then i<n, k=m+i−1, and b[m−1]≤a[i].
The −1 terms are retained exactly as reproduced in both sources.
Options:
(A) Only I
(B) Only II
(C) Either I or II, but not both
(D) Neither I nor II

## Solution

1. The loop starts i=j=k=0. Each iteration increments exactly one of i,j and also k, preserving k=i+j.

2. At termination, if i=n then j<m and k=n+j; the final extraction from a implies a[n−1]<b[j]. If j=m then i<n and k=m+i; the final extraction from b implies b[m−1]≤a[i].

3. Both printed assertions instead give k one less than these values. Hence neither assertion is correct: D.

4. This uses positive array lengths and defined array accesses, as intended by the example. The GateForum reproduction also prints k=n+j−1 and k=m+i−1.

5. The off-by-one observations therefore hold for both inspected third-party versions; they do not establish original official wording.

6. Teaching check: Initially k=i+j=0. Every loop iteration increments k and exactly one of i,j, so k=i+j remains true. At exit, replacing i by n or j by m yields k=n+j or k=m+i, directly contradicting the printed −1 regardless of the final comparison.

# GATE 2006: Q57 (printed CS Q57)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** C code:
void swap(int *px,int *py) {
 *px=*px-*py;
 *py=*px+*py;
 *px=*py-*px;
}
Statements: S1 compilation error; S2 may cause a segmentation fault for some arguments; S3 correctly swaps for all pointers to accessible integers; S4 correctly swaps for some but not all valid input pointers; S5 may add/subtract integers and pointers. Which statements are intended to be true?
Options:
(A) S1
(B) S2 and S3
(C) S2 and S4
(D) S2 and S5

## Solution

1. The code uses *px=*px−*py; *py=*px+*py; *px=*py−*px. For distinct valid integer objects and arithmetic without signed overflow, initial values x,y become x−y,y then x−y,x then y,x, correctly swapping.

2. If px=py, the first assignment zeroes the shared object and the result is not a swap unless it was zero. Invalid pointers may cause a segmentation fault.

3. Thus S2 and S4 are the intended statements: C. No pointer arithmetic occurs, and there is no intrinsic compilation error.

4. Signed overflow is an additional undefined-behavior limitation even with distinct accessible objects.

5. Teaching check: Aliasing is decisive: if px and py point to the same nonzero integer, the first subtraction writes zero and destroys the original value. With distinct valid cells the algebraic swap works only when each intermediate signed operation is representable. Dereferencing an invalid pointer is a further separate risk.
