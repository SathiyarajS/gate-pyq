

# GATE 1999: Q49 (printed A Q2.24)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C on distinct values; not total for arbitrary integers

**Essential problem context (paraphrased):** Trial(a,b,c) returns b if a≥b and c<b; otherwise calls Trial(a,c,b) if a≥b, or Trial(b,a,c). Does it find maximum,minimum,median,or none?

## Solution

For distinct values, a return requires c<b≤a, so b is the median. If a<b, swapping the first two puts the larger first. If a≥b but c≥b, swapping b and c either puts the middle value second or is followed by a first-pair swap; direct enumeration of the six strict orderings confirms termination at the median. Ties expose a defect: Trial(2,1,1) repeatedly calls itself because c<b is false while swapping equal arguments changes nothing. Trial(1,1,1) likewise never returns. Thus C describes the intended distinct-input algorithm, but no unconditional median function is established by the stated unrestricted int signature.

# GATE 1999: Q74 (printed B Q15(i))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 2

**Essential problem context (paraphrased):** For this program, determine printed a under call by value:
procedure P(x,y,z);
begin y := y+1; z := x+x end;
begin
  a := 2; b := 3;
  P(a+b,a,a);
  print(a)
end.
The initialization a:=2 is supplied by GFG; GateForum omits it.

## Solution

At entry the actual expression a+b is evaluated to 5. Call by value creates three independent local cells x=5, y=2 and z=2. The first assignment changes only local y from 2 to 3. The second computes local z=x+x=10. Neither assignment writes caller a; the local cells disappear when P returns. Hence caller a remains 2 and print(a) outputs 2. The two occurrences of actual a do not create aliases in call by value. This trace depends on GFG’s visible a:=2 initialization; the damaged GateForum version alone does not determine a numerical output.

# GATE 1999: Q75 (printed B Q15(ii))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 10 under expression-temporary convention; strict variable-reference semantics reject the call.

**Essential problem context (paraphrased):** Determine printed a under call by reference for:
procedure P(x,y,z);
begin y := y+1; z := x+x end;
begin
  a := 2; b := 3;
  P(a+b,a,a);
  print(a)
end.
Use GFG’s visible a:=2 initialization, absent in GateForum, and discuss passing the expression a+b by reference.

## Solution

There is a language-semantic qualification: an ordinary assignable reference parameter cannot bind to the non-variable expression a+b. In a strict Pascal-style var-parameter language this call is invalid, so no output is defined. The customary exercise convention evaluates a+b once into an anonymous temporary t=5 and binds x to t, while both y and z refer directly to caller a. Then y:=y+1 changes a from 2 to 3. Next z:=x+x reads t twice, obtains 10, and writes a=10. Thus the intended trace under that convention prints 10. It does not print 12: reevaluating a+b after a changes would be call-by-name behavior, not a reference to the original temporary. The convention and the secondary initialization must both be stated rather than silently assumed.

# GATE 1999: Q76 (printed B Q15(iii))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 10 if y restores before z; 3 if z restores before y; no unique output without a convention.

**Essential problem context (paraphrased):** Determine printed a under call by copy-restore for:
procedure P(x,y,z);
begin y := y+1; z := x+x end;
begin
  a := 2; b := 3;
  P(a+b,a,a);
  print(a)
end.
GFG supplies a:=2, which is missing in GateForum. No copy-back order is specified.

## Solution

Copy-in gives independent local values x=5, y=2, z=2. The body ends with x=5, y=3, z=10. Both y and z have the same copy-back destination, caller a, so restoration order matters. Restoring y then z sets a first to 3 and then to 10, printing 10. Restoring z then y sets a first to 10 and finally to 3, printing 3. Thus the given program has no uniquely determined copy-restore result unless the language specifies the order. A left-to-right formal-parameter restoration convention yields 10. As in reference passing, the non-variable actual a+b requires an expression temporary or a rule permitting input-only expressions; strict copy-in/copy-out parameters requiring assignable actuals reject the call. Under the temporary convention restoring unchanged x does not affect a. This is aliasing at copy-back, not aliasing between the local parameter cells.
