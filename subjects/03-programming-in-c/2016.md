**Paraphrased problem context:** Given void f(int,short); and a main body declaring int i=100; short s=12; short *p=&s;, which expression can fill a call-site blank without a type-checking error? A: f(s,*s). B: i=f(i,s). C: f(i,*s). D: f(i,*p). The printed wrapper uses void main(); judge the candidate expressions.

## Solution

The function expects int and short and returns void. In D, i is int and *p is short, so f(i,*p) is well typed. A and C incorrectly dereference the nonpointer s; B tries assigning a void result to i. Thus D, evaluating the blank expression independently of the nonstandard void main wrapper.

The unary * operator requires a pointer operand. Since s is a short integer, *s is invalid regardless of the value 12 stored in it. By contrast p has type short*, so *p is a short lvalue compatible with f's second parameter. In B the arguments themselves are compatible, but f returns no value, so its call cannot supply an integer assignment value. Separate argument-type checking from return-value checking.

**Paraphrased problem context:** Find the printed value in this C program (stdio.h is included):
void mystery(int *ptra,int *ptrb){int *temp;temp=ptrb;ptrb=ptra;ptra=temp;}
int main(){int a=2016,b=0,c=4,d=42;mystery(&a,&b);if(a<c)mystery(&c,&a);mystery(&a,&d);printf("%d\n",a);}

## Solution

mystery swaps only its local pointer parameters; it never writes through either pointer. All pointed-to integers remain unchanged and the conditional a<c is false. The printed a is 2016.

C passes the pointer values by value, producing local copies of the addresses. Changing which address ptra or ptrb contains does not modify a,b,c or d. To swap integers the function would need assignments through *ptra and *ptrb; to swap caller pointer variables it would need a different interface. After the first call a remains 2016, so 2016<4 is false. The final call likewise has no effect on a before printing.

**Paraphrased problem context:** Fill the loop condition so this C function returns the maximum array element for all n≥1:
int max(int *p,int n){int a=0,b=n−1;while(____){if(p[a]<=p[b])a=a+1;else b=b−1;}return p[a];}
A: a!=n. B: b!=0. C: b>(a+1). D: b!=a.

## Solution

At each iteration discard an endpoint no greater than the other: if p[a]≤p[b], advance a; otherwise decrement b. A maximum remains in the surviving interval. Continue until a=b, then return that sole survivor. Condition b!=a is D; stopping with two candidates is premature.

The invariant is that at least one maximum of the original array lies between indices a and b inclusive. Discarding the smaller endpoint preserves this invariant, including ties because the other equal value remains. Each step reduces b−a by 1, so termination occurs after n−1 iterations at a=b. For n=1 the correct loop runs zero times. Option C would stop with two values, potentially returning the smaller left one; A and B tie termination to fixed endpoints rather than convergence.

**Paraphrased problem context:** Find the printed sequence for count(3), where:
void count(int n){static int d=1;printf("%d ",n);printf("%d ",d);d++;if(n>1)count(n−1);printf("%d ",d);}
A:3 1 2 2 1 3 4 4 4. B:3 1 2 1 1 1 2 2 2. C:3 1 2 2 1 3 4. D:3 1 2 1 1 1 2.
The printed main wrapper calls count(3); assume the usual printing declarations.

## Solution

The static d is shared across recursive calls. Entry pairs are(3, 1),(2, 2),(1, 3); after the third increment d=4. Each of the three returning frames then prints 4. The complete sequence is 3 1 2 2 1 3 4 4 4, A. The snippet assumes normal printf declarations and acceptance of its void-main wrapper.

There is one static storage cell for d, not one copy per recursion frame. Trace entry: count(3) prints 3,1 and increments to 2; count(2) prints 2,2 and increments to 3; count(1) prints 1,3 and increments to 4. The base call skips recursion but still executes its final print. Returning callers also execute that final print and see the same shared 4. No decrement or new initialization happens during unwinding, which explains all three trailing 4s.

## Solution

The value parameter m changes from 10 to 15 locally. Writing through p updates i from 5 to 20, while caller j stays 10. Hence i+j=30. Routine library declarations and the intended void-main extension are assumed.

Passing &i copies i’s address, not its value, into p. Dereferencing p consequently changes the caller’s i. Passing j copies 10 into the separate local variable m, so changing m cannot change j. The final addition is 20+10, not 20+15 or the original 5+10.
