**Type / marks:** NAT, 1 mark(s).

**Official answer:** 26 to 26

**Derived answer:** 26

**Paraphrased problem context:** Function jumble(int x,int y) assigns x=2*x+y and returns x. Main initializes x=2,y=5, then executes y=jumble(y,x), then x=jumble(y,x), and finally prints main's x. Find the printed integer.

## Solution

Method: keep the function's local parameter names separate from the caller's variables, and evaluate statements in sequence.

1. Initially main has (x,y)=(2,5). In y=jumble(y,x), the first argument is main's y=5 and the second is main's x=2. Inside the function, local (x,y) therefore starts as (5,2).
2. The function computes local x=2×5+2=12 and returns 12. C passes these integers by value, so changing the local x does not alter main's x. The assignment updates only main's y, leaving main at (2,12).
3. The second call, x=jumble(y,x), now passes (12,2). The returned value is 2×12+2=26, and the enclosing assignment stores it in main's x.
4. Main is now (26,12), so printing x displays 26. Reusing the function's parameter name x does not make it an alias of the caller's x.

Result: 26. The official range 26 to 26 accepts this exact value.

**Official answer:** 6 to 6

**Derived answer:** 6

**Paraphrased problem context:** A C program initializes int arr[]={1,2,3,4,5,6,7,8,9,0,1,2,5}; and int *ip=arr+4; then prints ip[1] using the %d conversion. Find the integer displayed.

## Solution

Method: identify the pointer's base element, then apply C's definition of the subscript operator.

1. C array indices start at zero. Thus arr[0]=1, arr[1]=2, arr[2]=3, arr[3]=4, arr[4]=5, and arr[5]=6. “Index 4” denotes the fifth element, not the fourth.
2. In the expression arr+4, arr converts to a pointer to its first element, &arr[0]. Adding 4 to an int pointer advances it by four int elements, not by four bytes. Therefore ip=&arr[4], pointing at the value 5.
3. For a pointer p, C defines p[k] as *(p+k). Consequently ip[1]=*(ip+1): advance one more int from arr[4], then read the value at that location.
4. Substitute the pointer value explicitly: *(ip+1)=*((arr+4)+1)=*(arr+5)=arr[5]=6.
5. The access stays within the 13-element array and does not modify either ip or arr. The %d conversion prints the selected integer, followed by the newline specified in the program.

Result: 6. ip[0] would be 5, whereas ip[1] is 6; ip[1] is not the same as arr[1] because the two indexing expressions use different base pointers. No assumption about the byte size of int is needed.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** D

**Derived answer:** D

**Paraphrased problem context:** For positive integer n, convert(n) executes: if(n<0) printf("%d",n); else { convert(n/2); printf("%d",n%2); }. Decide whether it prints ordinary binary and terminates (A), reversed binary and terminates (B), binary without terminating (C), or nothing without terminating (D).

## Solution

1. The stopping branch is n<0, not n==0. Integer division of a positive integer by 2 produces another nonnegative integer, so none of the recursive calls can enter the stopping branch.
2. Repeated halving eventually reaches zero. For example, an input 5 gives calls with arguments 5, 2, 1, 0. At zero the else branch calls convert(0/2), which is convert(0) again.
3. Each printf in the else branch occurs after the recursive call. Since the innermost call never returns normally, no pending printf is reached. The negative-argument printf is also unreachable.
4. Therefore the abstract recursion neither prints nor terminates: D. A real implementation has finite resources and typically exhausts its call stack, rather than literally running forever. The familiar binary-conversion algorithm would need a reachable base case; it cannot be substituted for the code actually supplied.

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** r() contains static int num=7 and returns num--. main executes for(r(); r(); r()) printf("%d",r()); then returns. Which displayed output is correct: A 41, B 52, C 63, D 630?

## Solution

1. A static local variable is initialized once and keeps its value between calls. Post-decrement returns the old num and then reduces the stored value by one.
2. A for loop evaluates its initializer once, then repeatedly evaluates condition, body, and increment in that order. Calls in the initializer and increment still change num even though their returned values are discarded.
3. The initializer returns 7 and leaves num=6. The first condition returns 6, which is true, and leaves num=5. The body returns and prints 5, leaving num=4. The increment returns 4 and leaves num=3.
4. The second condition returns 3, so the body prints 2 and leaves num=1. The increment returns 1 and leaves num=0. The next condition returns 0, which is false, so there is no third body execution.
5. Only body calls print. No space or newline separates the two digits, so the displayed output is 52, option B. In particular, the zero used to stop the loop is never printed.

**Derived answer:** 5

**Paraphrased problem context:** The C program initializes float sum=0.0,j=1.0,i=2.0 and repeats while(i/j>0.0625) { j=j+j; sum=sum+i/j; printf("%f\n",sum); }. How many times is sum printed?

## Solution

1. The loop test is evaluated before doubling j. Variable i remains 2 throughout, while j doubles once per successful iteration. The threshold is 0.0625=1/16.
2. At successive tests, j is 1,2,4,8,16,32, giving i/j equal to 2,1,1/2,1/4,1/8,1/16. The first five values are strictly larger than 1/16; the sixth is equal and fails the > comparison.
3. Each of those five successful tests enters the body exactly once, executes one printf, and changes j to the next power of two. Therefore there are 5 prints.
4. As a check on operation order, the terms added inside the body use the already doubled j: 1,1/2,1/4,1/8,1/16. The printed sums are 1,1.5,1.75,1.875,1.9375, normally shown with six digits after the decimal by %f.
5. The test that stops execution produces no print. These powers of two and binary fractions are exactly representable in ordinary binary floating point, so rounding does not alter this stopping point.

**Official answer:** 10 to 10

**Derived answer:** 10

**Paraphrased problem context:** In C, a={2,4,6,8,10}, sum=0, and int *b=a+4. For i=0 through 4, execute sum=sum+(*b-i)-*(b-i); then print sum as an integer. What is printed?

## Solution

1. Pointer b is initialized to the final array element a[4]. No statement changes b, so *b remains 10 throughout the loop.
2. Distinguish the two expressions carefully. (*b-i) subtracts i from the value 10. By contrast, *(b-i) first moves the pointer i array positions backward and then reads a[4-i]. Pointer arithmetic counts int elements, not bytes.
3. For i=0,1,2,3,4, the first expression takes values 10,9,8,7,6. The second reads 10,8,6,4,2. Their differences are therefore 0,1,2,3,4.
4. Starting from zero, sum accumulates 0+1+2+3+4=10. Equivalently, a[4-i]=10−2i, so each summand is (10−i)−(10−2i)=i.
5. The output is 10 followed by a newline. All dereferences stay within a[0] through a[4]. The minus sign is subtraction, not a decrement of b, and confusing these operations would produce a different trace.
