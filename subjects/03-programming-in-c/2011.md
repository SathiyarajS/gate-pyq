**Paraphrased problem context:** What does this literal C fragment print? The initial capital in Char is as printed.
Char c[] = "GATE2011";
char *p = c;
printf("%s", p + p[3] - p[1]);

(A) GATE2011
(B) E2011
(C) 2011
(D) 011

## Solution

Using ASCII arithmetic, E−A=4, so the intended pointer is c+4 and the intended suffix is 2011, C. But p+p[3]−p[1] associates as (p+p[3])−p[1]. Its first pointer operation forms p+69 in ASCII, far beyond the 9-byte array, causing undefined behavior before the subtraction returns to offset 4. The source also capitalizes Char, which is not the C keyword char unless separately defined. Replacing Char with char and writing p+(p[3]−p[1]) repairs the intended calculation, still with an explicit character-encoding assumption. The official result is not a guarantee of the literal fragment.

Index the intended string: c[0]='G', c[1]='A', c[2]='T', c[3]='E', c[4]='2', c[5]='0', c[6]='1', c[7]='1', c[8]='\0'. A valid pointer to c[4] makes %s print characters until c[8], producing 2011. This explains the examiner's arithmetic but must not erase the separate language-law issues in the literal source. Pointer arithmetic has validity requirements at every intermediate operation, not only at the final address.

**Paraphrased problem context:** Consider unsigned int foo(unsigned int n, unsigned int r) { if (n>0) return ((n%r)+foo(n/r,r)); else return 0; }. What does foo(345,10) return?

(A) 345
(B) 12
(C) 5
(D) 3

## Solution

For positive n and base r>1, n%r is the final base-r digit and integer division n/r removes it. The recursive calls therefore sum the digits. With n=345 and r=10, the return is 5+4+3+0=12, option B.

Unroll the calls: foo(345,10)=5+foo(34,10); foo(34,10)=4+foo(3,10); foo(3,10)=3+foo(0,10); the last call returns 0. The call stack then returns 3,7,12 in reverse order. It does not reconstruct the original number because no place-value multiplications are used, and it does not stop after the first remainder. The base case is essential to terminate after all digits have been consumed.

**Paraphrased problem context:** Consider unsigned int foo(unsigned int n, unsigned int r) { if (n>0) return ((n%r)+foo(n/r,r)); else return 0; }. What does foo(513,2) return?

(A) 9
(B) 8
(C) 5
(D) 2

## Solution

The function sums the base-r digits of n. Since 513=512+1=2^9+1, its binary representation is 1000000001 and has two 1 bits. Consequently foo(513, 2)=2, option D. All intermediate recursive divisions are unsigned integer divisions and terminate at zero.

The successive n values are 513,256,128,64,32,16,8,4,2,1,0. Remainders modulo 2 are 1 at n=513 and n=1 and zero at every other positive step. Summing them produces 2. The exponent 9 tells where the highest bit lies, not how many set bits there are; similarly, the number of recursive positive calls is 10, not the return value. The function counts ones for base 2 because binary digits can only be zero or one.
