**Independently derived answer:** y := (x > 5);

**Essential problem context (paraphrased):** Replace Pascal if x>5 then y:=true else y:=false with one assignment.

## Solution

The comparison x>5 evaluates to a Boolean. In the true case, the original statement assigns true to y; in the false case, it assigns false. Assigning the comparison result therefore gives exactly the same value in both cases. At x=5, the result is false, so using ≥ instead would be incorrect. This simplification assumes y has Boolean type and the comparison has the ordinary Pascal semantics shown in the source. No branch or numeric Boolean encoding is needed.

# GATE 1991: Q35 (printed A Q4(ii))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204230/GATE1991.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** short-answer, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** begin S; while not B do S end

**Essential problem context (paraphrased):** Rewrite Pascal repeat S until B using a while construct with equivalent behavior.

## Solution

A repeat loop executes S before checking B, so S runs at least once. Execute S once explicitly, then test not B in the while guard. Whenever B remains false, execute S again; stop immediately after an iteration makes B true. Merely writing while not B do S would incorrectly permit zero executions when B starts true. This transformation preserves the sequence of evaluations of B after executions of S, including ordinary side effects in the condition. If S is a multi-statement sequence, it must be grouped as a Pascal compound statement.
