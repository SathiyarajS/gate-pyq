**Paraphrased problem context:** Function func(i,j) is called with i=9,j=10. If i<j, an inner block declares a new int i=0 and loops while that inner i<10, adding 2 to j and incrementing the inner i. After the block, printf("%d",i) executes. Determine the printed integer.

**Type / marks:** NAT, 1.

**Official answer:** 9 to 9

**Derived answer:** 9 to 9

## Solution

Givens and goal
Function func(i,j) is called with i=9,j=10. If i<j, an inner block declares a new int i=0 and loops while that inner i<10, adding 2 to j and incrementing the inner i. After the block, printf("%d",i) executes. Determine the printed integer.

Approach
Track each distinct variable object and which declaration each occurrence of i refers to.

Step-by-step solution
1. The function receives its own parameter i with value 9 and parameter j with value 10. The initial comparison succeeds.
2. Inside the conditional block, a new local i is declared. It shadows the parameter i only within that block. The loop increments this inner variable from 0 to 10; it does not alter the parameter i.
3. The loop also increases the function-local j, which has no effect on the printed expression. When execution leaves the block, the inner i goes out of scope.
4. The print statement is outside the block. Its identifier i therefore refers to the parameter, still equal to 9. The output is 9, with no newline implied by the shown format string.

**Common error:** Shadowing creates a different object; it is not assignment to the outer object.

Scope trace:

    Point                         Parameter i   Inner i   Parameter j
    Function entry                    9          absent        10
    Inner declaration                 9             0          10
    After ten loop iterations         9            10          30
    At printf                         9          absent        30

The table makes clear that reaching inner i=10 does not imply that printf prints 10. The condition uses the parameter before the inner declaration is reached, whereas the loop uses the inner object.

**Paraphrased problem context:** For a nonempty singly linked list, getListSize(head) returns 1 if E1 is true and otherwise returns E2. Choose between base tests head==NULL or head->next==NULL, and recursive expressions 1+getListSize(head) or 1+getListSize(head->next).

**Type / marks:** MCQ, 2.

**Official answer:** B

**Derived answer:** B

## Solution

Givens and goal
For a nonempty singly linked list, getListSize(head) returns 1 if E1 is true and otherwise returns E2. Choose between base tests head==NULL or head->next==NULL, and recursive expressions 1+getListSize(head) or 1+getListSize(head->next).

Approach
Match the base return value 1 to a one-node list and ensure recursion moves to a strictly shorter suffix.

Step-by-step solution
1. The input list is nonempty, so the current head points to a node. A one-node list is recognized by a null next pointer, and its length is 1.
2. If a next node exists, the tail beginning there is also nonempty. The total length is one for the current node plus the recursively computed tail length. This supplies the base condition and recursive expression in B.
3. Induction proves correctness: length 1 returns 1; assuming the routine counts a tail of length n−1, the recursive case returns 1+(n−1)=n.
4. Passing the unchanged head recursively never decreases the problem size and does not terminate on longer lists. Using head==NULL as the base test while returning 1 gives an extra count for the empty suffix. These defects eliminate the other choices.

**Assumption:** As usual for a finite singly linked list, the chain is acyclic. The question's recursion would not terminate on a cyclic structure.

Trace for three nodes A→B→C→NULL: the call at C detects next==NULL and returns 1; the call at B returns 1+1=2; the call at A returns 1+2=3. With a head==NULL base returning 1, even a one-node input would instead return 1+1=2. With an unchanged-head recursive call, any list longer than one node recurses forever rather than reaching the last node.

**Paraphrased problem context:** The recursive functions are bar(1)=0 and bar(n)=1+bar(n/2) otherwise, using C integer division; foo(1)=1 and foo(n)=1+foo(bar(n)) otherwise. Find the smallest positive integer n for which foo(n)=5.

**Type / marks:** NAT, 2.

**Official answer:** 65536 to 65536

**Derived answer:** 65536 to 65536

## Solution

Givens and goal
The recursive functions are bar(1)=0 and bar(n)=1+bar(n/2) otherwise, using C integer division; foo(1)=1 and foo(n)=1+foo(bar(n)) otherwise. Find the smallest positive integer n for which foo(n)=5.

Approach
First identify bar as a floor logarithm, then work backwards through the thresholds for successive foo return values.

Step-by-step solution
1. For positive n, integer division by 2 repeatedly halves n with truncation. If 2^m≤n<2^(m+1), exactly m divisions are needed to reach 1. Hence bar(n)=floor(log₂n).
2. Therefore foo(n)=1+foo(floor(log₂n)) for n>1, with foo(1)=1. A foo call counts one level and continues with its much smaller floor-logarithm argument.
3. Let a_j be the smallest input with return value j. The base is a₁=1. To obtain one extra level, floor(log₂n) must reach at least the smallest input a_j needed for the previous level. The least n with floor(log₂n)=a_j is n=2^(a_j).
4. Thus the successive thresholds are a₁=1, a₂=2, a₃=4, a₄=16, a₅=2^16=65536. Monotonicity of floor(log₂n) and of these level thresholds shows no smaller input can skip ahead to five levels.
5. Verify directly: bar(65536)=16, bar(16)=4, bar(4)=2, bar(2)=1. The foo chain is 65536→16→4→2→1, giving return values 5→4→3→2→1 when read from the outer call inward.
6. The requested integer is 65536. The division is integer division; treating bar as an unrounded real logarithm would not model the code.

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** In the conventional C runtime model, which object is stored in the heap? A function-local static variable; B ordinary function-local integer array; C integer array allocated by malloc; D function return address.

## Solution

Givens and goal
In the conventional C runtime model, which object is stored in the heap? A function-local static variable; B ordinary function-local integer array; C integer array allocated by malloc; D function return address.

Approach
Compare storage duration and allocation mechanism rather than source-code location.

Step-by-step solution
1. malloc requests dynamically allocated storage whose lifetime extends until it is released, typically by free. Conventional runtimes manage this storage in the heap. Thus C is the intended answer.
2. A local static variable exists for the program lifetime and conventionally occupies a static data region, despite its name having block scope. Scope does not determine storage duration.
3. An ordinary non-static local array has automatic storage duration and is conventionally placed in a stack frame. A return address is part of calling state, often on a stack or in an architecture-specific register.
4. A local pointer holding the malloc result can itself be in a stack frame while the array it points to is in the heap. The C standard specifies storage behavior, not physical regions literally named stack and heap; the answer uses the stated runtime convention.

P3: inside one main block, int a=5; float a=7;. Which compiles without a required error? A only P1; B only P2; C only P3; D all.

## Solution

Givens and goal
Each program includes stdio.h and has main returning 0. P1: file-scope int a=5; inside main, int a=7;. P2: inside one main block, int a=5; int a=7;. P3: inside one main block, int a=5; float a=7;. Which compiles without a required error? A only P1; B only P2; C only P3; D all.

Approach
Check whether declarations inhabit different scopes or attempt to define the same local identifier twice.

Step-by-step solution
1. P1 has an outer file-scope object and a distinct inner block-scope object. The inner a legally shadows the outer a inside main. The two definitions do not conflict because they are in different scopes.
2. P2 has two initialized definitions of the same ordinary automatic identifier in one block. It is not assignment to an existing object: the repeated type keyword introduces a second declaration/definition, which violates the constraints.
3. P3 also redeclares a in the same block, and additionally changes its type from int to float. This is not legal shadowing, because there is no nested inner block.
4. Only P1 is valid under the intended ANSI-C rules, so A. A compiler may issue a shadowing warning for P1, but an optional warning does not make the program invalid.

**Paraphrased problem context:** Find the printed c for this statement sequence in main: int *ptr,a,b,c; a=5; b=11; c=20; ptr=&a; *ptr=c; ptr=&c; a=*(&b); c=*ptr-a; printf("%d",c);. Assume successful compilation and execution.

## Solution

Givens and goal
Find the printed c for this statement sequence in main: int *ptr,a,b,c; a=5; b=11; c=20; ptr=&a; *ptr=c; ptr=&c; a=*(&b); c=*ptr-a; printf("%d",c);. Assume successful compilation and execution.

Approach
Track both the pointer target and the object values after every assignment.

Step-by-step solution
1. Initially a=5,b=11,c=20. The assignment ptr=&a stores a’s address in ptr; it does not change any integer value.
2. Then *ptr=c writes the current value of c into the object pointed to by ptr, which is a. The state becomes a=20,b=11,c=20, with ptr still pointing to a.
3. Next ptr=&c redirects the pointer to c without copying any old pointed-to value. The expression *(&b) is simply b, so a=*(&b) sets a=11. Now a=11,b=11,c=20 and ptr points to c.
4. In c=*ptr-a, the right-hand side reads the old value c=20 through ptr and subtracts a=11. The assignment therefore stores c=9, and printf prints 9.
5. This assignment is well-defined: the old c is read to calculate its new value. The crucial distinction is between changing ptr itself and assigning through *ptr to the current target.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 1 to 1

**Derived answer:** 1 to 1

**Paraphrased problem context:** The function computes length=end+1−start. It returns 0 if length<1 or start<0 or end<0. Otherwise if length%3==0 it returns func(start+1,end); if length%3==1 it returns 1+func(start,end−1); else it returns func(start+2,end). Find the maximum possible returned value for defined, non-overflowing C executions.

## Solution

Givens and goal
The function computes length=end+1−start. It returns 0 if length<1 or start<0 or end<0. Otherwise if length%3==0 it returns func(start+1,end); if length%3==1 it returns 1+func(start,end−1); else it returns func(start+2,end). Find the maximum possible returned value for defined, non-overflowing C executions.

Approach
Follow how the interval length moves between residue classes modulo three.

Step-by-step solution
1. For valid endpoints let L=end+1−start>0. The first branch changes L to L−1, the second to L−1 while adding 1, and the third to L−2. Every valid recursive step strictly decreases L, so it eventually reaches a base case.
2. If L≡0 mod 3, the next length is L−1≡2. The following step subtracts 2, reaching L−3≡0. This 0→2→0 cycle never enters residue 1 and therefore contributes no increment.
3. If L≡2 mod 3, its first step goes directly to L−2≡0, followed by the same zero-contribution cycle. If L≡1 mod 3, it adds 1 once and moves to L−1≡0, after which no further increments occur.
4. Invalid endpoints return zero immediately. The value 1 is attainable with start=end=0: length=1, so the function returns 1+func(0,−1)=1+0.
5. Therefore the maximum is 1. This analysis assumes representable arithmetic; evaluating end+1 or changing endpoints beyond signed-int limits can cause undefined behavior and is not a valid counterexample returning a larger defined integer.
