**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** A C program initializes int a=6, b=0, then executes while(a<10) { a=a/12+1; a+=b; }, followed by printf("%d",a). What happens in the intended execution model? A prints 9; B prints 10; C infinite loop; D prints 6.

## Solution

Approach: Trace the first iteration, then determine whether the loop reaches a repeating state. Both operands of a/12 are integers.
1. The initial test 6<10 is true. Integer division gives 6/12=0, so a=a/12+1 sets a to 1.
2. The following a+=b adds zero, because b was initialized to 0 and is never changed. The first iteration ends with a=1, b=0.
3. If an iteration starts with a=1, then 1/12=0, and the same two assignments leave a=1 again. This state is therefore preserved indefinitely.
4. The condition a<10 remains true, so control never reaches the printf after the loop.
Answer: C. The expression contains “+1”, but it does not mean a is incremented each time: a is first replaced by the quotient a/12. This is the textbook execution interpretation of the supplied program.

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** main calls fX once. The function has local char a; it reads a=getchar(), recursively calls fX if a is not newline, then prints a with putchar if a is not newline. Input is 1234 followed by newline. A no termination; B termination with no output; C termination with 4321; D termination with 1234.

## Solution

Approach: Distinguish the order in which recursive calls read characters from the order in which suspended calls resume printing.
1. The first call stores '1' in its own local a and calls fX again before reaching putchar. The next calls similarly store '2', '3' and '4'. Each call has a separate local variable.
2. A fifth call reads the newline. Both conditions are false, so this call neither recurses nor prints and returns immediately.
3. The suspended call holding '4' now continues at its second condition and prints 4. Returning again prints 3, then 2, then 1.
4. Once the first call returns, main terminates. The newline itself is never printed.
Answer: C, output 4321. Printing before the recursive call would preserve input order; printing after it reverses order. The explicitly supplied newline is the stopping condition, so no assumption about reading past end-of-file is needed.

**Official answer:** 6 to 6

**Derived answer:** 6

**Paraphrased problem context:** Evaluate 3+1+5*2/7+2−4−7−6/2 using these rules: + has highest precedence and associates left; − is next and associates right; * is next and associates right; / is lowest and associates right. All arithmetic is integer arithmetic.

## Solution

Approach: Build the grouping from the stated table, not from ordinary mathematical or C precedence. Associativity decides grouping only among operators at the same precedence.
1. Highest-precedence additions group (3+1+5)=9 and (7+2)=9. The expression becomes 9*2/9−4−7−6/2.
2. Subtraction has higher precedence than multiplication and division and is right-associative. Its group is 9−(4−(7−6)). Evaluate inward: 7−6=1, 4−1=3, 9−3=6.
3. The expression is now 9*2/6/2. Multiplication is next, giving 18/6/2.
4. Division is right-associative, so this means 18/(6/2), not (18/6)/2. The inner quotient is 3 and the result is 18/3=6.
Answer: 6. A fully parenthesized form is ((3+1)+5)*2 / (((7+2)−(4−(7−6)))/2). Both actual divisions are exact, so no integer-rounding issue arises.

**Paraphrased problem context:** The C function f(int x,int y) runs for(int i=0;i<y;i++){x=x+x+y;} and returns x. Which statements hold in the intended integer model? A f(20,10)>2²⁰; B f(20,20)>2²⁰; C f(20,10)<2¹⁰; D f(10,20)>2²⁰. The exponents are 20 and 10, not the decimal numbers 220 and 210.

## Solution

Approach: Derive a closed form for the loop instead of expanding twenty iterations individually.
1. Let x_k be the value after k iterations, with initial value x_0. Since y is unchanged, x_(k+1)=2x_k+y. Adding y gives x_(k+1)+y=2(x_k+y).
2. Therefore x_k+y=2^k(x_0+y), or x_k=2^k(x_0+y)−y. For the positive inputs listed, the loop performs exactly y iterations.
3. f(20,10)=30×2¹⁰−10=30,710. This exceeds 2¹⁰=1,024 but is below 2²⁰=1,048,576, so both A and C are false.
4. f(20,20)=40×2²⁰−20=41,943,020, and f(10,20)=30×2²⁰−20=31,457,260. Both exceed 2²⁰, making B and D true.
Answer: B and D. This trace assumes an int wide enough for these values, such as a 32-bit signed int. On a narrow implementation signed overflow would invalidate the mathematical trace; the original does not specify int width.

Assume argument expressions are evaluated right to left. Output choices: A 20101020; B 10202010; C 20102010; D 10201020.

## Solution

Approach: Separate the calls that evaluate arguments from the calls inside f.

2. Explanation and checks. The event trace is h(20): print 20, return 20; g(10): print 10, return 10; enter f with x=10,y=20; g(x): print 10; h(y): print 20. Reversing evaluation order does not swap the formal parameters: the first argument still supplies x. The explicit right-to-left assumption applies to evaluating the argument expressions, not to reversing the two statements in the body of f.

**Official answer:** A;B;D

**Derived answer:** A;B;D

**Paraphrased problem context:** In C, fX(char *a) sets char *b=a, executes while(*b) b++, then returns b−a as int. Which claims are true? A fX("abcd") returns; B with char c[]="abcd", fX(c) returns; C the function does not compile; D with char *c="abcd", fX(c) returns.

## Solution

Approach: Trace the pointer until the null terminator and distinguish reading a literal from modifying it.

1. Derivation. The pointer b advances until it reaches the terminating null byte and returns the element difference b−a, the string length. Each stated argument is a valid null-terminated four-character string, so each call returns 4. The function only reads characters; it does not modify string literals. Therefore A, B, D are true and the code is valid C. Pointer subtraction here is within the same array and the small result fits int.

2. Explanation and checks. The bytes at offsets 0,1,2,3 are a,b,c,d and are nonzero, so the loop advances four times. At offset 4 the terminating zero makes the condition false. Both pointers remain associated with the same character array, so subtraction gives four elements. The function never assigns through either pointer, and the supplied arguments are terminated, avoiding two common string errors. These are C examples; a stricter C++ string-literal type rule is not the language specified.

**Paraphrased problem context:** C code declares double a[2]={20.0,25.0}; sets p=a and q=p+1; and prints "%d,%d" with (int)(q−p), (int)(*q−*p). Which output? A 4,8; B 1,5; C 8,5; D 1,8.

## Solution

Approach: Evaluate the pointer expression and the dereferenced arithmetic expression separately.

1. Derivation. p points to a[0] and q=p+1 points to a[1]. Pointer subtraction counts array elements, not bytes, so q−p=1. The values differ by 25.0−20.0=5.0, cast to 5. The output is 1, 5, option B, independent of sizeof(double).

2. Explanation and checks. Adding one to a double pointer moves by the storage occupied by one double, but subtracting two double pointers converts the byte displacement back into an element count. Thus it is one regardless of the implementation’s double size. Dereferencing yields the numeric values 25.0 and 20.0, whose difference is exactly 5.0 here. The integer casts produce 1 and 5 for the two %d arguments; they do not turn the pointer difference into a byte distance.
