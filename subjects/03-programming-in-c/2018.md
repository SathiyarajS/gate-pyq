**Question:** [Official archived paper page 4](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** A

**Derived answer:** A under conventional layout and character encoding

**Source access:** Open archive member CS/CS2018.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** C declares struct Ournode { char x,y,z; }; initializes p={'1','0','a'+2}; sets q=&p; and prints printf("%c, %c", *((char*)q+1), *((char*)q+2)). Choices: A 0, c; B 0, a+2; C '0', 'a+2'; D '0', 'c'.

## Solution

Method and intermediate reasoning:

The cast occurs before pointer arithmetic: a char pointer advances by one byte, whereas adding 1 to a struct pointer would advance by a whole struct. Under the intended layout, offsets 1 and 2 select y and z. The expression 'a'+2 is evaluated numerically during initialization, not printed as source text. The %c conversion prints the represented character without surrounding quote marks. Keep the implementation assumptions below separate from the intended exam output.

Derivation, answer and qualifications:

With consecutive char members at byte offsets0, 1, 2, the two dereferences read y and z. In an ASCII-compatible execution character set, y is the character0 and z is c from a+2, giving0, c, A. Strict ISO C permits internal struct padding and does not universally require contiguous alphabetic codes. The result therefore assumes the conventional padding-free char layout and character encoding used by the question.

**Official answer:** 4 to 4

**Derived answer:** 4 in intended call-count model; signed-overflow caveat

**Source access:** Open archive member CS/CS2018.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Global int counter starts at 0. calc(a,b) increments counter, returns a*a*a if b==3, otherwise sets c=calc(a,b/3) and returns c*c*c. main calls calc(4,81), discards its return, then prints counter. Find the intended output.

## Solution

Method and intermediate reasoning:

Count activations on the descent separately from arithmetic on the return path. Calls occur at b=81,27,9,3; the last still increments counter before testing the base case. Unwinding produces mathematical values 4³,4⁹,4²⁷,4⁸¹. Already 4²⁷=2^54 exceeds a signed 32-bit range, and the final 2^162 exceeds signed 64-bit range. Thus counting gives the intended answer, but actual C execution is not guaranteed once signed overflow occurs.

Derivation, answer and qualifications:

The b arguments are81, 27, 9, 3, so counter is incremented four times before the base return. The intended answer is 4. However the return computation then cubes repeatedly to 4^81=2^162, overflowing signed int on ordinary32-bit or64-bit implementations. Signed overflow is undefined behavior in C even if main discards the return value, so the printed result is not portable without sufficiently wide integer arithmetic or an explicit abstraction that ignores overflow.

**Paraphrased problem context:** In C, str1="Hi", str2="Bye". fun1(char *s1,char *s2) swaps its local pointer variables using a temporary. fun2(char **s1,char **s2) swaps *s1 and *s2. main calls fun1(str1,str2), prints both strings, calls fun2(&str1,&str2), then prints both. Choices A Hi Bye Bye Hi; B Hi Bye Hi Bye; C Bye Hi Hi Bye; D Bye Hi Bye Hi.

## Solution

Method and intermediate reasoning:

C passes arguments by value in both calls. In fun1 the copied values happen to be addresses of characters, so replacing those local copies cannot replace main’s variables. In fun2 the copied values are addresses of main’s pointer variables; dereferencing them selects those actual variables, which the assignments can modify. Neither routine edits the string literals. This distinction is between swapping pointed-to pointers and swapping local pointer copies, not between two language-level parameter-passing modes.

Derivation, answer and qualifications:

fun1 swaps only local copies of the pointer values, leaving main’s strings unchanged: Hi Bye. fun2 receives their addresses and swaps the actual pointer variables, so the second output is Bye Hi. The whole output is Hi Bye Bye Hi, A.

## Solution

Method and intermediate reasoning:

The first loop sees i=2^40,2^39,…,2 before stopping at i=1, so its body runs 40 times. The second loop then uses integer division: 40→20→10→5→2→1. It executes for the first five of these values, not for the final 1. The two loops are consecutive, not nested: multiplying their iteration counts would not describe the return value. The exponent in 2^40 is essential and can be lost in text extraction.

Derivation, answer and qualifications:

The visually checked input is 2^40, not240. The first loop halves i until1, performing40 iterations, hence j=40. The second loop has j values 40, 20, 10, 5, 2 before stopping at 1, so sum=5, B.

# GATE 2018 CS: Q55 (printed CS Q45)

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 10230 to 10230

**Derived answer:** 10230

**Source access:** Open archive member CS/CS2018.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Count(x,y) does nothing if y==1. Otherwise, if x!=1 it prints * and calls Count(x/2,y); if x==1 it calls Count(1024,y−1). Integers use truncating division. How many prints result from Count(1024,1024)?

## Solution

Method and intermediate reasoning:

Separate the fast-changing variable x from the outer progress variable y. For each y>1, x halves ten times, since 1024=2^10. The x=1 call performs no print and starts the next y cycle with x reset. Values of y that produce prints are 1024 down through 2, a total of 1023, not 1024. The terminal y=1 call returns immediately, regardless of its x value. This counts executed print statements, not recursive invocations.

Derivation, answer and qualifications:

For a fixed y>1, x takes 1024, 512,..., 2, yielding10 prints before reaching1. Then y decreases by 1 and x resets to 1024. This occurs for y=1024, 1023,..., 2, namely1023 rounds. At y=1 the function stops without printing. Therefore there are10*1023=10230 prints in the abstract pseudocode model.
