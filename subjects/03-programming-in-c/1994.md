

# GATE 1994: Q52 (printed A Q6)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** x^n for n≥0 under exact arithmetic; 1 for n<0.

**Essential problem context (paraphrased):** What function of integer x,n is computed by this program?
function what(x,n):
  value := 1;
  if n > 0 then begin
    if n mod 2 = 1 then value := value*x;
    value := value*what(x*x,n div 2);
  end;
  return value;

## Solution

1. For n≤0 the conditional is skipped and the return value is one.

2. Write positive n=2k+r, where r∈{0,1}. The function returns x^r times what(x²,k).

3. Induct on n. The recursive argument k<n, and the induction hypothesis gives (x²)^k. Hence the result is x^(2k+r)=x^n.

4. The recursion depth and multiplication count are O(log n). Fixed-width integer overflow can change the numerical result; no word size is specified.

# GATE 1994: Q74 (printed B Q21)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** n=16 under the stipulated 4-byte-per-activation model, counting the initial fib call.

**Essential problem context (paraphrased):** fib(n)=1 for n=0 or 1; otherwise fib(n)=fib(n−1)+fib(n−2). The available stack is 64 bytes. Each activation stores only a 2-byte return address and a 2-byte integer parameter. Estimate the largest nonnegative n without overflow. GateForum prints parameter “1” in the header but uses n in the body; GFG uses n.

## Solution

Each active invocation occupies 2+2=4 bytes, so the stack can hold 64/4=16 simultaneously active invocations. The relevant quantity is peak recursion depth, not the exponentially growing total number of calls: completed calls return and free their space before their siblings finish.

Let D(n) be the largest number of simultaneously active fib frames, including the current frame. D(0)=D(1)=1, and for n≥2, D(n)=1+max(D(n−1),D(n−2)). It follows that D(n)=n for n≥1. For example fib(3)→fib(2)→fib(1) contains three active frames; the longest chain from fib(n) descends through n−1,n−2,…,1. The alternative final call at zero has no extra level, because fib(1) is a base case and does not call fib(0).

Therefore n=16 uses exactly 64 bytes, while n=17 needs 68 bytes. Both base cases need just four bytes. This estimate assumes the full 64 bytes are available to fib, its initial activation is stack-resident, and intermediate results, frame links, saved registers and runtime bookkeeping incur no further stack charge, exactly as stipulated. A real implementation may need more storage. Excluding the initial activation would shift the numerical bound to 17, but that is a different accounting convention, not the model used here.
