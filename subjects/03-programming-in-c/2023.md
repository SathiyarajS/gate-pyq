**Type / marks:** NAT, 1 mark(s).

**Official answer:** 7 to 7

**Derived answer:** 7

**Paraphrased problem context:** In C, funcp has static int x=1, then increments x and returns it. main declares separate int x,y, executes x=funcp(); y=funcp()+x; and prints x+y. What integer is printed?

## Solution

The static local x in funcp persists across calls. Its first call increments 1 to 2 and returns 2, assigned to main’s x. The second increments the same static value 2 to 3; main’s y becomes 3+2=5. Therefore main prints x+y=2+5=7. The local static and main’s x are distinct objects.

Teaching detail. A static local has block scope but static storage duration: its initialization occurs once, and the stored value survives a return from the function. It is not reinitialized to 1 at each invocation. Track the function's private x separately from main's x to avoid accidental overwriting: after the first call they both happen to equal 2, but the second call changes only the static variable to 3. main's previously stored x remains 2 and participates in both subsequent arithmetic expressions.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** A

**Derived answer:** A

**Paraphrased problem context:** main calls f1(), f2(2), f3() in that order. f1 returns 1; f3 returns 5. f2(X) first calls f3(), then returns f1() if X==1, otherwise returns X*f2(X−1). Describe its activation tree and identify the matching source option.

## Solution

main has three ordered children f1, f2(2), f3. The f2(2) activation first calls f3 and then recursively calls f2(1). That activation calls f3 and, because X=1, calls f1. Thus f2(2) has children f3, f2(1), and f2(1) has children f3, f1. This is activation tree A, visually verified.

Teaching detail. An activation-tree node represents one invocation, not one distinct function name. The recursive f2 calls at arguments 2 and 1 therefore occupy different nodes. The ordered tree is main[f1, f2(2)[f3, f2(1)[f3,f1]], f3]. Returning a value does not create another activation, so multiplying by X adds no node. Likewise the final f3 called by main is a sibling of f2, not a descendant. This trace verifies both call nesting and left-to-right sibling order.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** C

**Derived answer:** C under left-before-right recursive evaluation; order not fixed by C

**Paraphrased problem context:** The binary tree has root 10, left child 5 with leaves 3,8, and right child 11 with right leaf 13. C function foo(NULL) returns 0; otherwise it evaluates retval=p->val+foo(p->left)+foo(p->right), prints retval, and returns retval. Find the output under the intended left-before-right evaluation, and explain the C-language caveat. Source options include C: 3 8 16 13 24 50.

## Solution

Each call returns its subtree sum and prints that sum after both child calls. The leaf sums are 3, 8, 13; the subtree rooted at 5 sums 16; that at 11 sums 24; the root sums 50. If the left recursive operand is evaluated before the right, the output is 3 8 16 13 24 50, official C. However C does not specify operand evaluation order for +. Evaluating the right subtree first can instead print13 24 3 8 16 50, and the two left leaves may also appear in either order. The printed order is therefore not portable as written; the final return value 50 is stable. Preserve the official answer with this missing evaluation-order assumption disclosed.

Teaching detail. For a node u, the return value obeys sum(u)=value(u)+sum(left)+sum(right), with sum(NULL)=0. The print is after both recursive returns, so children print their subtree totals before their parent prints. The left subtree total is 3+5+8=16; the right is 11+13=24; the root is 10+16+24=50. The parenthesization of additions does not impose an evaluation order on function-call operands in C. The key's ordering is therefore an intended traversal convention, not a portable consequence of the written expression.
