**Paraphrased problem context:** Consider this C function:
void swap(int a, int b) {
  int temp; temp = a; a = b; b = temp;
}
To exchange caller variables x and y, which statement is correct?
Options:
(A) Call swap(x,y)
(B) Call swap(&x,&y)
(C) swap(x,y) cannot be used because it returns no value
(D) swap(x,y) cannot be used because its parameters are passed by value

## Solution

1. The function receives local copies a and b. Swapping those copies does not modify the caller’s x,y, so D.

2. A void function can modify caller objects through pointers, but this function’s parameters are int, not int*, and calling it with addresses does not repair its body.

3. Teaching check: Trace x=3,y=8: entry makes local a=3,b=8; the body leaves a=8,b=3, but x=3,y=8. A correct pointer-based version would take int *a,int *b and exchange *a,*b. A return value is not essential for that alternative.

**Paraphrased problem context:** For the first invocation of this C function, what does f(1) return?
int f(int n) {
  static int i=1;
  if(n>=5) return n;
  n=n+i; i++;
  return f(n);
}
Options:
(A) 5
(B) 6
(C) 7
(D) 8

## Solution

1. On the first call, n=1,i=1; the update yields n=2,i=2. The next call yields n=4,i=3, then n=7,i=4.

2. Since7≥5, that call returns7 and the result propagates back, C. This assumes f(1) is the first call, since static i persists across calls.

3. Teaching check: Static storage is initialized once, not once per recursive activation. The entry states (n,i) are (1,1),(2,2),(4,3),(7,4). Replacing static i with an ordinary local initialized to 1 would produce a different trace and return 5.

**Independently derived answer:** A

**Paraphrased problem context:** An input nonnegative integer has original digits d1 d2 … dm. The fragment is:
int n, rev; /* n contains the input */
rev=0;
while(n>0) {
  rev=rev*10+n%10;
  n=n/10;
}
Which invariant holds after iteration i? Assume integer division and no overflow; digit strings denote numeric values.
Options:
(A) n=d1…d_(m−i) AND rev=d_m d_(m−1)…d_(m−i+1)
(B) n=d_(m−i+1)…d_(m−1)d_m OR rev=d_(m−i)…d2 d1
(C) n≠rev
(D) n=d1 d2…d_m OR rev=d_m…d2 d1

## Solution

1. After i iterations, n is the original prefix d1...d_(m−i), and rev is the processed suffix in reverse order d_m d_(m−1)...d_(m−i+1), A. Each step removes n’s final digit and appends it to rev.

2. The notation describes numeric digit values, so leading zeros in the reversed suffix do not change the value; assume the input is supplied nonnegative and the reversed value fits int.

3. Teaching check: For input 1234, successive (n,rev) pairs are (123,4),(12,43),(1,432),(0,4321). This verifies both halves of the invariant simultaneously. An OR condition that merely describes the initial or final arrangement does not express the state after every iteration.

**Paraphrased problem context:** What is printed by this C fragment? Assume appropriate declarations/includes for i, strlen and printf.
char p[20];
char *s="string";
int length=strlen(s);
for(i=0;i<length;i++) p[i]=s[length-i];
printf("%s",p);
The %s format follows GFG. GateForum visibly prints a malformed alternate format rather than %s.
Options:
(A) gnirts
(B) string
(C) gnirt
(D) No output is printed

## Solution

1. The source length is6. At i=0, p[0]=s[length−0]=s[6], which is the string terminator.

2. Consequently printf with %s sees an empty string immediately, regardless of later copied characters, and prints nothing, D. This uses the GFG reproduction’s %s format and assumes surrounding declarations/includes for i and the library functions.

3. The alternate retypesetting mangles the printf format, so it is not used to silently change the code.

4. Teaching check: The source string positions are 0:s,1:t,2:r,3:i,4:n,5:g,6:\0. The very first assignment copies position 6 into p[0]. To reverse properly one would start at length−1 and terminate the destination, but do not silently repair the given fragment before predicting its output.

# GATE 2004: Q41 (printed CS Q41)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** What does this C-style fragment compute for positive integers x,y?
m=x; n=y;
while(m!=n) {
  if(m>n) m=m-n;
  else n=n-m;
}
printf("%d",n);
GFG option A is division by repeated subtraction; GateForum prints x+y instead.
Options:
(A) x/y by repeated subtraction
(B) x mod y by repeated subtraction
(C) Greatest common divisor of x,y
(D) Least common multiple of x,y

## Solution

1. For positive x,y, each iteration replaces the larger of m,n by its difference with the smaller. This preserves gcd(m,n), keeps both positive, and strictly decreases m+n until m=n.

2. The printed common value is gcd(x,y). This is not ordinary repeated subtraction for division: the roles of the two operands change.

3. Teaching check: For x=12,y=8, the pairs evolve (12,8)→(4,8)→(4,4), so the answer is 4. Every common divisor is preserved by subtracting one operand from the other. The positive decreasing sum proves termination, completing both partial correctness and progress.
