**Paraphrased problem context:** Why is seek latency not proportional to seek distance on a magnetic disk with concentric circular tracks?

(A) Nonuniform request distribution
(B) Arm starting and stopping inertia
(C) Higher capacity of tracks at platter periphery
(D) Unfair arm-scheduling policies

## Solution

1. A seek consists of accelerating the arm, moving it and decelerating it to settle accurately at the target track.

3. This is arm starting/stopping inertia, B. Request frequencies and track capacities do not explain the mechanical distance-time relation.

**Paraphrased problem context:** Which statements about auto-increment addressing are true? I: useful for self-relocating code. II: including it in an ISA requires an additional ALU for effective-address calculation. III: increment amount depends on the accessed data-item size.

(A) I only
(B) II only
(C) III only

3. An implementation can reuse existing arithmetic hardware; an additional ALU is not logically required. II is false, leaving C.

**Paraphrased problem context:** Which must be true of RFE (return from exception) on a general-purpose processor? I: it must be a trap instruction. II: it must be privileged. III: no exception can be allowed during its execution.

(A) I only
(B) II only
(C) I and II only
(D) I,II,III

## Solution

1. RFE restores saved execution/control state and may change privilege, so the conventional architecture restricts its use to privileged code: II. It returns from a trap rather than being required to generate one, so I is false.
2. A processor may define exceptions/faults during a return, for example invalid saved state, so III is not universally required. Therefore B under the conventional model.
3. Architectures can instead permit restricted unprivileged returns that cannot escalate privilege, so the broad must wording is architecture-dependent.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A under full-capacity inclusion convention

**Paraphrased problem context:** Which are necessary for L1/L2 cache inclusion? I: L1 must be write-through. II: L2 must be write-through. III: L2 associativity must exceed L1 associativity. IV: L2 must be at least as large as L1.

(A) IV only
(B) I and IV only
(C) I,II,IV only
(D) I,II,III,IV

## Solution

1. For every resident L1 block also to be represented in L2 while L1 can use its full capacity, L2 must be at least as large: IV. Write-back can be compatible with inclusion via appropriate dirty-state and invalidation handling, so I and II are not required.
2. Equal associativity can satisfy inclusion; it need not be strictly greater, so III is false. Hence A under the standard capacity convention.
3. A policy that deliberately underutilizes a larger L1 through back-invalidations could preserve resident-set inclusion with a smaller L2, so IV is not a purely set-theoretic necessity without the full-capacity convention.

**Paraphrased problem context:** Which are NOT true in a pipelined processor? I: bypassing handles all RAW hazards. II: register renaming eliminates all register-carried WAR hazards. III: dynamic branch prediction eliminates control-hazard penalties.

(A) I and II only
(B) I and III only
(C) II and III only
(D) I,II,III

3. Dynamic prediction can still choose the wrong branch direction, requiring recovery. III is false. The NOT-true statements are I and III, B.

**Paraphrased problem context:** Overlapping multiple register windows reduce memory accesses for which items? I: function locals and parameters. II: register saves and restores. III: instruction fetches.

(A) I only
(B) II only
(C) III only
(D) I,II,III

## Solution

1. A function’s locals and parameters can stay in its register window instead of memory, reducing I.

**Paraphrased problem context:** In an execution pipeline, when can the data TLB be accessed at the earliest?

(A) Before effective-address calculation starts
(B) During effective-address calculation
(C) After effective-address calculation completes
(D) After data-cache lookup completes

## Solution

1. The data TLB maps a virtual page number to a physical frame number. The virtual page number comes from the effective address of the data operand.
2. In the conventional sequential stage model, effective-address calculation must finish before that page number is available for translation. This gives C.
3. Waiting until the cache lookup ends is unnecessary. Speculative or overlapping translation in optimized microarchitectures is a separate implementation possibility, so the statement is not a universal physical restriction.

**Paraphrased problem context:** A machine has a 64-KiB, two-way set-associative data cache with 16-byte blocks, managed using 32-bit virtual addresses; pages are 4 KiB. A row-major double ARR[1024][1024] starts at the beginning of virtual page 0xFF000. A double occupies 8 bytes. The cache is initially empty, there is no prefetching, and only ARR causes data-memory references. The code is:
for(i=0;i<1024;i++)
 for(j=0;j<1024;j++) ARR[i][j]=0.0;
What is the total tag storage in the cache directory?

(A) 32 Kibits
(B) 34 Kibits
(C) 64 Kibits
(D) 68 Kibits

## Solution

1. The 64-KiB cache with 16-byte blocks contains 4096 lines. Two ways give 2048 sets, requiring 11 index bits; the byte offset needs 4 bits.
2. The 32-bit virtual address therefore leaves 32−11−4=17 tag bits per line. Total tag storage is 4096×17=69632 bits=68 Kibits, option D.
3. Valid, dirty and replacement bits are not tags and are excluded.

**Independently derived answer:** C (assuming write allocation)

**Paraphrased problem context:** A machine has a 64-KiB, two-way set-associative data cache with 16-byte blocks, managed using 32-bit virtual addresses; pages are 4 KiB. A row-major double ARR[1024][1024] starts at the beginning of virtual page 0xFF000. A double occupies 8 bytes. The cache is initially empty, there is no prefetching, and only ARR causes data-memory references. The code is:
for(i=0;i<1024;i++)
 for(j=0;j<1024;j++) ARR[i][j]=0.0;
What is the cache hit ratio for the initialization loop? The printed statement does not specify write allocation.

(A) 0%
(B) 25%
(C) 50%
(D) 75%

## Solution

1. Sequential row-major stores touch two adjacent 8-byte doubles in each 16-byte cache line. With the intended write-allocate policy and an initially empty cache, the first store misses and allocates the line, and the second store hits.
2. The hit ratio is therefore 1/2=50%, option C. The array is page-aligned and thus line-aligned.
3. No line is reused after the traversal moves beyond it, so capacity misses do not change this pairing. A no-write-allocate cache would leave every store a miss and yield 0% (A).
