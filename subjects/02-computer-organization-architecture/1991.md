**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204230/GATE1991.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** fill-in, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Low-order; high-order

**Essential problem context (paraphrased):** Which interleaving stores consecutive words in consecutive modules, and which stores them within one module?

## Solution

For M banks, low-order interleaving uses the low address bits as bank number: address j selects bank j mod M. Consecutive addresses consequently cycle through the banks, allowing overlap of sequential accesses. High-order interleaving selects the bank with high bits, leaving the low bits as the location within that bank. A consecutive run then stays in the same bank until it crosses that bank’s address range. These names describe address mapping, not whether the memory cells themselves are physically adjacent.

**Essential problem context (paraphrased):** Which operating mode is required when the 8086 CPU works with an 8087 arithmetic coprocessor? Forum misprints the CPU as 8087.

**Independently derived answer:** RQ/GT–R; LOCK–P; HOLD–S; READY–Q

**Essential problem context (paraphrased):** Match RQ/GT, LOCK, HOLD, READY with: P retain bus ownership during a critical sequence; Q insert wait states; R maximum-mode bus request/grant; S minimum-mode bus request.

## Solution

RQ/GT pins perform the maximum-mode request/grant handshake with another bus master. LOCK indicates that a protected sequence must not be interrupted by granting the bus away. In minimum mode, HOLD requests the bus and the CPU responds with its hold-acknowledge signal. READY lets slower memory or peripherals extend a bus cycle through wait states until data can be transferred safely. Thus ownership negotiation and transfer timing are distinct: READY delays a transaction but does not itself request control of the bus.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A if MAR means the virtual-address register; terminology needs qualification

**Essential problem context (paraphrased):** Which limits total address-space size: MAR width, available secondary storage, main memory, all, none?

## Solution

With v virtual-address bits, at most 2^v distinct addressable units can be named. Thus the architectural virtual-address width bounds the address space independently of how many pages are resident. Main memory limits residence, while backing storage can limit the amount of committed data, not necessarily the range of legal virtual addresses. The traditional answer A treats MAR as the register carrying that virtual address. If MAR instead denotes the post-translation physical memory-address register, its width bounds physical memory and need not equal the virtual-address width. The source does not make that distinction explicit.

**Essential problem context (paraphrased):** GFG choices: A hardware RST; B external instruction via INTA; C execute from 20H; D NOP; E none. Forum omits A and relabels the rest. What does TRAP do?

## Solution

TRAP is a nonmaskable vectored interrupt. The processor saves the return address and transfers control to its fixed vector 0024H, rather than fetching an instruction supplied by an external device via INTA. Thus 20H and NOP are wrong. The GFG phrase “executes an RST by hardware” describes that automatic restart-like transfer; it should not be confused with an external RST opcode or the normal software RST vector 20H. Forum lacks this choice, leaving its “none” alternative. The source-specific letters differ because a substantive alternative was omitted.

**Essential problem context (paraphrased):** What does ALE do: latch I/O output, disable chip select, latch address bits AD7–AD0, report TRAP enable status, none?

## Solution

The 8085 multiplexes the low eight address bits and data on AD7–AD0. Early in a bus cycle those pins carry address bits; afterward they carry data. ALE signals an external latch to capture the address during the address phase so that it remains available while the shared pins change function. It is therefore an address-demultiplexing control, not a general instruction-output latch or interrupt-status signal. The upper address bits have separate pins and do not require this same demultiplexing step.

# GATE 1991: Q43 (printed B Q7(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204230/GATE1991.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** MAR←PC; read instruction; IR←MDR, PC←PC+1; EA←zero_extend(IR[7:0])+(indexed?X:0), for word-addressed memory.

**Essential problem context (paraphrased):** A single-address CPU has 16-bit instructions; the low 8 bits are the operand-address field. Design a hardwired fetch cycle which also forms the effective address for an indexed instruction. The reproduction does not specify memory word size, address width, index-mode encoding, or a memory-ready protocol. Give register transfers.

## Solution

Use a word-addressed memory returning one 16-bit instruction per access, an address-width w≥8, PC, MAR, MDR, IR, index register X and effective-address register EA. Let I be the decoded indexed-mode condition, and Z(IR[7:0]) the zero-extended address field. These are explicit implementation assumptions, not facts supplied by the question.

T0: MAR←PC.
T1: assert memory READ; wait until READY; MDR←M[MAR].
T2: IR←MDR; PC←PC+1.
T3: EA←Z(IR[7:0]) + (I ? X : 0), modulo 2^w; finish fetch.

The operand field must come from the newly loaded IR, so effective-address formation follows T2. PC increment is independent of indexing: indexing modifies the operand address, not the address of the next instruction. The index flag is obtained from the instruction’s opcode/mode decoding; assigning it a particular bit without specification would be unjustified.

If memory is byte-addressed with an 8-bit data bus, use two reads, assemble the two bytes according to the selected endianness, and advance PC by two instead. If memory has a fixed guaranteed cycle, the READY self-loop can be replaced by the corresponding fixed number of timing states. These implementation variants do not change the essential separation of fetch, decode and address formation.

# GATE 1991: Q45 (printed B Q8(a.i))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204230/GATE1991.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 10 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 9 T-states = 3 μs, interpreting the printed mnemonic as 8085 ORI immediate.

**Essential problem context (paraphrased):** 8085 system: crystal 6 MHz; ROM 0000H–07FFH needs one wait state per access; RAM 1000H–17FFH needs none. Initially A=55H,B=AAH,C=F7H,D=10H,H=10H,L=FFH,PC=0200H,SP=17F0H, separately for each instruction. Find the instruction time for printed “ORI A,22”.

## Solution

The 8085 divides the external crystal frequency by two, giving a 3 MHz processor clock. Therefore one T-state lasts 1/3 μs, not 1/6 μs.

8085 ORI immediate is a two-byte instruction: an opcode-fetch cycle of 4 T-states and an immediate-data memory-read cycle of 3 T-states. With PC=0200H, both bytes, at 0200H and 0201H, lie in ROM. Each access adds one wait state. Total time is (4+1)+(3+1)=9 T-states, or 9/(3 MHz)=3 μs.

The accumulator’s original value affects the logical result but not this timing. The other general-purpose registers and the stack pointer are unused. The printed “ORI A,22” is not the conventional 8085 syntax, which writes only the immediate operand, e.g. ORI 22H. The implicit destination is always A. Whether the literal 22 is decimal or hexadecimal does not alter the cycle count. Treating it as register ORA A would incorrectly discard the immediate-byte read.

**Independently derived answer:** 11 T-states = 11/3 μs ≈3.667 μs.

**Essential problem context (paraphrased):** 8085 system: crystal 6 MHz; ROM 0000H–07FFH needs one wait state per access; RAM 1000H–17FFH needs none. Initially A=55H,B=AAH,C=F7H,D=10H,H=10H,L=FFH,PC=0200H,SP=17F0H, separately for each instruction. Find the instruction time for DCR M.

## Solution

The processor clock is 6 MHz/2=3 MHz, so a T-state is 1/3 μs. DCR M decrements the memory byte addressed by HL. It performs a 4-T opcode fetch, a 3-T memory read, and a 3-T memory write, for a nominal 10 T-states.

The opcode address PC=0200H is in ROM, adding one wait state. The operand address is HL=10FFH, obtained by concatenating H=10H and L=FFH. This lies in RAM’s 1000H–17FFH range, so neither the operand read nor the write adds a wait. Thus the total is (4+1)+3+3=11 T-states, or 11/3 μs≈3.667 μs.

“M” does not mean an immediate byte following the opcode; it is the indirect-memory operand at HL. The byte’s value was not specified, but every value uses the same timing. Nor is the ROM wait charged to every machine cycle merely because the program executes from ROM: each cycle’s addressed memory device determines its own wait requirement. The instruction changes arithmetic flags except carry, which is immaterial to the timing calculation.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204230/GATE1991.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 6 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Decode I/O address 40H, use an output latch, handshake flags and status tri-state buffer; poll bit 7 before each of 512 OUT operations.

**Essential problem context (paraphrased):** Design an SSI/MSI interface for an 8085 with demultiplexed addresses. OUT 40H writes an output byte; IN 40H reads INTERRUPT in bit 7 and BUFFULL in bit 0. In the supplied timing diagram active-low write assertion clears INTERRUPT; write completion latches new data and sets BUFFULL. Device active-low STROBE assertion clears BUFFULL; STROBE completion sets INTERRUPT. Supply a block schematic and program transferring 200H bytes starting at memory 3400H.

## Solution

Use an 8-bit equality decoder for address 40H gated by IO/M=1. Let SEL denote that I/O decode. Form /W=NOT(SEL AND NOT /WR) and /R=NOT(SEL AND NOT /RD). Thus memory access at 0040H cannot accidentally activate the port. The shared address is safe because read and write select different circuitry.

Schematic:
A[7:0],IO/M → address decoder → SEL → /W, /R gating.
CPU D[7:0] → 8-bit latch (transparent while /W=0) → DEVICE DATA.
/W falling → clear INTERRUPT; /W rising → close data latch, set BUFFULL.
/STROBE falling → clear BUFFULL; /STROBE rising → set INTERRUPT.
{INTERRUPT,0,0,0,0,0,0,BUFFULL} → tri-state buffer, enabled only by /R=0 → CPU data bus.

One implementation uses a BUFFULL D flip-flop with D=1 clocked by rising /W and asynchronously cleared while /STROBE=0. INTERRUPT uses D=1 clocked by rising /STROBE and asynchronously cleared while /W=0. Initialize BUFFULL=0 and INTERRUPT=1 when the device is ready. The external handshake must avoid overlapping write/acknowledge pulses that violate the flip-flops’ recovery times. Device data is stable after write completion and held until a later write. The timing diagram’s arrows refer to these separate leading/trailing edges, not merely inverse full/empty flags.

8085 program (hexadecimal literals):
    LXI H,3400H
    LXI B,0200H
WAIT_READY:
    IN 40H
    ANI 80H
    JZ WAIT_READY
    MOV A,M
    OUT 40H
    INX H
    DCX B
    MOV A,B
    ORA C
    JNZ WAIT_READY
WAIT_LAST:
    IN 40H
    ANI 80H
    JZ WAIT_LAST

BC counts 512 bytes; HL visits 3400H through 35FFH. The source RAM region for this subproblem must exist; it is independent of the smaller RAM map specified in part (a). Testing bit 7 waits for completion of the device strobe, whereas bit 0 can clear earlier at strobe assertion. The final loop waits for the last acknowledgement rather than returning with the final byte merely buffered. There is no timeout in this minimal program, so a nonresponsive device blocks indefinitely. Reading the status port does not clear either flag.
