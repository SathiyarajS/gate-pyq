**Essential problem context (paraphrased):** Octal 342 is treated as an eight-bit integer on an 8085. What decimal value does it represent? Forum options include 226 and−30.

## Solution

Convert 342₈=3·64+4·8+2=226, whose eight bits are 11100010. As an unsigned byte it is 226, GFG/Forum A. As signed two’s complement, the leading 1 gives 226−256=−30, Forum D. GFG’s faint/missing minus on its D further complicates the option mapping, so both interpretations are retained rather than asserting a unique official answer.

**Independently derived answer:** C for general base relocation; D also supports relative references

**Essential problem context (paraphrased):** Which addressing mode permits relocation without changing code: indirect, indexed, base-register, PC-relative?

## Solution

Base-register addressing forms effective address=base+stored displacement. Moving the program requires changing the base register, leaving its instruction displacements unchanged, which explains intended C. PC-relative addressing also preserves references within a uniformly moved block because both target and current PC increase by the same relocation amount; their difference stays fixed. Thus D has relocation capability too, though it is not a general replacement for every external/data reference. The scope of relocation is unstated, so C is the standard general mechanism rather than the only conceivable invariant addressing form.

The 8086 produces 20-bit physical addresses. Therefore it can address 2^20 distinct byte locations, which is 1, 048, 576 bytes, conventionally called 1 MB in this historical context. This gives A. # GATE 1998: Q81 (printed B Q15(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Use a gated hardware timer and read its frozen count.

**Essential problem context (paraphrased):** Draw an 8085-based system to measure the width of a TTL-compatible pulse. State necessary assumptions.

## Solution

One valid design uses an 8253 programmable interval timer rather than relying on uncertain software polling time. Configure counter 0 in binary mode 0, initially load N0=65535, and feed it a known clock f. Connect the measured pulse to GATE0. While GATE0 is high the counter decrements; when it falls, counting stops and the retained value N is read. Width is approximately (N0−N)/f, with one-clock quantization and gate synchronization uncertainty.

8085 AD0–AD7 ↔ shared data bus ↔ 8253 D0–D7
            └─ ALE latch → low address bus
latched address, upper address, IO/M → port decoder → /CS
8085 /RD,/WR → 8253 /RD,/WR
latched A0,A1 → timer A0,A1
known oscillator f → CLK0
TTL pulse → GATE0 and a separate readable input-port bit 0

Map counter ports to 80h–82h and control to 83h; map the pulse input latch/buffer to 90h. The input buffer must be enabled only for reads of its port. Supply the usual clock, reset, power and bus support circuitry. Gate and clock levels must meet the timer's electrical/timing specifications; synchronize an asynchronous input if required, accounting for the resulting edge uncertainty.

Require the timer to be armed while the pulse is low. The 8253 count load is not complete merely when the second byte is written: allow a complete CLK rising-and-falling sequence after that write before the measured pulse may rise. After the pulse falls, allow the gate synchronization and counter propagation to settle before latching the result. Use a suitable guard interval or ready handshake based on the chosen timer clock and device timing. Require one isolated pulse, and fewer than 65535 counted clocks. Polling must detect the high interval before its falling edge; a separate edge latch can remove that minimum-width limitation. The hardware gate, not the polling latency, determines the count. No unique numerical width follows without the input waveform and f. Other valid designs include calibrated software loops, but their instruction timing and missed-edge error must be stated.

# GATE 1998: Q82 (printed B Q15(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** HL = number of gated clocks; width ≈ HL/f.

**Essential problem context (paraphrased):** Write an 8085 assembly program to measure a TTL pulse width, stating hardware and timing assumptions. Use the counter/port design of original Q15(a).

## Solution

Use the 8253 design in part (a), with pulse bit 0 readable at port 90h. Control byte 30h selects counter 0, low-byte then high-byte access, mode 0 and binary counting. Load FFFFh. After the falling edge, control byte 00h latches counter 0 without changing its mode; read low byte first.

WAITLOW: IN 90H
         ANI 01H
         JNZ WAITLOW
         MVI A,30H
         OUT 83H
         MVI A,0FFH
         OUT 80H
         OUT 80H
WAITHIGH:IN 90H
         ANI 01H
         JZ WAITHIGH
WAITEND: IN 90H
         ANI 01H
         JNZ WAITEND
         MVI A,00H
         OUT 83H
         IN 80H
         MOV E,A
         IN 80H
         MOV D,A
         MVI A,0FFH
         SUB E
         MOV L,A
         MVI A,0FFH
         SBB D
         MOV H,A
         HLT

DE receives the frozen count N. SUB/SBB perform the 16-bit subtraction FFFFh−DE, leaving the elapsed clock count in HL. The SUB's borrow is retained across MOV and MVI, so SBB correctly handles the high byte. Divide this integer by the known clock frequency to obtain seconds; for f=1 MHz each count represents roughly 1 μs.

This is not an unrestricted pulse-capture instrument: the pulse must start only after both count bytes are written and the subsequent complete CLK rising-and-falling loading sequence has occurred. A source-side guard/ready handshake enforces this requirement; the software does not issue a timer-ready signal. Also allow at least one clock period plus the specified propagation margin after the falling edge before the latch command. Choose the external clock relative to the 8085 clock so the displayed polling/readout path already provides that settling interval, or insert a calibrated delay before OUT 83H. The pulse must last long enough to be seen by WAITHIGH, remain low during readout, and not exhaust the initial counter value. Otherwise missed pulses or wrap/terminal-count behavior invalidate the result. A ready handshake, external trigger latch and overflow indication are appropriate extensions. The answer explicitly uses a timer peripheral, whose gate capture avoids treating variable software latency as measured time.

# GATE 1998: Q85 (printed B Q18)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203837/GATE1998.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Under cold, aligned contiguous block-level accesses: 99%; l=1 contradicts 1<m≤l.

**Essential problem context (paraphrased):** A cache has l sets, block size b, k blocks per set, cache/main-memory times tc,tm. A loop of size nb executes 100 times, with n=km and 1<m≤l. Find hit ratio and discuss l=1.

## Solution

The loop contains n blocks and total cache capacity is kl blocks. Assume contiguous aligned loop blocks, ordinary block-number modulo-l indexing, no competing data/code, an initially empty cache and one counted access per loop block per pass. Since n≤kl, each set receives at most ceil(n/l)≤k loop blocks. Thus no loop block must evict another after the first pass.

The first traversal incurs n compulsory misses. The remaining 99 traversals hit on all n blocks. Out of 100n block references, 99n hit, so H=0.99. Neither tc nor tm affects this count; they would enter effective access-time calculations instead.

If b denotes b separately referenced words/instructions per block, the denominator changes: there are 100nb references, still n misses, giving H=1−1/(100b). If b is bytes while instructions have unspecified lengths, that word-reference formula cannot be asserted numerically. The definition of an access must be explicit.

The separate request l=1 is incompatible with the earlier constraint 1<m≤l. If it means keep m>1 while replacing the cache by one fully associative k-block set, then n=km>k. Under LRU and repeated cyclic scanning, every block-level access misses: by the time a block is revisited, at least k distinct blocks have intervened. H=0 at block granularity, or 1−1/b for b consecutive word references per block. This is conditional on LRU; an unspecified replacement policy can produce a different ratio. If the intended comparison instead keeps the entire loop fitting, its warmed-up behavior remains 99%. The source does not resolve these alternatives.
