**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B: position-independent code

**Essential problem context (paraphrased):** Relative addressing is most relevant to writing which application: (A) coroutines, (B) position-independent code, (C) shareable code, or (D) interrupt handlers?

## Solution

A PC-relative instruction stores an offset rather than an absolute target address. Its effective target is PC plus that offset. If both instruction and target move by the same relocation amount, the difference between them is unchanged, so the stored offset still works. Absolute addressing instead embeds a location that generally needs relocation. This is why relative addressing is associated with position-independent control transfers, subject to the architecture’s offset range and exact PC convention.

**Independently derived answer:** D: 64K words ×16 bits

**Essential problem context (paraphrased):** A ROM directly implements multiplication of two unsigned 8-bit inputs. What organization is required?

## Solution

The two input bytes together provide 16 address bits, so every possible operand pair requires one of 2^16=65,536 entries. The largest product is 255²=65,025, which needs 16 bits; therefore every stored result is a 16-bit word. The organization is 64K×16. A ROM with only 256 entries would distinguish just one operand, not all pairs, and an 8-bit output would lose the high byte of many products.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: 3

**Essential problem context (paraphrased):** How many machine cycles does an ordinary 8085 RET instruction require?

## Solution

RET first fetches its opcode. It then reads the two bytes of the saved return address from the stack, requiring two memory-read machine cycles. Those bytes restore the program counter and the stack pointer advances by two. Thus the total is one opcode-fetch cycle plus two memory-read cycles, or three. Machine cycles are not individual clock T-states, so counting clock periods instead would confuse two different timing measures.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A: alternating bits

**Essential problem context (paraphrased):** Which multiplier pattern gives frequent operations in Booth multiplication, including an alternating 1010… pattern?

## Solution

Booth recoding examines adjacent multiplier bits, with an appended low-order zero. Equal pairs 00 and 11 require no add/subtract; transitions 01 and 10 trigger addition or subtraction. An alternating pattern therefore triggers operations at almost every position. A long run of ones is cheaper because only its boundaries trigger work. Thus the alternating candidate A is worst among the listed patterns under the ordinary radix-2 Booth operation count, even though the number of shift steps remains fixed by word width.

**Independently derived answer:** A: nonuniform priority

**Essential problem context (paraphrased):** Does a daisy chain provide uniform priorities, nonuniform priorities, only support slow devices, or require a separate processor interrupt pin for every device?

## Solution

An interrupt acknowledgment or grant propagates down the chain. The first requesting device encountered captures it and prevents later devices from using that grant. Priority therefore depends on physical position in the chain, so devices have nonuniform priority. This scheme is attractive partly because it can share processor interrupt infrastructure; it does not require one processor pin for every device. Nothing in the chaining principle restricts it exclusively to slow devices.

**Essential problem context (paraphrased):** A microprogram unit has 25 control signals, at most two active in a word. Find the minimum bits; listed choices are 2,25,10,12.

## Solution

The legal output patterns are no active signal, one of 25 single signals, or one of C(25,2)=300 pairs: 326 patterns altogether. An unrestricted binary code therefore needs ceil(log₂326)=9 bits, since 256<326≤512. A decoder can map 326 of the 512 codes to these patterns, proving sufficiency. The listed 10-bit choice instead uses two independent five-bit selectors, each able to select one of 25 signals or a no-op. That practical architecture is sufficient but not information-theoretically minimal. No such field restriction is stated, so the missing 9-bit option is an explicit question/model discrepancy.

**Official answer:** Not available; no official key located.

**Independently derived answer:** GFG instruction stream outputs 00H,01H,…,FFH repeatedly; literal GateForum stream never writes the port.

**Essential problem context (paraphrased):** For an 8085-style system with output port 00H, analyze the program ORG 0100H; MVI A,00H; LXI H,0105H; OUT 00H; INR A; PCHL; HLT. What does it do to the port? GFG includes OUT and INR but calls the CPU 8052; GateForum calls it 8085 but omits OUT and INR.

## Solution

Interpret the instructions as 8085 instructions: PCHL copies HL into the program counter. The byte addresses are 0100–0101 for MVI A,00H and 0102–0104 for LXI H,0105H. Therefore the next instruction, OUT 00H, starts at 0105H. OUT occupies two bytes, INR A one, PCHL one, so the loop is OUT at 0105H, INR at 0107H, PCHL at 0108H. HLT at 0109H is never reached.

Initialization sets A=0 and HL=0105H once. Each iteration writes A to the port, increments A modulo 256, then jumps back to OUT. Consequently the port receives 0,1,2,…,255,0,…, an indefinitely repeating eight-bit count. An external DAC would turn this into a staircase ramp, but a DAC is not part of the stated hardware.

The two reproductions cannot be treated as one literal program. In GateForum, removing OUT and INR places PCHL itself at 0105H; it jumps to itself indefinitely and never performs an output operation. Thus the port remains at its previous value, which is unspecified. GFG's CPU label “8052” is incompatible with MVI, LXI and PCHL; the interpretation above uses its instruction stream and the 8085 identity stated in the other reproduction.

**Independently derived answer:** GFG: D0=01010101…, D1=00110011…, D2=00001111…; literal GateForum: no transitions caused by the program.

**Essential problem context (paraphrased):** For the output-port program ORG 0100H; MVI A,00H; LXI H,0105H; OUT 00H; INR A; PCHL; HLT., show the three least significant output-bit waveforms. Account for the differing GateForum program without OUT and INR.

## Solution

Sample immediately after successive OUT instructions. The low-three-bit output words are 000,001,010,011,100,101,110,111,000,… . Reading each column gives D0: 0 1 0 1 0 1 0 1; D1: 0 0 1 1 0 0 1 1; D2: 0 0 0 0 1 1 1 1. These eight samples repeat. Between output writes the port latch holds its previous value, so each column is a rectangular waveform, not a series of impulses.

If Δ is the interval between writes, D0 has period 2Δ, D1 period 4Δ and D2 period 8Δ, all with 50% steady-state duty cycle. In normal 8085 timing OUT takes 10 T-states, INR A takes 4 and PCHL takes 6, so Δ=20 T-states without interrupts or wait states. Their periods are therefore 40,80,160 T-states. If only qualitative waveforms are required, the relative periods suffice.

Initialization precedes the first write, so the output before that write is not specified. This result belongs to the GFG instruction stream interpreted as 8085. The shorter GateForum stream self-loops at PCHL without touching the port; its output bits remain at their unspecified prior levels and no counter waveform can be inferred.

# GATE 1996: Q91 (printed B Q25)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 0.015 of processor time, i.e. 1.5%.

**Essential problem context (paraphrased):** A 50 MHz processor uses DMA for a disk transferring 2000 Kbytes/s continuously. The average DMA block is 4 Kbytes. Each transfer needs 1000 processor cycles for setup and 500 processor cycles for its completion interrupt. What fraction of CPU time is consumed by disk handling?

## Solution

First count transfers rather than bytes: 2000 Kbytes/s divided by 4 Kbytes/transfer is 500 transfers/s. The same meaning of K occurs in both quantities and cancels, so decimal versus binary K does not change this rate.

The processor performs 1000+500=1500 cycles of administrative work for every transfer. At 500 transfers/s this costs 750,000 CPU cycles/s. A 50 MHz processor supplies 50,000,000 cycles/s, so the fraction used is 750,000/50,000,000=0.015, or 1.5 percent.

An equivalent time calculation checks the units. Each processor cycle lasts 1/(50×10^6) s=20 ns. Setup takes 20 microseconds and the completion handler takes 10 microseconds, totaling 30 microseconds per transfer. Transferring 4K bytes at 2000K bytes/s takes 0.002 s=2 milliseconds; 30 microseconds/2 milliseconds again equals 0.015. The transfer uses DMA, so the CPU is not charged for executing an instruction per byte. The calculation counts only the specified setup and completion overhead; additional bus-contention stalls, queuing effects, or other driver costs are not given and should not be invented. The statement that the disk transfers continuously fixes the block rate at its full throughput.

# GATE 1996: Q92 (printed B Q26(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Complete-service-time model: 8KB L1 and 4MB L2 (99.2 ns). Sequential probing gives different feasible minima; see solution.

**Essential problem context (paraphrased):** A three-level hierarchy has level-1 access time 50 ns/byte and options 8KB (hit .80), 16KB (.90), 64KB (.95); level-2 access time 200 ns/byte and options 4MB (hit .98), 16MB (.99), 64MB (.995); level 3 has access time 5 microseconds/byte, size 250MB, hit 1.0. Use the GFG table; GateForum has inconsistent duplicated tables, KB/MB units and 250/260MB labels. The question does not explicitly state whether lower-level access times include earlier failed probes. Choose minimum level-1 and level-2 sizes giving average access time strictly below 100 ns.

## Solution

If the tabulated times are complete service times for a hit at the corresponding level, and h2 is conditional on missing level 1, then T=h1·50+(1−h1)h2·200+(1−h1)(1−h2)·5000. Try the smallest options first: h1=.80 and h2=.98. Their mutually exclusive outcome probabilities are .80, .196, and .004, summing to one. Hence T=40+39.2+20=99.2 ns, strictly below 100. Since 8KB and 4MB are individually the smallest listed sizes, this pair is componentwise minimal in that model.

A different standard convention treats 50,200,5000 as incremental sequential probe times. Then every access pays 50, every L1 miss pays another 200, and a miss in both pays another 5000: Tseq=50+(1−h1)[200+(1−h2)5000]. The same 8KB/4MB pair gives 110 ns and fails. At 8KB, increasing L2 to 16MB gives exactly 100 ns, still failing the strict inequality; 64MB gives 95 ns. At 16KB, the smallest L2=4MB already gives 80 ns. Thus the nondominated feasible pairs in the sequential model are (8KB,64MB) and (16KB,4MB); neither is smaller in both coordinates. Minimizing total installed bytes selects (16KB,4MB), whereas minimizing L1 first selects (8KB,64MB).

Therefore the familiar 8KB/4MB answer requires the complete-service-time interpretation. Without specifying the timing convention, the literal question has no single model-independent answer. The lower-level hit ratio is also taken as conditional, not as an additional unconditional probability.

# GATE 1996: Q93 (printed B Q26(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 99.2 ns in the complete-service-time model; sequential alternatives are 80 ns for 16KB/4MB or 95 ns for 8KB/64MB.

**Essential problem context (paraphrased):** A three-level hierarchy has level-1 access time 50 ns/byte and options 8KB (hit .80), 16KB (.90), 64KB (.95); level-2 access time 200 ns/byte and options 4MB (hit .98), 16MB (.99), 64MB (.995); level 3 has access time 5 microseconds/byte, size 250MB, hit 1.0. Use the GFG table; GateForum has inconsistent duplicated tables, KB/MB units and 250/260MB labels. The question does not explicitly state whether lower-level access times include earlier failed probes. Calculate the average time for the sizes selected to satisfy the strict 100 ns bound.

## Solution

For the complete-service-time interpretation, select the smallest listed capacities, L1=8KB and L2=4MB. An access hits L1 with probability .80 and takes 50 ns. It misses L1 and hits L2 with probability .20×.98=.196 and takes 200 ns. It misses both with probability .20×.02=.004 and takes 5000 ns. The mean is therefore .80×50+.196×200+.004×5000=40+39.2+20=99.2 ns per byte. This is 0.8 ns below the required bound. Notice that even the rare .4 percent accesses to level 3 contribute 20 ns to the mean.

This calculation uses exclusive end-to-end outcomes. If the table instead lists incremental sequential access times, earlier failed probes must also be charged: 50+.20×200+.004×5000=110 ns for these same capacities, so they would not be a valid choice. In that model, the (16KB,4MB) pair gives 50+.10×200+(.10×.02)×5000=80 ns. The alternative nondominated (8KB,64MB) pair gives 50+.20×200+(.20×.005)×5000=95 ns. The (8KB,16MB) pair gives exactly 100 ns, which is excluded by “less than”.

Thus report 99.2 ns together with its timing assumption, rather than presenting it as a verified official value. Both table-unit defects in GateForum and the unstated timing convention should remain visible to students; neither justifies inventing an official answer key.
