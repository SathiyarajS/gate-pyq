**Essential problem context (paraphrased):** A one-head disk has 200 tracks,2400 rpm and 62,500 bits per track. Find average rotational latency P in ms and transfer rate Q in bits/s.

## Solution

2400 revolutions per minute is 40 revolutions per second, so one revolution takes 25 ms. A uniformly random angular arrival waits half a revolution on average, or 12.5 ms. Reading one full track per revolution transfers 62,500·40=2,500,000 bits/s. The 200-track count affects total capacity, not the instantaneous per-head track rate or rotational delay. Seek time, controller overhead and inter-track gaps are not included in these idealized quantities.

## Solution

Only saving, servicing and restoring displace main-program execution: 10+80+10=100 μs per interrupt. Each arrival period is 1000 μs, leaving 900 μs for the main program, or 90%. **Independently derived answer:** 2001, under conventional instruction-fetch PC advancement.

**Essential problem context (paraphrased):** The CPU instruction occupies one memory word with fields OP CODE, MODE, RegR. Mode 2 uses the address in RegR to fetch the operand, then increments RegR by one. The instruction is at word address 2000 and RegR selects PC. Find the operand address.

## Solution

Use the conventional fetch sequence for a word-addressed CPU. Before instruction fetch PC=2000. Fetching the one-word instruction into the instruction register advances PC to 2001. Decoding then selects PC as the mode-2 address register. The effective operand address is the value of PC at that point, namely 2001, so the operand is the contents of memory word M[2001]. The operand fetch subsequently increments PC again, but this later value is not the operand address.

In register-transfer notation: IR ← M[PC]; PC ← PC+1; EA ← PC; operand ← M[EA]; PC ← PC+1. The addresses 2000 and 2001 respectively hold the instruction and its following operand word. This is the usual immediate-operand idiom implemented by PC autoincrement. It assumes ordinary instruction-fetch advancement of the PC, implicit in the question's CPU convention; it does not treat PC as still 2000 during operand addressing.

**Essential problem context (paraphrased):** The CPU instruction occupies one memory word with fields OP CODE, MODE, RegR. Mode 2 uses the address in RegR to fetch the operand, then increments RegR by one. The instruction is at word address 2000 and RegR selects PC. For a non-jump instruction, find PC after execution.

## Solution

There are two distinct increments. First the instruction fetch consumes the memory word at 2000 and advances PC to 2001. Next mode 2 uses the current PC as the address of the operand, reads M[2001], and increments that selected register by one. Because the selected register is PC, it becomes 2002.

The instruction is specified to be non-jumping, so no later branch-target assignment replaces this sequential address. PC=2002 therefore identifies the next instruction, after both the instruction word and its inline operand word. Do not increment a third time for execution: the next fetch has not yet happened. Conversely 2001 accounts only for instruction fetch and overlooks the addressing mode's explicit post-increment. This result uses the conventional word-addressed fetch semantics implicit in part (a).

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 13.0918 microseconds with supplying-level access plus transfers; 13.102 microseconds if serial failed probes are separately charged.

**Essential problem context (paraphrased):** A hierarchy has (access time ti seconds, access probability pi, page-transfer time Ti seconds): M1=(10^-6,0.99000,0.001), M2=(10^-5,0.00998,0.1), M3=(10^-4,0.00002,no lower level). A miss at Mi transfers a page from M(i+1) to Mi, taking Ti. Calculate mean time to read one word.

## Solution

The probabilities sum to 1, so treat them as unconditional, mutually exclusive probabilities of the level supplying the requested word, rather than three conditional hit ratios. In particular the probability that a transfer into M1 is needed is p2+p3=0.01, while the probability of a transfer from M3 into M2 is p3=0.00002. A word originally at M3 requires both transfers, not just T2.

Under the convention that each case incurs the access time of the supplying level plus the required page-transfer times, the three costs are t1, t2+T1, and t3+T2+T1. Hence
E[T] = p1*t1+p2*(t2+T1)+p3*(t3+T2+T1)
     = (0.99000*10^-6+0.00998*10^-5+0.00002*10^-4)
       +(0.00998+0.00002)*0.001+0.00002*0.1
     = 0.0000010918+0.000010+0.000002
     = 0.0000130918 seconds = 13.0918 microseconds.

This is the direct probability-weighted reading of the supplied table. The transfer contributions alone are 12 microseconds; omitting them would be a serious error despite the high first-level hit probability.

The text does not explicitly say whether failed higher-level probes consume additional ti, or whether those costs are already covered in the tabulated/transfer costs. If each request first probes M1 and each M1 miss additionally probes M2, count t1 for every request, t2 for probability 0.01, and t3 for probability 0.00002. Then E[T]=t1+0.01*t2+0.00002*t3+0.01*T1+0.00002*T2=13.102 microseconds. This alternative is a different timing model, not a rounding of 13.0918. No official key is available to resolve that convention; do not silently claim the reproduction specifies it.

# GATE 1993: Q56 (printed II-C Q20(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=13), physical page 13. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** DESCRIPTIVE, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Read five bytes from input port 20 into consecutive memory cells starting at the address stored at 5000/5001.

**Essential problem context (paraphrased):** Identify the function of this 8085 segment: LHLD 5000; MVI B,5; GET: IN 20; MOV M,A; INX H; DCR B; JNZ GET.

## Solution

LHLD is a direct memory load of a register pair, not an immediate-address load: it loads L from memory[5000] and H from memory[5001]. Let the resulting 16-bit pointer be h. MVI initializes counter B to five. Each iteration reads one byte from the designated input port into accumulator A, and MOV M,A writes it to the memory location addressed by HL.

INX H advances the pointer by one. DCR B decreases the loop count and sets the zero flag. JNZ returns to GET while that count is nonzero. Thus the five iteration-start counts are 5,4,3,2,1, and exactly five input operations occur. The writes target h,h+1,…,h+4; afterward B=0 and HL=h+5, modulo the 16-bit address space.

The numeric radix of bare literals is not explicitly supplied; using customary hexadecimal assembly notation makes the pointer cells 5000H/5001H and port 20H. The transfer structure is unchanged under another assembler's radix convention. No input-ready polling or handshaking is implemented; the program assumes each IN yields a usable byte.

**Essential problem context (paraphrased):** List the registers and addressed locations used by: LHLD 5000; MVI B,5; GET: IN 20; MOV M,A; INX H; DCR B; JNZ GET.

## Solution

L and H jointly form a 16-bit destination pointer, with L the low byte. LHLD fetches its initial low and high bytes from consecutive memory cells 5000 and 5001; it does not set HL to the literal 5000. The symbol M in MOV M,A denotes memory addressed indirectly by HL and is not another physical register.

A is the accumulator carrying the latest byte returned by IN. B is an 8-bit down-counter initialized to five; DCR B updates the zero condition used by JNZ. INX H changes the register-pair pointer, so successive MOV operations reach consecutive destination addresses. The zero flag is tested after decrement, ensuring five iterations.

The operand 20 designates an I/O port in the separate 8085 port-address space, whereas 5000 and 5001 are memory addresses. GET labels the IN instruction in code and is the branch destination. At completion the original pointer storage cells need not change, B is zero, A contains the last input value, and HL points one location beyond the five-byte output block, subject to address wraparound.
