

# GATE 2005: Q19 (printed CS Q19)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** A CPU has one interrupt-request and one interrupt-grant line. What is possible? A neither vectored interrupts nor multiple devices; B multiple devices but no vectors; C both; D vectors but only one device.

## Solution

Multiple devices can share an interrupt-request line and arbitrate using a daisy-chained grant or an interrupt controller. The selected device can then place its vector on the data bus. Therefore both multiple devices and vectored interrupts are possible, C; one request wire does not require a single interrupt source.

Teaching detail:
A request wire signals that some device needs service; it need not encode which one. Arbitration through a controller or daisy-chain grant selects one requester, which can then supply an interrupt vector over another bus. Thus one shared request/grant pair does not limit the system to one device or one fixed service routine. C is possible; actual priority/fairness depends on the arbitration design.

# GATE 2005: Q65 (printed CS Q65)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D if operand words fetched in execution; B if all three instruction words already fetched

**Paraphrased problem context:** Three-word ADD A[R0],@B uses destination indexed address A+R0 and source memory-indirect address M[B]. Opcode/modes are word 1, A and B are words 2/3. How many memory cycles in execution? A3; B4; C5; D6. Distinguish opcode-only fetch boundary from fetching all instruction words before execution.

## Solution

After fetching the opcode word, execution reads instruction word A and instruction word B (two cycles), reads destination M[A+R0] (one), reads the indirect pointer M[B] and then source M[M[B]] (two), and writes the sum to M[A+R0] (one). This totals six, D. If the phrase execution cycle instead excludes fetching ALL three instruction words, only the four operand accesses remain, B. Both reproductions lack an explicit fetch-cycle boundary; the six-cycle answer uses the conventional opcode-only initial fetch assumed by this style of question. The total including all instruction words is seven memory accesses, with no overlap or cache effects specified.

Teaching detail:
Separate instruction-word reads from operand-addressing reads. After an opcode-only fetch, two more reads retrieve A and B. Indexed destination contributes one read of its old value; indirect source contributes one read for the pointer and one for its pointed-to value. Finally one write stores the sum. That is 2+1+2+1=6. If all three instruction words were already fetched, only four accesses remain; the missing boundary definition is therefore material, not a computational error.

**Paraphrased problem context:** Match 1 A[I]=B[J]; 2 while(*A++); 3 int temp=*x; to (a)indirect,(b)indexed,(c)autoincrement addressing. A (1, c),(2, b),(3, a); B (1, a),(2, c),(3, b); C (1, b),(2, c),(3, a); D (1, b),(2, b),(3, c). GFG D begins (1, b); GateForum D begins (1, a).

## Solution

Array indexing A[I]=B[J] naturally uses indexed addressing; walking a pointer with *A++ uses autoincrement; dereferencing *x uses indirect addressing. The matching is (1, b),(2, c),(3, a), option C.

Teaching detail:
Indexed addressing adds a scaled index to an array base, matching 1. Autoincrement supplies the current pointer address and advances the pointer, matching 2. Plain dereference uses an address stored in a register or variable without an index, matching 3. Thus the mapping is 1b2c3a. These are natural implementation correspondences, not claims that a compiler must choose exactly these machine instructions.

## Solution

The cache contains 32 KiB/32 bytes =1024 lines, so its index needs 10 bits. A block offset needs log2(32)=5 bits. Of the 32 address bits, 32−10−5=17 remain for the tag. Thus (10, 17), option A.

Teaching detail:
First divide data capacity by block size to obtain 1024 distinct cache positions. Choosing one needs 10 bits. Choosing a byte within 32-byte block needs 5 low-order bits. The tag identifies which memory block is currently occupying that position, using the remaining 32−10−5=17 bits. Check 10+17+5=32. The cache’s total number of bytes is not the number of line indices.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A, conditional on forwarding

**Paraphrased problem context:** Five one-cycle stages IF instruction fetch, RD decode/register read, EX ALU/address, MA data memory (stores use data read in RD), WB register write. Instructions I1:R0←M[loc1], I2:R0←R0+R0, I3:R2←R2−R0. Total cycles from first fetch through final completion? A8; B10; C12; D15. The source does not explicitly state forwarding.

## Solution

With ordinary EX forwarding, the load-use dependency requires one bubble: I1 follows IF1, RD2, EX3, MA4, WB5; I2 follows IF2, RD3 (held through cycle 4), EX5, MA6, WB7; I3 follows IF3 (held), RD5, EX6, MA7, WB8. The add result forwards to the subtract without another bubble. Total 5+2+1=8 cycles, option A. Forwarding is not explicitly stated in either reproduction, so 8 is conditional, not a uniquely established result from the written stage definitions alone. Without forwarding, with register write/read in opposite halves of one cycle, the two RAW dependencies instead add four bubbles, producing 11 cycles, absent from the choices.

Teaching detail:
With forwarding, the memory-loaded value appears only after I1’s MA stage, so I2 cannot consume it in EX at cycle 4; stall one cycle. Its ALU result can then forward directly to I3’s EX, adding no second bubble. An unstalled three-instruction/five-stage pipeline would take 7 cycles, so the one bubble makes 8. If forwarding is absent, register availability imposes further waits; the question’s stage list alone does not justify treating 8 as universal.

# GATE 2005: Q69 (printed CS Q69)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B, approximately 25

**Paraphrased problem context:** A10 KB/s device transfers bytes individually. Interrupt overhead 4 microseconds; byte-transfer time to CPU/memory negligible. Minimum intended performance gain using interrupts rather than program-controlled polling? A15; B25; C35; D45. Interpret as CPU occupation ratio and state unit convention.

## Solution

Polling occupies the CPU throughout the interval between consecutive bytes. Using the decimal convention 10 KB/s=10000 bytes/s, this interval is 100 microseconds, whereas interrupt servicing costs 4 microseconds. CPU-time cost ratio is 100/4=25, option B. This compares CPU occupation, not device throughput, which is unchanged. With binary KB the exact ratio is 1/(10240×4×10^−6)=24.4140625; 25 is the intended rounded/conventional option.

Teaching detail:
At 10000 bytes/s a byte arrives every 100 microseconds. Polling continually tests readiness and occupies the CPU for that whole interval. Interrupt service instead occupies only 4 microseconds per byte; the rest can run unrelated work. Their CPU cost ratio is 100/4=25. This is not a 25-fold faster physical device. Binary KB changes the exact ratio, hence the declared convention matters.

**Paraphrased problem context:** Disk:16 surfaces, 512 tracks/surface, 512 sectors/track, 1 KB/sector, 3000 rpm. DMA steals a 40 ns memory cycle for each four-byte word. Maximum CPU-blocked percentage: A10; B25; C40; D50. Check exact units rather than assuming one option is exact.

## Solution

One track passes the head per revolution; surfaces and tracks determine capacity, not a multiplier of simultaneous transfer rate. Rotation rate is 3000/60=50 revolutions/s. With binary KiB, the transfer rate is 512×1024×50 bytes/s. At four bytes per stolen cycle, memory is occupied for (512×1024×50/4)×40×10^−9=0.262144 of the time, or 26.2144%. The nearest option is B (25%), but no option equals the exact result. Decimal KB gives 25.6%, still not exactly 25%; B requires approximate arithmetic.

Teaching detail:
Compute the streaming rate for the track under one active head:50 revolutions/s times 512 sectors/revolution times 1024 bytes/sector. Divide by 4 to obtain stolen cycles/s, then multiply by 40 ns/cycle. This dimensional chain yields 0.262144 seconds blocked per second. Multiplying by surfaces or total tracks would incorrectly assume simultaneous transfer from all disk positions. B is nearest, but 26.2144% is not exactly 25%.

## Solution

This supplies both a feasible schedule and a lower bound: two operand transfers plus a later result transfer cannot fit in two cycles.

All widths equal; increments must use ALU. Memory read takes two cycles: address→MAR then memory→MDR. Two-word CALL Rn, sub: opcode fetch already increments PC to second word. Execute Rn←PC+1 and PC←M[PC]. Minimum execution cycles A2; B3; C4; D5.

## Solution

At execution start PC addresses the second instruction word. A four-cycle schedule is: (1) broadcast PC to MAR and S; (2) read M[MAR] into MDR while loading the increment operand 1 into T; (3) send ALU(S+T) to Rn; (4) send MDR to PC. The external memory read does not occupy the internal bus carrying 1 in cycle 2. Three bus transfers of PC, return address, and target plus preparation of the increment require four cycles in this latched-input datapath. Thus C (4), assuming the usual constant-one ALU input/control needed for the specified increment operation, which the schematic does not explicitly draw.

Teaching detail:
Two different results must be preserved: the incremented return address and the target stored in memory. Broadcast PC to MAR and S together in the first cycle, since both need the same value. In the second, memory fills MDR while the internal bus supplies the increment constant to T. The third transfers S+T to Rn; the fourth transfers MDR to PC. Memory’s external transfer can overlap internal-bus work; counting it as another serialized internal transfer would overestimate. The constant input is a conventional control assumption explicitly identified.

## Solution

The sign is 0. The seven-bit biased exponent is 13+64=77=0x4D. The eight-bit pure-fraction field is obtained by truncation: floor(0.239×256)=61=0x3D, binary 00111101. Concatenating sign, exponent, and mantissa gives 0x4D3D, option D. No normalization or rounding is applied.

Teaching detail:

The sign 0 followed by exponent 1001101 produces the high byte 01001101=4D; the low byte is 3D. Round-to-nearest would be a different instruction, explicitly excluded here.

**Paraphrased problem context:** A 16-bit format has sign bit 15, seven-bit excess 64 exponent in 14…8, eight-bit pure fractional mantissa in 7…0; sign-magnitude. Printed 85(b): normalize the representation from(a), now storing an implicit leading 1 before the binary point, padding only zeros during shifts. Hex choices A 0A20; B 1134; C 49D0; D 4AE8. Preserve the linked truncated value, not a fresh conversion of the exact decimal.

## Solution

Part(a) stores the fraction .00111101₂ times 2^13. Moving the radix point three places right gives 1.11101₂×2^10. With the leading 1 implicit and only zeros padded, the eight stored fraction bits are 11101000=0xE8. The biased exponent is 10+64=74=0x4A, so the word is 0x4AE8, option D. This normalizes the truncated stored mantissa from part(a). Directly converting the original exact decimal to normalized form would produce different low bits; the explicit zero-fill rule is essential.

Teaching detail:
Begin with the already truncated .00111101×2^13. Shift three places to make its leading 1 sit before the point:1.11101×2^10. Drop only that implicit leading 1 and pad the remaining fraction to 11101000. The new biased exponent 10+64=74 gives high byte 4A; the fraction givesE 8. This transformation preserves the stored number exactly. Re-expanding the original decimal instead would introduce nonzero lower bits disallowed by the zero-padding premise.
