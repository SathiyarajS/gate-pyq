**Official answer:** Not available; no official key located.

**Independently derived answer:** C

## Solution

Multiple devices can share an interrupt-request line and arbitrate using a daisy-chained grant or an interrupt controller. The selected device can then place its vector on the data bus. Therefore both multiple devices and vectored interrupts are possible, C; one request wire does not require a single interrupt source.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D if operand words fetched in execution; B if all three instruction words already fetched

## Solution

After fetching the opcode word, execution reads instruction word A and instruction word B (two cycles), reads destination M[A+R0] (one), reads the indirect pointer M[B] and then source M[M[B]] (two), and writes the sum to M[A+R0] (one). This totals six, D. If the phrase execution cycle instead excludes fetching ALL three instruction words, only the four operand accesses remain, B. Both reproductions lack an explicit fetch-cycle boundary; the six-cycle answer uses the conventional opcode-only initial fetch assumed by this style of question. The total including all instruction words is seven memory accesses, with no overlap or cache effects specified.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B, approximately 25

## Solution

Polling occupies the CPU throughout the interval between consecutive bytes. Using the decimal convention 10 KB/s=10000 bytes/s, this interval is 100 microseconds, whereas interrupt servicing costs 4 microseconds. CPU-time cost ratio is 100/4=25, option B. This compares CPU occupation, not device throughput, which is unchanged. With binary KB the exact ratio is 1/(10240×4×10^−6)=24.4140625; 25 is the intended rounded/conventional option.

Three bus transfers of PC, return address, and target plus preparation of the increment require four cycles in this latched-input datapath. Thus C (4), assuming the usual constant-one ALU input/control needed for the specified increment operation, which the schematic does not explicitly draw.
