**Paraphrased problem context:** A processor supports up to 4 GB of word-addressable memory, with two bytes per word. What is the minimum address-bus width in bits?

## Solution

Using the exam’s binary memory-size convention, 4 GB=2³² bytes. A word address identifies two bytes, leaving 2³¹ addressable words and requiring 31 address bits. Decimal 4·10⁹ bytes gives the same ceiling 31.

The address bus counts addressable units, not bytes unless memory is byte-addressable. Here each address selects one two-byte word, so divide byte capacity by 2 before taking the base-two logarithm. With 31 address bits there are 2^31 distinct patterns, exactly enough for the word addresses. Thirty bits would reach only 2^30 words, or 2 GiB, so the lower width is insufficient. Data-bus width and address-bus width are separate questions.

The file has 29154·1024 bytes. Ceiling(29154/64)=456 bus acquisitions. This assumes a DMA burst retains the bus for its programmed block; cycle stealing would count differently. Decimal kilobytes would yield 445, so the binary-unit convention matters.

The file contains 29853696 bytes. A count register bounds bytes per programmed block in byte-addressable memory, so use a ceiling:455 full 64 KiB blocks carry 29818880 bytes, leaving 34816 bytes for one more block. Rounding down would leave data untransferred. If the usable maximum count is 65535 rather than 65536,455 such blocks still fall short and 456 suffice. The answer concerns block ownership episodes, not one bus acquisition per individual byte.

## Solution

Ignoring unstated register overhead, the old steady-state clock is 800 ps and the new bottleneck 600 ps. Throughput rises from 1/800 to 1/600 instructions/ps. Relative increase=(800/600−1)·100%=33.333...%, rather than the 25% decrease in clock period.

A pipeline clock must accommodate its slowest stage, so the new clock is max(600,350,500,400,300)=600 ps. Subtracting 1 and converting to percent gives 33⅓%. Computing(800−600)/800 instead measures a 25% period reduction, a different requested quantity.

**Derived answer:** B

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** An n-bit carry-lookahead adder uses gates with fan-in at most 2. What is its asymptotic addition time? A: Θ(1). B: Θ(log n). C: Θ(√n). D: Θ(n).

## Solution

With bounded fan-in 2, carry generate/propagate combines through a balanced prefix tree of depthΘ(log n). The high-order result depends on Θ(n) inputs, and depth d gates can depend on at most 2^d inputs, giving a matching Ω(log n) lower bound. Thus Θ(log n), B.

A carry can be summarized by generate and propagate signals, and adjacent summaries combine associatively. A balanced tree merges pairs, then groups of 4,8 and so on; after logarithmically many levels the needed carry information spans all bits. With fan-in bounded by 2, a constant number of levels cannot combine information from arbitrarily many positions. This restriction is why the unbounded-fan-in intuition of a single huge AND/OR gate cannot justify constant-time addition here.

**Paraphrased problem context:** A processor has 40 instructions and 24 general-purpose registers. Its 32-bit instruction has an opcode, two register fields and an immediate field. How many bits remain for the immediate?

## Solution

Forty opcodes require ceil(log₂40)=6 bits. Each of 24 registers requires5 bits, so two register fields need10. The immediate field has 32−6−10=16 bits.

An r-bit identifier distinguishes at most 2^r possibilities. Five opcode bits cover only 32 instructions, so six are needed; four register bits cover only 16 registers, so five are needed per operand. Some encodings remain unused, but fractional bit fields are impossible in this fixed-field format.

**Paraphrased problem context:** Functional units UF and UG compute F and G in 5 ns and 3 ns. Two instances of each are available. Find the minimum completion time for ten computations F(G(Xi)), i=1,…,10, ignoring other delays.

## Solution

Each of the two F units must perform at least five5 ns operations to finish ten jobs. No F can begin before the first G output at 3 ns, so makespan≥3+25=28 ns. Two G units produce pairs at 3, 6, 9, 12, 15 ns. Feed the F units continuously in paired intervals3–8, 8–13, 13–18, 18–23, 23–28. This attains28 ns.

Think in five two-job batches. The G stage finishes each batch every 3 ns, whereas F needs 5 ns, so F is the bottleneck after startup. Waiting buffers hold early G outputs while F is busy. Multiplying ten jobs by 8 ns ignores parallelism; using just 25 ns forgets the unavoidable initial G latency.

**Paraphrased problem context:** A three-stage 3 GHz pipeline has τ1=3τ2/4=2τ3. Split the longest stage into two equal stages. Ignoring pipeline-register delay, find the new frequency in GHz.

## Solution

The relation gives tau2=4tau1/3 and tau3=tau1/2; tau2 is originally longest. A3GHz clock therefore has tau2=1/3 ns and tau1=1/4 ns. Splitting tau2 creates two1/6 ns stages; the new bottleneck is tau1=1/4 ns, giving4GHz.

The original stage times are τ1=1/4 ns, τ2=1/3 ns, τ3=1/8 ns. After splitting, the four stages are 1/4,1/6,1/6,1/8 ns. The clock period is their maximum, not their average or sum. Adding one stage does not automatically multiply the frequency by four-thirds; it does so here because of these particular delays.
