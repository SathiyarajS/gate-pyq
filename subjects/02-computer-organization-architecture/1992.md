**Independently derived answer:** Dynamic internal storage must be refreshed before charge leaks away

**Essential problem context (paraphrased):** Why do some microprocessors specify a minimum as well as maximum clock frequency?

## Solution

Some processors use dynamic nodes or storage circuits that retain information as charge rather than static feedback. Clocked transitions periodically refresh or transfer that charge. If the clock is slowed excessively or stopped, leakage can corrupt stored state, imposing a minimum rate. This is an implementation property, not a universal law for every processor; a fully static design can often stop its clock while preserving state. The maximum clock rate instead arises from propagation and setup/hold timing constraints.

**Type / marks:** fill-in, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** It overlaps instruction fetch with execution and reduces fetch waiting

**Essential problem context (paraphrased):** Why does prefetching instructions into a buffer improve processing speed?

## Solution

While the execution unit works on one instruction, a fetch unit can use available bus cycles to obtain later instructions into a queue. When execution needs the next instruction, it may already be present, hiding some memory latency rather than performing fetch and execution strictly serially. The gain is conditional on resources and a sufficiently predictable instruction stream. Branches can invalidate prefetched instructions, and a saturated shared memory bus can limit overlap, so prefetch is not a guarantee of speedup for every program.

**Independently derived answer:** Literal premise impossible; 256 if the second group was intended to be one-address

**Essential problem context (paraphrased):** An 11-bit instruction with 4-bit address fields allegedly supports five two-address instructions and 32 two-address instructions. How many zero-address instructions remain?

## Solution

A two-address instruction uses eight operand bits, leaving only three opcode bits, hence at most eight distinct two-address operations. The literal total of 37 is impossible. If the second phrase is repaired to 32 one-address instructions, five primary opcodes are consumed, leaving three. Expanding each by four bits gives 48 one-address opcode patterns. After using 32, the remaining 16 patterns can each expand by another four bits into 16 zero-address patterns, yielding 256. Both copies repeat “two-address, ” so 256 is explicitly a conditional reconstruction, not a solution to the literal inconsistent specification.

**Independently derived answer:** A, C, D for conventional ALU/register slices

**Essential problem context (paraphrased):** Which bit-slice claims hold: cascade for word length; speed independent of width; no standalone program counter; only the CPU datapath?

## Solution

A bit-slice component implements a small-width arithmetic/register datapath. Cascading slices constructs a wider datapath, so A holds. Control sequencing and program-counter functions are normally supplied externally to the datapath slice, motivating C and D. Speed is not generally width-independent: carry propagation and inter-slice wiring can increase delay unless additional carry-lookahead structures are used. These claims refer to conventional datapath slices rather than every chip ever marketed in a bit-slice family; specialized sequencer components can supply the omitted control functions.

**Independently derived answer:** C: case dispatch through a jump table

**Essential problem context (paraphrased):** 8085 PCHL copies HL to PC. Which construct is it especially useful for: if/then/else, while, case, call?

## Solution

A case statement can compute an index, retrieve the selected branch address from a table into HL, then use PCHL to jump directly there. This is an indirect/computed branch rather than a fixed immediate target. Ordinary if and while control are usually implemented with conditional direct branches. PCHL also does not save a return address, so it is not a complete CALL instruction. With auxiliary code an indirect jump can participate in many constructs; C identifies the characteristic direct application, not an impossibility theorem for every other use.

# GATE 1992: Q42 (printed B Q5(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204205/GATE1992.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 180 ns for sequential cache lookup then main-memory read on a miss; 176 ns if miss latency already includes lookup or reads begin in parallel.

**Essential problem context (paraphrased):** Main memory takes 500 ns and cache 50 ns. Requests are 80% reads and 20% writes; read hit ratio is 0.9. Writes update cache and main memory simultaneously. Find average access time.

## Solution

Separate access types before averaging. A read hit costs 50 ns. Under the usual serial lookup model, a read miss first spends 50 ns discovering the miss and then 500 ns accessing main memory, for 550 ns. Therefore E[read]=0.9(50)+0.1(550)=100 ns.

The statement explicitly says write-through updates are simultaneous, so the write completes when the slower device completes: E[write]=max(50,500)=500 ns. Adding 50+500 for a write would contradict this parallel-update stipulation. No write buffer or early processor release is stated.

Weighting by request mix gives E[access]=0.8(100)+0.2(500)=180 ns. Equivalently, the overall probabilities are 0.72 read hit, 0.08 read miss and 0.20 write, giving 0.72(50)+0.08(550)+0.20(500).

There is a timing-model ambiguity: if main-memory access starts in parallel with cache lookup, or a quoted 500 ns miss time is interpreted as total latency including lookup, then a miss costs 500 rather than 550 ns. That model gives E[read]=95 ns and overall 176 ns. The text establishes simultaneous writes but does not explicitly establish read overlap; 180 ns is the serial-read result, while 176 ns requires the alternative convention. This is effective time per processor memory request, not a change to the physical 500 ns main-memory device latency.

# GATE 1992: Q43 (printed B Q5(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204205/GATE1992.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Gate each request with its mask enable and assign A to INTR1, B to INTR2, C to INTR3; optional explicit priority gating suppresses lower requests.

**Essential problem context (paraphrased):** Three devices A,B,C use interrupt request lines INTR1>INTR2>INTR3. Draw priority logic with an interrupt mask register so A>B>C.

## Solution

Define mask-register bits MA,MB,MC with 1 meaning masked (disabled). Let RA,RB,RC be pending request signals. Form eligible requests a=RA∧¬MA, b=RB∧¬MB, c=RC∧¬MC.

Schematic using the processor’s specified priority mechanism:
RA ──AND(¬MA)──> INTR1 [highest]
RB ──AND(¬MB)──> INTR2
RC ──AND(¬MC)──> INTR3 [lowest]
       ↑ three-bit interrupt mask register
Because the processor already prioritizes the three lines, this wiring suffices. If an explicit one-hot external priority network is desired, use instead:
INTR1=a
INTR2=b∧¬a
INTR3=c∧¬a∧¬b.
These equations are also a gate-level schematic: invert a and b as needed and AND the shown eligible inputs. They ensure that only the highest-priority eligible device is presented at a time.

Priority must depend on eligible requests, not raw requests: a masked A must not suppress an unmasked B or C. With all requests asserted and masks 000, A wins; with MA=1 and others 0, B wins; with MA=MB=1, C wins. With every mask bit set, no interrupt is raised.

Assume a device holds its request until acknowledged, or use pending-request latches before these gates, so a lower request survives service of a higher one. Service clears only the acknowledged source’s pending request. Mask-register writes are controlled by the processor. If the hardware convention defines 1 as enabled, replace each ¬M by M; the priority relation itself is unchanged.

# GATE 1992: Q44 (printed B Q6(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204205/GATE1992.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Map RAM 00000–3FFFF, EPROM 40000–7FFFF, EERAM 80000–803FF, I/O C0000–C000F. Literal 6K chips can be used as 64 banks of 4K; a conditional 64K-chip interpretation needs four banks.

**Essential problem context (paraphrased):** A byte-addressed processor has 20 address bits (1 MiB). It needs 256 KiB RAM, 256 KiB EPROM, 16 memory-mapped I/O devices and 1 KiB EERAM. Available chips are printed as RAM 6K×8 at 140 ns, EPROM 256K×8 at 150 ns, and EERAM 256×8 at 500 ns read/3 μs write. Design a memory map minimizing decoding complexity and show its decoding logic.

## Solution

Use K=1024 and hexadecimal byte addresses. The following aligned allocation permits a top-level 2-to-4 decoder on A19,A18:
00: 00000–3FFFF, 256 KiB RAM
01: 40000–7FFFF, 256 KiB EPROM
10: 80000–803FF, 1 KiB EERAM (remaining quadrant reserved)
11: C0000–C000F, 16 one-byte I/O registers (remaining quadrant reserved).
The I/O allocation assumes one addressed register per device; a device with multiple registers needs a correspondingly larger aligned subrange. Reset-vector placement is not specified.

Let R=¬A19∧¬A18, P=¬A19∧A18, E=A19∧¬A18, I=A19∧A18. These are active-high bank selections. EPROM has CS=P, internal address A17..A0 and output enable qualified by memory read; it is not written during normal operation.

Both reproductions really print 6K×8 RAM, not 64K×8. A simple literal implementation uses 64 such chips, exposing only their lowest 4 KiB. Connect chip address A11..A0 to processor A11..A0 and hold its extra address bit at zero. A 6-to-64 decoder on A17..A12, enabled by R, selects exactly one chip. CS_RAM[j]=R∧(A17..A12=j), 0≤j<64. This deliberately sacrifices 2 KiB per chip to obtain regular power-of-two decoding. It implements all 256 KiB without assuming an undocumented capacity. The capacity lower bound is ceil(256/6)=43 chips; packing 42 full chips plus 4 KiB of a final chip needs non-power-of-two block selection/address translation, so minimum chip count and simplest decoder are different objectives.

For EERAM form E_exact=E∧(A17..A10=0). A 2-to-4 decoder on A9,A8 selects four 256-byte chips; connect A7..A0 to each. CS_E[k]=E_exact∧(A9A8=k), 0≤k<4. For I/O form I_exact=I∧(A17..A4=0); decode A3..A0 into 16 selects. Qualify all reads/writes with the processor’s memory-cycle control, since these are memory-mapped devices. An 8085-style IO/M signal is low for these cycles. Device-specific active-low chip selects are the complements of the active-high equations.

Block diagram:
A19,A18→2:4 decoder→R→6:64(A17..A12)→RAM banks
                         P──────────────────→EPROM
                         E→zero-test A17..A10→2:4(A9,A8)→EERAM
                         I→zero-test A17..A4 →4:16(A3..A0)→I/O
A shared 8-bit data bus serves selected devices only. For a multiplexed address/data bus, latch the low address using ALE first.

If 6K was intended to be 64K, an explicitly corrected alternative replaces the RAM arrangement by four 64K×8 chips selected by A17,A16, with A15..A0 internal. This common four-chip design must not be presented as using the literal printed components. Partial decoding can omit reserved-region zero tests but creates address aliases; the exact map above avoids them.

# GATE 1992: Q45 (printed B Q6(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204205/GATE1992.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total None mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Literal 12.5 mHz needs no speed wait states. If intended 12.5 MHz, add 5 read wait clocks or 36 write wait clocks in the stated two-clock timing model.

**Essential problem context (paraphrased):** A byte-addressed processor has 20 address bits (1 MiB). It needs 256 KiB RAM, 256 KiB EPROM, 16 memory-mapped I/O devices and 1 KiB EERAM. Available chips are printed as RAM 6K×8 at 140 ns, EPROM 256K×8 at 150 ns, and EERAM 256×8 at 500 ns read/3 μs write. The processor clock is printed as 12.5 mHz and a memory transfer allows two clocks. Assuming 8085-like control signals, design extra EERAM interface logic.

## Solution

The printed unit matters: lowercase mHz means millihertz. At literal 12.5 mHz, f=0.0125 Hz, T=80 seconds and two clocks provide 160 seconds. Neither a 500 ns read nor a 3 μs write needs any speed-extension wait states. The extraordinary slowness strongly suggests a unit error, but both reproductions print mHz and an official correction is unavailable.

For the conventional intended interpretation 12.5 MHz, T=80 ns and the specified ordinary memory interval is 2T=160 ns. RAM 140 ns and EPROM 150 ns fit this idealized interval; EERAM does not. With W additional whole clocks:
Read: (2+W)80≥500 ⇒ W≥4.25 ⇒ W_read=5.
Write: (2+W)80≥3000 ⇒ W≥35.5 ⇒ W_write=36.
Total durations are 7 clocks=560 ns and 38 clocks=3040 ns. Rounding down would violate the specified device timing.

Interface block diagram:
latched address→EERAM decoder→SEL_E
SEL_E + memory RD/WR + cycle-start→operation latch / wait controller
clock→6-bit elapsed-clock counter→threshold comparators→READY
latched address + data bus + held RD/WR→four EERAM chips.
READY is high for ordinary accesses. At the beginning of a selected EERAM transfer, latch read versus write, clear the counter and assert READY low before its processor sampling point. Hold address, chip select and the applicable read/write strobe stable as the bus is stretched. At the release sampling point choose READY high only when completion will occur no earlier than 7 clocks after transfer start for a read or 38 for a write. End-of-cycle resets the controller. Equivalently, count five or 36 inserted wait clocks after the nominal two-clock interval. Gate initialization with a single cycle-start pulse so held strobes do not repeatedly reset the counter. A six-bit counter accommodates the longest interval.

These counts follow the problem’s simplified timing model. Actual 8085 READY sampling, decoder delay, setup/hold margins, write-pulse width and whether 3 μs denotes strobe time or internal programming time require the particular EERAM/processor data sheets. If writes are internally timed, latch the write data/address and wait on a busy signal rather than blindly holding a programming pulse. No exact pin waveform or additional nanosecond margin can be inferred from the supplied numbers.
