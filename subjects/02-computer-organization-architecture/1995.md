**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B: ANI F0H

**Essential problem context (paraphrased):** Which 8085 instruction clears the accumulator’s lower four bits while retaining the upper four: XRI 0FH, ANI F0H, XRI F0H, or ANI 0FH?

## Solution

F0H is binary 11110000. AND with its four high ones preserves the corresponding accumulator bits; AND with its four low zeros clears those bits. Thus ANI F0H performs the required masking. XOR would toggle selected bits instead of necessarily clearing them. ANI 0FH does the opposite mask, preserving the low nibble and clearing the high nibble. The operation is independent of the accumulator’s initial value.

**Independently derived answer:** C

**Essential problem context (paraphrased):** Choose the true statement: ROM is read/write; PC points to the last executed instruction; stack is LIFO; all instructions affect flags.

## Solution

A stack removes the most recently pushed item first, which is last-in-first-out. Ordinary ROM is not general read/write memory. A program counter conventionally identifies the next instruction to fetch or the current fetch position, not a record of the last completed instruction. Instructions such as data moves can leave flags unchanged, so not every instruction affects them. Therefore only the stack statement C is a reliable general description among these alternatives.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Essential problem context (paraphrased):** Which mechanism is directly justified by locality: interrupts, DMA, polling, or cache memory?

## Solution

Temporal locality means a recently accessed item is likely to be accessed again. Spatial locality means nearby addresses are likely to be accessed soon. A cache retains recent blocks in fast storage, exploiting both kinds of locality to avoid slower memory accesses. Interrupts and polling concern detecting events; DMA concerns moving data without the CPU handling every transfer. None depends on locality in the same direct way, so cache memory is the relevant mechanism.

**Essential problem context (paraphrased):** Which two 8085 instructions double DE and leave the result in HL: XCHG/DAD B, XTHL/DAD H, PCHL/DAD D, or XCHG/DAD H?

## Solution

XCHG exchanges the DE and HL register pairs, so HL receives the original DE. DAD H then adds HL to itself and stores the 16-bit result in HL. Thus the pair produces twice the original DE, modulo 2^16, with carry recording overflow. DAD B would add BC rather than double HL; XTHL exchanges with stack memory; PCHL changes control flow. These different effects rule out the other sequences.

**Independently derived answer:** With widened intermediates: X=EEH, Y=36H, Z=3478H; W underflows (CAH if wrapping).

**Essential problem context (paraphrased):** A and B are unsigned bytes with A=5CH and B=92H; W,X,Y are unsigned bytes and Z is a two-byte unsigned integer. Execute X:=A+B; Y:=abs(A−B); W:=A−B; Z:=A*B. Give the stored values and error conditions. GFG supplies this Y statement; GateForum prints malformed abs(bA-b).

## Solution

Convert the hexadecimal operands first: A=92 and B=146. Their sum is 238=EEH, within the unsigned-byte range 0 through 255. Their mathematical difference is −54, so its absolute value is 54=36H. The product is 13432=3478H, within the unsigned 16-bit range. Thus X and Z fit their declared destinations and Y fits if abs receives the mathematical signed difference.

W cannot represent −54. A checked implementation reports a range/underflow error; an explicitly wrapping 8-bit implementation stores −54 modulo 256=202=CAH. These are distinct execution models, not two simultaneous outcomes. If execution traps at W, the subsequent assignment to Z is not reached.

There is also an intermediate-arithmetic ambiguity: if A−B is evaluated as an unsigned 8-bit operation before abs, it becomes CAH=202 and abs leaves it unchanged, giving Y=CAH instead of 36H. Similarly Z requires multiplication in a sufficiently wide type, not truncation to a byte before assignment. The pseudocode does not specify these rules or byte order. Report Z as the word 3478H, with bytes 34H and 78H in unspecified order. The malformed GateForum Y expression cannot be executed literally with the declared variables.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 262,144,000 bytes under the standard 400-tracks-per-surface model.

**Essential problem context (paraphrased):** A disk has 8 surfaces, outer diameter 12cm, inner diameter 4cm, track spacing 0.1mm, 20 sectors per track, and 96 bytes formatting overhead per 4000-byte data sector. Find unformatted capacity.

## Solution

Tracks occupy an annulus, so use the radial width, not the difference of diameters. The usable width is (12−4)/2=4cm=40mm. At a track pitch of 0.1mm, the standard capacity model gives 40/0.1=400 tracks per surface. Eight surfaces therefore have 3200 tracks, and with 20 sectors per track there are 64,000 sectors.

Each physical sector accounts for 4000 payload bytes plus 96 overhead bytes, or 4096 unformatted bytes. Multiplying gives 64,000×4096=262,144,000 bytes. This equals 250 MiB or 262.144 decimal MB. The formatted payload capacity is instead 64,000×4000=256,000,000 bytes, a useful cross-check; the difference 6,144,000 is exactly 96×64,000.

This conventional calculation treats the annular width as 400 track pitches. Counting both boundary centerlines as tracks would require a different geometrical endpoint convention not supplied by the question. It also assumes all surfaces are usable and every track has the stated 20 sectors.

**Independently derived answer:** 4,800,000 payload bytes/s at 3600 rpm; 480,000 bytes/s at 360 rpm.

**Essential problem context (paraphrased):** For the disk in 14(a), each track has 20 sectors of 4000 payload bytes plus 96 overhead bytes each. Find bytes transferred per second between disk and memory at 3600 rpm (GFG), or 360 rpm (GateForum).

## Solution

Effective transfer rate counts payload delivered to memory, not sector formatting bytes. A complete revolution passes 20×4000=80,000 payload bytes under the active head. At 3600 revolutions per minute, the rotational rate is 3600/60=60 revolutions per second. Thus the sustained payload rate is 80,000×60=4,800,000 bytes/s, or 4.8 decimal MB/s.

GateForum prints 360 rpm. Under that literal variant the rotation rate is 6 revolutions per second and the answer is 80,000×6=480,000 bytes/s. This factor-of-ten source discrepancy must not be hidden by treating the two reproductions as identical.

The model assumes a continuous transfer from one active surface, ignores seek and rotational-start latency, and treats formatting overhead as space already occupying part of each revolution. Do not multiply the rate by eight surfaces unless simultaneous transfer from eight heads is explicitly specified. The corresponding raw byte rates including formatting would be 4,915,200 and 491,520 bytes/s, but those are not the requested effective payload rates.

# GATE 1995: Q71 (printed B Q16(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Searches up to ten bytes at 1C40H–1C49H for the first 05H.

**Essential problem context (paraphrased):** MVI B,0AH; MVI A,05H; LXI H,1C40H; CALL SUB; HLT; SUB: CMP M; RZ; INX H; DCR B; JNZ SUB; RET. What does this program do?

## Solution

B starts at decimal 10, A contains the search value 05H, and HL points to 1C40H. In 8085 notation M refers to the memory byte addressed by HL. CMP M computes flags as if subtracting that byte from A, without modifying A. If the byte equals 05H, the zero flag is set and RZ returns immediately to the caller.

On a mismatch, INX H advances the address, DCR B reduces the remaining count, and JNZ repeats while the count remains nonzero. Importantly, that JNZ tests the flags from DCR B, not the earlier comparison. After ten mismatches, B becomes zero and RET returns normally. HLT then stops the main program.

Thus the routine performs a bounded linear search, examining addresses 1C40H through 1C49H and stopping on the first match. On success HL addresses that match and B is the number of positions remaining including the matched position. On failure HL points one byte beyond the searched interval and B=0. A stays 05H throughout.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** HL=1C40H+k for first match offset k∈{0,…,9}; if absent, HL=1C4AH.

**Essential problem context (paraphrased):** MVI B,0AH; MVI A,05H; LXI H,1C40H; CALL SUB; HLT; SUB: CMP M; RZ; INX H; DCR B; JNZ SUB; RET. Find HL after execution; no memory contents are supplied.

## Solution

Let k be the offset of the first byte equal to 05H among the ten searched locations. For every preceding mismatch the program increments HL exactly once. It therefore reaches the matching address 1C40H+k after k increments. CMP sets zero and RZ returns before INX H, leaving HL pointing directly at the match. In particular, an immediate match leaves HL=1C40H; a match in the last tested byte leaves HL=1C49H.

If all ten comparisons fail, every iteration executes INX H, including the last one. Starting at 1C40H, ten increments give 1C4AH. DCR B then makes B=0 and the routine returns without testing that next address.

No single unconditional final address can be inferred because the source gives no values for memory 1C40H–1C49H. The no-match value 1C4AH is a conditional answer, not an established fact. This distinction also avoids the common off-by-one error of returning 1C49H after ten failures.

**Essential problem context (paraphrased):** A CRT has 80×25 character cells, each 9×12 pixels. Find video-buffer RAM for monochrome graphics at one bit per pixel.

## Solution

Convert the character grid into pixel dimensions first. There are 80×9=720 horizontal pixels and 25×12=300 vertical pixels. The bitmap therefore contains 720×300=216,000 pixels. At one bit per pixel it requires 216,000 bits, which is 216,000/8=27,000 bytes.

The same result follows by counting 80×25=2000 cells, each covering 9×12=108 pixels: 2000×108=216,000. This cross-check shows that the cell dimensions are not merely font metadata; they determine the graphics resolution. The result is 27 decimal kB or 27,000/1024≈26.367 KiB.

This is a tightly packed one-bit framebuffer. A 720-pixel row occupies exactly 90 bytes, so no padding is needed to reach a whole-byte row boundary. A device might allocate a larger power-of-two RAM bank or impose extra row alignment, but neither is specified. Text-mode character/attribute storage is not the requested buffer: the problem explicitly asks for monochrome graphics mode.
