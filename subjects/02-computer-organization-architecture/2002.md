## Solution

Step 1: Separate three causes of lost pipeline throughput.

Step 2: Stage imbalance makes the clock period depend on the slowest stage. A dependence can make an instruction wait until its operand is available. Conclusion and qualifications: Unequal stage delays leave faster stages waiting for the slowest. Data dependence can require stalls, and shared hardware can create structural conflicts. Each can reduce performance, so D. Suitable forwarding, scheduling or duplicated resources may mitigate particular cases, rather than making the hazards impossible.

1. Read the timing rule before doing arithmetic. R0, R1, and R2 load simultaneously on every falling edge. A downstream register therefore samples the old contents of the register before it, not the new value arriving during that same edge. Read Z after the final full adder has settled.

2. Follow one input pair through the circuit. Pair t enters R0 at edge t. Its low-bit sum and carry enter R1 at edge t+1. Its middle-bit sum and carry enter R2 at edge t+2, after which the last full adder produces the high sum bit and final carry. The delayed low bits complete the four-bit output. Thus the input captured at edge 1 first appears as a complete sum after edge 3.

3. Compute the first four operand sums, preserving the carry bit:

```text
Input pair    A     B     Decimal sum     Four-bit sum
    1        110   101       6+5=11            1011
    2        011   101       3+5=8             1000
    3        111   011       7+3=10            1010
    4        101   110       5+6=11            1011
    5–8      000   000       0+0=0             0000
```

4. Check the first sum at bit level. For 110 + 101, bit 0 gives 0+1+0 = 1, so s0=1,c1=0. Bit 1 gives 1+0+0 = 1, so s1=1,c2=0. Bit 2 gives 1+1+0 = 2, so s2=0,c3=1. The result c3s2s1s0 is 1011.

5. Apply the two-edge delay and the all-zero initial register contents. The requested sequence is:

```text
Clock edge       1     2     3     4     5     6     7     8
Z after settling 0000  0000  1011  1000  1010  1011  0000  0000
Source input     init  init   1     2     3     4     5     6
```

The initial two outputs come from the zero-filled pipeline. Input pairs 7 and 8 have not yet reached the output at edge 8. Register-by-register synchronous simulation verifies all eight reported outputs.

**Essential problem context (paraphrased):** The circuit takes three-bit inputs A=a₂a₁a₀ and B=b₂b₁b₀ and produces Z=z₃z₂z₁z₀. All registers load simultaneously on falling CLOCK edges; the clock period exceeds every circuit’s settling time. The diagram has R0 (6 bits) holding b₂,a₂,b₁,a₁,b₀,a₀. A full adder takes R0’s b₀,a₀ with carry-in 0. R1 (6 bits) holds the forwarded b₂,a₂,b₁,a₁ and this adder’s carry and sum. A second full adder takes R1’s b₁,a₁ and that stored carry. R2 (5 bits) holds the forwarded b₂,a₂, the second adder’s carry and sum, and the forwarded least-significant sum. A third, unregistered full adder takes R2’s b₂,a₂ and stored carry; its carry and sum are z₃,z₂, while R2’s stored sums directly provide z₁,z₀. What operation does this circuit implement?

## Solution

1. Identify each arithmetic stage from the source diagram. The first full adder takes a0, b0, and carry-in 0. It produces the least significant sum bit s0 and carry c1. R1 stores those values together with the delayed higher operand bits.

2. Follow the carry to the next stage. The second full adder takes a1, b1, and that same operand pair’s carry c1. It produces s1 and c2. R2 stores these along with the delayed a2,b2 and s0.

3. Finish the sum. The last full adder takes a2,b2,c2 and outputs s2 plus the carry c3. The circuit combines these with the delayed low bits as Z = c3s2s1s0. Consequently the four-bit unsigned result is exactly A+B; the leading carry is retained rather than discarded.

4. Explain why the registers matter. They delay the remaining operand bits and previously computed low sum bits along with the carry. This keeps all four output bits associated with one input pair while different pairs occupy different stages. Without those matching delays, bits from different pairs could be mixed.

5. Identify the implementation and performance. It is a pipelined unsigned three-bit binary adder, accepting a new pair each clock and producing one four-bit sum per clock after filling. A pair captured by R0 at edge t appears at Z after edge t+2 and combinational settling. It passes through three register loads, R0, R1, R2; there are two full clock intervals between its first capture and final output. This explicit convention avoids an ambiguous bare latency number.

**Essential problem context (paraphrased):** A 32-bit floating-point format has fields, from most to least significant: sign (1 bit), fraction (24 bits), exponent (7 bits). Sign 0 means positive and 1 negative. The binary point precedes the fraction bits. The exponent is stored in excess-64 representation, and the exponentiation base is 16. Represent decimal −7.5 as a normalized number in this format. Derive each field and give the complete representation in hexadecimal.

## Solution

1. Write the numeric interpretation of this particular format. For sign bit s, unsigned 24-bit fraction integer F, and unsigned stored exponent E, the value is (−1)^s × (F/2^24) × 16^(E−64). The storage order is sign, fraction, exponent, unlike IEEE 754.

2. Normalize the magnitude in radix 16. Since 7.5/16 = 0.46875 and 0.46875 = 7/16 + 8/256, we have 7.5 = 0.78₁₆ × 16¹. The leading hexadecimal fraction digit 7 is nonzero, so this is normalized. Leading zeros within that hexadecimal digit’s four binary bits are allowed in radix-16 normalization.

3. Fill each field. The value is negative, so s=1. The six-hex-digit fraction is 780000, giving F=0x780000 and fraction bits 0111 1000 0000 0000 0000 0000. The actual exponent is 1; applying excess-64 gives E=65, whose seven-bit form is 1000001.

4. Concatenate the fields without moving the exponent to the front:

```text
1 | 011110000000000000000000 | 1000001
= 1011 1100 0000 0000 0000 0000 0100 0001
= 0xBC000041
```

Equivalently, the word is (1 << 31) | (0x780000 << 7) | 65. The fraction is shifted by seven because the exponent occupies the low seven bits.

5. Decode the candidate to verify it: −(0x780000/2^24) × 16^(65−64) = −0.46875 × 16 = −7.5 exactly. No rounding is needed because the fraction has a finite binary and hexadecimal representation.

3. Find all array elements with A[0]’s index. Its block is block 0 and its cache index is 0. An index of 0 requires block number 0,512,1024,… . Within the declared array, 0≤i≤2047, so floor(i/4) ranges only from 0 to 511. Only block 0 occurs, containing A[0], A[1], A[2], A[3].

How many data-cache misses occur? Briefly justify.

## Solution

1. Count the blocks touched. The array holds 2048 four-byte elements, so its total size is 8192 bytes. With 16-byte lines, there are 8192/16 = 512 distinct array blocks, each containing four consecutive elements.

2. Trace the first reversed block. The first access, A[2047], misses because the cache is empty and loads the entire block A[2044…2047]. The next accesses A[2046], A[2045], A[2044] therefore hit. Crossing to A[2043] causes the next miss and loads the next group of four.

3. Generalize the pattern. In every group of four reversed accesses, the first is a miss and the other three are hits. No accesses outside the array intervene. The 512 array blocks have distinct cache indices, although even a smaller cache would still preserve this immediate three-hit pattern for a single uninterrupted sequential scan.

4. Multiply the counts: misses = 512×1 = 512, hits = 512×3 = 1536, total accesses = 512+1536 = 2048. All these misses are compulsory first references, not conflict misses.

5. Reverse traversal changes which element first brings in each block, but not the number of blocks touched. A direct-mapped simulation from A[2047] down to A[0] confirms the count of 512 misses.
