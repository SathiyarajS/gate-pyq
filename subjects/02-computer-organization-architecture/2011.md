**Paraphrased problem context:** A computer receives interrupts on excessive CPU temperature, mouse movement/button events, keyboard key press/release, and completed disk reads. Which should have the highest priority?

(A) Hard disk
(B) Mouse
(C) Keyboard
(D) CPU temperature sensor

## Solution

An excessive CPU temperature can imminently damage hardware or invalidate operation, so the intended protective interrupt priority places it above routine disk, mouse and keyboard events. Thus D under the stated safety-oriented priority policy.

Priority is about the urgency and consequences of delaying service, not how frequently an event occurs. A mouse or keyboard event can ordinarily wait briefly without permanent harm; a completed disk read is also routine. An overtemperature condition needs immediate protective handling, such as throttling or shutting down, to prevent damage. Hence the temperature sensor is the intended highest-priority source, rather than whichever input device generates the most interrupts.

**Paraphrased problem context:** The instruction LW R1,20(R2) loads a 32-bit memory word into R1. Its effective address is 20 plus the contents of R2. Which listed addressing mode best describes the memory operand?

(A) Immediate addressing
(B) Register addressing
(C) Register indirect scaled addressing
(D) Base indexed addressing

## Solution

The effective address is the content of R2 plus the displacement20. The memory operand is neither the literal20 nor a register value, and no scale factor is applied. Among the options this is called base indexed addressing, D; base-plus-displacement is a more precise description.

The operation can be written R1←Memory[R2+20]. Immediate addressing would use 20 itself as data; register addressing would take the operand directly from a register. Scaled indexing would multiply an index by an element size, which is absent here. Thus the listed base-indexed choice is the closest match. The memory word being 32 bits affects the load size, not the formula used to locate that word.

**Paraphrased problem context:** On a non-pipelined sequential processor, transferring 500 bytes uses this interrupt-service program: initialize address register; initialize count=500; LOOP: load one byte from device; store it to the address register's memory location; increment address register; decrement count; if count != 0 go to LOOP. Each load/store takes 2 cycles and every other statement takes 1 cycle. DMA instead needs 20 cycles for initialization/overheads and 2 cycles per byte. What is the approximate DMA speedup over the program?

(A) 3.4
(B) 4.4
(C) 5.1
(D) 6.7

## Solution

The two initializations take2 cycles. Each of 500 loop iterations uses2 cycles for load, 2 for store and 1 each for increment, decrement and branch, totaling7. Programmed transfer costs3502 cycles. DMA costs20+500×2=1020 cycles. Speedup3502/1020≈3.433, closest to 3.4, A.

Count the conditional branch even on its last, untaken execution: testing the condition is still an instruction. The loop therefore executes 500 loads, 500 stores and 1500 one-cycle bookkeeping instructions, in addition to the two initializations. DMA removes per-byte CPU loop bookkeeping but still pays its transfer cycles and setup. Speedup is old elapsed cycles divided by new elapsed cycles, not the reverse and not the difference between the two counts.

**Paraphrased problem context:** An ideal four-stage instruction pipeline has combinational delays S1=5 ns, S2=6 ns, S3=11 ns, S4=8 ns. A 1 ns pipeline register follows every stage, including the last. Approximately what is its steady-state speedup over the corresponding non-pipelined implementation?

(A) 4.0
(B) 2.5
(C) 1.1
(D) 3.0

## Solution

The non-pipelined combinational delay is 5+6+11+8=30 ns. The pipelined clock period is determined by the slowest stage plus its pipeline-register delay: 11+1=12 ns. In ideal steady state one instruction completes every 12 ns, so the conventional throughput speedup is 30/12=2.5, option B. If the non-pipelined implementation also counts a final 1 ns output register, the ratio is 31/12≈2.58, still the same approximate option. This is steady-state throughput, not the latency speedup of one instruction.

After filling, different instructions occupy the four stages concurrently. The clock cannot advance every average-stage delay; the slowest stage must finish before its register captures the result. That sets 12 ns per output instruction despite three faster stages. One instruction still traverses four pipeline cycles, but the question asks steady-state throughput. Using the ideal stage-count speedup of four would require balanced stages with negligible register overhead, neither of which holds here.

**Paraphrased problem context:** An 8 KB direct-mapped write-back cache has 32-byte blocks and 32-bit byte addresses. Metadata per cache block contains one valid bit, one modified bit, and the minimum tag bits needed to identify the mapped memory block. How many metadata bits are needed in total?

(A) 4864
(B) 6144
(C) 6656
(D) 5376

## Solution

There are 8192/32=256 cache lines, requiring 8 index bits. A 32-byte block requires 5 byte-offset bits, leaving 32−8−5=19 address-tag bits. Add one valid bit and one modified (dirty) bit per line: 21 bits per line. The metadata memory is therefore 256×21=5376 bits, option D. Data storage itself is not included.

Interpret 8 KB as 8×1024 bytes in the conventional cache model. The address splits into [19 tag bits][8 line-index bits][5 block-offset bits]. The index chooses one of the 256 lines, and the offset selects a byte within its 32-byte block. Only the tag must be stored as an address identifier; index and offset are implicit in placement. Write-back additionally needs the dirty bit to decide whether eviction must write data to memory, while valid distinguishes populated from unused entries.
