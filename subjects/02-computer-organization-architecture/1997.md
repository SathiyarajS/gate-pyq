**Essential problem context (paraphrased):** At which 8085 vector address does RST 7.5 start:0000H, 0075H, 003CH, 0034H?

## Solution

The 8085 vectored restart spacing is eight bytes. The RST 7.5 interrupt vector corresponds to 7.5·8=60 decimal, which is 3C hexadecimal. Thus the routine begins at 003CH, C. Writing 0075H would confuse the interrupt’s label with a hexadecimal address. The related RST 6.5 vector is 0034H, explaining another distractor.

**Independently derived answer:** B: proportional to log N

**Essential problem context (paraphrased):** An N-bit adder uses 4-bit 74181 ALUs and 4-bit 74182 carry generators, with N divisible by 4. What is best asymptotic addition delay?

## Solution

A four-way carry generator combines propagate/generate information for four lower-level groups. Cascading these in a balanced hierarchy reduces the number of groups by a factor of four per level. Therefore carry information traverses O(log₄ N)=O(log N) levels, followed by constant local sum-generation work. B is the best bounded-fan-in architecture among the choices. A serial chain would take linear time, but is not the best organization; constant delay would require unbounded fan-in or a different physical model.

Binary addition first gives 55H+25H=7AH. The low nibble A hexadecimal represents 10, which is invalid as one BCD digit. DAA adds 06H to correct that nibble, producing 80H. # GATE 1997: Q51 (printed A Q7(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 3 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D←D3; CLK←NAND(A15,…,A8,IO/M,NOT(/WR)); asynchronous clear from reset; Q is the port output.

**Essential problem context (paraphrased):** An 8085 must drive a one-bit output port at I/O address FF hexadecimal through a D flip-flop. The transferred bit is D3, and the output must clear at power-on. Using exactly one ten-input NAND gate, one inverter and one D flip-flop, give the interface circuit. State clock/reset polarities explicitly.

## Solution

The eight-bit I/O address FFH is all ones. In an 8085 I/O cycle, that address is duplicated on the high address bus A15…A8, so these eight nonmultiplexed lines can be decoded without adding an address latch. Do not use AD7…AD0 directly throughout the write: those pins carry the data during the data phase.

Let /WR denote the active-low write strobe and IO/M=1 denote an I/O cycle. Use the one inverter to form W=NOT(/WR). The ten-input NAND receives A15,A14,…,A8,IO/M,W. Its output is
CLK = NOT(A15·A14·…·A8·IO/M·W).

A complete connection list is:
8085 D3 → D input of the flip-flop.
A15…A8, IO/M, NOT(/WR) → the ten NAND inputs.
NAND output → positive-edge-triggered CLK.
RESET OUT → active-high asynchronous CLEAR.
Q → the one-bit output.
Any asynchronous preset input is tied inactive.

For FFH on an I/O write, CLK goes low while /WR is asserted and rises when that write ends. The positive edge captures D3 while the data is valid. For another port, a memory cycle, or a nonwrite cycle, at least one NAND input is zero and the clock remains high. Asynchronous clearing makes Q=0 during the power-on reset independently of clock activity.

The flip-flop's clear polarity matters. The above netlist chooses an active-high CLEAR so the 8085's active-high RESET OUT connects directly. With an active-low /CLR device instead, connect the same active-low power-on /RESET IN net that resets the CPU to /CLR. Do not connect RESET OUT directly to /CLR and do not silently use a second inverter. The edge and reset assumptions are explicit because the question does not specify a particular flip-flop part. This is an ideal bus-timing design, assuming normal setup/hold timing and no wait-state or reset anomaly.

# GATE 1997: Q52 (printed A Q7(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** MVI A,00H; LOOP: CMA; OUT FFH; JMP LOOP. Each steady-state half-period is 1+3+3=7 machine cycles.

**Essential problem context (paraphrased):** An 8085 must drive a one-bit output port at I/O address FF hexadecimal through a D flip-flop. The transferred bit is D3, and the output must clear at power-on. Write an 8085 program producing equal ON and OFF intervals of seven bus/machine cycles each.

## Solution

Only accumulator bit 3 affects this one-bit port. Complementing the entire accumulator is therefore enough to toggle the output: bit 3 alternates between 0 and 1. One program is

        MVI A,00H
LOOP:   CMA
        OUT FFH
        JMP LOOP

CMA takes one machine cycle, OUT takes three, and an unconditional JMP takes three. Between the end of one OUT and the end of the next OUT, the processor executes JMP, CMA and OUT. The total is 3+1+3=7 machine cycles. The same instruction path is used whether D3 is changing from 0 to 1 or from 1 to 0, so both steady-state half-periods are equal. At the FFH output port, values FFH and 00H alternate, but only their D3 bits are stored.

The initialization MVI is outside the loop and does not contribute to repeated periods. Power-on clearing ensures the initial output is low; the interval from reset release to the very first transition need not equal a later half-period. Interrupts and inserted wait states must be absent if exact timing is required.

Here “bus cycles” is interpreted as the 8085 machine-cycle count, not seven clock T-states. The instructions take 4+10+10=24 T-states in a normal execution, so a complete square-wave period is 14 machine cycles, or 48 T-states. Counting instruction bytes or taking “7” as seven T-states would give the wrong timing model.

**Essential problem context (paraphrased):** A floating-point value is n=(f,e)=f·2^e. The fractional mantissa f has 6 bits including its sign bit, in sign-magnitude form. The exponent e has 4 bits including its sign bit, also sign-magnitude. A=54.75 and B=9.75 in decimal. No rounding mode, guard-bit convention, or normalization rule is explicitly supplied; use the conventional normalized fraction 1/2≤|f|<1 and state the rounding assumption. Represent A and B in this format.

## Solution

The six mantissa bits include the sign, leaving only five fraction-magnitude bits. The four exponent bits similarly leave three bits for its magnitude, so exponents range from −7 to +7, not the biased range of IEEE formats. Use a sign bit of 0 for each positive field.

Convert the values exactly first:
54.75=110110.11₂=.11011011₂×2^6,
9.75=1001.11₂=.100111₂×2^4.
Both normalized binary fractions need more than five magnitude bits. Therefore there is no exact six-bit-mantissa representation of either input under this normalization. A finite encoding requires a rounding rule; merely truncating without saying so would hide a loss of information.

Under chopping toward zero, retain the first five fraction bits:
A: mantissa 0|11011, exponent 0|110; value .11011₂×64=54.
B: mantissa 0|10011, exponent 0|100; value .10011₂×16=9.5.
The vertical bar separates the sign from magnitude. No hidden leading bit is added; all five fraction bits are explicitly stored. The exponent fields are the sign-magnitude representations of +6 and +4.

For comparison, round-to-nearest with ties-to-even gives A=54 again but B=10, encoded as mantissa 0|10100 with exponent 0|100. B=9.75 lies exactly halfway between 9.5 and 10; the retained significand integer for 10 is even. Other tie rules may choose differently. This alternative is not an official correction: it demonstrates why the source's missing rounding policy matters. The subsequent worked addition and 3.9% error use the explicitly stated chopping model throughout.

**Essential problem context (paraphrased):** A floating-point value is n=(f,e)=f·2^e. The fractional mantissa f has 6 bits including its sign bit, in sign-magnitude form. The exponent e has 4 bits including its sign bit, also sign-magnitude. A=54.75 and B=9.75 in decimal. No rounding mode, guard-bit convention, or normalization rule is explicitly supplied; use the conventional normalized fraction 1/2≤|f|<1 and state the rounding assumption. Show the floating-point addition of A and B.

## Solution

Use the chopping encodings A≈.11011₂×2^6=54 and B≈.10011₂×2^4=9.5. To add, align both to the larger exponent +6. Shifting B's fraction right by two places gives .0010011₂×2^6. With only five fraction positions and chopping on alignment, this becomes .00100₂×2^6=8.

The stored-width addition is
  .11011 × 2^6
+ .00100 × 2^6
= .11111 × 2^6.

The mantissa is already normalized, lying between 1/2 and 1, and has five fraction bits. There is no carry that requires an exponent increment. Store mantissa 0|11111 and exponent 0|110, representing (31/32)×64=62. Both fields are within range.

Keeping guard bits changes the intermediate arithmetic but not this particular chopped final answer. With full aligned precision, the represented inputs sum to .1111111₂×2^6=63.5. Chopping that result to five fraction bits again yields .11111₂×2^6=62. Thus a final value of 62 does not establish whether guard bits were used; both stated chopping paths happen to agree here.

Under a different policy, round-to-nearest with ties-to-even encodes the inputs as 54 and 10. Their exact sum is 64=.10000₂×2^7, already representable, so the stored result is mantissa 0|10000, exponent 0|111. The true decimal-input sum is 64.5, which also rounds to 64 at this precision. The source does not choose between these policies. This solution therefore reports 62 only under chopping, with 64 as a clearly separate rounded alternative; it does not present an unspecified hardware behavior as an official answer.

**Essential problem context (paraphrased):** A floating-point value is n=(f,e)=f·2^e. The fractional mantissa f has 6 bits including its sign bit, in sign-magnitude form. The exponent e has 4 bits including its sign bit, also sign-magnitude. A=54.75 and B=9.75 in decimal. No rounding mode, guard-bit convention, or normalization rule is explicitly supplied; use the conventional normalized fraction 1/2≤|f|<1 and state the rounding assumption. Find the percentage error in the addition, to one decimal place.

## Solution

The exact mathematical sum of the original decimal inputs is A+B=54.75+9.75=64.5. With normalized five-bit fraction magnitudes and chopping as in the worked addition, the computed result is 62. The absolute error is |62−64.5|=2.5. Percentage relative error uses the exact value as denominator:

100×|computed−exact|/|exact|
=100×2.5/64.5
=100×5/129
≈3.87596899%.

Rounded to one decimal place, the error is 3.9%. If a signed percentage error were desired, it would be −3.9%, indicating underestimation; the usual unqualified percentage error is its nonnegative magnitude.

Do not divide by the computed 62, and do not use 63.5 as the reference merely because that is the exact sum of the already chopped input representations 54 and 9.5. The task concerns addition of the original A and B; input-representation error is part of the total discrepancy from 64.5. Relative to 63.5 alone the arithmetic-stage error would be a different quantity, 100×1.5/63.5≈2.4%.

The source's missing rounding policy persists into this part. Under round-to-nearest/ties-to-even the computed sum is 64, making the corresponding total percentage error 100×0.5/64.5≈0.77519%, or 0.8%. Accordingly 3.9% is a conditional derived answer under the declared chopping convention, not a uniquely verified official value.
