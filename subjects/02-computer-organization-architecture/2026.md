**Type / marks:** MCQ, 1 mark.

**Official and derived answer:** B

## Solution

Immediate addressing encodes a literal constant in the instruction, giving P to 4. Indirect addressing obtains an address through a pointer, giving Q to 2. Base-plus-index addressing selects an array element using a varying index, giving R to 1. A fixed displacement from a record base selects a record field, giving S to 3. The matching tuple is therefore (4,2,1,3), option B.

Option A uses memory operands directly in ADD; B still adds a memory operand and targets memory; C likewise tries to add memory operands before storing. Those three do not obey the stated architecture.

## Q36 — Computer Organization and Architecture: binary32 addition

Paper page 25; key page 1. MCQ, 2 marks. **Answer: C, hexadecimal 35E80000.**

1. Both operands are positive normal IEEE 754 binary32 numbers. The exponent field of 35C00000 is 107, so its unbiased exponent is −20. Its fraction field is 400000, giving significand 1.5. Thus X = 1.5 × 2^−20.
2. For 34A00000 the exponent field is 105, giving unbiased exponent −22; fraction 200000 gives significand 1.25. Thus Y = 1.25 × 2^−22 = 0.3125 × 2^−20.
3. Their sum is 1.8125 × 2^−20. Since 1 ≤ 1.8125 < 2, no exponent renormalization is required. The fraction is 0.8125 = 13/16, which has an exact terminating binary expansion.
4. The exponent bits remain 107, contributing 35800000. The stored fraction is (13/16) × 2^23 = 680000 in hexadecimal. Combining the fields yields 35E80000. No rounding error occurs here.

**Computational check:** Python struct unpacked both binary32 operands and repacked their sum, obtaining 0x35e80000. This complements the exact field-level derivation; it is not the sole justification.

## Q38 — Computer Organization and Architecture: cache address fields

Paper page 27; key page 2. MCQ, 2 marks. **Answer: A, N = M + L.**

1. Byte addresses contain 32 bits. A 128-byte block needs log2(128)=7 offset bits.
2. The cache contains 2^23 / 2^7 = 2^16 blocks. In a direct-mapped organization, there are 2^16 sets, requiring 16 index bits. Hence its tag length is M=32−16−7=9.
3. K=2^L ways reduce the set count to 2^(16−L). The set index therefore uses 16−L bits while the block offset remains 7 bits.
4. The set-associative tag length is N=32−(16−L)−7=9+L=M+L.

**Common error:** Associativity changes the number of sets, not the number of bytes per block. Offset bits do not grow with the number of ways.

# GATE 2026 CS1: Q59

**Question:** [Official master paper page 44](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=44); consult original wording and options.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 77.3 to 77.3

## Solution

At 15000 revolutions per minute, one revolution takes 60000/15000=4 milliseconds. The mean rotational latency for an independently random sector is half a revolution, or 2 milliseconds. The prescribed track visits require 5+7+5=17 adjacent-track movements, totaling 17 milliseconds. Thirty sector accesses contribute a mean rotational delay of 30*2=60 milliseconds. One sector takes 4/400=0.01 milliseconds to transfer, so transfer time is 0.3 milliseconds. The sum is 17+60+0.3=77.3 milliseconds. This is an expected-time calculation under the independent uniform rotational-position convention, not an exact realized duration determined by arbitrary unspecified sector locations. The question asks for total time without explicitly saying expected; retain the official number with this qualification.

# GATE 2026 CS1: Q60

**Question:** [Official master paper page 44](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=44); consult original wording and options.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 95 to 95

## Solution

With a one-nanosecond clock and the exercise’s single occupied EX-stage model, an operation lasting t consumes ceil(t) cycles and blocks subsequent use for ceil(t)-1 extra cycles. The listed contributions are LOAD 15*1=15, IMUL 10*1=10, IDIV 5*2=10, FADD 10*1=10, FSUB 5*1=5, FMUL 15*2=30, and FDIV 5*3=15. All remaining operations finish within one cycle and add no structural stall. The total is 95 cycles. This assumes the variable-duration EX operation prevents a new instruction from entering that stage while it is occupied; a separately pipelined functional-unit implementation would require additional architectural details.

# GATE 2026 CS1 Q16: pipeline-model qualification

Subject: Computer Organization and Architecture. MCQ, 1 mark. Official scoring answer: **B (read-after-write)**.

Sources inspected through text extraction on 2026-11-09:
- [Official master paper, page 13](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=13)
- [Official published key, page 1](https://gate2026.iitg.ac.in/doc/download/2026/Keys/CS1_Keys.pdf#page=1)

## Intended derivation

A read-after-write dependency occurs when an earlier instruction produces a register value that a later instruction consumes. If the consumer reads before the producer's result is available, it obtains stale data. A classic example is an ADD writing R1 followed by an instruction using R1. This makes B a valid data-hazard category.

In the conventional single-issue, in-order, fixed-stage pipeline, all register reads occur in an earlier fixed stage than all register writes, and instructions reach those stages in program order. Under that model, later writes cannot overtake earlier reads or writes. Thus write-after-read and write-after-write dependencies do not become pipeline hazards. Read-after-read does not overwrite a value and is not a data hazard. This model supports the intended unique selection B.

## Discrepancy / missing-model qualification

The question describes a pipelined processor without specifying the fixed-stage, in-order model. The general wording is therefore broader than the assumptions needed for a unique MCQ answer.

- A write-after-read hazard can occur when an earlier instruction is delayed before reading R1 while a later instruction writes R1 early. The earlier instruction would consume the later value instead of the old value it should have read.
- A write-after-write hazard can occur when a long-latency earlier instruction and a short-latency later instruction both write R1, but the earlier one completes last. Without ordering or renaming, the final value can incorrectly come from the earlier instruction.

Such hazards can arise in pipelines that permit the relevant execution reordering; they are not excluded merely by the word pipelined. Register renaming and appropriate scheduling can remove or prevent them, but those mechanisms are not stated in this question.
