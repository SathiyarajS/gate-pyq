**Paraphrased problem context:** Match P immediate, Q indirect, R base with index, S base with offset to 1 array element, 2 pointer, 3 record field, 4 constant. The choices give different permutations of these matches.

**Type / marks:** MCQ, 1.

**Official answer:** B

**Derived answer:** B

## Solution

Givens and goal
Match P immediate, Q indirect, R base with index, S base with offset to 1 array element, 2 pointer, 3 record field, 4 constant. The choices give different permutations of these matches.

Approach
Write the effective operand or effective address for each addressing mode and identify the high-level data access it implements.

Step-by-step solution
1. Immediate addressing puts the operand value directly in the instruction, such as an encoded literal 7. It naturally represents a constant, so P→4.
2. Indirect addressing obtains an operand’s address through another location or register. A pointer holds an address and is dereferenced to find the actual data, so Q→2.
3. Base-plus-index addressing computes an address from an array base and an index-dependent displacement, conceptually base+i·element_size. Varying i chooses an array element, so R→1.
4. Base-plus-fixed-offset addressing selects a field at a fixed byte displacement from the start of a record, such as record_base+offset_of_field. Thus S→3.
5. The complete mapping is (P,Q,R,S)→(4,2,1,3), option B. The key distinction is a varying index for array positions versus a fixed layout displacement for a named record field; both may ultimately use addition in the hardware.

**Paraphrased problem context:** X, Y and Z are memory locations. R0, R1 and R2 are registers. In a load-store architecture with destination-first syntax, select the instruction sequence implementing Z=X+Y. Options A–C use memory directly in an ADD; D loads X and Y, adds registers, and stores the result.

**Type / marks:** MCQ, 1.

**Official answer:** D

**Derived answer:** D

## Solution

Givens and goal
X, Y and Z are memory locations. R0, R1 and R2 are registers. In a load-store architecture with destination-first syntax, select the instruction sequence implementing Z=X+Y. Options A–C use memory directly in an ADD; D loads X and Y, adds registers, and stores the result.

Approach
Separate data movement from arithmetic and trace where each value resides after every instruction.

Step-by-step solution
1. A load-store ISA permits ordinary arithmetic instructions to use registers, not arbitrary memory operands. First execute LOAD R0,X, giving R0=memory[X].
2. Execute LOAD R1,Y, giving R1=memory[Y]. Both operands of the addition are now available in registers.
3. Execute ADD R2,R0,R1. Destination-first syntax means R2 receives R0+R1; it does not mean R0 is overwritten.
4. Execute STORE Z,R2. This copies the sum from R2 to memory[Z], completing the high-level assignment. This four-instruction sequence is option D.
5. A tries ADD Z,X,Y with all three operands in memory. B loads only X and still uses memory for Y and the ADD destination. C computes ADD R0,X,Y without loading either source. These violate the stated load-store arithmetic restriction even if some other ISA might allow them.

**Paraphrased problem context:** Which register dependence can cause a data hazard in a pipelined processor? A read-after-read, B read-after-write, C write-after-read, D write-after-write. The source does not explicitly constrain instruction issue or completion order.

**Type / marks:** MCQ, 1.

**Official answer:** B

**Derived answer:** B in the classic in-order fixed-stage model; WAR/WAW can also be hazards in broader pipeline models.

## Solution

Givens and goal
Which register dependence can cause a data hazard in a pipelined processor? A read-after-read, B read-after-write, C write-after-read, D write-after-write. The source does not explicitly constrain instruction issue or completion order.

Approach
Explain the true producer-consumer hazard, then state the narrower pipeline model needed to make the official MCQ selection unique.

Step-by-step solution
1. Suppose instruction I1 computes R1=R2+R3 and the following instruction I2 computes R4=R1+1. I2 must read the value produced by I1, so this is a read-after-write (RAW) dependence on R1.
2. If I2 reaches its register-read/use stage before I1’s result is available, it can read the old R1. That is a data hazard. Forwarding or a stall may be needed to preserve the intended computation. Thus B is a genuine hazard category.
3. In the conventional single-issue, in-order, fixed-stage pipeline, reads occur in an earlier fixed stage than writes. A later instruction cannot overtake an earlier read or write. Under those assumptions, WAR and WAW dependencies do not cause hazards, and B is the intended unique answer. RAR is not a hazard because neither instruction changes the shared register.
4. The unrestricted wording is broader. A write-after-read (WAR) hazard can arise if an earlier instruction is delayed before reading R1 and a later instruction overwrites R1 first. A write-after-write (WAW) hazard can arise if a slow earlier instruction and a fast later instruction both write R1, but the earlier write completes last, leaving the wrong final value.
5. Therefore preserve official B for scoring, with the qualification that C and D can also be hazard categories in pipelines permitting the relevant reordering. Register renaming and ordering mechanisms may prevent them, but are not specified.

Discrepancy retained: CS-2026-S1-Q16-PIPELINE-MODEL. This is a model-dependent uniqueness issue, not an official key correction. The published single-answer selection requires the narrower pipeline convention described above.

**Type / marks:** MCQ, 2.

**Official answer:** C

**Derived answer:** C

## Solution

Givens and goal
X and Y are IEEE 754 single-precision values with hexadecimal bit patterns 35C00000 and 34A00000. Find the bit pattern for Z=X+Y among A 35C80000, B 35CC0000, C 35E80000, D 35EC0000.

Approach
Decode sign, biased exponent and fraction; align exponents, add significands, and re-encode the exact sum.

Step-by-step solution
1. Both operands are positive normal IEEE 754 binary32 numbers. The exponent field of 35C00000 is 107, so its unbiased exponent is −20. Its fraction field is 400000, giving significand 1.5. Thus X = 1.5 × 2^−20.
2. For 34A00000 the exponent field is 105, giving unbiased exponent −22; fraction 200000 gives significand 1.25. Thus Y = 1.25 × 2^−22 = 0.3125 × 2^−20.
3. Their sum is 1.8125 × 2^−20. Since 1 ≤ 1.8125 < 2, no exponent renormalization is required. The fraction is 0.8125 = 13/16, which has an exact terminating binary expansion.
4. The exponent bits remain 107, contributing 35800000. The stored fraction is (13/16) × 2^23 = 680000 in hexadecimal. Combining the fields yields 35E80000. No rounding error occurs here.

**Computational check:** Python struct unpacked both binary32 operands and repacked their sum, obtaining 0x35e80000. This complements the exact field-level derivation; it is not the sole justification.

Binary significand check: X=1.1₂×2^−20 and Y=1.01₂×2^−22=0.0101₂×2^−20. Their sum is 1.1101₂×2^−20. Dropping the implicit leading 1 leaves fraction bits 1101 followed by nineteen zeros, exactly the hexadecimal fraction 680000. Since all significant bits fit within binary32 precision, the rounding mode does not alter the answer here.

**Paraphrased problem context:** A byte-addressed processor has a 2^32-byte physical address space. The cache holds 2^23 bytes in 128-byte blocks. Compare direct-mapped tag length M with K-way set-associative tag length N, where K=2^L and L∈{1,2,3}. Choices are N=M+L, M−L, M+K, M−K.

**Type / marks:** MCQ, 2.

**Official answer:** A

**Derived answer:** A

## Solution

Givens and goal
A byte-addressed processor has a 2^32-byte physical address space. The cache holds 2^23 bytes in 128-byte blocks. Compare direct-mapped tag length M with K-way set-associative tag length N, where K=2^L and L∈{1,2,3}. Choices are N=M+L, M−L, M+K, M−K.

Approach
Partition the same physical address into tag, set index, and block offset for the two organizations.

Step-by-step solution
1. Byte addresses contain 32 bits. A 128-byte block needs log2(128)=7 offset bits.
2. The cache contains 2^23 / 2^7 = 2^16 blocks. In a direct-mapped organization, there are 2^16 sets, requiring 16 index bits. Hence its tag length is M=32−16−7=9.
3. K=2^L ways reduce the set count to 2^(16−L). The set index therefore uses 16−L bits while the block offset remains 7 bits.
4. The set-associative tag length is N=32−(16−L)−7=9+L=M+L.

**Common error:** Associativity changes the number of sets, not the number of bytes per block. Offset bits do not grow with the number of ways.

Concrete check: for L=2, the cache is four-way. It has 2^14 sets, so its address fields are 11 tag bits, 14 set-index bits and 7 offset bits, totaling 32. Direct mapping used 9+16+7=32. The increase is log₂4=2 bits, not four bits; this distinguishes M+L from M+K. Subtracting L or K would move the tag in the wrong direction.

**Type / marks:** NAT, 2.

**Official answer:** 77.3 to 77.3

**Derived answer:** 77.3 to 77.3

## Solution

Givens and goal
A disk rotates at 15000 rpm, has 400 sectors per track and 1024 bytes per sector, and takes 1 ms per adjacent-track move. Starting at track 0, read ten randomly located sectors on each of tracks 5,12,7 in that order. Find the total time to one decimal place, under the published key’s expected-latency convention.

Approach
Calculate seek time, expected rotational waiting, and actual sector transfer time separately, then add them without double counting.

Step-by-step solution
1. Convert rotation speed to period. A minute is 60000 ms, so one revolution takes 60000/15000=4 ms.
2. The required track movements are |5−0|=5, |12−5|=7 and |7−12|=5. At 1 ms per adjacent move, total seek time is (5+7+5)·1=17 ms. There is no additional seek between sectors on the same track.
3. Under independent uniform rotational positions for successive accesses, average wait to the requested sector is half a revolution, 4/2=2 ms. There are 3·10=30 sector accesses, so the expected rotational wait is 30·2=60 ms.
4. One sector occupies 1/400 of a revolution and takes 4/400=0.01 ms to transfer. Thirty sectors take 0.30 ms. Equivalently, the transfer rate is (400·1024)/4=102400 bytes/ms and the total data is 30·1024=30720 bytes, giving the same 0.30 ms.
5. Add the components: 17+60+0.30=77.30 ms. Rounded to one decimal, the official result is 77.3 ms.

Discrepancy retained: CS-2026-S1-Q59-EXPECTED. This is an expected time under the independent random-angle access model, not an exact elapsed duration fixed by unspecified sector locations. Reordering reads by rotational position or batching nearby sectors would require a different model. The source says “total time” without explicitly saying expected, so the published interval 77.3 to 77.3 is preserved with this qualification.

Split addresses into tag, line index, and byte offset before tracing the repeating pattern.

Step-by-step solution
1. There are 4096/16=256 cache lines, requiring 8 index bits, and a 16-byte block requires 4 offset bits. In a 24-bit physical address, the remaining 12 bits form the tag.
2. The decompositions (tag,index,offset) are P=(845,B3,2), Q=(845,B2,6), R=(845,B3,6), S=(846,B3,2), all hexadecimal. P and R share one memory block; S has the same index but a different tag; Q has a separate index.
3. In the first cycle, P misses and loads tag 845 into line B3. Q misses and loads its separate line B2. R hits the block loaded by P. S misses and replaces B3 with tag 846.
4. At the start of every later cycle B3 contains S’s tag. P therefore misses and replaces S; R subsequently hits P’s block; S then misses and replaces P again. Q remains resident and hits in all nine later cycles.
5. A and B are true; C and D are false. As a check, misses total 10 for P, 1 for Q, 0 for R, and 10 for S: 21 misses and 19 hits over 40 accesses. Spatial locality explains R’s hits, whereas index conflict explains repeated P/S misses.

**Paraphrased problem context:** A byte-addressed machine has 1 MB physical memory. Address 0xA2C28 maps to cache block number 176 (decimal), numbered from zero. Find the largest cache size in KB under the conventional power-of-two direct-mapped bit-field organization. K=2¹⁰,M=2²⁰.

## Solution

Givens and goal
A byte-addressed machine has 1 MB physical memory. Address 0xA2C28 maps to cache block number 176 (decimal), numbered from zero. Find the largest cache size in KB under the conventional power-of-two direct-mapped bit-field organization. K=2¹⁰,M=2²⁰.

Approach
Locate the required binary index within the physical address and maximize its allowed leading zeros.

Step-by-step solution
1. A 1 MB byte-addressed space has 20-bit addresses. The given address is 1010 0010 1100 0010 1000 in binary. Let b be block-offset bits and s be index bits. The cache index is (address >> b) mod 2^s and cache capacity is 2^(b+s) bytes.
2. The required index 176 is binary 10110000, so s≥8. In the address, the eight-bit slice equal to 10110000 occurs with its low end at bit 6: shifting right by b=6 gives 0x28B0, whose low eight bits are 0xB0=176. Examining possible offsets 0 through 12 yields no other matching eight-bit slice.
3. For b=6, the low 9,10, and 11 bits of 0x28B0 also equal 176 because the added bits are zero. The low 12 bits are 0x8B0=2224, so s=12 fails; all larger widths retain that unwanted set bit and fail too.
4. The maximum feasible choice is b=6,s=11: block size 2⁶=64 bytes, line count 2¹¹=2048, and capacity 2¹⁷=131072 bytes=128 KB. As a direct check, floor(0xA2C28/64)=10416, and 10416 mod 2048=176.
5. The feasible smaller capacities with the same block size are 16,32,64 KB. This maximization relies on conventional power-of-two cache/block sizes and consecutive index bits. Arbitrary modular mappings or nonstandard capacities are not implied by the source wording; retain that model qualification with official answer 128.

## Solution

Givens and goal
A nonpipelined processor averages 5 cycles/instruction at 1.6 GHz. Its pipeline has ideal CPI 1 but runs at 1.2 GHz; 30% of instructions incur an additional 2-cycle stall. Compute long-program speedup to two decimals. The published accepted range is 2.30–2.40.

Approach
Compare actual seconds per instruction, not CPI alone.

Step-by-step solution
1. The nonpipelined average instruction time is CPI/frequency=5/(1.6×10⁹) seconds=3.125 ns.
2. Each pipelined instruction contributes one base cycle on average. The expected added stall cost is 0.30×2=0.60 cycles per instruction, so effective CPI is 1.60.
3. The pipelined instruction time is 1.60/(1.2×10⁹) seconds=4/3 ns≈1.33333 ns. Its clock is slower, so a CPI reduction by itself would overstate the improvement.
4. Speedup is old time/new time=3.125/(4/3)=2.34375, which rounds to 2.34. Equivalently use (5/1.6)/(1.6/1.2).
5. The full official accepted interval 2.30–2.40 is preserved, rather than replaced with a single exact scoring value. The calculation assumes long-program throughput, negligible pipeline fill/drain cost, and additive two-cycle stalls as stated; a short program or overlapping penalties would need more details.
