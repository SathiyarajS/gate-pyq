**Paraphrased problem context:** A CPU has fixed 24-bit instructions and a program beginning at decimal address 300. Which listed decimal value is a legal program counter in that instruction stream? The conventional byte-addressing assumption is implicit in the reproduction.
Options:
(A) 400
(B) 500
(C) 600
(D) 700

## Solution

1. With byte-addressed memory and fixed 24-bit instructions, each instruction occupies 3 bytes. Addresses in this instruction stream are 300+3k.

2. Only600 among the listed values differs from 300 by a multiple of 3, so C. Instruction width alone does not establish byte addressing or prohibit other instruction streams; those are the conventional implicit assumptions.

3. Teaching check: Convert instruction width from bits to bytes before testing alignment: 24/8=3. The differences from the starting address are 100,200,300,400; only 300 is divisible by three. This checks positions in the given instruction stream, not all arbitrary code addresses in memory.

**Paraphrased problem context:** A cache block is 64 bytes. Main memory has k banks of width c bytes; consecutive c-byte chunks map cyclically onto consecutive banks. All banks can be read in parallel, but repeated accesses to one bank are serialized. Every parallel round takes k/2 ns of decoding plus 80 ns for the bank access. For c=2,k=24, how long does fetching the block starting at address 0 take?
Options:
(A) 92 ns
(B) 104 ns
(C) 172 ns
(D) 184 ns

## Solution

1. Each parallel round transfers at most 24×2=48 bytes. A 64-byte block starting at zero needs 32 bank-width chunks and hence two rounds.

2. Each round costs 24/2+80=92 ns, including the stated decoding cost. Total latency is 184 ns (D).

3. Teaching check: The block contains 64/2=32 chunks. The first 24 can be read together, but the remaining eight return to banks already used and require a second round. The stated model charges decoding again for that round even though not all 24 banks supply another chunk.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** A 1 GHz CPU has five pipeline stages; fetch is stage 1. Conditional branches compute their target and condition in stage 3. After fetching a branch, no further instruction is fetched until the outcome is known. A program has 10⁹ instructions, 20% conditional branches. With base CPI 1 before branch stalls, what approximate execution time results?
Options:
(A) 1.0 s
(B) 1.2 s
(C) 1.4 s
(D) 1.6 s

## Solution

1. A branch fetched in stage 1 resolves at the end of stage 3, so two subsequent fetch slots are lost. The ideal CPI is 1 and branch frequency is 0.2, giving CPI=1+2(0.2)=1.4.

2. At 1 GHz, 10^9 instructions take approximately 1.4 seconds (C); constant pipeline fill/drain time is ignored as in the options. The statement that instructions take one cycle on average must mean the base CPI before these stalls.

3. Teaching check: The two idle fetch slots are the cycles while the branch passes stages 2 and 3. Since one fifth of instructions causes this penalty, average overhead is 0.4 cycles per instruction. The five-stage depth does not mean five cycles of throughput cost for every ordinary instruction.

**Paraphrased problem context:** The instruction bbs reg,pos,label branches if bit pos of a 32-bit register is 1; positions 0…31 start at the least-significant bit. Emulate it by temp←reg & mask, then branch if temp≠0. How should mask be computed?
Options:
(A) 0x1 << pos
(B) 0xffffffff >> pos
(C) pos
(D) 0xf

## Solution

1. The mask must contain exactly one set bit at position pos: mask=0x1 << pos. AND with the register is nonzero exactly when that bit is set.

2. Thus A. These are register-level pseudocode shifts; a literal C implementation should use an unsigned 32-bit 1 to handle position 31 safely.

3. Teaching check: A one-hot mask isolates exactly the requested bit; an all-ones mask shifted right would generally retain several bits. If implemented in C rather than register pseudocode, use a suitably wide unsigned constant to avoid undefined signed left-shift behavior at the top bit.

## Solution

1. A 4 KB page requires 12 offset bits, leaving 32−12=20 virtual-page-number bits. There are 128/4=32 TLB sets, requiring 5 index bits.

3. Teaching check: Partition the virtual address into offset, set index and tag. Page offsets require log₂4096=12 bits. Four-way associativity means only 128/4=32 sets, so five more bits select the set and the remaining fifteen distinguish pages within that set.

**Paraphrased problem context:** Compare two 32 KB caches with 32-byte blocks and 32-bit addresses: one is two-way set associative, the other direct mapped. A 2:1 multiplexer takes 0.6 ns; a k-bit comparator takes k/10 ns. The hit-latency model counts comparator and way-selection delays. Find two-way cache hit latency h₁.
Options:
(A) 2.4 ns
(B) 2.3 ns
(C) 1.8 ns
(D) 1.7 ns

## Solution

Step 1: 32 KB / 32 B=1024 cache lines. Two ways give 512 sets, so index=9 bits and block offset=5 bits.

Step 2: The tag is 32−9−5=18 bits. Two tag comparisons proceed in parallel, taking 18/10=1.8 ns; selecting the matching way adds 0.6 ns.

Step 3: Thus h1=2.4 ns, A, within the stated model that counts comparator and multiplexer latency.

Step 4: Teaching check: Two-way associativity halves the number of sets relative to direct mapping, increasing the tag by one bit. Both way tags are compared in parallel, so do not double comparator latency. The selected data then passes through one 2:1 multiplexer.

**Paraphrased problem context:** A CPU has a 32 KB direct-mapped cache with 128-byte blocks. C array A[512][512] uses 8-byte elements. The two programs execute separately from the same initially cold cache; i,j,x are in registers.
P1: for(i=0;i<512;i++) for(j=0;j<512;j++) x+=A[i][j];
P2: for(i=0;i<512;i++) for(j=0;j<512;j++) x+=A[j][i];
Let M1,M2 be their cache-miss counts. Use the conventional block-aligned base address assumed by the listed answers. Find M1.
Options:
(A) 0
(B) 2048
(C) 16384
(D) 262144

## Solution

1. In C, A is row-major. Each 128-byte cache block holds 128/8=16 elements.

2. P1 visits all 512×512 elements sequentially, so one compulsory miss serves each group of 16 elements. For a block-aligned A, M1=512×512/16=16384, C; each later element in the same block hits.

3. Teaching check: C’s rightmost subscript varies over contiguous elements. Each cache block supplies sixteen consecutive doubles, causing one miss followed by fifteen hits in a sequential scan. The whole array is much larger than the cache, but immediate within-block reuse still occurs.

**Paraphrased problem context:** A CPU has a 32 KB direct-mapped cache with 128-byte blocks. C array A[512][512] uses 8-byte elements. The two programs execute separately from the same initially cold cache; i,j,x are in registers.
P1: for(i=0;i<512;i++) for(j=0;j<512;j++) x+=A[i][j];
P2: for(i=0;i<512;i++) for(j=0;j<512;j++) x+=A[j][i];
Let M1,M2 be their cache-miss counts. Use the conventional block-aligned base address assumed by the listed answers. Find M1/M2.
Options:
(A) 0
(B) 1/16
(C) 1/8
(D) 16

## Solution

1. P1 has 16384 misses under the block-aligned assumption. P2 accesses A[j][i] with stride 512×8=4096 bytes=32 cache lines.

2. The cache has 32768/128=256 lines, so successive row accesses cycle through only 256/gcd(256,32)=8 cache indices. With 512 rows, every would-be reused block is evicted before the next column accesses it.

3. All 512²=262144 P2 accesses miss. M1/M2=16384/262144=1/16, B.

4. The last options are on physical page 13.

5. Teaching check: A 4096-byte stride advances by 32 cache indices modulo 256. Only eight indices participate in a column, repeatedly overwriting each other. Thus the next column cannot reuse the previous column’s blocks, even though adjacent elements within a row occupy the same block.
