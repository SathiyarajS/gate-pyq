**Essential problem context (paraphrased):** Quicksort selects each pivot randomly. What is its worst-case sorting complexity on n values: O(n), O(n log n), O(n²), or O(n!)?

## Solution

Step 1: Random pivot selection improves the expected split quality, but it does not make extreme pivots impossible. A sequence selecting the minimum or maximum at every partition still has nonzero probability.

Step 2: That sequence performs(n−1)+(n−2)+…+1=n(n−1)/2 partition comparisons, yielding Θ(n²).

Thus C is the tight worst-case bound. Θ(n log n) is the expected runtime over the random choices, not the maximum possible runtime of a particular execution.

**Essential problem context (paraphrased):** Compare f(n)=n² lg n and g(n)=n(lg n)^10. Which asymptotic relationship holds: only f=O(g), only g=O(f), neither, or both?

## Solution

Step 1: Divide f(n)=n² lg n by g(n)=n(lg n)^10. The ratio is n/(lg n)^9.

Step 2: Put t=lg n, so the ratio becomes 2^t/t^9, which tends to infinity because an exponential dominates every fixed power of t.

Therefore g=O(f), while f is not O(g), giving B. The logarithmic factor with exponent 10 cannot compensate asymptotically for the additional factor n in f.

**Essential problem context (paraphrased):** In BFS from r in an undirected unweighted graph, vertex u is visited before v. Must d(r,u)<d(r,v), >, ≤, or none of these?

## Solution

Step 1: Breadth-first search’s FIFO queue processes all vertices at distance k before any vertex at distance k+1. Thus dequeue/discovery order is nondecreasing in distance from r.

Step 2: Two distinct vertices in the same layer can occur in either order, so visiting u first does not imply a strict inequality. A star centered at r supplies such an equal-distance example.

Therefore d(r,u)≤d(r,v), C, for vertices reached by this BFS. Unreachable vertices are not visited by the traversal from r.

Total weight is 2+3+4+7+9=25. The tree is connected and acyclic; Kruskal’s cut property establishes minimality.

These four edges leave two components, {n1,n2,n6} and {n3,n4,n5}. Their cheapest connecting edges are n2–n4 and n6–n4, both weight 4. Either one completes a tree of weight 25; choosing both would create a cycle and require losing a forced edge. Hence there are exactly two MSTs.

**Essential problem context (paraphrased):** For a connected weighted undirected graph, compare the minimum edge weight present in different MSTs.

## Solution

Let m be the minimum weight of any edge joining distinct vertices. Suppose an MST T had no edge of weight m. Add an edge e of weight m to T. A tree plus one edge contains a cycle, and every other edge on that cycle would be heavier than m. Removing any such edge yields a spanning tree lighter than T, a contradiction. Therefore every MST includes an edge of weight m. The identity of that edge need not be unique, but the numerical minimum is. For the given graph it is 2.

**Independently derived answer:** Yes; for the given graph the invariant maximum is 9.

**Essential problem context (paraphrased):** For a connected weighted undirected graph, compare the maximum edge weight present in different MSTs.

## Solution

Suppose MST T has maximum edge weight M, and another MST U has all edge weights less than M. Remove an edge of weight M from T, splitting its vertices into two components. Because U is connected, some U edge crosses this cut. Its weight is less than M; inserting it into T minus the removed edge produces a lighter spanning tree, contradicting minimality. Swapping T and U rules out either having a strictly larger maximum. This proves equality of the maximum value, not uniqueness of the heaviest edge or of the MST itself. In the supplied graph n5’s cheapest incident edge has weight 9, and the constructed MST’s largest weight is 9.
