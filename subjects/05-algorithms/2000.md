**Essential problem context (paraphrased):** A sorted array s contains n integers. Determine whether two distinct elements sum to less than 1000. What is the most efficient asymptotic runtime, including choice O(1)?

## Solution

Step 1: In ascending order, the smallest sum of two distinct positions is s[1]+s[2]. Every other pair replaces one or both elements by values at least as large.

Step 2: If that sum is below 1000, a qualifying pair exists; otherwise no pair can qualify. Only two accesses, an addition, and a comparison are needed.

Thus Θ(1), option A, for n≥2 with random-access storage. For n<2 return false immediately. Searching all pairs or applying a two-pointer scan is unnecessary for this inequality-existence question.

**Essential problem context (paraphrased):** For array s[1…n] and 1≤k≤n, execute reverse(s,1,k),reverse(s,k+1,n),reverse(s,1,n). Does this rotate left by k,leave unchanged,reverse everything,or none?

## Solution

Step 1: Split the original array into consecutive blocks A=s[1…k] and B=s[k+1…n], so it is AB. The first two operations produce A^R B^R.

Step 2: Reversing the whole concatenation reverses block order and each block: (A^R B^R)^R=BA. This moves the first k entries to the end while preserving order within each block.

Thus A, a left rotation by k. For k=n, the second range is empty and must be treated as a no-op; the full rotation leaves the array unchanged.

**Essential problem context (paraphrased):** Connected undirected G has distinct edge weights. Which is false: every MST contains the minimum edge; if the maximum edge lies in an MST it is a bridge; no MST contains the maximum edge; G has a unique MST?

## Solution

Step 1: The globally lightest edge is the unique lightest edge across a cut separating one endpoint from the other, so the cut property forces it into the MST. Distinct weights also give a unique MST.

Step 2: If the maximum edge lies on a cycle, it is the unique heaviest edge there and the cycle property excludes it. Thus if it appears in an MST, it must be a bridge. But a bridge is mandatory, even when globally heaviest.

A graph that is itself a weighted tree supplies a counterexample to C. Therefore C is false, while B correctly handles the bridge case.

**Essential problem context (paraphrased):** In undirected DFS, u is discovered and v is the next newly discovered vertex. Which is always true? The options assert a direct edge with ancestry, or that absent edge implies u is a leaf, or that absent edge implies the same parent.

## Solution

Step 1: If u has an unvisited neighbor when its exploration begins, DFS immediately follows an edge to such a neighbor. Then the next discovery v is adjacent and becomes a child of u.

Step 2: If the next discovery is not adjacent to u, DFS must have exhausted u without discovering any child and backtracked to an ancestor before reaching v. Therefore u is a leaf in the DFS tree, proving C.

The backtrack may cross several ancestors, so u and v need not share a parent. The two options requiring adjacency in every case are also too strong.

**Essential problem context (paraphrased):** Let m,n be positive integers and let the line be y=(n/m)x. Define A=mq−np for endpoint (p,q), and B=ms−nr for endpoint (r,s). Complete clash: initialize false; line4 tests A [box] 0; line5 tests B [box] 0; line6 tests A [box] 0 and B [box] 0; line7 tests A [box] 0 and B [box] 0. Each successful test sets clash=true.

## Solution

A segment intersects the infinite line if either endpoint lies on it, or if its endpoints lie on opposite sides. The completed Pascal-style code is:
function clash(m,n,p,q,r,s: integer): Boolean;
begin
  clash := false;
  if (m*q-n*p) = 0 then clash := true;        {line 4}
  if (m*s-n*r) = 0 then clash := true;        {line 5}
  if (m*q-n*p) < 0 and (m*s-n*r) > 0 then clash := true; {6}
  if (m*q-n*p) > 0 and (m*s-n*r) < 0 then clash := true; {7}
end;
For a point interpolated along the segment with parameter t in [0,1], the signed expression is (1−t)A+tB. If A and B have opposite signs, this linear continuous function has a zero in the interval. If both have the same nonzero sign, every convex combination has that sign and there is no intersection. Endpoint equality also handles a zero-length segment lying on the line and a whole segment coincident with it. Avoid multiplying A*B merely to test the signs: that introduces extra overflow risk. As mathematical pseudocode, the original arithmetic assumes exact integer results.

**Independently derived answer:** (1) f[n]!=0; (2) f[n]; (3) f[n]=t;

**Essential problem context (paraphrased):** Array f[0..M] starts at zero. fib(n) checks n>M for error, returns 1 for n=0 or 1, then executes if([1]) return [2]; t=fib(n−1)+fib(n−2); [3]; return t. Assume 0<=n<=M and exact arithmetic. Fill the three boxes.

## Solution

The completed function is:
fib(n) {
  if (n > M) error();
  if (n == 0) return 1;
  if (n == 1) return 1;
  if (f[n] != 0) return f[n];
  t = fib(n-1) + fib(n-2);
  f[n] = t;
  return t;
}
Use a local t in each recursive activation. Since both base cases equal 1, every valid Fibonacci result is positive. Thus zero safely means “not computed” under the stated exact-arithmetic model. On a cache miss, recursively obtain the two predecessors, store their sum before returning, and reuse it whenever n is requested again. For example fib(4) obtains fib(3)=3, then reads the cached fib(2)=2, producing 5. The base cases need not be stored because they already take constant time. With overflowing machine arithmetic, zero might cease to be a valid sentinel; practical implementations can use an independent computed flag or arbitrary-precision values.

**Essential problem context (paraphrased):** Array f[0..M] starts at zero. fib(n) checks n>M for error, returns 1 for n=0 or 1, then executes if([1]) return [2]; t=fib(n−1)+fib(n−2); [3]; return t. Assume 0<=n<=M and exact arithmetic. With memoization filled correctly, find the running time of the first fib(n) computation.

## Solution

For each k from 2 through n there is at most one cache miss. That miss performs a constant number of comparisons, two recursive calls, one addition and one store. All later calls on the same k return from the cache in constant time. The subproblem dependency graph has n+1 possible arguments and two outgoing calls per non-base argument, so the total number of calls and primitive operations is O(n), not exponential. A first computation must actually compute each of fib(2),...,fib(n), giving Ω(n) work; therefore the tight bound is Θ(n). The descent n,n−1,...,1 can occupy Θ(n) stack frames. Initializing the provided whole array costs Θ(M) separately, but the stem says it is already initialized. If bit complexity is counted, Fibonacci numbers have Θ(n) bits, and the n additions have increasing cost; the conventional linear answer assumes constant-time arithmetic.

**Essential problem context (paraphrased):** An array has four 0s, five 1s and three 2s, and is to be sorted increasingly using swaps. GFG Q64 p9 permits nonadjacent swaps; GateForum Q17 p16 requires adjacent swaps. Solve both distinct source versions. Find the maximum, over initial orders, of the minimum required swaps.

## Solution

Arbitrary-swap version: partition the target positions into zones of sizes 4,5,3 for 0,1,2. A misplaced value j in zone i is a directed edge i→j. Incoming and outgoing edge counts balance at every zone. First cancel every opposite pair i→j,j→i with one swap, fixing two positions. Once opposite pairs are exhausted, remaining edges form consistently oriented 3-cycles, each fixed by two swaps. Let d be the number of canceled pairs and c the number of remaining 3-cycles. This uses d+2c swaps and moves M=2d+3c<=12 misplaced positions. Each 3-cycle uses one position in the 2-zone, so c<=3. For c=0,1,2,3, the bound d<=floor((12−3c)/2) gives d+2c<=6,6,7,7 respectively. Hence seven swaps always suffice.
Attainment: use 1111|00222|001, where bars show target zones. Its opposite pairs are two 0/1 pairs and one 1/2 pair, and the remaining six misplaced entries form two 3-cycles, so seven suffice. To see six cannot suffice, all 12 positions are initially wrong. Six swaps would have to fix two positions each, and thus every swap would need to exchange an opposite pair without creating any new error. There are only three opposite pairs initially; after removing those, the remaining directed 3-cycles have no such pair. Six swaps are therefore impossible. The worst-case optimum is exactly 7.
Adjacent-only version: the minimum number of swaps equals the inversion count because an adjacent swap changes that count by exactly 1, and swapping adjacent inverted pairs sorts while decreasing it each time. The largest inversion count is attained by descending groups 222111110000. Every unequal pair is then inverted: 3*5+3*4+5*4=15+12+20=47. Equal-value pairs contribute zero. This discrepancy is substantive; neither reproduction is authenticated as the official wording.

GFG Q64 p9 permits nonadjacent swaps; GateForum Q17 p16 requires adjacent swaps. Solve both distinct source versions. Give an order attaining the worst-case minimum.

## Solution

For arbitrary swaps, choose [1,1,1,1 | 0,0,2,2,2 | 0,0,1], with target-zone lengths 4,5,3. The counts are four 0s, five 1s, three 2s. Number positions 1 through 12. One seven-swap sorting sequence is (1,5),(2,6),(7,12),(3,10),(8,10),(4,11),(9,11). After the first three swaps, the unsorted portion consists of two cycles, each carrying a 1 in the 0-zone, a 2 in the 1-zone and a 0 in the 2-zone. Each takes two swaps. All 12 entries were initially misplaced, so six swaps would require every swap to fix two errors. Only three opposite pairs are available, and a residual 3-cycle cannot be fixed in that way. Thus seven are necessary as well as sufficient; the general upper bound is proved in part(a).
For adjacent-only swaps, choose [2,2,2,1,1,1,1,1,0,0,0,0]. It has 3*5 inversions of type(2,1), 3*4 of type(2,0), and 5*4 of type(1,0), for 47. No array with these multiplicities can have more inversions, because every unequal pair is already inverted here. An adjacent inversion-removal sort takes exactly 47 swaps. This descending arrangement is not the arbitrary-swap witness: allowing distant exchanges changes the optimization problem.
