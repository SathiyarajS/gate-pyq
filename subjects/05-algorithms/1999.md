**Independently derived answer:** B

**Essential problem context (paraphrased):** Does stable sorting mean O(n log n) time, preservation of the order of equal keys, divide-and-conquer, or O(n) space?

## Solution

Label two records with equal key as (k,first) and (k,second), in that input order. A stable sort guarantees that first still precedes second afterward. That property matters when one field has already been sorted and a later stable pass sorts another field. Runtime, extra space and algorithmic paradigm are separate properties: a stable insertion sort may take quadratic time, while some fast sorts are unstable. Hence the definition is B.

# GATE 1999: Q13 (printed A Q1.13)

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D: floor(n/2)

**Essential problem context (paraphrased):** Partition n array values so negatives precede positives. What is the minimum number of arbitrary exchanges in the worst case: n−1,n,n+1,or none?

## Solution

Suppose there are k negative values. Their final region is the first k positions. Let t positives currently lie in that region; exactly t negatives then lie outside it. Pair and swap each misplaced positive with a misplaced negative, requiring t exchanges. Every exchange fixes at most one misplaced negative in the target region, proving optimality. Since t≤min(k,n−k), the worst case over k is floor(n/2), attained by placing balanced sign groups in the wrong halves. Thus none of the listed formulas A–C is the general answer. This uses arbitrary swaps, not adjacent swaps.

## Solution

Pass one merges singleton runs into pairs: [20,47], [8,15], [4,9], [30,40], [12,17]. Pass two merges adjacent pairs into four-element sorted runs. The first two yield [8,15,20,47]; the next two yield [4,9,30,40]. The final pair has no partner and remains [12,17]. Concatenating these runs gives B. The whole array is not yet sorted; later passes merge the length-four runs and the remaining tail.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Essential problem context (paraphrased):** For n a power of two, how many multiplications are minimally needed to compute a^n? Options log2 n, sqrt(n), n−1,n.

## Solution

Write n=2^k. Repeated squaring computes a²,a⁴,…,a^(2^k), using exactly k multiplications. To prove minimality in the ordinary multiplication-only straight-line model, observe that one multiplication can at most double the largest exponent already available. Starting with exponent 1, after t multiplications every computed exponent is at most 2^t. Reaching n therefore requires t≥log2 n=k. Construction and lower bound coincide, giving A; n=1 needs zero multiplications.

**Essential problem context (paraphrased):** Merge file lengths10,20,15,5,25 with pairwise merging; cost is records moved. Choose165,90,75,65.

## Solution

Always merge the two shortest remaining files, as in the optimal merge/Huffman construction. Merge5+10=15, costing15; then15+15=30, costing30; then20+25=45, costing45; finally30+45=75, costing75. Total cost is15+30+45+75=165. The greedy choice is optimal because two smallest weights can occupy deepest sibling leaves of an optimal merge tree, after which contracting them leaves the same problem on fewer files. Counting only75 ignores repeated moves through intermediate merges.

**Essential problem context (paraphrased):** M:T(n)=T(n−1)+n; N:T(n)=T(n/2)+n; O:T(n)=T(n/2)+n log n; P:T(n)=T(n−1)+log n. Match to U O(n),V O(n log n),W O(n²),X O(log² n).

## Solution

For M, summing1+2+…+n gives Θ(n²). For N, the work is n+n/2+n/4+…=Θ(n). For O, the first term already gives n log n and the geometric weighted tail is O(n log n), hence Θ(n log n). For P, summing log k for k=2…n gives log(n!)=Θ(n log n): the upper bound is n log n and the last n/2 terms each exceed log(n/2). Thus M-W,N-U,O-V,P-V, option B. The listed big-O labels are interpreted as tight intended growth classes; loose upper bounds would not define a unique matching.

# GATE 1999: Q63 (printed B Q8)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Two comparisons suffice and are necessary in the worst case.

**Essential problem context (paraphrased):** An n×n matrix A has every row and column in ascending order. Draw a decision tree finding its first, second, and third smallest entries using the minimum number of comparisons. Assume n≥2; count repeated values as separate entries.

## Solution

The first entry is always A₁₁. Set b=A₁₂ and c=A₂₁. Every remaining entry is at least b or c, so the second is min(b,c).

If b≤c, the only candidates for third are c and d=A₁₃. Other entries in the first row are at least d; entries outside the first row are at least c (including A₂₂). If c<b, the analogous candidates are b and e=A₃₁. When n=2, the missing d or e can be treated as +∞, so the third is simply the other one of b,c and just one comparison suffices for that special size.

For n≥3 the full decision tree is:

                         compare b ≤ c?
                       / yes             \ no
              compare d ≤ c?           compare e ≤ b?
              / yes     \ no           / yes      \ no
          (A₁₁,b,d)  (A₁₁,b,c)    (A₁₁,c,e)   (A₁₁,c,b)

Each root-to-leaf path has two comparisons. The leaves give the first three entries in order. Ties can follow the ≤ branch: tied entries have equal values, so either identity order is valid.

Optimality for n≥3: all four strict order possibilities displayed at the leaves can occur in a row-and-column-sorted matrix. A single binary comparison has only two outcomes and cannot distinguish four possible ordered triples of positions; two comparisons are necessary in the worst case. For n=2 there are only the two orders of b,c and one comparison is both sufficient and necessary. For n=1 a third entry does not exist, so the task presupposes at least n=2.

# GATE 1999: Q67 (printed B Q11(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 3 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Procedure-cost-only model: O(log n). With ordinary constant recursion/control overhead: Θ(n).

**Essential problem context (paraphrased):** Given the algorithm below, with procedure A taking O(1) time and B(n) taking O(1/n) time, derive its time complexity in O-notation. GFG retains the O symbols lost in GateForum.

what(n):
    if n = 1: call A
    else:
        what(n-1)
        call B(n)

Assume n is a positive integer.

## Solution

In the idealized accounting suggested by the question, count only costs of A and B. Let their costs be a and b(k), with a=O(1) and b(k)=O(1/k). The recurrence is T(1)=a and T(n)=T(n−1)+b(n). Expanding gives T(n)=a+Σ(k=2..n)b(k)≤C₀+C₁Σ(k=2..n)1/k for suitable constants, absorbing finitely many small inputs into C₀.

The harmonic sum is bounded above by 1+ln n, by comparison with the integral of 1/x. Thus T(n)=O(log n). If the supplied procedure costs are actually Θ(1) and Θ(1/n), the lower integral bound gives Θ(log n), but upper bounds alone do not prove this tight classification.

Cost-model qualification: a real RAM implementation must perform a test, decrement, recursive call and return at each of n recursion levels. These contribute Θ(1) per level, giving T_RAM(n)=T_RAM(n−1)+Θ(1)+O(1/n)=Θ(n), with Θ(n) stack depth. Moreover a nonzero discrete instruction cost cannot asymptotically decrease as 1/n. Therefore O(log n) is the intended abstract procedure-cost result, not an unconditional full implementation running-time claim.
