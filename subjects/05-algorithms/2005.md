**Type / marks:** MCQ, 1 mark(s).

**Independently derived answer:** D

**Paraphrased problem context:** A known bound for computing transitive closure of an n-element relation is: A O(n); B O(n log n); C O(n^(3/2)); D O(n³).

## Solution

Warshall’s algorithm considers each possible intermediate vertex k and updates reachability R[i, j]←R[i, j]∨(R[i, k]∧R[k, j]) for every i, j. Its three nested loops take O(n³), D. Faster algebraic algorithms exist; the question asks a known upper bound, not a tight lower bound. The other listed bounds are subquadratic and cannot explicitly output every entry of an arbitrary n×n closure matrix.

Teaching detail:
Warshall’s algorithm loops over intermediate vertex k and every ordered pair(i, j), updating reachability using i→k→j. There are n choices in each loop, giving O(n³). This is a known upper bound, not a proof that faster algebraic methods are impossible. An explicitly written arbitrary n×n closure has quadratic output size, so the three listed subquadratic alternatives cannot generally output the full matrix.

**Independently derived answer:** C

**Paraphrased problem context:** T(n)=2T(n/2)+n, with T(0)=T(1)=1. Which claim is false? A O(n²); B Θ(n log n); C Ω(n²); D O(n log n).

## Solution

For n=2^k, dividing by n gives T(n)/n=T(n/2)/(n/2)+1, so T(n)=n(1+log2 n). Standard rounding of subproblem sizes preserves Θ(n log n). Therefore O(n²), Θ(n log n), and O(n log n) hold, but Ω(n²) does not, C, since(n log n)/n²→0.

Teaching detail:
For powers of two, each recursion level contributes n and there are log₂n nontrivial levels plus linear total base cost. Thus T(n)=n(1+log₂n), giving Θ(n log n). This is bounded above by n² but not below by a positive constant times n², since log n/n tends to zero. Hence the false bound is C. A loose upper bound can still be true even when it is not tight.

## Solution

Using adjacency lists, up to V extract-min operations and O(E) decrease-key operations each cost O(log V) with a binary heap. Including initialization gives O((E+V)log V), D. The O(E+V log V) bound requires different amortized heap operations, such as a Fibonacci heap, not a standard binary heap.

Dijkstra extracts each vertex once and may relax each edge. A binary heap takes logarithmic time for extract-min and decrease-key, producing V log V plus E log V. The sum is O((V+E)log V). The tempting E+V log V bound uses an amortized heap with cheaper decrease-key, not the specified ordinary binary heap. Positive weights ensure the settled-distance greedy step is valid.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Merge roughly log n sorted lists, each containing roughly n/log n elements, using a heap. Options include A O(n log log n), B Θ(n log n), C Ω(n log n), D Ω(n^(3/2)). Find the intended efficient merge bound.

## Solution

Keep the smallest remaining item from each of k=Θ(log n) lists in a min-heap. Repeatedly extract the minimum and replace it by the next item from the same list. There are Θ(n) items, each costing O(log k)=O(log log n), so the merge costs O(n log log n), A. The comparison lower bound for arbitrary interleavings of equally sized lists is Ω(n log k), so this is also the worst-case asymptotic order.

Teaching detail:
The heap needs one current head per list, only Θ(log n) elements. Removing the smallest head and inserting its successor costs O(log log n), not O(log n), because heap height depends on list count. Repeating for Θ(n) output elements gives O(n log log n). The lists are already internally sorted, so sorting their whole union from scratch would waste that available order.

**Independently derived answer:** D

**Paraphrased problem context:** Two undirected-graph decision problems: α asks for an independent set of size |V|−4; β asks for an independent set of size 5. A α in P, β NP-complete; B α NP-complete, β in P; C both NP-complete; D both in P. The source says independent set, not clique, for β.

## Solution

For α, an independent set of |V|−4 vertices exists exactly when some four-vertex complement covers all edges (handle |V|<4 separately). Enumerate O(n^4) complements and check the remaining edges. For β, enumerate O(n^5) five-vertex subsets and test that all ten vertex pairs are nonedges. Both are polynomial-time because 4 and 5 are constants, so D.

Teaching detail:
An independent set leaves no edge with both endpoints inside it. For α, enumerate every possible four-vertex excluded set and test the remaining induced graph for an edge; O(n⁴(n+m)) is polynomial. For β, enumerate every five-vertex set and test its ten pairs for the absence of edges; O(n⁵) suffices with adjacency lookup. Unlike the NP-complete general independent-set problem, the relevant size or complement size here is a fixed constant, not part of the input. Hence both are in P.

**Paraphrased problem context:** double foo(int n){int i;double sum;if(n==0)return 1.0;sum=0.0;for(i=0;i<n;i++)sum+=foo(i);return sum;} Printed 81(a): maximum auxiliary space of foo(n)? A O(1); B O(n); C O(n!); D O(n^n). Seek intended tight order, not merely any loose upper bound.

## Solution

Every activation stores only a constant number of locals, but calls are nested. A path foo(n)→foo(n−1)→…→foo(0) reaches n+1 simultaneous activations. The loop calls execute sequentially, so the exponentially many calls are not all live at once. Maximum stack space is Θ(n), option B.

Teaching detail:
Count simultaneously live activations, not total recursive calls. During its last recursive branch, foo(n) may be suspended while foo(n−1), foo(n−2),…, foo(0) are active, giving linear depth. Each frame contains only a constant number of scalar locals. Separate loop iterations return before the next call, so their storage is reused. This distinguishes linear stack space from exponential running time. Larger Big-O choices are also loose bounds; the intended answer describes the tight growth.

A recursive implementation can still have a linear stack, but adding two linear requirements remains linear. The table itself gives a linear lower bound in the stated storage scheme. Count constant-size machine words as specified by the double implementation; arbitrary-precision value bit lengths would be a different model.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=11), physical page 11. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Paraphrased problem context:** Undirected connected graph has distinct positive edge weights. Partition X, Y separates s∈X, t∈Y; e is the minimum-weight edge crossing that cut. Printed 82(a): e must belong to which object: minimum spanning tree, weighted shortest s–t path, every s–t path, or weighted longest s–t path? GFG has a blank A and shifted labels; preserve the concept rather than a universal option letter.

## Solution

Let T be a minimum spanning tree. If its edges omit the unique lightest crossing edge e, insert e into T, making a cycle. That cycle contains another edge f crossing the same cut. Distinct weights give w(e)<w(f); replacing f by e makes a lighter spanning tree, a contradiction. Hence e belongs to the MST. Connectivity is implicitly required for a spanning tree (otherwise use a minimum spanning forest in relevant components). GFG prints this answer beside B after a blank A; GateForum prints it as A. The answer concept is unambiguous, but the source option letters are not interchangeable.

Teaching detail:
Use an exchange argument. If an MST omitted the lightest crossing edge, adding it creates a cycle. Because its endpoints are on opposite sides, the rest of that cycle must cross the same cut elsewhere. Replace that heavier crossing edge by e; distinct weights make the improvement strict, contradicting minimality. This proves MST membership but not membership in every s–t path: a path can cross on a more expensive edge. Minimum total distance is a different objective.

**Independently derived answer:** A

**Paraphrased problem context:** Undirected connected graph has distinct positive edge weights. Partition X, Y separates s∈X, t∈Y; e is the minimum-weight edge crossing that cut. Printed 82(b): path congestion is its largest edge weight. Which always minimizes congestion from s to t? A path in an MST; B weighted shortest path; C Euler walk; D Hamiltonian path.

## Solution

Take the s–t path in an MST and let f be its heaviest edge. Removing f partitions the tree with s and t on opposite sides. Any other s–t path must cross this cut. A crossing edge lighter than f could replace f to improve the MST, so every crossing edge has weight at least w(f). Every alternative path therefore has bottleneck at least w(f), exactly the MST path’s bottleneck. Option A.

Teaching detail:
Take the unique s–t path in an MST and remove its heaviest edge f. This creates a cut separating s, t. If any crossing edge were lighter than f, substituting it would create a cheaper spanning tree. Thus every alternative s–t path must use a crossing edge at least as heavy as f. Its maximum edge cannot be lower than the MST path’s maximum, proving minimax optimality even though the MST path need not minimize total distance.

Printed 84(a): in a maximum-profit schedule A all jobs done; B T1, T6 omitted; C T1, T8 omitted; D T4, T6 omitted.

## Solution

Order jobs by descending profit and put each in the latest free slot not exceeding its deadline. One resulting schedule in slots 1…7 is T2, T7, T9, T5, T3, T8, T1. Their deadlines are respectively 2, 2, 3, 4, 5, 7, 7, so all meet their deadlines. T4 and T6 are omitted, option D. In particular T2, T4, T7, T9 all have deadline≤3, so at least one of them must be omitted; T4 has their lowest profit. Only seven slots exist through the latest deadline, requiring another omission, optimally T6.

Teaching detail:
The greedy unit-job method processes larger profits first and places each job as late as its deadline permits, leaving earlier slots for tighter deadlines. It yields T2, T7, T9, T5, T3, T8, T1. Check every slot against its deadline:1≤2, 2≤2, 3≤3, 4≤4, 5≤5, 6≤7, 7≤7. T4 and T6 are absent. The three-slot deadline bottleneck among T2, T4, T7, T9 explains why a job must be omitted even before considering total capacity.

**Paraphrased problem context:** Nine unit-time jobs T1…T9, one at a time, earn profits[15, 20, 30, 18, 18, 10, 23, 16, 25] if finished by deadlines[7, 2, 5, 3, 4, 5, 2, 7, 3], respectively. Printed 84(b): maximum profit A147; B165; C167; D175.

## Solution

The schedule T2, T7, T9, T5, T3, T8, T1 earns 20+23+25+18+30+16+15=147. All nine profits sum to 175. At least one of the four jobs with deadline≤3 must be dropped, losing at least 18, and at least one additional job must be dropped since the latest deadline is 7, losing at least 10. Therefore profit≤175−18−10=147, attained above. Option A.

Teaching detail:
Sum the feasible schedule’s seven profits to obtain 147. For optimality, the four jobs with deadline at most 3 cannot all fit in three slots, requiring a loss of at least 18. At most seven jobs can finish by the latest deadline 7, so another distinct job must be omitted, losing at least 10. Subtract these unavoidable losses from 175 to get upper bound 147, matched by the schedule. Thus the result is proven optimal rather than just a greedy candidate.
