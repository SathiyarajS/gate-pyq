**Paraphrased problem context:** Which asymptotic claims are correct? I. (n+k)^m=Θ(n^m) for fixed constants k,m; II. 2^(n+1)=O(2^n); III. 2^(2n)=O(2^n) in GFG; GateForum instead shows 2^(2n+1)=O(2^n). Both claims have the same false truth value. A. I and II; B. I and III; C. II and III; D. I, II and III.

## Solution

1. Test big-O claims by ratios. A bounded positive ratio suffices for O; a ratio bounded away from zero as well establishes Θ. Doubling the exponent is not multiplying the result by a constant: 2^(2n)=(2^n)². This is the specific error behind claim III.

2. For fixed k,m, ((n+k)^m)/(n^m)=(1+k/n)^m tends to 1, so I holds.2^(n+1)=2·2^n, so II holds. But 2^(2 n)/2^n=2^n is unbounded, so III fails. Thus I and II only, A. In the GateForum variant, the ratio for III is 2^(n+1), which is likewise unbounded.

**Paraphrased problem context:** An undirected graph has vertices {a,b,e,f,g,h} and edges {ae,ab,af,eb,eg,bf,bh,fh,fg,gh}. Which listed sequences can be depth-first traversals starting at a, allowing arbitrary neighbor order? I. a,b,e,g,h,f; II. a,b,f,e,h,g; III. a,b,f,h,g,e; IV. a,f,g,h,b,e. A. I, II and IV only; B. I and IV only; C. II, III and IV only; D. I, III and IV only.

## Solution

1. DFS must finish every reachable unexplored neighbor before returning from a vertex. The three accepted sequences can be realized without any backtrack until all six vertices are visited because each consecutive pair is an edge. In II the transition from f to e would require backtracking through b, but f still has unvisited neighbors g and h, so DFS cannot yet leave f. Hence e cannot be next.

2. I, III and IV each trace a simple path through all vertices using displayed edges, so a neighbor order realizes each. In II, f has no edge to e and still has unvisited neighbors g and h; DFS must visit one of these before backtracking. Thus II is impossible and the answer is D.

**Paraphrased problem context:** Array insertion sort normally uses linear search to find where the next element belongs. If binary search replaces that search, what happens to worst-case total running time? A. It remains Θ(n²); B. It becomes Θ(n(log n)²); C. It becomes Θ(n log n); D. It becomes Θ(n).

## Solution

1. During insertion into a sorted prefix of length i, search needs O(log i) comparisons but opening an array slot may move i elements. Summing these movements over all prefixes dominates the sum of logarithmic searches. Binary search improves comparisons, not the cost of physically maintaining the sorted array.

2. Binary search reduces comparisons needed to locate each insertion position, but array elements still must shift to make room. A reverse-sorted input needs 1+2+...+(n−1)=Θ(n²) moves. The worst-case runtime therefore remains Θ(n²), A, despite O(n log n) comparisons.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** For a permutation a1,...,an of n distinct integers, an inversion is an index pair i<j with ai>aj. What is insertion sort's worst-case time if inputs are restricted to permutations of 1,...,n with at most n inversions?
A. Θ(n²)  B. Θ(n log n)  C. Θ(n^1.5)  D. Θ(n)

## Solution

1. In insertion sort, a larger element shifts right exactly when it is an inversion partner of the current key. Each original inversion causes one such shift and is then removed.
2. With I inversions, the inner loops therefore make I shifts. The n−1 outer iterations and their final failed/boundary tests add Θ(n) work, so total work is Θ(n+I).
3. The restriction I≤n gives O(n+n)=O(n). Reading and processing n entries still requires Ω(n), including an already sorted input.
4. Matching the upper and lower bounds gives Θ(n), D. The unrestricted reverse-order example has Θ(n²) inversions and is excluded here.

Baseline derivation and caveats (retained): In standard insertion sort, shifting an earlier larger element past the current key removes exactly one inversion. Total shifts equal the input inversion count I, and outer-loop work plus terminating comparisons contributes Θ(n). Hence running time is Θ(n+I). With I≤n this is O(n), while scanning the n elements requires Ω(n), so the restricted worst case is Θ(n), option D.

**Independently derived answer:** C

**Paraphrased problem context:** The integer cube root of a natural number n is the largest natural m with m³≤n. The input n is represented in binary. Which describes its computation complexity?
A. O(n), but not O(n^0.5)
B. O(n^0.5), but not O((log n)^k) for any constant k>0
C. O((log n)^k) for some constant k>0, but not O((log log n)^m) for any constant m>0
D. O((log log n)^k) for some constant k>0.5, but not O((log log n)^0.5)

## Solution

1. The input length is b=floor(log2 n)+1; complexity in n and in the bit length b must not be confused.
2. Binary search the integer interval [0,n], retaining the largest tested m with m³≤n. Halving the interval takes O(log n)=O(b) iterations.
3. Using schoolbook arithmetic, a multiplication of O(b)-bit numbers costs O(b²); two multiplications form m³. Hence this explicit algorithm costs O(b³), polynomial in log n.
4. The output cube root has about b/3 bits, so even writing it costs Ω(b), which dominates every fixed power of log b. Thus a polynomial in log log n cannot suffice in the bit model, and C follows.

Baseline derivation and caveats (retained): Let b be the number of input bits, so b=Theta(log n). Binary search for the largest m with m³≤n needs O(b) comparisons. Schoolbook multiplication computes a b-bit cube in O(b²) bit operations, giving an explicit O(b³) algorithm. The answer itself has Theta(b) bits for growing n, so writing it already requires Omega(b) bit operations. Thus the problem is polynomial in log n, but not polynomial in log log n, option C. This is a bit-complexity statement, not a unit-cost model for arbitrarily large integers.

**Paraphrased problem context:** G=(V,E) is an undirected graph with subgraph G1=(V1,E1). Give an edge weight 0 if it is in E1, and 1 otherwise. Run single-source shortest paths from an arbitrary v1∈V1. Which property can always be inferred from the computed path costs?
A. Number of edges in shortest paths from v1 to every vertex of G
B. G1 is connected
C. V1 forms a clique in G
D. G1 is a tree
Interpret B as determining whether G1 is connected, not asserting connectivity on every input.

## Solution

1. With only weights 0 and 1, a finite path has total cost 0 precisely when all of its edges belong to E1.
2. Hence d(v1,v)=0 precisely for vertices in the G1 component of v1. Test this for every v∈V1: all distances zero means G1 is connected; any positive/infinite distance means it is not.
3. Cost does not count zero-weight edges. A zero-weight chain and a zero-weight clique on V1 can give identical distance-zero results but different edge counts and cycle structure.
4. Thus the distances determine connectivity (B), but neither clique/tree status nor shortest-path edge counts.

Baseline derivation and caveats (retained): An edge has weight zero exactly when it belongs to E1. Consequently, for a vertex v in V1, distance(v1,v)=0 exactly when v is connected to v1 using only edges of G1. Checking whether every vertex of V1 has zero distance therefore decides whether G1 is connected, B. Zero distances do not reveal edge counts, clique structure, or acyclicity: a tree and a triangle within the reachable zero-weight component can have identical distances. B must be read as determining connectivity, not asserting that every possible input G1 is connected.

ac:1; ad:2; cd:2; bg:2; ei:2; bd:3; fh:4; hi:4; ij:5; ab:6; ae:8; eh:8; gh:8; fi:9; ef:11; gi:14; dh:15; gj:19.

## Solution

1. Kruskal processes edges by nondecreasing weight, accepting an edge only when its endpoints lie in different components.
2. Accept ac(1), ad(2); reject cd(2), since a,c,d are already connected. Accept bg(2), ei(2), then bd(3), which joins {b,g} with {a,c,d}.

5. Total=1+2+2+2+3+4+4+5+8=31, B. eh(8) is internal to the second component and is not needed.

Baseline derivation and caveats (retained): Kruskal's algorithm can select ac(1), ad(2), bg(2), ei(2), bd(3), fh(4), hi(4), ij(5), and gh(8). These nine edges connect all ten vertices without a cycle. Their total is 1+2+2+2+3+4+4+5+8=31, option B. The other weight-2 edge cd is skipped because ac and ad already connect c and d; the final weight-8 edge joins the two remaining components. Equal-weight alternatives may produce a different MST with the same total.

# GATE 2003: Q70 (printed CS Q70)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203452/GATE2003.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** G is a directed n-vertex graph. A path may repeat vertices; a simple path has no repeated vertex. Initialize A[j,k]=1 when edge (j,k) exists, otherwise 0. Run in-place:
for i=1,...,n:
  for j=1,...,n:
    for k=1,...,n:
      A[j,k]=max(A[j,k], A[j,i]+A[i,k])
Which is necessarily true at termination?
A. A[j,k]≤n
B. If A[j,j]≥n−1, G has a Hamiltonian cycle
C. Whenever a path j→k exists, A[j,k] is its longest-path length
D. Whenever a path j→k exists, every simple j→k path has at most A[j,k] edges

## Solution

1. Initially every one-edge path has its length represented by A[j,k]≥1. Updates only increase entries, so established lower bounds persist.
2. For a simple path with internal vertices, take its highest-numbered internal vertex i. Splitting there gives two subpaths whose internal vertices have smaller indices. Inductively their lengths are bounded above by A[j,i] and A[i,k] before processing i.
3. The update therefore makes A[j,k] at least the sum of those lengths, the length of the original path. This proves D for every simple path.
4. This is not a correct longest-simple-path algorithm: it never checks that the joined paths are disjoint. Cycles can repeatedly inflate values, and zero is an unsafe unreachable marker for maximizing lengths. Therefore exactness, an n bound and Hamiltonian-cycle inference do not follow.

Baseline derivation and caveats (retained): The recurrence A[j,k]=max(A[j,k],A[j,i]+A[i,k]) gives option D. Induct on the largest-index internal vertex of a simple path: direct edges start at one; splitting a path at its largest-index internal vertex combines previously established lower bounds for the two pieces. Monotone updates cannot destroy them. Thus the final A[j,k] is at least the length of every simple j-to-k path. It need not equal a longest-path length: cycles and zero values used for nonexistent edges can inflate entries, so the other claims fail. For example, a directed two-vertex cycle with an isolated third vertex can produce values larger than n and large diagonal entries although there is no Hamiltonian cycle. Neither the claimed n bound nor the exact-longest-path interpretation is justified.
