**Paraphrased problem context:** For n>1, T1(n)=4T1(n/2)+T2(n), and T2(n)=5T2(n/4)+Θ(log₂n). Both equal 1 for n≤1. Determine T1’s asymptotic order among n², n²log₂n, n^(log₄5), and n^(log₄5)log₂n.

**Type / marks:** MCQ, 1.

**Official answer:** A

**Derived answer:** Theta(n^2)

## Solution

Givens and goal
For n>1, T1(n)=4T1(n/2)+T2(n), and T2(n)=5T2(n/4)+Θ(log₂n). Both equal 1 for n≤1. Determine T1’s asymptotic order among n², n²log₂n, n^(log₄5), and n^(log₄5)log₂n.

Approach
Solve T2 first, then use its growth rate as the nonrecursive term in the recurrence for T1.

Step-by-step solution
1. In T2, the branching parameters are a=5 and b=4. The critical power is n^(log₄5). Set α=log₄5≈1.161.
2. A logarithm is polynomially smaller than n^α: for example log₂n=O(n^(α/2)). The first case of the Master theorem therefore gives T2(n)=Θ(n^α).
3. Substitute into T1: T1(n)=4T1(n/2)+Θ(n^α). Its critical power is n^(log₂4)=n². Because α<2, the additive term is again polynomially smaller than the critical power.
4. Applying the same Master-theorem case yields T1(n)=Θ(n²), option A. There is no extra logarithmic factor because the additive term is not Θ(n²), which would be the balanced case.
5. A recursion-tree check explains the dominance. At depth j, the T2 work totals Θ(4^j(n/2^j)^α)=Θ(n^α(4/2^α)^j). The ratio exceeds 1, so lower levels dominate. With depth log₂n, the leaf scale is 4^(log₂n)=n². Standard floor/ceiling handling of non-power inputs does not change this asymptotic result.

**Paraphrased problem context:** In an undirected integer-weighted graph, d_k(u) is the minimum weight of an s-to-u path with at most k edges, or infinity if none exists. S1 says d_(k+1)(u)≤d_k(u). S2 says that if edge (u,v) lies on a shortest s-to-v path, then d_k(u)≤d_k(v) for every k. Classify S1 and S2.

**Type / marks:** MCQ, 2.

**Official answer:** A

**Derived answer:** A

## Solution

Givens and goal
In an undirected integer-weighted graph, d_k(u) is the minimum weight of an s-to-u path with at most k edges, or infinity if none exists. S1 says d_(k+1)(u)≤d_k(u). S2 says that if edge (u,v) lies on a shortest s-to-v path, then d_k(u)≤d_k(v) for every k. Classify S1 and S2.

Approach
Compare nested feasible path sets for S1 and use an explicit small edge-budget counterexample for S2.

Step-by-step solution
1. Every path using at most k edges also uses at most k+1 edges. The feasible set for d_k(u) is therefore contained in the feasible set for d_(k+1)(u).
2. Minimizing over a larger set cannot increase the minimum. Hence d_(k+1)(u)≤d_k(u), including the situation where an unavailable path of value infinity becomes available. S1 is true without assuming positive weights.
3. For S2, consider four vertices s,a,u,v with edges s—a of weight 1, a—u of weight 1, u—v of weight 1, and s—v of weight 10. The shortest s-to-v path is s—a—u—v, of total weight 3, and it includes (u,v).
4. Impose budget k=1. There is no one-edge s-to-u path, so d₁(u)=∞. But the direct edge s—v is permitted, giving d₁(v)=10. The asserted inequality ∞≤10 is false.
5. Thus only S1 holds, option A. Being a prefix of an unrestricted shortest path does not imply being reachable under the same smaller edge budget. The counterexample uses strictly positive integer weights, so the failure does not depend on negative cycles or an ambiguity about repeated vertices.

**Paraphrased problem context:** A simple undirected edge-weighted graph has distinct edge weights. Assess: A each cycle’s largest edge belongs to no MST; B each cycle’s smallest edge belongs to every MST; C each vertex’s largest incident edge belongs to no MST; D each vertex’s smallest incident edge belongs to every MST.

**Type / marks:** MSQ, 2.

**Official answer:** A;D

**Derived answer:** A;D

## Solution

Givens and goal
A simple undirected edge-weighted graph has distinct edge weights. Assess: A each cycle’s largest edge belongs to no MST; B each cycle’s smallest edge belongs to every MST; C each vertex’s largest incident edge belongs to no MST; D each vertex’s smallest incident edge belongs to every MST.

Approach
Use exchange arguments for the valid cycle/cut statements and connected counterexamples for the invalid ones.

Step-by-step solution
1. For A, suppose an MST T contains the uniquely heaviest edge e of some cycle. Removing e splits T into two components. The rest of the cycle still connects e’s endpoints, so at least one other cycle edge f crosses that cut. Distinctness makes weight(f)<weight(e). Replacing e with f produces a lighter spanning tree, a contradiction. Thus A is true.
2. For D, take the cut {v} versus all other vertices. Let e be v’s unique lightest incident edge. If an MST omitted e, adding e creates a cycle. On that cycle another edge incident to v crosses the same cut and is heavier. Removing it would reduce the tree weight. Thus e must belong to every MST and D is true.
3. B is not a valid cycle rule. Consider edges ad=1, bd=2, ab=3, bc=4, ac=5. In the cycle a—b—c—a the smallest edge is ab=3. But Kruskal’s algorithm selects ad,bd,bc, forming an MST of weight 7 and excluding ab because a and b already have the cheaper connecting path a—d—b.
4. C fails even for a graph that is itself a tree. It has only one spanning tree, so every edge must be present, including a vertex’s heaviest incident edge. A two-vertex graph with one edge is the simplest witness.
5. Select A and D. Distinct weights make these strict exchange comparisons immediate. The ordinary MST question assumes connectivity; for a disconnected graph the corresponding statements apply componentwise to a minimum spanning forest, with no incident-edge claim needed for an isolated vertex.

**Paraphrased problem context:** DFS assigns each vertex discovery time d and finish time f. The directed input graph is acyclic. For an edge u→v, which time orders are impossible? A d[u]<d[v]<f[v]<f[u]; B d[v]<d[u]<f[u]<f[v]; C d[v]<f[v]<d[u]<f[u]; D d[u]<d[v]<f[u]<f[v].

**Type / marks:** MSQ, 2.

**Official answer:** B;D

**Derived answer:** B;D

## Solution

Givens and goal
DFS assigns each vertex discovery time d and finish time f. The directed input graph is acyclic. For an edge u→v, which time orders are impossible? A d[u]<d[v]<f[v]<f[u]; B d[v]<d[u]<f[u]<f[v]; C d[v]<f[v]<d[u]<f[u]; D d[u]<d[v]<f[u]<f[v].

Approach
Use the parenthesis theorem for recursive DFS intervals, then use acyclicity to exclude ancestor-directed back edges.

Step-by-step solution
1. A DFS call remains active while all recursive descendants are explored. Therefore two vertices’ discovery-to-finish intervals are either nested, for an ancestor and descendant, or disjoint. Partial overlap is impossible.
2. D has d[u]<d[v]<f[u]<f[v], a partial overlap. Once v is discovered while u’s call is active, v must finish before that call can finish. Thus D is impossible in every DFS, regardless of whether the graph is acyclic.
3. In B, v’s interval strictly contains u’s, so v is a DFS ancestor of u. The DFS-tree edges give a directed path v→…→u. Together with the given edge u→v, this creates a directed cycle, forbidden in a DAG. Hence B is also impossible.
4. A is possible: take the graph with only edge u→v and begin at u. The times can be d[u]=1,d[v]=2,f[v]=3,f[u]=4, a tree-edge interval.
5. C is possible if v is explored first and finishes before u is discovered. With the same single edge u→v, choose v as the first DFS root: times can be d[v]=1,f[v]=2,d[u]=3,f[u]=4. The later edge goes to an already finished vertex and creates no cycle.
6. Select B and D. The DAG restriction is needed for excluding B; the nesting rule alone already excludes D.

## Solution

Givens and goal
With logarithms base 2, order n^(1/3), log n, log(n!), and 2^(log n) by increasing asymptotic growth. A log n,n^(1/3),2^(log n),log(n!); B n^(1/3),log n,log(n!),2^(log n); C log n,n^(1/3),log(n!),2^(log n); D 2^(log n),n^(1/3),log n,log(n!).

Approach
Simplify the exponential and bound the factorial logarithm.

Step-by-step solution
1. Because the bases match, 2^(log₂n)=n exactly. It must therefore be compared as a linear function, not as an arbitrary exponential.
2. Write log(n!)=Σ(k=1 to n)log k. Every summand is at most log n, giving an upper bound n log n. The last at least n/2 summands are at least log(n/2), giving a lower bound (n/2)log(n/2). Thus log(n!)=Θ(n log n).
3. Any fixed positive power of n eventually dominates log n, so log n=o(n^(1/3)). Also n^(1/3)/n=n^(−2/3)→0, and n/(n log n)=1/log n→0.
4. The required increasing order is log n, n^(1/3), n, Θ(n log n), matching A. This is an eventual growth comparison, not a claim of strict ordering at every small input.

Approach

5. Only A and B are linear. Matching recursion shape alone is insufficient: B and C have the same branching but different work per node.

## Solution

Givens and goal
A weighted directed acyclic graph has n vertices and m edges, with a specified source s. Find the fastest worst-case complexity to compute shortest-path distances from s to reachable vertices: A Θ(m+n); B Θ(m+n log n); C Θ(nm); D Θ(n³).

Approach
Use an order in which every predecessor is settled before its successors.

Step-by-step solution
1. A DAG has a topological ordering: each edge u→v goes forward in that order. Compute one using indegrees or DFS in O(m+n) time with adjacency lists.
2. Initialize d[s]=0 and d[v]=∞ for all other vertices. Process vertices in topological order; for each outgoing edge u→v of weight w, set d[v]=min(d[v],d[u]+w) when d[u] is finite.
3. When u is processed, every possible final edge of a path into u comes from an earlier vertex. By induction, all those predecessor distances are final, so d[u] is the shortest distance. Negative edge weights do not break this argument because there are no cycles or backward dependencies.
4. Each vertex is initialized/processed once and each edge relaxed once, totaling O(m+n). Worst-case instances require reading relevant edge weights and producing vertex distances, giving a matching linear lower bound in the standard input model.
5. Thus A is correct. Dijkstra’s priority queue and Bellman-Ford’s repeated passes are unnecessary when acyclicity supplies the processing order.

## Solution

Givens and goal
For integer A[1…n], determine whether for every i>j in {1,…,n−1}, A[i+1]−A[i] > A[j+1]−A[j]. Choose optimal worst-case time: A Θ(n); B Θ(log n); C Θ(n log n); D Θ(n²).

Approach
Reduce all pairwise comparisons to adjacent comparisons using transitivity.

Step-by-step solution
1. Define d_i=A[i+1]−A[i]. The condition says each later difference is larger than every earlier one. This is equivalent to d_1<d_2<…<d_(n−1).
2. The forward implication includes all adjacent pairs. Conversely, if adjacent inequalities hold, chaining d_j<d_(j+1)<…<d_i proves the required inequality for every i>j.
3. Algorithm: if n≤2 return true; set previous=A[2]−A[1]; for i=2,…,n−1 set current=A[i+1]−A[i]; if current≤previous return false; otherwise set previous=current. If the loop ends return true. Only O(1) extra storage is needed.
4. The loop uses O(n) time. For a lower bound, consider a valid array such as A[i]=i², whose differences are strictly increasing. If any position is unread, an adversary can change that entry sufficiently to violate a neighboring comparison while leaving all inspected values unchanged. Thus worst-case inspection requires Ω(n) entries for n≥3.
5. The optimal bound is Θ(n), A. Use sufficiently wide arithmetic so subtraction does not overflow; the proof is in the mathematical-integer model.
