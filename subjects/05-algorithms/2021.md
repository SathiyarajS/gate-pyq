**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C for n≥5; small-n premise omitted

**Paraphrased problem context:** An array contains n integers. Let t be the optimal worst-case number of element comparisons needed to find both its minimum and maximum. Which printed bound is intended? A t>2n−2; B t>3⌈n/2⌉ and t≤2n−2; C t>n and t≤3⌈n/2⌉; D t>⌈log2 n⌉ and t≤n. The source gives no small-n restriction.

## Solution

The optimal worst-case comparison count for simultaneous minimum and maximum is ceil(3n/2)−2. Compare elements in pairs, then compare each pair’s smaller element only against the running minimum and its larger element only against the running maximum; for even n this costs3n/2−2, and for odd n it costs3(n−1)/2. The standard adversary lower bound matches these counts. Consequently n<t≤3ceil(n/2) for n≥5, giving intended C. Literal qualification: for n=3 or4, t=n, and for n=1 or2 it is smaller, so the strict inequality in C is not valid for every unspecified n.

For even n, first compare one pair to initialize min/max (1 comparison); each of the remaining (n−2)/2 pairs needs one internal comparison and two comparisons with min/max. Total 1+3(n−2)/2=3n/2−2. For odd n, initialize both extrema to the first value for free, then spend three comparisons for each of (n−1)/2 pairs. Pseudocode for each pair (a,b): compare a,b; let lo=min(a,b), hi=max(a,b); compare lo with running_min and hi with running_max. For the matching lower bound, each nonmaximum needs a loss certificate and each nonminimum a win certificate, totaling 2n−2 certificates. An adversary classifies elements as untouched, winner-only, loser-only or both, and consistently places winner-only elements above loser-only elements. Comparing two untouched elements can create two certificates, but such comparisons are disjoint and number at most floor(n/2). Other comparisons can be answered to create at most one new certificate. Therefore at least 2n−2−floor(n/2)=ceil(3n/2)−2 comparisons are needed. This proof concerns worst-case comparisons, not a particular presorted input.

## Solution

The DFS root is an articulation point exactly when it has at least two DFS children. Distinct child subtrees have no connecting edge in an undirected DFS, whereas one child subtree remains connected after deleting the root. This proves B and disproves A. A DFS leaf cannot disconnect the remaining DFS tree when removed, so C is false. D is too strong: use edges x-u, u-y, y-x, u-z and DFS order x, u, y, z. Vertex u is an articulation point because its removal isolates z, but the edge x-y avoids u even though x is its ancestor and y its descendant.

For a nonroot vertex u, the actual test is whether some DFS child v has low[v]≥discovery[u], meaning that child's subtree lacks a back-edge to a strict ancestor of u. It does not assert that every descendant is trapped. The counterexample in the main derivation separates a trapped branch z from a branch y that can reach ancestor x by a back-edge. For the root, two distinct child subtrees cannot connect except through the root, or DFS would have explored them as one subtree.

## Solution

The diagram yields Q(a)=9, Q(c)=1, Q(b)=9, Q(d)=max(1, 9)=9, Q(f)=9, Q(e)=max(9, 81)=81, Q(g)=max(9, 81)=81, Q(t)=max(81, 729)=729. Sum=1+9+1+9+9+9+81+81+729=929. All edge directions and weights were visually inspected.

A topological dynamic program initializes score(s)=1 and all other scores=0, then for each edge u→v sets score(v)=max(score(v),score(u)×weight). A predecessor ordering such as s,a,b,c,d,e,f,g,t suffices. It runs in O(V+E), since a DAG has no profitable cycle to revisit. Store parent pointers when maximizing if an actual maximizing path is also wanted.
