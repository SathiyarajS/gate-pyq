(C) 6

2. 3. Thus three is the standard generic cubic cost, not a universal lower bound for every coefficient choice. Original official wording and key remain unavailable.

4. Teaching check: Evaluate the nested form from the inside: t=a₃x+a₂, then t=tx+a₁, then p=tx+a₀. Each stage contributes one multiplication. The answer depends on treating the cubic as a generic polynomial; it is not a theorem about every particular nonzero coefficient tuple.

Options:
(A) n−1
(B) 2n−2
(C) C(n,2)

## Solution

2. Hence2n−2, B.

3. Teaching check: This is a lower-bound-plus-construction proof. Every spanning tree has exactly n−1 edges and every available edge costs at least two. Connecting consecutive indices achieves that lower bound; no search over all spanning trees is necessary.

Options:
(A) Queue
(B) Stack
(C) Heap
(D) B-tree

## Solution

1. All edges have equal unit cost, so increasing distance order is breadth-first order. A FIFO queue processes each vertex and scans each adjacency list once, in O(V+E) time.

2. Thus A; a priority heap is unnecessary.

3. Teaching check: In an unweighted graph, every discovered neighbor is exactly one hop farther than its predecessor. A FIFO queue keeps frontier layers in nondecreasing distance order, which is the priority rule Dijkstra needs here. With adjacency lists the total scan cost is the sum of degrees, O(V+E).

**Independently derived answer:** C under the standard swap-based comparison

**Paraphrased problem context:** Among the standard in-place sorting algorithms listed, which needs the fewest swaps under the conventional worst-case exchange-count comparison?
Options:
(A) Quicksort
(B) Insertion sort
(C) Selection sort
(D) Heapsort

## Solution

1. Selection sort places the minimum remaining item in its final location with at most one exchange per pass, hence at most n−1 swaps. Standard swap-based insertion sort, quicksort and heapsort can use more.

2. Thus selection sort, C, in the conventional worst-case exchange-count comparison. A shift-based insertion implementation can avoid an explicit swap operation, so literal source-code swap counts are implementation-dependent.

3. Teaching check: Selection sort can inspect the entire unsorted suffix without moving any item, then exchange its minimum with the first unsorted position. This separates comparison count, Θ(n²), from exchange count, O(n). The question asks about swaps, not fastest running time.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B with constant extra space; A also possible with a stack

**Paraphrased problem context:** An array element is a leader if it exceeds every element to its right. Which description gives the best algorithm for finding all leaders? No auxiliary-space restriction is stated, which affects whether the options are exclusive.
Options:
(A) Linear time with a left-to-right pass
(B) Linear time with a right-to-left pass
(C) Divide and conquer in Θ(n log n)
(D) Θ(n²) time

## Solution

1. Scanning right to left while retaining the largest value seen reports exactly the elements strictly larger than every element to their right. This is Θ(n) time and O(1) extra working space, yielding the usual B.

2. However A is also achievable in linear time if extra storage is allowed: scan left to right, keep candidate leaders in a decreasing stack, and pop every prior candidate≤the new value before pushing it. Each entry is pushed/popped at most once; the final stack contains the leaders.

3. Since the prompt does not require constant space, traversal direction alone does not make B uniquely correct.

4. Teaching check: Right-to-left scanning initializes the current maximum with the rightmost element and reports a new element only when it is strictly greater. Equal values do not become leaders if an equal value occurs later. A left-to-right monotone stack is a separate linear-time possibility, explaining the nonunique direction-only options.

**Independently derived answer:** D

**Paraphrased problem context:** T is a depth-first-search tree of an undirected graph G. Distinct u and v are leaves of T and both have graph degree at least 2. Which statement must hold?
Options:
(A) Some vertex w is adjacent to both u and v
(B) Some vertex w has removal disconnecting u from v
(C) Some cycle contains both u and v
(D) Some cycle contains u and every neighbor of u

## Solution

1. In an undirected DFS, every non-tree edge joins a vertex to an ancestor. Since u is a DFS leaf, all its neighbors lie on its single root-to-u tree path.

2. Let w be its highest ancestor-neighbor. The tree path w to u plus the edge uw forms a cycle containing every neighbor of u, since all those neighbors lie between w and u.

3. Degree at least two ensures a genuine cycle. Thus D.

4. Two distinct cycles sharing only a root refute the asserted common cycle; other DFS graphs refute the universal common neighbor and separator assertions.

5. Teaching check: DFS in an undirected graph has no cross edge joining separate finished subtrees. A leaf’s non-parent neighbors must therefore be ancestors. The path from its highest such neighbor to the leaf contains every other neighbor along that ancestor chain, and the closing back edge creates the required cycle.

**Paraphrased problem context:** For integers n>1, T(n)=2T(⌊√n⌋)+1 and T(1)=1. What is the asymptotic growth?
Options:
(A) Θ(log log n)
(B) Θ(log n)
(C) Θ(√n)
(D) Θ(n)

## Solution

1. After h repeated floor-square-root steps, the subproblem size is floor(n^(1/2^h)). For n≥2 it first reaches 1 when n<2^(2^h), so h=floor(log₂(log₂ n))+1.

2. The recurrence tree is a full binary tree of height h. Every node contributes one, including the T(1)=1 leaves, so T(n)=2^(h+1)−1. Because log₂ n<2^h≤2 log₂ n, this is Θ(log n), option B.

3. Teaching check: The depth is Θ(log log n), but exponentiating that Θ statement alone would not justify Θ(log n). The sharper h=log₂(log₂ n)+O(1) bound controls the number of leaves within constant factors. Floor rounding is included explicitly and ensures termination at the stated base case.

Options:
(A) Θ(n)
(B) Θ(n log n)
(C) Θ(n²)
(D) Θ(n³)

## Solution

1. Select the median in Θ(n) time and partition in Θ(n) time, producing two subproblems of approximately n/2 elements. The recurrence T(n)=2T(n/2)+Θ(n) gives Θ(n log n), option B, including the median-selection cost.

2. This assumes standard balanced handling of duplicate keys or distinct keys; a two-way partition that mishandles equal keys can defeat that guarantee.

3. Teaching check: Finding the median is not free, but its linear cost can be absorbed into the same Θ(n) term as partitioning. Each recursion level processes a total of Θ(n) elements, and balanced halves give Θ(log n) levels. Thus median selection does not make quicksort linear overall.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Given two length-n binary arrays a,b, find the longest interval [i,j] on which Σₖ₌ᵢʲaₖ=Σₖ₌ᵢʲbₖ, or report none. Which complexity describes the fastest method?
Options:
(A) O(3^n) and Ω(2^n) time if hashing is allowed
(B) O(n³) and Ω(n^2.5) time in the key-comparison model
(C) Θ(n) time and space
(D) O(√n) time only if the sum of all 2n entries is even

## Solution

1. Set prefix differences D[0]=0 and D[k]=sum(a[1..k])−sum(b[1..k]). A span (i,j) has equal sums iff D[i−1]=D[j].

2. Every D[k] lies in [−n,n], so an array of 2n+1 entries can store the earliest index of each difference. Scan once and maximize the distance to its first occurrence.

3. Time and space are Θ(n), option C; hashing is unnecessary. Reading the inputs already takes Ω(n) time.

4. Teaching check: Store the earliest occurrence of each prefix difference because that maximizes the length to a later equal difference. A binary-array prefix difference stays between −n and n, so direct indexing gives worst-case linear performance rather than relying on average-case hash-table behavior.
