**Paraphrased problem context:** Give the tightest listed upper bound on selection-sort swaps for n numbers: A O(log n), B O(n), C O(n log n), D O(n²).

## Solution

Each selection-sort pass finds the minimum of the unsorted suffix and moves it using at most one swap. There are n−1 passes, and worst-case inputs require a linear number of swaps. Hence O(n), B; the quadratic comparison count does not imply quadratic swaps.

Teaching detail:
On pass i, selection sort scans the remaining suffix to locate its minimum, then swaps it into position i. It may perform many comparisons during that scan, but at most one swap. There are n−1 such passes, giving at most n−1 swaps. A cyclic displacement input can require a swap on each pass, so the worst-case number grows linearly, not logarithmically. The commonly remembered quadratic selection-sort cost counts comparisons, not swaps.

**Paraphrased problem context:** Which are true?1 Undirected-cycle detection is in P.2 It is in NP.3 Every NP-complete problem has a nondeterministic polynomial-time algorithm. A1, 2, 3; B1, 2; C2, 3; D1, 3.

## Solution

Undirected-cycle detection is polynomial via DFS or union-find, so it belongs to P and therefore also NP. By definition an NP-complete decision problem belongs to NP and has a nondeterministic polynomial-time algorithm. All three statements are true, A.

Teaching detail:
DFS detects an undirected cycle in O(V+E) time by finding an already visited neighbor other than the parent, so the first claim is polynomial. Every deterministic polynomial computation is also an allowed nondeterministic polynomial computation, giving P⊆NP and claim2. NP-completeness includes membership in NP in its definition, not only NP-hardness, so claim3 follows. No assumption that P≠NP is needed for any of these conclusions.

**Paraphrased problem context:** What is standard Bellman–Ford complexity on a complete n-vertex graph? AΘ(n²), BΘ(n²log n), CΘ(n³), DΘ(n³log n).

## Solution

The standard Bellman-Ford algorithm performs up to n−1 full edge-relaxation passes. A complete graph has Θ(n²) edges, yielding Θ(n³) time, C, for the usual worst-case/full-pass algorithm.

Teaching detail:
One relaxation pass examines all edges. The standard algorithm allows n−1 passes because a simple shortest path can use up to n−1 edges. A complete directed graph has n(n−1) edges; an undirected one has n(n−1)/2, both Θ(n²). Multiplying by Θ(n) passes gives Θ(n³). Early termination may improve a particular instance, but does not change the stated standard worst-case/full-pass bound.

**Paraphrased problem context:** How many elements can heapsort sort in Θ(log n) time? AΘ(1), BΘ(√log n), CΘ(log n/log log n), DΘ(log n).

## Solution

Let m be the number of elements. Heapsort takes Θ(m log m). Choosing m=Θ(log n/log log n) gives log m=Θ(log log n), so m log m=Θ(log n). Hence C; m=Θ(log n) would require an extra log log n factor.

Teaching detail:
Use a new variable m for the input length, since n only describes the time budget. Heapsort costs Θ(m log m). Set L=log n. The candidate m=L/log L has log m=log L−log log L=Θ(log L), so m log m=Θ(L). Constant m is too small, and m=√L gives Θ(√L log L)=o(L). Setting m=L instead gives Θ(L log L), which is too large. Thus the inverse scale is log n/log log n.

**Paraphrased problem context:** Besides constant-time Enqueue/Dequeue, MultiDequeue sets m=k and repeatedly dequeues while the queue is nonempty and m>0, decrementing m. Starting with an empty queue, find worst-case total time for n top-level operations: AΘ(n), BΘ(n+k), CΘ(nk), DΘ(n²).

## Solution

Let E be the number of Enqueue operations among the n top-level operations. Starting from an empty queue, at most E elements can be removed in total, whether by individual Dequeue calls or inside MultiDequeue. Therefore all successful inner-loop iterations together cost O(E)⊆O(n), not O(nk). Each top-level call and each terminating loop check contribute O(1), adding O(n). Conversely, n calls incur Ω(n) total overhead, and n Enqueue calls witness that bound. The worst-case total is Θ(n), option A, assuming constant-time primitive queue operations and constant-time arithmetic on the counter.

Teaching detail:
Charge every actual deletion to the earlier insertion that supplied that element. Since an element cannot be deleted twice without being inserted again, the total number of successful dequeues is no larger than the number of Enqueue operations, at most n. MultiDequeue also performs one final failing guard check, but there are at most n top-level calls to pay for those checks. This accounting bounds the complete sequence by a constant times n regardless of k. Multiplying the worst cost of one call by n would ignore the initially empty queue and double-count available elements.
