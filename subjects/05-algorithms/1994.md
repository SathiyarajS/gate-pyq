**Essential problem context (paraphrased):** Which recurrence models worst-case binary search: T(n)=T(n/2)+k, 2T(n/2)+k, T(n/2)+log n, or T(n/2)+n?

## Solution

A binary-search step compares the target with the middle key and discards one half. Only the surviving half is searched recursively, so there is one T(n/2) term, not two. Selecting and comparing the middle item takes constant time in an indexed array, represented by k. Repeated halving reaches a constant-size range after Θ(log n) steps. The recurrence presupposes constant-time midpoint access; a linked-list implementation has different access costs.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Essential problem context (paraphrased):** Does quicksort use dynamic programming, backtracking, divide and conquer, or greedy design?

## Solution

Quicksort chooses a pivot, partitions the input into regions ordered relative to it, and recursively sorts those smaller regions. The resulting subproblem solutions combine to give the sorted whole, so the design is divide and conquer. It does not cache overlapping subproblems as dynamic programming does, and it does not search and undo candidate solutions as backtracking does. Good or bad pivot choices affect the balance and complexity, not this classification.

**Essential problem context (paraphrased):** Which is false: optimal BST via dynamic programming; BFS cannot find connected components; preorder/postorder do not generally uniquely determine a binary tree; DFS can find components?

## Solution

Start BFS from an unvisited vertex and mark everything reachable. In an undirected graph this is exactly its connected component. Repeating from remaining unvisited vertices finds every component in O(V+E), disproving B. DFS works similarly. Optimal BST construction has a dynamic-programming formulation. Preorder and postorder alone do not generally distinguish a node’s sole left child from its sole right child, so nonuniqueness is possible. That last statement is a general insufficiency, not a claim that every traversal pair is ambiguous.

# GATE 1994: Q53 (printed A Q7)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** In order: i<min; (j+K) mod n ≠ i; A[(j+K) mod n]; temp; i+1.

**Essential problem context (paraphrased):** A[0..n−1] contains n integers. Shift it cyclically left K places, 1≤K≤n−1, in linear time without another array. Fill the five blanks in this skeleton.
min:=n; i:=0;
while ___ do begin
  temp:=A[i]; j:=i;
  while ___ do begin
    A[j]:=___; j:=(j+K) mod n;
    if j<min then min:=j;
  end;
  A[(n+i-K) mod n]:=___;
  i:=___;
end;

## Solution

1. The desired assignment is new A[j]=old A[(j+K) mod n]. Follow this permutation one cycle at a time.

2. Save the first value in temp, copy forward along the cycle, and stop before the next source would be the overwritten start. The last destination is (i−K) mod n, where temp belongs.

3. Let g=gcd(n,K). The first cycle contains precisely the indices divisible by g. Its smallest positive visited index is g, so min becomes g. For K in the given range the cycle has at least two positions.

4. The remaining starts 1,…,g−1 cover the other residue classes. No update makes min smaller than g. After these g cycles the outer loop ends. Each index is assigned once, so time is Θ(n), with O(1) extra storage.

Code:
min := n; i := 0
while i < min:
    temp = A[i]; j = i
    while (j + K) % n != i:
        A[j] = A[(j + K) % n]
        j = (j + K) % n
        if j < min: min = j
    A[(n + i - K) % n] = temp
    i = i + 1

# GATE 1994: Q78 (printed B Q24(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Choose u of degree at most one in the current induced forest; add u iff no original neighbor of u is already in I.

**Essential problem context (paraphrased):** Complete this scheme for a tree: V is its vertex set, I=∅; while V≠∅ choose u∈V satisfying blank 1, set V:=V−{u}, and if u satisfies blank 2 set I:=I∪{u}; output I. Fill both properties to obtain a maximum independent set.

## Solution

Fill the first blank with: u is a leaf or isolated vertex in the forest induced by the current V. Fill the second with: u has no neighbor already in I, where adjacency is measured in the original tree. The removal changes the working forest only; it must not erase the adjacency information needed to test membership conflicts. Because every nonempty forest has a vertex of degree at most one, selection is always possible.

Independence is immediate: a vertex enters I only after checking that it is nonadjacent to every earlier selected vertex. To prove maximum size, maintain the stronger invariant that some maximum independent set of the original tree contains I and uses no previously rejected vertex. Consider a selected leaf u of the working forest. If u already has a neighbor in I, no independent set extending I can use u; rejecting it preserves the invariant. Otherwise u is eligible. In the remaining eligible graph it has at most one neighbor. If it has none, every maximum extension includes it. If it has one neighbor v, take a maximum extension: when it omits u, it must contain v (otherwise u could be added). Replace v by u. This preserves cardinality and independence, since u has no other eligible neighbor and none in I. Thus some maximum extension contains u, so adding u is safe.

At termination no undecided vertices remain; the invariant makes I itself maximum. “Choose any vertex and add it if possible” would guarantee only maximality, not maximum size: choosing the center of a star first is a counterexample. The leaf condition is essential.

# GATE 1994: Q79 (printed B Q24(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Θ(n) time and O(n) working space with adjacency lists, degree counters and a leaf queue; naïve rescanning may take Θ(n²).

**Essential problem context (paraphrased):** For the tree independent-set algorithm that repeatedly removes a current leaf or isolated vertex and adds it if it has no selected neighbor, determine the time complexity and necessary implementation assumptions.

## Solution

A tree with n vertices has n−1 edges. Store its original adjacency lists, each vertex's current degree, a removed flag, a selected-neighbor (blocked) flag, and a queue of vertices whose current degree is at most one. Initializing these structures takes O(n+|E|)=O(n) time.

Pop a still-unremoved queue entry u, mark it removed, and add it to I exactly when its blocked flag is false. If added, mark its neighbors blocked. For each still-present neighbor, decrement the neighbor's degree; enqueue it when its degree first falls to one. Isolated initial vertices are queued from the start. Any harmless duplicate or stale entries can be skipped with the removed flag; alternatively use a queued flag.

Every vertex is removed once. Its adjacency list is scanned only a constant number of times, and the sum of degrees is 2(n−1). Hence all degree maintenance, blocking updates and queue operations total O(n). Reading all vertices and producing the result requires Ω(n) in the worst case, yielding Θ(n) time. The queue, flags, degree counts and adjacency representation require O(n) space.

The abstract scheme by itself does not force this bound: repeatedly searching all remaining vertices for a leaf or scanning I to test every candidate can take quadratic time. The linear bound is the efficient adjacency-list implementation, not a representation-independent guarantee. This distinction matters because the printed question specifies a tree and an algorithm outline but not data structures.

# GATE 1994: Q80 (printed B Q25)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204113/GATE1994.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Start i=1,j=n; advance i if sum<M, decrease j if sum>M, return at equality. Use i<j for distinct indices, i≤j if reuse is allowed.

**Essential problem context (paraphrased):** An integer array satisfies A[1]≤A[2]≤…≤A[n]. Give Pascal-like linear-time pseudocode to find indices i,j with A[i]+A[j]=M if a pair exists. State how equal indices are treated.

## Solution

For distinct array positions, use: i:=1; j:=n; found:=false; while (i<j) and not found do begin s:=A[i]+A[j]; if s=M then found:=true else if s<M then i:=i+1 else j:=j−1 end; if found then output(i,j) else output('no pair'). A return statement at equality is an equivalent formulation. Use an arithmetic type wide enough to avoid overflow in the sum.

The invariant is that any still-possible pair lies entirely within the index interval [i,j]. If A[i]+A[j]<M, then A[i]+A[k]≤A[i]+A[j]<M for every k≤j in that interval. Therefore no candidate using i works, and discarding i is safe. If the sum exceeds M, then A[k]+A[j]≥A[i]+A[j]>M for all remaining k≥i, so discarding j is safe. Equality supplies a valid witness immediately. These arguments use nondecreasing order and therefore also cover duplicates and negative integers.

Each unsuccessful iteration shortens the interval by one; there are at most n−1 such iterations, giving O(n) time and O(1) auxiliary space. Empty and single-element arrays have no distinct-position pair.

The source does not explicitly require i≠j. If reusing a single position is permitted, change the loop condition to i≤j. The same elimination proof then includes the diagonal pair when 2A[i]=M. Keeping this variant explicit prevents silently rejecting a valid pair under that interpretation.
