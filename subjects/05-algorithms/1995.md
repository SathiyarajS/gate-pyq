**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Essential problem context (paraphrased):** Does merge sort use divide and conquer, backtracking, heuristic search, or a greedy approach?

## Solution

Merge sort divides an input into smaller portions, recursively sorts each portion, then combines the sorted results using a merge. This division into subproblems and combination of their solutions is divide and conquer. It does not search and undo candidate choices as backtracking does, and it is not a sequence of locally optimal choices justified by a greedy exchange property. The merge step is linear, leading to the familiar Θ(n log n) recurrence for balanced splits.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: O(m+n)

**Essential problem context (paraphrased):** How many comparisons asymptotically suffice to merge sorted lists of sizes m and n into one sorted list?

## Solution

Compare the two current front items, emit the smaller and advance that list. Every comparison emits one item, and once one list is exhausted the remaining items can be copied without further comparisons. At most m+n−1 comparisons are therefore needed when both lists are nonempty. Balanced interleavings can attain this bound, giving linear worst-case work. Merely searching in logarithmic time would not output the entire merged list; the standard merge exploits the existing order of both inputs.

**Independently derived answer:** C: gcd of the original integers

**Essential problem context (paraphrased):** For positive integers X,Y, repeatedly replace the larger by its difference from the smaller until X=Y, then print X. What is computed?

## Solution

For X>Y, gcd(X,Y)=gcd(X−Y,Y), because the common divisors are unchanged by subtraction. The symmetric identity holds when Y>X. Thus every loop preserves the original gcd. Both variables remain positive, and their sum strictly decreases on each iteration, so the process terminates. At termination X=Y, whose gcd is that common value. The printed result is therefore the original gcd, not their lcm or the quotient of a single division.

**Independently derived answer:** D: I and III under the usual fixed-table expected-collision interpretation

**Essential problem context (paraphrased):** Evaluate I more hash entries increase collisions; II recursive programs are efficient; III quicksort worst case O(n²); IV binary search on a linear linked list is efficient.

## Solution

Quicksort can repeatedly split off only one pivot, giving (n−1)+(n−2)+…+1=Θ(n²), so III holds. In a fixed-size table under uniform hashing, adding keys increases expected collision pressure, supporting I in the conventional sense. Recursion alone guarantees no efficiency bound, and a linked list lacks constant-time midpoint access, so II and IV are not general truths. Strictly, a particular inserted key can land in an empty bucket without adding a collision; “increases” in I is an expected trend or nondecreasing count, not a guaranteed strict increase at every insertion.

**Official answer:** Not available; no official key located.

**Independently derived answer:** 3

**Essential problem context (paraphrased):** GET(A,B)=1 if B=0; otherwise GET(A,B)=0 if A<B; otherwise GET(A−1,B)+GET(A−1,B−1). Find GET(3,2).

## Solution

The base case with B=0 represents the single way to choose no elements. The A<B case represents the impossibility of choosing more elements than are available. The recursive case separates choices according to whether the last element is excluded or included; it is Pascal’s binomial recurrence.

Expand the requested call rather than assuming a closed form: GET(3,2)=GET(2,2)+GET(2,1). The first term is GET(1,2)+GET(1,1)=0+[GET(0,1)+GET(0,0)]=0+0+1=1. The second is GET(1,1)+GET(1,0)=1+1=2. Hence the result is 3, agreeing with the binomial coefficient C(3,2). The ordering of the tests matters at (0,0): B=0 is tested first and returns 1.

## Solution

Use the usual left-to-right version: compare adjacent entries and swap whenever the left entry exceeds the right. After one full pass, the largest element of the active prefix has bubbled to its final rightmost position. Shorten the active prefix by one for the next pass.

Pass 1: 37,52,12,11,25,92.
Pass 2: 37,12,11,25,52,92.
Pass 3: 12,11,25,37,52,92.
Pass 4: 11,12,25,37,52,92.
Pass 5: 11,12,25,37,52,92.
For example, in pass 1, 92 is successively swapped with 37,52,12,11,25. In pass 2, 52 moves to the penultimate position. A no-swap early-exit implementation would detect completion on pass 5 in this trace.

# GATE 1995: Q82 (printed B Q22)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** GFG:2 MSTs, each weight12: {AB,AE,BC,BD}, {AB,AE,BC,CD}. Literal GateForum:2 MSTs, each weight15: {AE,DE,BC,BD}, {AE,DE,BC,CD}.

**Essential problem context (paraphrased):** The weighted undirected graph has vertices A,B,C,D,E and edges AB=2, AE=3, BC=3, BD=4, CD=4, DE=5. Draw and count all minimum spanning trees. These are the edges visibly present in GFG p8. GateForum p15 omits the AB line while retaining a detached weight2; also analyze that literal graph.

## Solution

A spanning tree on five vertices has four edges. In the GFG graph, AB is the unique cheapest edge crossing the cut {A}, so it belongs to every MST. AE is the unique cheapest edge crossing {E}, and BC is the unique cheapest edge crossing {C}; these too are forced by the cut property. The three edges AB,AE,BC form a tree on A,B,C,E, with D still isolated. Connect D using either BD or CD, each of weight4. Using DE of weight5 instead would cost more. Thus the optimum total is2+3+3+4=12 and there are exactly two choices.

Draw tree1 as E−(3)−A−(2)−B−(3)−C, with an additional B−(4)−D branch. Draw tree2 as the path E−(3)−A−(2)−B−(3)−C−(4)−D. The edge sets in the answer uniquely specify every diagram and show that both graphs are connected and acyclic. Forced edges plus the only two minimum connectors prove completeness, rather than merely exhibiting two examples.

The missing AB line in GateForum materially changes the graph. If interpreted literally, A has only neighbor E, and {A,E} connects to the rest only through ED. Consequently AE=3 and ED=5 are forced. In the remaining BCD triangle, choose BC=3 and either BD=4 or CD=4. This gives exactly two spanning trees of minimum weight15. The count happens to remain2, but the trees and weights differ. Do not silently treat the detached numeral2 as an edge; the alternate GFG raster supplies the evidence for the primary reconstruction.
