**Paraphrased problem context:** What is the tight asymptotic order of the worst-case lower bound on comparisons required by comparison-based sorting of n elements?
Options:
(A) n
(B) n²
(C) n log n
(D) n(log n)²

## Solution

1. A comparison decision tree must distinguish n! possible input permutations, so its worst-case height is at least ceil(log2(n!))=Ω(n log n). Mergesort or heapsort attains O(n log n), making that the tight order of the worst-case comparison bound, C.

2. Teaching check: A binary comparison tree of height h has at most 2^h leaves. Distinct orderings need separate leaves, so 2^h≥n!. Summing logarithms or using Stirling’s estimate gives log2(n!)=Θ(n log n). This lower bound applies to comparison sorting, not every integer-key sorting method.

# GATE 2004: Q39 (printed CS Q39)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D under a unit-cost RAM model

**Paraphrased problem context:** Matrices M1,M2 are stored in arrays A,B respectively. Each may use row-major or column-major contiguous storage. How does this affect the time complexity of a fixed algorithm computing M1×M2?
Options:
(A) Best when A is row-major and B column-major
(B) Best when both are row-major
(C) Best when both are column-major
(D) Independent of storage scheme

## Solution

1. Changing row-major to column-major storage changes the address formula, not the number of arithmetic operations or constant-time element accesses. Thus asymptotic running time for a fixed multiplication algorithm is independent of the layout, D.

2. For the usual i,j,k loop order, A-row-major/B-column-major can improve locality and elapsed time, but that is a cache-performance distinction rather than an asymptotic RAM-operation count.

3. Teaching check: For an r×c row-major array, address(i,j) uses ic+j; column-major uses jr+i. Both formulas take constant time under a unit-cost RAM model. Cache misses may differ dramatically, but that does not by itself alter a fixed algorithm’s asymptotic arithmetic/access count.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** For real arithmetic, m>1 and ε>0, what does this algorithm approximate?
x=m; y=1;
while(x-y>ε) { x=(x+y)/2; y=m/x; }
print(x);
Options:
(A) log m
(B) m²
(C) m^(1/2)
(D) m^(1/3)

## Solution

1. In real arithmetic xy=m initially and after each iteration. Thus x is an upper bound and y=m/x a lower bound for sqrt(m).

2. Updating x to (x+m/x)/2 preserves x≥sqrt(m) and decreases it unless equality holds; resetting y preserves the invariant. The limits agree at sqrt(m).

3. At termination y≤sqrt(m)≤x and x−y≤epsilon, giving absolute error at most epsilon. This is an algorithm question about iteration, not a request to solve an excluded calculus topic; integer division would invalidate the real-arithmetic interpretation.

4. Teaching check: After the update, x is the arithmetic mean of a pair whose product is m, so x≥sqrt(m) by AM–GM. Setting y=m/x gives y≤sqrt(m). Their shrinking gap supplies a direct error bound, not merely a guess based on numerical similarity.

(B) P,Q,R,U,S,T
(C) P,Q,R,U,T,S

## Solution

3. The order is P,Q,R,U,S,T, with final distances 0,1,2,3,4,7 in that order. In particular the diagonal edge is directed R→S, not S→R.

4. Teaching check: Record the finalized distances in extraction order: P:0,Q:1,R:2,U:3,S:4,T:7. Once R is processed, its outgoing R→S edge lowers S to 4. Reversing that arrow would alter the computation, so direction is part of the essential figure data.

**Independently derived answer:** C

**Paraphrased problem context:** A[1..n] stores bits. Function f(m) takes Θ(m) time for positive m, with constant bookkeeping for m=0. What is the complexity of:
counter=0;
for(i=1;i<=n;i++) {
  if(A[i]==1) counter++;
  else { f(counter); counter=0; }
}
Option D is little-o in the clearer GateForum reproduction.
Options:
(A) Ω(n²)
(B) Ω(n log n) and O(n²)
(C) Θ(n)
(D) o(n)

## Solution

1. The counter measures the current consecutive run of ones. A zero invokes f on that run length and then resets the counter.

2. The lengths passed to all calls sum to at most n, because no position containing one belongs to two completed runs. Thus all calls together take O(n), including O(1) bookkeeping for zero-length runs, while the loop itself always performs n iterations and costs Ω(n).

3. Total complexity is Θ(n), C. A final run without a trailing zero does not increase this bound.

4. Teaching check: Charge each unit of f’s linear work to one of the ones in its completed run. No one belongs to two runs, so total charged work is linear. The always-executed loop supplies the matching linear lower bound; little-o(n) cannot describe it.

**Paraphrased problem context:** For positive integer n, find the time complexity of:
int recursive(int n) {
  if(n==1) return 1;
  else return recursive(n-1)+recursive(n-1);
}
Use the ordinary execution model without memoization; the source prose says “a>0” although the code parameter is n.
Options:
(A) O(n)
(B) O(n log n)
(C) O(n²)
(D) O(2^n)

## Solution

1. For positive integer n, each nonbase invocation makes two independent calls at n−1. With the usual unit-cost model and no memoization, T(n)=2T(n−1)+Θ(1), T(1)=Θ(1).

2. The recursion tree has 2^(n−1) leaves and 2^n−1 total calls, yielding Θ(2^n), and hence D. The identical arguments do not make the two evaluations a single call in this abstract execution model; integer overflow and compiler transformations are outside the model.

3. Teaching check: At recursion depth k there are 2^k calls, until depth n−1. Adding the geometric series gives 2^n−1 calls. The depth is only n, but depth alone is not total work when the recursion branches.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Paraphrased problem context:** A program visits every node x of a balanced binary search tree with n leaves, computing g(x). The cost at x is min(number of leaves in x’s left subtree,number in x’s right subtree). What is worst-case total time?
Options:
(A) Θ(n)
(B) Θ(n log n)
(C) Θ(n²)
(D) Θ(n² log n)

## Solution

1. In a perfect balanced tree with n leaves, the root costs n/2, the two children together cost n/2, and every internal level similarly costs n/2. There are log2 n internal levels, so this supplies a Θ(n log n) worst-case lower bound.

2. For any balanced tree, at each depth the subtrees are disjoint and the sum of their leaf counts is at most n; summing min(left leaves,right leaves) at that depth is at most n/2. Height O(log n) gives O(n log n), with traversal overhead O(n).

3. Thus worst-case Θ(n log n), B, assuming the usual balanced binary-tree model.

4. Teaching check: For n=8 in a perfect tree, the root cost is 4, the next level totals 4 and the next totals 4, giving 12 before traversal bookkeeping. Each internal level contributes n/2, and there are log2 n such levels. Counting only the root misses the repeated per-level work.
