**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 2. Consult original wording and choices.

**Paraphrased problem context:** The directed acyclic graph has V={1,2,3,4,5,6} and edges 1→2, 1→3, 2→4, 3→4, 2→5, 4→5, 3→6, 4→6. Which sequence is NOT a topological ordering?
Options:
(A) 1,2,3,4,5,6
(B) 1,3,2,4,5,6
(C) 1,3,2,4,6,5
(D) 3,2,4,1,6,5

## Solution

1. Approach. A topological ordering places the tail of every directed edge before its head. It suffices to find one violated edge to reject an ordering.

2. Derivation and interpretation. The figure has 1→2 and 1→3, then 2,3 preceding 4 and 4 preceding 5,6. A topological ordering must place 1 before 2 and 3. D begins 3,2,4,1 and violates both outgoing constraints from 1; A,B,C respect the displayed edges. Thus D.

**Paraphrased problem context:** Which listed sorting algorithm has the lowest worst-case time complexity?
Options:
(A) Merge sort
(B) Bubble sort
(C) Quick sort
(D) Selection sort

## Solution

1. Approach. Compare guaranteed worst-case bounds, not average performance. Mergesort halves the input and performs linear merging on each recursion level.

2. Derivation and interpretation. Standard mergesort guarantees Θ(n log n) worst-case time. Bubble sort, selection sort and conventional quicksort can take Θ(n²) in the worst case. Hence mergesort, A.

# GATE 2007: Q41 (printed CS Q41)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 10. Consult original wording and choices.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** In an unweighted undirected connected graph, which method most efficiently finds shortest paths from a source S to every other vertex?
Options:
(A) Dijkstra from S
(B) Warshall
(C) DFS from S
(D) BFS from S

## Solution

1. Approach. All edges have equal cost, so distance is the number of edges. A FIFO queue processes every distance-d vertex before any distance-(d+1) vertex.

2. Derivation and interpretation. BFS starts at S and discovers vertices in increasing number of edges from S. When a vertex is first discovered, its level is its shortest-path distance; parent pointers recover paths. With adjacency lists, every vertex and edge is processed O(1) times, giving O(V+E). DFS does not generally find shortest paths; generic Dijkstra adds priority-queue overhead, and Warshall solves a more expensive all-pairs/reachability problem. Thus D is the appropriate algorithm.

# GATE 2007: Q44 (printed CS Q44)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 10. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** For the following source C-style function with n≥m, how many recursive calls are made?
int gcd(n,m) {
    if(n % m == 0) return m;
    n = n % m;
    return gcd(m,n);
}
The source does not explicitly say worst case or m>0; state those assumptions in interpreting the options.
Options:
(A) Θ(log₂ n)
(B) Ω(n)
(C) Θ(log₂ log₂ n)
(D) Θ(√n)

## Solution

1. Approach. This is Euclid’s algorithm. An upper bound comes from a constant-factor size reduction within two calls; a tight worst-case lower bound comes from consecutive Fibonacci arguments.

2. Derivation and interpretation. For positive integers n≥m>0, Euclid replaces (n,m) by (m,n mod m). Within two recursive steps the larger argument decreases by at least a factor of two, so there are O(log n) recursive calls. Consecutive Fibonacci inputs attain a matching lower bound: their quotients are one for most steps, and F_k grows exponentially in k, giving Θ(log n) calls in the worst case (A). The statement does not say worst case: when m divides n, there are zero recursive calls. Therefore Θ(log n) is not a pointwise bound for every input satisfying n≥m. Positive m is also necessary to avoid remainder by zero.

**Paraphrased problem context:** What is the time complexity of this recursive function, with unit-cost arithmetic and square root?
int DoSomething(int n) {
    if(n<=2) return 1;
    else return DoSomething(floor(sqrt(n))) + n;
}
Options:
(A) Θ(n²)
(B) Θ(n log₂ n)
(C) Θ(log₂ n)
(D) Θ(log₂ log₂ n)

## Solution

1. Approach. The function makes one recursive call, not n calls. Each square root halves the logarithm of the argument, so analyze the recursion in terms of log n.

2. Derivation and interpretation. Assuming unit-cost integer arithmetic and square root as intended, T(n)=T(floor(sqrt(n)))+Θ(1). After k reductions the argument is approximately n^(1/2^k), and reaches a constant when 2^k=Θ(log n). Thus k=Θ(log log n), giving D. Adding n to the returned value is one arithmetic operation, not n operations; floors change only constant-level stopping details.

# GATE 2007: Q49 (printed CS Q49)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 12. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** In a connected undirected graph, w is the minimum edge weight and e is a particular edge of weight w. Which statement is false?
Options:
(A) Some minimum spanning tree contains e
(B) If an MST T omits e, every edge of the cycle in T+e has the same weight
(C) Every MST contains an edge of weight w
(D) Every MST contains e

## Solution

1. Approach. Use the exchange argument: inserting a non-tree edge creates one cycle, and removing a cycle edge gives another spanning tree. Equal minimum-weight edges need not be individually mandatory.

2. Derivation and interpretation. Take any MST T. If e is absent, adding it creates a cycle. Every edge of that cycle has weight at least w by global minimality of w, and none can have weight greater than w: exchanging such an edge for e would make a strictly cheaper spanning tree. Thus all cycle edges have weight w, proving B; exchanging any one of them for e produces an MST containing e, proving A. Every MST contains an edge of weight w by the same argument (or contains e itself), proving C. However a triangle with all edges weight w has MSTs omitting any chosen edge, so e need not belong to every MST. D is false, assuming the usual loop-free graph convention.

**Paraphrased problem context:** Given an array of an even number n of values, both its minimum and maximum must be found. Which comparison-count claim is true?
Options:
(A) At least 2n−c comparisons are necessary for some constant c
(B) At most 1.5n−2 comparisons are sufficient
(C) At least n log₂ n comparisons are necessary
(D) None of these

## Solution

1. Approach. A comparison within a pair simultaneously rules one element out as maximum and the other out as minimum. Exploit this dual use before separately reducing the two candidate sets.

2. Derivation and interpretation. Partition the even number n of values into n/2 pairs. Compare within each pair, putting its smaller member in a minimum-candidate set and larger member in a maximum-candidate set. Find the minimum of the n/2 smaller values and maximum of the n/2 larger values. The comparison count is n/2+(n/2−1)+(n/2−1)=3n/2−2, so B. This construction disproves the claimed asymptotically larger lower bounds in A and C.

**Paraphrased problem context:** For the following printed C fragment, T(n) counts for-loop executions on input n. Which asymptotic bounds are intended?
int IsPrime(n) {
    int i,n;
    for(i=2;i<=sqrt(n);i++)
        if(n%i==0) { printf("Not Prime\n"); return 0; }
    return 1;
}
The source redeclares n; interpret the intended divisor-testing algorithm separately from literal C validity.
Options:
(A) O(√n) and Ω(√n)
(B) O(√n) and Ω(1)
(C) O(n) and Ω(√n)
(D) None of these

## Solution

1. Approach. A uniform lower bound must apply to easy inputs too. Even numbers terminate at i=2, whereas prime numbers make the loop test all candidate divisors through floor(√n).

2. Derivation and interpretation. Under the intended interpretation that n is the positive input integer, at most floor(sqrt(n))−1 candidate divisors are tested, so T(n)=O(sqrt(n)). For even n≥4, the first divisor i=2 causes immediate return, so T(n)=1 on an unbounded input family and no uniform Ω(sqrt(n)) lower bound is valid. For all sufficiently large n at least one iteration occurs, establishing Ω(1); B is therefore the intended answer. Prime n attain Θ(sqrt(n)). Source caveat: the printed function uses old-style IsPrime(n) and then declares int i,n inside its body, redeclaring its parameter n in the same scope. This is not valid C as printed; the algorithmic answer requires repairing the parameter declaration/removing the duplicate local n.

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2007.pdf, physical page 19. Consult original wording and choices.

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Letters a,b,c,d,e,f occur with probabilities 1/2,1/4,1/8,1/16,1/32,1/32, respectively. Which list, in a,b,c,d,e,f order, is a Huffman code?
Options:
(A) 0,10,110,1110,11110,11111
(B) 11,10,011,010,001,000
(C) 11,10,01,001,0001,0000
(D) 110,100,010,000,001,111

## Solution

1. Approach. Repeatedly merge the two lowest-probability nodes. Code length is leaf depth in the resulting binary tree; high-probability a should get a one-bit word. Prefix-free alone is not enough to guarantee optimality.

2. Derivation and interpretation. Huffman merging combines e and f (1/32 each) into 1/16, merges with d to 1/8, merges with c to 1/4, merges with b to 1/2, then merges with a. The resulting leaf depths for a,b,c,d,e,f are 1,2,3,4,5,5. Option A supplies a prefix code with these depths: 0,10,110,1110,11110,11111. Bit reversal at internal branches can give other equivalent codes, but A is the listed optimal code.

(C) 2.25

## Solution

1. Approach. Average code length is probability-weighted, not the arithmetic mean of the six word lengths. Huffman merging gives lengths 1,2,3,4,5,5, with the shortest code assigned to the most frequent symbol.

2. Derivation and interpretation. Using the independently derived lengths 1,2,3,4,5,5, the weighted average is (1/2)*1+(1/4)*2+(1/8)*3+(1/16)*4+(1/32)*5+(1/32)*5 = 31/16 = 1.9375 bits per symbol. Answer D.
