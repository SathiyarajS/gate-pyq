**Paraphrased problem context:** Which transformation suffices to turn an arbitrary context-free grammar into an LL(1) grammar? A. Removing left recursion alone; B. Left factoring alone; C. Both removing left recursion and left factoring; D. None of these.

## Solution

1. LL(1) requires a deterministic choice of production from one lookahead symbol. Factoring resolves shared prefixes and removing left recursion removes an immediate predictive-parsing obstacle; neither establishes the required disjoint prediction sets in all grammars. In particular LL(1) cannot describe every context-free language.

2. Removing left recursion and left factoring remove common obstacles but do not make every CFG LL(1). Inherently ambiguous CFLs have no unambiguous grammar, whereas every LL(1) grammar is unambiguous; some unambiguous CFLs also are not LL(1). Thus none of the proposed transformations suffices for an arbitrary CFG, D.

**Paraphrased problem context:** The SLR parser for grammar G has n₁ states and its LALR parser has n₂ states. Which relationship is necessary in the standard constructions? A. n₁<n₂; B. n₁=n₂; C. n₁>n₂; D. None of these.

## Solution

1. SLR states are sets of LR(0) items. Start with canonical LR(1) states for LALR and discard lookaheads to identify equal cores; merging those states leaves the reachable LR(0) cores. Different reduction entries in the tables do not create extra automaton cores.

2. SLR uses the canonical LR(0) item-state cores. LALR merges canonical LR(1) states that share an LR(0) core, leaving one state per such core. Thus their automata have the same number of states, n 1=n 2, B, under the conventional constructions, even though their reduction lookaheads and conflict behavior differ.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B under a restricted one-pass evaluation model

**Paraphrased problem context:** In bottom-up evaluation of a syntax-directed definition, inherited attributes can: A. Always be evaluated; B. Be evaluated only if the definition is L-attributed; C. Be evaluated only if the definition has synthesized attributes; D. Never be evaluated. Discuss the usual parsing-time interpretation and its limitation.

## Solution

1. A synthesized attribute flows from children to parent and is naturally evaluated when a bottom-up parser reduces a production. An inherited attribute flows from parent or siblings toward a child and may be needed before that child is reduced. Therefore identify which dependency schedule the question permits before selecting an option.

2. Inherited attributes cannot in general be computed by the simple reduce-only mechanism used for synthesized attributes. In the usual left-to-right one-pass implementation, usable inherited information must be available from the parent context and already processed left siblings, the L-attributed dependency condition behind B. Even then suitable scheduling/marker productions or stack access may be needed; being L-attributed is not a blanket guarantee for every unmodified LR evaluation scheme. If bottom-up evaluation instead allows building a full parse/dependency graph and later scheduling arbitrary acyclic dependencies, L-attributedness is not necessary. The choice therefore depends on the conventional parsing-time model, which the prompt does not spell out.

**Paraphrased problem context:** For the grammar S→iEtSS′ | a; S′→eS | ε; E→b, consider the usual predictive parsing table M with end marker $. What are M[S′,e] and M[S′,$], respectively?
A. {S′→eS}, {S′→ε}
B. {S′→eS}, ∅
C. {S′→ε}, {S′→ε}
D. {S′→eS,S′→ε}, {S′→ε}

## Solution

1. FIRST(eS)={e}, so insert S′→eS in the e column.
2. S is the start symbol, so $∈FOLLOW(S). In S→iEtSS′, the first S is followed by nullable S′ whose nonempty FIRST is {e}; hence e∈FOLLOW(S) as well.
3. The final S′ inherits FOLLOW(S), giving FOLLOW(S′)={e,$}. For the ε production, put S′→ε in every FOLLOW column, therefore both e and $.
4. The resulting cells are {eS,ε} and {ε}, option D. The two entries in the e cell are the dangling-else conflict, so the grammar itself is not LL(1).

Baseline derivation and caveats (retained): FIRST(eS)={e}, so the rule S′→eS enters M[S′,e]. Because S′ can be empty and follows S in S→iEtSS′, e belongs to FOLLOW(S), while $ belongs to FOLLOW(S) because S is the start symbol. The trailing S′ inherits FOLLOW(S), giving FOLLOW(S′)={e,$}. Thus S′→ε also enters both cells. The e cell contains both alternatives and the $ cell contains only ε, option D; the conflict means this grammar is not LL(1).

**Paraphrased problem context:** Consider S→CC and C→cC | d. This grammar is:
A. LL(1)
B. SLR(1) but not LL(1)
C. LALR(1) but not SLR(1)
D. LR(1) but not LALR(1)

## Solution

1. C generates zero or more c symbols followed by d. Its alternatives begin with distinct terminal symbols: FIRST(cC)={c} and FIRST(d)={d}.
2. Neither C alternative is nullable, so no FIRST/FOLLOW overlap can create a second entry in its parsing-table cells. Put C→cC under c and C→d under d.
3. S has only one production; under either c or d use S→CC. No table cell has two choices. Thus one lookahead symbol always selects a production and the grammar is LL(1), A.

Baseline derivation and caveats (retained): For C→cC|d the alternatives have disjoint FIRST sets {c} and {d}, and neither can derive ε. S has only its single production S→CC. Therefore every predictive-table cell has at most one production and the grammar is LL(1), option A. No stronger bottom-up distinction is needed.

**Paraphrased problem context:** A translation scheme is S→TR; R→+ T {print('+');} R | ε; T→num {print(num.val);}. Token num represents an integer, and num.val is its value. For input 9+5+2, what is printed?
A. 9+5+2
B. 95+2+
C. 952++
D. ++952

## Solution

1. Expand S→TR. The initial T consumes 9 and immediately prints 9.
2. The first R consumes + and invokes T on 5, printing 5. Its following action prints + before the recursive R begins.
3. That recursive R consumes +, invokes T on 2 and prints 2, then prints +. Its final R chooses ε and prints nothing.
4. Concatenating the actions yields 9,5,+,2,+, or 95+2+, B. Moving the plus action to after the recursive R would change the result, but that is not this scheme.

Baseline derivation and caveats (retained): The initial T prints 9. Each R expansion reads +, processes T (which prints the next number), prints +, and only then processes the remaining R. Hence the execution order is 9,5,+,2,+, yielding 95+2+, option B. The action is before the recursive R, so it does not postpone both plus signs to the end.

S→id := E {gen(id.place '=' E.place);}

B. t1=Y+Z; X=t1

4. The ordered output is precisely B. No identifier-copy actions occur in the definition, ruling out C and D; the addition action cannot be bypassed to get A.

Baseline derivation and caveats (retained): An identifier expression uses the identifier’s existing place and emits no copy. The addition allocates one temporary and emits t₁=Y+Z, after which its place is t₁. The assignment then emits X=t₁. Thus the two-instruction sequence in B follows directly; no temporaries are needed merely to refer to Y and Z.

**Paraphrased problem context:** A hypothetical language permits globals but no nested function declarations:
global int i=100, j=5;
void P(x) {
  int i=10;
  print(x+10);
  i=200;
  j=20;
  print(x);
}
main() { P(i+j); }
If the language uses static scoping and call-by-need, what values are printed?
A. 115,220  B. 25,220  C. 25,15  D. 115,105

## Solution

1. Under static scope the actual expression i+j is bound to the globals visible at the call in main. P's local i does not replace that lexical binding.
2. Call-by-need postpones evaluation until first use and caches its result. At print(x+10), the actual is first demanded: global i+j=100+5=105. The first print is 105+10=115.
3. P then sets its own local i to 200 and global j to 20. Neither assignment changes the cached value 105.
4. The second print reuses that value, giving 105. Therefore D. Recomputing 100+20 would be call-by-name, not call-by-need.

Baseline derivation and caveats (retained): Under lexical scope the delayed actual expression i+j refers to main's enclosing global bindings, initially 100 and 5. Its first demand evaluates and memoizes 105, so print(x+10) emits 115. Assigning 200 to P's local i and 20 to global j cannot change the already cached actual value. The later print(x) emits 105. Thus D, 115 followed by 105. Call by need evaluates once on first demand; it is not repeated call-by-name evaluation.
