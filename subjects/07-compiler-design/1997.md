**Essential problem context (paraphrased):** Grammar X→X⊕Y|Y, Y→Z⊙Y|Z, Z→id. Determine associativity of⊕ and⊙.

## Solution

In X→X⊕Y, additional⊕ operators are introduced inside the left X. Thus id⊕id⊕id groups as (id⊕id)⊕id. In Y→Z⊙Y, additional⊙ operators occur in the right Y, grouping id⊙id⊙id as id⊙(id⊙id). Therefore⊕ is left associative and⊙ right associative, A. The lower nonterminal level also makes⊙ bind more tightly, but precedence and associativity are distinct properties.

**Independently derived answer:** C

**Essential problem context (paraphrased):** A language permits arrays whose sizes are unknown at compile time and requires efficient memory use. Can it be compiled using static allocation, dynamic allocation, or only interpreted?

## Solution

The compiler can generate runtime code that evaluates an array’s size, allocates that much storage and records its address and dimensions. Dynamic allocation therefore handles unknown compile-time sizes while avoiding allocation for an arbitrary worst-case bound, giving C. Interpretation is not necessary: compilation can defer particular operations until runtime. Static allocation alone cannot efficiently reserve exactly the required unknown sizes in the general case.

Recursion normally creates nested activation lifetimes, which a stack handles. Dynamic scope concerns name lookup and does not itself force arbitrary object lifetimes. Lexical lookup searches the enclosing declaration chain. At S1, the local x in B shadows A’s x; B’s z and A’s y are accessible. **Essential problem context (paraphrased):** For expression prefix (a*b)*c op…where op is+, *, or exponentiation, which operators permit the accumulated product to remain in one register?

## Solution

After computing a*b, the single accumulator holds that intermediate value. If op is+or*, ordinary precedence and left associativity allow completing the multiplication by c before moving to the following operation; the accumulator can be reused without spilling a*b. If op is exponentiation, the c-power subexpression binds more tightly and normally must be computed before multiplying by the held a*b, creating a second live intermediate. Thus A in the stated compiler-evaluation model. The omitted suffix and machine instruction set are not fully specified; recomputation or different schedules can change storage requirements, so this is not an architecture-independent impossibility theorem.

# GATE 1997: Q83 (printed B Q22)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203902/GATE1997.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Use separate addition/comparison levels, one comparison per expression, and explicit statement/block productions.

**Essential problem context (paraphrased):** A language L is a subset of Pascal with expressions using only + and <, assignment statements, while statements, and compound statements begin ... end. Give an unambiguous grammar. The source does not specify lexical details, empty statements, or a trailing-semicolon convention.

## Solution

Here is one unambiguous grammar under the conventional choices that + binds more tightly than <, + associates to the left, and < is nonassociative. The lexer supplies tokens id and num; reserved words are distinct tokens, and := is assignment. Start symbol S denotes one statement.

S → id := E | while E do S | begin L end
L → S R
R → ; S R | ε
E → A | A < A
A → A + P | P
P → id | num | ( E )

The grammar deliberately uses nonempty compound statements with semicolons between statements, not after the last one. If empty blocks are required, add the separate production S→begin end. If an optional trailing semicolon is required, replace R by R→ε | ; T and T→ε | S R. These are explicit syntax extensions, not facts supplied by the question.

The expression hierarchy enforces a unique outer operator structure. An unparenthesized < must be the single comparison at the E level, so a+b<c+d parses as (a+b)<(c+d), and a<b<c is rejected unless parentheses explicitly group a comparison. Left recursion at A gives (a+b)+c, not a+(b+c). Parentheses delimit a complete nested expression. At statement level, id, while and begin select disjoint alternatives. The keyword do separates a while condition from its body; matching begin/end delimit a compound body, and semicolons separate its statements. There is no if/else construct and hence no dangling-else ambiguity.

For example, while x<y+1 do begin x:=x+1; y:=y+2 end has a unique parse: its loop body is the entire block, containing two assignments. Static type rules, such as requiring a Boolean while condition and compatible assignment types, belong to semantic analysis rather than this context-free grammar. The source does not uniquely determine every optional Pascal syntax feature; the stated conventions make this proposed grammar precise.

## Solution

Use synthesized attributes X.type and X.code for E,T,V; use LHS.type and LHS.name for the assignment target. A code value is a token list, and || denotes concatenation. Identifier type is i or r. The following semantic actions specify the traversal without depending on a particular parser implementation.

V→id:       V.type=give-type(id); V.code=[give-name(id)]
V→(E):      V.type=E.type; V.code=E.code
T→V:        T.type=V.type; T.code=V.code
E→T:        E.type=T.type; E.code=T.code
LHS→id:     LHS.type=give-type(id); LHS.name=give-name(id)

For E→E1+T, let t=join(E1.type,T.type), where join(i,i)=i and every other numeric pair gives r. Set E.type=t and E.code=E1.code || T.code || [(+,t)]. For T→T1*V, set t=join(T1.type,V.type), T.type=t and T.code=T1.code || V.code || [(*,t)]. Subscripting E1 and T1 distinguishes the right-hand-side occurrence from the left-hand-side occurrence of the same nonterminal.

For assign-stmt→LHS:=E, check that the expression can be assigned to the destination. Emit [address(LHS.name)] || E.code || [(:=,LHS.type)]. Writing the LHS first follows the conventional postfix assignment form x y (:=,i); the assignment operator consumes the target address and the computed value. In a textual postfix language the name in that first position can denote its address implicitly.

A necessary semantic convention: with precisely the six listed typed operator tokens, the r arithmetic operators must accept integer operands by implicit widening, and (:=,r) must widen an integer value when needed. Under that convention the rules above handle mixed expressions. For integer x,y and real z, the translation of z:=x+y*z is z x y z (*,r) (+,r) (:=,r). Multiplication is emitted first, preserving the grammar's precedence. A real-to-integer assignment is rejected unless an explicit narrowing rule has been authorized.

If the target instead requires both operands already to have the operator's physical type, implicit widening is unavailable. Then replace operand code c by c||[i2r] whenever its integer result is consumed as real, and similarly before assignment to a real target. This alternative introduces an extra conversion token not supplied in the question. Homogeneous expressions need no such extension. Type tags alone do not define a real-to-integer rounding rule or a machine-level cast. Keeping these conventions explicit avoids silently inventing conversion behavior while still giving a complete translation scheme for the stated operator alphabet.

**Independently derived answer:** Bottom to top: Main, A1, B1, A2, B2. Dynamic links follow the call chain; static links B2→A2, A2→Main, B1→A1, A1→Main.

**Essential problem context (paraphrased):** Consider this Pascal nesting and call structure, with no calls other than those shown. Main declares X; A, nested in Main, declares Y; B, nested in A, declares Z; C, nested in B, also declares Z. Main calls A; A calls B; B calls C and, after C returns, calls A. C contains no procedure calls. At an instant there are five activation records on the runtime stack. Show its top, static and dynamic links, and local variables. Source skeleton:
program Main; var X: integer;
  procedure A; var Y: integer;
    procedure B; var Z: integer;
      procedure C; var Z: integer;
      begin {no procedure calls} end;
    begin C; A end;
  begin B end;
begin A end.
Ellipses in the source allow other non-call work; the skeleton preserves every shown declaration and call.

## Solution

Distinguish a procedure's lexical parent from the activation that calls it. The dynamic link records the caller; the static link records the active instance of the enclosing lexical scope. Calls to A from inside B are recursive calls to a procedure declared directly inside Main, not declarations of a new A inside B.

Trace the shown calls. Main calls A1, which calls B1. B1's call to C1 creates only the fourth record, and C1 makes no further calls. C1 returns before the following call to A2, so its record has been removed. A2 is then the fourth record, and its call to B2 creates the fifth. At any matching five-record stage of this call pattern, the active chain is therefore:

Stack position   Activation   Local slot   Dynamic link   Static link
TOP              B2           B2.Z         A2             A2
                 A2           A2.Y         B1             Main
                 B1           B1.Z         A1             A1
                 A1           A1.Y         Main           Main
BOTTOM           Main         Main.X       null           null

Other ordinary record fields, such as a return address and saved registers, may exist but are not assigned values by the problem. A1.Y and A2.Y are distinct storage cells, as are B1.Z and B2.Z. No numeric values for X,Y,Z can be recovered from the ellipses. The completed C1 record, including its separate C1.Z slot, is absent.

The dynamic chain is B2→A2→B1→A1→Main. The different static chain from B2 is B2→A2→Main. In particular, A2's static link must not point to B1 merely because B1 called it. To create A2, B1 can follow its own static chain B1→A1→Main to find A's lexical parent. This is the central distinction the example tests.
