**Essential problem context (paraphrased):** Which fixed-form FORTRAN77 statements are valid: DO 13 I = 1; A = DIM ***7; READ = 15.0; GO TO 3 = 10?

## Solution

FORTRAN77 does not reserve these apparent keywords, and blanks outside character constants do not distinguish tokens in fixed form. DO 13 I = 1 can therefore be an assignment to variable DO13I, not a DO loop. READ=15.0 assigns to variable READ, and GO TO 3=10 assigns to GOTO3. These names satisfy the traditional letter-first length rule. DIM***7 has an invalid triple-star operator and is not a valid exponentiation expression. The answer concerns statements placed in valid fixed-form source columns and with ordinary implicit typing, not modern free-form parsing.

**Essential problem context (paraphrased):** Global m is declared in PARAM. P declares another local m; Q does not. Where is the global name m directly visible?

## Solution

Lexical lookup in P finds its local m before reaching the enclosing declaration, so unqualified m there denotes the local variable. In Q, which has no local m, lookup reaches the global declaration in PARAM. The same global name is visible in the main block itself. Hence PARAM and Q are the regions of direct visibility, C. The global object can still be accessed indirectly through P’s reference parameters; object accessibility is distinct from whether its identifier is shadowed.

**Essential problem context (paraphrased):** Which first-pass tasks apply: allocate literal space,compute program length,build symbol table,generate load/store machine code?

## Solution

Pass one tracks the location counter and instruction/data sizes. It assigns addresses to labels, records symbol values, and determines the total layout and length. The answer assumes the ordinary two-pass design, not a hybrid implementation that opportunistically emits some instructions early.

## Solution

Let S denote a statement, L a nonempty statement list, E the given expression nonterminal, and id an identifier token. Use:
S → id := E
S → for id := E to E do S
S → begin L end
L → S
L → S ; L

The first production recognizes assignments. The second has a statement as its body, permitting either a single assignment, another loop, or a block. The third encloses a list in begin/end. The two L productions generate exactly one or more statements separated by semicolons, without a trailing semicolon. They replace the informal ellipsis with ordinary CFG recursion; no repetition operator or optional metasyntax is used.

For any finite list length k≥1, apply L→S;L exactly k−1 times and finish with L→S. Conversely each derivation has precisely that separator structure. An empty block is not explicitly requested; if the language separately permits begin end, add an epsilon-list production as an explicit extension rather than silently changing the language. Expression syntax is delegated to the provided E grammar.

**Official answer:** Not available; no official key located.

**Independently derived answer:** Address of a for x; current integer value of b for y.

**Essential problem context (paraphrased):** Procedure P(var x:integer; y:integer) is called as P(a,b). What is pushed on the argument stack for a and b?

## Solution

The var qualifier gives x reference semantics: P must be able to access and modify the caller's actual variable a. Therefore pass a's storage address, not merely its current contents. The unqualified integer y is a value parameter, so evaluate b and push a copy of its current integer value.

After entry, assigning to x changes a because x denotes a through the supplied reference. Assigning to y changes only the callee's copy, leaving b unchanged. Passing the address of b for y would instead implement reference semantics; passing only a's value for x would lose the required alias to the caller's variable.

The question concerns argument payloads, not a complete activation-record layout. Return addresses, saved links and registers may also occupy the stack, but their presence does not change these two payloads. Argument order and stack growth direction depend on the calling convention and are not specified, so no particular push order or numeric offsets should be invented.

# GATE 1993: Q67 (printed II-C Q26(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204139/GATE1993.pdf#page=14), physical page 14. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** DESCRIPTIVE, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** x uses an indirect load/store through its pointer slot; y uses its own value slot directly.

**Essential problem context (paraphrased):** Procedure P(var x:integer; y:integer) receives the address of actual a and value of actual b on its stack. How does generated addressing for x differ from y?

## Solution

With a frame pointer FP and symbolic offsets ox,oy, the slot at FP+ox contains an address, whereas the slot at FP+oy contains an integer. To read x, first load ptr:=memory[FP+ox], then load memory[ptr]. To assign x:=v, store v into memory[ptr]. These operations reach the caller's a.

To read y, load memory[FP+oy] directly. To assign y:=v, store v into that same local argument slot. This changes the callee's copied value, not b. Thus reference-parameter access has one extra level of indirection relative to a direct stack-slot value parameter, even if a machine's addressing modes combine the micro-operations in one instruction.

The offsets remain symbolic because the source specifies neither stack layout nor saved control fields. If the compiler caches a parameter in a register, it must preserve the same observable aliasing behavior; such optimization does not change the semantic distinction being asked about.
