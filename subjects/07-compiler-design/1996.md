**Independently derived answer:** B: 2,1,2,1

**Essential problem context (paraphrased):** Assign object-code generation, adding literals to the literal table, assembly listing generation, and establishing local-symbol addresses to pass 1 or 2.

## Solution

Pass 1 scans source statements, advances the location counter, records labels and collects literals. It therefore establishes local-symbol addresses and enters literals before final machine-code emission. Pass 2 uses those tables to encode instructions, resolve forward uses and produce object code; the final listing can include that generated code. Hence the listed order is 2,1,2,1. If the word resolution refers specifically to substituting a symbol address at its use, that substitution occurs in pass 2; the conventional matching here means establishing the symbol-table address in pass 1.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D: the nested-if statement with one dangling else

**Essential problem context (paraphrased):** For stmt→if id then stmt | if id then stmt else stmt | id:=id, which listed nested-if statement is ambiguous?

## Solution

An else following two unfinished nested if statements can attach either to the inner if or to the outer if. These choices produce different parse trees under the given grammar: if p then (if q then s else t), versus if p then (if q then s) else t. Both yield the same token sequence. The nested statement in D has precisely this form. A language implementation may impose “else matches the nearest if,” but that extra convention does not remove ambiguity from the grammar as printed.

# GATE 1996: Q41 (printed A Q2.16)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A: (ii) only

**Essential problem context (paraphrased):** Macro M1 recursively invokes M1(X+1) when X=0, otherwise emits WORD X. M2 instead recursively invokes M2(X) when X=0. Which can recurse indefinitely?

## Solution

For M1 invoked with X=0, the recursive call receives 1. Its condition is then false, so it emits WORD 1 and stops. For any nonzero initial value it stops immediately. M2 invoked with X=0 calls itself with the same argument, so the condition never changes and expansion repeats indefinitely. Thus only the second definition has the nontermination problem, option A. This reasoning uses expansion-time integer parameter evaluation; the recursion is in the macro processor, not a runtime subroutine.

**Independently derived answer:** D: A–3,B–4,C–2,D–1

**Essential problem context (paraphrased):** Match activation record, location counter, reference counts and address relocation with subroutine call, assembler, garbage collection and linking loader.

## Solution

An activation record stores the state of a subroutine invocation, such as saved control information and local variables. An assembler’s location counter tracks the address assigned to successive statements. Reference counts can support garbage collection by tracking how many references target an object. Address relocation adjusts addresses when a linking loader places program units in memory. These associations give 3,4,2,1 in the listed order. Reference counting has cycle limitations, but it is still the relevant collection mechanism in this matching question.

# GATE 1996: Q83 (printed B Q20)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203937/GATE1996.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Literal output ab+cd+. (final dot is emitted); root multiplication with two parenthesized addition subtrees.

**Essential problem context (paraphrased):** Use the SDTS E→E+E {print “+”}, E→E*E {print “.”}, E→id {print id.name}, E→(E) {no action}. An LR parser executes a production's action immediately after reducing by it. Draw the parse tree and give the translation of (a+b)*(c+d).

## Solution

The root production is E→E*E. Its left E derives (E), whose inner E derives E+E with identifier leaves a and b. Its right E derives (E), whose inner E derives E+E with identifier leaves c and d. Thus a textual description of the full parse tree is E(E('(',E(E(id a),'+',E(id b)),')'), '*', E('(',E(E(id c),'+',E(id d)),')')). Parentheses are terminal children of their E→(E) nodes, not emitted characters.

Actions run on reduction, after the right-hand-side subexpressions have been recognized. Reducing id a prints a, reducing id b prints b, and reducing their addition prints +. The parenthesized left operand therefore emits a b +. The E→(E) reduction emits nothing. Similarly the right operand emits c d +. Only after both operand E nodes exist can the root multiplication reduce and print the dot specified by its action.

The literal complete output is a b + c d + ., or ab+cd+. when concatenated without separators. The final dot is an emitted multiplication token, not sentence punctuation. It is postfix notation: each operation follows its operands. As a check, a postfix evaluator pushes a and b, combines them by +, pushes c and d, combines them by +, then multiplies the two resulting values. The grammar is ambiguous in general for unparenthesized mixed operators, but these explicit parentheses fix the intended tree for this particular sentence. The enlarged GateForum p16 action explicitly prints a dot, and the GFG p9 action also shows a dot. Conventional postfix ab+cd+* expresses the same multiplication, but it is not the exact string emitted by the printed SDTS and must not replace it silently.
