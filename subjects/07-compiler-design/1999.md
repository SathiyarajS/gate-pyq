**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Essential problem context (paraphrased):** Which parser recognizes the broadest grammar class: LL(1), canonical LR, SLR, or LALR?

## Solution

Canonical LR(1) retains a full lookahead context in its states. SLR instead uses FOLLOW sets for reductions, and LALR merges states sharing LR(0) cores; both simplifications can create conflicts absent from the canonical construction. LL(1) is also a more restrictive deterministic grammar class. Consequently canonical LR is the most powerful among the choices, B. Power here concerns which grammars can be handled without conflicts, not implementation speed or table size.

**Essential problem context (paraphrased):** Global x is set to0.25. show prints x. small has local x=0.125 and calls show. Main calls show,then small, using dynamic scope.

## Solution

Dynamic lookup searches active calling environments. In the first show call, no nearer local x is active, so the global value 0.25 is printed. In the second call, small is the active caller and its local x=0.125 is the nearest binding, so show prints 0.125. Thus C. Under lexical scope, show’s definition outside small would instead resolve both calls to the global binding; the explicit dynamic-scoping premise is therefore essential.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A: 3

**Essential problem context (paraphrased):** Count tokens in legacy FORTRAN DO 10 I = 1.25. Options 3,4,5,none; the number contains a decimal point, not a comma.

## Solution

In the classic fixed-form FORTRAN lexical convention, embedded blanks are insignificant outside literals. Thus DO 10 I becomes the identifier DO10I when the remainder is an assignment rather than a valid DO-loop header. The decimal point in 1.25 means this is not the loop form DO 10 I=1,25. Its tokens are identifier DO10I, assignment equals, and real literal 1.25: three, A. A comma would change the interpretation and token count, so the punctuation was checked against the alternate reproduction.

# GATE 1999: Q40 (printed A Q2.15)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=5), physical page 5. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C literally; usefulness assumptions matter

**Essential problem context (paraphrased):** A grammar is both left and right recursive for a nonterminal. Must it be ambiguous,unambiguous,or is more information required?

## Solution

Both recursion directions can certainly occur in an ambiguous grammar: S→Sa|aS|a derives aa using either recursive rule. But the premise alone does not say that the recursive nonterminal is reachable and productive. For example S→c together with A→Aa|aA|b has both recursion directions at A, while the start language has just one parse tree for c. Thus the literal premise does not force ambiguity, giving C. The example deliberately exposes the omitted usefulness condition; it does not assert that an arbitrary useful doubly recursive nonterminal is harmless. The usual ambiguity claim needs a more precise grammar hypothesis.

# GATE 1999: Q64 (printed B Q9)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** For S→L₁.L₂, use S.val=L₁.val+L₂.val/2^(L₂.len); synthesize L.val and L.len.

**Essential problem context (paraphrased):** Assign synthesized attributes to evaluate a binary numeral, exemplified by 101.101=5.625. The reproduced grammar is damaged: GateForum prints “S → LL\L; L → LB\B; B → 0\1”, with no radix point; GFG has conventional alternative bars but an unclear/missing radix-point glyph. Conditional intended grammar used below: S→L.L | L; L→LB | B; B→0 | 1. Write semantic rules for every production.

## Solution

Source qualification: a radix-point production is required to parse the supplied fractional example. The following is an explicitly stated reconstruction consistent with that example, not a claim that an official original was verified. If the production is literally S→LL with no point terminal, the grammar does not parse 101.101 at all and is ambiguous about splitting an unmarked bit string.

Use synthesized attributes L.val (the bit string interpreted as an unsigned integer) and L.len (its number of bits). Let B.val be the numeric value of one bit. Distinguish repeated L occurrences by subscripts:

S → L₁ . L₂ : S.val := L₁.val + L₂.val / 2^(L₂.len)
S → L        : S.val := L.val
L → L₁ B     : L.val := 2*L₁.val + B.val; L.len := L₁.len + 1
L → B        : L.val := B.val; L.len := 1
B → 0        : B.val := 0
B → 1        : B.val := 1

Appending a bit shifts the existing integer one binary place left, hence multiplication by two. The fractional substring represents its integer value divided by 2 raised to its length; this also handles leading zeros correctly. All right-hand sides depend only on child attributes, so the definition is S-attributed.

For 101, successive (val,len) pairs are (1,1),(2,2),(5,3). Both L occurrences in 101.101 therefore have (5,3), and S.val=5+5/8=5.625. For 0.001, the fractional attributes (1,3) give 1/8 rather than 1/2, showing why the length attribute is essential.

# GATE 1999: Q77 (printed B Q16)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203805/GATE1999.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Both qsort frames and exchange link statically to sort; partition links to qsort(1,3).

**Essential problem context (paraphrased):** In a Pascal skeleton, program sort declares a,x and the sibling procedures readarray, exchange, qsort. qsort declares k,v and a nested function partition, which declares i,j. The active call sequence is sort → qsort(1,9) → qsort(1,3) → partition(1,3) → exchange(1,3). Draw the runtime stack with access links after each activation.

## Solution

Access (static) links follow lexical nesting, whereas control (dynamic) links follow the caller. Label frames S=sort, Q1=qsort(1,9), Q2=qsort(1,3), P=partition(1,3), E=exchange(1,3). Each line below is a complete snapshot written bottom → top; the parenthesized target is the access link:

1. [S(outer/null)]
2. [S(outer/null)] [Q1(S)]
3. [S(outer/null)] [Q1(S)] [Q2(S)]
4. [S(outer/null)] [Q1(S)] [Q2(S)] [P(Q2)]
5. [S(outer/null)] [Q1(S)] [Q2(S)] [P(Q2)] [E(S)]

The final stack, top first, is:
E : static→S;  dynamic→P
P : static→Q2; dynamic→Q2
Q2: static→S;  dynamic→Q1
Q1: static→S;  dynamic→S
S : static→outer/null; dynamic→outer/null

Recursive Q2 is not lexically declared inside Q1, so its static link must not point to Q1. Partition accesses its enclosing qsort variables such as v through Q2, then global a through Q2→S. Exchange was declared directly inside sort, so its a and x references use E→S, even though partition called it. readarray is not active and has no frame in these snapshots. Return addresses and saved registers may also occupy frames but do not change the links.
