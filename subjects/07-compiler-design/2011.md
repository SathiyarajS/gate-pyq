**Paraphrased problem context:** In a compiler, during which phase are language keywords recognized?

(A) Parsing the program
(B) Code generation
(C) Lexical analysis
(D) Dataflow analysis

## Solution

Lexical analysis groups source characters into tokens and recognizes reserved keywords, often by distinguishing them from identifier tokens using a keyword table. This precedes parsing, so C.

A scanner first isolates a lexeme such as 'while'. It then returns the reserved token WHILE rather than an ordinary identifier token. A parser consumes that token to determine grammatical structure. Code generation emits target instructions after the program has been analyzed, while dataflow analysis studies facts such as reaching definitions. These later tasks cannot be the first point at which the keyword token is recognized.

**Paraphrased problem context:** Which machine model has the necessary and sufficient power for conventional lexical analysis of a modern language such as Java?

(A) Finite-state automaton
(B) Deterministic pushdown automaton
(C) Nondeterministic pushdown automaton
(D) Turing machine

## Solution

Conventional token categories such as identifiers, keywords and numeric literals are specified by regular patterns. Finite-state automata suffice to recognize them; pushdown or Turing power is unnecessary for this lexical task. Hence A, distinguished from parsing nested syntax.

A lexical analyzer needs only a finite summary of a token prefix: for example, whether it has begun an identifier, is inside a number, or has just seen an exponent sign. A regular expression for a token can be converted to an NFA and then a DFA. Nested grammatical structure, such as matching arbitrary levels of parentheses, is handled later by parsing. Stronger machines could perform lexical recognition too, but their extra power is not necessary.

**Paraphrased problem context:** For binary operators ↑ and ↓, ↑ has higher precedence and is right-associative, whereas ↓ is left-associative. Which parse tree represents 7↓3↑4↑3↓2? Trees are encoded below as fully parenthesized expressions.

(A) 7↓(3↑(4↑(3↓2)))
(B) (7↓(3↑(4↑3)))↓2
(C) 7↓(((3↑4)↑3)↓2)
(D) (((7↓3)↑4)↑3)↓2

## Solution

Higher-precedence ↑ groups the middle chain, and its right associativity gives 3↑(4↑3). Lower-precedence ↓ then associates left, yielding(7↓(3↑(4↑3)))↓2. The displayed tree with that structure is B.

Associativity is applied only after precedence identifies which operators compete at the same level. First make the ↑ subtree with root ↑, left leaf 3 and right subtree (4↑3). The remaining expression has the form 7↓T↓2; left associativity makes its root the final ↓, with right child 2 and left child (7↓T). A gives ↓2 too high a binding priority; C and D left-group the ↑ chain or combine the initial ↓ too early.

**Paraphrased problem context:** Evaluate the fixed expression tree (a-b)+(e-(c+d)) on a load-store machine. Leaves a,b,c,d,e start in memory. Binary operations require both operands in registers and leave their result in a register; no intermediate result may be stored in memory. What is the minimum number of registers needed? The tree must be evaluated as given.

(A) 2
(B) 9
(C) 5
(D) 3

## Solution

A leaf needs 1 register; a binary node with equally demanding children needs one more than either, otherwise it needs the larger requirement when evaluated in the favorable order. Thus a−b needs 2; c+d needs 2; e−(c+d) also needs 2; the root combining two 2-register subtrees needs 3. Three suffice by retaining one subtree result while evaluating the other in two registers. Two cannot hold one completed child while evaluating the other fixed subtree. Hence D. This evaluates the supplied tree without algebraic reassociation; rewriting the arithmetic expression into a different tree changes the problem.

A concrete three-register schedule is: load c and d into R1,R2; replace R1 by c+d; load e into R2 and replace R2 by e-R1; then load a into R1 and b into R3, replace R1 by a-b, and add R1 to R2. The two main subtrees each need two registers to combine two operands. Whichever subtree finishes first leaves one live result while the second is evaluated, forcing a third register without spilling or reassociation.
