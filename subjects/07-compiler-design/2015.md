**Derived answer:** C

**Paraphrased problem context:** At any valid shift-reduce parsing state, which is true? A viable prefixes appear only at the stack bottom, not inside; B only at its top, not inside; C the stack contains only a set of viable prefixes; D it never contains viable prefixes.

## Solution

A handle is the portion reduced in a reverse rightmost derivation. A viable prefix stops at or before the right end of such a handle. The parser stack's grammar symbols form one viable prefix, and each initial segment of those symbols is also viable. Read the paper's “set” wording in this prefix sense, not as a claim that arbitrary internal substrings or LR state numbers are grammar prefixes.

Baseline derivation and retained qualifications: The grammar-symbol portion of a shift-reduce stack is a viable prefix: a prefix of a right-sentential form that does not pass the handle’s right end. Taking a shorter prefix cannot cross that end, so every prefix is viable too. Thus C.

**Derived answer:** C

**Paraphrased problem context:** A variable is live at statement Si if some reachable use Sj has no intervening assignment, including Si and Sj. CFG: block1 p=q+r; s=p+q; u=s*v; branches to block2 v=r+u or block3 q=s*u; both go to block4 q=v+r; block4 loops to block1. Which are live at both block2 and block3 entry? A p,s,u; B r,s,u; C r,u; D q,v.

## Solution

Use the old value test: a value matters only if a path reads it before replacement. At block2, r and u are read immediately; old v is killed by v=r+u, old q by block4, and p,s by block1 before future use. At block3, s,u are immediate reads and v,r remain needed at block4. Taking the intersection of {r,u} and {s,u,v,r} leaves {r,u}. Liveness is backward data flow and uses possible paths, not just values read in the next line.

Baseline derivation and retained qualifications: At entry to block2, r and u are used by v=r+u; old v is overwritten and old q is overwritten in block4. At entry to block3, s and u are used by q=s*u, while v and r are needed by block4. Thus live-in sets are{r, u} and{s, u, v, r}; their intersection is{r, u}, C. Values overwritten in block1 before any later use need not be added.

## Solution

One valid translation is t1=r/3; t2=q+t1; t3=t2+s; t4=t*5; t5=t3−t4; t6=u*v; t7=t6/w; t8=t5+t7. There are eight binary-operation nodes and each three-address instruction computes only one. Reusing one scratch register would not be SSA.

Baseline derivation and retained qualifications: The expression has eight binary operations: the divisions r/3 and (u*v)/w, multiplications t*5 and u*v, and four outer additive/subtractive operations. A three-address translation with a fresh temporary for every operation therefore uses eight temporaries, including the expression result.

## Solution

Lexical analysis uses minimized DFAs; parsing constructs production/parse trees; register allocation uses interference-graph coloring; expression evaluation visits operands before operators in postorder. Therefore P-2, Q-4, R-1, S-3, C.

Teaching detail:
Lexical patterns are recognized by finite automata, which can be minimized without changing recognized tokens. Parsing uses grammar productions organized into a parse tree. Register-allocation interference graphs put simultaneously live variables at adjacent vertices, so colouring assigns nonconflicting registers. To evaluate an expression tree, children must be evaluated before their operator parent, which is postorder. Combining all four gives the single complete matching C.

**Derived answer:** C

**Source access:** Open archive member CS/CS2015.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** About AST and CFG, which is true? A successors always correspond to later source code; B neither can contain a cycle; C maximum successors can depend on input program; D each node corresponds to at most one statement.

## Solution

AST node arity can vary with program constructs, and CFG successor counts can vary with multiway branches such as switch. Thus C under the general AST/basic-block CFG representation. CFGs can contain loop cycles, successors need not follow source order, and a basic block can contain several statements.

Teaching detail:
An AST can represent a construct with a variable number of operands or children, while a CFG can give a multiway branch many successor blocks. Thus a fixed universal successor count does not follow from the general names. CFG loop back-edges directly disprove B, and also disprove A’s assumption that all successors appear later in source. A basic-block CFG node can contain several sequential statements, disproving D. Different fixed-arity normalized intermediate representations are possible, but are not specified here.

**Paraphrased problem context:** Among simple LR (SLR), canonical LR and look-ahead LR (LALR), identify, in order, the easiest method to implement and the most powerful method. Options: (A) SLR, LALR; (B) canonical LR, LALR; (C) SLR, canonical LR; (D) LALR, canonical LR.

## Solution

1. SLR uses one FOLLOW set for all reductions of a nonterminal, whereas canonical LR keeps the lookahead specific to each item/context. LALR merges compatible LR states for smaller tables but may introduce conflicts that canonical LR avoids.

2. SLR uses LR(0) states plus FOLLOW sets and is the simplest of the three. Canonical LR(1) retains item-specific lookaheads and recognizes the broadest grammar class. Thus SLR, canonical LR, C.

**Paraphrased problem context:** Grammar G has productions S→F|H, F→p|c, H→d|c. S,F,H are nonterminals; p,d,c are terminals. Assess S1: LL(1) can parse all strings generated using grammar G; S2: LR(1) can parse all strings generated using grammar G. Options: (A) S1 only; (B) S2 only; (C) both; (D) neither. The question concerns this grammar, not whether its language has a different LL(1) or LR(1) grammar.

## Solution

1. The string c has two parse trees: S→F→c and S→H→c.

2. Thus the displayed grammar is ambiguous and is neither LL(1) nor LR(1). Concretely FIRST(F) and FIRST(H) both contain c, causing an LL conflict; after shifting c, completed F→c and H→c items both reduce on end-of-input, causing an LR reduce/reduce conflict. Therefore D for parsing with this grammar. Its finite language can of course be represented by a different unambiguous grammar S→p|d|c.
