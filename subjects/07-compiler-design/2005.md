

# GATE 2005: Q14 (printed CS Q14)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Both A and B are valid objections

**Paraphrased problem context:** Grammar A→AA|(A)|ε is unsuitable for predictive parsing because it is: A ambiguous; B left-recursive; C right-recursive; D an operator grammar. Assess the nonunique objections rather than forcing one choice.

## Solution

The production A→AA is directly left-recursive, so a naive predictive recursive-descent parser can recur indefinitely before consuming input; this is B. The same grammar is also ambiguous: ε has the distinct derivations A→ε and A→AA→εA→ε, giving different parse trees. An ambiguous grammar cannot be LL(1), so A is also a valid reason. Therefore the single-choice wording does not uniquely distinguish these two objections. Right recursion alone is not a barrier to predictive parsing.

Teaching detail:
The production A→AA begins with the same nonterminal, so direct predictive expansion can recurse without consuming input. Independently, ε has distinct parse trees A⇒ε and A⇒AA⇒εε, demonstrating ambiguity. A grammar with these properties cannot be LL(1), making both A and B valid reasons in the literal single-choice wording. Right recursion alone is not an objection to predictive parsing, and adjacent nonterminals also prevent the standard operator-grammar restriction.

# GATE 2005: Q59 (printed CS Q59)

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Grammar E→E+n | E×n | n generates n+n×n. List the handles in bottom-up reduction order. A n, E+n, E+n×n; B n, E+n, E+E×n; C n, n+n, n+n×n; D n, E+n, E×n.

## Solution

The rightmost derivation is E ⇒ E×n ⇒ E+n×n ⇒ n+n×n. Reversing it reduces the leftmost n first, then E+n, then E×n. These handles are n, E+n, E×n, option D. The fixed terminal n on the right of each operator means this is not the usual ambiguous E→E+E|E×E grammar.

Teaching detail:
A handle is the RHS whose reduction undoes one step of a rightmost derivation, not an arbitrary matching substring. Reverse the displayed derivation: n+n×n→E+n×n→E×n→E. The successive reduced RHS strings are n, E+n and E×n. Reducing the rightmost terminal n first would not reverse this rightmost derivation. The grammar’s fixed terminal right operands force the association, unlike E→E+E.

**Paraphrased problem context:** For S→(S)|a, let n1, n2, n3 count SLR(1), canonical LR(1), LALR(1) states. In GFG: A n1<n2<n3; B n1=n3<n2; C n1=n2=n3; D n1=n3=n2 (duplicated equality as reproduced). Determine the actual counts independently; alternate distractor ordering differs.

## Solution

For augmented S′→S and S→(S)|a, LR(0) has six states with kernels S′→·S, S′→S·, S→(·S), S→a·, S→(S·), and S→(S)· (including closures). Canonical LR(1) separates the inner/non-inner versions with lookaheads ) and $, yielding ten states. Merging identical LR(0) cores gives six LALR states again. Therefore n1=n3<n2, B. GateForum and GFG differ in irrelevant distractor ordering, but B agrees.

Teaching detail:
SLR states are LR(0) item-set states, so its FOLLOW-based action construction does not add states. The six cores are listed in the baseline derivation. Canonical LR(1) retains context: an expression enclosed by parentheses must expect a closing parenthesis, whereas the outer expression expects end-of-input, creating extra versions of cores and ten states. LALR merges versions sharing the same LR(0) core, restoring six. Therefore 6=6<10 in the order n1, n3, n2.

**Independently derived answer:** C

**Paraphrased problem context:** Expression grammar E→number | E+E | E×E has the usual synthesized arithmetic values and is given to yacc without precedence/associativity declarations. Printed 83(a): yacc A detects/eliminates recursion; B resolves reduce/reduce conflict; C resolves shift/reduce in favor of shift; D resolves shift/reduce in favor of reduce.

## Solution

The grammar E→number | E+E | E×E is ambiguous. After recognizing E+E or E×E, a following operator permits either reduction of the completed expression or shifting to build the right operand further. This is a shift/reduce conflict. With no precedence/associativity declarations, yacc defaults to shifting, option C; left recursion itself is valid for LR parsing.

Teaching detail:
After E+E has been recognized and a further operator is seen, the parser can either reduce the completed expression now or shift the operator to extend its right operand. The grammar does not specify which grouping is intended, hence a shift/reduce conflict. yacc’s default selects shift. Left recursion is supported naturally by LR parsing and is not removed automatically; no two distinct completed production reductions cause this particular ambiguity.

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203225/GATE2005.pdf#page=12), physical page 12. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Expression grammar E→number | E+E | E×E has the usual synthesized arithmetic values and is given to yacc without precedence/associativity declarations. Printed 83(b): under its default resolution, how is 3×2+1 interpreted? A equal precedence, left associative, result 7; B equal precedence, right associative, result 9; C ×higher, left associative, result 7; D +higher, left associative, result 9.

## Solution

Using the default shift resolution from part(a), neither operator receives a special precedence declaration and pending operators are reduced from the right. Thus 3×2+1 is parsed as 3×(2+1)=9. This behaves as equal precedence and right associativity, option B. This conclusion is conditional on the default shift resolution, not on adding conventional arithmetic precedence declarations.

Teaching detail:
At the + following 3×2, shifting postpones reducing 3×2. The parser first combines 2+1, then multiplies that result by 3, giving 9. Applying the same shift default to repeated operators creates right association. This is not evidence of a declared higher precedence for+: the behavior is the equal-precedence default arising from unresolved conflicts. A user-supplied precedence declaration could intentionally change the result.
