

# GATE 2025 CS1: Q12

**Question:** [Official archived paper page 12](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=12); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** Which claim about a compiler symbol table is false? A It tracks variable scope. B It can use a binary search tree. C It is no longer needed after parsing. D It is created during lexical analysis.

## Solution

Approach: Follow identifier information through the compiler rather than treating parsing as the last compilation phase.
A symbol table maps names to attributes such as type, declaration scope and storage location. Scope checking needs those associations, so A describes a normal role. A binary search tree can support lookup and insertion by identifier name, so B is a valid implementation possibility even though hash tables are also common.
After parsing, semantic analysis still needs symbol information for declaration and type checks; later code generation may need storage and addressing attributes. Therefore C’s claim that the table is unnecessary after parsing is false, and C is the keyed answer.
D reflects the conventional introductory pipeline in which lexical analysis begins identifier entries. Real implementations may create or enrich tables at other stages, so D should not be read as a universal requirement on every compiler architecture. The decisive false claim in the intended model is C.

# GATE 2025 CS1: Q13

**Question:** [Official archived paper page 13](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=13); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** Which compiler activity uses live-variable analysis? A runtime function-call management; B assigning registers to variables; C strength reduction; D constant folding.

## Solution

Approach: Ask which optimization needs to know whether an existing variable value can be used again.
A variable is live at a program point if some execution path may read its current value before assigning a new value to that variable. Registers hold only a limited number of such values. If two values must remain available at the same time, allocating the same physical register to both can destroy a value that will be needed.
Register allocation therefore uses live ranges, commonly creating an interference edge between values that are simultaneously live. Values whose live ranges do not overlap can reuse a register. This selects B.
Strength reduction, C, replaces an expensive operation with an equivalent cheaper one, while constant folding, D, evaluates expressions with known constants. Neither is identified by the need for liveness in this question. Runtime call management concerns the calling convention and activation records rather than this particular analysis.

# GATE 2025 CS1: Q46

**Question:** [Official archived paper page 46](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=46); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A;D

**Derived answer:** A;D

**Paraphrased problem context:** While computing FIRST and FOLLOW for top-down parsing, select true statements: A A→ε adds ε to FIRST(A); B the input end marker is added to FIRST(S), where S is the start symbol; C A→ε adds ε to FOLLOW(A); D the end marker is added to FOLLOW(S).

## Solution

Approach: Keep separate what a nonterminal can begin with and what can appear immediately after it.
FIRST(A) contains terminals that can start a string derived from A, and includes ε when A can derive the empty string. Therefore the production A→ε makes A true.
FOLLOW(A) contains terminals, or the designated end marker, that may occur immediately after A in a sentential form or completed parse. ε is not an input symbol and never belongs in FOLLOW merely because A is nullable, so C is false. Nullability instead causes FOLLOW information to propagate through nullable suffixes.
The start symbol represents an entire accepted input, so the end marker follows it: D is true. That marker is not automatically the first symbol of any derivation from S, making B false. Thus select A,D. For an ε-production, a predictive parser uses FOLLOW(A) to decide when to take it; it does not put ε into FOLLOW(A).

# GATE 2025 CS1: Q52

**Question:** [Official archived paper page 52](https://gate2026.iitg.ac.in/doc/download/2025/CS12025.pdf#page=52); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 6 to 6

**Derived answer:** 6

**Paraphrased problem context:** Partition this three-address code into maximal basic blocks. 1001 i=1; 1002 j=1; 1003 t1=10*i; 1004 t2=t1+j; 1005 t3=8*t2; 1006 t4=t3−88; 1007 a[t4]=0.0; 1008 j=j+1; 1009 if j≤10 goto 1003; 1010 i=i+1; 1011 if i≤10 goto 1002; 1012 i=1; 1013 t5=i−1; 1014 t6=88*t5; 1015 a[t6]=1.0; 1016 i=i+1; 1017 if i≤10 goto 1013. How many blocks?

## Solution

Approach: Mark every leader: the first instruction, every jump target, and every instruction immediately following a jump when present in the supplied code.
The first instruction makes 1001 a leader. Branch targets make 1003,1002,1013 leaders. The instructions following branches at 1009 and 1011 are 1010 and 1012, so they are leaders too. The branch at 1017 is the last supplied instruction; there is no following instruction to create an extra block.
Sorting the distinct leaders gives 1001,1002,1003,1010,1012,1013. Each block extends to just before the next leader, or to the end: [1001], [1002], [1003–1009], [1010–1011], [1012], [1013–1017]. There are six blocks.
A basic block has one entry and no internal branch out before its end. This explains why even a single assignment at 1002 or 1012 can form its own block: the next instruction is independently a branch target. Counting loops or conditionals alone would not identify the correct partition.

# GATE 2025 CS2: Q21

**Question:** [Official archived paper page 18](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=18); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** For compiler intermediate-code generation, consider: I. backpatching can generate code for Boolean expressions in one pass; II. backpatching can generate code for flow-of-control statements in one pass. Which is correct?
Options: A. I only; B. II only; C. both; D. neither.

## Solution

A branch target may not be known when its branch instruction is first generated. Backpatching emits the instruction with a placeholder target and records its location on a list. Later, when the target's instruction address becomes known, the compiler fills that field without rereading the source.

For a Boolean expression such as a<b && c<d, the compiler can keep true and false lists. A true branch from the first comparison is patched to the start of the second comparison; the final true/false branches are patched to the enclosing statement's destinations. This supports short-circuit Boolean code in one pass, so I is true.

For an if, while, or similar statement, next lists and branch lists are patched when the following block, loop test, or exit becomes known. Thus flow-of-control code can also be generated in one pass, making II true. “One pass” does not prohibit editing previously emitted target fields; that editing is precisely the role of backpatching. Answer: C.

# GATE 2025 CS2: Q22

**Question:** [Official archived paper page 19](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=19); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** Classify these syntax-directed attribute rules:
1. R→AB with B.i=R.i−1, A.i=B.i, R.i=A.i+1.
2. P→CD with P.i=C.i+D.i, D.i=C.i+2.
3. Q→EF with Q.i=E.i+F.i.
Options list the classification of rules 1,2,3 respectively:
A. [S and L], [S not L], [neither].
B. [neither], [S and L], [S and L].
C. [neither], [L not S], [S and L].
D. [S not L], [L not S], [S and L].
Here S means S-attributed and L means L-attributed.

## Solution

An S-attributed definition has only synthesized attributes: the parent obtains its values from children. An L-attributed definition additionally permits a child's inherited attributes to depend on the parent's inherited attributes and on attributes of siblings to that child's left, so a left-to-right evaluation is possible.

Rule 1 assigns attributes on both children, so it is not S-attributed. In particular A.i depends on B.i, an attribute of A's right sibling. That violates the L-attributed direction restriction. The listed dependencies also form the cycle R.i→B.i→A.i→R.i; they do not provide a straightforward acyclic evaluation. Thus rule 1 is neither.

In rule 2, P.i is synthesized, but D.i is inherited from its left sibling C. This is permitted in an L-attributed definition and disallowed in an S-attributed one. Rule 3 only synthesizes the parent's Q.i from E.i and F.i, so it is S-attributed, and every S-attributed definition is also L-attributed. The sequence is [neither], [L not S], [S and L], which is C. The letters used to name an attribute, such as i, do not determine its classification; its dependency does.

# GATE 2025 CS2: Q40

**Question:** [Official archived paper page 30](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=30); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** For grammar S→Aa | bAc | dc | bda and A→d, choose the parsing classification.
Options: A. neither LALR(1) nor SLR(1); B. CLR(1) but not LALR(1); C. LALR(1) but not SLR(1); D. both LALR(1) and SLR(1).

## Solution

First compute FOLLOW(A). In S→Aa, a follows A; in S→bAc, c follows A. Thus FOLLOW(A)={a,c}.

The LR(0) state reached by reading d directly from the start contains A→d· and S→d·c. SLR puts the reduction A→d on every symbol in FOLLOW(A), including c, but S→d·c requires shifting c. This is a shift/reduce conflict. Likewise, after reading bd the state contains A→d· and S→bd·a, producing a conflict on a. So the grammar is not SLR(1).

Canonical LR(1) retains the particular context. After the initial d, the completed item is [A→d·,a]; it reduces only on a, while S→d·c shifts c. After bd, the completed item is [A→d·,c]; it reduces only on c, while S→bd·a shifts a. These actions do not conflict.

LALR merges states only when their complete LR(0) cores are identical. The two potentially troublesome states have different S items, S→d·c versus S→bd·a, so they are not merged merely because both contain A→d·. All other reductions arise in completed S productions or similarly nonconflicting states. Hence the precise lookahead separation survives LALR construction. Answer: C.

# GATE 2025 CS2: Q51

**Question:** [Official archived paper page 39](https://gate2026.iitg.ac.in/doc/download/2025/CS22025.pdf#page=39); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** C;D

**Derived answer:** C;D

**Paraphrased problem context:** The terminals are if,then,else,a,b,c. Two grammars are:
G1: S→if E then S | if E then S else S | a; E→b.
G2: S→if E then S | M; M→if E then M else S | c; E→b.
Select true statements: A. G1 not LL(1), G2 LL(1); B. G1 LL(1), G2 not LL(1); C. neither LL(1); D. both ambiguous.

## Solution

Write i for the complete terminal phrase “if b then” and e for “else.” In G1, the string i i a e a has two parses: i [i a e a] attaches the else to the inner if, while [i [i a] e a] attaches it to the outer if. This is the dangling-else ambiguity.

G2 may resemble a matched/unmatched-if grammar, but its M production ends in S, not in an entirely matched nonterminal. Consequently an unmatched if can occur in that else branch. A concrete ambiguous string is i i c e i c e c. Its first parse is i [i c e (i c e c)]: the initial S uses S→iS, and its inner S→M derives i c e (i c e c). Its second parse is i [i c e (i c)] e c: the outer S→M uses M→i M e S, with its then-branch M deriving i c e (i c) and its final S deriving c. The else tokens attach to different if occurrences, yet the terminal string is identical. Thus G2 is ambiguous too.

An LL(1) grammar is unambiguous, so neither grammar can be LL(1). Directly, G1's two if-alternatives have the same FIRST token, and G2's S alternatives both admit strings beginning with if. These create predictive parsing conflicts. Select C,D. Do not silently replace G2 by a standard unambiguous dangling-else grammar; the printed S in M's last position is essential.
