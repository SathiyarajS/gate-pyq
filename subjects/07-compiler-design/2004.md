**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Paraphrased problem context:** P,Q,R are nonterminals and r,s,t are terminals. Which rules violate the requirements for an operator grammar? (i) P→QR; (ii) P→QsR; (iii) P→ε; (iv) P→QtRr.
Options:
(A) i only
(B) i and iii only
(C) ii and iii only
(D) iii and iv only

## Solution

1. An operator grammar forbids adjacent nonterminals on a right-hand side and, in the standard definition used here, empty productions. P→QR violates the first rule and P→ε the second.

2. P→QsR and P→QtRr separate nonterminals by terminals. Thus i and iii, B.

3. Teaching check: A right-hand side can contain several nonterminals provided terminals separate adjacent ones. Thus QsR and QtRr are permitted. The empty-production restriction belongs to the conventional operator-grammar definition used here; do not confuse this syntactic test with conflict-free operator-precedence parsing.

**Independently derived answer:** C

**Paraphrased problem context:** A program has separately stored source modules M1 and M2. M1 refers to a function defined in M2. At what stage is this reference resolved in the conventional separate-compilation model?
Options:
(A) Edit time
(B) Compile time
(C) Link time
(D) Load time

## Solution

1. With conventional separate compilation and static linking, each module produces an object file with symbol definitions/references. The linker matches the external reference in M1 to the definition in M2, so link time, C.

2. Dynamic loading can defer binding, but is not the default compilation model stated here.

3. Teaching check: Compilation can emit an unresolved external symbol into M1’s object file. Linking has access to both objects and supplies the address from M2. Editing only changes text; loading places an already linked image into memory under the assumed static-binding model.

# GATE 2004: Q10 (printed CS Q10)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** For E→E1−E2, generate code for a CPU with only one user register. Subtraction requires its first operand in that register; E1 and E2 have no common subexpression. Which evaluation order gives the shortest code?
Options:
(A) Evaluate E1 first
(B) Evaluate E2 first
(C) Necessarily interleave E1 and E2 evaluation
(D) Evaluation order is of no consequence

## Solution

1. Evaluate E2 first and save its value in a temporary memory location. Then evaluate E1, leaving the required first operand in the sole register, and subtract the saved E2.

2. Evaluating E1 first would require saving it, evaluating/storing E2, then reloading E1 before subtraction. Thus E2-first, B, avoids an extra reload in the stated accumulator-style model, assuming both expressions require evaluation and their order is free of side-effect constraints.

3. Teaching check: The final subtraction needs register=E1 and memory temporary=E2. E2-first naturally reaches that arrangement after one save. E1-first must preserve E1 across E2’s evaluation, then reload it, adding a memory operation. This argument assumes unrestricted evaluation order and nontrivial expression evaluations.

# GATE 2004: Q45 (printed CS Q45)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203330/GATE2004.pdf#page=6), physical page 6. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C (GFG); no listed option (GateForum)

**Paraphrased problem context:** Grammar and semantic rules, start E: E→E1 # T with E.value=E1.value×T.value, or E→T with E.value=T.value; T→T1 & F with T.value=T1.value+F.value, or T→F with T.value=F.value; F→num with F.value=num.value. Find the root value for 2 # 3 & 5 # 6 & 4. The addition rule is visible in GFG; GateForum instead prints multiplication for that rule as well.
Options:
(A) 200
(B) 180
(C) 160
(D) 40

## Solution

1. The grammar groups & inside T, hence it has higher precedence than #. In the GFG image the T→T1 & F semantic rule is T.value=T1.value+F.value, while E→E1 # T multiplies.

2. Therefore 2 # 3 & 5 # 6 & 4 evaluates as 2×(3+5)×(6+4)=160, option C. The GateForum image instead prints multiplication in BOTH semantic rules, which yields 2×3×5×6×4=720, absent from the options.

3. This is a substantive reproduction variant; C applies only to the visibly printed GFG plus-sign rule, not to the alternate as printed.

4. Teaching check: Precedence comes from the grammar, not the symbols’ usual meanings. T binds & before the E-level #. Thus the parse groups 3&5 and 6&4 before combining the factors with #. Applying the Forum multiplication variant honestly gives 720, not a listed value.
