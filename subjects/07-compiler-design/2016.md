**Type / marks:** NAT, 1 mark(s).

**Official answer:** 10.0 : 10.0

**Derived answer:** 10

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Find the minimum total number of variable names in static single-assignment form for this straight-line code, including incoming variables:
x=u−t;
y=x*v;
x=y+w;
y=t−z;
y=x*y;

## Solution

The five incoming values u, t, v, w, z each need one name. The two definitions of x and three of y need five distinct SSA names: x1=u−t; y1=x1*v; x2=y1+w; y2=t−z; y3=x2*y2. Total 5+5=10 variables, counting incoming values as requested.

In SSA, each name has exactly one definition, but it can be read many times. Hence the two reads of t share one incoming name, while the successive writes to y cannot share a name. When renaming, every use must refer to its most recent preceding definition: the final product uses x2 and y2, not the original names. There are no branches here, so no φ-functions are necessary. Five new defined names plus five distinct incoming names is the requested total.

# GATE 2016 CS1: Q46 (printed CS Q36)

**Question:** [Official archived paper page 15](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** D

**Derived answer:** D under implicit local-a binding

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Assume dynamic scoping and pass-by-reference in this pseudocode:
a=3;
void n(x){x=x*a;print(x);}
void m(y){a=1;a=y−a;n(a);print(a);}
void main(){m(a);}
What is printed? A:6,2. B:6,6. C:4,2. D:4,4. The source does not explicitly declare whether m's first assignment introduces a local a; preserve that ambiguity.

## Solution

The intended pseudocode treats a=1 inside m as introducing a local a, while reference parameter y remains an alias of the outer a=3. Then local a=y−a=2. Passing it by reference to n makes x and dynamically resolved a refer to that same local cell: x=x*a stores 4, and both prints show 4, D. If a=1 instead assigns the existing outer dynamically scoped a, y aliases it, so a=y−a becomes 0 and the output is 0, 0. The source lacks an explicit local declaration, so its binding convention must be supplied.

Distinguish parameter aliasing from name lookup. Under the intended local-binding interpretation, y aliases the global cell containing 3, while m's local a first contains 1 and then 2. n's formal x aliases that local cell, and dynamic lookup of its free name a finds the active m frame, also that same cell. Thus the assignment squares 2 in place. Under assignment-to-existing-binding semantics both y and a refer to the global cell before subtraction, making 1−1=0. The printed key chooses the former semantics but does not remove the source ambiguity.

**Paraphrased problem context:** Three binary operators have these language-specific rules: + has highest precedence and is left-associative; − has medium precedence and is right-associative; * has lowest precedence and is left-associative. Evaluate 2−5+1−7*3.

## Solution

Addition has highest precedence, giving 5+1=6. The remaining subtraction is right-associative, so 2−6−7 groups as 2−(6−7)=3. Multiplication has lowest precedence, producing 3*3=9.

Insert parentheses in precedence order before calculating: the expression becomes (2−(5+1)−7)*3, then right associativity changes the subtraction part to 2−((5+1)−7). The inner result 6−7 is−1, so the outer result is 3 and multiplying by 3 gives 9. Ordinary arithmetic precedence would put multiplication first and produce a different result; this question intentionally defines a different expression grammar.

**Paraphrased problem context:** A syntax-directed translation scheme has S→aA {print 1}, S→a {print 2}, A→Sb {print 3}. A bottom-up parser processes input aab. What is the output? A:1 3 2. B:2 2 3. C:2 3 1. D:syntax error.

## Solution

Bottom-up parsing of aab first reduces the second a by S→a, printing 2. Then Sb reduces to A, printing 3. Finally aA reduces to S, printing 1. The action order is 2, 3, 1, option C.

Reduction order follows a rightmost derivation in reverse, not the textual order in which productions are listed. A valid derivation is S⇒aA⇒aSb⇒aab. Reversing those steps first collapses the second a into S, then Sb into A, then aA into S. Each semantic action is at the end of its production, so it runs at the corresponding reduction and emits 2,3,1. The successful derivation also rules out syntax error.

## Solution

Lexical analysis uses regular expressions; top-down parsing constructs a leftmost derivation; semantic analysis checks types; runtime environments organize activation records. Hence P-iii, Q-i, R-ii, S-iv, B.

A lexer recognizes tokens such as identifiers and numbers from character patterns. A top-down parser expands the leftmost pending nonterminal toward the input. Semantic analysis rejects type-incompatible expressions even when their syntax parses. Activation records store each call’s parameters, locals and return information at runtime; this separates all four roles.

**Official answer:** B

**Derived answer:** B

**Source access:** Open archive member CS/CS2016.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Which grammar has no left recursion? A S→AB,A→Aa|b,B→c; B S→Ab|Bb|c,A→Bd|ε,B→e; C S→Aa|B,A→Bb|Sc|ε,B→d; D S→Aa|Bb|c,A→Bd|ε,B→Ae|ε.

## Solution

Grammar B has an acyclic nonterminal dependency chain S→A/B, A→B, with B deriving only terminal e; it cannot derive a sentential form beginning again with the same nonterminal. A has direct A→Aa. C has S⇒Aa⇒Sca. D has A⇒Bd⇒Aed. Thus B alone is free of left recursion.

Left recursion means a derivation A⇒+Aα, possibly passing through other nonterminals and nullable productions. It is not the same as any recursion anywhere on a right side. In B every chain beginning in a nonterminal descends from S to A to B, and B immediately produces terminal e, so no cycle can return to its starting nonterminal.

**Paraphrased problem context:** Two grammars describe C-like declarations with at least one array dimension, e.g. int a[10][3];. Terminals: int, ;, id, [, ], num. G1: D→int L;, L→id [E, E→num] | num][E. G2: D→int L;, L→id E, E→E[num] | [num]. Which correctly generate the declarations? A both; B G1 only; C G2 only; D neither.

## Solution

G1 emits the opening bracket with id, then its recursive E→num][E adds each completed dimension and the next opening bracket, ending with E→num]. G2 emits one or more bracketed num groups through left recursion E→E[num] with base[num]. Both generate int id[num]...[num]; with at least one dimension, including the example. Thus A.

For two dimensions, G1 derives L⇒id [E⇒id [num][E⇒id [num][num]. G2 derives L⇒id E⇒id E[num]⇒id [num][num]. Substituting id=a and the two num tokens by 10 and 3 yields the example in each. Left recursion may inconvenience a parser, but it does not make the generated language incorrect.
