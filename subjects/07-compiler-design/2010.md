**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 3. Consult original wording and choices.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** Which compiler data structure manages information about variables and their attributes?
Options: (A) Abstract syntax tree; (B) Symbol table; (C) Semantic stack; (D) Parse table.

## Solution

A symbol table stores identifier entries and attributes such as type, scope, storage location and parameter information. An abstract syntax tree represents program structure, a parse table guides parsing, and a semantic stack supports intermediate parser actions. Therefore the data structure asked for is the symbol table, B.

Teaching detail: For example, a declaration “int count” can create a symbol-table entry recording the name count, integer type and scope. Later uses look up that entry for type checking and storage access. The syntax tree may refer to the entry but is not itself the lookup structure; a parse table instead maps parser states/lookahead to parsing actions.

# GATE 2010: Q24 (printed CS Q14)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 3. Consult original wording and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Which class of programming languages necessarily needs heap allocation in its runtime environment?
Options: (A) Languages supporting recursion; (B) Languages using dynamic scoping; (C) Languages allowing dynamic data structures; (D) Languages using global variables.

## Solution

Dynamically created data structures can have sizes and lifetimes unrelated to the last-in-first-out nesting of procedure activations, so their runtime storage requires heap-style allocation in the standard implementation model. Recursion and dynamic scope can be supported with activation stacks; global variables can use static storage. C is the intended distinction. A language implementation may realize the allocator through a preallocated arena, but that is still heap-style management rather than a counterexample to the storage-lifetime distinction.

Teaching detail: A recursive call creates a new activation record that can be popped when the call returns, so recursion alone needs a stack, not a heap. A linked node returned to a caller may have to survive its creator’s return and be freed in an arbitrary order. That non-LIFO lifetime is the key distinction tested by dynamic data structures.

# GATE 2010: Q47 (printed CS Q37)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 9. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** All operations take operands from registers. What is the minimum number of registers needed to execute this program without spilling?
a=1; b=10; c=20;
d=a+b; e=c+d; f=c+e;
b=c+e; e=b+f; d=5+e;
return d+f;
Options: (A) 2; (B) 3; (C) 4; (D) 6.

## Solution

Immediately after c=20, a,b,c are all live because a and b are needed for d=a+b while c is needed later. At least three registers are therefore necessary. Three suffice: put a,b,c in registers r1,r2,r3; overwrite r1 with d=a+b, then with e=c+d; overwrite r2 with f=c+e; overwrite r3 with b=c+e after c dies; overwrite r1 with e=b+f and then d=5+e. The final d+f uses r1 and r2. Thus 3, B, under the usual model allowing a destination to reuse a dead operand register.

Teaching detail: One possible register state trace is (a,b,c)→(d,b,c)→(e,b,c)→(e,f,c)→(e,f,b)→(e,f,b)→(d,f,b), where dead values may be overwritten. At the middle expression f=c+e, both c and e must remain available for the following b=c+e, so the third register is still useful. The lower-bound argument assumes executing the given operations, rather than constant-folding the entire straight-line program.

# GATE 2010: Q48 (printed CS Q38)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2010.pdf, physical page 9. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Classify the grammar S→aSa | bS | c.
Options: (A) LL(1) but not LR(1); (B) LR(1) but not LL(1); (C) Both LL(1) and LR(1); (D) Neither LL(1) nor LR(1).

## Solution

The productions S→aSa, S→bS and S→c begin with distinct terminals a,b,c and none derives epsilon. Their FIRST sets are disjoint, so one lookahead symbol uniquely selects the production and the grammar is LL(1). Every LL(1) grammar is LR(1), so it is both, C. The trailing a in aSa does not cause a predictive conflict because the initial a already selects that alternative.

Teaching detail: The predictive parsing table contains exactly S→aSa under lookahead a, S→bS under b and S→c under c. There are no epsilon productions, so no FIRST/FOLLOW conflict arises. Recursion does not by itself prevent LL(1); left recursion would, but here each recursive call is preceded by a terminal consumed from the input.
