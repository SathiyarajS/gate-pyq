

# GATE 2002: Q18 (printed A Q1.18)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203519/GATE2002.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Essential problem context (paraphrased):** Compare function results under value-result and reference parameter passing. They:
(A) Never differ; (B) Differ when loops are present; (C) Differ in every case; (D) May differ when exceptions are present.

## Solution

Step 1: Use an exceptional exit to distinguish parameter mechanisms.

Step 2: Suppose an actual variable initially holds 0 and the function sets its formal to 1 before raising an exception. Reference passing has already changed the actual to 1. Under copy-restore with copying back only at normal return, the actual remains 0. This is a possible difference, not a claim that all calls differ or that exceptions have one universal language-independent copy-out policy.

Conclusion and qualifications: With reference passing, updates immediately affect the actual argument. With value-result (copy-in/copy-out), they can remain in the local formal until normal return. If an exception exits before copy-out, the visible results can differ, D, under the conventional no-copy-out-on-exception rule. Aliasing can also distinguish these mechanisms; loops alone neither force nor exclude a difference.

# GATE 2002: Q99 (printed B Q22(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203519/GATE2002.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** Two parse trees: +(i,*(j,k)) and *(+(i,j),k), with E→id at every identifier leaf.

**Essential problem context (paraphrased):** Grammar E→E+E | E*E | id. Original22(a): Construct all parse trees for i+j*k, where i,j,k are identifiers.

## Solution

With productions E→E+E, E→E*E, E→id, the two full parse trees are:
Tree 1, root addition:
E
├── E
│   └── id(i)
├── +
└── E
    ├── E
    │   └── id(j)
    ├── *
    └── E
        └── id(k)

Tree 2, root multiplication:
E
├── E
│   ├── E
│   │   └── id(i)
│   ├── +
│   └── E
│       └── id(j)
├── *
└── E
    └── id(k)
Here id(i), id(j), and id(k) denote the id tokens with those lexemes. Both yields are i + j * k. There are exactly two trees because the root split must be at one of the two operators, and each remaining two-identifier subtree has a unique possible split. Their grouping is i+(j*k) versus (i+j)*k.

# GATE 2002: Q100 (printed B Q22(b))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203519/GATE2002.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** No relative precedence is specified or enforced by this grammar.

**Essential problem context (paraphrased):** Grammar E→E+E | E*E | id. Original22(b): What precedence, if any, does this grammar impose on * and +?

## Solution

Both + and * are produced by the same nonterminal E, and the grammar allows both i+(j*k) and (i+j)*k for the same token string. It therefore does not enforce multiplication-before-addition or addition-before-multiplication. Saying merely that the operators have equal precedence is also incomplete: the grammar does not enforce associativity, so it does not define a unique parse even under that description. External parser precedence declarations could resolve conflicts, but they are not part of the supplied grammar.

# GATE 2002: Q101 (printed B Q22(c))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203519/GATE2002.pdf#page=10), physical page 10. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** E→E+T | T; T→T*F | F; F→id.

**Essential problem context (paraphrased):** Grammar E→E+E | E*E | id. Original22(c): Modify the grammar to obtain exactly one parse tree per string in the same language and a nonambiguous LALR(1) grammar.

## Solution

One replacement grammar is:
E → E + T | T
T → T * F | F
F → id
It accepts exactly the original token language id ((+|*) id)*, without introducing parentheses or changing which token strings are allowed. The E/T levels make * bind more tightly than +, and the left-recursive productions make repeated uses of either operator associate left. Thus i+j*k has only the i+(j*k) parse. This standard expression grammar is SLR(1), and hence LALR(1); separating the levels resolves the shift/reduce ambiguity. The original grammar specified no precedence, so multiplication-before-addition and left associativity are a legitimate choice of an unambiguous interpretation, not properties already forced by that grammar.
