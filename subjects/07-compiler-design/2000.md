**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Essential problem context (paraphrased):** Does aliasing mean multiple names for one memory location, equal values, repeated identifiers, or repeated use of a variable?

## Solution

Step 1: Aliasing occurs when two accessible expressions designate the same storage object. For example, if p=&x, then x and *p refer to the same int.

Step 2: Assigning through either expression changes what the other observes. Two separate variables can hold equal values without aliasing, and the same identifier can name different objects in different scopes.

Thus A, not merely equal contents or repeated spelling.

**Essential problem context (paraphrased):** For input scanned left to right, does top-down parsing construct a leftmost derivation, its reverse, a rightmost derivation, or a reversed rightmost derivation?

## Solution

Step 1: A top-down parser starts from the start symbol and expands grammar symbols to match the input prefix. It expands the leftmost unprocessed nonterminal to produce the next input symbols.

Step 2: These expansions run in the forward direction from start symbol to terminal string, giving a leftmost derivation, A.

A reversed rightmost derivation characterizes standard bottom-up shift-reduce parsing instead.

**Essential problem context (paraphrased):** Given E→E*F|F+E|F and F→F−F|id, which operator-precedence claim is true: * above +; − above *; + and − equal; + above *?

## Solution

Step 1: The only grammar productions introducing minus are inside F. Any operand F used by multiplication or addition is therefore formed before the surrounding E-level operation.

Step 2: For example id*id−id must have the minus within the right F, giving id*(id−id), rather than treating minus as an outer E-level operation. Thus minus binds more tightly than multiplication, B.

The E rules do not give a clean unambiguous ordering between + and *; some mixed expressions have multiple parses. F→F−F is itself associative-ambiguous. These ambiguities do not invalidate the separation placing minus at the tighter grammar level.

# GATE 2000: Q86 (printed B Q19(a))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203732/GATE2000_compressed-1.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** (4−(2−4))*2 = 12

**Essential problem context (paraphrased):** Grammar/SDTS: E→E1*T {E.val=E1.val*T.val}; E→T {E.val=T.val}; T→F−T1 {T.val=F.val−T1.val}; T→F {T.val=F.val}; F→2 {F.val=2}; F→4 {F.val=4}. Attributes are evaluated immediately after bottom-up reductions. Construct the parse tree for 4−2−4*2 and evaluate it.

## Solution

The grammar makes subtraction part of T and multiplication part of E. Thus subtraction binds more tightly than multiplication. Moreover T→F−T is right-recursive, so the subtraction chain groups to the right, not to the left. The annotated parse tree is:
E[12]
├── E[6]
│   └── T[6]
│       ├── F[4] → 4
│       ├── −
│       └── T[−2]
│           ├── F[2] → 2
│           ├── −
│           └── T[4]
│               └── F[4] → 4
├── *
└── T[2]
    └── F[2] → 2
Its left-to-right terminal yield is exactly 4−2−4*2. Bottom-up, the innermost T has value 4; its parent computes 2−4=−2; the next T computes 4−(−2)=6. E→T copies 6. The final right T has value 2, so the root computes 6*2=12. Ordinary arithmetic precedence would give a different result; here the supplied grammar, not familiar operator conventions, defines the grouping.

**Official answer:** Not available; no official key located.

**Independently derived answer:** Each production adds 1 to the sum of its nonterminal children’s red attributes; the given input has E.red=10.

**Essential problem context (paraphrased):** Grammar/SDTS: E→E1*T {E.val=E1.val*T.val}; E→T {E.val=T.val}; T→F−T1 {T.val=F.val−T1.val}; T→F {T.val=F.val}; F→2 {F.val=2}; F→4 {F.val=4}. Attributes are evaluated immediately after bottom-up reductions. Add synthesized attributes to compute E.red, the total reductions without changing the grammar.

## Solution

Every nonterminal node in a parse tree represents one use of a grammar production, hence one reduction in a bottom-up parse. A terminal contributes no reduction by itself; F→2 or F→4 contributes one. Preserve all original val actions and append:
E → E1 * T : E.red = E1.red + T.red + 1
E → T      : E.red = T.red + 1
T → F − T1 : T.red = F.red + T1.red + 1
T → F      : T.red = F.red + 1
F → 2      : F.red = 1
F → 4      : F.red = 1
These are synthesized because each left-hand attribute depends only on child attributes. No global counter or inherited attribute is needed. In 4−2−4*2, there are four F reductions, four T reductions (two T→F and two T→F−T), and two E reductions (E→T and E→E*T), totaling 10. One bottom-up production sequence is F→4, F→2, F→4, T→F, T→F−T, T→F−T, E→T, F→2, T→F, E→E*T, understood as reductions from right-hand sides to left-hand sides. Parser accept is not an additional grammar reduction, and any augmented start rule is outside the question’s requested reduction to E.
