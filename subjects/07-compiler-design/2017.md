**Paraphrased problem context:** Match compiler inputs P:syntax tree, Q:character stream, R:intermediate representation, S:token stream with phases i:code generator, ii:syntax analyzer, iii:semantic analyzer, iv:lexical analyzer. Options (P,Q,R,S): A:(ii,iii,iv,i), B:(ii,i,iii,iv), C:(iii,iv,i,ii), D:(i,iv,ii,iii).

## Solution

1. Follow the compiler pipeline from source text. The lexical analyzer reads characters and groups them into tokens, so Q→iv. The syntax analyzer reads those tokens and recognizes grammatical structure, so S→ii.

2. Semantic analysis then uses the syntax tree to check matters such as declarations, types, and compatible operations; hence P→iii.

3. After front-end processing and intermediate-code construction, the code generator translates the intermediate representation into target code, giving R→i. In the requested P,Q,R,S order the mapping is (iii,iv,i,ii), option C. Do not confuse a phase's output with its input.

**Paraphrased problem context:** Which parser-power statements are correct? I:Canonical LR is more powerful than SLR. II:SLR is more powerful than LALR. III:SLR is more powerful than canonical LR. A:I only. B:II only. C:III only. D:II and III.

## Solution

1. Power here refers to the class of grammars handled without parsing conflicts, with the usual one-symbol lookahead versions. The inclusion chain is SLR(1) ⊂ LALR(1) ⊂ canonical LR(1).

2. SLR uses coarse FOLLOW sets for reductions. Canonical LR uses item-specific lookahead information; LALR merges compatible LR state cores and retains more discrimination than SLR but can lose some canonical LR power.

3. Thus canonical LR can handle every SLR grammar and some additional grammars, making I true. II and III reverse the inclusion direction and are false. Choose A. This comparison is about grammar recognition capability, not parser speed or table size.

**Paraphrased problem context:** Grammar G is E→E−T|T, T→T+F|F, F→(E)|id. Choose an equivalent grammar without left recursion. A:the same grammar. B:E→TE′, E′→−TE′|ε, T→T+F|F, F→(E)|id. C:E→TX, X→−TX|ε, T→FY, Y→+FY|ε, F→(E)|id. D:E→TX|(TX), X→−TX|+TX|ε, T→id.

## Solution

1. Apply the standard direct-left-recursion transformation A→Aα|β becomes A→βA′, A′→αA′|ε. For E, α is −T and β is T, giving E→TX and X→−TX|ε.

2. Apply it separately to T: α is +F and β is F, giving T→FY and Y→+FY|ε. Keep F→(E)|id so arbitrarily nested factors remain possible. These are exactly option C.

3. A leaves both original recursions intact. B fixes E but leaves T→T+F directly left-recursive. D restricts T to id and cannot generate nested expressions such as ((id)) or parentheses as arbitrary factors. The transformation preserves the generated strings, although semantic associativity must be handled when constructing evaluation actions.

## Solution

1. FOLLOW(Q) contains terminal symbols that can occur immediately after a derivation of Q, not the next nonterminal’s name. Its only occurrence is in P→xQRS.

2. R can produce w, placing w immediately after Q. It can also disappear through ε, exposing S, which produces y.

3. S is not nullable, so Q never reaches the end of this production and no end marker is inherited. FOLLOW(Q)={w,y}, C.

**Paraphrased problem context:** Grammar: stmt→if expr then expr else expr; stmt | δ; expr→term relop term | term; term→id | number; id→a|b|c; number→[0–9]. δ is the empty statement and relop a relational operator. A program contains ten if terminals. Find its number of control-flow paths, counting the two branches of one if as two paths.

## Solution

1. The stmt grammar appends one if statement followed by another stmt. Thus ten if terminals describe ten sequential binary choices, not a nesting with an unspecified shape.

2. After the first if there are two structural paths. Each subsequent if doubles the existing path count because every current path can take either its then or else branch.

3. Therefore P0=1 and Pn=2Pn−1, giving P10=2^10=1024. This counts syntactic control-flow graph paths, as the question’s example does; repeated or constant conditions can make some paths infeasible for actual executions.

**Paraphrased problem context:** For (a−1)*(((b+c)/3)+d), find minimum registers for optimal load/store code generation without spills. Only loads/stores can access memory; arithmetic operands must be registers or immediate constants.

## Solution

1. Evaluate the more demanding right subtree first. Load b into R1 and c into R2; add into R1. Divide R1 by immediate 3, then reuse R2 to load d and add it to R1. Now R1 holds ((b+c)/3)+d.

2. Keep R1 live and load a into R2. Subtract immediate 1 from R2, then multiply R2 and R1 into either register. At no time are more than two registers live, and no intermediate is stored to memory.

3. One register cannot perform b+c under the stated arithmetic rule because both non-immediate operands must be in registers simultaneously. Hence both lower and upper bounds are 2.
