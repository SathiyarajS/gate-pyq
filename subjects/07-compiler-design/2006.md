**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=1), physical page 1. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Grammar: S→S*E | E; E→F+E | F; F→id. Consider LR(0) items 1: S→S*·E; 2: E→F·+E; 3: E→F+·E. Which pair appears together in a canonical item set?
Options:
(A) 1 and 2
(B) 2 and 3
(C) 1 and 3
(D) None of these pairs

## Solution

1. The state after recognizing S* contains S→S*·E plus closure items E→·F+E,E→·F,F→·id. The item E→F·+E occurs after a transition on F, together with E→F·.

2. The item E→F+·E occurs after a further transition on +, again with the initial E/F closure. These three kernels are different states; closure does not introduce either of the other listed advanced items.

3. Thus none of the listed pairs coexist, D.

4. Teaching check: LR closure inserts productions with the dot at their beginning when a nonterminal follows the dot. It never advances an existing dot. Thus an item beginning E→·F can coexist with item 1, but the advanced E→F·+E requires a GOTO on F, producing another state.

# GATE 2006: Q55 (printed CS Q55)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=8), physical page 8. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** Consider C functions:
int work1(int *a,int i,int j) {
 int x=a[i+2]; a[j]=x+1; return a[i+2]-3;
}
int work2(int *a,int i,int j) {
 int t1=i+2; int t2=a[t1]; a[j]=t2+1; return t2-3;
}
S1: work2 always gives the same output and effect on state as work1.
S2: the transformations always reduce CPU time.
Which truth values apply?
Options:
(A) S1 false, S2 false
(B) S1 false, S2 true
(C) S1 true, S2 false
(D) S1 true, S2 true

## Solution

1. work1 reads a[i+2], writes a[j], then reads a[i+2] again in its return expression. work2 saves the first value and reuses it after the store. If j=i+2, the store changes the location that work1 rereads, so the functions need not return the same value; S1 is false.

2. Compiler transformations also do not universally improve runtime on every target/input, and this transformation is not even semantics-preserving without a non-alias condition. S2 is false.

3. Thus A. The clearer GateForum code confirms a[j]=x+1 and return a[i+2]−3 versus the saved-value return t2−3.

4. For i=0, j=2, initial a[2]=5, work1 returns 3 whereas work2 returns 2.

5. Teaching check: Take i=0,j=2,a[2]=5. Both functions store 6 into a[2], but work1 then rereads 6 and returns 3, while work2 reuses saved 5 and returns 2. Reusing a load across a potentially aliasing store is not a valid unconditional common-subexpression transformation.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** A pedagogical pass-by-reference language executes:
subroutine swap(ix,iy)
 it=ix
 L1: ix=iy
 L2: iy=it
end
ia=3; ib=8; call swap(ia,ib+5); print ia,ib.
Statements: S1 an unnamed temporary initialized to 13 is allocated and its address passed for the second argument; S2 runtime error at L1; S3 runtime error at L2; S4 prints 13,8; S5 prints 13,−2. Which stated set is correct under the expression-to-temporary model?
Options:
(A) S1 and S2
(B) S1 and S4
(C) S3
(D) S1 and S5

## Solution

1. Initially ia=3 and ib=8; the expression ib+5 evaluates to 13. Under the stated expression-to-temporary reference model, the compiler passes the address of a temporary containing 13, not the address of ib. swap sets ia to 13 and the temporary to 3; ib remains 8.

2. S1 and S4 hold, so B. This is the pedagogical model specified by the options, not a guarantee that every actual FORTRAN standard/compiler permits defining an expression-associated dummy argument.

3. Teaching check: The expression ib+5 has a value but is not the storage cell ib. Passing a temporary permits swap to overwrite the argument without overwriting ib. Trace the two addressed cells separately: ia changes 3→13, temporary changes 13→3, and ib stays 8.

**Independently derived answer:** A

**Paraphrased problem context:** For grammar S→FR, R→*S|ε, F→id, what are predictive-table entries M[S,id] and M[R,$], respectively?
Options:
(A) {S→FR}, {R→ε}
(B) {S→FR}, empty
(C) {S→FR}, {R→*S}
(D) {F→id}, {R→ε}

## Solution

1. For S→FR, R→*S|ε, F→id, FIRST(FR)={id}; hence M[S,id]={S→FR}. Since S is the start symbol and R occurs at the end of S→FR, $ belongs to FOLLOW(R).

2. Therefore M[R,$]={R→ε}. Option A.

3. Teaching check: An LL(1) table uses FIRST of a nonempty production; ε productions use FOLLOW of their left-hand side. Since id begins FR, the S/id cell receives S→FR. Since R can end the start-symbol derivation, end marker $ belongs to FOLLOW(R).

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** A syntax-directed translation has productions:
S→ER
R→*E {print('*')} R | ε
E→F+E {print('+')} | F
F→(S) | id {print(id.value)}
Here id denotes an integer. What is printed on input 2*3+4?
Options:
(A) 2*3+4
(B) 2*+34
(C) 23*4+
(D) 234+*

## Solution

1. S→ER and R→*E{print(*)}R|ε put multiplication below the expression E; E→F+E{print(+)}|F groups the addition on the right. For 2*3+4, first print 2, then parse E for 3+4, printing 3,4,+, then print * when that E finishes.

2. The output is 234+*, option D. Applying ordinary arithmetic precedence would incorrectly give 23*4+.

3. Teaching check: Semantic print actions fire at their positions in the grammar, not according to the usual arithmetic-precedence rules. The E nonterminal consumes the whole 3+4 before R’s multiplication-print action runs. The result is therefore postfix for 2*(3+4).

# GATE 2006: Q60 (printed CS Q60)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005203119/GATE2006.pdf#page=9), physical page 9. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Consider C code (with defined arithmetic and x,y live after the fragment):
for (i=0;i<n;i++) {
 for (j=0;j<n;j++) {
  if (i%2) { x+=(4*j+5*i); y+=(7+4*j); }
 }
}
Which optimization claim is not supported by this fragment?
Options:
(A) It contains loop-invariant computation
(B) Common-subexpression elimination is possible
(C) Strength reduction is possible
(D) Dead-code elimination is possible

## Solution

1. Within the inner j loop, i%2 and 5*i are invariant. The expression 4*j occurs in both updates and can be shared.

2. The products by loop indices can use strength reduction through induction-variable increments. However x and y are updated and may be used later; nothing in the snippet establishes that those results are dead.

3. Therefore the claim of available dead-code elimination is unsupported and is the intended false statement, D. This uses the ordinary compiler-question assumption that program behavior is defined and x,y remain live afterward.

4. Teaching check: An expression can be expensive and still necessary. Dead-code elimination requires showing that its computed value never affects observable behavior, which is not established for x or y. In contrast, the repeated arithmetic patterns are visible directly within the loops.
