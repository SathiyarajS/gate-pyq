**Paraphrased problem context:** Which compiler statement is false? A: A basic block is entered at its beginning and exited at its end. B: Available-expression analysis supports common-subexpression elimination. C: Live-variable analysis supports dead-code elimination. D: Replacing x=4*5 by x=20 is common-subexpression elimination.

## Solution

1. Method and setup. Common-subexpression elimination reuses a previously computed expression whose operands have not changed. Here no prior computation is being reused: a constant expression is evaluated during compilation. Available-expression and liveness analyses instead answer whether a value is reusable and whether a computed result will be needed.

2. Work through the result and its assumptions. Replacing the compile-time arithmetic4×5 by 20 is constant folding, not common-subexpression elimination. The other statements describe standard basic-block and dataflow uses. Thus the false statement is D.

## Solution

1. Set up the reasoning. Inspect the recursive side of each operator production. T recurs on the left of *, while P recurs on the right of +.

2. Derive the result. The rule T→T*U is left-recursive and groups multiplication to the left. P→Q+P is right-recursive and groups addition to the right. Thus + is right associative and * left associative, B.

3. Check the interpretation. Expanding T twice gives (Id*Id)*Id, whereas expanding P twice gives Id+(Id+Id). Associativity concerns grouping of repeated operators, not which operator has greater precedence.

**Paraphrased problem context:** Which is not performed during compilation of a program? A dynamic memory allocation; B type checking; C symbol-table management; D inline expansion.

## Solution

1. Set up the reasoning. Distinguish work done on the source representation by a compiler from operations performed by the compiled program when it runs. A dynamic allocation creates runtime objects whose sizes or lifetimes may depend on execution.

2. Derive the result. Allocation of the running program’s dynamic objects occurs at runtime. Type checking, symbol-table construction and inline expansion are compiler tasks. Thus A. A compiler may itself allocate memory while running, but that is not the intended meaning of program dynamic allocation.

3. Check the interpretation. The compiler may emit allocation calls and itself allocate memory while compiling; those facts do not make allocation of the target program's runtime objects a compilation phase. Type checks, names, and inlining are standard compile-time concerns.

**Official answer:** D

**Derived answer:** D under the general recursion storage model

**Source access:** Open archive member CS/CS2014.pdf inside the linked official CS.zip. Page numbers refer to the extracted PDF, not the Drive preview.

**Paraphrased problem context:** Evaluate: (1) statically allocating every data area prevents recursion; (2) automatic garbage collection is essential for recursion; (3) dynamic allocation of activation records is essential for recursion; (4) both heap and stack are essential for recursion. Choose A 1,2 only; B 2,3 only; C 3,4 only; D 1,3 only.

## Solution

Step 1: General recursive calls can leave multiple invocations of the same procedure simultaneously active. Each needs its own parameters, local variables, return address and other activation information. Step 2: One fixed static record per procedure cannot preserve all these activations; records must be allocated as calls occur. This is the intended sense in which 1 and 3 hold. Step 3: A runtime stack allocates and reclaims activation records without a heap or automatic garbage collector, refuting 2 and 4. Thus D. Bounded recursion or tail-call elimination can use fixed storage, so these claims concern the conventional general recursion model, not every special recursive program.

**Paraphrased problem context:** The basic block executes a=b+c; c=a+d; d=b+c; e=d−b; a=e+b. What are the minimum DAG node and edge counts? A (6,6); B (8,10); C (9,12); D (4,4).

## Solution

Step 1: Preserve old values when tracking assignments: let the input leaves be b0,c0,d0. The first three operations create u=b0+c0, v=u+d0, w=b0+v. The current c is v and current d is w. Step 2: Algebraically, e=w−b0=(b0+v)−b0=v, and final a=e+b0=v+b0=w. Therefore e shares v's node and a shares w's node. Step 3: The minimized DAG has three input leaves and three binary addition nodes: six nodes. Each operation has two incoming operand edges, giving six edges, A. Without cancellation, a purely syntactic DAG gives eight nodes and ten edges. The keyed minimum assumes valid algebraic identities, not unrestricted floating-point cancellation.
