**Paraphrased problem context:** A bottom-up parser processes n tokens using a grammar with no epsilon or “unit” productions, expressly described in the source as A→ε and A→a. What is the maximum number of reductions? A n/2; B n−1; C2n−1; D2^n.

## Solution

A reduction with a right-hand side of length at least 2 decreases the stack/sentential length by at least 1. Starting with n terminals and ending with one start symbol thus allows at most n−1 such reductions, attained by binary reductions, giving B. However the source calls A→a a unit-production, whereas standard CFG terminology reserves unit-production for A→B with B a nonterminal. If only standard unit rules and epsilon rules are forbidden, terminal rules A→a remain, and a Chomsky-normal-form derivation can require n terminal reductions plus n−1 binary reductions=2n−1. The key therefore relies on the source’s intended ban on length-one reductions, not the usual terminology alone.

Teaching detail:
Each reduction replaces a right-hand side by one nonterminal. If every permitted right-hand side has at least two symbols, each reduction shrinks the total length by at least one. Reducing n tokens to one start symbol then permits at most n−1 reductions; a binary parse tree attains that many internal combinations. The caveat is not optional: a normal terminal production A→a has length 1 and would add reductions without shortening the string. The printed parenthetical explicitly rules those out, even though it uses nonstandard “unit” terminology.

**Paraphrased problem context:** Two LR(1) states have items X→c·X, X→·cX, X→·d; first has lookaheads c/d on all, second $. About merging them into LALR, which claims are false?1 cannot merge because lookaheads differ;2 merging creates shift/reduce conflict;3 merging creates reduce/reduce conflict;4 cannot merge because goto on c leads to different states. A1 only, B2 only, C1and4, Dallfour.

## Solution

The two LR(1) states have the same LR(0) core, so LALR construction merges them and unions the lookahead sets for each core item. Every displayed item still has symbols to the right of the dot. Consequently this merged state has no reduction action and can create neither a shift/reduce nor a reduce/reduce conflict there. Its equal-core goto states are likewise merged in the LALR construction. Each of the four asserted objections is false, so D.

Teaching detail:
LALR equivalence compares items after removing lookaheads, and the two displayed sets then match exactly. Unioning lookaheads gives{c, d,$} for each item. Shift actions depend on the symbol after the dot; none of these items has its dot at the end, so there is no reduce action to conflict with a shift or another reduction. Goto targets with equal cores are treated by the same merging rule. Different lookaheads and different original state numbers are not reasons to reject the merge.

**Source access:** Archived official IIT Bombay booklet A. Physical PDF page numbers are used; ORS code A is the matching key column. Booklets B/C/D permute the same questions, not separate sessions.

**Paraphrased problem context:** p starts5. The function uses reference parameter x and value parameter c: int f(int &x, int c){c=c−1;if(c==0)return1;x=x+1;return f(x, c)*x;} What does f(p, p) return? A3024, B6561, C55440, D161051. The published key awards Marks to All; source does not specify operand evaluation order.

## Solution

The parameter declaration int &x is C++ reference syntax, not valid C. Every recursive invocation aliases the same p through x, whereas c is a private by-value copy. The four non-base calls increment p successively to 6, 7, 8 and 9; the fifth call returns 1 without incrementing p. In return f(x, c) * x, multiplication does not require the left operand to be evaluated first. If each call reads its right-hand x before executing the recursive call, the stored factors are 6, 7, 8, 9 and the return value is 6×7×8×9=3024 (A). If each call executes the recursive call before reading its right-hand x, all four factors are the final p=9 and the result is 9^4=6561 (B). Mixed choices can give other values. Under C++ rules sequencing a function’s execution as a unit relative to otherwise unsequenced outside evaluations, this is an unspecified operand-order issue; the recursive function call must not be confused with an unsequenced x++ written directly beside a read of x. The source does not prescribe an evaluation convention or a language version, so no unique numerical option follows. The official Code A key explicitly awards Marks to All. This record is classified under compiler parameter-passing/evaluation semantics, not as a valid C program.

Teaching detail:
Make the parameter environments explicit: each call has its own c, but every x refers to the same external p. The nonbase frames correspond to c after decrement4, 3, 2, 1. Each increments p once, so p becomes 9 at the base return. A frame can fetch its multiplication operand before recursion, preserving its current6, 7, 8or9, or fetch after recursion, seeing9. Thus a single deterministic answer requires an evaluation-order convention absent from the prompt. The official MTA must remain an adjudication label, not be replaced by whichever value one compiler happens to print.

**Source access:** Archived official IIT Bombay booklet A. Physical PDF page numbers are used; ORS code A is the matching key column. Booklets B/C/D permute the same questions, not separate sessions.

**Paraphrased problem context:** Register-only processor allows at most 2 source operands and 1destination. Code: c=a+b;d=c*a;e=c+a;x=c*c;if(x>a){y=a*a;}else{d=d*d;e=e*e;}. All variables dead after segment. With only 2 registers and code motion as the only optimization, minimum spills to memory: A0, B1, C2, D3.

## Solution

One spill store suffices. With registers R1, R2, start with a in R1 and b in R2. Compute R2←R1+R2 (c), store c once in spill slot S, and compute R2←R2×R2 (x). Compare R2 with R1. On the true branch compute y as R1←R1×R1. On the false branch execute: load R2←S; R2←R2×R1 (d); R2←R2×R2 (d²); load R2←S; R2←R2+R1 (e); R2←R2×R2 (e²). The computations d=c*a and e=c+a have been sunk into the false branch, where they are used, and arranged just before their respective squarings. Their former values are unused on the true branch, and all variables are dead after the segment, so this code motion preserves the required values. It performs one spill store and two reloads on the false path; reloads are not additional spills to memory. For the lower bound, after forming c the independent live values a and c already occupy both registers. Before the branch can be decided, at least one of d=c*a, e=c+a or x=c*c must be computed. If d or e is first, its result is needed for its later square while both a and c remain necessary for the other operations. If x is first, x and a are needed for the test while c is still needed on the false path. Thus the first such result forces three simultaneously needed values in a no-spill schedule, regardless of permitted reordering. A live value must be saved. Since recomputation and dead-code elimination are not allowed, zero spills is impossible and the minimum is one, option B.

Teaching detail:
The spill count in this question counts stores of live register values to memory. It does not count initial operand loads or each subsequent reload as another spill. The construction saves c once, reuses its register for x, then reloads c separately for the two false-branch calculations. Its one-store bound and the three-live-values argument together establish an exact minimum, not just an example. If arbitrary recomputation or elimination of dead code were allowed, the optimization problem would change, which is why the stated restriction matters.

**Paraphrased problem context:** For the same code c=a+b;d=c*a;e=c+a;x=c*c;if(x>a)y=a*a;else{d=d*d;e=e*e;}, all variables dead afterward. With original statement order and only register-allocation optimization, how many registers avoid spills? A3, B4, C5, D6.

## Solution

Retain the printed statement order. Immediately after e=c+a and before x=c*c, a is live for the comparison and true branch, c is live for x, and d, e are live for their possible false-branch squarings. Thus {a, c, d, e} is a four-value live set, giving a lower bound of four registers. Four also suffice: R1 holds a throughout the straight-line part; R2 starts as b, is overwritten by c=a+b, then is overwritten by x=c*c once c has had its last use; R3 holds d=c*a and R4 holds e=c+a. The comparison uses R2 and R1. On the true branch, y=a*a can overwrite R1. On the false branch, d² and e² overwrite R3 and R4 respectively. No extra destination register is needed because destinations may alias source registers. Hence the exact minimum is four, option B.

Teaching detail:
Liveness asks whether a computed value will still be needed on some future path. Before x is computed, a is required for comparison, c for the square, and d/e for the possible false branch. Even though only one branch eventually executes, register allocation cannot discard d/e before the condition is known under the fixed order. Four live values therefore impose four registers. At the next step c has its final use, so x can overwrite its register and no fifth register is needed.
