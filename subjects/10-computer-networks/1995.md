

# GATE 1995: Q12 (printed A Q1.12)

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=2), physical page 2. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A: 2 for either reproduced set

**Essential problem context (paraphrased):** Find minimum Hamming distance of {000000,010101,101010,000111,011001,111111}; GateForum omits 101010.

## Solution

Hamming distance counts differing bit positions. For example 010101 and 000111 differ in exactly two positions, so the minimum is at most two. Checking the other distinct pairs finds no pair differing in one position; their distances are two, three, four or six. Hence the minimum is two. The additional GFG codeword 101010 has distances three or six to some words and does not introduce a distance-one pair. Removing it, as the alternate does, therefore leaves the same minimum, though the reproduced code sets are not identical.

# GATE 1995: Q74 (printed B Q17(a.i))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** As-written data order: 0|0110101|1|1 = 0011010111; LSB-first numeric order: 0|1010110|1|1 = 0101011011.

**Essential problem context (paraphrased):** An asynchronous start-stop link uses seven data bits, one odd-parity bit and one stop bit at 1200 bits/s. Give the complete transmitted frame for data string 0110101. State bit-order convention.

## Solution

The data string 0110101 contains four ones. Odd parity requires the total number of ones in the data plus parity field to be odd, so the parity bit must be 1, giving five ones. In ordinary asynchronous binary framing, the line is idle high, the start bit is 0, and the stop bit is 1. The order is start, seven data bits, parity, stop.

If the supplied string lists the data in temporal transmission order, the frame is 0 | 0110101 | 1 | 1, or 0011010111. This is the direct as-written interpretation.

UARTs conventionally transmit the least significant data bit first. If 0110101 instead denotes a seven-bit numerical value written most-significant-bit first, reverse its data order to 1010110, producing 0 | 1010110 | 1 | 1, or 0101011011. Reversal does not change parity. The question does not explicitly specify how the written string maps to bit significance, so both interpretations are identified rather than silently choosing one. Neither idle time before the start nor voltage-level inversion is an additional data bit.

# GATE 1995: Q75 (printed B Q17(a.ii))

**Question:** [Third-party reproduction](https://media.geeksforgeeks.org/wp-content/cdn-uploads/20211005204046/GATE1995.pdf#page=7), physical page 7. Consult the reproduced wording and choices. Original official provenance and completeness have not been established.

**Type / marks:** descriptive, Unallocated leaf; group total 5 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** 120 strings/s with consecutive frames and no extra idle gaps.

**Essential problem context (paraphrased):** An asynchronous link transmits seven-bit strings with one start bit, one odd-parity bit and one stop bit, at 1200 bits/s. How many strings per second can it transmit?

## Solution

Count every transmitted bit, not just payload. Each frame has one start bit, seven data bits, one parity bit and one stop bit: 1+7+1+1=10 bits. A rate of 1200 bits/s therefore supports 1200/10=120 complete strings per second, assuming frames are sent back-to-back.

Equivalently, one bit lasts 1/1200 second, so one frame lasts 10/1200=1/120 second, about 8.333ms. The reciprocal is again 120 frames/s. The payload rate is 7×120=840 data bits/s and framing efficiency is 7/10=70%.

The odd-parity value and the order of the seven data bits do not affect frame length. Asynchronous operation permits extra idle time between frames, so 120 is the maximum sustained count under the stated framing, not a guarantee if the sender inserts delays. Dividing 1200 by seven would ignore required framing and overstate throughput.
