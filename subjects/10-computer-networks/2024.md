**Paraphrased problem context:** A browser fetches an index page and its embedded images from one server over one TCP connection. DNS and browser caches start empty. Put these outgoing packets in chronological order: (i) GET index, (ii) DNS request, (iii) GET image, (iv) TCP SYN. A iv,ii,iii,i; B ii,iv,iii,i; C ii,iv,i,iii; D iv,ii,i,iii.

## Solution

Approach: Identify what information or connection each operation needs before it can happen.
1. The browser begins with the server's name but, because the DNS cache is empty, must resolve that name to an IP address. The DNS request (ii) comes first.
2. Once the address is known, TCP connection establishment begins with the SYN packet (iv). HTTP requests use the established connection.
3. The browser requests the top-level index document (i). It must receive and parse that document to discover the embedded image references in this model.
4. It can then request an image object (iii), reusing the one TCP connection.
Answer: C, ii → iv → i → iii. DNS replies and the rest of the TCP handshake occur between these events, but are not among the four packets the question asks us to order.

**Paraphrased problem context:** Client P successfully connects to TCP server Q. NP is the sequence number in P's SYN; NQ is the acknowledgment number in Q's SYN-ACK. Which claims are correct? A NP is randomly chosen by P. B NP is always 0 for a new connection. C NQ=NP. D NQ=NP+1.

## Solution

Approach: Separate the choice of the initial sequence number from the rule for acknowledging a SYN.
1. A new TCP connection does not always begin at sequence number zero. The initial sequence number is chosen by the endpoint using a scheme intended to make it difficult to predict and to separate old connection traffic from new traffic. This is the randomized or pseudorandom selection described by A; B is false.
2. TCP acknowledgment numbers identify the next sequence number expected from the peer. A SYN consumes one position in sequence space even though it is not an ordinary payload byte.
3. After receiving a SYN with sequence NP, Q therefore acknowledges NP+1, with arithmetic modulo 2³². This makes D true and C false.
Answer: A and D. Actual initial-sequence algorithms may combine a clock with a keyed pseudorandom function; the key's “randomly” should not be read as requiring a fresh independent uniform draw.

4. Replacing one fixed-width address with another neither inserts nor removes bytes. Total Length therefore does not change merely because of NAT; D is false.
Answer: A and C. A device performing port translation also updates relevant transport-header fields, but those are not among these choices. The checksum option identifies the intended IPv4 model.

**Paraphrased problem context:** A file of 10⁶ bytes travels P→Q→R in consecutive 10³-byte chunks. Each link is 10⁶ bits/s. Chunk headers, propagation, processing and queueing are negligible; chunks are below the MTU. Router Q forwards each complete received packet and can receive one while transmitting another. P starts at t=0. When does R finish receiving? A 8.000 s; B 8.008 s; C 15.992 s; D 16.000 s.

## Solution

Approach: Separate the time to fill the two-link pipeline from the steady interval between completed packets.
1. The file has 10⁶/10³=1,000 chunks. Each chunk contains 1,000×8=8,000 bits, so one link serializes it in τ=8,000/10⁶=0.008 s.
2. Q receives the first complete chunk at t=τ and transmits it on the second link during the next interval. R therefore finishes the first chunk at 2τ.
3. While Q transmits chunk 1, it receives chunk 2. Both links have the same rate, so each later chunk finishes at R exactly τ after its predecessor. Chunk k finishes at (k+1)τ.
4. The last chunk therefore finishes at 1,001×0.008=8.008 s.
Answer: B. Multiplying the whole-file time by two ignores pipelining; using only 8.000 s ignores the final second-link serialization. Negligible propagation does not mean zero transmission time.

**Paraphrased problem context:** An IPv4 datagram totals 1420 bytes including a 20-byte header. It traverses a sender-to-router link with MTU 542, then a router-to-receiver link with MTU 360. Assuming ordinary permitted fragmentation and 20-byte fragment headers, how many fragments reach the receiver?

## Solution

Approach: MTU includes each fragment's header. Nonfinal payload boundaries must align to eight-byte units, and the intermediate router fragments existing fragments rather than reassembling the original datagram.
1. Original payload is 1420−20=1400 bytes. On the first link, raw payload capacity is 542−20=522 bytes. Round down to a multiple of 8: floor(522/8)×8=520 bytes.
2. The sender creates payloads 520,520,360, each with a 20-byte header. Their original-data starting offsets are 0,520,1040 bytes.
3. On the second link, raw capacity is 360−20=340 bytes, with aligned nonfinal capacity floor(340/8)×8=336 bytes. Each 520-byte payload splits into 336+184; the 360-byte payload splits into 336+24.
4. Six payload fragments arrive: 336,184,336,184,336,24. Their starting offsets, in eight-byte units, are 0,42,65,107,130,172. Only the last has no more-fragments flag; total payload still sums to 1400.
Answer: 6. Applying ceil(1400/336)=5 directly at the second link incorrectly assumes that the router reassembles and repacks the first-link fragments. Normal IPv4 forwarding leaves reassembly to the final destination, and fragmentation presumes DF is unset.

Approach: Use end-to-end addressing for the IP packet and local-link addressing for its enclosing frame.

This changes link addresses without replacing the final IP destination Y under ordinary routing. TCP does not make a distant host directly reachable on the local Ethernet.

The printed B does not mention the Don’t Fragment bit.

## Solution

Approach: State the fragmentation-permitted model separately from the literal unrestricted assertion.

This gives the official B, C. Preserve official B, C, and distinguish the intended DF=0 model from the literal unrestricted claim.

2. Explanation and checks. A fragment is itself an IP packet and can follow routing decisions independently, so intermediate reassembly would both require storage and assume all fragments meet at the same router. Destination-only reassembly avoids that assumption. When DF=0 an oversized fragment or datagram may be fragmented further. When DF=1, B’s asserted behavior cannot occur: the router must not fragment. This is a wording/model discrepancy, not a reason to silently replace the published B;C answer with a different scoring value.

Approach: Distinguish the window used during an RTT from its value after that RTT’s acknowledgements.

1. Derivation. Under the standard timeout slow-start model, a timeout sets ssthresh to half the old congestion window, 6MSS, and resets cwnd to 1MSS. The first subsequent RTT uses1 and its successful ACKs grow cwnd to 2; the second uses2 and grows it to 4. Thus during the third RTT cwnd is 4MSS, still below the threshold. This assumes the textbook one-MSS post-timeout reset and per-round doubling.

2. Explanation and checks. The timeout halves the threshold, not the new sending window: ssthresh becomes 6 while cwnd restarts at 1. Thus the three rounds begin with windows 1,2,4 respectively. Doubling the third round’s window to 8 would describe a later update, and would also require handling the threshold transition. The requested third round begins below ssthresh, so that boundary detail does not affect the answer. This is the stipulated textbook congestion-control model, not a universal statement about every modern TCP implementation.

**Paraphrased problem context:** An Ethernet segment transmits at 10^8 bits/s, has maximum length 500 m and signal propagation speed 2×10^8 m/s. What theoretical minimum frame length in bits permits collision detection?

## Solution

Approach: Ensure that the sender is still transmitting when a worst-case collision indication returns.

1. Derivation. The one-way propagation delay is 500/(2×10⁸)=2.5μs. To detect a collision originating at the far end, transmission must continue for at least the round-trip delay5μs. At10⁸bits/s this requires10⁸×5×10⁻⁶=500 bits. This is the theoretical collision-detection minimum from the supplied parameters, not the separate standardized512-bit Ethernet minimum.

2. Explanation and checks. A distant node may begin transmitting just before the first signal reaches it. Evidence of that collision must then travel back to the original sender, making the worst-case duration approximately twice the one-way propagation delay. Frame transmission time L/R must therefore satisfy L/R≥2d/v, or L≥2dR/v. Substituting gives 500 bits. Using only the one-way delay yields 250 bits and can let the sender finish too early to detect the collision.
