**Paraphrased problem context:** For a network with 500 nodes and 4000 links, evaluate these textbook routing statements. S1: Link-state has higher computational overhead than distance-vector. S2: Distance-vector with split horizon avoids persistent routing loops, unlike link-state. S3: After topology change, link-state converges faster than distance-vector. A: all true. B: all false. ## Solution

1. Method and setup. A link-state router builds a topology view and computes routes locally; distance-vector routers repeatedly exchange route estimates. 2. Work through the result and its assumptions. Link-state routing maintains topology and runs a shortest-path computation, conventionally costing more local computation but converging faster than iterative distance-vector updates. Split horizon does not eliminate all loops involving three or more routers, so S2 is false. The textbook comparison is S1/S3 true, D; actual convergence depends on timers, implementation and failure pattern, not the node/link counts alone.

This construction assumes no clock rollback and no counter reuse within a second; global uniqueness is limited by the timestamp wrap interval.

**Paraphrased problem context:** A router with MTU 1500 bytes receives a 4404-byte IPv4 packet whose header is 20 bytes. What are the third fragment's (MF,total length,offset) fields? A (0,1444,370); B (1,1424,185); C (1,1500,370); D (0,1424,2960).

## Solution

Step 1: Remove the original header to get 4404−20=4384 payload bytes. Each full fragment can carry 1500−20=1480 bytes; this is a multiple of eight, as required for nonfinal fragment payloads. Step 2: Two full fragments carry 2960 payload bytes, leaving 4384−2960=1424 bytes for the third fragment. Add its own 20-byte header: total length 1444. Step 3: Its starting payload offset is 2960 bytes, stored in eight-byte units as 2960/8=370. It is the last fragment, so MF=0. Therefore A, assuming fragmentation is permitted and the arriving packet is an unfragmented original.
