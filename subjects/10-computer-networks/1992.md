**Independently derived answer:** 4 parity bits; minimum distance4 for the extended Hamming code

**Essential problem context (paraphrased):** A code carries four data bits and is to detect up to three bit errors and correct one. Give extra parity bits and minimum distance.

## Solution

Ordinary Hamming(7, 4) uses three parity bits and has distance three, enough for single-error correction but only two-error detection as a code-distance property. Adding one overall parity bit produces extended Hamming(8, 4), with four redundancy bits and distance four. Distance d detects up to d−1 errors and corrects floor((d−1)/2), giving three and one here. These are separate guarantees: a decoder that automatically corrects a one-bit-looking syndrome can miscorrect some triple errors. Guaranteed simultaneous classification of every one-bit versus three-bit error requires a stronger distance condition than this standard detect-or-correct interpretation.

**Independently derived answer:** The receiver acknowledges acceptance before the sender proceeds

**Essential problem context (paraphrased):** Fill in why a handshake protocol provides reliable transfer for each data item sent.

## Solution

A request or data-valid signal tells the receiver that a transfer is available. The receiver responds with an acknowledgment after accepting the item, allowing the sender to withdraw it or send the next one. This coordinates devices with different or variable speeds without assuming a fixed delay is always sufficient. The basic handshake prevents loss from timing mismatch; it does not alone detect arbitrary corruption of data bits. Error-detecting codes or retransmission rules would be separate protocol features.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C: synchronization

**Essential problem context (paraphrased):** Are start/stop bits used for error detection, correction, synchronization, or slowing communication?

## Solution

In asynchronous serial communication, the start transition establishes the beginning of a character frame and lets the receiver align its sampling clock. Stop bits return the line to an idle state and separate frames. They are framing overhead rather than payload. A receiver may report a framing error when an expected stop bit is absent, but these bits are not a general error-correcting code. Slowing the payload rate is a consequence of overhead, not their purpose.
