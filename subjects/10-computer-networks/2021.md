**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** S1: The destination MAC address of an ARP reply is a broadcast address. S2: The destination MAC address of an ARP request is a broadcast address. Which is correct? A both true; B S1 true/S2 false; C S1 false/S2 true; D both false.

## Solution

In ordinary Ethernet ARP address resolution, a requester broadcasts because it does not yet know the target MAC address. The target learns the requester’s MAC from that request and unicasts the reply to it. Thus S1 is false and S2 true, C. This describes the normal request/reply exchange, not gratuitous ARP or implementation-specific unicast refresh traffic.

The requester already knows the destination IP but lacks its link-layer address. It therefore sends an Ethernet broadcast asking which host owns that IP. The request includes the requester's own sender MAC/IP, so the responding target has the information needed for a unicast reply. Do not confuse the IP address being resolved with the Ethernet destination field the statements ask about.

**Question:** [Official archived paper page 36](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=36); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A; B; C

**Derived answer:** A; B; C

**Paraphrased problem context:** A TCP server listens on port P of host S and has an active client connection. S crashes and reboots. The client uses no TCP keepalive timer. Select possible behaviors: A a client waiting for a packet may wait indefinitely; B the restarted server can listen again on P; C a client packet after reboot receives RST; D a client packet after reboot receives FIN.

## Solution

A passive client with no keepalive, no pending retransmission and no application timeout can wait indefinitely after a silent server crash, so A is possible. After reboot the server can bind and listen on the same port again, so B is possible. The old established connection state is gone; a segment from that old connection can elicit a reset, not an orderly FIN, giving C rather than D. This is the standard reachable-server TCP response model; actual delivery can still be affected by packet loss or filtering, and a listening socket does not restore the lost connection.

A crash does not perform an orderly TCP close, so no reliable FIN is sent merely because the old connection disappeared. After reboot the endpoint has no matching established-connection state. A valid arriving old-connection segment is therefore rejected/reset in the standard reachable-host model rather than resuming that connection. Waiting indefinitely is a possibility, not a promise: an application timeout, retransmission timeout, keepalive, or network error could instead terminate a particular client's wait.

**Question:** [Official archived paper page 36](https://gate2026.iitg.ac.in/doc/download/2021/cs_2021.pdf#page=36); consult original wording, diagrams and choices.

**Type / marks:** MSQ, 2 mark(s).

**Official answer:** A; C

**Derived answer:** A; C

**Paraphrased problem context:** P sends a 1400-byte TCP segment to Q through router R. MTUs are 1500 bytes on P–R and 820 bytes on R–Q; IP headers are 20 bytes, identification 0x1234, and DF=0. Select true statements: A R creates two fragments and the second IP datagram is 620 bytes; B if the second fragment is lost, R retransmits it with ID 0x1234; C if it is lost, P must resend the whole TCP segment; D the TCP destination port can be obtained from the second fragment alone.

## Solution

The TCP segment is the 1400-byte IP payload. The original IP datagram is 1420 bytes and fits the first MTU. The second link allows 820-20=800 payload bytes per fragment, a multiple of eight. Fragment payloads are therefore 800 and 600 bytes, giving datagram sizes 820 and 620, so A holds. IP routers do not retransmit lost fragments, so B is false. Loss prevents reassembly of the original segment and TCP at P retransmits the unacknowledged data, corresponding to C in the ordinary unchanged-segmentation model. TCP may resegment retransmitted bytes in a more general implementation; it does not repair just the missing IP fragment. The TCP header is only in the first fragment, so the second alone does not reveal the destination port and D is false.

IPv4 fragment offsets count eight-byte units. The first fragment has offset 0, payload 800, total 820 and MF=1; the second has offset 100, payload 600, total 620 and MF=0. Both retain the original identification for reassembly. The receiver needs both to reconstruct the TCP segment. Reliable delivery belongs to TCP endpoints, not an IP router's fragment-repair service. A later TCP retransmission may choose new segmentation or a new IP identification; retaining the exam answer does not justify claiming otherwise.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 50 to 52

**Derived answer:** 51

**Paraphrased problem context:** A sliding-window protocol uses a full-duplex error-free link with negligible frame/ACK processing, unlimited queued frames, 2000-bit data frames, 10-bit ACK frames, 1 Mbps in each direction, and 100 ms one-way propagation. What is the minimum sender window in frames needed for 50% utilization (source asks nearest-integer rounding)?

## Solution

A data frame takes 2000/10^6=2 ms to serialize; an ACK takes 10/10^6=0.01 ms. The earliest ACK for the first frame returns after 2+100+0.01+100=202.01 ms. For an unsaturated sliding window of W frames, utilization is W*2/202.01. Requiring at least 0.5 gives W>=50.5025, so the smallest integer window is 51. The official accepted interval is 50 to 52 and is retained, but the explicit ACK serialization and minimum-integer calculation give 51.

A cycle for the first frame includes its serialization, forward propagation, ACK serialization, and reverse propagation: 202.01 ms. In that interval W frames occupy the forward link for 2W ms, unless the link is already saturated. Hence utilization is min(1,2W/202.01). W=50 gives about 49.5025%, below the target, whereas W=51 gives about 50.4925%. This directly checks the minimum-integer result and explains why the wider official interval is preserved separately from the derivation.

**Paraphrased problem context:** TCP hosts P,Q choose initial sequence numbers X,Y. P sends SYN=1,SEQ=X,ACK=0; Q accepts. Select Q's response (SYN,SEQ,ACK,ACKnumber,FIN): A (1,X+1,0,Y,0); B (0,X+1,0,Y,1); C (1,Y,1,X+1,0); D (1,Y,1,X,0).

## Solution

Q sends SYN+ACK using its own initial sequence Y and acknowledging X+1 because SYN consumes one sequence number. Thus SYN=1, SEQ=Y, ACK=1, ACKnumber=X+1, FIN=0, C; sequence arithmetic is modulo 2³².

TCP sequence spaces are independent in the two directions. Q must announce Y, not X+1, as its own sequence number. The acknowledgment X+1 says that P's SYN was consumed and the next expected sequence is X+1. FIN is zero because the response establishes rather than closes the connection.

**Paraphrased problem context:** CRC generator x³+x+1; message 11000. Append three check bits to obtain a divisible transmitted polynomial over GF(2). Find check bits. A 101; B 110; C 100; D 111.

## Solution

Append three zeros to 11000, obtaining 11000000. Divide over GF(2) by 1011. XOR at the leading positions gives 11000000 XOR10110000=01110000, then XOR01011000=00101000, then XOR00101100=00000100. The three-bit remainder is 100, so C. Appending100 makes the transmitted polynomial divisible by the generator.

In polynomial arithmetic coefficients are mod 2, so subtraction is XOR without borrows. Generator degree three fixes a three-bit remainder, including any leading zero. As a verification, 11000100 divided by 1011 has zero remainder. Dividing the unshifted message instead would generate the wrong checksum.

**Paraphrased problem context:** Distance-vector routing: R→X,Y,Z link costs 3,2,5. Advertised distances X,Y,Z→P are 7,6,5; to Q are 4,6,8. Update R. A P distance 10; B Q distance 7; C P next hop Y; D Q next hop Z.

## Solution

Bellman-Ford updates R-to-P with min(3+7, 2+6, 5+5)=8, reached through Y. For Q it uses min(3+4, 2+6, 5+8)=7, reached through X. Hence B, C, not A or D.

The update formula is D_R(v)=min_N(c(R,N)+D_N(v)). For P the three candidates are 10,8,10; for Q they are 7,8,13. Store both the minimum cost and its minimizing neighbor. Choosing the neighbor with the cheapest direct link alone would pick Y for both and be wrong for Q.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 130 to 140

**Derived answer:** 135

**Paraphrased problem context:** Pure ALOHA frames are 1000 bits over 1Mbps. All attempts, including retries, are Poisson at 1000 frames/s. Find successful frames/s, rounded to nearest integer.

## Solution

A frame occupies 1000/10^6=0.001 seconds. For pure ALOHA the vulnerable period is twice that, 0.002 seconds. Given the stated Poisson attempt rate 1000 per second, the chance of no competing attempt in that interval is exp(-1000*0.002)=e^-2. Successful throughput is 1000e^-2=135.335 frames/second, rounding to 135, within the official 130–140 interval.

Let frame duration τ=0.001s and total offered load G=λτ=1. Pure ALOHA success probability is e^(−2G), unlike slotted ALOHA's e^(−G). Thus normalized throughput is Ge^(−2G) frames per frame-time, or λe^(−2G) frames/s. Retry attempts are already included in λ and must not be added again.
