

# GATE 2009: Q46 (printed CS Q46)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 10. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** RSA has n=pq and φ(n)=(p−1)(q−1), message 0<M<n. The source calls(e, n) private and(d, n) public. Assess I M′=M^e mod n and M=(M′)^d mod n; II ed≡1 mod n; III ed≡1 mod φ(n); IV both message exponentiations use modulusφ(n). A I/II; B I/III; C II/IV; D III/IV.

## Solution

RSA exponentiation is modulo n=pq, and the chosen exponents obey ed≡1 (mod φ(n)), with φ(n)=(p−1)(q−1). Thus statements I and III are correct, option B. Writing ed=1+kφ(n), Euler’s theorem proves M^(ed)≡M modulo n when M is coprime to n; reduction separately modulo p and q, followed by the Chinese remainder theorem, also proves it for non-coprime messages. Statement II incorrectly uses modulus n for the exponent-inverse condition; IV incorrectly performs message arithmetic modulo φ(n). The question reverses the usual names of e and d (calling e private and d public), but RSA’s mathematical inversion works either way and the answer is unchanged.

Teaching detail:
Two different moduli serve different roles. Messages live modulo n, while the inverse relationship between exponents is taken moduloφ(n) (or a suitable Carmichael modulus in other formulations). Combining the message exponentiations gives M^(ed); choosing ed=1+kφ(n) returns M. This explains I and III and rejects the distractors that interchange these moduli. The source’s naming of e and d is reversed from many textbooks but does not alter the algebra.

# GATE 2009: Q47 (printed CS Q47)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 11. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** TCP initial sequence numbers use the low 32 bits of a persistent time-of-day counter incremented once per millisecond. Maximum packet lifetime 64 s. The source asks the minimum permissible rate of sequence-number increase in a connection. Choices A 0.015/s; B 0.064/s; C 0.135/s; D 0.327/s. Connection duration is not specified; the listed-result derivation requires an explicit extra model.

## Solution

Let S=2^32, clock rate C=1000/s, packet lifetime M=64 s, and a constant-rate connection start at time 0 with initial sequence number 0, so its sequence trajectory is q(t)=rt. For r<C, the next occurrence of this sequence value on the returning clock trajectory is at time (S+rt)/C. To let a packet sent at t expire before that clock reuse, require (S+rt)/C−t≥M, equivalently (C−r)t≤S−CM. Requiring this throughout a connection of duration D therefore gives r≥C−(S−CM)/D (with nonnegative rates understood). If the intended duration is one clock cycle, D=S/C, this becomes r≥C²M/S=1000²×64/2^32=0.0149011612/s, closest to A, 0.015/s. This is an exact conditional derivation under the stated constant-rate, returning-clock model. The question does not actually specify D: the tiny minimum is therefore conditional on the one-clock-cycle interpretation, not a universal minimum. In particular, every r<C eventually reaches the returning forbidden strip if the connection continues indefinitely. The original 1/M shortcut is unjustified and is not used. Conceptual reference: Tanenbaum, Computer Networks, 5th edition, Figure 6-10 (clock-based forbidden regions); https://csc-knu.github.io/sys-prog/books/Andrew%20S.%20Tanenbaum%20-%20Computer%20Networks.pdf .

Teaching detail:
Do not infer a universal rate from 64 seconds alone:1/64 is not derived from the supplied 32-bit clock. Under a constant-rate trajectory and a connection lasting exactly one clock wrap, substitution yields r≥1000²·64/2³²≈0.014901/s, nearest A. The baseline derives the time-to-reuse inequality and shows where that extra duration enters. For an indefinitely long connection, any rate below the clock slope eventually meets the returning forbidden region. Thus the numeric choice is conditional; absent the duration/model assumption, the prompt does not uniquely define that minimum.

# GATE 2009: Q48 (printed CS Q48)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 11. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** What condition on CRC generator G(x) detects all odd-weight bit errors? A more than two terms; B G does not divide 1+x^k for any k within frame length; C 1+x divides G; D an odd number of terms.

## Solution

Over GF(2), an error polynomial E(x) with an odd number of nonzero coefficients satisfies E(1)=1. If x+1 divides G(x), every multiple of G(x) evaluates to zero at x=1. Therefore no odd-weight E(x) is divisible by G(x), and every such error has a nonzero CRC syndrome. Hence C. Option B instead addresses two-bit errors of the form x^i(1+x^k); merely having more than two terms is insufficient, and an odd number of terms makes G(1)=1 rather than giving the needed x+1 factor.

Teaching detail:
A polynomial has factor x+1 over GF(2) exactly when its value at 1 is 0, meaning an even number of nonzero coefficients. An odd-weight error has E(1)=1, so it cannot be a multiple of a generator that vanishes at 1. Therefore its division remainder cannot be zero, and the CRC detects it. This parity argument establishes C without enumerating error positions. The condition about 1+x^k is associated with two-bit errors, not all odd-weight errors.

# GATE 2009: Q57 (printed CS Q57)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** Frames 1000 bits traverse a 10^6 bps duplex link with one-way propagation 25 ms, packed back-to-back in transit. Minimum bits l to distinguish frames physically in the link? A 2; B 3; C 4; D 5.

## Solution

Frame transmission time is 1000/10^6=0.001 s=1 ms. One-way propagation time is 25 ms, so the link can hold (10^6×0.025)/1000=25 frames in transit. Distinguishing these requires l=ceil(log2 25)=5 bits, option D. This question asks about frames physically within the one-way link, not the sender window needed to cover a complete data-plus-ACK round trip; that latter calculation is not the quantity requested here.

Teaching detail:
Transmission consumes 1 ms per frame. During the 25 ms one-way propagation delay, 25 complete frame-lengths can occupy the channel, so at least 25 distinct labels are needed. Four bits give only 16 labels; five give 32 and suffice. The quantity is one-way in-flight frames, not the round-trip bandwidth-delay product for a continuously busy sender. That distinction prevents mistakenly demanding six bits here.

# GATE 2009: Q58 (printed CS Q58)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2009.pdf, physical page 13. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** Using the preceding l, sender window is 2^l frames and ACKs always piggyback on return frames. After the initial full window, minimum wait before next transmission, ignoring processing? A 16; B 18; C 20; D 22 ms. Immediate equal-size return frame is the timing convention.

## Solution

From Q57 l=5, so the stated sender window is 2^5=32 frames. Sending those frames takes 32×1=32 ms. The first frame is fully received after 1+25=26 ms. With an immediately sent equal-sized return frame carrying the piggybacked acknowledgment, its serialization takes 1 ms and propagation another 25 ms, so the ACK is fully received at 52 ms. The sender thus waits 52−32=20 ms after its initial burst, option C. This is the minimum: any delay waiting for a return data frame would increase it. The question stipulates the window size; do not replace it with protocol-specific Go-Back-N or Selective-Repeat sequence-space restrictions.

Teaching detail:
The first outgoing frame finishes transmission at 1 ms and arrives fully at 26 ms. An immediately transmitted 1000-bit return frame finishes its own serialization at 27 ms and arrives fully back at 52 ms. The initial 32-frame window completes sending at 32 ms. Thus the minimum additional wait is 20 ms. Waiting for return application data would increase it, so immediate piggybacking is the minimum-time assumption, not a guaranteed real traffic pattern.
