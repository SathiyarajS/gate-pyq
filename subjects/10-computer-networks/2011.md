**Paraphrased problem context:** A layer-4 firewall can inspect all protocol headers up to the transport layer. Which action can it NOT perform?

(A) Block all HTTP traffic between 9:00 PM and 5:00 AM
(B) Block all ICMP traffic
(C) Block incoming traffic from a specific IP address but allow outgoing traffic to that address
(D) Block TCP traffic from a specific user on a multi-user system between 9:00 PM and 5:00 AM

## Solution

IP addresses, protocol numbers and transport ports are present in network/transport headers, allowing conventional address, protocol and port-based time rules. A particular logged-in user on a shared machine is not identified by these headers, so a layer-four firewall alone cannot implement D. The HTTP option assumes the conventional known service ports, rather than universal application identification on arbitrary ports.

Separate the information needed for each rule from the information available in a packet. A time rule can consult the firewall's clock; an IP rule can inspect the source/destination address; ICMP is identified by the network protocol field. A TCP segment identifies ports and endpoints, not which operating-system user owns its connection. Enforcing that last distinction needs additional identity information, such as a host agent or authenticated application proxy.

**Paraphrased problem context:** Match email activities to application protocols: m1 sends email from a mail client to a mail server; m2 downloads email from a mailbox server to a mail client; m3 checks email using a web browser.

(A) m1 HTTP; m2 SMTP; m3 POP
(B) m1 SMTP; m2 FTP; m3 HTTP
(C) m1 SMTP; m2 POP; m3 HTTP
(D) m1 POP; m2 SMTP; m3 IMAP

## Solution

Mail submission uses SMTP; downloading from a mailbox in the listed mapping uses POP; browser-based access uses HTTP. Therefore C. IMAP is another mail-access protocol, but it is not the correct mapping of the supplied alternatives.

Follow the direction and interface of each operation rather than treating all email traffic as one protocol. SMTP transfers outgoing messages to the mail infrastructure. POP retrieves stored mailbox messages. In webmail, the browser communicates with a web server over HTTP, even though that server may use other mail protocols behind the scenes. In B, FTP is a file-transfer protocol, not the specified mailbox retrieval protocol; A and D reverse the submission/retrieval roles.

**Paraphrased problem context:** A symmetric distance-vector network has edges N1-N2:1, N2-N3:6, N3-N4:2, N4-N5:4, N5-N2:3. Stabilized vectors in destination order N1,...,N5 are N1=(0,1,7,8,4), N2=(1,0,6,7,3), N3=(7,6,0,2,6), N4=(8,7,2,0,4), N5=(4,3,6,4,0). Each round all nodes first exchange current vectors, then update. Between rounds a link-cost change modifies only the directly incident entry at each endpoint. If N2-N3 decreases to 2, what is N3's vector after the next round?

(A) 3,2,0,2,5
(B) 3,2,0,2,6
(C) 7,2,0,2,5
(D) 7,2,0,2,6

## Solution

Before the next exchange, only the incident entries change: N2 sets its distance to N3 to 2, and N3 sets its distance to N2 to 2. In particular N2 still advertises distances 1 to N1 and 3 to N5; N4 advertises 8 to N1 and 4 to N5. N3 recomputes through neighbors N2 (link cost 2) and N4 (link cost 2): to N1, min(2+1, 2+8)=3; to N2, min(2+0, 2+7)=2; to itself, 0; to N4, min(2+7, 2+0)=2; to N5, min(2+3, 2+4)=5. Its vector becomes (3, 2, 0, 2, 5), option A.

The distance-vector recurrence is D3(j)=min over neighbors k of [cost(3,k)+Dk(j)], with D3(3)=0. The exchange occurs before recomputation, so N3 cannot use routes N2 or N4 will discover later in this same round. In particular, destination N5 improves via N2 from 6 to 2+3=5, while N1 improves to 2+1=3. Mixing updated and old advertisements would model an asynchronous cascade rather than the specified one-round calculation.

**Derived answer:** C

**Source access:** Archived official IIT Kharagpur paper and IIT Madras key, booklet A. Physical PDF page numbers are used; code A is the matching key column. Final-revision designation is unverified.

**Paraphrased problem context:** Use the symmetric network edges N1-N2:1,N2-N3:6,N3-N4:2,N4-N5:4,N5-N2:3 and stabilized vectors N1=(0,1,7,8,4),N2=(1,0,6,7,3),N3=(7,6,0,2,6),N4=(8,7,2,0,4),N5=(4,3,6,4,0). Nodes exchange current vectors synchronously, then update; between rounds only incident entries change. First reduce N2-N3 to 2 and perform exactly one round as in the preceding question. Then N1-N2 fails; N2 immediately changes its N1 entry to infinity. After the NEXT round, what cost to N1 does N3 record?

(A) 3
(B) 9
(C) 10
(D) Infinity

## Solution

This is the round immediately after the update in printed question 52, not a converged routing table. In that previous round N4 retained distance 8 to N1: via N3 it saw the old advertised distance 7, giving 2+7=9, while via N5 it obtained 4+4=8. When link N1–N2 fails, N2 immediately changes its N1 entry to infinity. In the next exchange N3 therefore sees N2 advertise infinity and N4 advertise 8 to N1. Its new distance to N1 is min(2+infinity, 2+8)=10, option C. Ordinary distance-vector updating uses neighbors’ current advertisements; it does not retain its obsolete distance 3 as an independent route.

The crucial neighbor advertisement is N4's, so reconstruct it from the previous round: to N1, via N3 costs 2+7=9 using the old N3 vector, while via N5 costs 4+4=8; thus N4 advertises 8. Following failure, N3 hears no usable N1 route from N2 but still hears N4's stale value. Its update to 10 illustrates distance-vector count-to-infinity behavior: a finite advertised route can temporarily survive even though N1 is physically disconnected.
