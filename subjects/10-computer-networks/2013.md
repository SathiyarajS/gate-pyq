**Paraphrased problem context:** Choose conventional transport protocols for real-time multimedia, file transfer, DNS, email, respectively. A TCP/UDP/UDP/TCP; B UDP/TCP/TCP/UDP; C UDP/TCP/UDP/TCP; D TCP/UDP/TCP/UDP.

## Solution

For the actual listed applications, real-time multimedia conventionally uses UDP to avoid retransmission delays; file transfer uses reliable TCP; DNS lookup commonly uses UDP; email transfer uses TCP. The order is UDP, TCP, UDP, TCP, C. DNS can also use TCP and multimedia can use other transports; this is the conventional application mapping, not an exclusive claim about every implementation.

Teaching detail:
The classification concerns conventional transports, not application-layer names. Multimedia often values timeliness over retransmitting late packets, favoring UDP. File transfer and email need reliable ordered delivery, favoring TCP. Ordinary DNS query/response fits UDP. Therefore the pattern is UDP, TCP, UDP, TCP. The DNS answer is not a claim that DNS never uses TCP: large responses, truncation fallback and zone transfers are familiar exceptions.

**Paraphrased problem context:** X signs message M, encrypts the message/signature pair for Y, and Y decrypts and verifies. Choose the ordered key sequence. A sender private, recipient private;sender public, recipient public. B sender private, recipient public;sender public, recipient private. C sender public, recipient private;recipient public, sender private. D sender private, recipient public;recipient private, sender public.

## Solution

X authenticates by signing with X’s private key and protects confidentiality for Y using Y’s public key. Y decrypts with Y’s private key and verifies the signature with X’s public key. This matches D. Actual signature schemes need not literally encrypt the whole message with the signing key; signing/verification is the appropriate cryptographic interpretation.

Teaching detail:
Authentication and confidentiality have different key owners. Only X should be able to create X’s signature, so signing uses X’s private key. Anyone may encrypt a message for Y using Y’s public key, but only Y’s private key decrypts it. Since encryption is the outer layer, Y must first remove that layer and only then verify X’s signature with X’s public key. D has that receive-side order; B reverses the two receive operations. Real signatures use a signature algorithm, usually over a digest, rather than literal message encryption.

**Paraphrased problem context:** S sends a packet to D via two routers, S–R1–R2–D. Count network-layer and data-link-layer visits, respectively. A4/4; B4/3; C4/6; D2/6.

## Solution

The network layer is visited at the source, each of the two routers, and the destination: 4 times. There are three links, and each requires a data-link send and receive, so the data-link layer is visited6 times. Hence C.

Teaching detail:
Count at nodes and links separately. Network-layer processing occurs at S, R1, R2, D, once at each. The links are S–R1, R1–R2, R2–D. Each link has a sending data-link action and a receiving data-link action, so three links contribute six visits. A router participates in two data-link interfaces: it receives one frame and constructs/transmits another, while forwarding the enclosed network packet.

**Paraphrased problem context:** Ethernet data rate500 Mbps, frame length 10000 bits, propagation speed200000 km/s. Ignoring other delays, maximum cable length for collision detection: A1, B2, C2.5, D5 km.

## Solution

Frame transmission time=10000/(500×10^6)=20μs. Collision detection requires the round-trip propagation time not to exceed this, so one-way delay≤10μs. At200000 km/s the maximum length is 2 km, B, neglecting other delays as in the question.

Teaching detail:
A transmitter must still be sending when a collision signal from the far end could return. A frame occupies10000/(500×10^6)=20×10^−6 seconds on the wire. Therefore the round trip2L/v must be at most 20 microseconds. Solving L≤v·10 microseconds with v=200000 km/s gives2 km. Using one-way propagation alone would incorrectly double the allowed length. This ideal collision-domain calculation excludes repeater and transceiver delays.

**Paraphrased problem context:** IPv4 has MF=0, HLEN=10, total length 400 bytes and fragment offset300. Choose position and first/last payload byte indexes. A last, 2400, 2789; B first, 2400, 2759; C last, 2400, 2759; D middle, 300, 689.

## Solution

MF=0 indicates the last fragment; its positive offset shows it is not the sole initial fragment. The first payload byte has zero-based index300×8=2400. HLEN10 means40 header bytes, leaving400−40=360 payload bytes. The last byte index is 2400+360−1=2759. Therefore C.

Teaching detail:
The fragment offset unit is 8 bytes, not1byte, so offset300 starts at original payload byte2400. HLEN counts32-bit words:10 words=40 bytes of header. Subtracting that from total length 400 leaves360payload bytes. Inclusive indexing makes the final byte2400+359=2759. MF=0 says no more fragments follow; because the offset is nonzero, this is a final fragment rather than a complete unfragmented datagram beginning at 0.
