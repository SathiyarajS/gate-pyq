**Paraphrased problem context:** Which protocol is NOT used to resolve one form of address to another? A: DNS. B: ARP. C: DHCP. D: RARP.

## Solution

DNS resolves names to addresses, ARP resolves network-layer addresses to link-layer addresses, and RARP performs the reverse mapping. DHCP leases/configures host addressing rather than acting as an address-resolution protocol. Thus C.

Think of the direction of each lookup: DNS maps a domain name to an IP address; ARP maps a local network-layer address to a hardware address; RARP requests a protocol address from a hardware-address identity. DHCP instead assigns a lease and supplies configuration such as a subnet mask and default gateway. It may use address information internally, but that does not make its primary role address resolution in the sense asked here.

**Paraphrased problem context:** Which are stateful application-layer protocols? i:HTTP; ii:FTP; iii:TCP; iv:POP 3. A: i,ii only. B: ii,iii only. C: ii,iv only. D: iv only.

## Solution

FTP maintains control-session state and POP 3 proceeds through authorization, transaction and update states. HTTP is conventionally stateless at the protocol level despite application cookies, while TCP is stateful but belongs to the transport layer. Therefore FTP and POP 3, C.

Apply both filters in the question: stateful, and application-layer. TCP satisfies the first but fails the second because it is a transport protocol. HTTP's request semantics do not require retained server session context; a website's cookies or login sessions are application mechanisms layered on HTTP. FTP keeps connection, authentication and transfer-mode context, while POP 3 has protocol states with different permitted commands. Only ii and iv satisfy both filters.

**Paraphrased problem context:** B digitally signs message m for A. Kx− denotes x's private key, Kx+ its public key; Kx(m) denotes the paper's encryption notation and H(m) its message digest. Which pair should B send? A:{m,KB+(H(m))}. B:{m,KB−(H(m))}. C:{m,KA−(H(m))}. D:{m,KA+(m)}.

## Solution

The signer is B, so the signature is produced with B’s private key on the message digest. A verifies it with B’s public key. The transmitted pair is {m, KB−(H(m))}, B. This is the exam’s simplified signature notation; practical signatures use a secure signature construction and encoding rather than arbitrary raw encryption.

A digital signature authenticates the sender and detects message modification; it does not by itself hide the message. The public key is for verification, not for creating a signature attributable only to B. Using A's key would authenticate the wrong party or provide encryption rather than a B signature. A verifies the received digest signature using B's public key and compares it to the digest independently computed from m. Practical schemes supply the necessary secure padding and signature encoding.

**Paraphrased problem context:** A router receives a 1000-byte IP datagram, including a 20-byte IP header, and must forward it over a link of MTU 100 bytes. Find the number of fragments, assuming IPv 4 fragmentation is permitted and each fragment has a 20-byte header.

## Solution

The original datagram contains 1000−20=980 payload bytes. Each fragment can hold 100−20=80 payload bytes, already a multiple of 8 as required for nonfinal IPv 4 fragments. Twelve fragments carry 960 bytes and a thirteenth carries 20, so 13 fragments. This assumes IPv 4 fragmentation is permitted (DF=0); otherwise the router drops rather than fragments the datagram.

The MTU bounds each entire fragment, including its own header. Thus divide the 980-byte payload by 80, not the original 1000-byte datagram by 100. Each nonfinal fragment's payload must be a multiple of 8 for IPv 4 fragment offsets, and 80 already qualifies. The last fragment has 20 payload bytes plus its 20-byte header, for 40 bytes total; the other twelve total 100 bytes each. Repeated headers make aggregate transmitted bytes 1240, which is larger than the original datagram.

**Paraphrased problem context:** A token bucket is full with capacity 1 MB. Tokens arrive at 10 MB/s and the maximum output link rate is 20 MB/s. Find the minimum time to send 12 MB in the fluid token-bucket model.

## Solution

Token conservation imposes transmitted data≤1+10t megabytes, so sending 12 MB needs t≥1.1s. The output-rate bound additionally gives t≥12/20=0.6s. Attain 1.1s by sending at 20 MB/s for 0.1s, consuming the initial 1 MB net token reserve while transmitting 2 MB, then at 10 MB/s for 1s for the remaining 10 MB. This is the standard fluid token-bucket model, with no additional packet-granularity overhead.

A full bucket permits an initial burst above the sustained token rate. While transmitting at 20 MB/s, tokens are consumed net at 20−10=10 MB/s, so the initial 1 MB reserve lasts 0.1s. During that interval 2 MB are sent, not 1 MB, because new tokens keep arriving. The remaining 10 MB then require 1s at the sustained 10 MB/s rate. The token conservation lower bound proves no alternative schedule can beat this 1.1s construction.

**Paraphrased problem context:** A sender uses stop-and-wait ARQ with 1000-byte frames at 80 Kbps. ACKs have 100 bytes and the receiver sends them at 8 Kbps. One-way propagation is 100 ms;1 Kbps=1000 bits/s. Assuming no loss and no processing delay, find sender throughput in bytes/s.

## Solution

Data serialization takes 8000/80000=0.1s. ACK serialization takes 800/8000=0.1s, and round-trip propagation contributes 0.2s. With no specified processing delay, each stop-and-wait cycle is 0.4s and carries 1000 bytes. Throughput=1000/0.4=2500 bytes/s.

A stop-and-wait cycle includes four serial intervals: data transmission 0.1s, forward propagation 0.1s, ACK transmission 0.1s and return propagation 0.1s. The next frame cannot begin until the ACK finishes arriving. Only 1000 data bytes are useful sender throughput per cycle; adding ACK bytes to the numerator would measure a different quantity. Convert bits to bytes consistently: the data frame is 8000 bits and the ACK is 800 bits, so their unequal link rates nevertheless produce equal serialization times.

**Paraphrased problem context:** In an Ethernet LAN, which is true? A a station stops sensing once transmitting; B jam pads short frames; C transmission continues after detecting a collision; D exponential backoff reduces collision probability on retransmission.

## Solution

In shared half-duplex CSMA/CD Ethernet, random exponential backoff spreads retransmission times after a collision and reduces renewed collision probability. Stations monitor during transmission, abort the data frame on collision, and send a jam signal to make the collision detectable. Thus D.

After repeated collisions, the random waiting range grows, making identical retries less likely among contenders. A jam signal announces a collision so all participants abandon the damaged frame; it is not padding to reach minimum length. These statements concern collision-detecting shared Ethernet, not collision-free full-duplex switched operation.

**Paraphrased problem context:** A 128×10^3 bit/s satellite link has 150 ms one-way propagation delay. Selective repeat sends 1-kilobyte frames; ACK serialization is negligible. Find minimum sequence-number bits needed for 100% utilization.

## Solution

Using1 KiB=1024 bytes, frame serialization takes 8192/128000=0.064s. To keep the link busy for serialization plus0.3s round-trip propagation requires W≥ceil(1+0.3/0.064)=6 frames. Selective repeat requires a sequence space of at least2W=12, so ceil(log2 12)=4 bits. Decimal1KB gives W=ceil(1+0.3/0.0625)=6 as well, so the answer does not depend on that unit convention.

The first ACK can return only after one frame serialization plus a round trip, at 0.064+0.300=0.364 s. Six serializations span 0.384 s and avoid an idle gap; five span only 0.320 s. With m sequence bits, selective repeat requires W≤2^(m−1), so three bits allow only four outstanding frames, whereas four allow eight.
