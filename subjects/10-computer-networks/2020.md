

# GATE 2020 CS: Q25 (printed CS Q15)

**Question:** [Official archived paper page 7](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=7); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** D

**Derived answer:** D

**Paraphrased problem context:** Which IP-router claims are true? I Forwarding never modifies IP packets. II A router need not implement a routing protocol. III It should reassemble fragments when outgoing-link MTU exceeds incoming-packet size. Options: A I,II; B I only; C II,III; D II only.

## Solution

Worked explanation

Distinguish the forwarding plane from the control plane. Forwarding uses an existing destination-prefix table; a human can configure static routes, so a dynamic routing protocol is not mandatory. Forwarding is not a bit-for-bit copy of the IP header: hop lifetime is decremented, and IPv4’s header checksum must reflect that. A larger next-link MTU merely permits larger packets; it does not make a transit router the reassembly destination. Fragments may follow different paths, another reason end-to-end reassembly belongs at the destination. Thus only II survives.

Derivation and answer

A router changes at least TTL/hop limit while forwarding and, in IPv4, adjusts the header checksum, so I is false. It can use a static forwarding/routing table without a dynamic routing protocol, so II is true. Ordinary IP fragment reassembly is performed at the destination, not by transit routers merely because the next MTU is larger, so III is false. Thus D.

# GATE 2020 CS: Q35 (printed CS Q25)

**Question:** [Official archived paper page 9](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=9); consult original wording, diagrams and choices.

**Type / marks:** NAT, 1 mark(s).

**Official answer:** 6 to 6

**Derived answer:** 6

**Paraphrased problem context:** An empty-cache browser fetches a page with text and five very small separately referenced images using nonpersistent HTTP. What is the minimum number of TCP connections needed to display it completely?

## Solution

Worked explanation

First retrieve the HTML/text document. Its references reveal five image resources, each of which must then be requested because the cache starts empty. Nonpersistent HTTP closes a connection after one request/response object, so the six objects require six connections. Concurrently opening image connections may reduce elapsed time but cannot reduce the count. “Very small” changes transmission duration, not HTTP’s connection-reuse rule. Persistent HTTP would permit reuse, but the question expressly excludes it.

Derivation and answer

Nonpersistent HTTP uses a separate TCP connection for each retrieved object. There is one HTML/text object and five image objects, so six connections. This uses the standard interpretation of separate externally referenced images, not inline data embedded in the HTML.

# GATE 2020 CS: Q48 (printed CS Q38)

**Question:** [Official archived paper page 13](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=13); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** An ISP owns 202.61.0.0/17 and wants one aggregatable block for 1500 computers. Candidate network starts: I 202.61.84.0/21; II 202.61.104.0/21; III 202.61.64.0/21; IV 202.61.144.0/21. Which candidates are valid? A I,II; B II,III; C III,IV; D I,IV.

## Solution

Worked explanation

Host capacity first: /22 has 1024 total addresses and cannot serve 1500 machines; /21 has 2048 total, conventionally 2046 usable, so it suffices. A /21 mask is 255.255.248.0, making its third-octet start a multiple of 8. The available /17 spans third octets 0 through 127. I fails alignment because 84 mod 8=4. II starts at 104 and ends at 111, inside the allocation. III spans 64–71, also inside. IV is aligned but spans 144–151 outside the /17. Interpreting 84.0/21 as an arbitrary address within the 80.0/21 network would silently change the listed network start; the intended assessment uses actual aligned block bases.

Derivation and answer

A/21 block provides2048 addresses, enough for1500 hosts, and must begin on a multiple-of 8 boundary in the third octet.104 and 64 are aligned and lie within the/17 allocation’s third-octet range0–127.84 is not an aligned network address, and 144 lies outside the allocation. Thus II andIII, B. This treats the supplied address as the claimed network start rather than silently normalizing a host-bearing prefix.

# GATE 2020 CS: Q65 (printed CS Q55)

**Question:** [Official archived paper page 16](https://gate2026.iitg.ac.in/doc/download/2020/cs_2020.pdf#page=16); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 44 to 44

**Derived answer:** 44 under classic one-MSS initial window

**Paraphrased problem context:** TCP is established at t=0, RTT=6 ms, receiver advertised window=50 KB, client slow-start threshold=32 KB, MSS=2 KB, no errors or timeouts. Find congestion window after all ACKs at t=60 ms. Initial cwnd and ACK growth convention are not stated; give the intended classic-model answer with that caveat.

## Solution

Worked explanation

There are 60/6=10 completed RTT rounds. In the intended one-MSS initial model the window in MSS after rounds 0…10 is 1,2,4,8,16,17,18,19,20,21,22. Multiply by 2 KB to get 2,4,8,16,32,34,36,38,40,42,44 KB at times 0,6,…,60 ms. The threshold 32 KB is reached after round 4, leaving six additive-increase rounds, not ten. The advertised receiver window limits allowed outstanding data to min(cwnd,rwnd), but here 44<50, so it does not bind. This table is conditional on the classic RTT-based growth and stated initial-window assumption; it is not a claim that all compliant TCP implementations must start at 2 KB.

Derivation and answer

In the classic round-based model, start cwnd at one MSS=2KB when t=0. After RTTs at 6, 12, 18, 24ms, slow start gives 4, 8, 16, 32KB. Then congestion avoidance adds one MSS=2KB per RTT; the next six acknowledgments rounds through60ms give34, 36, 38, 40, 42, 44KB. The50KB receiver window does not bind. Thus official44KB follows. The initial congestion window and ACK growth convention are not explicitly specified; modern larger initial windows or different ACK accounting can change the result. Retain44 as the intended historical model, not a universal TCP outcome.
