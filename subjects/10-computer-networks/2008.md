**Paraphrased problem context:** What is the maximum size of data the application layer can pass to TCP?

(A) Any size
(B) 2^16 bytes minus TCP-header size
(C) 2^16 bytes
(D) 1500 bytes

## Solution

1. TCP offers applications an ordered byte stream, rather than one application-message-per-packet service.
2. TCP divides that stream into segments; IP and link-layer limits constrain individual packets/frames, not the total stream length.
3. Thus neither 1500 nor 2^16 bytes is a maximum application stream size. A is intended. Real API calls may still impose implementation-specific buffer limits.

**Independently derived answer:** D

**Paraphrased problem context:** Which system call results in sending SYN packets?

(A) socket
(B) bind
(C) listen
(D) connect

## Solution

1. socket creates a socket, bind assigns a local endpoint, and listen makes a TCP socket passive.
2. connect initiates the active TCP open, starting the three-way handshake by sending SYN.
3. The requested call is therefore D. This reasoning is specifically for TCP; UDP connect does not initiate a TCP handshake.

**Official answer:** Not available; no official key located.

**Independently derived answer:** D

**Paraphrased problem context:** During TCP slow start, how does the congestion-window size grow over successive round trips?

(A) Does not increase
(B) Linearly
(C) Quadratically
(D) Exponentially

## Solution

1. The congestion window grows exponentially over successive round-trip times in slow start, option D. In the simplified textbook model each acknowledged segment increases the window by one MSS; a window of W segments produces about W acknowledgments in one RTT, so the window becomes approximately 2W.
2. After k such rounds it is approximately 2^k times its initial value, until reaching a threshold or encountering loss. Growth is per ACK rather than continuous time; delayed ACKs and practical implementations affect the precise factor but not the intended exponential-versus-linear distinction.

**Official answer:** Not available; no official key located.

**Independently derived answer:** C

**Paraphrased problem context:** A Class B network uses subnet mask 255.255.248.0. What is the maximum number of hosts per subnet?

(A) 1022
(B) 1023
(C) 2046
(D) 2047

## Solution

Step 1: 255.255.248.0 has 8+8+5=21 leading one bits because 248=11111000₂. Thus 32−21=11 host bits remain.
Step 2: A subnet has 2^11=2048 addresses; reserving the all-zero host part for the subnet address and the all-one host part for broadcast leaves 2046 usable host addresses, option C. The original Class B label does not change the host count once the subnet mask is supplied.

**Independently derived answer:** B

**Paraphrased problem context:** A computer transmits on a 10-Mbit/s network through a token bucket replenished at 2 Mbit/s. Initially it holds its full capacity of 16 Mbits. How long can transmission continue at the full 10 Mbit/s?

(A) 1.6 seconds
(B) 2 seconds
(C) 5 seconds
(D) 8 seconds

## Solution

1. At full output rate 10 Mbit/s, tokens are consumed at 10 Mbit/s while replenishment continues at 2 Mbit/s. The initially full 16-Mbit bucket therefore drains at a net rate of 8 Mbit/s.
2. Its maximum full-rate burst lasts 16/(10−2)=2 seconds, option B. Equivalently 10t≤16+2t gives t≤2.
3. Ignoring concurrent refill would incorrectly produce 1.6 seconds.

# GATE 2008: Q59 (printed CS Q59)

**Question:** [Official-source archive](https://drive.google.com/file/d/1popAHO-cX69oQEx_tD0wZXL1tTrBljeO/view), member CS/CS2008.pdf, physical page 11. Consult original wording and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** Not available; no official key located.

**Independently derived answer:** A

**Paraphrased problem context:** A TCP server executes socket(), bind(), listen(), then is preempted before any accept(). A client executes socket() and connect() to it. Which event can occur in the intended normal setting?

(A) connect() returns successfully
(B) connect() blocks
(C) connect() returns an error
(D) connect() causes a core dump

## Solution

1. The client connect() can return successfully, option A. After socket(), bind() and listen(), the server kernel has a listening TCP endpoint and can complete the three-way handshake while the server process is descheduled.
2. The resulting established connection waits in the listener’s accept queue; accept() subsequently removes an entry and returns a connected socket to the server process. Hence user-space accept() is not required for the client handshake to complete.
3. The intended setting assumes an available backlog slot and normal network operation; incidental loss, queue exhaustion or unrelated errors can of course affect real calls.
