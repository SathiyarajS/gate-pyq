**Paraphrased problem context:** Match layers P=data link, Q=network, R=transport with: (1) reliable transfer over a physical point-to-point link; (2) encode/decode data for physical transmission; (3) end-to-end communication between processes; (4) route data from one network node to the next.
Options:
(A) P-1,Q-4,R-3
(B) P-2,Q-4,R-1
(C) P-2,Q-3,R-1
(D) P-1,Q-3,R-2

## Solution

2. Physical encoding/decoding belongs to the physical layer rather than these three.

3. Teaching check: Ask what the communication endpoints are: adjacent link endpoints identify the data-link layer; hosts or network nodes identify routing; application processes identify transport. Encoding bits onto a physical medium is the unused physical-layer description, not a network-layer function.

**Independently derived answer:** B

**Paraphrased problem context:** Which statement about a transparent bridge and a router is NOT true?
Options:
(A) Both selectively forward data packets
(B) A bridge uses IP addresses while a router uses MAC addresses
(C) A bridge builds its forwarding table by inspecting incoming packets
(D) A router can connect a LAN to a WAN

## Solution

1. A transparent bridge forwards using learned MAC addresses, while an IP router forwards using network-layer IP addresses. Option B reverses these roles and is false.

2. Both can selectively forward, bridges learn source addresses from arriving frames, and routers can join LANs to WANs.

3. Teaching check: A learning bridge records the source MAC and incoming port of received frames, then consults destination MACs for forwarding. A router performs a network-prefix lookup on a destination IP address. Reversing these address families is the decisive false statement.

(C) 876

## Solution

1. Each character occupies 1 start+8 data+2 stop+1 parity=12 transmitted bits. Under binary serial signaling,9600 baud means 9600 bits/s, yielding 9600/12=800 characters/s, B.

2. No additional idle time is assumed.

3. Teaching check: Framing overhead is four bits per character, making twelve transmitted bits for eight useful bits. The useful-data fraction is 8/12, but the question asks characters per second, so divide by 12 rather than reporting a bit rate.

**Official answer:** Not available; no official key located.

**Independently derived answer:** B

**Paraphrased problem context:** A,B are the only Ethernet stations, each with a steady frame queue. Their first frames collide; A wins the first backoff race and transmits successfully. They transmit again and collide. What is the probability A wins the second backoff race?
Options:
(A) 0.5
(B) 0.625
(C) 0.75
(D) 1.0

## Solution

1. After A succeeds, its next frame starts with collision count reset; following the next collision A chooses uniformly from{0,1}. B’s still-unsent frame has now collided twice, so B chooses uniformly from{0,1,2,3}.

2. Of the 8 equally likely pairs, A wins strictly when(A,B) is(0,1),(0,2),(0,3),(1,2),(1,3), giving 5/8=0.625. Equal choices cause another collision, not a win.

3. This evaluates the stated next backoff race, not eventual success after arbitrarily many tied races.

4. Teaching check: Binary exponential backoff counts collisions for the current frame, not for the station forever. A has a new frame while B retries its old one. Among A’s two and B’s four choices, five of eight pairs give A the strictly smaller delay; ties are new collisions.

Maximum IP packet sizes including a 20-byte IP header are A:1000 bytes, B:100 bytes, C:1000 bytes. A–B is 1 Mbps and B–C is 512 Kbps. Assuming correct delivery and data packets only, how many total bytes including headers reach the destination IP layer for one application message in the best case?
Options:
(A) 200
(B) 220
(C) 240
(D) 260

## Solution

1. Each application message contributes 180 bytes plus 20 TCP-header bytes, so the IP payload is 200 bytes. The100-byte MTU in network B leaves 80 payload bytes per fragment.

2. Three fragments carry 80,80,40 bytes with their own 20-byte IP headers, totaling 100+100+60=260 bytes delivered to the destination IP layer.80 is divisible by the IPv4 fragment-offset unit 8, so this split is valid. Routers do not reassemble merely because the following network has a larger MTU.

3. Teaching check: Only IP headers are repeated per fragment; the TCP header belongs to the original 200-byte payload and is not added to each fragment. Payload sizes 80,80,40 need three IP headers, so 200+3×20=260 bytes.

**Paraphrased problem context:** Networks A→B→C connect host HA in A to host HC in C. Every application message has 180 bytes; TCP adds a 20-byte header. Maximum IP packet sizes including a 20-byte IP header are A:1000 bytes, B:100 bytes, C:1000 bytes. A–B is 1 Mbps and B–C is 512 Kbps. GateForum labels the second link 512 Mbps in its diagram but 512 Kbps in prose; use the common GFG/prose reading, retaining this discrepancy. What is the sustained application-data rate to HC, ignoring errors, acknowledgements and other overhead?
Options:
(A) 325.5 Kbps
(B) 354.5 Kbps
(C) 409.6 Kbps
(D) 512.0 Kbps

## Solution

1. Per message the bottleneck B→C link transports260 bytes, of which 180 are application data. Its sustained goodput is 512×180/260=354.4615Kbps, rounding to 354.5Kbps.

2. The1Mbps link is not the bottleneck. This uses pipelined steady-state traffic, ignoring stated overheads; it is not the reciprocal of end-to-end latency of one isolated message.

3. GateForum’s diagram labels the second link 512Mbps while its prose and GFG say 512Kbps; the derivation follows the common prose value. Taking the alternate diagram literally changes the bottleneck and invalidates these options.

4. Teaching check: Goodput counts useful application bits, not all bits on the bottleneck. Each 260 transmitted bytes delivers 180 application bytes, giving efficiency 9/13. Multiplying 512 Kbps by that efficiency yields 354.46 Kbps; using 200 useful bytes would incorrectly include TCP overhead.
