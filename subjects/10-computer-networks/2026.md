

# GATE 2026 CS1: Q18

**Topic:** TCP connection closing.

**Question:** Consult [the original master question, page 15](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=15) for the full wording and options. This entry supplies an original solution, not a complete transcription.

**Type / marks:** MCQ, 1 mark.

**Official and derived answer:** D

## Solution

TCP supports simultaneous close: either endpoint may send FIN before receiving the other endpoint’s FIN, and the protocol has states and acknowledgements for that case. Thus D is true. Connection establishment conventionally uses the three-way handshake, so A is false. Either endpoint may initiate closing, so the restriction in B is false. TCP provides two independent byte streams for full-duplex communication, contradicting C.

## Q19 — Computer Networks: HTTP/1.1 persistence and pipelining

Paper page 15. **Answer: A, C, D.** Official key agrees.

1. A persistent connection can carry successive request/response exchanges with its server. Its lifetime is not limited to one embedded object, nor to one HTML page. Hence A and D are supported.
2. Pipelining permits a client to send another request before the preceding response has finished arriving. Responses still arrive in request order; pipelining is not arbitrary interleaving of response bodies. Thus C is supported.
3. A direct TCP connection has a fixed remote endpoint. It cannot become a direct connection to another server merely because the next resource belongs to the same webpage. Under the question's ordinary browser-to-origin-server interpretation, B is false.

**Standards cross-check:** [RFC 9112, section 9.3](https://httpwg.org/specs/rfc9112.html#persistent.connections) describes persistent connections and section 9.3.2 describes pipelining. Protocol support does not imply that every browser currently enables pipelining.

**Interpretation caveat:** A connection to a forward proxy can carry requests for multiple origins. Therefore the explanation rejects B for direct browser-to-server connections, not as an absolute statement about every HTTP deployment. This caveat does not change the published key.

# GATE 2026 CS1: Q44

**Question:** [Official paper page 33](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=33); refer to the original wording and options.

**Type / marks:** MCQ, 2 marks.

**Official answer:** B

## Solution

Using the usual simplified exercise convention that the initial congestion window is one segment, the window doubles each RTT while below the threshold. By the end of rounds transmitting windows 1,2,4,...,512, a total of 1023 segments has begun transmission. The next window is 1024, covering sequence positions 1024 through 2047. It starts after ten RTTs, so segment 2000 starts in the interval [10,11) milliseconds, corresponding to B, under the idealized round model. The threshold 10000 does not intervene because the window is only 1024. Important: the initial congestion window and the precise initial time origin are not explicitly specified in the inspected question. With an initial window of ten segments, the same idealized doubling calculation instead places segment 2000 in the eighth sending round, starting after seven RTTs. Therefore the official B needs the implicit one-segment convention; it is not a consequence of the stated parameters alone.

# GATE 2026 CS1: Q45

**Question:** [Official paper page 34](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=34); refer to the original wording and options.

**Type / marks:** MCQ, 2 marks.

**Official answer:** B

## Solution

One frame occupies the transmitter for 1000/100000 seconds = 10 milliseconds. The acknowledgment of the first frame can arrive only after that full frame is transmitted, propagates to the receiver, and its zero-length acknowledgment propagates back. The interval is therefore 10+100+100 = 210 milliseconds. Sending W frames back-to-back occupies 10W milliseconds. To avoid any idle gap before the first window slot is reusable requires 10W>=210, hence W>=21. At W=21 the first acknowledgment arrives exactly when transmission of the initial window finishes, sustaining full utilization. Twenty frames cover only the propagation round trip and omit the first frame transmission time. Select B.

## Q56 — Computer Networks: CIDR sizing and alignment

Paper page 43. MSQ, 2 marks. **Answer: A, B, C.**

1. A single CIDR allocation must have a power-of-two address count. Since 2^12=4096<6000≤8192=2^13, the smallest fitting block is /19, containing 8192 addresses.
2. A /19 boundary leaves thirteen host bits. Its mask is 255.255.224.0, so the fourth octet must be zero and the third octet must be a multiple of 32.
3. The ISP's /15 block spans second-octet values 16 and 17 with first octet 202. The candidates in A, B and C are all within that range and use aligned third octets 0, 64 and 32 respectively.
4. D uses third octet 24, which is not a multiple of 32. It is a host address inside the /19 network starting at third octet 0, not the canonical start of a distinct /19 allocation. Therefore exclude D.

**Interpretation note:** A request for 6000 addresses is rounded up to a CIDR block that can hold at least that many; a single /19 does not contain exactly 6000. The eligibility result is unchanged if a conventional subnet reserves two addresses, since 8190 remains sufficient.
