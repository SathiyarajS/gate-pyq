# GATE 2026 CS1: Q18

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=15).

**Paraphrased problem context:** Choose the true TCP statement: A establishment uses a two-way handshake; B only the client may initiate closing; C TCP is half-duplex; D client and server may initiate closing simultaneously.

**Type / marks:** MCQ, 1.

**Official answer:** D

**Derived answer:** D

## Solution

Givens and goal
Choose the true TCP statement: A establishment uses a two-way handshake; B only the client may initiate closing; C TCP is half-duplex; D client and server may initiate closing simultaneously.

Approach
Distinguish connection establishment, directional data flow, and each endpoint’s independent ability to send FIN.

Step-by-step solution
1. Ordinary TCP establishment uses SYN, SYN+ACK and ACK, a three-way handshake. Therefore A’s two-way-handshake description is incorrect.
2. A TCP connection supports data in both directions independently. Either endpoint may transmit while receiving, so it is full-duplex rather than half-duplex; C is false.
3. Either endpoint can initiate closing its sending direction by sending FIN. The server need not wait for the client to begin, so B is false.
4. Both endpoints may independently send FIN before receiving the other endpoint’s FIN. TCP handles this simultaneous close by acknowledging each FIN and completing the state transitions. Thus D is true.
5. Closing is not a rule that only a designated “client side” may invoke: client and server describe connection establishment roles, not permanent ownership of shutdown.

# GATE 2026 CS1: Q19

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=15).

**Paraphrased problem context:** For ordinary direct browser-to-origin HTTP/1.1, evaluate: A several same-page objects on one server can use one TCP connection; B objects on different servers can use that same direct TCP connection; C another request may be sent before the prior object finishes downloading; D several pages on one server may share a TCP connection.

**Type / marks:** MSQ, 1.

**Official answer:** A;C;D

**Derived answer:** A;C;D

## Solution

Givens and goal
For ordinary direct browser-to-origin HTTP/1.1, evaluate: A several same-page objects on one server can use one TCP connection; B objects on different servers can use that same direct TCP connection; C another request may be sent before the prior object finishes downloading; D several pages on one server may share a TCP connection.

Approach
Separate persistent connections from pipelining and from changing the remote TCP endpoint.

Step-by-step solution
1. A persistent connection can carry successive request/response exchanges with its server. Its lifetime is not limited to one embedded object, nor to one HTML page. Hence A and D are supported.
2. Pipelining permits a client to send another request before the preceding response has finished arriving. Responses still arrive in request order; pipelining is not arbitrary interleaving of response bodies. Thus C is supported.
3. A direct TCP connection has a fixed remote endpoint. It cannot become a direct connection to another server merely because the next resource belongs to the same webpage. Under the question's ordinary browser-to-origin-server interpretation, B is false.

**Standards cross-check:** [RFC 9112, section 9.3](https://httpwg.org/specs/rfc9112.html#persistent.connections) describes persistent connections and section 9.3.2 describes pipelining. Protocol support does not imply that every browser currently enables pipelining.

**Interpretation caveat:** A connection to a forward proxy can carry requests for multiple origins. Therefore the explanation rejects B for direct browser-to-server connections, not as an absolute statement about every HTTP deployment. This caveat does not change the published key.

Worked connection example: a browser can request /index.html, /style.css and /logo.png from the same origin through one persistent TCP connection. With pipelining it may send the later requests before the first response body is complete, although HTTP/1.1 preserves response order. It can later request /about.html on that still-open connection too. This explains A, C and D without assuming that pipelining provides HTTP/2-style multiplexing.

# GATE 2026 CS1: Q44

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=33).

**Paraphrased problem context:** A TCP connection has slow-start threshold 10000 segments, fixed RTT 1 ms, unlimited queued data, no losses, and segment numbering from 1. Find the interval when segment 2000 begins: A [9,10), B [10,11), C [11,12), D [12,13) ms. The initial congestion window and precise time origin are not explicitly stated.

**Type / marks:** MCQ, 2.

**Official answer:** B

**Derived answer:** B under the implicit initial-window=1 convention; otherwise under-specified.

## Solution

Givens and goal
A TCP connection has slow-start threshold 10000 segments, fixed RTT 1 ms, unlimited queued data, no losses, and segment numbering from 1. Find the interval when segment 2000 begins: A [9,10), B [10,11), C [11,12), D [12,13) ms. The initial congestion window and precise time origin are not explicitly stated.

Approach
Derive the official result under the usual one-segment, idealized-round convention, then identify which missing assumptions it uses.

Step-by-step solution
1. Assume the first segment starts at time 0, the initial congestion window is one segment, and each RTT doubles the allowed batch during slow start. The sending windows are 1,2,4,8,… .
2. Number rounds from r=0. Round r starts at r milliseconds and sends 2^r segments. Through the end of round r the cumulative number is 1+2+…+2^r=2^(r+1)−1.
3. Through round 9 the cumulative count is 2^10−1=1023. Round 10 has window 1024 and covers segment numbers 1024 through 2047. Therefore segment 2000 belongs to the sending interval [10,11) ms, giving official option B.
4. The slow-start threshold does not change this calculation because the relevant window, 1024, is well below 10000.
5. The initial window is material. If it were ten segments, cumulative counts would be 10(2^(r+1)−1). Through round 6 this is 1270; round 7 reaches 2550. The same segment would then begin in [7,8) under the same idealized batch convention.

Discrepancy retained: CS-2026-S1-Q44-IW. Official B depends on initial window 1, the chosen post-establishment time origin, and the textbook round model. The stated parameters alone do not uniquely determine the interval. This is not a claim that a revised official key exists.

# GATE 2026 CS1: Q45

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=34).

**Paraphrased problem context:** A lossless sliding-window link sends 1000-bit frames at 100 kbps (100000 bits/s). One-way propagation is 100 ms; processing and ACK transmission times are zero. Find the smallest window W for 100% utilization among 10,21,20,11 frames.

**Type / marks:** MCQ, 2.

**Official answer:** B

**Derived answer:** B

## Solution

Givens and goal
A lossless sliding-window link sends 1000-bit frames at 100 kbps (100000 bits/s). One-way propagation is 100 ms; processing and ACK transmission times are zero. Find the smallest window W for 100% utilization among 10,21,20,11 frames.

Approach
Find when the first frame’s acknowledgement returns, then require the initial window to keep the transmitter busy until that instant.

Step-by-step solution
1. Frame transmission time is T_tx=1000/100000 s=0.01 s=10 ms. Propagation time is T_prop=100 ms in each direction.
2. Start frame 1 at time 0. Its last bit leaves the sender at 10 ms and reaches the receiver at 110 ms. With zero processing and ACK transmission time, its ACK is sent then and reaches the sender at 210 ms.
3. Sending W frames back-to-back occupies the sender for W·10 ms. If this duration is less than 210 ms, the sender exhausts its window before the first ACK returns and must sit idle.
4. Full utilization requires 10W≥210, giving W≥21. With W=21, the first ACK arrives exactly when frame 21 finishes, allowing frame 22 to start without a gap. Later acknowledgements then arrive at the same spacing as new frames are sent.
5. Therefore the minimum is 21 frames, option B. W=20 covers only the 200-ms propagation round trip and overlooks the first frame’s own 10-ms transmission. W=10 or 11 is also too small.

The equivalent formula is W≥1+2T_prop/T_tx=1+20=21. It assumes acknowledgements are issued after full frame reception as in the stated textbook link model.

# GATE 2026 CS1: Q56

**Original question:** [Complete wording, options and figures](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS1.pdf#page=43).

**Paraphrased problem context:** An ISP controls 202.16.0.0/15 and must allocate a single CIDR block able to hold 6000 addresses. Which proposed allocations are valid: A 202.16.0.0/19; B 202.17.64.0/19; C 202.16.32.0/19; D 202.17.24.0/19?

**Type / marks:** MSQ, 2.

**Official answer:** A;B;C

**Derived answer:** A;B;C

## Solution

Givens and goal
An ISP controls 202.16.0.0/15 and must allocate a single CIDR block able to hold 6000 addresses. Which proposed allocations are valid: A 202.16.0.0/19; B 202.17.64.0/19; C 202.16.32.0/19; D 202.17.24.0/19?

Approach
Round the requested count up to a power of two, then check both containment in the parent network and alignment of the network address.

Step-by-step solution
1. A single CIDR allocation must have a power-of-two address count. Since 2^12=4096<6000≤8192=2^13, the smallest fitting block is /19, containing 8192 addresses.
2. A /19 boundary leaves thirteen host bits. Its mask is 255.255.224.0, so the fourth octet must be zero and the third octet must be a multiple of 32.
3. The ISP's /15 block spans second-octet values 16 and 17 with first octet 202. The candidates in A, B and C are all within that range and use aligned third octets 0, 64 and 32 respectively.
4. D uses third octet 24, which is not a multiple of 32. It is a host address inside the /19 network starting at third octet 0, not the canonical start of a distinct /19 allocation. Therefore exclude D.

**Interpretation note:** A request for 6000 addresses is rounded up to a CIDR block that can hold at least that many; a single /19 does not contain exactly 6000. The eligibility result is unchanged if a conventional subnet reserves two addresses, since 8190 remains sufficient.

Network-range check: A spans 202.16.0.0 through 202.16.31.255; C spans 202.16.32.0 through 202.16.63.255; B spans 202.17.64.0 through 202.17.95.255. All lie inside the parent range 202.16.0.0 through 202.17.255.255. For D, masking third octet 24 by 224 gives 0, demonstrating that 202.17.24.0/19 normalizes to 202.17.0.0/19 rather than naming an aligned block beginning at 24.

# GATE 2026 CS2: Q21

**Question:** [Official master paper page 17](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS2.pdf#page=17); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** B

**Derived answer:** B

**Paraphrased problem context:** A 4-million-byte file crosses consecutive links of 2 Mbps, 500 kbps, and 1 Mbps. Propagation, processing, other traffic, and overhead are ignored; M=10⁶ and k=10³. Choose transfer time: A 731 s; B 64 s; C 8 s; D 16 s. Packet size and forwarding mode are not specified.

## Solution

Givens and goal
A 4-million-byte file crosses consecutive links of 2 Mbps, 500 kbps, and 1 Mbps. Propagation, processing, other traffic, and overhead are ignored; M=10⁶ and k=10³. Choose transfer time: A 731 s; B 64 s; C 8 s; D 16 s. Packet size and forwarding mode are not specified.

Approach
Compute the intended bottleneck throughput, then separate it from exact store-and-forward completion time.

Step-by-step solution
1. Convert the file to bits: F=4×10⁶×8=32×10⁶ bits. The three rates are 2×10⁶, 0.5×10⁶, and 1×10⁶ bits per second.
2. In continuous pipelined transfer the slowest link determines sustained throughput: R=min(R1,R2,R3)=0.5×10⁶. Therefore F/R=64 seconds, the published answer B.
3. For a more explicit model, split the file into N equal store-and-forward packets of L bits, NL=F. The first packet needs L/R1+L/R2+L/R3 to traverse the path. Each later packet completes one bottleneck service time L/R2 after the preceding one.
4. The exact expression is L/R1+L/R2+L/R3+(N−1)L/R2=64+1.5×10⁻⁶L seconds. It approaches 64 as fill/drain effects become negligible. If the whole file is one stored unit, the time is 16+64+32=112 seconds.
5. Thus retain official B under the intended idealized throughput convention. Negligible propagation and processing do not themselves specify packet size or eliminate all serialization transients; 64 is not a forwarding-model-independent result.

**Type / marks:** MCQ, 1 mark(s).

**Official answer:** C

**Derived answer:** C

**Paraphrased problem context:** Which protocol may need to broadcast some application messages? A SMTP; B FTP; C DHCP; D HTTP.

## Solution

Givens and goal
Which protocol may need to broadcast some application messages? A SMTP; B FTP; C DHCP; D HTTP.

Approach
Consider what a client knows before it has an IP configuration.

Step-by-step solution
1. A newly connected DHCP client may have neither a usable IP address nor the address of a DHCP server. It cannot begin by directing all messages to a known server address.
2. It can broadcast a DHCPDISCOVER message so reachable DHCP servers can respond. Depending on the state and flags, later DHCP messages may also be broadcast.
3. SMTP transfers mail, FTP transfers files, and HTTP exchanges web requests and responses conventionally using unicast communication with an identified endpoint. They do not have the same initial address-discovery requirement.
4. Therefore C is correct. The word may matters: DHCP can also use unicast in appropriate states; the claim is not that every DHCP message is broadcast. Link-layer discovery used beneath another protocol should not be confused with that protocol’s application messages.

**Paraphrased problem context:** An IPv4 subnet has mask 255.255.240.0. Find the maximum number of conventional network-interface addresses assignable in that subnet.

## Solution

Givens and goal
An IPv4 subnet has mask 255.255.240.0. Find the maximum number of conventional network-interface addresses assignable in that subnet.

Approach
Count host bits and remove the two reserved endpoint addresses.

Step-by-step solution
1. The mask in binary is 11111111.11111111.11110000.00000000. It contains 8+8+4=20 leading ones, so the prefix length is /20.
2. An IPv4 address has 32 bits. The host portion therefore has 32−20=12 bits and permits 2¹²=4096 different bit patterns.
3. The all-zero host field denotes the subnet itself, while the all-one host field is the subnet-directed broadcast address. Neither is assigned to a conventional interface in this subnet.
4. Thus the usable count is 4096−2=4094. The special treatment of /31 point-to-point links is irrelevant to a /20 subnet. Reserving addresses administratively would reduce a particular deployment’s capacity, but no such reservation is specified.

# GATE 2026 CS2: Q43

**Question:** [Official master paper page 30](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS2.pdf#page=30); consult original wording, diagrams and choices.

**Type / marks:** MCQ, 2 mark(s).

**Official answer:** D

**Derived answer:** D

**Paraphrased problem context:** Data bits 110001011 use CRC generator 1001. Which 3-bit remainder is appended? A 011; B 101; C 000; D 100.

## Solution

Givens and goal
Data bits 110001011 use CRC generator 1001. Which 3-bit remainder is appended? A 011; B 101; C 000; D 100.

Approach
Divide the zero-extended message by the generator over GF(2).

Step-by-step solution
1. The generator has degree 3, so append three zeros: 110001011000. In polynomial form the message is M=x⁸+x⁷+x³+x+1 and the divisor is G=x³+1.
2. Long division starts with x¹¹+x¹⁰+x⁶+x⁴+x³. XOR x⁸G to cancel x¹¹, leaving x¹⁰+x⁸+x⁶+x⁴+x³. XOR x⁷G to leave x⁸+x⁷+x⁶+x⁴+x³.
3. Continue XOR division: subtract x⁵G to obtain x⁷+x⁶+x⁵+x⁴+x³; subtract x⁴G to obtain x⁶+x⁵+x³; subtract x³G to obtain x⁵; finally subtract x²G to obtain x². Each subtraction is XOR, so duplicate monomials cancel.
4. Thus the remainder is x², represented by 100, option D. A shorter independent check uses x³≡1 modulo G: x⁸+x⁷+x³+x+1 reduces to x²+x+1+x+1=x², and the appended factor x³ does not change it.
5. The transmitted bits are 110001011100. XORing this remainder into the zero-extended message makes it divisible by 1001. CRC division uses XOR, never carries or ordinary integer subtraction.

How many transmission rounds are needed to reach congestion avoidance? The initial congestion window and round-count convention are not explicitly stated.

## Solution

Givens and goal
A new TCP connection has constant receive window 48 KB, MSS 2 KB, and slow-start threshold 16 KB, with no timeouts or duplicate ACKs. How many transmission rounds are needed to reach congestion avoidance? The initial congestion window and round-count convention are not explicitly stated.

Approach
Use the textbook one-MSS start for the published answer and explain the dependency on that assumption.

Step-by-step solution
1. Under the conventional exercise assumption, the initial congestion window is one MSS=2 KB. In idealized slow start, one successful round doubles the window because acknowledgements increase the congestion window for the next round.
2. The sending-window sequence is round 1:2 KB, round 2:4 KB, round 3:8 KB, round 4:16 KB. The threshold 16 KB is first reached in the fourth sending round.
3. The receive window is 48 KB, larger than every window in this sequence, so it never limits the growth before the threshold. Using the threshold-round index gives the official answer 4.
4. However, only three completed doubling rounds separate the initial 2 KB window from 16 KB. Counting completed slow-start rounds instead of labeling the first threshold sending round changes the wording of the answer by one.
5. Moreover the initial congestion window is not specified; starting at 4 KB would give sending windows 4,8,16 and an index of 3. Modern TCP implementation defaults need not be one MSS. Therefore retain 4 as the published scoring answer with these implicit assumptions, rather than asserting an implementation-independent fact.

# GATE 2026 CS2: Q65

**Question:** [Official master paper page 42](https://gate2026.iitg.ac.in/doc/download/2026/QPs/CS2.pdf#page=42); consult original wording, diagrams and choices.

**Type / marks:** NAT, 2 mark(s).

**Official answer:** 30 to 30

**Derived answer:** 30 to 30

**Paraphrased problem context:** Two hosts use a lossless 3000 km link of bandwidth 10⁸ bits/s and propagation delay 5 ns/m. Every data byte gets a sequence number. Find the minimum sequence-field width N so numbers do not wrap before 60 s and full utilization is possible.

## Solution

Givens and goal
Two hosts use a lossless 3000 km link of bandwidth 10⁸ bits/s and propagation delay 5 ns/m. Every data byte gets a sequence number. Find the minimum sequence-field width N so numbers do not wrap before 60 s and full utilization is possible.

Approach
Compare the long-term no-wrap requirement with the in-flight window requirement.

Step-by-step solution
1. At full rate the byte rate is 10⁸/8=12.5×10⁶ bytes/s. In 60 seconds the sender transmits 60×12.5×10⁶=750,000,000 bytes, requiring at least that many distinct sequence numbers before reuse.
2. An N-bit field has 2^N possible values. Since 2²⁹=536,870,912<750,000,000 and 2³⁰=1,073,741,824≥750,000,000, the no-wrap condition requires N≥30.
3. Convert the link length to 3,000,000 m. One-way propagation is 3,000,000×5 ns=15 ms, so propagation round trip is 30 ms when other delays are ignored.
4. The bandwidth-delay product for that round trip is 12.5×10⁶×0.030=375,000 bytes. A window supporting that many outstanding bytes can keep the link busy. Even a selective-repeat-style sequence-space requirement of twice that window is only 750,000 values, far below 2³⁰.
5. Thus the 60-second nonwrapping condition dominates and N=30. This uses the question’s idealized data rate and ignores unspecified header, acknowledgement-transmission, and processing overhead; those details are not needed to overturn the much larger no-wrap bound.
